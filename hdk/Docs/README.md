## 文档原则

1. **记录项目，不记录平台手册。** HarmonyOS 与仓颉文档通过本仓库构建的本地语料与索引查询。项目文档解释工具做了什么、模块如何分工、有哪些长期不变量，不复制文档正文、抓取 URL 列表、API 字段表或文档 ID。
2. **记录当前事实，不记录过程。** 直接修改对应章节；不要追加“某日抓取了多少篇”、命令输出、修复流水、待构建或待验证日志。
3. **只记录稳定约束。** 至少应影响多个实现点、未来维护者的选择，或数据/安全/兼容边界。单点实现由代码说明，回归由测试说明，修改过程由提交历史说明。
4. **避免双重来源。** 数值和资源名以 `crawl*.py`、`indexer.py`、配置文件和测试为准；文档解释语义、选择方式和长期不变量，不复制整份常量表。
5. **删除过时内容。** 实现改变后更新或移除旧说法，不保留“旧版/新版”并列叙事；确需解释重大转向时建立决策记录（见下）。

本仓库是一个工具型仓库（构建离线文档知识库并对外提供 HDK MCP），无用户可见界面，因此不设 UI_SYSTEM / INTERACTION_SYSTEM / PROJECT_SYSTEM 文档。本仓库也不建立 `docs/decisions/` 目录：只有出现跨模块、难回退且存在真实替代方案的硬选择时才在 `Docs/decisions/` 留痕（当前无此类记录）。

## Agent 更新判断

一次代码变更完成后，依次判断：

- 是否改变了工程、质量或工作区体系中的长期规则？是则更新对应主题文档。
- 是否只是新增了一个抓取源、调整了关键词或修正了一篇文档落盘？只通过代码与测试验证，不因此更新文档。
- 是否做出了跨模块、难回退且存在真实替代方案的决定？是则新增决策记录。
- 其余情况不改文档。

## 文档完成标准

- 描述与当前生产目录（根目录的 `*.py` 与 `harmonyos_docs/`、`cangjie_docs/`）一致。
- 每条规则能指向代码、配置或测试中的真实落点。
- 阅读者不需要先阅读历史日志，也能知道现在应如何实现和验证。
