# 设备升级规范  
  
本章节主要介绍星闪设备升级流程、以及升级过程中常用指令的使用规范。

#### 升级流程

OTA升级流程主要分为新版本检测、版本下载与校验、版本升级三个阶段。

  1. 新版本检测：涉及App与主控设备的交互，不作详细介绍。
  2. 版本下载与校验：主要包括建立SSAP连接、查询设备信息、协商升级参数、检查升级参数等指令。
  3. 版本升级：主要包括传输升级包、上报升级结果、上报升级错误信息等指令。

#### 通用要求

  * **OTA升级使用华为通用UUID建立SSAP连接。**

星闪OTA服务包含两个属性：otaCtrl（控制通道）和otaData（数据通道），具体说明参见表星闪OTA服务Profile。

    * otaData（数据通道）：OTA升级文件通过拆包后从数据通道发送。数据通道采用不带应答的write，以提高传输效率。
    * otaCtrl（控制通道）：除了传输升级包，其他的升级指令都需要采用控制通道。控制通道采用带应答的写和带应答的通知。

  * **星闪设备升级过程中控制通道不能断开。**

在星闪设备版本升级过程中（不含设备重启过程、重启后的离线升级过程），必须支持星闪控制通道与SSAP连接通道的共存，确保可以控制设备。

  * **星闪设备支持主备双备份** 。

由于OTA升级过程中可能存在各种异常而导致中断失败，因此设备都必须要支持在非易失性介质中备份版本，即升级区和版本运行区为两个独立分区保存。

#### 协商升级参数

传输升级包之前，主控设备需要确认星闪设备最大缓冲包数量。

主控设备以轮为单位下发OTA升级包，每一轮所有分段连续下发后，会等待星闪设备通过0x8081上报正确收到的包。最大缓冲数据包数量是指每一轮中连续下发的分段个数（最大不得超过64）。

#### 检查升级参数

升级开始之前，需要检查升级参数是否匹配。

  1. 主控设备给星闪设备下发OTA头信息（0x0002）。
  2. 星闪设备收到OTA头信息（0x0002）后，检查是否满足升级条件。具体匹配规则如下：
     * 头信息的Product ID与设备的Product ID一致。
     * 头信息的Hw Version与设备的Hw Version一致。
     * 头信息的SW Version ＞ 设备当前SW Version。
     * 头信息的Totle Size ≤ 设备为运行程序分配的最大flash空间。
  3. 根据上述升级条件的匹配结果，来确定是否执行升级操作。
     * 如果匹配成功，则通过0x8002应答success。
     * 如果匹配失败，则通过0x8002返回相应错误码。

#### 传输升级包

  1. 主控设备采用otaData数据通道，将OTA升级文件分包下发给星闪设备。

主控设备每一轮下发MaxSegCacheNum个数据包分段，并等待星闪设备应答。每次发送数据包时，其长度与MTU相等，MTU不要太大（几十个字节即可），以免强干扰下长数据包发送不成功。

  2. 星闪设备回复OTA升级文件接收结果（0x8081）。

当星闪设备收到本轮发送的最后一个数据包、或达到设定的超时时间仍未收到本轮最后一个包时，设备发送数据包应答。

     * 本轮传输的超时时间 = 已收到的相邻包之间的最大时间间隔 ×（总共传输的包数-已收到的包个数+n）。之所以加n，是为了追加n个包的时间间隔冗余，n的取值范围为（1~每轮最大包数），通常取个3左右。每收到一个新的分段，需要重新评估本轮数据分段接收的超时时间。

例如，下图中绿色表示本轮已收到的包（seg 0/1/2/3/5），红色表示未收到的包，则收到seg 9的超时时间**= max（T1，T2，T3，T4/2）×（9 - 5 + n）** 。

![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/97/v3/33fij7kgQi6-xZLuAI55HQ/zh-cn_image_0000002484824542.png?HW-CC-KV=V1&HW-CC-Date=20261005T090900Z&HW-CC-Expire=86400&HW-CC-Sign=85784ACF3F07FAF14F344C168F98ADC9BB687EBE722F53F3CFD369BD9215F463)

     * 如果第一轮还未收到两个包，无法计算包传输的最大时间间隔，则最大时间间隔可以设置为200ms。
     * 新一轮开始时，包传输的最大时间间隔沿用上一轮取值。待收到新一轮数据分段的第二个分段后。再重新计算最大时间间隔。

如果星闪设备包含模组和MCU，则由模组完成升级文件的数字签名SHA256校验，MCU不做数字签名校验。MCU与模组都要升级成功，才能上报升级成功。

#### 上报升级错误信息

当星闪设备升级出错时，上报错误信息（0x8000）。主控设备任何时候收到升级错误信息（0x8000），即结束升级并上报错误原因。

与上报升级结果指令不同，上报升级错误信息指令可以用于整个升级过程的任何阶段，而上报升级结果指令只能用于升级结束之后。
