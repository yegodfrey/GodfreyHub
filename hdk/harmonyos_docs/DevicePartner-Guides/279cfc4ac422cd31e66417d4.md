# 多端适配

## 在DP平台配置多端适配和产品国际化后，中控屏英文模式下页面显示内容不一致，如何解决？

解决措施：

1.DP平台-交互设计-智慧生活APP开发-智慧生活App设计部署完页面内容，保存，点击部署按钮。

2.多端适配-中控屏开发部署完页面内容保存，点击部署按钮。

3.产品配置-产品国际化确认信息填写完整准确、保存、提交。

4.在手机侧清除智慧生活App缓存，然后验证。

伙伴在中控屏上进行系统设置，操作步骤：设置-显示-显示模式-深色。

**问题现象**

使用手机打开官网下载的[AirLink测试工具](https://developer.huawei.com/consumer/cn/doc/development/smarthome-Library/download-0000001050287714#ZH-CN_TOPIC_0000001056845319__section17953112220224)，弹出提示"Please use 10.1.x"。

**解决措施**

使用EMUI 10.1及以上系统的华为手机安装AirLink工具进行测试。

## 如何在固件中烧写激活码

激活码是设备合法性认证的唯一标识，系统会通过激活码配置文件"hal_token.c"中的OEMReadToken函数来读取激活码。烧写激活码有以下两种方式：

* 通过AT指令写入：开发AT指令，调用激活码写入函数。以Hi3861模组为例，烧写激活码的AT指令如下：

  ```screen
  AT+TOKEN=激活码
  ```

* 通过bin烧录：在bin文件中替换激活码，并按照指定的地址和长度烧录。烧录的地址和长度可以参考激活码配置文件"hal_token.c"中的定义。

  ```screen
  // token flag offset address 
  #define TOKEN_REGION_BEGIN 0x1F9000
  #define TOKEN_REGION_END 0x1FB000
  ```

## 如何解决HarmonyOS PC端鼠标点击或滑动不生效问题

**问题现象**

在HarmonyOS PC环境中，使用鼠标进行点击或滑动操作时，界面响应失效。

**原因分析**

1. 事件机制差异：HarmonyOS PC端的鼠标操作基于mouse事件体系，而常规H5开发及移动端组件库多基于touch事件体系，两者存在兼容性问题。2. 组件库适配限制：Vant组件库主要面向移动端设计，默认仅监听touch事件，未对桌面端的mouse事件进行原生适配，导致在PC端使用时交互失效。

**解决方案**

引入官方提供的@vant/touch-emulator库。该库能够在桌面端自动将mouse事件模拟并转换为touch事件，从而实现Vant组件在PC端的正常交互。

具体实施步骤如下：

1. 安装依赖包

执行以下命令安装模块：

```screen
npm install @vant/touch-emulator -S
```

2. 引入模块

在项目入口文件main.js中添加以下引入语句，无需额外配置即可全局生效：

```screen
import '@vant/touch-emulator';
```

## 使用中控屏测试时，如何清理中控屏的智慧生活和智慧生活基础服务的缓存

1. 清理"智慧生活全屋版"应用数据

* 进入设置，依次点击：应用 > 应用管理 > 点击右上角四个点图标 > 勾选"显示系统程序"。
* 找到并点击"智慧生活全屋版"，进入其详情页，选择"存储"，点击"删除数据"。

2. 清理"智慧生活基础服务"应用数据

* 返回应用管理列表，同样找到"智慧生活基础服务"，进入其详情页，选择"存储"，点击"删除数据"。
* 完成上述操作后，建议重启中控屏以确保配置生效。

## 设备详情页的二级页面操作手机的物理返回键直接返回到智慧生活首页

**问题现象**

设备详情页的二级页面（如历史记录页）中，操作手机的物理返回键，页面直接跳转至智慧生活首页，而非预期的上一级页面（设备详情页）。

**问题根因**

手机的物理返回键的默认行为是返回WebView容器的上一层，即智慧生活首页。如果未对物理返回键事件进行拦截和处理，导致默认行为生效。

**解决方案**

需重写物理返回键事件处理逻辑。具体步骤如下：

1. 调用 hilink.overrideBackPressed 方法，将第一个参数设置为 true。此举将拦截默认返回行为，并将返回逻辑交由H5端处理。
2. 在 window 对象上挂载 goback 方法，用于处理返回事件。
3. 在 goback 方法中实现具体的页面跳转逻辑。

   代码示例：

   ```screen
   // 1. 在页面初始化或适当时机调用，启用自定义返回逻辑
   window.hilink.overrideBackPressed(true);
   // 2. 定义 goback 方法，实现自定义返回逻辑
   window.goback = () => {
     // 方式一：使用框架路由
     this.$router.go(-1);
     // 方式二：若无需框架依赖，可使用原生JS
     // history.back();
   };
   ```

## 创建快捷方式三端差异性问题

**问题现象**

调用 JS API: hilink.createShortCut 时，三端（HarmonyOS, iOS,Android）智慧生活App表现如下：

1. HarmonyOS 5.0 及以上系统智慧生活App：提示创建失败，并引导用户通过长按设备卡片添加至桌面。
2. iOS 系统智慧生活App：不支持创建快捷方式，无相关功能。
3. Android 系统智慧生活App：功能正常，可成功创建快捷方式。

**解决方案**

1. HarmonyOS 5.0 及以上系统：

当前版本中，hilink.createShortCut API 暂不支持直接创建快捷方式，提示"创建失败，可通过长按设备卡片添加至桌面"属于预期行为（非异常报错）。建议引导用户通过智慧生活首页的设备页面，长按设备卡片的方式添加至桌面。

2. iOS 系统：

iOS 平台不支持快捷方式功能。建议在 H5 页面布局中，针对 iOS 设备隐藏快捷方式创建入口。

3. Android 系统：

Android 平台功能正常，保持现有逻辑即可。

## 跳转华为商城三端差异性问题

**问题现象**

调用 JS API: hilink.gotoVmall 时，三端（HarmonyOS, iOS,Android）智慧生活App表现如下：

1. HarmonyOS 5.0 及以上系统智慧生活App：提示"暂不支持跳转华为商城"。
2. iOS 系统智慧生活App：API 接收并处理绝对路径链接（如：https://m.vmall.com/product/xxxxxx.html）。
3. Android 系统智慧生活App：API 接收并处理相对路径链接（如：/product/xxxxx.html）。

**解决方案**

1. HarmonyOS 5.0 及以上系统智慧生活App：

当前版本中，hilink.gotoVmall API 暂不支持跳转到华为商城。建议在该平台隐藏跳转入口或提供替代方案。

2. iOS 系统智慧生活App：iOS 平台需传递绝对路径链接。

示例代码：

```screen
window.hilink.gotoVmall('https://m.vmall.com/product/xxxxxx.html')
```

3. Android 系统智慧生活App：Android 平台需传递相对路径链接。

示例代码：

```screen
window.hilink.gotoVmall('/product/xxxxx.html')
```

> 注意
>
> 请确保在不同平台调用时严格按照上述路径格式传递参数，以避免跳转失败。
