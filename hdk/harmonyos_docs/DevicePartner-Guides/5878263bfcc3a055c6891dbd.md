# 设备控制

## 设备智慧生活App端下发控制指令失败

**问题现象**

智慧生活App端下发控制指令失败，返回错误码errCode 9203，提示控制指令无效。

**可能原因**

控制指令对应的服务ID（SID）未在SVC_INFO结构体中正确配置，导致设备无法识别控制指令。

**解决措施**

查看设备侧日志，确认是否出现以下错误信息：

```screen
LD_ERR:hilink_local_ctrl_cmd.c:728, invalid URI
LD_ERR:hilink_local_mng_cmd.c:105, deal cmd failed [17]
```

检查SVC_INFO结构体配置。

查看设备固件中的SVC_INFO结构体定义，确认是否包含对应SID。

## 智慧生活App无法接收设备上报数据

**问题现象**

智慧生活App无法接收到设备上报的属性数据，或上报的数据与预期不符。

**可能原因**

设备上报的profile非法，被云端服务拦截。

**解决措施**

查看设备侧日志，确认是否出现以下错误信息：

```screen
LD_ERR:hilink_login_to_cloud.c:662, invalid param.
```

1. 在HILINK_PutCharState，HILINK_GetCharState 接口中增加日志，打印上报值，验证其是否与物模型（Profile）定义匹配。 ![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/1/v3/FTJcSdzqQ4yjEOQvUSqn-A/zh-cn_image_0000002594218464.png?HW-CC-KV=V1&HW-CC-Date=20260924T071230Z&HW-CC-Expire=31536000000&HW-CC-Sign=6DBA056A310F4527C4CE772F57C6222801D7D49F5683B1ED906E319CE9844F98)

2. 确认对应SID是否有上报属性。

## 从智慧生活App设备控制页进入设置页后，无法返回设备控制页

**问题描述**

从智慧生活App的设备控制页进入设置页，点击标题栏中的返回图标，直接返回智慧生活九宫格页面，无法返回设备控制页。

**可能原因**

如果接入智慧生活App的H5页面标题栏是自定义开发实现，可能是发生了事件冒泡，导致点击标题栏中的返回图标触发了返回智慧生活九宫格页面的click事件。
> 说明
>
> 事件冒泡就是当一个HTML元素触发一个事件时，该元素的祖先节点都会收到这个事件。

**解决措施**

* 如果H5页面标题栏是智慧生活App原生代码，请联系华为技术支持人员进行定位。


* 如果H5页面标题栏是自定义开发，请检查标题栏绑定事件的组件间的层级关系（比如，返回智慧生活九宫格页面和H5设备控制页面的click事件对应的组件），避免发生事件冒泡。

## 设备注册/配网成功后，无法拉起设备控制页

**问题现象**

手机本地未安装FA时，拉起FA完成设备注册/配网后，页面退出，无法拉起设备控制页。

**可能原因**

* 原因一：注册/配网FA使用StartAbility拉起控制FA，需要传入flag，flag未包含FLAG_INSTALL_ON_DEMAND，导致无法触发自动安装FA的功能。


* 原因二：注册/配网FA拉起控制FA时，系统处理时序错误，导致无权限拉起控制FA。

**解决措施**

1. 将flag设置为"276826112"，该取值包含了FLAG_INSTALL_ON_DEMAND和FLAG_ABILITY_NEW_MISSION等flag。关于flag的取值和说明可以参看[Ability框架的意图常量](https://developer.harmonyos.com/cn/docs/documentation/doc-references/js-apis-want-constant-0000001149223824#section111975902313)。


2. 注册/配网FA拉起控制FA时，不能直接关闭当前FA，而应在控制FA拉起后，以事件通知的方式关闭当前FA。详见最新的FA Demo，获取方式参见[获取Demo工程](https://device.harmonyos.com/cn/docs/devicepartner/DevicePartner-Guides/atomic-service-dp-preparations-0000001182777231#section20898161093710)。

## 使用SoftAP方式完成设备配网后，拉起控制FA失败

**问题现象**

使用SoftAP的方式完成设备配网后，拉起控制FA失败，手机弹框提示"查询失败"。

**可能原因**

手机在SoftAP配网完成后会从设备的热点切回原来连接的Wi-Fi，此时有可能网络还未恢复正常，导致查询设备控制FA失败。

**解决措施**

通过代码实现如下逻辑：配网成功后，延迟几秒（例如3s）再去启动控制页FA。

## 手机碰一碰已配网设备的NFC标签，无法拉起设备控制FA页面

**问题现象**

手机碰一碰已配网设备的NFC标签，拉起的是配网FA页面，而非设备控制FA页面。

**可能原因**

NFC标签中写入的14字段值与设备的SN不一致。

**解决措施**

检查NFC标签中的14字段与设备的SN号是否一致。如果不一致，需要重新写入。

## 智慧生活App或原子化服务中绑定的设备离线后，设备控制页多久会显示离线状态？

智慧生活App或原子化服务中绑定的设备离线后，经过3次心跳（总共150秒），设备控制页会提示设备离线状态。

## 双连方案产品开发时智慧生活App设备信息页面，设备型号显示产品型号信息错误

可能原因：获取设备列表接口的响应消息或设备新增通知接口的请求消息中"devInfo"字段中"model"字段值内容不正确。

解决措施：需要伙伴排查 获取设备列表和设备新增通知这两个接口的devInfo字段，修改里面的model字段值。

## HarmonyOS Connect极小硬件方案，二靠广播无法拉起FA

**问题描述**

HarmonyOS Connect极小硬件方案，一靠广播拉起FA设备代理注册成功后，二靠广播无法拉起FA，没有出现靠近发现水波纹。

**可能原因**

二靠广播报文中的SN信息与代理注册"deviceinfo"中上传的SN信息不一致。

**解决措施**

确保二靠广播报文中的SN信息与代理注册"deviceinfo"中上传的SN信息一致。

## HarmonyOS Connect极小硬件方案，二靠广播拉起FA，设备控制界面一直显示"连接中"

**问题描述**

HarmonyOS Connect极小硬件方案，二靠广播拉起FA，进入设备控制界面后，连接状态一直显示"连接中"。

**可能原因**

* 原因一：未申请测试权限。


* 原因二：二靠广播配对失败。

**解决措施**

1. 确认已在Device Partner平台申请测试权限。
   1. 登录[华为智能硬件合作伙伴平台](https://devicepartner.huawei.com/cn/ )。
   2. 选择"账号 > 基本资料"，单击页面右上角的"申请测试权限"。如果显示"尚未申请测试权限"，单击"立即申请测试权限"。
2. 检查设备侧一靠广播的配对连接是否采用：安全配对连接、不绑定、安全级别Justwork。如果不符合，需要进行修改。

## HarmonyOS Connect极小硬件方案，强制退出FA，设备侧无法监听到蓝牙断开

**问题描述**

HarmonyOS Connect极小硬件方案，二靠广播拉起FA，设备控制界面显示"已连接"。强制退出FA，设备侧无法监听到蓝牙断开，在蓝牙设置中重启蓝牙，再次拉起FA后，连接失败。

**可能原因**

强制退出FA，未调用智慧生活基础服务的断开蓝牙连接的接口。

**解决措施**

在FA进入后台的生命周期中调用断开蓝牙接口，FA进入后台会进入onHide()事件中。在BleServiceAbility.java中调用"onDisconnec()"，代码如下所示：

```screen
case ACTION_MESSAGE_CODE_UNSUBSCRIBE: {
    remoteObjectHandler = null;  
    remote.onDisconnect(); // 断开蓝牙连接    
    break;
}
```

## 鸿蒙智联SDK报文上报的频率限制是多少

最短50ms上报一次报文，即不超过20次/秒。

## 调用鸿蒙智联SDK方法导致程序异常终止

**问题现象**

在子线程中调用恢复出厂设置的方法"hilink_restore_factory_settings"，出现程序异常终止的现象。

**可能原因**

子线程没有分配足够多的内存，线程栈空间不足，导致执行报错，线程意外终止。

**解决措施**

如果在子线程中调用鸿蒙智联SDK方法，线程创建时要分配足够的栈内存。

例如，"hilink_restore_factory_settings"方法需要用到加解密的库，栈空间要求至少分配4K。

## 使用智慧生活App与多个设备配网后，只显示最后一个设备

**问题现象**

使用智慧生活App与多个设备分别完成配网后，智慧生活App中只显示最后一个设备。

**可能原因**

调试时多个设备SN相同，导致后添加的设备会覆盖之前添加的设备。

**解决措施**

修改"hal_sys_param.c"文件中"char* HalGetSerial(void)"函数，返回Flash中产线预置的唯一标识（保证唯一性的前提下，也可以使用设备MAC地址）。

以Hi3861为例，示例代码如下：

```screen
char* HalGetSerial(void)
{
    unsigned char mac[6]={0};
    if(hi_wifi_get_macaddr((char*)mac, 6) != 0) {
        return NULL;
    }
    char serial[16] = {0};
    sprintf(serial,"%02X%02X%02X%02X%02X%02X",mac[0],mac[1],mac[2],mac[3],mac[4],mac[5]);
    char* value = (char*)malloc(strlen(serial) + 1);
    if (value == NULL) {
        return NULL;
    }
    if (strcpy_s(value, strlen(serial) + 1, serial) != 0) {
        free(value);
        return NULL;
    }
    return value;
}
```

## 使用智慧生活App控制设备的某个功能时，设备控制页面必现"修改失败"

**问题现象**

使用智慧生活App控制设备的某个功能时，设备控制页面必现"修改失败"，如下图所示：

![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/ad/v3/mvOQbecST9OsjZ-F8dlSwA/zh-cn_image_0000002594508630.png?HW-CC-KV=V1&HW-CC-Date=20260924T071230Z&HW-CC-Expire=31536000000&HW-CC-Sign=0C56667B228015D1473D613867505305324EA3FA89F293E61DF9C633B8E7DFB8 "点击放大")

**可能原因**

鸿蒙智联SDK下发控制指令接口返回了错误码-1或-201。

**解决方式**

在下发控制指令hilink_put_char_state（或HILINK_PutCharState）接口中实现对应服务的控制时，确保返回值为"0"或"-111"。

* 返回值为"0"时，代表同步控制场景。
* 返回值为"-111"时，代表异步控制场景。

## 设备近场连接后切换为远场，要求在设置界面>选择网络信息配置，来进行远场切换，实际在设备详情页面顶部，点击"配置网络"且网络配置成功后，该提示会自动消失，如何处理？

1.设置Wi-Fi信息后，网络信息配置选项会置灰，设备切换为远场，并且可正常控制设备。（这里"网络信息"选项置灰需要看下设置页面处是否置灰）

2.点击"配置网络"且网络配置成功后，切换为远场，退回H5页面，该提示会自动隐藏（可理解为消失），属于正常现象。
