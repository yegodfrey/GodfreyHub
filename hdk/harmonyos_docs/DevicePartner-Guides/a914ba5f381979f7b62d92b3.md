# 设备配网

## Combo模组采用SoftAP配网，日志提示错误码"0x02001d01"

**问题现象**

Combo模组采用SoftAP模式配网时，设备侧日志中提示了错误码"0x02001d01"。具体的日志如下所示：

```screen
**************** LOS_ErrHandle enter **************** 
* fileName    os_unspecific_file 
* lineNo      a1b2c3f8 
* errorNo     0x02001d01 * paraLen     0 
* para: 
**************** LOS_ErrHandle  exit ****************
```

**可能原因**

Combo模组在使用SoftAP配网的时候，未等设备系统完成启动，就执行了"hilink_main"函数。

**解决措施**

确保系统启动之后，再调用"hilink_main"函数。方法如下：

* 方法一：在调用"hilink_main"函数之前延迟1秒，代码如下：

  ```screen
   osDelay(1000); // 延迟1秒
  ```

* 方法二：采用"SYS_RUN"来执行"hilink_main"函数，调用代码如下：

  ```screen
  void HilinkMain(void)
  {
      int ret = hilink_main();
      if (ret != 0) {
          hilink_printf("hilink_main start error\r\n");
      }
  }
  SYS_RUN(HilinkMain);
  ```

## 使用RTL8720CF模组调测蓝牙配网功能，在连续多次配网后出现模组重启的现象

**问题现象**

HarmonyOS Connect双连方案中，使用RTL8720CF模组调测蓝牙配网功能，在连续多次配网后会出现模组重启的现象，且打印线程信息时发现存在"bt schedule"和"avdCtrl"两个线程未退出。

**可能原因**

设备配网完成后，在释放蓝牙配网占用的资源时接口调用不正确，导致线程无法正常退出，引起内存泄漏。

**解决措施**

在释放蓝牙配网占用的相关资源时，正确接口调用顺序如下：

BLE_CfgNetDisConnect > HILINK_BT_DisconnectFreeResource > BLE_CfgNetDeInit > hilink_stop。

## 配网方式设置HILINK_NETCONFIG_NONE之后，Hilink是否会执行连接WiFi操作

HILINK_NETCONFIG_NONE 方式不用配网，是通过网线等手段连接到网络，配网模式设置成NONE时，hilink sdk跳过配网过程，直接进入设备连网状态，连接网络，检测网络状态。

## OpenHarmony SDK如何获取当前设备Wi-Fi的SSID和PWD

获取方法：通过系统侧"AddDeviceConfig"接口保存在设备本地，可通过在此接口增加日志调试确认保存位置，增加接口获取即可WiFi的SSID和PWD。

## 已配网设备恢复出厂设置后，二次配网失败

**问题现象**

设备正常配网成功后，设备恢复出厂设置进入待配网模式，二次配网失败。设备侧日志显示，配网认证注册成功后再次触发了重启，导致设备又进入到了待配网模式。

**可能原因**

hilink_notify_devstatus处理函数中HILINK_DEVICE_UNREGISTER分支调用了hilink_restore_factory_settings函数，导致KitFramework数据被删除。

**解决措施**

hilink_notify_devstatus处理函数HILINK_DEVICE_UNREGISTER分支中，删除hilink_restore_factory_settings函数调用。

## 使用开放网络对设备进行配网，结果配网失败

**问题现象**

在给设备配网时，选择开放网络进行配网，模组侧打印 "ConnectTo conn failed -9"，导致配网失败。

**可能原因**

设备使用了FastConnect进行连接，而FastConnect是不支持开放网络的。

**解决措施**

在ParseNetCfgDate函数里找到FastConnect调用的地方，加上分支判断，如果是开放网络，调用NormalConnect进行连接，否则使用FastConnect进行连接。

## 智慧生活App添加设备失败，配网进度显示99%，设备日志显示"hilink register timeout"

**问题现象**

智慧生活App添加设备失败，配网进度显示99%，设备日志报错如下：

```screen
hilink register timeout
```

**可能原因**

* 原因一："hal_sys_param.c"文件中的产品信息未配置正确，导致KitFramework认证失败。
* 原因二："hilink_device.h"文件中的产品信息未配置正确，导致HiLinkSDK注册超时。

**解决措施**

1. 检查"hal_sys_param.c"文件中企业英文名、产品型号、品牌英文名信息是否配置正确，确保和Device Partner平台管理中心上的产品信息保持一致。


2. 检查"hilink_device.h"的产品ID、设备类型 、企业ID是否配置正确，确保和Device Partner平台管理中心上的产品信息保持一致。
3. 在Device Partner平台的管理中心上重新[申请设备软证书](https://device.harmonyos.com/cn/docs/devicepartner/DevicePartner-Guides/device-authorization-0000001134626077)，并写入设备。

## 设备处于待配网模式时，手机未碰触设备也会出现连接弹窗

**问题描述**

设备处于待配网模式时，手机未碰触设备也会出现连接弹窗。

**可能原因**

该模组支持Wi-Fi靠近发现功能（此时代码中HILINK_GetDevSurfacePower接口的返回值为"0"）。当手机靠近待配网的设备时，会发现设备并出现连接弹窗。

**解决措施**

打开"hilink_device.c"文件，将HILINK_GetDevSurfacePower接口的返回值配置为"-1"，关闭Wi-Fi靠近发现功能。

## HarmonyOS Connect极小硬件方案，一靠广播配网进度"30%"时连接失败

**问题描述**

HarmonyOS Connect极小硬件方案，一靠广播拉起FA配网进度"30%"时显示连接失败。

**可能原因**

* 原因一：蓝牙设备已经被配对连接。
* 原因二：蓝牙设备配对连接步骤错误。

**解决措施**

1. 检查设备蓝牙是否已经配对连接。如果已经连接上，则需要重启设备。


2. 检查设备侧一靠广播的配对连接是否采用：安全配对连接、不绑定、安全级别Justwork。如果不符合，需要进行修改。

## 模组待配网的超时时间是多久？如何配置？

超时时间默认为10分钟。修改方法如下：

* 极速常规/秒控配网：在超时时间函数"HILINK_SetNetConfigTimeout(unsigned long netConfigTimeout)"中配置。
* 蓝牙辅助配网：在BLE配网广播控制函数"BLE_CfgNetAdvCtrl(unsigned int advSecond)"中配置，其中的蓝牙广播时间必须与极速常规/秒控配网中的超时时间保持一致。

## 设备处于开机状态且手机网络正常，但智慧生活App上设备卡片显示离线状态

**问题现象**

设备处于开机状态且手机网络正常，但智慧生活App上设备卡片显示离线状态，且串口工具不停重复打印设备侧日志"+NOTICE:SCANFINISH/+NOTICE:DISCONNECTED"。

**可能原因**

设备已连接的热点的SSID或密码发生变更。

**解决措施**

* 方式一：将热点SSID和密码改回，模组即可重新连接热点，恢复正常。
* 方式二：将模组重置，重新给模组配网。

## 设备配网过程中，KitFramework认证时软证书解析失败

**问题现象**

设备KitFramework认证时软证书解析失败，日志显示"ERROR : Get padding failed，ret = -0x6200" 。

**可能原因**

* 原因一：ProdID或者AcKey配置异常。
* 原因二：使用了其他产品的设备软证书。

**解决措施**

1. 检查"hal_token.c"中的productId及AcKey信息，确保和[Device Partner平台](https://devicepartner.huawei.com/console/product/home)管理中心上的产品信息保持一致。
2. 重新[申请设备软证书](https://device.harmonyos.com/cn/docs/devicepartner/DevicePartner-Guides/device-authorization-0000001134626077)并写入设备。

## 设备配网过程中，KitFramework认证时产品信息查询失败

**问题现象**

设备KitFramework认证时产品信息查询失败，日志显示"ERROR [KitFramework]: Do symbol authentication failed, ret = -30004" 。

**可能原因**

* 原因一：设备的基础信息与Device Partner平台配置的产品信息不一致。
* 原因二：未添加调测设备SN。

**解决措施**

1. 检查"hal_sys_param.c"文件中企业英文名、产品型号、品牌英文名信息是否配置正确，确保和[Device Partner平台](https://devicepartner.huawei.com/console/product/home)管理中心上的产品信息保持一致。


2. 进入[Device Partner平台](https://devicepartner.huawei.com/console/product/home)的管理中心，选择"产品开发 > 集成开发 > 管理调测设备"，添加调测设备的SN号。

## 设备配网过程中，设备侧日志已显示"get wifi ssid pwd done"，但热点无法连接

**问题现象**

设备配网的过程中，设备侧日志已显示"get wifi ssid pwd done"，但之后串口工具循环打印设备侧日志"+NOTICE:SCANFINISH/+NOTICE:DISCONNECTED"，热点无法连接，最终设备配网失败。

**可能原因**

* 原因一：在智慧生活App扫描配网输入热点信息界面时，输入了错误的SSID或密码。
* 原因二：勾选了记住密码，但热点密码已发生了改变，再次配网时传入了旧密码导致。

**解决措施**

1. 将设备重置，并重新进入待配网状态。
2. 重新给设备配网，在热点信息界面输入正确的SSID和密码。

## 设备配网失败且设备侧日志显示"Parse symbol authentication response message failed"

**问题现象**

设备配网的过程中，串口工具打印的设备侧日志显示"Parse symbol authentication response message failed"，配网流程结束后，智慧生活App显示设备配网失败。

**可能原因**

* 原因一：hal_sys_param.c文件中的产品信息未配置正确。
* 原因二：设备软证书（激活码）与产品信息不匹配。
* 原因三：Device Partner平台管理中心上添加的调测设备SN与HalGetSearial接口返回的value值不一致。

**解决措施**

1. 检查hal_sys_param.c文件中企业英文名、产品型号、品牌英文名信息是否配置正确，确保和Device Partner平台管理中心上的产品信息保持一致。
2. 在Device Partner平台管理中心上重新申请设备软证书（激活码），并写入设备。
3. 检查hal_sys_param.c文件中HalGetSearial接口的实现，可通过打印value方式查看其返回值是否和Device Partner平台管理中心上配置的调测设备SN是否一致（大小写也需要保持一致）。

## 设备已配置的网络不可用时，是否可以自动切换到待配网状态？

不可以。网络不可用时设备处于离线状态，网络恢复后可以自动连接。只有恢复出厂设置才可以让设备重新处于待配网状态。

## 设备配网完成登录上线后，设备反复离上线

**问题现象**

设备配网成功并完成注册登录后，出现频繁上线和离线状态切换的现象，设备状态不稳定。

认证阶段的产品对应认证沙箱环境。

已商用的产品对应商用环境。

**解决措施**

步骤 1：查看设备注册日志。

查看设备日志中的注册成功消息，确认用户环境：

步骤 2：检查智慧生活 App 环境配置。

1、打开智慧生活App。

2、进入设置->关于->环境选择，测试中的产品选择沙箱环境。

**可能原因二**

测试账号缺少相应权限，无法获取设备云端配置信息，导致设备注册到云端认证失败，最终离线。

**解决措施**

步骤 1：查看设备注册日志。

检查设备日志，更新的域名是沙箱环境还是商用环境。


授权测试账号配网的GRS Key值：

```screen
LD_DEBUG:SetGrsInfoValue() 292, set grs info: smarthome, com.huawei.cloud.wisedevice, sandboxDevicePrimaryCloudUrl, sandboxDeviceStandbyCloudUrl, CN
```

关键区别：

* hilinkDevicePrimaryCloudUrl → 测试环境（无权限）。
* sandboxDevicePrimaryCloudUrl → 沙箱环境（有权限）。

步骤 2：确认账号权限状态。

1. 登录 Device Partner 平台。

2. 进入"产品开发 > 集成开发 > 管理调测设备"。

3. 查看当前账号是否已添加为调测设备管理员。

4. 确认账号是否已获得产品测试权限。

**可能原因** **三**

设备注册时需要上报物模型（Profile）信息，服务端会将设备上报的 Profile 与 Device Partner 平台产品配置进行比对验证：

* 验证通过 → 设备注册成功。
* 验证失败 → 设备注册失败，返回错误码 15013。

**解决措施**

步骤 1：查看设备日志中的错误码，确认是否出现错误码 15013。

```screen
LD_ERR:RegWanResponse() 902, register to cloud failed, errCode[15013]
LD_ERR:HandleCloudSessCreated() 2009, register to cloud failed, ret[15013]
```

步骤 2：对比 Device Partner 平台配置。

1. 登录 Device Partner 平台。

2. 进入"产品开发 > 产品定义 > 物模型配置"。

3. 查看产品配置的 SID、属性定义、权限设置。

4. 与设备上报的 Profile 进行逐项比对。

## 设备配网进度在40%~50%失败

**场景一：**PIN 码不一致导致 Speke 协议失败。

**可能原因**

设备侧PIN码与DevicePartner平台产品配置中的PIN码不一致，导致Speke密钥协商协议失败。

**解决措施**

查看设备侧日志，确认是否出现以下错误信息：

```screen
LD_ERR:HiLinkSetStaInfo() 1038, InitPakeKey Session failed
LD_INFO:ProcessPkt() 2092, Get bind session failed!
LD_ERR:ReceiveBindPkt() 2173, deal CoAP msg failed [-11]
```

步骤 1：验证 PIN 码配置一致性。

1. 登录 Device Partner 平台。

2. 进入"产品开发 > 集成开发 > 管理调测设备"。

3. 确认"是否开启 PIN 码校验"配置状态。

4. 对比 PIN 码类型（自动/手动）与固件配置是否一致。
> 注意
>

## 手机碰一碰NFC标签，提示"系统错误"

2. 选择" 系统和更新 > 日期和时间"。

## 手机碰一碰NFC标签，无法进行NAN配网

**问题现象**

手机碰一碰NFC标签，无法进行NAN配网，FA日志中打印碰一碰Intent参数nanSessionId字段的值为"NAN_DEVICE_NOT_FOUND"。

**可能原因**

* 用于配网的模组不支持NAN配网。
* 手机与模组之间距离大于30cm。
* 上一次碰一碰拉起配网FA进行NAN配网未完成，模组的NAN通道将锁定一段时间。

**解决措施**

1. 咨询产品对应模组伙伴，确认模组是否支持NAN配网。
2. 将手机靠近至模组30cm半径以内后重新碰一碰配网。
3. 等待模组日志打印以下信息时，即可进行NAN配网(x代表任意数字)。

   ```screen
   Send: msgType[x] msgId[x] msgLen[x]
   ```

   若模组日志打印显示以下信息，则表示当前模组只能进行SoftAP配网，请重启模组或重新烧录模组。

   ```screen
   wait STA join AP
   ```

## 手机首次碰一碰NFC标签，拉起的是非配网FA页面

**问题现象**

手机首次碰一碰NFC标签，拉起的是非配网FA页面（比如控制FA页面）。

**可能原因**

* 原因一：服务意图配置的Ability名称不是配网FA页面的Ability名称。
* 原因二：原子化服务包中其他模块的Ability与配网FA的Ability重名，导致拉起的FA页面有误。

**解决措施**

1. 确认服务意图配置的"服务名"是否为配网FA的Ability名称。
   1. 登录[HarmonyOS服务开放平台](https://developer.huawei.com/consumer/cn/console#/openCard/FastService/63)。
   2. 在服务列表中找到对应的原子化服务，单击"编辑"。
   3. 选择"配置 > FA信息"，确认配置方式中的"服务名"是否为配网FA的Ability名称。如果不正确，需要重新配置。
2. 确认其他模块Ability名称是否与配网FA的Ability重名。
   1. 在DevEco Studio项目下，逐个排查其他模块中的"src/main/config.json"文件。
   2. 在json文件中，找到"module/mainAbility"配置项，检查是否与配网FA的Ability同名。
   3. 找到并选中重名的Ability，单击右键，选择"Refactor > Rename"，重命名文件。

## 智慧生活App中自动出现设备弹框，是否利用了靠近发现能力

不是。靠近发现与智慧生活App的设备发现功能的主要区别如下：

* 靠近发现是一种基于设备芯片的Wi-Fi或蓝牙广播的连接能力。只需将HarmonyOS手机靠近设备（距离大约在30cm以内），无需打开智慧生活App，即可发现设备并在手机上弹框。
* 智慧生活App的设备发现功能是基于智慧生活基础服务的。因此必须在打开智慧生活App之后，才能自动扫描待配网状态的设备（持续1min），发现设备后会在智慧生活App中自动弹框。

## 智慧生活基础服务删除数据后，手机首次碰一碰拉起FA异常

**问题描述**

1. 智慧生活基础服务删除数据后，手机首次碰一碰拉起FA连接弹窗，弹窗中设备图片/设备名称/FA图标缺失。
2. 进入华为账号登录页后，点击"华为账号快捷登录"，出现如下现象：
   * 无法跳转到账号授权页面，导致FA闪退。
   * 进入账号授权页面，点击"授权"后无法跳转到配网页面，导致FA闪退。

**可能原因**

智慧生活基础服务删除数据后，手机首次碰一碰时，智慧生活基础服务会进行初始化操作，在初始化未完成前碰一碰拉起FA会导致以上异常现象。

**解决措施**

该现象属于智慧生活基础服务机制而非问题，若认证测试提出该问题可以申请豁免。

待智慧生活基础服务初始化完成后（实际所需时间与网络情况有关），重试碰一碰拉起FA，可以正常显示。

## 使用智慧生活App删除设备后设备无热点发出，但仍可以继续添加设备

**问题现象**

使用智慧生活App删除设备后，设备无热点发出，但是还可以继续添加设备。

**可能原因**

智慧生活App是通过局域网coap扫描出来设备，而非设备发出的热点。

**解决措施**

智慧生活App是通过局域网coap扫描出来设备，属于正常现象。

## 老蓝牙设备已添加至账号A，A账号还可以扫描发现该设备

**问题现象**

智慧生活App已经添加了老蓝牙设备，但仍可以扫描到该设备。

**可能原因**

伙伴通过H5代码进行设备注册时，MAC地址取值错误导致云端存储的MAC地址与实际扫描到的MAC不一致。APP无法过滤，当作新设备进行展示。

**解决措施**

伙伴修改H5关于设备注册MAC地址处理的代码逻辑。
