# 设备连接控制规范

本章节主要针对设备连接配对、设备控制等过程中的数据传输进行了规定。

#### 概述

主控设备通过广播发现可连接的星闪设备之后，需要建立通信通道，以实现彼此之间的数据传输。设备之间采用配对绑定，可以提升星闪链路传输的安全性。首次连接时，设备之间需要交换安全秘钥、并缓存秘钥。再次连接时，无需重复配对过程，能够以更快的安全启动速度实现连接。

#### 设备连接注册流程

设备连接注册流程主要分为以下三个阶段：

  1. **建立连接** ：主控设备与星闪设备之间使用华为通用UUID，建立SSAP连接。
  2. **代理注册** ：主控设备获取星闪设备的相关信息，并在云端代理注册。星闪设备接收并存储AuthCode，用于数据传输过程的加密。该过程主要涉及如下服务。
     * 查询星闪辅助配网协议版本（netCfgVer）
     * 查询设备配网注册信息（deviceInfo）
     * 发送authCode至设备（authSetup）
  3. **断开连接** ：主控设备与星闪设备之间 断开SSAP连接。

#### 设备控制流程

设备控制流程（含数据加解密）主要分为以下三个阶段：

  1. **建立连接** ：主控设备与星闪设备建立SSAP连接。
  2. **协商秘钥** ：主控设备与星闪设备创建会话并协商秘钥（SN1、SN2），详见创建会话（createSession）。
  3. **加密传输** ：对于控制报文和响应报文，均需要经加密处理后再进行数据传输。传输结束后，断开SSAP连接。



数据传输均需使用customSecData服务，典型场景包括：查询设备状态、查询设备所有服务、查询设备信息、控制设备状态、设备主动上报等。

  * 设备连接：使用华为通用UUID建立SSAP连接。



华为SSAP服务声明为Primary Service，包含读、写两个属性，具体说明参见表星闪基础服务Profile

- | - | readData | 15f1**e601** -a277-43fc-a484-dd39ef8a9100 | indicate/read | String  
- | - | writeData | 15f1**e602** -a277-43fc-a484-dd39ef8a9100 | write | String

主控设备与星闪设备协商的MTU（Maximum Transmission Unit）范围为160~500字节， 默认协商的MTU为251字节。

  * **设备配对** ：推荐使用Just Works配对模式。



Just Works适用于无交互界面的星闪设备（例如星闪耳机），由主控设备发起连接即可完成配对，用户无需在被连接的星闪设备上进行操作。

此外，星闪设备需要支持iOS系统协商为免配对接入。

  * **设备控制** ：
    * 已存在SIG Profile的设备（如血压计、血糖仪等）：采用SIG Profile定义的设备能力。在设备发现、配对阶段，使用华为通用UUID的SSAP通道，设备注册完成后即断开连接。在设备控制阶段，使用SIG标准UUID建立连接。
    * 不存在SIG Profile的设备（如二轮车、点读笔等）：优先采用华为Profile定义的设备能力。在设备发现、配对、控制阶段，均使用华为通用UUID的SSAP通道。



#### 数据传输规范

星闪设备的数据在应用层传输时，需要遵循华为通用的格式要求。

单个数据包最大251字节，由Header与Payload组成，Header长度为7字节，Payload长度最大为244字节。

支持分包传输，分包传输时Payload总长度最大为500字节。

#### 通用服务规范

**查询星闪辅助配网协议版本（netCfgVer）**

建立SSAP连接后，主控设备会通过netCfgVer服务，查询星闪辅助配网协议版本。星闪设备收到请求后，返回协议版本。

  * **加密方式** ：不加密
  * **请求格式** ：
    * 当请求为空时，表示主控设备为手机。
    * 当请求格式如下时，表示主控设备为网关。


    
    
    {"source":"gw"}

  * 响应格式：


    
    
    {"ver":%d}

**表2** 响应参数说明参数 | 类型 | 说明  
---|---|---  
ver | int | 星闪辅助配网协议版本，取值如下：

  * 2：采用HiChain1.0认证方式接入。
  * 3：采用HiChain3.0认证方式接入，默认支持设备与手机直连。
  * 4: 协商采用HiChain 3.0 Speke认证方式，控制采用Authcode加密。
  * 5：协商采用HiChain 3.0，控制采用HiChain 3.0加密。既支持设备与手机直连，又支持设备与网关连接。
  * 100~199：采用本协议规范接入，默认为100。

  * **加密方式** ：基于AuthCode派生秘钥
  * **请求格式** ：无
  * **响应格式** ：

    "productId":"%s",  
    "sn":"%s",  
    "vendor":[{ 
            "devId":"%s",  
            "deviceInfo":%s, 
            "serviceInfo:":%s}] 
    }

其中，deviceInfo取值格式如下:

  * **Comb****设备（Wi-Fi+BLE+SLE****）：**
        
        {"sn":"%s","model":"%s","devType":"%s","manu":"%s","prodId":"%s","mac":"%s","blemac":"%s","slemac":"%s","hiv":"%s","fwv":"%s","hwv":"%s","swv":"%s","protType":"%s"}

  * **Comb****设备（BLE+SLE****）：**
        
        {"sn":"%s","model":"%s","devType":"%s","manu":"%s","prodId":"%s","blemac":"%s","slemac":"%s","hiv":"%s","fwv":"%s","hwv":"%s","swv":"%s","protType":"%s"}

#### [h2]发送authCode至设备（authSetup）

星闪设备注册成功后，主控设备会从云端获取authCode、并通过authSetup服务将authCode下发至星闪设备。星闪设备需要存储该值，用于后续数据传输的加解密。

  * **加密方式：** 不加密
  * **发送格式：**
        
        {
        "devId":"xxxx",
        "authCode":"xxxx",
        "uidHash":"xxxx",
        "authCodeId":"xxxx"
        }

其中，authCode的长度为32字节，由16bytes的二进制数据转成16进制字符串而成。




#### [h2]创建会话（createSession）

主控设备通过createSession服务，请求创建会话并协商会话秘钥。星闪设备返回响应，会话创建成功。

  * **加密方式：** 不加密


  * **请求格式：**
        
        {
        "seq":%s,
        "uuid":"%s",
        "uidHash":"%s",
        "sn1":"%s"
        }

**表4** 请求参数说明参数 | 类型 | 说明  
---|---|---  
seq | String | 连接序列号，每次递增。  
uuid | String | 手机的唯一标识。  
uidHash | String | UID的Hash值。  
sn1 | String | 协商的sn1参数，用于计算秘钥盐值。  
  
  * **响应格式：**
        
        {
        "seq":%s ,
        "sessId":"%s",
        "sn2":"%s" ,
        "authCodeId":"%s"
        }

**表5** 响应参数说明参数 | 类型 | 说明  
---|---|---  
seq | String | 连接序列号，每次递增。  
sessId | String | 设备分配给手机的会话ID，长度为32个字节的随机字符串。  
sn2 | String | 协商的sn2参数，用于计算秘钥盐值。  
authCodeId | String | 采用的authCode序号。  
  



#### [h2]查询设备状态（customSecData）

主控设备通过customSecData服务，查询设备状态（携带具体sid）。星闪设备收到请求后，返回查询结果或错误码。

![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/54/v3/PZdkJ8_eSJGfc8A6QLVR_w/note_3.0-zh-cn.png?HW-CC-KV=V1&HW-CC-Date=20261005T090859Z&HW-CC-Expire=86400&HW-CC-Sign=70F11185EC8C80CD69BA72CD407877FEE5C35F0EED06497C2AB590740FBED4F6)

vendor中各字段的取值必须与华为Profile保持一致。

  * **加密方式：** spekeKey/sessionKey
  * **请求格式：**
        
        {
        "seq":%s,// 为递增数字
        "vendor":[{
                "sid":"onoff"}]
        }

  * **响应格式：**
    * 执行成功，返回具体查询结果。
          
          {
          "seq":%s,// 为递增数字
          "vendor":[{
                  "sid":"onoff",
                  "data":{"onoff":0}
                  }]
          }

    * 执行失败，返回错误码。
          
          { "errcode": xxx}

查询成功后，蓝牙设备还需要主动上报所有服务状态，参见设备主动上报。

  * **加密方式：** spekeKey/sessionKey

#### 代理删除设备（authdelete）

星闪设备在同一时间段只能与一个用户仅绑定。通过authdelete服务，解除星闪设备与老用户的绑定关系后，才能与新用户进行绑定。

**图4** 设备代理删除流程：  
![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/46/v3/ryIyRHanT7-kAFDs5nN3HA/zh-cn_image_0000002484664570.png?HW-CC-KV=V1&HW-CC-Date=20261005T090859Z&HW-CC-Expire=86400&HW-CC-Sign=62BC21A45BE1142837B5010CB5EA1BC81A7CA49BF7E625BDBC33F9BBE7460845)

  * **加密方式：** 无


  * **请求格式：**
        
        { "challenge": "xxxx"}



  * **响应格式：**
    * 执行成功，返回sigvalue取值。
          
          { "sigvalue": "xxxx"}

其中，设备签名参数sigvalue的计算方法如下：

      1. 根据prk与info，计算okm的取值。

prk = extract(authcode)

info ="Device-Revoke"

okm= expand(prk, info)

      2. 采用hmac-sha256算法，计算签名参数。

sigvalue = hmac(devId+challenge+authcodeId, okm)

其中，authcode、devId、authcodeId在设备注册时均存储在Flash中。devid、challenge、authcodeId以及okm，均使用字面字符的直接byte[]、无需转为原始字节数组byte[]，String到byte数组的转换统一按UTF-8处理。

    * 执行失败，返回错误码。
          
          { "errcode": xxx}




#### [h2]恢复出厂设置（clearDevRegInfo）

主控设备通过clearDevRegInfo服务，发送恢复出厂设置指令。星闪设备收到请求后，清除设备已注册的信息。

  * **加密方式：** 基于Authcode派生秘钥


  * **请求****格式****：**
        
        {"devId":"%s"}
