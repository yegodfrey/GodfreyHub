# 设备升级规范

本章节主要介绍设备升级流程、以及升级过程中常用指令的使用规范。

#### 升级流程

OTA升级流程主要分为新版本检测、版本下载与校验、版本升级三个阶段。

  1. 新版本检测：涉及App与蓝牙网关的交互，不作详细介绍。
  2. 版本下载与校验：主要包括建立GATT连接、查询设备信息、协商升级参数、检查升级参数等指令。
  3. 版本升级：主要包括传输升级包、上报升级结果、上报升级错误信息等指令。

#### 通用要求

  * **OTA升级使用华为通用UUID建立GATT连接。**

蓝牙OTA服务包含两个属性：otaCtrl（控制通道）和otaData（数据通道），具体说明参见表1。

    * otaData（数据通道）：OTA升级文件通过拆包后从数据通道发送。数据通道采用不带应答的write，以提高传输效率。
    * otaCtrl（控制通道）：除了传输升级包，其他的升级指令都需要采用控制通道。控制通道采用带应答的写和带应答的通知。

**表1** 蓝牙OTA服务Profile服务 Service ID | 服务UUID Service UUID | 服务类型 Service Type | 属性 Characteristics | 属性UUID Characteristic UUID | 属性类型 Character Type | 操作权限 Permissions  
---|---|---|---|---|---|---  
ota | **15f1e610-a277-43fc-a484-dd39ef8a9100** | ota | - | - | - | -  
- | - | - | otaCtrl | **15f1e611-a277-43fc-a484-dd39ef8a9100** | characteristic.otaCtrl | indicate/write  
- | - | - | otaData | **15f1e612-a277-43fc-a484-dd39ef8a9100** | characteristic.otaData | write  
  
  * **蓝牙设备升级过程中控制通道不能断开。**

在蓝牙设备版本升级过程中（不含设备重启过程、重启后的离线升级过程），必须支持蓝牙控制通道与GATT连接通道的共存，确保可以控制设备。

  * **蓝牙设备支持主备双备份** 。

由于OTA升级过程中可能存在各种异常而导致中断失败，因此设备都必须要支持在非易失性介质中备份版本，即升级区和版本运行区为两个独立分区保存。




#### 建立GATT连接

#### [h2]长上电设备与浅度休眠低功耗设备

  1. 由网关下发0xE200给设备，指令下发需要采用Set State指令，设备需要回复，设备回复内容默认为0。
  2. 设备收到网关下发的连接指令后，开始发送可连接广播，可连接广播包请参见[HarmonyOS Connect蓝牙BLE设备接入规范中设备名称广播](https://device.harmonyos.com/cn/docs/devicepartner/DevicePartner-Guides/device-development-ble-specifications-advertising-0000001352545729#section18727163214500)。
  3. 网关收到可连接广播后，与设备建立GATT连接。



属性名称 | Attribute Type | 数据结构 | 说明  
---|---|---|---  
GATT连接认证码 | 0xE200 | uint8 gattConn[5] | 建立GATT连接，用于设备升级。 设备回复内容默认为0。  
  
#### [h2]深度休眠低功耗设备

  1. 深度休眠低功耗设备每隔24小时向网关发送一次版本升级请求。采用State Change Notify（0xD4027D）指令。 

属性名称 | Attribute Type | 数据结构 | 说明  
---|---|---|---  
深度休眠低功耗设备升级 | 0xE106 | uint8 deviceType[4] | deviceType[4]参数内容保留。  
  
  2. 设备等待网关回复，超时时间为3秒。在此期间，设备不进入休眠状态。
     1. 如果收到网关回复1（表示有升级版本），发送可连接广播1分钟。
     2. 如果收到网关回复0（表示无升级版本）、或者在超时时间内未收到网关回复，则设备进入休眠状态。
  3. 网关收到可连接广播后，与设备建立GATT连接。

#### 协商升级参数

传输升级包之前，网关需要确认设备最大缓冲包数量。

网关下发OTA升级包是以轮为单位，每一轮所有分段连续下发后，网关会等待设备通过0x8081上报正确收到的包。最大缓冲数据包数量是指每一轮中连续下发的分段个数（最大不得超过64）。

Payload | n | 无  
上行（设备侧 → 主控侧） | 应答/上报 | Command | 2 | 0x8001  
Payload | n | 详见表2 Payload字段说明。  
  
**表5** 协商升级参数-Payload字段说明字段 | 说明 | 长度（字节） | 取值

#### 检查升级参数

升级开始之前，需要检查升级参数是否匹配。

  1. 网关给设备下发OTA头信息（0x0002）。
  2. 设备收到OTA头信息（0x0002）后，检查是否满足升级条件。具体匹配规则如下：
     * 头信息的Product ID与设备的Product ID一致。
     * 头信息的Hw Version与设备的Hw Version一致。
     * 头信息的SW Version ＞ 设备当前SW Version。
     * 头信息的Totle Size ≤ 设备为运行程序分配的最大flash空间。
  3. 根据上述升级条件的匹配结果，来确定是否执行升级操作。
     * 如果匹配成功，则通过0x8002应答success。
     * 如果匹配失败，则通过0x8002返回相应错误码。

  * 0x00：匹配成功可以升级。有新版本，手机侧提示红点。
  * 0x01：匹配与运行版本相同。无新版本不需要升级。
  * 0x02：Product ID不匹配。

  * 0x04：Firmware Version错误。
  * 0x05：Hw Version不匹配。
  * 0x06：OTA文件大小超过最大值。
  * 0x07：当前设备状态无法升级。

  
  
#### 传输升级包

  1. 网关采用otaData数据通道，将OTA升级文件分包下发给设备。

网关每一轮下发MaxSegCacheNum个数据包分段，并等待设备端应答。每次发送数据包时，其长度与MTU相等，MTU不要太大（几十个字节即可），以免强干扰下长数据包发送不成功。

  2. 设备回复OTA升级文件接收结果（0x8081）。

当设备收到本轮发送的最后一个数据包、或达到设定的超时时间仍未收到本轮最后一个包时，设备发送数据包应答。

     * 本轮传输的超时时间 = 已收到的相邻包之间的最大时间间隔 ×（总共传输的包数-已收到的包个数+n）。之所以加n，是为了追加n个包的时间间隔冗余，n的取值范围为（1~每轮最大包数），通常取个3左右。每收到一个新的分段，需要重新评估本轮数据分段接收的超时时间。

例如，下图中绿色表示本轮已收到的包（seg 0/1/2/3/5），红色表示未收到的包，则收到seg 9的超时时间**= max（T1，T2，T3，T4/2）×（**9 - 5 + n** ）**。

![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/d6/v3/2lA8ul9-TUiO7DsCnPTdmQ/zh-cn_image_0000001430061180.png?HW-CC-KV=V1&HW-CC-Date=20261005T090900Z&HW-CC-Expire=86400&HW-CC-Sign=2687C9570B4ACB9808B14A442DDCA1B7950CB4AFE75C6DD7F6847BD309C806C4)

     * 如果第一轮还未收到两个包，无法计算包传输的最大时间间隔，则最大时间间隔可以设置为200ms。
     * 新一轮开始时，包传输的最大时间间隔沿用上一轮取值。待收到新一轮数据分段的第二个分段后。再重新计算最大时间间隔。
     * 设备每轮预期收包最大超时时间为15s，响应重传2次，每次间隔15s；即网关从每轮发包开始到收到响应结束的最大预期时间为45s。如一轮发10包，网关除200ms*10发包外，冗余43s等待响应；设备按照都未收到包，则第15s发送第一次响应，此后间隔15s重发2次。

如果设备包含模组和MCU，则由模组完成升级文件的数字签名SHA256校验，MCU不做数字签名校验。MCU与模组都要升级成功，才能上报升级成功。

#### 上报升级错误信息

当设备升级出错时，上报错误信息（0x8000）。主控侧任何时候收到升级错误信息（0x8000），即结束升级并上报错误原因。

与上报升级结果指令不同，上报升级错误信息指令可以用于整个升级过程的任何阶段，而上报升级结果指令只能用于升级结束之后。
