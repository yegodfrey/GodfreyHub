# Vendor Model规范

接入HarmonyOS Connect生态的蓝牙Mesh设备，需要满足蓝牙Mesh标准协议的SIG Model、以及扩展协议的华为Vendor Model。华为Vendor Model是由华为自定义的规范，在Mesh系统架构处于Model层（Model Layer），可以解决蓝牙Mesh标准中支持的品类与操作受限的问题。

![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/28/v3/gWRgXbJmSZKeTUl0Dzl_zA/zh-cn_image_0000001474731125.png?HW-CC-KV=V1&HW-CC-Date=20261005T090900Z&HW-CC-Expire=86400&HW-CC-Sign=A71840B6ECE4DD9E4FAFC8300205997A208B0F997F01F230E916B9FE6C728654)

  * **SIG Model中已定义的功能：** 当前仅支持灯的开关（modelId：0x1000）、亮度（modelId：0x1300）、色温（modelId：0x1306）、场景（modelId：0x1203）。
  * **其他功能：** 伙伴可以通过华为Vendor Model来扩展实现设备控制与设备状态上报等能力，例如门窗开关事件上报（0xE101）。



#### Vendor Model ID

当SIG Models无法满足实际功能需求时，可采用自定义的Vendor Models来定义节点功能。每个Model在Mesh网络中都必须具有唯一标识符（即Vendor Model ID），以确保Model之间可以相互识别。

Vendor Model ID采用4字节的标识符，格式为“**0x yyyy zzzz** ”，字段说明参见表1。

**表1** Vendor Model ID格式字段 | 长度（字节） | 说明  
---|---|---  
yyyy | 2 | 厂商自定义ID。最多可自定义256个Model。  
zzzz | 2 | Company ID，使用华为申请值0x027D。  
  
由于蓝牙Mesh采用Client-Server架构通信，Model也可分为Server Model和Client Model两类。

  * **Server Model** ：提供Model实现的服务，包括为实现设备元素基本功能而定义的状态（States）、一组可作用于状态的消息（Messages）、以及响应消息的行为（Behaviors）等。
  * **Client Model** ：请求Model实现的服务，可以通过特定的消息（Messages）查询或更改Server Model定义的状态（States）。



Vendor Model中定义了Server Model和Client Model对应的ID（见表2），以便于进行消息扩展，同时vendor model需要支持建组。

**表2** Server Model与Client Model的ID类型 | **Model名称** | Vendor Model ID  
---|---|---  
Mesh网关 | Client Model | 0x0002 0x027D 采用小端字节序，实际编码为 0x7D020200  
Mesh设备 | Server Model | 0x0001 0x027D 采用小端字节序，实际编码为 0x7D020100  
  
#### Vendor Model消息结构

Model间交互的消息主要由操作码（Opcode）和相关参数（Parameters）组成。每种类型的消息都由唯一的Opcode标识，Parameters根据不同Model所要传递的信息不同而不同。

消息需要通过访问层（Access Layer）传递，格式参见表3。消息中的数据均采用**小端模式** 。

  * 采用不分包传输（Unsegmented）时，消息总长度不超过11字节，Attribute Value长度不超过5字节。
  * 采用分包传输（Segmented）时，消息总长度不超过380字节，Attribute Value长度不超过374字节，原则上不建议采用分包传输。



**表3** 消息字段说明字段 | 子字段 | 长度（字节） | 说明  
---|---|---|---  
不分包 | 分包  
Opcode | - | 3 | 3 | 表示该消息需要进行的操作。详见操作码（Opcode）。  
Parameters | TID | 1 | 1 | 表示消息包的序号。自动生成，每条新消息序号递增，确保接收的消息包不重不漏。  
Attribute Type | 2 | 2 | 表示控制或者上报状态的属性类型，比如开灯的亮度等。 取值范围为0x0000~0xFFFF。  
Attribute Value | ≤5 | ≤374 | 表述属性类型对应的取值，比如灯的亮度值、上报的事件类型。  
  
vendor model与sig mesh协议一致，设备接收并处理网关的消息，除非该消息的SRC/DST/TID值与过去6s收到的消息一致。

#### 操作码（Opcode）

不同类型的消息都有一个唯一的操作码。Vendor Model的操作码均为3字节，格式为“0b **11yyyyyy zzzzzzzz zzzzzzzz** ”，字段说明详见表4。

**表4** Opcode格式说明字段 | 长度（字节） | 说明  
---|---|---  
11yyyyyy | 1 | 最高位11为固定值，yyyyyy由厂商自定义。最多可支持64个Vendor Opcode。  
zzzzzzzz zzzzzzzz | 2 | Company ID，使用华为申请值0x027D。  
  
常用消息对应的操作码参见表5。 

**表5** 消息操作码消息类型 | 操作码 | 消息方向与用途  
---|---|---  
Get State | 0xD0027D | 网关侧 → 设备侧，获取设备信息。  
Set State | 0xD1027D | 网关侧 → 设备侧，设置设备信息。  
Set State Unack | 0xD2027D | 网关侧 → 设备侧，设置设备信息、且无需设备响应。  
Set State Status | 0xD3027D | 设备侧 → 网关侧，设备响应“Set State”消息。  
State Change Notify | 0xD4027D | 设备侧 → 网关侧，上报设备状态、且需要网关回复，用于关键事件上报，即对人和财产造成重大影响的事件，比如烟雾、水浸、燃气报警事件。  
State Change Notify Status | 0xD5027D | 网关侧 → 设备侧，网关响应“State Change Notify”消息。  
State Change Notify Unack | 0xD6027D | 设备侧 → 网关侧，上报设备状态、且不需要网关回复，用于非关键事件上报。  
Get State Status | 0xD7027D | 设备侧 → 网关侧，设备响应“Get State”消息。  
Set State Unack Unreport | 0xD8027D | 网关侧 → 设备侧，设置设备信息、且无需设备响应和无需设备数据上报。

产品Profile中定义了HarmonyOS Connect生态中蓝牙Mesh设备的功能属性。如果当前的Profile属性不能满足实际功能需求，请联系华为产品经理增加Profile及对应的Mesh指令。

  * Attribute Type：由属性类型确定。
    1. 在《产品Profile与蓝牙Mesh指令映射关系表》中，根据产品Profile中的功能标识SID（A列）+属性Characteristics（D列），确定功能属性所在行。
    2. 在功能属性所在行，查找蓝牙Mesh指令Attribute Type（L列）的对应值，即为Attribute Type的取值。
  * Attribute Value：由属性类型、消息类型共同确定。
    1. 在《产品Profile与蓝牙Mesh指令映射关系表》中，根据产品Profile中的功能标识SID（A列）+属性Characteristics（D列），确定功能属性所在行。
    2. 在功能属性所在行，查找Opcode（K列）的对应描述，可以获取当前属性支持的消息类型与操作码。
    3. 参考表6，根据消息类型或操作码查找对应的蓝牙Mesh指令，并在《产品Profile与蓝牙Mesh指令映射关系表》中明确蓝牙Mesh指令所在列。 

**表6** 消息与指令的映射关系消息名称 | 操作码 | 蓝牙Mesh指令  
---|---|---  
Get State | 0xD0027D | (GET) Request Payload  
Set State | 0xD1027D | (SET) Request Payload  
Set State Unack | 0xD2027D | (SET) Request Payload  
Set State Status | 0xD3027D | (SET) Response Payload  
State Change Notify | 0xD4027D | (STATUS) Report Payload  
State Change Notify Status | 0xD5027D | (STATUS) Response Payload  
State Change Notify Unack | 0xD6027D | (STATUS) Report Payload  
Get State Status | 0xD7027D | (GET) Response Payload  
Set State Unack Unreport | 0xD8027D | (SET) Request Payload  
  
    4. 根据功能属性所在行、蓝牙Mesh指令所在列，查找到Attribute Value的字段说明。再结合产品Profile的Valid Values（H列）、以及Mesh数据类型（S列），可以确定具体取值。

特别地，对于浮点类型的数据（即产品Profile中Format列为“float”的数据），需要满足如下要求。其他类型数据的格式与标准协议相同。

       * 长度：4字节。
       * 规则：float数据取值范围为（-214748.0000， 214748.0000），精度为0.0001。空口传输时，发送端发送时数据乘以10000，按照int传输，接收端收到后除以10000。
       * 举例：
         * 例1：28.4，Mesh设备上报284000，网关解析后，还原成28.4。
         * 例2：0.2，Mesh设备上报2000，网关解析后，还原成0.2。
         * 例3：-0.3，Mesh设备上报-3000，网关解析后，还原成-0.3。
