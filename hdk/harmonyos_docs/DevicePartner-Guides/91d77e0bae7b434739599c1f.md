# 设备控制规范

#### 通用要求

#### [h2]组播地址配置规则

  * 多网关下每个网关可以分配64个组播地址。设备的每个Model至少支持52个组播地址。
  * 组播地址范围为0xC000~0xFEFF，其中自定义组播地址范围0xD001~0xDFFF。有两个常用的组播地址定义如下： 

**表1** 常用组播地址组播地址名称 | **组播地址取值**  
---|---  
所有网关的组播地址 | 0xF000  
所有设备的组播地址 | 0xCFFF  
  
  * 当添加/删除组播地址的指令（Config Model Subscription Add/Config Model Subscription Delete）下发到设备的某个element时，设备需要支持当前element下的所有Model与分配的组播地址一次性绑定/解绑，无需对该element中的每个Model逐个下发指令。 

**表2** 添加/删除指令参数说明参数 | 说明  
---|---  
ElementAddress | 元素地址  
Address | 待绑定/解绑的组播地址。  
ModelIdentifier | Model标识符。取值可以为当前element下的任何一个Model的ID，均能达到相同的绑定/解绑效果。  
  



#### [h2]Scene配置规则

  * 一个设备至少支持26个Scene ID的配置。
  * 调用场景状态的指令（Recall Messages）中的Option参数暂未启用。



#### [h2]心跳配置规则

  * 网关通过心跳判别设备状态：如果连续三个周期未收到设备心跳，则认为设备离线。 

设备类型 | 心跳周期  
---|---  
长上电设备、浅度休眠低功耗设备 | 网关通过Config Heartbeat Publication Set指令，设置设备的心跳周期为128s。  
深度休眠低功耗设备 | 设备每30分钟唤醒一次，上报的任意状态都可以作为心跳识别。  
  
  * 设备订阅网关心跳：当设备收到网关下发的Config Heartbeat Subscription Set指令后，需要订阅网关的心跳地址。如果设备在512s内未收到网关心跳或其它报文，则认为网关离线，此处仅用于支持网关离线时本地控制的场景。



#### [h2]其他功能要求

  * 设备需要根据接收到的指令中的地址为组播地址、Scene地址或单播地址，来配置广播随机时延的生效或失效。
    * 组播地址或Scene地址：设备回复指令时，需要配置广播时延生效，即设备在收到组控指令后，随机时延0~300ms上报。
    * 单播地址：设备回复指令时，保持默认（默认广播时延失效），按标准规范要求发送。
  * 长供电且不会关闭Rx接收的设备，必须具备Relay功能，建议具备Friend功能。设备的Relay功能默认关闭，网关可通过指令Config Relay Set开启。

Relay与Friend功能的具体实现可以参见蓝牙Mesh标准协议。

  * 低功耗设备上电/重启、或完成配网后，至少延迟1分钟才能进入休眠，以便与网关进行指令交互。
  * 设备发送Beacon报文的时间间隔 = 观测周期 * (观测Beacon个数 + 1) / 预期Beacon个数。如果间隔时间小于10s，则取10s；如果时间间隔大于10min，则取10min。例如，取一段观测周期5min，预期收到10个Beacon报文，实际收到9个，则间隔时间为5min。
  * 深度休眠低功耗设备移动后长时间未收到Beacon，需要在重启时唤醒超过30s，至少覆盖2个周期。对于功耗影响小的设备，可以额外再增加每48小时唤醒至少15s来接收Beacon报文。
  * 设备侧不能仅接收配网网关的消息，需要支持其他设备发送的控制指令、订阅消息等。
  * 设备侧RPL表至少支持缓存30个，避免发生重放攻击。



#### 指令基本要求

  * **设备侧 → 网关侧：**
    * 当设备状态发生变化时（例如，设备上电、重启，或用户对设备进行操作），需要向所属网关MAC地址主动上报，不允许向网关组播组0xF000发送，包括上报设备状态、上报设备版本号、以及浅度休眠低功耗设备上报唤醒占空比等。
    * 设备在启动后、或者当收到组控指令后，按照0~300ms随机时延上报变化的状态。
    * 通常情况下，设备发送的指令无需网关回复。仅在某些情况下（例如深度休眠低功耗设备查询升级版本、事件类消息上报）必须要求网关进行回复。两类设备指令的具体说明如下： 

**表3** 两类设备指令说明指令分类 | 重传机制 | 指令说明  
---|---|---  
**无需网关回复** 的设备指令 | 
      * 应用层：只发送一次，不做重试。
      * 网络层：重传8次，每次重传间隔不能大于30ms。
| 
      * 对于SIG Model中定义的功能，优先采用标准指令上报。
      * 对于Vendor Model中定义的功能，采用自定义指令State Change Notify Unack（0xD6027D）上报。  
**需要网关回复** 的设备指令 | 
      * 应用层：总共重传5次，1秒重试一次，直到收到回复或者超时停止。
      * 网络层：重传8次，每次重传间隔不能大于30ms。
| 设备采用自定义指令State Change Notify（0xD4027D）上报，网关采用自定义指令State Change Notify Status（0xD5027D）回复。  
  


  * **网关侧****→ 设备侧：**

设备收到网关下发的指令后，需要根据指令类型进行响应（或不响应）。
    * 网关上电或重启后发送Get State（0xE001）指令，设备收到本指令后，需要上报支持的所有状态。自定义的Vendor Model必须以Get State Status的方式上报，标准的Model以标准指令上报，例如开关、亮度、色温。
    * 网关下发Get State（0xD0027D）指令查询设备信息，设备需要采用Get State Status（0xD7027D）进行响应。例如，根据网关的查询指令上报设备能力。
    * 网关下发Set State（0xD1027D）指令设置设备信息，设备需要采用Set State Status（0xD3027D）进行响应。
    * 网关下发Set State Unack（0xD2027D）指令设置设备信息，设备无需响应。




#### 上报设备状态

设备启动（上电或重启）后，必须向所属网关MAC地址主动上报其支持的所有状态，不允许向网关组播组（0xF000）上报。上报采用State Change Notify Unack指令。

设备所需上报的状态，举例如下：

  * 单色灯：必须上报开关和亮度状态。
  * 插座/开关：必须上报开关状态。
  * 门窗开关传感器：必须上报门状态、电池电量。开门事件和防拆报警事件均属于事件类，而非状态类，不允许在上电时上报。



为了实现设备状态改变时，能够按照指定的广播地址、重试次数等要求自动上报，设备需要自行调用Config Model Publication Set上报参数。

#### 上报设备版本号

设备启动（上电或重启）、或配网完成后，需要向网关主动上报设备版本号，上报采用State Change Notify Unack（0xD6027D）指令。

![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/be/v3/_Kv_VahSQDafzU2dOovbOQ/note_3.0-zh-cn.png?HW-CC-KV=V1&HW-CC-Date=20261005T090900Z&HW-CC-Expire=86400&HW-CC-Sign=5EEF86E42335213917E497303A165FA796CC77281B775CBB6CE34C96D30F0702)

如果网关超时未收到设备的上报，会下发0xE005查询设备版本号。

执行指令 | Attribute Type | 数据结构 | 说明  
---|---|---|---  
上报软硬件版本信息 | 0xE005 | uint8 versionNumber[5] | 

  * byte0~1：软件版本号。例如版本号“1.0”，“0”放在byte0，“1”放在byte1。
  * byte2~3：固件版本号。例如版本号“2.3”，“3”放在byte2，“2”放在byte3。
  * byte4：硬件版本号。例如"1"，"2"。

  
  
#### 上报设备能力

当网关下发0xE160查询设备能力时，设备需要返回子设备支持的通用能力。目前通用能力包括两种：支持远程诊断、支持触发条件或执行动作与Scene ID关联。

执行指令 | Attribute Type | 数据结构 | 说明  
---|---|---|---  
上报设备能力 | 0xE160 | uint8 capability[5] | 每个bit代表一种能力是否支持，0-不支持，1-支持。

  * byte0-bit0：支持远程诊断。
  * byte0-bit1：支持触发条件或执行动作与Scene ID关联。该能力当前仅适用于开关类设备。
  * byte0-bit2：支持控制后设备不响应不上报能力。
  * 其它：预留。

  
  
  * **支持远程诊断**
    1. 设备收到网关Attribute Type 0xE160指令后，通过0xE160的byte0-bit0返回给网关，声明支持远程诊断能力。
    2. 网关通过下发Attribute Type 0xE161指令，启动设备的远程诊断。
    3. 设备诊断结束后，使用Attribute Type 0xE162上报诊断结果。

执行指令 | Attribute Type | 数据结构 | 说明  
---|---|---|---  
启动远程诊断 | 0xE161 | uint8 diagnosis.action | 
    * 0：无动作。
    * 1：启动远程诊断。  
远程诊断结果上报 | 0xE162 | uint8 diagnosis.diagFaultId[3] | 蓝牙设备回复参数。其中的每个bit代表一个故障码，bit与故障码的转换关系由网关实现。
    * byte0：故障ID标识，每个bit位代表一个故障，上报0x00表示无故障。网关转换时bit0对应101，bit对应102，依次类推，bit7对应108。
    * byte1：建议ID标识，每个bit位代表一个建议，上报0x00表示无建议。网关转换时bit0对应201，bit1对应202，依次类推，bit7对应208。
    * byte2：修复ID标识，每个bit位代表一个修复。上报0x00表示无修复。网关转换时bit0对应301，bit1对应302，依次类推，bit7对应308。  
  
  * **支持触发条件或执行动作与Scene ID关联**

开关类设备支持触发条件或执行动作与Scene ID关联，以实现场景联动。

    1. 设备收到网关Attribute Type 0xE160指令后，通过0xE160的byte0-bit1返回给网关，声明支持触发条件或执行动作与Scene ID关联的能力。
    2. 由于Mesh标准协议不支持配置场景为某个执行动作，设备可以采用Attribute Type 0xE05F，保存scene ID和对应的动作。Scene ID的删除仍采用标准的Scene Delete。

执行指令 | Attribute Type | 数据结构 | 说明  
---|---|---|---  
保存动作的Scene ID | 0xE05F | uint8 saveSceneAct[5] | 
    * byte1~2：网关创建的Scene ID，下发给设备保存。
    * byte3~4：Attribute Type。
    * byte5：Value。  
  



#### 浅度休眠低功耗设备上报唤醒占空比

浅度休眠低功耗设备启动（上电或重启）、或配网完成后，需要上报唤醒占空比（即RX打开时间/RX关闭时间）。

  * 设备需要支持RX接收能力，供网关查询或者设置唤醒占空比。
  * 设备需要提供接口，供网关设置设备上报时延0~300ms。
  * 设备支持的唤醒占空比范围，在一个周期内RX打开时间≥30ms，RX关闭时间≤1000ms，且占空比≥10%，建议占空比采用60ms/160ms。支持的时钟精度为20ppm。



执行指令 | Attribute Type | 数据结构 | 说明  
---|---|---|---  
设备RX接收能力 | 0xE064 | uint8 rx.capbility[4] | 设备上报RX接收的打开时长与关闭时长。

  * byte1-2：打开RX天线的时长，单位ms。
  * byte3-4：关闭RX天线的时长，单位ms。

  
设置RX后的回复能力 | 0xE065 | uint8 rx.ackTimeSet[4] | 设备收到消息后，需要等待（x+n）ms，再做出应答。其中，x为固定时长，n为随机时延且n<=max。

  * byte1-2：接收到指令后的固定等待时间x，单位ms。
  * byte3-4：随机延迟最大时间max，单位ms。

  
  
#### 深度休眠低功耗设备接收缓存指令

当深度休眠低功耗设备处于唤醒状态时，方可接收网关下发的缓存指令，默认至少500ms唤醒的时间。缓存指令的接收规则优先采用标准蓝牙Mesh协议中的Friend方式。

如果深度休眠低功耗设备本身不支持Friend方式，则需要遵循华为蓝牙Mesh规范定义的规则，流程如下：

![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/fd/v3/uitI_Va5Tx638ZCLl5_kow/zh-cn_image_0000002577691208.png?HW-CC-KV=V1&HW-CC-Date=20261005T090900Z&HW-CC-Expire=86400&HW-CC-Sign=9F3CB38E60CEFD7E95F6DF4B6944D4CBC06BCBE2D10896562730CA4BAF3E8A90)

  1. 网关收到控制指令后不管设备是否唤醒都会直接发送一次，后续网关会判断设备是否处于唤醒状态。如果处于唤醒状态，网关需要进一步判断是否存在设备相关的缓存指令。
  2. 网关下发Attribute Type 0xE06E指令，将判断结果发送给设备。
  3. 设备收到Attribute Type 0xE06E指令：
     * 当内容值为1时，表示有缓存指令，需要保持唤醒状态。

设备在指定的唤醒时间内不休眠，唤醒时间取值通常为200~3000ms，默认500ms。后续设备每次收到缓存指令后，也保持同样的唤醒时间不休眠。

     * 当内容值不为1时，可以进入休眠状态。
  4. 网关采用Set State Unack，向设备逐条下发缓存指令。
  5. 待所有缓存指令发送完成后，网关下发Attribute Type 0xE06F指令，结束发送。
  6. 设备收到Attribute Type 0xE06F指令，可以进入休眠状态。
  7. 如果缓存指令为升级指令，网关采用Set state Ack、Attribute Type=0xE106（请参见[深度休眠低功耗设备](https://device.harmonyos.com/cn/docs/devicepartner/DevicePartner-Guides/device-development-mesh-specifications-upgrade-0000001352745513#section38748112449)）下发，设备收到并响应后需要发送1min可连接广播。此时网关发现有版本后开始进行升级。



执行指令 | Attribute Type | 数据结构 | 说明  
---|---|---|---  
是否存在设备相关的缓存指令 | 0xE06E | uint8 haveCmd | 

  * 1：有缓存指令，需要保持唤醒。
  * 其他：无缓存指令，可以进入休眠。

  
退出指令 | 0xE06F | uint8 cmdStatus | 0：指令发送结束。  
  
#### 深度休眠低功耗设备查询IV Index

  1. 深度休眠低功耗设备每隔一段时间（默认24小时，不超过48小时）唤醒后，需要从网关侧查询IV Index是否更新。设备唤醒时长建议不低于500ms。 

执行指令 | Attribute Type | 数据结构 | 说明  
---|---|---|---  
查询IV Index | 0XE070 | uint8 ivValue[5] | 请求参数：建议全部为0。  
  


  2. 网关接收到指令后，立即发送更新后的Secure Beacon报文。
  3. 设备收到Beacon报文后，如果IV Index有更新，则需要采用更新后的IV Index。
