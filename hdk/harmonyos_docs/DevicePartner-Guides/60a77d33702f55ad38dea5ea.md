# 设备注册

#### 入参说明

碰一碰或靠一靠根据设备的连接状态分为首次和再次。

* 首次表示未注册，此时手机与设备碰/靠后，将启动注册流程。
* 再次表示已注册，此时手机与设备碰/靠后，将启动控制流程。

当进行碰/靠操作时，由智慧生活基础服务拉起原子化服务。程序从[Ability](https://developer.harmonyos.com/cn/docs/documentation/doc-guides/ability-ability-overview-0000000000029852)开始执行，需要在Ability的onStart方法中对intent传入的参数进行解析，据此判断是启动连接流程还是启动控制流程。

* 首次（未注册）智慧生活基础服务传递参数如下所示：

  ```
  { 
      "empty": false, 
      "params": { 
          "ProtocolID": 21, 
          "bleMac": "************",  
          "businessInfo": { 
              "empty": false, 
              "params": { 
                  "91": "************************", 
              }, 
              "unpacked": true 
          }, 
          "guestStrategy":-1,
          "isBound": false, 
          "ohos.extra.param.key.INSTALL_ON_DEMAND": false, 
          "productInfo": "{productinfo}", 
          "sn": "************", 
          "source": "NFC", 
          "uuid": "********-****-****-****-************", 
          "tagUid ": "BPN8wklwgA==" 
      }, 
      "unpacked": true 
  } 
  ```

  未连接状态，intent不会携带deviceId信息，据此判断启动连接流程。  

  |参数名称|说明|
  |:----------|:-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
  |bleMac|表示设备BLE MAC地址。|
  |0X91|表示厂商自定义信息。|
  |deviceId|表示设备ID。|
  |productInfo|表示设备型号+设备子型号。|
  |source|表示拉起FA的方式，取值范围如下： * NFC：表示通过碰一碰NFC标签拉起FA。 * BT_ICONNECT：表示通过蓝牙靠近发现拉起FA。|
  |ProtocolID|表示设备与手机的连接方式。 * 当"source"为"NFC"时，ProtocollD的取值范围如下： * 0x00：仅采用Wi-Fi SoftAP配网。 * 0x01：优先采用Wi-Fi NAN配网，连接超时后采用Wi-Fi SoftAP配网。 * 0x02：采用蓝牙代理注册。 * 0x06：采用蓝牙辅助配网（不上云查询设备是否配网，不上家居云查管控策略）。 * 0x07：采用蓝牙辅助配网。 * 0x08：仅采用NFC标签。 * 0xFF：结束符，不可使用。 <!-- --> * 当"source"为"BT_ICONNECT"时，ProtocollD的取值需要先转换为二进制，再按照[表1 ProtocollD的取值说明](#ZH-CN_TOPIC_0000001165828400__table31304249121)进行判断处理。 例如，上面示例中接收到的值为"21"，转换成二进制为"10101"。具体含义参见[表1 ProtocollD的取值说明](#ZH-CN_TOPIC_0000001165828400__table31304249121)。|
  |sn|表示设备序列号。|
  |uuid|表示回调传入的随机数。|
  [表1 参数说明]

  |比特位|取值说明|
  |:---------|:--------------------------------------------------------------------------------------|
  |bit0|表示第二次碰一碰是否弹框。 * 0：不弹框。 * 1：弹框。|
  |bit1|预留，当前未启用。默认为"0"。|
  |bit2\~bit7|将bit2\~bit7转换成int值，取值标识的事件类型如下： * 0：表示弹出设备弹半模态控制框。 * 4：表示当前设备发生异常事件。 * 5：表示纯蓝牙设备请求代理注册。|
  [表2 ProtocollD取值说明]

* 再次（已注册）智慧生活基础服务传递参数如下所示：

  ```

          "businessInfo": { 
              "empty": false, 
              "params": { 
                  "91": "************************", 
              }, 
              "unpacked": true 
          }
          "deviceId": "********-****-****-****-************",  
          "isBound": false, 
          "ohos.extra.param.key.INSTALL_ON_DEMAND": false,  
           "productInfo": "{productinfo}", 
          "sn": "************", 
          "source": "NFC", 
          "uuid": "********-****-****-****-************", 
          "tagUid ": "BPN8wklwgA=="
      },

  }
  ```

已连接状态，intent会携带deviceId信息，据此判断启动控制流程。  

#### 设备注册

不同的连接方式要传递的参数不一样、跳转的页面也不一样，需要先对智慧生活基础服务传递过来的参数进行解析，再根据解析出来的字段判断是否蓝牙连接。示例步骤如下：

1. 在"entry"目录下的"MainAbility.java"文件中，在意图配置的Ability的onStart方法中对intent携带的参数进行解析，代码示例如下：

   <br />

   ```
   @Override 
   public void onStart(Intent intent) { 
       intent.setParam("window_modal", WINDOW_MODAL); 
       String deviceId = intent.getStringParam("deviceId"); 
       String uuid = intent.getStringParam("uuid"); 
       String productInfo = intent.getStringParam("productInfo"); 
       String productId = (productInfo != null && productInfo.length() >= 4) ? productInfo.substring(0, 4) : null;
       String subModelId = (productInfo != null && productInfo.length() >= 4) ? productInfo.substring(4, 6) : null;
       String source = intent.getStringParam("source");
       int businessStage = intent.getIntParam("businessStage", 0);
       Object businessInfo = intent.getParams().getParam("businessInfo");
       if (businessInfo != null) {
           ZSONObject objectBusinessInfo = ZSONObject.classToZSON(businessInfo);
           // 91字段是Demo中NFC里面烧录的业务自定义内容
           String data91 = objectBusinessInfo.getZSONObject("params").getString("91");
       }
       if (!TextTool.isNullOrEmpty(deviceId) && businessStage == CONFIG_COMPLETE) {
   	// TODO: 已经从智慧生活基础服务连接界面重新拉起原子化服务，设备已经注册完成，进入半模态控制界面 
       } else { 
   	// TODO: 拉起原子化服务场景，包括：帐号授权、设备注册等过程 
           super.onStart(intent); 
       } 
   }
   ```

   <br />

2. 在"entry"目录下的"EntryInternalAbility.java"文件中，根据解析的参数数据进行跳转判断逻辑，代码示例如下：

   <br />

   ```
   private static final String HILINK_NET_CONFIG_URI = "hilink://hilinksvc.huawei.com/device?action=deviceAdd&prodId=%s&fromApp=%s";

   /**
    * 跳转注册或控制界面判断
    */
   private void goNetConfigOrDevicePage() {
       if (EntryUtil.isEmpty(deviceId)) {
           // 设备未注册，进入智慧生活基础服务连接界面
   	openHiLinkNetConfig();
       } else {
           // 设备已注册，进入设备控制界面
       }
   }

   /**
    * 打开连接界面
    */
   private void openHiLinkNetConfig() {
       mContext.getUITaskDispatcher().asyncDispatch(() -> {
           String uriStr = String.format(Locale.ROOT, HILINK_NET_CONFIG_URI, productId, mContext.getBundleName());
           LogUtil.info(TAG, "openHiLinkNetConfig: uriStr = " + uriStr);
           Intent intent = new Intent();
           intent.setParam("uuid", uuid);
           Operation operation = new Intent.OperationBuilder()
                   .withDeviceId("")
                   .withFlags(Intent.FLAG_ABILITY_NEW_MISSION | Intent.FLAG_NOT_OHOS_COMPONENT)
                   .withAction("android.intent.action.VIEW")
                   .withUri(Uri.parse(uriStr))
                   .build();
           intent.setOperation(operation);
           mContext.startAbility(intent, -1);
           mContext.terminateAbility(); // 拉起 连接设置页面 的同时，关闭当前界面
       });
   }
   ```
