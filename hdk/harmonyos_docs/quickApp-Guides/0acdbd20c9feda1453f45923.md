# 折叠屏适配开发指南

折叠屏设备在展开和折叠时，屏幕的物理尺寸和分辨率（宽高比）会发生剧烈变化（通常从传统的16:9或20:9瞬间切换到接近1:1或4:3的近正方形比例）。为了保证玩家在折叠/展开设备时，游戏画面不拉伸、UI不错位且能获得最佳的视觉体验，开发者需要对小游戏进行动态响应式布局适配。  

#### 核心适配原则

1. 拒绝坐标硬编码。 切勿在游戏初始化时一次性缓存宽高并贯穿全场景，必须支持动态获取和实时更新。

2. 相对布局与锚点。 游戏内的UI元素（如血条、设置按钮、虚拟摇杆）应基于屏幕边缘（顶、底、左、右、居中）进行相对定位，或保持核心区比例不变，向两侧延伸背景，而非固定绝对坐标。

3. 黑边与裁剪平衡。 针对游戏主场景，设计合理的摄像机视野或视口裁剪策略，确保核心操作区在各种宽高比下均能完整显示。

#### 关键API

华为小游戏提供了获取窗口信息和监听尺寸变化的底层接口，这是实现折叠屏切换基础。

1. 静态获取。 使用[qg.getSystemInfoSync](https://developer.huawei.com/consumer/cn/doc/quickApp-References/quickgame-api-sysinfo-0000001083874626#section14651153111516)或[qg.getSystemInfo](https://developer.huawei.com/consumer/cn/doc/quickApp-References/quickgame-api-sysinfo-0000001083874626#section16231152791216)接口，在游戏冷启动、热启动初始化和感知到窗口变化时，获取当前设备的窗口尺寸和屏幕基础参数。

2. 动态监听。 使用[qg.onWindowResize](https://developer.huawei.com/consumer/cn/doc/quickApp-References/quickgame-api-window-0000002327339169#section14948251203111)接口，在玩家中途折叠或展开屏幕时立即触发回调，返回更新后的窗口尺寸。这是折叠屏适配最关键的触发入口。

#### 适配方案

1. 初始化画布与渲染分辨率。 在游戏入口脚本中，先通过[qg.getSystemInfoSync](https://developer.huawei.com/consumer/cn/doc/quickApp-References/quickgame-api-sysinfo-0000001083874626#section14651153111516)或[qg.getSystemInfo](https://developer.huawei.com/consumer/cn/doc/quickApp-References/quickgame-api-sysinfo-0000001083874626#section16231152791216)确定初始的分辨率，并将游戏Canvas的宽高同步设置为该尺寸，确保开局画面比例正确。

2. 注册全局尺寸变更监听。 在游戏主循环或全局管理类中注册[qg.onWindowResize](https://developer.huawei.com/consumer/cn/doc/quickApp-References/quickgame-api-window-0000002327339169#section14948251203111)。当触发回调时，必须同步更新游戏引擎的Viewport（视口）或DesignResolution（设计分辨率）。

3. 主流游戏引擎适配对接。 不同的游戏引擎（如Cocos Creator，LayaAir，Egret）对尺寸变更的底层封装不同，收到onWindowResize通知后需调用引擎对应的方法：

   |游戏引擎|核心方法/属性|
   |:------------|:--------------------------------------------------|
   |Cocos Creator|view.setCanvasSize()，view.setDesignResolutionSize()|
   |LayaAir|Laya.stage.scaleMode，Laya.stage.setScreenSize()|
   |Egret|stage.scaleMode|

   以Cocos Creator为例的示例代码如下所示：

   ```
   qg.onWindowResize((res) => {
     if (typeof cc !== 'undefined' && cc.view) {
       // 1. 修改引擎底层的 Canvas 实际像素尺寸
       cc.view.setCanvasSize(xxx, xxx);

       // 2. 根据新的宽高比或调用qg.getSystemInfo获取详细窗口信息，动态调整设计分辨率的适配策略
       let aspectRatio = res.windowWidth / res.windowHeight;
       if (aspectRatio > 1) { 
         // 横屏展开状态（接近正方形或更宽）
         cc.view.setDesignResolutionSize(this.DESIGN_WIDTH, this.DESIGN_HEIGHT, cc.ResolutionPolicy.FIXED_HEIGHT);
       } else {
         // 竖屏或折叠状态
         cc.view.setDesignResolutionSize(this.DESIGN_WIDTH, this.DESIGN_HEIGHT, cc.ResolutionPolicy.FIXED_WIDTH);
       }
     }
   });
   ```

4. UI布局动态刷新与安全区域。 叠屏展开后，原本靠边的UI如果使用绝对坐标，会"漂浮"在屏幕中间。

   1. 激活UI重新对齐。 在[qg.onWindowResize](https://developer.huawei.com/consumer/cn/doc/quickApp-References/quickgame-api-window-0000002327339169#section14948251203111)触发并更新引擎分辨率后，调用UI框架的刷新方法，让挂载了物理边界锚点的UI重新计算位置。

   2. 安全区域（Safe Area）。 考虑到部分设备屏幕有摄像头或挖孔，重要UI（如返回按钮、金币显示、充值入口）应根据[qg.getSystemInfoSync](https://developer.huawei.com/consumer/cn/doc/quickApp-References/quickgame-api-sysinfo-0000001083874626#section14651153111516)或[qg.getSystemInfo](https://developer.huawei.com/consumer/cn/doc/quickApp-References/quickgame-api-sysinfo-0000001083874626#section16231152791216)获取的安全区域计算位置，避免被物理遮挡。
