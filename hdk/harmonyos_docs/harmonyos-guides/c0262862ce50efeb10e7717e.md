# attach启动调试

开发者也可以通过将调试程序attach到已运行的应用进行调试。

Attach Debugger和Debug的区别在于，Attach Debugger to Process可以先运行应用/元服务，然后再启动调试，或者直接启动设备上已安装的应用/元服务进行调试；而Debug是直接运行应用/元服务后立即启动调试。

## 前提条件

当前设备上被attach的应用代码和本地代码一致，且已提前构建生成必要的sourceMap文件。

## 使用约束

attach不支持的场景：

* 本地无源码。
* bundleName不匹配，将出现提示"The selected process does not match the bundlename of the current project!"，但不阻塞调试过程。 ![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/77/v3/8jIrPuZoQheE4_ok_24KMg/zh-cn_image_0000002701823594.png?HW-CC-KV=V1&HW-CC-Date=20260928T063033Z&HW-CC-Expire=31536000000&HW-CC-Sign=7C24C1FE24279BF78716911E447A811BA5751F8A764FB9DBF187A67874BE6A00)

   ![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/b7/v3/Uj6iInRqSemNfJXohP7Juw/zh-cn_image_0000002701663674.png?HW-CC-KV=V1&HW-CC-Date=20260928T063033Z&HW-CC-Expire=31536000000&HW-CC-Sign=2F4534F0699DAE47CBCFF61F85550E59AFD390658C8BD9FA797056AD6B688451)

2. 选择要调试的应用进程，若应用bundleName与当前工程不一致，则需勾选Show all process。

   ![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/52/v3/A8u74lEgQaeDBQHIvV3Pdg/zh-cn_image_0000002701663676.png?HW-CC-KV=V1&HW-CC-Date=20260928T063033Z&HW-CC-Expire=31536000000&HW-CC-Sign=F3DCDA28AE946C9A4B6930E0EADB80D4FE1B1E751F4841FD9F56DF8F4DE8E884)
   > 说明
   >
   > 正常情况下，attach调试仅支持debug签名的应用，从DevEco Studio 6.0.2 Beta1版本开始，PC/2in1上的应用，如果使用了release签名并且配置了ohos.permission.kernel.ALLOW_DEBUG权限，也支持被attach调试。

3. 选择需要使用的调试配置，或者使用默认配置。

   ![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/7c/v3/CLlf2jddTeeG5YUavVBSTA/zh-cn_image_0000002731542867.png?HW-CC-KV=V1&HW-CC-Date=20260928T063033Z&HW-CC-Expire=31536000000&HW-CC-Sign=ED018F4867F89FC440BC7CC44B5C58A8AB5BBFDDC2C2FEDD4A986E79C039BB4E)
