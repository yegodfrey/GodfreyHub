# FirebaseCore

## FirebaseApp

该API为Firebase SDK的入口点。它保存了FirebaseAPI的公共配置和状态。大多数应用不需要直接与FirebaseApp交互。在AGC中FirebaseApp对应的方法是默认直接支持的，转换为AGC之后可以直接删除该接口中使用的方法。下面给出简易代码示例。

使用Firebase的FirebaseApp中方法的代码场景：

```screen
import com.google.firebase.FirebaseApp;
FirebaseApp.initializeApp(this.getApplicationContext());
```

在To HMS API模式下，可直接删除对应使用代码。

## Add HMS API模式通用解决方案

对于当前AGC暂未提供相应能力的API，我们提供了一个通用的解决方案，这个方案可以使得您的工程在选择Firebase优先的策略时，能够正常使用您之前所使用的所有Firebase的接口，而在AGC优先时，如果相关API的能力实在不可或缺，您可以选择自己实现相关逻辑。我们假设该API属于类FirebaseClass，返回值类型为FirebaseReturnType，所需入参类型为FirebaseInputType。即该API的代码形式可能如下所示：

```screen
public class FirebaseClass{   
    public FirebaseReturnType firebaseApi(FirebaseInputType){
    }
}
```

下面给出一种可能的使用场景和相应的解决方案，其他场景均可以参考此方案。

API使用场景：

```screen
FirebaseClass firebaseObject = new FirebaseClass();//firebaseObject代表调用此API的对象
FirebaseInputType firebaseInputObject = new FirebaseInputType();//firebaseInputObject为此API所需的输入对象
FirebaseReturnType fReturn = firebaseObject.firebaseApi(firebaseInputObject);//fReturn为此API的输出对象
```

那么大致上此场景可以分为两小类情况：与此API相关的调用类和输入类有不支持的，或是都支持的。针对这两种情况，我们可以采取不同的处理策略。

第一种情况（与此API相关的调用类和输入类有不支持的）：

```screen
if(org.xms.g.utils.GlobalEnvSetting.isHms()){
    //AGC无对标能力，如果必需相关能力请自行开发
}else{
    FirebaseClass firebaseObject = new FirebaseClass();
    FirebaseInputType firebaseInputObject = new FirebaseInputType();
    FirebaseReturnType fReturn = firebaseObject.firebaseApi(firebaseInputObject);
    //按照原有业务需求处理
}
```

第二种情况（与此API相关的调用类和输入类都支持，仅仅此方法不支持）：

```screen
ExtensionClass extensionObject = new ExtensionClass();
ExtensionInputType extensionInputObject = new ExtensionInputType();
//这样处理的好处在于不影响其他会用到这两个对象的API
if(org.xms.g.utils.GlobalEnvSetting.isHms()){
    //AGC无对标能力，如果必需相关能力请自行开发
}else{
    FirebaseReturnType fReturn = ((FirebaseClass)extensionObject.getGInstance())
        .firebaseApi((FirebaseInputType)extensionInputObject.getGInstance());
    //按照原有业务需求处理
}
```
