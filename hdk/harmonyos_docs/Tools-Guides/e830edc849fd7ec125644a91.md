# CPU frequency

该数据源通过Linux内核ftrace基础设施记录CPU电源管理方案的更改。

## Frequency scaling

有两种方法可以获取CPU频率数据。

* 启用power/cpu_frequency ftrace事件。（请参阅下面的TraceConfig）。这将在每次内核频率缩放驱动程序更改频率时记录一个事件。请注意，并非所有平台都支持此功能。根据我们的经验，它在基于ARM的SoC上可行，但在大多数基于英特尔的现代平台上不产生数据。这是因为最近的Intel CPU使用了一个内部的DVFS，它由CPU直接控制，并且不会向内核暴露频率变化事件。另请注意，即使在基于ARM的平台上，事件也仅在CPU频率改变时触发。在许多情况下，CPU频率在几秒钟内不会改变，这将在跟踪的开始处显示为一个空块。建议总是将这与轮询结合起来，以获得初始频率的可靠快照。
* 通过启用linux.sys_stats数据源并将cpufreq_period_ms设置为大于0来轮询sysfs。这将定期轮询/sys/devices/system/cpu/cpu*/cpufreq/cpuinfo_cur_freq，并在跟踪缓冲区中记录当前值。在基于英特尔和ARM的平台上都可以运行。

在大多数HarmonyOS设备上，频率缩放是按集群（大/小核心组）进行的，因此四个CPU组同时改变频率的情况并不罕见。

## Available frequencies

通过启用linux.system_info数据源，可以一次性记录每个CPU支持频率的完整列表。这将在跟踪记录开始时记录/sys/devices/system/cpu/cpu*/cpufreq/scaling_available_frequencies。

这在现代英特尔平台上是不支持的，原因与前面提到的power/cpu_frequency相同。

## Idle states

当没有线程有资格被执行时（例如，都处于睡眠状态），内核会将CPU设置为空闲状态，关闭一些电路以减少空闲功耗。大多数现代CPU都有多个空闲状态：更深的空闲状态使用更少的电力，但也需要更多的时间恢复状态。

空闲转换相对来说比较快，CPU可以在一秒钟内进入和离开空闲状态数百次。空闲不能与完全设备暂停相混淆，后者是一种更强、更具侵入性的省电状态。即使在屏幕亮起且设备看起来运行正常时，CPU也可以处于空闲状态。

## UI

在UI界面，CPU频率和空闲率显示在同一轨道上。轨道的高度代表频率，着色代表空闲状态（彩色：非空闲，灰色：空闲）。悬停或单击轨迹中的点将显示频率和空闲状态。

## Full-device suspend

当笔记本电脑处于"睡眠"模式或智能手机显示屏关闭足够时间时，会发生设备完全挂起。当设备处于挂起状态时，大多数硬件单元都会关闭，进入可能的最高省电状态（而不是完全关闭）。
> 说明
>
> 大多数HarmonyOS设备在调暗显示屏后不会立即挂起，但如果通过电源按钮强制关闭显示屏，则会挂起。UI界面无法清晰显示挂起状态。
