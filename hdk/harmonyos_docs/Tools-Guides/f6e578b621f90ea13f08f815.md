## 查看Bisheng Shader静态性能分析

> 说明
>
> Bisheng Shader静态性能分析工具当前支持的芯片：马良 910 （仅支持OpenGL ES），马良 920，马良930，马良935。

点击"Disassembly>Shader Statistics"，以Shader 66为例，如下图所示。

![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/f5/v3/T93NoowLRX6FD8ZwmyrZ2w/zh-cn_image_0000002570858652.png?HW-CC-KV=V1&HW-CC-Date=20260909T155305Z&HW-CC-Expire=31536000000&HW-CC-Sign=EB0BC88A0F00B6A46D876C941D36732DADF5CA08CB5026A6B0EE0FD1C5F50D0A)

|名称|描述|影响|建议|
|:------------------------------------|:---------------------------------------------------------------------------|:---------------------------------------------------------------|:-----------------------------------------------------------------------------------------|
|Shader Type|shader类型。|-|-|
|SIMD|一个warp的线程数，有32和64两种配置，编译器根据shader类型和内容选择。|-|-|
|Number of general purpose register|通用寄存器的使用数量。|寄存器会影响并发的warp数量，从而影响GPU的执行效率。|SIMD32： <=64(Excellent) <=84(Good) >128(Poor) SIMD64: <=32(Excellent) <=42(Good) >64(Poor)|
|Number of constant register|常量寄存器的使用数量。通常包含字面常量、uniform修饰变量、内建变量等。|常量寄存器用于减少UBO的访问或常量间的计算加速。|关注该指标是否接近上限(vs/fs: 512,cs:1024)，如果达到上限建议尝试减小UBO的size或手动合并常量计算。|
|Private memory usage per-thread(Byte)|每个线程使用的private memory的大小，单位Byte。通常为shader里使用了local array变量或者变量过多，导致寄存器spill。|用private memory做变量访问效率较低，对性能影响大。|1. 避免local array变量的非常量下标索引；2. 减少local array变量或者减少变量的生命周期，避免寄存器spill。|
|Nesting depth|分支嵌套深度。|GPU执行是需要额外单元记录和恢复分支信息，且分支记录单元是warp内共享的。因此分支嵌套过深可能导致warp并发低。|<=4(Excellent) <=8(Good) >12(Poor)|
|Estimated warp concurrency|同一时刻，一个执行单元内下发的warp数量（warp并发度）。|当执行单元遇到数据依赖造成指令间等待时，可以切换到另一个warp来提高执行单元的利用率。|>=4(Excellent) >=3(Good) <=2(Poor)|
|Total instructions|总指令数。|总指令数多说明单个shader的执行时间可能较长。同时也会影响指令段的cache。|避免超大shader。|
|Total ALU instructions|总的计算指令数。|-|-|
|32 bit ALU instructions|32 bit计算指令数。对应全精度计算(highp)。|-|-|
|16 bit ALU instructions|16 bit计算指令数。对应半精度计算(mediump/lowp)。|-|-|
|16 bit ALU instructions ratio|16 bit计算指令数占总计算指令数占比。|马良 910 SIMD64下，16 bit计算指令是32bit计算指令效率的2倍。因此提高半精度计算比例能提升GPU的执行效率。|建议lighting和后处理等精度不敏感pass的半精度比例能达到20%。|
|Total Control flow instructions|控制流指令数。|GPU架构适合并行计算，过多的分支可能导致一个warp内的线程分叉，导致执行效率低。同时控制流指令执行效率比普通ALU指令低。|1. 尽量减少shader中的控制流。2. 用三目运算或者数值运算替代简单的控制流。3. 分支判断条件尽量使用uniform。4. for循环尽量使用常量循环。|
|Total Memory instructions|访存类指令数。|存储访问的时延较长，可能GPU的执行效率低；同时对带宽等可能也有影响。|1. 尽量合并访存操作，减少无效分量或者逐个分量的访存。2. 合理排布访存操作的顺序，提高cache命中率。|
|Memory read instructions|读存储指令数。|-|-|
|Memory write instructions|写存储指令数。|-|-|
|Total texture instructions|采样类指令数。|与访存类指令类似。|1. 控制纹理大小和采样坐标的顺序和跨度，提高cache命中率。2. 一个shader内的采样指令尽量控制在16以内。|

## Shader编辑

打开"Pipeline State"窗口，点击"VS > Edit"或"FS > Edit"等，可对shader内容进行编辑。

![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/2f/v3/77r0lj5sRRKUlkEP3zk57g/zh-cn_image_0000002596556031.png?HW-CC-KV=V1&HW-CC-Date=20260909T155305Z&HW-CC-Expire=31536000000&HW-CC-Sign=604AC28618142CB5BFAC24A497C7F12F496179385EE3A8F9B2CC9082FF1D835F)

修改好shader后点击Apply changes，查看是否修改成功。点击Tools->Patch Edited Shaders，保存修改后的rdc文件。

点击Reset按钮，删除所有修改保存原始shader。

点击Remove changes，使用原始shader。

## 用户自定义修改SPIRV-Cross参数

1. 打开关键帧进行回放，选择一个drawcall，选择Window->Pipeline State，找到对应的VS/FS/CS shader，点击View。
2. Disassembly type选择GLSL(SPIRV-Cross)，正常展示GLSL源码，HLSL操作相同。
3. 点击Tools->Settings->Shader Viewer，双击SPIR-V->GLSL，修改Command Line参数，点击OK。

   ![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/e8/v3/-1PMBQc7TV6c5mlNmgYCpg/zh-cn_image_0000002571151502.png?HW-CC-KV=V1&HW-CC-Date=20260909T155305Z&HW-CC-Expire=31536000000&HW-CC-Sign=3942EF7DBF2D5E19D82B0A2A6F7CC43F3F74D8FA7BDA24C3A713433BA861F0E4)

4. 重新打开shader view GLSL(SPIRV-Cross)窗口，修改的参数已生效。

## 顶点调试

顶点调试窗口界面。

![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/34/v3/-LTGtQVCQoatxF8pvy5DXg/zh-cn_image_0000001186303002.png?HW-CC-KV=V1&HW-CC-Date=20260909T155305Z&HW-CC-Expire=31536000000&HW-CC-Sign=63E75E18EA7DCF65FD08E1071B63D360A114F678FDCA294FB9025FF1BF65227B)

顶点调试需要调用"Mesh Viewer"窗口以及"Event Browser"窗口。在"Event Browser"窗口中点击对应的Draw会打开对应的顶点着色器，对应的绘制顶点信息会展示在"Mesh Viewer"窗口中。

"Mesh Viewer"窗口如上图深蓝色区域所示，右键点击后会弹出选项。如果使用的是D3D11图片，则会多一个调试选项，上图中采用的是OpenGL ES，没有该选项。修改对应的顶点信息后下方的Preview也会做出显示。

"VS In"为当前绘制的内容，"VS Out"已经完成绘制的内容，棋盘格显示区域为可旋转视角，按下鼠标左键并拖动即可完成视角的切换。

如果"Event Browser"中选中的EID下包含多个Draw，右键点击棋盘格显示区域中的绘制部分，会跳转到对应的顶点信息。

## 像素调试

像素调试基于"Texture Viewer"窗口。选择一张rdc图片，鼠标右击图中FBO窗口，对应的像素信息会展示在图中Pixel Context窗口处。

如果所选像素进行过修改，那么下方的"History"按钮将会亮起，点击后可以查看历史绘制信息。

如果选择了要调试的当前调用，则可以点击"Debug"按钮跳过像素历史记录，然后直接跳至调试器，像素的输入将被自动填充。

![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/50/v3/WW1ll0KCTIm1jBbJmRuB3A/zh-cn_image_0000001186621540.png?HW-CC-KV=V1&HW-CC-Date=20260909T155305Z&HW-CC-Expire=31536000000&HW-CC-Sign=A458D3A17066F60317F0BD47DE6FF7BA41A23DA0EFB9D9949AC50A992123D9C6)
> 说明
>
> 像素调试时需要注意以下几点。
>
> * 如果所选的绘图调用未写入右键显示的像素，则像素历史记录窗口将打开，选择要调试的绘图调用。
> * 如果一次Drawcall重画同一像素几次，则调试结果将来自通过深度测试的最后一个片段。如果要从列表中选择特定片段，请首先启动像素历史记录，然后从列表中选择要调试的片段。
