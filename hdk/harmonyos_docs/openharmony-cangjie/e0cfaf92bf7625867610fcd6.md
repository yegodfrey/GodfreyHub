class RawBench
    
    public class RawBencher<T> { 
        public init() 
        public init(initial: T)
    }

功能: 提供较低级别的性能测试 API ，以便对性能测试过程进行更细粒度的控制。使用时应小心，因为如果使用不当，可能会产生误导性结果。 示例： 如何对 [Array](https://developer.huawei.com/consumer/cn/doc/openharmony-cangjie/core_package_structs#struct-arrayt).sort 进行性能测试：
    
    @Test
    class BenchSort {
        @RawBench[len in [1,100,10000]]
        func sort(len: Int64): Unit {
            let b = RawBencher<Array<Int64>>()
            b.beforeInvocation{ => Array(len,{ i: Int64 => len-i}) }
            b.runBench { x =>
                x.sort()
            }   
        }
    }

![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20240621215222.18951469579235160655082427707129:50001231000000:2800:C3E97A2437FC59116A0922E8A051E7740839CAE95E2315DC1C817E5B83270D9E.png?needInitFileName=true?needInitFileName=true) 上例每次都会分配新数组，这可能会导致后台进行大量 [GC](https://developer.huawei.com/consumer/cn/doc/openharmony-cangjie/runtime_package_funcs#func-gcbool) 工作，从而导致结果不太精确。 如何更好得对 [Array](https://developer.huawei.com/consumer/cn/doc/openharmony-cangjie/core_package_structs#struct-arrayt).sort 进行性能测试，消除过多对象分配：
    
    @Test
    class BenchSort {
        @RawBench[len in [1,100,10000]]
        func sort(len: Int64): Unit {
            let b = RawBencher<Array<Int64>>()
            let array = Array(len,{ i: Int64 => len-i})
            b.beforeInvocation{ => array.clone() }
            b.runBench { x =>
                x.sort()
            }   
        }
    }

请记住，并不总是可以在 beforeInvocation 中将对象恢复到其原始状态的同时满足 beforeInvocation 的所有要求。 例如，如下即为不正确的方式对 [ArrayList](https://developer.huawei.com/consumer/cn/doc/openharmony-cangjie/collection_package_class#class-arraylistt).append 进行性能测试：
    
    @Test
    class BenchAppend {
        @RawBench
        func append(): Unit {
            let b = RawBencher<ArrayList<Int64>>()
            let data = ArrayList()
            b.beforeInvocation{ => 
                data.clear() 
                data
            }
            b.runBench { x =>
                x.append(1)
            }   
        }
    }

上例看起来正确，但是它并不满足 beforeInvocation 的要求。 它的问题是，根据是否调用基准测试，[ArrayList](https://developer.huawei.com/consumer/cn/doc/openharmony-cangjie/collection_package_class#class-arraylistt).clear() 的工作方式有所不同。 一种正确的，但依然不够好的对 [ArrayList](https://developer.huawei.com/consumer/cn/doc/openharmony-cangjie/collection_package_class#class-arraylistt).append 的性能测试方案：
    
    @Test
    class BenchAppend {
        @RawBench
        func append(): Unit {
            let b = RawBencher<ArrayList<Int64>>()
            b.beforeInvocation{ => 
                ArrayList()
            }
            b.runBench { x =>
                x.append(1)
            }   
        }
    }

这里的问题是 [ArrayList](https://developer.huawei.com/consumer/cn/doc/openharmony-cangjie/collection_package_class#class-arraylistt) 的创建比 [ArrayList](https://developer.huawei.com/consumer/cn/doc/openharmony-cangjie/collection_package_class#class-arraylistt).append 花费更多的时间，因此 append 的实际时间可能会在测量噪声中丢失。 如下为一种更好的方式对 [ArrayList](https://developer.huawei.com/consumer/cn/doc/openharmony-cangjie/collection_package_class#class-arraylistt).append 进行测试：
    
    @Test
    class BenchAppend {
        @RawBench[times in [10,100]]
        func append(times: Int64): Unit {
            let b = RawBencher<ArrayList<Int64>>()
            b.beforeInvocation{ => 
                ArrayList()
            }
            b.runBench { x =>
                for(i in 0..times) {
                    x.append(1)
                }
            }
        }
    }

这仍然不是最好的方法，因为性能测试结果将包括循环本身的执行时间。但目前在很多场景上它都比其他选择更好。 [h2]init()
