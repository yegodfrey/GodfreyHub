# 用户授权

用户授权，即应用请求获取个人数据（如通话、联系人、日历等）时，用户对请求范围与程度的决策。权限的使用与管理需满足数据最小化和透明可控原则，只在必要时申请所需权限，并做到让用户知情、同意和可撤销。

#### 敏感权限范围

涉及敏感个人数据的使用需要用户授权和管理，并遵循可知可控原则。为了更好地保护用户隐私、规范并简化权限的使用，我们将 HarmonyOS 上可授予的权限进行了分类、整合和缩减。目前可动态申请的权限分为以下 8 类，应用可根据需要向用户申请。通讯录权限的使用受限，开发者需先在应用市场申请相应证书，并按照动态申请权限的流程向用户申请授权。（更多内容详见 [应用权限列表](https://developer.harmonyos.com/cn/docs/documentation/doc-guides/security-permissions-available-0000001051089272)）。

     1. 位置信息
     2. 相机
     3. 麦克风
     4. 媒体和文件（媒体：图片和视频；文件：公共目录下载的文件）
     5. 日历
     6. 健身运动
     7. 身体传感器
     8. 多设备协同

#### 授权方式

当用户使用需要特定权限才能正常运行的功能时，应用需通过**权限申请弹框** 向用户申请授权。为了让用户理解权限申请的目的和使用场景（同时也是工信部要求），申请权限时需提供权限使用目的描述。

**权限申请弹框使用说明**

     1. 该弹框由系统弹出，设计师需关注该权限弹框的出现场景是否符合用户预期，建议在用户使用需要授权的功能时出现，避免在应用启动时就申请。
     2. 系统弹框已有权限申请描述，无需开发者提供。权限申请描述：是否允许“XX（应用名）”访问 XX（权限名称）？
     3. 权限使用目的由开发者提供，描述应简单、可理解，建议描述：用于 XXXX（目的或场景），如**“** 用于扫码添加好友和拍照**”。**
     4. 用户可自由授予权限或禁止、撤销授权。应用不得通过“未授权则无法使用应用”等方式胁迫用户授予权限。

**用户点击“禁止”后**

     1. 需避免权限被**“** 禁止**”** 后应用闪退、强制退出界面等问题；
     2. 点击“禁止”即系统的权限弹框不再出现。若用户再次出发此功能，需由应用自行引导开启相应权限。
