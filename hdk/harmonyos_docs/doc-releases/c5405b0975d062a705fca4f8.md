# ArkUI

#### ArkTS声明式UI更新机制优化

ArkTS声明式UI在API9上优化了相关UI更新机制，当自定义组件的某个状态变量发生变化导致自定义组件重新渲染时，仅执行该自定义组件build函数中的部分UI描述（使用了该状态变量的内置UI组件的UI描述）来实现更高性能的UI更新。而API8及以前在状态变量发生变化时会执行build函数中的全量UI描述来实现UI更新。

#### [h2]API 8及之前版本的UI更新机制

当自定义组件使用的状态变量发生变化时，会重新执行自定义组件的build函数中的全量UI描述来刷新UI界面。以下示例展示了相关更新流程：
    
    @Component
    struct CountDownComponent {
        @Prop count: number;
        costOfOneAttempt: number = 1;
    
        build() {
            Column() {
                if (this.count> 0) {
                    Text(`You have ${this.count} Nuggets left`)
                } else {
                    Text("Game over!")
                }
    
                Button() {
                    Text("Try again")
                }.onClick(() => {
                    this.count -= this.costOfOneAttempt;
                })
            }
        }
    }
    
    @Entry
    @Component
    struct ParentComponent {
        @State countDownStartValue: number = 10; 
    
        build() {
            Column() {
                Text(`Grant ${this.countDownStartValue} nuggets to play.`)
                Button() {
                    Text("+1 - Nuggets in New Game")
                }.onClick(() => {
                    this.countDownStartValue += 1;
                })
                CountDownComponent({ count: this.countDownStartValue, costOfOneAttempt: 2 })
            }.width('100%')
        }
    }

上述示例代码运行后，当用户单击按钮时，系统实际按如下流程进行更新操作：

     1. 自定义组件ParentComponent的countDownStartValue状态变量的值增加1；
     2. countDownStartValue状态变量改变将ParentComponent标记为需要更新；
     3. ParentComponent执行更新并重新运行其build函数：
        1. 执行Column的UI描述，将width属性值100%重新设置给Column组件；
        2. 执行Text的UI描述，将"Grant 11 nuggets to play."的文本内容重新设置给Text组件；
        3. 执行Button的UI描述，将点击事件回调函数重新设置给Button组件；
        4. 执行Button内部Text的UI描述，将”+1 - Nuggets in New Game“的文本内容重新设置给Text组件；
     4. 子组件CountDownComponent的count成员使用@Prop接受父组件的countDownStartValue，从而在countDownStartValue值发生变化时，单向同步到CountDownComponent的count值使之发生改变并标记CountDownComponent需要更新；

CountDownComponent执行更新并重新运行其build函数：
        1. 执行Column的UI描述；
        2. 执行if的UI描述，对if条件进行评估，值为true；
        3. 运行if的true分支，执行Text的UI描述，将"You have 11 Nuggets left"的文本内容重新设置给Text组件；
        4. 执行button的UI描述，将点击事件回调重新设置给Button组件；
        5. 执行Text的UI描述，将"Try again"的文本内容重新设置给Text组件。

#### [h2]API 9 Beta1的UI更新机制

自定义组件在执行build函数的UI描述过程中会生成状态变量及使用该状态变量的UI组件的对应关系表。当状态变量发生变化时，会首先查询上述关系表找到使用该状态变量的UI组件，然后从build函数中抽取上述UI组件相关的UI描述进行执行来刷新UI界面，以下代码展示了相关更新流程：
    
    @Component
    struct CountDownComponent {
        @Prop count: number;
        costOfOneAttempt: number = 1;
    
        build() {
            Column() {
                if (this.count> 0) {
                    Text(`You have ${this.count} Nuggets left`)
                } else {
                    Text("Game over!")
                }
    
                Button() {
                    Text("Try again")
                }.onClick(() => {
                    this.count -= this.costOfOneAttempt;
                })
            }
        }
    }
    
    @Entry
    @Component
    struct ParentComponent {
        @State countDownStartValue: number = 10; 
    
        build() {
            Column() {
                Text(`Grant ${this.countDownStartValue} nuggets to play.`)
                Button() {
                    Text("+1 - Nuggets in New Game")
                }.onClick(() => {
                    this.countDownStartValue += 1;
                })
                CountDownComponent({ count: this.countDownStartValue, costOfOneAttempt: 2 })
            }.width('100%')
        }
    }

上述示例代码运行后，当用户单击按钮时，系统实际按如下流程进行更新操作：

     1. 自定义组件ParentComponent的countDownStartValue状态变量的值增加1；
     2. countDownStartValue状态变量改变将ParentComponent标记为需要更新；
     3. ParentComponent执行更新：
        1. 查询使用countDownStartValue状态变量的UI组件：Text（在回调函数中使用状态变量不会记录使用依赖，故Button不包含在内）；
        2. 从build函数中抽取Text的相关UI描述重新执行，将“Grant 11 nuggets to play.”重新设置给Text组件；
     4. 子组件CountDownComponent的count成员使用@Prop接受父组件的countDownStartValue，从而在countDownStartValue值发生变化时，单向同步给CountDownComponent的count值使之发生改变并标记CountDownComponent需要更新：
        1. CountDownComponent查询使用count状态变量的UI组件和语法：if语法、if条件为true下的Text；
        2. 从build函数中抽取if语法包裹的UI描述重新执行，对if条件进行评估，值为true，条件未发生变化，忽略相应分支逻辑的执行。
        3. 从build函数中抽取Text的相关UI描述重新执行，将“You have 11 Nuggets left”重新设置给Text组件。

从上述变化可以看出，优化后的UI更新机制可大幅减少系统处理的步骤和开销。
