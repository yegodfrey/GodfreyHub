# API 7相对API 6变更详细说明

#### JS API变更说明

#### [h2]窗口模块（window）监听功能新增入参类型

窗口的监听功能新增监听类型的入参“type”。在原本仅可对键盘高度变化（keyboardHeightChange）进行监听的基础上，增加两种监听类型供开发者选择：

     * type设置为“windowSizeChange”时表示监听类型为窗口尺寸变化监听。
     * type设置为“systemAvoidAreaChange”时表示监听类型为系统窗口规避区变化监听。

**变更影响**

API 6及之前的窗口模块JS接口行为发生变更。

**关键的接口/组件变更**

     * window.on()
     * window.off()

**适配指导**

需要修改原有代码中接口调用时的入参，增加type参数，设置“windowSizeChange”或“systemAvoidAreaChange”。
    
    var type = 'windowSizeChange';
    windowClass.on(type, (err, data) => {
        if (err) {
            console.error('Failed to enable the listener for window size changes. Cause: ' + JSON.stringify(err));
            return;
        }
        console.info('Succeeded in enabling the listener for window size changes. Data: ' + JSON.stringify(data));
    });

#### [h2]窗口模块（window）设置导航栏状态栏属性的新增

窗口的导航栏状态栏新增可设置属性。在入参SystemBarProperties中新增如下两个可设置的属性：

     * 新增属性“isStatusBarLightIcon”表示状态栏图标是否为高亮状态。
     * 新增属性“isNavigationBarLightIcon”表示导航栏图标是否为高亮状。

**变更影响**

API 6及之前的窗口模块JS接口行为发生变更。

**关键的接口/组件变更**

window.setSystemBarProperties()

**适配指导**

需要修改原有代码中入参“SystemBarProperties”的属性，补充属性“isStatusBarLightIcon”和“isNavigationBarLightIcon”。
    
    var SystemBarProperties={
        statusBarColor: '#ff00ff',
        navigationBarColor: '#00ff00',
        //以下两个属性从API Version7开始支持
        isStatusBarLightIcon: true,
        isNavigationBarLightIcon:false
    };
    windowClass.setSystemBarProperties(SystemBarProperties, (err, data) => {
        if (err) {
            console.error('Failed to set the system bar properties. Cause: ' + JSON.stringify(err));
            return;
        }
        console.info('Succeeded in setting the system bar properties. Data: ' + JSON.stringify(data));
    });

#### [h2]窗口模块（window）新增了可获取的窗口属性

获取当前窗口属性的接口“getProperties()”，返回的WindowProperties窗口属性有新增。该接口通过callback回调返回窗口属性，异步返回WindowProperties窗口属性。该窗口属性中新增如下属性：

     * 新增窗口属性“windowRect”表示窗口尺寸。
     * 新增窗口属性“type”表示窗口类型。
     * 新增窗口属性“isTransparent”表示窗口是否透明，默认为false。
     * 新增窗口属性“dimBehindValue”表示靠后的窗口的暗度值，取值范围为0~1，1表示最暗。
     * 新增窗口属性“isLayoutFullScreen”表示窗口是否为沉浸式，默认为false。
     * 新增窗口属性“focusable”表示窗口是否可聚焦，默认为true。
     * 新增窗口属性“touchable”表示窗口是否可触摸，默认为true。
     * 新增窗口属性“isPrivacyMode”表示隐私模式，默认为false。
     * 新增窗口属性“isRoundCorner”表示窗口是否为圆角。

**变更影响**

API 6及之前的窗口模块JS接口的返回信息发生变更。

**关键的接口/组件变更**

window.getProperties()

**适配指导**

无需对原有代码进行适配修改。
    
    windowClass.getProperties((err, data) => {
        if (err) {
            console.error('Failed to obtain the window properties. Cause: ' + JSON.stringify(err));
            return;
        }
        console.info('Succeeded in obtaining the window properties. Data: ' + JSON.stringify(data));
    });

#### Java API变更说明

#### [h2]手势与事件分发、阻挡机制变更

变更前：手势与事件分开，事件缺少分发和阻挡机制，当组件之间相互有遮挡重叠时，点击此区域，所有组件均可响应点击事件。

变更后：手势与事件绑定，增加拦截机制，可实现手势的定制转发和阻挡，支持更为丰富的场景。

**变更影响**

布局中存在相互遮挡的组件时，上方组件会拦截手势，导致下方组件无法响应任何手势。

**关键的接口/组件变更**

无

**适配指导**

     * 在XML布局时将不需要响应手势的组件调整到下层。
     * 可以在Java代码中根据实际需要动态调用Component.setVisibility(HIDE)隐藏上层的组件。

#### [h2]match_content属性与组件宽高的关系变更

变更前：设置match_content属性的组件，其宽高完全由子组件的大小来决定，不受背景图片大小的影响。

变更后：组件既设置了match_content属性，又设置了背景图片时，那么组件的大小会与背景图片大小一致以保证图片完全显示。

**变更影响**

使用背景图片的部分组件在之前的版本显示正常，当前却可能出现组件下方有空余区域的现象。

**关键的接口/组件变更**

无

**适配指导**

对于设置了背景图片的组件，需对比检查各版本的显示效果并根据需要调整其背景图片的大小。

#### [h2]max_line属性实现机制变更

变更前：Text组件设置max_line属性后，仅截取前两行文字来呈现。

变更后：设置max_line属性即设置Text组件的高度为两行文字的高度。

**变更影响**

由于HarmonyOS的文本在垂直方向默认居中对齐，当设置max_line将Text组件高度变为两行文字高度后，就会 出现多行文字显示截断的现象。

**关键的接口/组件变更**

max_line

**适配指导**

     * 对于设置max_line属性的Text组件，同时补充设置ohos:text_alignment="top"，可兼容变更前后的版本。
     * 可以针对Text组件，设置truncation_mode以省略掉超过限定高度的文字内容。

#### [h2]ScrollView滑动支持机制变更

变更前：ScrollView只支持竖向滑动，不受父组件ScrollView、子组件DirectionalLayout及后代组件Text宽度设置的影响，可正常竖向展示文本内容。

变更后：ScrollView增加支持了横向滑动。

**变更影响**

当父组件ScrollView、子组件DirectionalLayout、后代组件Text采用match_content、match_content、match_content的宽度配置时，ScrollView会适应每行文字展开后的长度并变成横向滑动的效果。

**关键的接口/组件变更**

ScrollView

**适配指导**

当存在ScrollView嵌套DirectionalLayout再嵌套Text的场景时，需要给父组件ScrollView和子组件DirectionalLayout的宽度分别设置为match_parent，以兼容变更前后的版本。

#### [h2]组件背景色透明度实现机制变更

变更前：父组件的透明度不会影响子组件的透明度。

变更后：父组件的透明度会影响子组件的透明度。

**变更影响**

当应用存在多层布局时，上层布局可能存在显示不清的现象。

**关键的接口/组件变更**

无

**适配指导**

使用background_element属性设置组件背景色，来替代使用alpha来设置组件透明度。

#### [h2]TextForm.setLineHeight实现机制变更

变更前：TextForm.setLineHeight为空实现，即使错误调用也不会产生任何负面效果。

变更后：TextForm.setLineHeight已具体实现，功能为设置文本的行高。

**变更影响**

当使用TextForm.setLineHeight接口传入一个较小的参数时，由于设置的文本行高过小，会产生多行文本重叠的现象。

**关键的接口/组件变更**

TextForm.setLineHeight

**适配指导**

     * 调用TextForm.setLineHeight接口时，根据实际场景传入合理的参数值。
     * 避免调用此接口。

#### [h2]富文本文字计算方式变更

变更前：调用addTouchEventListener(TouchEventListener listener, int start, int end)这个接口给富文本设置点击事件，在计算富文本起始和结束位置的时候不会算入特殊字符。

变更后：调用addTouchEventListener(TouchEventListener listener, int start, int end)接口设置点击事件时会将特殊字符计算在内。

**变更影响**

在使用addTouchEventListener()为富文本设置点击事件后，由于将特殊字符计算在内，导致传入的富文本起始和结束位置计算不正确，响应点击事件的位置错乱，焦点移位。

**关键的接口/组件变更**

addTouchEventListener(TouchEventListener listener, int start, int end)

**适配指导**

接口设置富文本的点击响应事件，必须将想点击的富文本的起始位置填写正确，起始位置需包含转义字符等特殊字符在内的所有字符。

#### [h2]Image缩放模式变更

变更前：布局属性scale_mode相关设定不严格。

变更后：布局属性scale_mode相关设定进行了优化调整。

**变更影响**

当组件设置的宽高和其图片的宽高不匹配时，比如Image组件尺寸是图片尺寸的一半，将会出现截断显示不全的现象。

**关键的接口/组件变更**

scale_mode

**适配指导**

     * 可以将XML中scale_mode="center"改为scale_mode="inside"，这时图片会居中缩放适配Image组件大小。
     * Image组件和对应图片尺寸保持一致，将无此问题。

#### [h2]获取焦点显示的实现变更

变更前：获取焦点不显示蓝框。

变更后：获取焦点显示蓝框，以适配不同平台的焦点显示效果。

**变更影响**

获取焦点时的显示在版本前后表现不一致，变更后获取焦点时应用页面显示蓝框。

**关键的接口/组件变更**

无

**适配指导**

     * 在API 7及以上，可调用setFocusedEffect(false)使获取焦点时的蓝框消失。
     * 在使用较低版本的三方组件XPopup时，也会触发蓝框显示，将其依赖版本升级到1.1.4即可解决此问题。
    
    dependencies {
        implementation 'io.openharmony.tpc.thirdlib:XPopup:1.1.4'
    }

#### [h2]TextField注册软键盘回调次数变更

变更前：TextField的setEditorActionListener监听回调中只响应一次。

变更后：TextField的setEditorActionListener监听回调中，ohos:input_enter_key_type属性设置默认值时会回调两次，down和up时各调用一次。

**变更影响**

在onTextEditorAction回调函数中创建Dialog如果不做事件类型判断，将会创建了两个Dialog，只销毁一个Dialog，导致LoadingDialog一直停留的现象。

**关键的接口/组件接口**

setEditorActionListener

**适配指导**

     * 进行搜索相关功能开发时，在XML文件中设置TextField的相关属性为ohos:input_enter_key_type="enter_key_type_search"。
     * TextField设置setEditorActionListener监听时，在onTextEditorAction回调中对XML设置的对应属性做type值判断，以保证Dialog只弹出一次。

#### [h2]JavaUI框架层布局显示/隐藏改变相关机制变更

变更前：父容器或布局的显示或隐藏状态的改变，不会通知或影响子组件的显示和隐藏。

变更后：父容器或布局的显示或隐藏状态的改变，会通知子组件同步进行显示或隐藏。

**变更影响**

当应用存在兄弟组件之间上下覆盖的情况下，可能因为父组件的显示/隐藏导致子组件同步的显示/隐藏，从而出现页面空白内容无法加载的现象。

**关键的接口/组件变更**

无

**适配指导**

     * 在XML布局中对组件进行适当的隐藏。
     * 在Java代码中，根据实际需要动态调用Component.setVisibility(HIDE)隐藏不需要显示的组件。

#### [h2]组件焦点与输入相关实现变更

变更前：使用setVisibility(HIDE)时，组件不会失去焦点，可继续输入内容。

变更后：使用setVisibility(HIDE)或setVisibility(INVISIBLE)后，组件的焦点被清除，无法支持继续输入。

**变更影响**

使用setVisibility(HIDE)或setVisibility(INVISIBLE)后，组件的焦点被清除，无法支持继续输入。

**关键的接口/组件变更**

setVisibility(HIDE)、setVisibility(INVISIBLE)

**适配指导**

在需要保证组件不可见，又要保证其焦点不被清除的场景，建议使用setAlpha(0)方法。
