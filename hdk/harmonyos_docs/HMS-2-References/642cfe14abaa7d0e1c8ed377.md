# 1\. 接口定义  
  
##### 接口访问地址：开发者的回执接收服务器的地址，由开发者定义，同开发者联盟配置的回执地址一致。

消息流向：PUSH服务器->开发者回执接收服务器

# 2\. 接口描述

回执消息发生在系统检测到客户端有应答返回，并且有开发者在开发者联盟上开通了“消息回执”权益的场景。

# 3\. 参数

**表5-14**

参数名称                 | 类型                 | 是否必须                 | 描述                   
---|---|---|---  
statuses                 | JSON Array                 | 是                 | 为了提升性能，目前回执会对结果消息合并，最大为1000个结果。                   
token                 | JSON String                 | 是                 | PUSH TOKEN                   
biTag                 | JSON String                 | 是                 | CP在发送消息请求时携带的biTag。                   
status                 | JSON Integer                 | 是                 | 请参见“华为消息状态介绍”。                   
timestamp                 | JSON String                 | 是                 | 消息到达终端的时间戳（本地时间）                   
appid                 | JSON String                 | 否                 | 用户在开发者联盟的APPID，可选。                   
requestId                 | JSON String                 | 否                 | 请求ID，在发送接口中返回的值。                   
  
华为消息状态(status)介绍  
●  0：成功  
●  1：设备不在线  
●  2：成功发送到设备，对应的客户端应用不存在，通常表示已经卸载  
●  5：终端安装了该应用，但从未打开过，未申请token，所以不能展示  
●  6：用户设置不接收该APP的PUSH消息  
●  7：下发通知栏消息给sdk由Push弹通知栏，PushAPK不允许弹通知栏（华为手机管家设置）  
●  8：PushAPK不允许弹通知栏（华为手机管家设置）  
●  9：SDK不允许弹通知栏（华为手机管家设置）  
●  10：非活跃设备，消息丢弃  
●  12：无设备路由信息

●  13：设备在其他大区(国内一般不用考虑，通常是全球化CP)

●  102：消息被频控

●  201：无效token管控

注意：

当前提供的回执状态只包括0、2、5、6、7、8、9、10、102、201，设备不在线时不发送回执，设备上线后消息未过期补发成功后会发送回执，如果设备一直不在线，则一直不会触发回执。  
最佳实践：建议针对上述状态中的2、5、6、7、8、9、10、201做过滤处理，减少对这些用户的无效推送。

# 4\. 返回值

**表5-15**

参数名称                 | 类型                 | 是否必选                 | 描述                   
---|---|---|---  
errno                 | JSON String                 | 可选                 | 开发者服务端返回的处理结果状态。                   
errmsg                 | JSON String                 | 可选                 | 开发者处理结果的描述信息。

        2. Content-Type:application/json;charset=UTF-8
        3. Content-Length: 66
        4. {
        5.     "errno": "0",
        6.     "errmsg":"success"
        7. }
