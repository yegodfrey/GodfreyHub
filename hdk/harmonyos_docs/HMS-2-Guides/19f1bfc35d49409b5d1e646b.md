# 1. 场景介绍

用户完成支付后，有时会由于网络异常、应用异常退出、应用服务器故障、应用客户端问题等原因，应用无法获取用户实际支付结果，导致未及时发放用户购买的商品，从而出现掉单的情况。针对这种情况，华为支付服务提供了订单查询能力。在支付请求前，由应用持久保存订单号，然后在可能丢单的情况下，调用订单查询能力来查询实际支付结果。

实际支付处理时，以下场景需要查询订单：  
● 应用具备订单查询功能，用户进入订单后，应用主动查询用户的订单状态。  
● 在出现掉单情况后应用将未支付成功的订单号保存，用户每次登录应用，应用需要根据订单号定期查询订单状态。  
● 支付过程中出现以下支付异常，应用需要立即查询订单的真实状态。如果订单状态仍在处理中，需要继续定时查询，直至订单成功或失败。  
    − 应用在支付过程异常中断（关机、程序崩溃等），支付结果码为-1005。  
    − 支付后onActivityResult回调参数resultCode不为Activity.RESULT_OK。  
    − 支付结果码为30002，30005，30006，30008，30012，30013。  
   

    − 支付结果码为0但是验签失败。    

# 2. 业务流程

1\. 应用在用户操作过程中触发查询订单状态的场景，具体参见场景介绍。

2\. 应用根据支付未成功的订单号调用[getOrderDetail](https://developer.huawei.com/consumer/cn/doc/development/HMS-2-References/hmssdk_jointOper_api_reference_c5)接口请求查询订单。

3\. HMS SDK通过回调方式返回查询结果。

4\. 应用根据查询结果确认订单是否已经支付成功。

# 3. 注意事项

● 没有服务器的单机应用，只能调用getOrderDetail接口查询订单。有独立开发者服务器的应用，除了调用getOrderDetail接口，还可以直接向开发者服务器查询订单。  
● 必须已经提前为应用申请支付服务，参见[申请支付服务](https://developer.huawei.com/consumer/cn/doc/development/HMS-2-Guides/hmssdk_jointOper_prepare_applypayservice)。  
● 支付查询订单支持的地区为[全球价格信息](https://developer.huawei.com/consumer/cn/service/josp/agc/app/views/operate/productmng/html/price.list.html)中所列地区。  
   

● 支付查询订单只支持同服务地查询，切换帐号服务地后将无法查询到原服务地订单。    

# 4. 开发步骤

1、当出现需要查询订单的情况时，应用封装查询订单相关参数，具体参数参见[getOrderDetail](https://developer.huawei.com/consumer/cn/doc/development/HMS-2-References/hmssdk_jointOper_api_reference_c5)接口。
      
      1. OrderRequest or = new OrderRequest();
             
             
        2. showLog("checkPay: begin=" + reqId);
             
             
        3. or.setRequestId(reqId);
             
             
        4. or.setTime(String.valueOf(System.currentTimeMillis()));
             
             
        5. or.setKeyType("1");
             
             
        6. or.setMerchantId(cpId);
             
    
    

2、生成签名字符串，即getOrderDetail接口的sign字段。  
● 如果由应用服务端生成签名字符串，参见[支付签名的生成方法](https://developer.huawei.com/consumer/cn/doc/development/HMS-2-Guides/hmssdk_jointOper_generateSign)中的生成规则生成。  
● 如果由应用客户端直接生成支付签名字符串，可以参考HMS SDK工程目录PaySignUtil.java中的rsaSign()方法生成支付签名。示例代码如下：
      
      1. or.sign = PaySignUtil.rsaSign(PaySignUtil.getStringForSign(or), pay_priv_key);
             
    
    

PaySignUtil.getStringForSign(or)返回支付参数组成的待签名字符串，pay_priv_key为支付私钥。

警告：

如果开发者有自己的服务器，为了保证支付私钥的安全性，强烈建议在应用服务端生成签名字符串。        

  
   

3、调用getOrderDetail接口并处理回调。    

● 如果订单结果为空，保存订单号，间隔一段时间后重新调用getOrderDetail接口再次查询。例如30分钟后再次查询，超过24小时当支付失败处理。  
● 如果订单结果不为空且返回码为0，则参考[对响应消息验签的方法](https://developer.huawei.com/consumer/cn/doc/development/HMS-2-Guides/hmssdk_jointOper_verifySign)对查询结果进行验签。  
    − 验签成功则表示支付成功，发放商品。  
    − 验签失败则当支付失败处理，需检查查询参数、支付公钥等是否正确。  
● 如果订单结果不为空且返回码为-1，表示本次支付失败，结束查询流程。  
● 如果订单结果不为空且返回码为30005，表示网络问题，可立即重新调用getOrderDetail接口再次查询。  
● 如果订单结果不为空且返回码仍然为300开头的错误码，表示可能支付尚未完成，保存订单号。间隔一段时间后重新调用getOrderDetail接口再次查询。例如30分钟后再次查询，超过24小时当支付失败处理。  
   

示例代码如下：    

   
      
      1. HMSAgent.Pay.getOrderDetail(or, new GetOrderHandler() {

        5.         if (checkPayResult != null && checkPayResult.getReturnCode() == retCode) {
                 
                 
        6.             // 处理支付业务返回码
                 
                 
        7.             if (retCode == HMSAgent.AgentResultCode.HMSAGENT_SUCCESS) {
                 
                 
        8.                 boolean checkRst = PaySignUtil.checkSign(checkPayResult, pay_pub_key);
                 
                 
        9.                 if (checkRst) {
                 
                 
        10.                     //TODO: 支付成功，发放对应商品
                 
                 
        11.                     showLog("checkPay: Pay successfully, distribution of goods");
                 
                 
        12.                 } else {
                 
                 
        13.                      //TODO: 验签失败，当支付失败处理 
                 
                 
        14.                     showLog("checkPay: Failed to verify signature, pay failed");
                 
                 
        15.                 }
                 
                 
        16.                 // 不需要再查询
                 
                 
        17.                 removeCacheRequestId(checkPayResult.getRequestId());
                 
                 
        18.             } else if (retCode == PayStatusCodes.ORDER_STATUS_HANDLING
                 
                 
        19.                             || retCode == PayStatusCodes.ORDER_STATUS_UNTREATED
                 
                 
        20.                             || retCode == PayStatusCodes.PAY_STATE_TIME_OUT) {
                 
                 
        21.                 //TODO: 未处理完，需要重新查询。如30分钟后再次查询。超过24小时当支付失败处理 
                 
                 
        22.                 showLog("checkPay: Pay failed. errorCode="+retCode+"  errMsg=" + checkPayResult.getReturnDesc());
                 
                 
        23.             } else if (retCode == PayStatusCodes.PAY_STATE_NET_ERROR) {
                 
                 
        24.                 //TODO：网络失败，需要重新查询
                 
                 
        25.                 showLog("checkPay: A network problem caused the payment to fail. errorCode="+retCode+"  errMsg=" + checkPayResult.getReturnDesc());
                 
                 
        26.             } else {
                 
                 
        27.                 //TODO： 支付失败，不需要再查询
                 
                 
        28.                 showLog("checkPay: Pay failed. errorCode="+retCode+"  errMsg=" + checkPayResult.getReturnDesc());
                 
                 
        29.                 removeCacheRequestId(reqId);
                 
                 
        30.             }
                 
                 
        31.         } else {
                 
                 
        32.             //TODO: 没有结果回来，需要重新查询。如30分钟后再次查询。超过24小时当支付失败处理
                 
                 
        33.             showLog("checkPay: Pay failed. errorCode="+retCode);
                 
                 
        34.         }
                 
                 
        35.    }
                 
                 
        36. });
