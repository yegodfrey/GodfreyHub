# 订阅专用功能说明

#### 配置订阅型商品

订阅型商品用订阅组来管理维护，所以在创建订阅型商品前，需要先创建订阅组，并在创建订阅型商品时指定商品所在的订阅组。订阅组用于承载同类型商品的管理，一个订阅组可以包含多个订阅型商品，且同一个订阅组只有一个商品是处于生效状态。当商品处于生效状态时，您需要为用户提供该商品对应的服务。这样的机制为您提供了便捷方式，让商品服务大致相同但有细微差别的需求得以快速实现。

示例：

您若想提供视频会员的订阅型业务，则需要创建一个订阅组，专门用于承载视频会员类商品。同时，如果您希望提供不同的续费周期供用户选择，那么您可以在刚创建的订阅组里，添加不同续费周期的商品，比如：月度续费商品、半年续费商品、年度续费商品等。当前续费周期可选值有1周、30天、31天、1个月、2个月、3个月、6个月和12个月，您可在配置订阅型商品时按需选择。为了让您的订阅型商品更有吸引力，订阅型商品提供了两种促销手段：

* 折扣价格：设置一个低于商品原价的价格，让用户在购买初期以低价享受一段时间的商品服务。
* 免费试用：设置一个免费时间段，让用户在购买初期免费享受一段时间的商品服务。

促销限制：

1. 用户对每个订阅组至多享受一次促销。如果一个订阅组里的多个商品均配置了促销活动，在用户尝试切换该订阅组的其他商品时，用户只能享受在该订阅组第一次遇到的促销。当切换订阅时在该订阅组再次遇到促销，将不再享有促销资格。
2. 促销价享受的触发方式是新订阅、恢复订阅、切换订阅三种情况。促销的享受资格不受订阅方式影响，无论是新发起的订阅，恢复订阅，还是切换订阅等，均遵从"用户对每个订阅组至多享受一次促销"的原则，只要没有享受过该订阅组的促销，就可以享受促销。

具体配置方法请参见[配置商品信息](https://developer.huawei.com/consumer/cn/doc/HMSCore-Guides/config-product-0000001050033076)。  

#### 订阅状态及续期处理

通常情况下，一个完整的订阅需具备以下几个阶段。

<br />

* 优惠期：包括免费试用和促销两种模式。如果购买订阅型商品时，商品拥有优惠价格且用户有资格享受，则用户成功订阅后将进入优惠期。
* 第一次标准价格续期：第一次按商品标准价格的续期处理，该标准价格为订阅时的商品原价。如果用户在优惠期结束后进入该续期阶段，且在优惠期内，您调整了商品价格，则此次续期价格不受您调整价格的影响，以进入优惠期时商品的标准价格为准。
* 第二次标准价格续期及其他续期：与第一次标准价格续期不同的是，后续的每次续期都会在订阅关系过期前10天开始获取下次续期扣款的金额和商品状态，并基于更新后的订阅价格和商品状态来处理下一个续期。
* 失效期：没有续期（比如主动取消续期）或订阅周期末扣费失败则进入失效期。失效的订阅具有保留期（保留期详见以下说明），在保留期内，用户无法享受订阅型商品的服务，但可以在恢复订阅后再次享受应用提供的服务。  
  ![](https://media:201774940770192068)  
  失效订阅的保留期：
  * 中国大陆：180天
  * 其他国家或地区：30天

对于用户而言，订阅有如下几个状态：

![](https://media:201774940770281069)

* 续期：订阅处于生效状态，即用户可以享受商品对应的服务，其下一次续期也将按期进行扣费以续期。
* 到期：订阅处于生效状态，用户仍可以享受商品对应的服务，但订阅续期已被用户取消，将不会进行下一次的续期扣费。
* 已到期：订阅处于失效状态，用户无法享受商品的服务。原因是最近一次的续期扣费没有成功，用户取消订阅，用户不同意涨价或者是扣款账户发生了异常，均可导致订阅进入该状态。此外，该订阅会进入至多180天的[保留期](#ZH-CN_TOPIC_0000001050130264__li17105111312918)。
* 待生效：订阅还未开始生效，用户暂时还无法享受该订阅型商品的服务。当用户在订阅组内进行切换订阅时，如果切换到一个下周期生效的订阅时，则新切换的商品处于待生效状态，需要等原订阅到期后才生效。在用户的切换操作完成后，原订阅会变为到期状态，而新切换的商品为待生效状态，并且会在原订阅型商品的编辑订阅页内显示新切换商品的开始时间。

订阅续期处理

订阅的下一个续期价格（包括原价、涨价和降价）是在续期前10天确定，该时间比1周的订阅周期长。因此对于订阅周期为1周的订阅型商品，价格变化后在下一次续期时仍然按照原价格进行，此后的价格将在10天前确认。

在订阅周期结束前24小时，华为IAP会尝试向用户发起扣款以完成订阅型商品的续期。若扣费失败，华为IAP会在一定期限内重新尝试扣费，从而恢复订阅。  
![](https://media:201774940770377070)  
因为扣费失败而进入失效期内的订阅，每天会重试一次扣费，在超过重试时间窗后将结束重试，其中重试时间窗基于配置指定。  

#### 用户变更订阅关系

用户可以在HMS Core（APK）的订阅管理页面里，对订阅进行如下操作。

* 取消订阅：对已购订阅型商品进行取消操作。取消成功，则订阅将不会进行下一周期的续费，但不影响当前周期对订阅的使用。
* 恢复订阅：对于处于到期、已到期的订阅，用户可以恢复订阅，以再次享受订阅对应的服务。
* 切换订阅：对已购订阅型商品，进行同一个订阅组不同订阅型商品的切换操作，有如下两种切换效果：
  * 立即生效的切换订阅：用户原订阅的剩余金额将折算成新订阅的天数，延长新订阅的有效期。 目前这种切换效果的触发场景为：原订阅的续费周期和即将更换的订阅续费周期相同。
  * 下周期生效的切换订阅：原订阅设置为到期状态，新订阅为待生效状态，新订阅会在原订阅的失效日期开始扣费并生效。目前这种切换效果的触发场景为：原订阅的续费周期和即将更换的订阅续费周期不同。

![](https://media:201774940770413071)  
目前的订阅型商品并没有等级的概念，后续将会实现订阅等级的概念。在加入等级后，对于切换订阅场景，切换机制会优先判断新订阅的商品和原商品的等级关系，如果等级相同，则切换效果的触发场景不变。如果从低等级切换到高等级的升级切换订阅，效果为立即生效。如果是从高等级切换到低等级的降级切换订阅，效果为下周期生效。  

#### 修改订阅型商品

调整订阅型商品价格

您可以为每个订阅型商品降低或提高价格。

* 降低价格：对所有用户生效，包括已经订阅的用户和新订阅的用户，在订阅的下一次续费起生效。
* 提高价格：当提高订阅型商品价格时，有两种策略可选：
  * 为已订阅的用户保留原价，对新订阅的用户使用新的价格。
  * 对已订阅的用户生效。华为IAP会在下一个续期日提前10天通知已订阅的用户商品价格上涨以及新价格的收费日期。如果在距离下个续期日10天内调整价格， 则下次续期将按照现有价格再续订一个周期，然后在下个周期结束提前10天通知已订阅的用户。其他的限制还包括：
    * 订阅型商品新的价格需要已订阅用户的同意，如果用户不同意，其订阅不会自动续期，直到用户同意涨价。
    * 在价格调整生效后，您将无法撤销。您可以计划新的价格调整从而实现降价，但此前因价格提高而选择停止续订的用户需要重新订阅。
    * 如果用户支付了促销价格的订阅型商品且当前周期为以促销价格购买订阅型商品的周期，则用户下一周期将按照原价进行订阅，再在下一个续费周期按照上述规则执行。

处理订阅型商品下架

在处理订阅型商品的下架时，需要考虑对用户的影响。

在您停止提供订阅服务前，您应该通过下架该商品来防止新用户订阅。建议您将订阅型商品的下架时间与其续费周期相对应。例如，在订阅型商品续费周期为1个月的情况下，您应该提前1个月将您的订阅下架，这可以在停止提供订阅的商品服务之前让用户体验到完整时限的商品服务，并且将不会在下一个订阅续期日期被收取费用。以此类推，对于续费周期为1周的订阅需要提前7天，对于续费周期为6个月的订阅需要提前6个月。当您将某个订阅型商品下架时，您的用户将收到有关订阅终止通知。  

#### 提供订阅管理的页面跳转

您的应用可以通过[startIapActivity](https://developer.huawei.com/consumer/cn/doc/HMSCore-References/iapclient-0000001050137587#section16600172243819)接口跳转到HMS Core（APK）的管理订阅页面和编辑订阅页面。管理订阅页面展示的是当前用户在您的应用内已订阅的商品列表，编辑订阅页展示的是用户已在您的应用订阅的某个商品详情及该商品所在订阅组的其他商品的信息。

* 手机订阅管理：

![](https://media:201774940770470072 "点击放大") ![](https://media:201774940770573073 "点击放大")

* 智慧屏订阅管理： ![](https://media:201774940770688074 "点击放大")

  ![](https://media:201774940770785075 "点击放大")

使用方式如下：

* 跳转到管理订阅页  

  ```
  "Java"
  // 创建一个StartIapActivityReq对象
  StartIapActivityReq req = new StartIapActivityReq();
  req.setType(StartIapActivityReq.TYPE_SUBSCRIBE_MANAGER_ACTIVITY);
  // 获取调用接口的Activity对象
  final Activity activity = getActivity();
  IapClient mClient = Iap.getIapClient(activity);
  Task<StartIapActivityResult> task = mClient.startIapActivity(req);
  task.addOnSuccessListener(new OnSuccessListener<StartIapActivityResult>() {
      @Override
      public void onSuccess(StartIapActivityResult result) {
          Log.i("startIapActivity", "onSuccess");
          // 请求成功，需拉起IAP返回的页面
          if (result != null) {
              result.startActivity(activity);
          }
      }
  }).addOnFailureListener(new OnFailureListener() {
      @Override
      public void onFailure(Exception e) {
          Log.e("startIapActivity", "onFailure");
      }
  });
  ```

  ```
  "Kotlin"
  // 创建一个StartIapActivityReq对象
  val req = StartIapActivityReq()
  req.setType(StartIapActivityReq.TYPE_SUBSCRIBE_MANAGER_ACTIVITY)
  // 获取调用接口的Activity对象
  val activity: Activity = getActivity()
  val mClient = Iap.getIapClient(activity)
  val task = mClient.startIapActivity(req)
  task.addOnSuccessListener { result ->
      Log.i("startIapActivity", "onSuccess")
      // 请求成功，需拉起IAP返回的页面
      result?.startActivity(activity)
  }.addOnFailureListener { Log.e("startIapActivity", "onFailure") }
  ```

#### 沙盒环境的订阅测试

您可以将对应的华为帐号添加到AppGallery Connect的测试帐号里，以实现用该帐号购买时进入沙盒环境的订阅测试。沙盒测试允许您在接入华为应用内支付联调过程中无需真实支付即可完成端到端的测试，帮助您快速测试应用的订阅场景，具体请参见[测试订阅型商品续订](https://developer.huawei.com/consumer/cn/doc/HMSCore-Guides/sandbox-testing-0000001050035039#section7873953153616)。  

#### 接收订阅关键事件的通知

如果您在[AppGallery Connect](https://developer.huawei.com/consumer/cn/service/josp/agc/index.html)申请支付服务时提前配置了订阅通知地址，用户购买订阅型商品后，华为应用内支付服务器会在订阅场景的某些关键事件发生时调用此接口通知您配置的服务器。 主要涉及的场景如下：

* 用户第一次订阅成功。

<!-- -->

* 因特殊原因运营客服主动取消用户的订阅。
* 已过期的订阅自动续期成功。
* 用户主动恢复一个已过期的订阅。
* 用户调整订阅且在下个续订生效。
* 用户主动或者App取消一个订阅，已经收费的服务仍然有效，但是后续续期会停止。
* 用户主动恢复一个已经取消的订阅的续期状态。
* 一个订阅成功续期后。
* 一个到期的订阅进入帐号保留期。
* 用户同意一个订阅型商品的价格上涨，后续续期将以更高的价格进行。

若开发者服务器返回结果为非成功响应（返回的http status code值为200之外的值），将对本次关键事件的通知进行周期性重发。建议在您的服务端收到通知后立即返回成功响应，避免通知消息堆积。  

#### 多角色应用接入订阅专项说明

用户购买订阅型商品时使用的帐号是华为帐号，一个华为帐号在同一订阅商品上只能同时存在一笔订阅。如果您的应用存在多角色，可能会存在权益发放错乱的现象。针对这个场景建议的处理方案如下：

1. 当用户为角色A购买订阅型商品后，该用户的其他角色只允许购买普通包周期商品服务（您可以通过华为消耗型商品自行实现）。
2. 当用户为角色A购买订阅型商品后，再为角色B购买订阅型商品时，您可以自行设计将角色A的剩余权益转移给角色B。
3. 建议您配置多个订阅型商品。如游戏不同区服对应不同角色，每个区服创建独立的订阅商品。
