# FAQ\&常见问题指引

#### 如何联系华为支付团队？

开发者可以进入[在线提单](https://developer.huawei.com/consumer/cn/support/feedback/#/)页面\>选择HMS Core，向华为支付团队提问。华为支付团队会及时解决和回复开发者的问题。

![](https://media:801772763966921051 "点击放大")  

#### 华为支付界面品牌logo是什么，如何获取？

华为支付logo资源可[在此下载](https://developer.huawei.com/consumer/cn/design/resource/)，或者见附件：[华为支付logo.zip](https://media:801772763967061054)  

#### 商户入网后，商户号及authId可以从哪里获取？

商户号：入网完成后可以在"账户中心"-\>"商户主题信息"-\>"商户号"处获取。参考[入网信息确认](https://developer.huawei.com/consumer/cn/doc/HMSCore-Guides/certificate-preparation-0000001596094962#section64183273115)

authId："商户中心"-\>"证书管理"-\>"上传商户证书"-\>"证书ID"处获取。参考[证书介绍](https://developer.huawei.com/consumer/cn/doc/HMSCore-Guides/certificate-preparation-0000001596094962#section1557292604420)  

#### 普通商户、平台类商户和服务商的商户名称在收银台上怎么展示？

收银台展示商户名称规则如下：

* 普通商户：直接展示商户简称。
* 平台类商户：展示平台类商户简称和平台子商户简称。
* 服务商：展示特约商户简称。  

#### 什么情况下需要"敏感信息处理"？

目前只有商户入网及管理中的[子商户入网](https://developer.huawei.com/consumer/cn/doc/HMSCore-References/api-partner-merc-manage-register-submerc-0000001642382965)接口涉及敏感信息加密处理，其他业务均不涉及敏感信息处理。  

#### 支付完成后怎么跳转首页？

华为支付支付成功后都会同步回调支付结果给开发者，可以在回调方法中处理回调结果并返回首页，如：

```
const orderStr = "{\"merc_no\":\"***\",\"prepay_id\":\"1230331185102089244382635044\",\"timestamp\":\"1680259863114\",\"noncestr\":\"1487b8a60ed9f9ecc0ba759fbec23f4f\",\"sign\":\"****\",\"auth_id\":\"***\"}";
HMSPAYMENT.pay(orderStr).then(res => {
    // 解析res参考下表，处理支付结果、刷新跳转界面等操作
}).catch(err => {
    console.error("aggr err: "+ JSON.stringify(err));
});
```

三、调用云测接口报错怎么排查？

请求云侧接口报错或失败排查步骤：

1. 排查签名配置是否正确。具体请参考[证书准备](https://developer.huawei.com/consumer/cn/doc/HMSCore-Guides/certificate-preparation-0000001596094962)章节。确保使用了准确的mercNo，authId及签名私钥。
2. 排查待签字符串是否正确拼接。 对象内的待签字段需要排序后再拼接。对象内的嵌套的下一级对象，如goodsInfo，也需要排序后再拼接。具体示例参考[签名规则](https://developer.huawei.com/consumer/cn/doc/HMSCore-References/api-signature-rule-0000001538533912)
3. 排查签名算法是否处理正确。商户请求华为支付侧的签名方式为"SHA256WithRSA/PSS"，请参考[客户端示例代码](https://developer.huawei.com/consumer/cn/doc/HMSCore-Examples/client-sample-code-0000001538858772)工程里的签名方式处理。
4. 请确保使用的 bcpkix-jdk15on版本jar包，不要使用老的jar包，否则存在包冲突或算法不一致的情况。
5. 排查http请求是否合法。 如https协议及加密套件是否版本过低，数据交换格式是否为application/json等。请参考API接口说明。
6. 排查该业务接口请求的参数处理是否正确。 如url是否正确，参数是否必填，字段长度是否满足约束，业务参数是否合法。 具体请参考各接口的说明。  

#### 通知回调相关问题

一、通知回调问题怎么排查？

* 排查签名配置是否正确。具体请参考[证书准备](https://developer.huawei.com/consumer/cn/doc/HMSCore-Guides/certificate-preparation-0000001596094962)章节。确保使用了准确的mercNo，authId及签名私钥。
* 排查是否接收了通知结果的完整内容。切勿直接使用对象接收通知内容，也不要对请求体做任何修改调整。直接使用通知的完整内容进行验签才能保证验签的合法性。
* 排查签名算法是否处理正确。商户请求华为支付侧的签名方式为"SHA256WithRSA/PSS"，请参考[客户端示例代码](https://developer.huawei.com/consumer/cn/doc/HMSCore-Examples/client-sample-code-0000001538858772)工程里的签名方式处理。
* 请确保使用的 bcpkix-jdk15on版本jar包，不要使用老的jar包，否则存在包冲突或算法不一致的情况。
* 排查商户提供的https域名是否满足华为的安全性要求。 如https协议及加密套件是否版本过低，数据交换格式是否为application/json等。请参考API接口说明。
* 排查商户提供的服务器，是否存在有IP防火墙策略限制。如果存在，需要对华为支付出口网段开通白名单。
* 商户回调通知处理正常后，请在返回3秒内返回应答响应{"resultCode":"000000","resultDesc":"Success."}。否则华为支付会认为通知失败，会触发重试机制
* 华为支付服务器调用回调地址发生如"找不到有效的证书请求目标地址"等异常。请检查及验证回调地址是否可外网正常访问。

<br />

二、部分提供通知回调的API接口中的callbackUrl参数是否可以自定义？回调通知的报文是否支持商户自定义？

* API接口callbackUrl参数是可以由商户自行定义的HTTPS协议的有效接口。
* 回调通知内容暂时无法自定义。

<br />

三、接收到多次回调，怎么解决？

1. 接收到多次回调是开发者返回的响应报错，导致重试。请检查返回的响应格式不是application/json以及响应的报文是不是 {"resultCode":"000000","resultDesc":"Success."} 。
2. 自验证回调接口是否可正常接收响应，如华为支付响应连接超时也会触发重试回调。

<br />

四、支付成功后没有收到回调？

* 检查预下单是传入的callbackUrl接口地址是否有效。
* 开发者们服务器是否有白名单等网络限制
* 加密套件不一致，目前华为支付支持的加密套件如下：

```

AES256-GCM-SHA384

ECDHE-ECDSA-AES128-SHA
ECDHE-RSA-AES128-SHA
ECDHE-RSA-AES256-SHA
ECDHE-ECDSA-AES256-SHA
AES128-SHA
AES256-SHA
```

五、商户提供的回调通知接口在华为支付生产环境需要加网络白名单吗？如何验证提供的回调地址华为支付服务器访问是否正常？

1. 回调通知当前未做白名单限制，不需要在华为支付添加白名单，
2. 提供的回调地址，保证公网可正常访问即可。

#### 加签验签相关问题

一、接入开发时，请求参数的签名、结果验签的场景是什么？签名和验证签名如何实现？

签名：商户客户端发送给华为支付服务器的请求必须签名后发送给华为支付服务器，否则无法成功创建订单、商户服务器发送查询订单状态请求时需要签名、商户服务器发送退款请求时需要签名。

验签：商户客户端收到sdk返回的结果时可对支付状态验签、华为服务器异步通知商户服务器订单状态时，商户服务器务必使用华为支付平台公钥验证签名、华为服务器异步通知商户服务器退款状态时，商户服务器务必使用华为支付平台公钥验签。

详细场景介绍参见[签名规则](https://developer.huawei.com/consumer/cn/doc/HMSCore-References/api-signature-rule-0000001538533912)和[验签规则](https://developer.huawei.com/consumer/cn/doc/HMSCore-References/api-signature-rule-0000001538533912#section395172634813)。签名实现可以参考[签名规则](https://developer.huawei.com/consumer/cn/doc/HMSCore-References/api-signature-rule-0000001538533912)，验证签名实现可以参考[验签规则](https://developer.huawei.com/consumer/cn/doc/HMSCore-References/api-signature-rule-0000001538533912#section395172634813)。

<br />

二、请求头PayMercAuth中的callerId和请求体中的mercNo或者combineMercNo是什么关系？

callerId和mercNo或者combineMercNo都是请求发起方商户号。

三、服务器是node.js代码，怎么实现对请求参数签名？

参见签名示例：

```
import jsrsasign from 'jsrsasign';
export function signRsa(plainData : string) {
  let rsa = new jsrsasign.RSAKey();
  const priKey = '-----BEGIN PRIVATE KEY-----\n' 
    '开发平台中获取的商户私钥\n'
  + '-----END PRIVATE KEY-----\n';
  rsa = jsrsasign.KEYUTIL.getKey(priKey);
  const sig = new jsrsasign.KJUR.crypto.Signature({
    alg: 'SHA256withRSAandMGF1',
  });
  sig.init(rsa);
  sig.updateString(plainData);
  return jsrsasign.hextob64(sig.sign());
}
```

<br />

四、接口请求一致响应"无效的签名"应该如何排查？

1. 加签私钥和上传到商户平台的公钥是否配对。
2. 排查待签字符串是否正确拼接。 对象内的待签字段需要排序后再拼接。对象内的嵌套的下一级对象也需要排序后再拼接。具体示例参考[签名规则](https://developer.huawei.com/consumer/cn/doc/HMSCore-References/api-signature-rule-0000001538533912)。
3. 排序拼接的字段命名和请求参数命名方式是否一致（如加签字段使用了匈牙利命名方式，请求参数则用小驼峰命名方式，导致加签验证内容不一致）。
4. 相关加签内容字段（如sign）内容是否正确设置（如加签后内容未及时设置到sign字段，一直使用固定的sign内容去发起请求）。
5. 检查加签算法是否和要求的加签算法一致。

<br />

五、为什么都是同一个接口，如支付、退款等，请求加签用RSA，回调验签用SM2，加签验签方式是不同的？回调验签的方式可以由商户自行决定吗？

1. 商户预下单请求加签，华为支付提供了SHA256WithRSA/PSS和SM2两种签名方式，由商户自行选择使用哪一种签名方式进行签名。
2. 对于支付业务，应监管要求，需要支持国密算法。回调通知华为支付统一使用SM2进行加签，所以目前只能使用SM2进行回调验签，无法由商户选择。

<br />

六、当前华为支付API接口请求中支持的加签验签方式有哪些？

请求加签验签方式：RSA/SM2

通知回调验签方式：SM2

<br />

七、请求头"PayMercAuth"鉴权字段headerSign签名，排除headerSign外，是否需要排除bodySign？ 以及headerSign签名只是对请求头参数（Content-Type和PayMercAuth）进行签名吗，其他的诸如Content-Length需要参与签名吗？

* 请求头"PayMercAuth"鉴权字段headerSign签名不用排除bodySign。
* headerSign签名仅对PayMercAuth排除headerSign后其余字段并按[签名规则](https://developer.huawei.com/consumer/cn/doc/HMSCore-References/api-signature-rule-0000001538533912)排序拼接后做签名，诸如Content-Type、Content-Length等字段都不参与签名。

<br />

八、请求接口加签验证中，如果请求头"PayMercAuth"中bodySign字段为空值，会做验签吗？还是会先校验字段？

鉴权请求头"PayMercAuth"会先校验相关字段再做验签。bodySign字段设置为空值，不会做验签，直接响应异常。  

#### 支付相关问题

一、哪里可以获取到华为支付系统订单号sysTransOrderNo和combineSysTransOrderNo?

支付成功后，回调通知里面会返回华为支付服务订单号sysTransOrderNo或combineSysTransOrderNo。

<br />

二、预下单后一段时间后再支付，能否有接口查到prepayId？

目前没有提供可以查询prepayId的接口。

<br />

三、商户侧没有传营销信息，支付回调里面为什么会有营销信息？

营销活动不需要商户侧传递，拉起收银台前华为支付会根据用户和商户去获取华为支付侧配置的营销活动信息展示在收银台，若用户使用了营销活动，支付结果就会返回营销信息。

<br />

四、支付接口expireTime字段含义是什么，生成规则是什么？

expireTime字段为交易要求过期时间（较当前时间晚\[5分钟，15天\]）以及要使用必须传准确的UTC时间，如不传默认为2小时。

开发者可以参考如下函数获取对应的UTC过期时间：

```
/**  
* 获取UTC格式的过期时间  
* @param expectedExpiredTime 范围为5分钟到15天，请换算为分钟  
* @return UTC时间  
*/ 
private static String getTradeExpireTime(int expectedExpiredTime) {
     SimpleDateFormat formatter = new SimpleDateFormat("yyyy-MM-dd'T'HH:mm:ss.SSSZ");
     formatter.setTimeZone(TimeZone.getTimeZone("UTC"));
     Calendar calendar = Calendar.getInstance();
     calendar.set(Calendar.MINUTE, calendar.get(Calendar.MINUTE) + expectedExpiredTime);
      return formatter.format(calendar.getTime());
 }
```

#### 退款相关问题

一、申请退款一直响应失败怎么处理？

1. 检查退款目标账号状态是否正常（如证件是否过期，信息是否填写完备）。
2. 订单不存在或者已经过期导致无法发起退款，需要人工介入。
3. 申请的退款金额超过原支付交易可退款金额。

<br />

二、申请退款接口报余额不足？

请在[华为支付商户平台](https://petalpay-merchant.cloud.huawei.com/)检查账户余额是否充足，可能已经结算到银行卡导致商户余额不足。

<br />

三、查询退款订单信息报参数错误？

华为支付对外提供了两个退款查询接口，请检查参数会否传递正确，查询接口如下：

1. 通过商户订单号（mercOrderNo）来进行退款订单查询
2. 通过华为支付系统订单号（sysTransOrderNo）进行退款订单查询

<br />

四、不换单重复发起退款，返回000000，不返回退款金额是为什么？

请检查首次发起退款是否已正常完成退款。订单已经全额退款后，重复发起退款不会再返回退款金额。

<br />

五、华为支付的退款操作，除了通过接入指导中的退款接口退款，还有财务功能相关平台吗？能从这个平台进行退款？

除接入指导文档中提供给商户的退款接口进行退款，商户也可以登录[华为支付商户平台](https://petalpay-merchant.cloud.huawei.com/)-交易中心-交易明细-订单详情页面，点击退款菜单发起退款操作。

这个功能商户不需要对接联调，可以直接使用，支持发起部分退款和全额退款。

<br />

五、退款接口字段mercRefundOrderNo和sysTransOrderNo有什么不同？

mercRefundOrderNo商户自定生成，保证唯一性，不超过46位。

sysTransOrderNo是华为支付返回的交易订单号。  

#### 签约代扣相关问题

一、华为支付签约的免密代扣在哪里可以解约？

开发者可以通过如下途径完成免密代扣解约

1. "华为钱包"-"我的"-"华为支付"-点击右上角菜单栏-"免密代扣"-"华为支付免密代扣"完成解约。
2. 通过华为支付服务对开放的[API接口](https://developer.huawei.com/consumer/cn/doc/HMSCore-References/api-apply-unsign-0000001631099308)进行解约。

<br />

二、同一用户重复签约华为支付服务会生成多笔签约吗？

同一个商户号、使用同一个华为支付服务账号、使用同一套签约模板时，多次重复签约时会只会生成一笔签约。  

#### 账单相关问题

一、华为支付商户平台能否查订单（对账单、结算单）吗？

登录[华为支付商户平台](https://petalpay-merchant.cloud.huawei.com/)，可以查询账单明细（可以查询订单对应生成对账单和结算单，不能在商户平台直接查询订单）。

对账单查询及下载方法：开发者可以在登录商户平台之后，进入【交易中心】-\>【支付流水对账】页面，根据"对账单时间"查询支付流水对账单后，点击页面右边的"下载"按钮将对账单下载至本地查看对账单详情。

结算单明细下载方法：开发者可以在登录商户平台之后，进入【交易中心】-\>【查看结算单】页面，根据"结算时间"查询结算单后，点击"导出结算明细"按钮查看结算明细。

结算费率说明：在交易过程中会产生一定的手续费，结算时扣除相应的手续费再结余下的金额。具体费率根据开发者申请的支付方式对应的手续费决定，单笔订单四舍五入，保留小数点后2位。

开发者可将支付流水对账单结合结算明细进一步查看，结算单明细包含所有在该结算周期清算完成的交易信息。

#### 收银台相关问题

一、拉起收银台无反应？

请检查以下注意事项：

1. 入参格式要求：orderStr注意是JsonStr的格式，不要json对象，也不要重复序列化。
2. 快应用场景下，appId必填，还请传入对应的appId。
3. 如果在快应用加载器可以拉起收银台，正式环境下拉不起来，请检查appId入参是否正确。
4. 华为支付收银台目前仅支持在安装HMS CORE的华为手机上拉起。还请确认联调用设备是否满足。
5. HMS CORE版本过低，或用户初次拉起，可能存在引导升级的情况，属于正常情况，请勿取消退出。

<br />

二、拉起收银台报错？

该情况一般属于入参格式存在问题，还请根据SDK支付的回调信息进行定位，请检查一下注意事项：

1. noncestr入参每次都是唯一的。
2. timestamp时间戳需要是当前时间。
3. 签名是否没有排序拼接。
4. 签名后的入参字段重新赋值。
5. prepay_id对应的订单确保未过期或未完成支付。
6. 检查网络转态是否正常或有开启代理。

<br />

三、收银台支付报错"应用信息校验不通过，请联系商家处理"？

1. 应用属性是否配置appid，确认appid配置是否有调整。
2. 是否配置添加了公钥指纹，参见[添加公钥指纹](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/application-dev-overview#section1726913517284)。
3. 检查一下orderStr中merc_no、app_id、auth_id等参数是否正确。  

#### 接口异常报错

一、API接口请求响应异常:"INVALID_TIME"？

可能是请求头"PayMercAuth"中 "time"字段的时间戳参数过期了，可重新生成后再发起请求。

<br />

二、API接口请求异常：ERROR - \[AbstractRestInvocation.java:invoke:266\] - \[\] - Invocation failed, cause=InvocationException: code=400;msg=CommonExceptionData \[message=Parameter is not valid for operation\] ?

请检查请求头Content-Type是否正确设置为"application/json"。

<br />

三、请求华为支付提供的Api接口报异常："200001 非法的参数"，怎么处理？

1. 检查请求报文中的参数是否和接口参数对应。
2. 检查请求报文中是否有多余的参数字段。
