# 处理延迟付款型支付

延迟付款型支付，即用户在您的应用内购买时，并非即时完成付款，仅当用户完成剩余付款步骤后，才完成交易的一种支付模式。延迟付款型支付允许一笔订单长时间处于待付款状态，只要用户在规定的时间段内完成付款，就能正常完成这笔交易。

例如在拉美地区，当地流行现金支付方式，用户在应用内购买商品时使用现金支付方式来创建一个Pending状态的订单，同时会收到付款号码和付款指引。然后，用户可以选择一家线下便利店出示付款号码，使用现金完成该笔订单的支付。华为应用内支付随后会通知您订单已完成购买，您可以进行发货处理。

当前支持延迟付款型支付的国家/地区如下表：  

|序号|国家/地区|国家/地区码|币种|支付方式|
|:-|:----|:-----|:--|:--------|
|1|埃及|EG|EGP|Fawry Pay|
|2|哥伦比亚|CO|COP|Efecty|
|3|墨西哥|MX|MXN|OXXO Pay|
|4|智利|CL|CLP|Multicaja|
|5|中国|CN|CNY|好友代付|

若您的应用在延迟付款型支付的国家/地区上架，可以选择改造您的应用以支持在您的应用中使用延迟付款型支付。

在应用初始化过程中，您的应用需要调用[enablePendingPurchase](https://developer.huawei.com/consumer/cn/doc/HMSCore-References/iapclient-0000001050137587#section19183633182613)来使能延迟付款型支付。之后您的应用通过[createPurchaseIntent](https://developer.huawei.com/consumer/cn/doc/HMSCore-References/iapclient-0000001050137587#section1255302563115)接口发起支付时，在随后打开的IAP收银台中，用户才可以选择相应的现金支付方式来完成支付。选择现金支付方式进行支付时，若用户离开收银台时暂未完成支付，您的应用将接收到错误码60057（OrderStatusCode.ORDER_STATE_PENDING），标记此次交易处于Pending状态，代表用户已使用现金支付方式成功下单，正在等待线下付款。若已完成支付，您的应用将接收到返回码0（OrderStatusCode.ORDER_STATE_SUCCESS）和购买数据，此时按照标准流程处理即可，具体请参见[确认交易](https://developer.huawei.com/consumer/cn/doc/HMSCore-Guides/dev-guide-0000001050130254#section1868165018437)。

当订单从Pending状态变更为Purchased时您才能进行发货处理。为了能让您的应用尽快获取到订单的最新状态，及时给用户发货，IAP服务器提供了订单状态从Pending到Purchased的变更通知，具体请参见[接收延迟付款型支付关键事件通知](https://developer.huawei.com/consumer/cn/doc/HMSCore-Guides/notifications-about-pending-payment-events-0000001184383570)。您的应用服务器可以通过监听处理该通知刷新订单状态，进行发货处理。另外，也可在您的应用中接入[消耗型商品的补单流程](https://developer.huawei.com/consumer/cn/doc/HMSCore-Guides/redelivering-consumables-0000001051356573)或[提供非消耗型商品对应的服务](https://developer.huawei.com/consumer/cn/doc/HMSCore-Guides/dev-guide-0000001050130254#section1752543164411)来获取已完成支付的商品的购买数据，随后执行相关的发货操作。

* 仅手机/平板支持延迟付款型支付，其他设备类型不支持。
* 仅使用[createPurchaseIntent](https://developer.huawei.com/consumer/cn/doc/HMSCore-References/iapclient-0000001050137587#section1255302563115)接口购买一次性商品场景支持延迟付款型支付，包括消耗型商品、非消耗型商品。
