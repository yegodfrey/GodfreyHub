# 集成调测类问题

如果您在下面没有找到需要的问题，请加入[Stack Overflow](https://stackoverflow.com/questions/tagged/huawei-mobile-services?tab=Frequent)社区参与讨论。

#### 修改agconnect-services.json配置文件中的collector_url后，导致数据上报失败？

**【根因分析】**

Analytics Kit会对collector_url做允许清单校验，在SDK中预置的允许清单域名为：

{“dbankcloud.com”,“dbankcloud.cn”, “dbankcloud.eu”,“dbankcloud.asia”, “digitalincloud.com”,“digitalincloud.cn”,“digitalincloud.eu”,“digitalincloud.asia”, “dbankcdn.com”,“dbankcdn.cn”,“dbankcdn.eu”,“dbankcdn.asia”,“hicloud.com”} 该地址由系统维护，不允许修改。

**【解决方法】**

collector_url由系统维护，不允许修改。如果您已修改，请下载最新的“agconnect-services.json”文件。

      * iOS接入调试模式，详情请参见[接入调试](https://developer.huawei.com/consumer/cn/doc/HMSCore-Guides/ios-accessing-0000001050168481#section12460142503316)。

#### Android应用开启了调试模式，但应用调试界面未显示上报数据？

**【根因分析】**

可能有如下原因：

      * 未开通分析服务。 
      * 获取的“agconnect-services.json”不是原始文件。 
      * 端侧logcat日志数据没有上报成功。 

**【解决方法】**

按如下步骤检查配置：

      1. 请确保已开通分析服务并检查API管理的开关是否开启（系统默认开启）。
      2. 请确保“agconnect-services.json”文件是原始文件，未有任何改动。
      3. 查看端侧logcat日志数据是否上报成功，如果日志中有打印“resultCode: 200”，说明数据上报成功。未成功可能有如下两个原因：

原因一：您使用了tools:node="replace"，该参数导致应用某些配置与AGC sdk配置冲突，导致调用AGC接口获取token失败。

原因二：编译APK时未进行排除Analytics Kit混淆配置，导致APK出现异常。

针对原因一：

         1. 将参数改为tools:node="merge"。 
         2. 手动把AGC所有的“AndroidManifest.xml”文件信息写到您的App的“AndroidManifest.xml”文件信息里。 

针对原因二：

         1. 打开Android工程的混淆配置文件。 
         2. 加入排除Analytics Kit的混淆配置。 
    
    -keep class com.huawei.updatesdk.**{*;}
    -keep class com.huawei.hms.**{*;}
    -keep class com.huawei.agconnect.**{*;}
    -keep interface com.huawei.hms.analytics.type.HAEventType{*;}
    -keep interface com.huawei.hms.analytics.type.HAParamType{*;}

#### 实时概览为何没有数据上报？

**【根因分析】**

未关闭debug模式，上报的事件数据不会出现在实时概览里，而是在[应用调试](https://developer.huawei.com/consumer/cn/doc/HMSCore-Guides/app-debugging-0000001051799712)里。

**【解决方法】**

打开本地日志，查看日志中是否有debugMode enabled的字样，如有，则表示debug模式未关闭，请执行如下命令行，停用调试模式后再次尝试：
    
    adb shell setprop debug.huawei.hms.analytics.app .none.

#### 在应用集成页面验证初始化代码时，为何提示数据接入失败？

**【根因分析】**
      * 手机时间被修改过。 
      * 手机无网络。 
      * 手机连接了代理。 

**【解决方法】**

      * 集成SDK前，请检查手机时间设置是否正确。 
      * 集成SDK前，请检查手机网络连接状态，确保网络正常。 
      * 集成SDK前，请检查手机是否设置了代理，如有设置，需关闭代理。 

#### 应用已经集成了Huawei Analytics Kit，为什么当天在事件分析报告里查不到数据？

**【根因分析】**

Huawei Analytics Kit的数据报告（如事件分析报告、留存分析报告等），除实时趋势是分钟级更新外，其他各项指标均为次日更新。

**【解决方法】**

应用集成Huawei Analytics Kit后，次日可查看事件分析、留存分析等报告。

#### 项目概览启动方式卡片下为什么没有数据？

**【根因分析】**

Android：初始化Analytics SDK时，如果是Context方式初始化，并且Context是从Application获取，将影响LAUNCHAPP事件部分参数的自动采集，某些场景取不到App的启动方式。

快应用：快应用SDK 6.0.0.300版本才开始支持启动方式的上报。

**【解决方法】**

Android：建议您使用Activity方式初始化。

快应用：请确认您已升级至6.0.0.300或者之后的版本。

#### 为什么相同时间段内，同一事件在“事件分析”中的事件计数与“漏斗分析”中的事件计数结果不一致？

**【根因分析】**

该现象是正常现象，详细原因如下：

在漏斗分析过程中，如果一个用户在一个转化周期内有多个事件都符合某个转化步骤的定义，那么会优先选择更靠近最终转化目标的事件作为转化事件，并在第一次达到最终转化目标时停止转化的计算。

假设定义一个漏斗的转化步骤有A、B、C三步，那么不同用户的行为序列及实际转化步骤（加粗部分）见如下例子：

例1：A ->A ->**A - >B**

例2：A ->A ->**A - >B ->C**

例3：A ->A ->**A - >B ->C ->A ->B**

例4：**A** ->B **- >B ->C**

#### 实时概览中的用户分析、事件分析为什么显示暂无数据？

**【根因分析】**

在事件管理和用户属性管理中未添加自定义事件及对应参数、未添加自定义用户属性，将导致事件分析、用户分析无数据呈现。

**【解决方法】**
      * 事件管理。请确认在“事件管理”中已添加自定义事件及其对应参数，添加自定义事件的具体操作步骤如下：选择“华为分析 > 管理 > 事件管理 ”，点击“新建” 、“自定义事件”，输入事件保存后，点击事件在输入框中添加自定义参数，点击“保存”即可。 
      * 用户属性管理。请确认在“用户属性管理“中已添加自定义用户属性。添加自定义的用户属性的操作步骤如下：选择“华为分析 > 管理 > 用户属性管理 > 新建”，输入属性后点击“保存”即可。 

#### 为什么在“实时概览”或者“事件分析”中看不到上报事件的自定义参数？

**【根因分析】**

因为在事件管理中未添加自定义参数，导致实时概览和事件分析中都看不到自定义参数。

**【解决方法】**

请确认在“事件管理”中已给事件添加自定义参数。添加自定义参数的具体操作步骤如下：选择“华为分析 > 管理 > 事件管理 > 编辑”“，然后在输入框中添加自定义参数后点击“保存”即可。

#### agconnect-services.json中为什么存在.cn的域名？

此域名为备用域名，与.com域名解析得到的站点IP是相同的。假如您选择的数据处理位置是德国站点，那么.com域名与.cn域名解析后都是德国站点的IP。.cn域名是为了确保.com域名解析失败时，能将您的数据及时、可靠地上传到云侧，避免因域名解析失败丢失数据，进而影响您的运营决策。

#### 因网络原因导致分析数据上报失败，分析服务SDK是否支持自动重发？

当上报事件失败时，该事件会自动存入缓存，缓存的事件重发有两种方式：

      * 第一种是在发送失败后等待30秒，跟随下一次事件上报动作一同触发上报。 
      * 第二种是应用退出后会立即触发上报。 

缓存中未发送成功的数据只有主动调用清除缓存接口或手机恢复出厂设置才会被清理掉。

#### 集成分析服务SDK后，是否支持自动上报未捕获的异常？

仅集成分析服务SDK不支持自动上报应用崩溃相关事件，需要另外再集成华为崩溃分析SDK，详情可查看[华为崩溃服务介绍](https://developer.huawei.com/consumer/cn/doc/development/AppGallery-connect-Guides/agc-crash-introduction-0000001055732708)。

#### 为满足监管要求，集成SDK后要求用户在未同意访问网络前不能发送任何网络请求，如何处理？

      * 用户在未同意访问网络前请不要调用Analytics Kit SDK初始化接口[getInstance](https://developer.huawei.com/consumer/cn/doc/HMSCore-References/android-api-hianalytics-0000001050707170#section126742153455)。 
      * AGC SDK在1.5.0.300版本（分析服务5.3.0.300版本）提供了设置能否发送网络请求的能力，您可以按如下步骤实现。 
        1. 在AndroidManifest.xml的Application中增加如下meta-data配置，value配置为false，表示不发送网络请求。
               
               <meta-data
                    android:name="com.huawei.agconnect.AccessNetwork"
                    android:value="false" />

        2. 在用户同意访问网络后调用setAccessNetwork接口打开网络发送请求开关。
               
               AccessNetworkManager.getInstance().setAccessNetwork(true);

        3. （可选）如果使用了多进程处理机制，则需要在子进程中调用初始化方法。

在Application的onCreate方法中添加初始化代码：
               
               if (AGConnectInstance.getInstance() == null) { 
                    AGConnectInstance.initialize(getApplicationContext()); 
               }

#### 在Android 11上，已安装HMS Core（APK）最新版本，仍然提示升级，如何解决？

Android 11更改了应用查询用户在设备上已安装的其他应用以及与之交互的方式。您应用的targetSdkVersion是30或者更高版本，并且集成的Analytics Kit 6.2.0.301之前版本时，将无法访问HMS Core（APK），并且持续提示升级。

您可以通过以下两种方法解决。

      * 方法一：

升级Analytics Kit的SDK至6.2.0.301及以上版本，版本信息请参见[6.2.0.301](https://developer.huawei.com/consumer/cn/doc/HMSCore-Guides/version-change-history-0000001050705116#section145576131172)。

      * 方法二：

如果不升级SDK，需要在“AndroidManifest.xml”中manifest下添加<queries>标签。
            
            <manifest ...>
                ...
                <queries>
                    <intent>
                        <action android:name="com.huawei.hms.core.aidlservice" />
                    </intent>
                </queries>
                ...
            </manifest>

#### 在用户同意隐私协议之前应用调用了androidId接口，如何处理？

**【根因分析】**

由于各个厂商Push Token生成规则不一致可能会获取其他额外信息，比如小米手机中获取Push Token时候会调用androidId接口，华为分析SDK不会采集上报这些额外信息。在未获取用户同意前其他关联SDK会初始化分析SDK，导致调用了androidId接口。

**【解决方法】**

      1. 参考[SDK处理的个人信息](https://developer.huawei.com/consumer/cn/doc/HMSCore-Guides/android-sdk-data-security-0000001050745153#section899720401027)中Push Token的说明内容刷新您的隐私声明获取用户同意。 
      2. 请升级分析服务Android SDK为 6.5.0.300或以上版本。

#### 同一日期的新用户数，为何两次查询结果不一致？

**【问题描述】**

同一日期的新用户数，为何会出现两次查询结果不一致的情况？例如，2022年11月5日查询2022年11月1日的新用户数比2022年11月4日查询2022年11月1日的新用户数多。

**【根因分析】**

华为分析以用户行为事件发生日期统计指标，由于终端用户使用App的环境各有差异，可能会出现部分于2022年11月1日使用App的用户行为数据因网络异常等原因被缓存未上报，而当用户于2022年11月4日再次使用App时上报了缓存的历史数据。

#### 当日新增用户数加上前一天的累计用户数，与当日累计用户数不一致？

**【问题描述】**

新增用户页面，统计日当日的新增用户数加上前一天的累计用户数，与统计日当日的累计用户数不一致。

**【根因分析】**

在过滤器中选择了过滤条件后，可能会导致出现这个现象，因为用户的用户属性可能发生了变化。

当根据用户属性过滤时，某些新用户可能会被过滤掉，导致查询的新增用户数偏少。如：A用户曾经上报属性“南京”，后来上报属性为“上海”。当过滤器中选择“南京”时，新增用户数和累计用户数都能统计到该用户；而当过滤器中选择“上海”时，该用户属于累计用户，但不属于新增用户，故累计用户数可以统计到该用户，但新增用户数统计不到。

#### 应用迁移使用约束

      * 帐号持有者身份可以看见“应用转移”的按钮，并可以进行转移操作，其他角色无法看见“应用转移”按钮。转移不支持跨站点转移。 
      * 迁移后的新product_id，默认是没有开通分析服务的，您需要重新点击开启分析服务、并重新下载agconnect-services.json文件更新到工程中。 
      * 如果迁移前的项目下，只有一个App，在迁移过程中，默认保留该App的历史数据。迁移后需要主动登录并打开分析服务的任一菜单，同步状态至系统。 
      * 如果迁移前的项目下，有多个App，则默认不保留该迁移App的历史数据，该项目下其余App的历史数据不会变化。 
      * 应用迁移后，需要重新配置转化事件回传。
