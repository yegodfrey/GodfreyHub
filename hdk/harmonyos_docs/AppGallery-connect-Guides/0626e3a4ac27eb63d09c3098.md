# 获取经过反混淆处理的崩溃报告

当使用ProGuard或DexGuard在编译时将代码中的类名、字段和方法等混淆处理为不可阅读的代码时，您可以通过将混淆Mapping文件上传到AGC的方式获取经过反混淆处理的崩溃报告。

当前，混淆Mapping文件共支持三种上传方式：

* [使用Gradle插件上传](#section356573433213)
* [使用符号表工具自动上传](#section121670437238)
* [手动上传](#section9308948193214)

> 说明
>
> 推荐您使用Gradle插件上传，除此之外您还可以使用符号表工具上传。只有当开发环境、工具限制等原因导致无法使用上述两种方式自动上传时，才建议您在AGC崩溃服务界面手动上传。

## 前提条件

1. 您需要在AGC控制台[开通崩溃服务](https://developer.huawei.com/consumer/cn/doc/AppGallery-connect-Guides/agc-crash-enableservice-0000001326330021)。
2. 您需要在您的应用中[集成崩溃服务SDK](https://developer.huawei.com/consumer/cn/doc/AppGallery-connect-Guides/agc-crash-integratesdk-android-0000001275810158)。

## 使用Gradle插件上传

1. 在项目级build.gradle文件中集成1.3.0.300及以上版本的agcp插件。

   ```screen
   buildscript {  
           dependencies {  
           classpath 'com.huawei.agconnect:agcp:x.x.x.x' 
           }  
   }
   ```

   > 说明
   >
   > agcp插件最新版本号参见[Android使用入门](https://developer.huawei.com/consumer/cn/doc/AppGallery-connect-Guides/agc-get-started-android-0000001058210705)。
2. 在应用级build.gradle文件中配置混淆Mapping文件的上传开关。 说明
   >
   > 混淆Mapping文件的上传开关配置必须在"apply plugin"配置后面添加，否则会编译报错。

   ```screen
   apply plugin: 'com.huawei.agconnect'
   agcp{
       mappingUpload = true
       debug = false
       appVersion = 'xxx'
   }
   ```

   属性说明如下表所示。

   |属性名称|类型|默认|说明|
   |:------------|:------|:----|:------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
   |mappingUpload|boolean|false|混淆Mapping文件上传开关，只有设置成true，agcp插件才会自动上传混淆Mapping文件。|
   |debug|boolean|false|debug的编译版本默认不会上传混淆Mapping文件，如果您需要上传debug版本的混淆Mapping文件，可以将debug属性设置为true。|
   |appVersion|String|空|上传混淆Mapping文件的版本号。 * 如果此处没有设置appVersion，上传混淆Mapping文件的版本号为：build.gradle文件中的versionName。如果build.gradle中versionName没有设置，则取AndroidManifest.xml中的versionName，两者都不设置则无法上传混淆Mapping文件。 * 如果此处设置了appVersion，则以此处配置的参数值为最终版本上传。 > 注意 > 您需要保证appVersion参数与实际发生Crash的App版本号（versionName）相同，否则将导致混淆Mapping文件与apk不匹配导致无法解析崩溃异常。|

3. 在命令行窗口进入工程目录"$Project"，执行如下命令验证混淆Mapping文件能否自动上传。

   ```screen
   gradle clean assembleRelease
   ```

   查看process${variant.name}MappingUpload是否执行成功，其中variant.name为相应的变体名称。

   ![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20250704155606.95985663877393836217072478917120:50001231000000:2800:AA6E37BD8C20EF3DD6E6D1184633335519D1586CDDB7B3F64681BBCCB2EA2B31.png)

   该命令会将您的工程目录"$Project.buildDir/outputs/mapping/$Variant.dirName/mapping"下生成的混淆Mapping文件自动上传至AGC。如果使用Gradle插件的方式不能实现自动上传，您可以尝试[使用符号表工具上传](#section121670437238)或[手动上传](#section9308948193214)。
   > 注意
   > * 上传任务执行不能过于频繁，60秒内只能执行1次。
   > * agcp插件在上传混淆Mapping文件时，会将混淆Mapping文件压缩成mapping.zip(在$Project.buildDir/outputs/mapping/$Variant.dirName/目录中)然后上传，mapping.zip文件最大支持8MB。如果超过8MB，建议[手动上传](#section9308948193214)。

## 使用符号表工具自动上传

1. 下载符号表工具[agconnect-crash-symbol-1.4.2.300.jar](https://developer.huawei.com/repo/com/huawei/agconnect/agconnect-crash-symbol/1.4.2.300/agconnect-crash-symbol-1.4.2.300.jar)，保存在本地，例如"d:\project\demo\jar"。
2. 在您的工程目录"$Project.buildDir/outputs/mapping/$Variant.dirName/mapping"中找到您的混淆Mapping文件，保存到本地，例如"D:\project\demo\mapping"。
3. 在命令行窗口执行如下命令自动上传混淆Mapping文件。

   ```screen
   cd d:\project\demo\jar
   java -jar <JAR包的包名> -u -j <json文件所在路径> -v <app版本号> -m <mapping文件所在目录>
   ```

   > 注意
   > * json文件所在路径可参见[添加配置文件](https://developer.huawei.com/consumer/cn/doc/AppGallery-connect-Guides/agc-crash-integratesdk-android-0000001275810158#section12282853104317)，此参数需包含文件名。
   > * app版本号应与实际发生Crash的App版本号（versionName）相同，否则将导致混淆Mapping文件与apk不匹配导致无法解析崩溃异常。
   > * 文件不超过8MB。如果超过8MB，建议[手动上传](#section9308948193214)。

   示例：

   ```screen
   cd d:\project\demo\jar
   java -jar agconnect-crash-symbol-1.4.2.300.jar  -u -j D:\project\demo\json\agconnect-services.json -v 1.0 -m D:\project\demo\mapping
   ```

   出现如下图结果，表示Mapping文件已经上传成功。

   ![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20250704155606.41844917185343574479886189584235:50001231000000:2800:DF2B395A94737DBF18EE0036819ED8CA2A6ABA9AB17FF4FE39EE118A2FC183CF.png)

## 手动上传

当因开发环境、工具限制等导致无法使用Gradle插件和符号表工具自动上传时，您还可以选择在AGC页面手动上传。
> 说明
>
> 只有已经上报崩溃问题的应用才支持手动上传混淆mapping文件。

1. 在您的工程目录中找到您的混淆Mapping文件。 $Project.buildDir/outputs/mapping/$Variant.dirName/mapping.txt

2. 登录[AppGallery Connect](https://developer.huawei.com/consumer/cn/service/josp/agc/index.html)，点击"开发与服务"。
3. 在项目列表中找到您的项目，在项目下的应用列表中点击您的应用。
4. 点击"质量 > 崩溃"，进入崩溃服务的页面。
5. 选择"映射文件 > 混淆Mapping文件"，点击需要上传混淆Mapping文件的应用版本对应的"上传"。 说明
   >
   > 此方式支持上传zip和txt格式的混淆Mapping文件。
   > * zip大小不超过50MB，zip中的混淆Mapping文件必须为txt格式，必须放在zip包的根目录下，且根目录下只能包含1个txt的混淆Mapping文件。解压后的大小不超过400MB和300万行。
   > * txt大小不超过50MB和300万行，超过50MB需压缩后上传，两次上传的间隔应大于60秒。

   ![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20250704155606.61995098286713052135049727882907:50001231000000:2800:0D7059B99B66744F642A278DBDABC84D836321CA7765CDE307E6CD70F95AD8E1.png)
6. 点击弹出框中的![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20250704155606.16094683646411618688507071580284:50001231000000:2800:E8CADCC5FFBAE6672C3E3F00EA93EF6A29AA2C75CD4B36FE2FD0F8D5941BA54C.png)，上传混淆Mapping文件。
7. 上传文件后，可在"详情"列查看文件上传详情。

## 分析崩溃问题

崩溃问题发生上报后，您即可在AGC上查看和分析崩溃问题，具体操作请参考[分析崩溃问题](https://developer.huawei.com/consumer/cn/doc/AppGallery-connect-Guides/agc-crash-locate-0000001055140557)。
