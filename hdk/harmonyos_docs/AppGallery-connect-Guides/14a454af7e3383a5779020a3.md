# 业务介绍

AppGallery Connect（简称AGC）云缓存是一项基于Serverless架构的即开即用、稳定可靠、自动弹性伸缩、免运维的Key-Value型缓存服务，可满足用户高并发及数据快速访问的业务诉求。

您无需下载安装Redis客户端，云缓存服务会自动连接缓存实例。您可以直接访问命令行工具，对复杂的数据进行读写操作。

云缓存服务提供可视化操作界面，您可以实时查看热Key、慢Key、大Key、缓存访问量等信息，方便您定位问题。

## 相关概念

|名称|说明|
|:---|:-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
|热Key|一般来说，一个Key一秒内访问量超过200次时，我们判定其为热Key。 如何避免热Key： * String类型长度控制在5000以内，Hash、List、Set等元素数量尽量不超过200个。 * Key的命名前缀为业务缩写，禁止包含特殊字符（比如空格、换行、单双引号以及其他转义字符）。 * 在客户端配置读写分离。 * 设计熔断/降级机制，在发生击穿的场景下进行限流和服务降级。|
|慢Key|一般来说，一个Key操作耗时超过1000ms时，我们判定其为慢Key。以下几种情况可能产生慢Key： * 客户端超时，有可能是网络传输有延迟，也有可能是排队的命令比较多。 * 使用复杂度过高的命令。 * Key的Value较大（即大Key）。 如何避免慢Key： * 尽量不使用耗时命令。 * 避免写入大Key。|
|大Key|大Key可以分为两种情况： * Key的Value较大，例如一个String类型的Key大小达到10MB，或者一个集合类型（Hash、List、Set等）的元素总大小达到了100MB。一般我们定义单个String类型的Key长度大于5000，则认为其为大Key。 * Key的元素较多，例如一个Hash类型的Key，其元素数量达到了10000。一般我们定义集合类型的Key中元素超过200个，则认为其为大Key。 如何避免大Key： * String类型长度控制在5000以内，Hash、List、Set等元素数量尽量不超过200个。 * Key的命名前缀为业务缩写，禁止包含特殊字符（比如空格、换行、单双引号以及其他转义字符）。 * 进行大Key拆分，通过多Key存储，建议单个Key的大小不超过500。 * 将大Key单独转移到其余存储介质。 * 定期清理过期Key。|
|访问量|在Redis客户端和云缓存Web CLI页面，对缓存数据进行读写操作的频次。|
