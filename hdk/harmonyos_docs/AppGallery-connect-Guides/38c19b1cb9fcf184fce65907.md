# 获取NDK崩溃报告

如果您的应用使用了原生库，要获取可阅读的NDK崩溃堆栈，崩溃服务需要了解原生二进制文件中的符号。原生符号文件可用于将原生二进制文件中的符号还原为可阅读的代码，您可以通过将原生符号文件上传到AGC的方式获取NDK崩溃报告。

## 前提条件

1. 您需要在您的应用中[集成崩溃服务NDK](https://developer.huawei.com/consumer/cn/doc/AppGallery-connect-Guides/agc-crash-integratendk-android-0000001280639012)。
2. 您已经制造过至少一次崩溃，详情请参见[测试崩溃实现](https://developer.huawei.com/consumer/cn/doc/AppGallery-connect-Guides/agc-crash-test-0000001055420516)。

## 上传原生符号文件

当前，原生符号文件共支持三种上传方式：

* [使用Gradle插件自动上传](#section151617514155)
* [使用符号表工具上传](#section1594072643211)
* [手动上传](#section17106112782117) 说明
  >
  > 推荐您优先使用Gradle插件上传，除此之外您还可以使用符号表工具上传。只有当开发环境、工具限制等原因导致无法使用上述两种方式上传时，才建议您在AGC崩溃服务页面手动上传。

### 使用Gradle插件自动上传

1. 在项目级build.gradle文件中集成1.3.2.301及以上版本的agcp插件。

   ```screen
   buildscript {  
           dependencies {  
           classpath 'com.huawei.agconnect:agcp:x.x.x.x' 
           }  
   }
   ```

   > 说明
   >
   > agcp插件最新版本请参见[AGC插件版本更新说明](https://developer.huawei.com/consumer/cn/doc/AppGallery-connect-Guides/agc-sdk-changenotes-0000001058732550#section1850181717218)。
2. 在应用级build.gradle文件中配置原生符号文件的上传开关。 说明
   >
   > 原生符号文件的上传开关配置必须在"apply plugin"配置后面添加，否则编译会报错。

   ```screen
   apply plugin: 'com.huawei.agconnect'
   agcp{
       symbolUpload = true
       debug = false
       debugSoDirectory = 'xxx'
       ndkDirectory = 'xxx'
   }
   ```

   属性说明如下表所示。

   |属性名称|类型|默认|是否必须|说明|
   |:---------------|:------|:----|:---|:-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
   |symbolUpload|boolean|false|是|原生符号文件上传开关，只有设置成true，agcp插件才会生成原生符号文件上传任务。|
   |debug|boolean|false|是|debug的编译版本默认不会生成上传原生符号文件任务，如果您需要上传debug版本的原生符号文件，可以将debug属性设置为true。|
   |debugSoDirectory|String|空|是|Debug so文件所在路径。 * 如果没有配置此参数，则会去工程的相应目录下查找，如采用Android Studio+CMake方式编译，编译的Debug so文件通常位于<项目文件夹>/<module>/build/intermediates/cmake/{variant.name}/obj/<架构>目录下。 * 如果配置了此参数，则根据配置的目录查找对应的so文件，进行解析上传。|
   |ndkDirectory|String|空|是|Android Studio安装NDK版本所在的路径。 如C:/Users/AppData/Local/Android/Sdk/ndk/20.0.5594570 必须设置，如果此处没有设置，则无法解析原生符号文件。|

3. 同步工程，生成如下上传任务，双击执行相应的上传任务。 ![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20250704155605.85838479106451537801346634724653:50001231000000:2800:21B9F93E42D202325AA375601B968C1B31FC85CF5D49216575E1BF4B7770B5D2.png)

4. 验证原生符号文件是否上传成功。 查看process${Variant.name.capitalize()}SymbolUpload是否执行成功。variant.name为相应的变体名称。

   > 注意
   > * 上传任务执行不能过于频繁，60秒内只能执行5次。
   > * agcp插件在上传原生符号文件时，会将原生符号文件压缩成symbol_xx.zip(在$Project.buildDir/agcp/symbol/release/目录中)然后上传，symbol_xx.zip文件最大支持8MB。如果文件超过8MB，建议[手动上传](#section17106112782117)。

### 使用符号表工具上传

1. 下载符号表工具[agconnect-crash-symbol-1.4.2.300.jar](https://developer.huawei.com/repo/com/huawei/agconnect/agconnect-crash-symbol/1.4.2.300/agconnect-crash-symbol-1.4.2.300.jar)，保存在本地，例如"d:\project\demo\jar"。
2. 获取应用当前版本的Debug so文件。 如Android Studio+CMake方式编译，编译的Debug so文件通常位于<项目文件夹>/<module>/build/intermediates/cmake/{variant.name}/obj/<架构>目录下。

   Debug so文件是指具有调试信息的so文件，为了能够解析NDK崩溃的堆栈，必须使用对应的Debug so文件生成应用当前版本的原生符号文件。因此建议每次构建或发布应用版本时，备份好当前的Debug so文件。 说明
   >
   > Debug so文件与原生符号文件是一一对应关系。在使用Debug so文件生成的原生符号文件中，有唯一标识UUID字段（该字段每个Debug so文件唯一）。而在应用上报的堆栈信息中，每一级堆栈也都会携带一个UUID字段。当这两个字段匹配时，说明原生符号文件和堆栈信息对应。如果不匹配，则说明生成原生符号文件的Debug so文件不是对应版本应用的。
3. 在命令行窗口执行如下命令生成原生符号文件并自动上传。

   ```screen
   cd d:\project\demo\jar
   java -jar <JAR包的包名> -i <Debug so文件所在目录> -o <原生符号文件输出目录> -ndk <android ndk所在目录> -u -j <json文件所在路径> -v <app版本号>
   ```

   > 注意
   > * 为避免上一次的结果影响，原生符号文件生成时会对输出路径下的所有txt和zip文件先做删除操作，因此最好指定一个空文件夹作为输出目录。
   > * json文件所在路径可参见[添加配置文件](https://developer.huawei.com/consumer/cn/doc/AppGallery-connect-Guides/agc-crash-integratesdk-android-0000001275810158#section12282853104317)，此参数需包含文件名。
   > * app版本号应与实际发生Crash的App版本号（versionName）相同。
   > * 文件不超过8MB。如果文件超过8MB，建议[手动上传](#section17106112782117)。

   示例：

   ```screen
   cd d:\project\demo\jar
   java -jar agconnect-crash-symbol-1.4.2.300.jar -i D:\project\demo -o D:\project\demo\output -ndk C:\Users\AppData\Local\Android\Sdk\ndk\20.0.5594570 -u -j D:\project\demo\json\agconnect-services.json -v 1.0
   ```

### 手动上传

当因开发环境、工具限制等原因导致无法使用Gradle插件和符号表工具自动上传时，您还可以选择在AGC页面手动上传。

1. 生成原生符号文件。
   1. 下载符号表工具[agconnect-crash-symbol-1.4.2.300.jar](https://developer.huawei.com/repo/com/huawei/agconnect/agconnect-crash-symbol/1.4.2.300/agconnect-crash-symbol-1.4.2.300.jar)，保存在本地，例如"d:\project\demo\jar"。
   2. 获取应用当前版本的Debug so文件。 例如Android Studio+CMake方式编译，编译的Debug so文件通常位于<项目文件夹>/<module>/build/intermediates/cmake/{variant.name}/obj/<架构>目录下。

      Debug so文件是指具有调试信息的so文件，为了能够解析NDK崩溃的堆栈，必须使用对应的Debug so文件生成应用当前版本的原生符号文件。因此建议每次构建或发布应用版本时，备份好当前的Debug so文件。 说明
      >
      > Debug so文件与原生符号文件是一一对应关系。在使用Debug so文件生成的原生符号文件中，有唯一标识UUID字段（该字段每个Debug so文件唯一）。而在应用上报的堆栈信息中，每一级堆栈也都会携带一个UUID字段。当这两个字段匹配时，说明原生符号文件和堆栈信息对应。如果不匹配，则说明生成原生符号文件的Debug so文件不是对应版本应用的。
   3. 在命令行窗口执行如下命令生成原生符号文件。

      ```screen
      cd d:\project\demo\jar
      java -jar <JAR包的包名> -i <Debug so文件所在目录> -o <原生符号文件输出目录> -ndk <android ndk所在目录>
      ```

      > 说明
      >
      > -o 参数可不指定，如果不指定，原生符号文件输出目录默认为当前文件夹。

      示例：

      ```screen
      cd d:\project\demo\jar
      java -jar agconnect-crash-symbol-1.4.2.300.jar -i D:\project\demo -o D:\project\demo\output -ndk C:\Users\AppData\Local\Android\Sdk\ndk\20.0.5594570
      ```


2. 登录[AppGallery Connect](https://developer.huawei.com/consumer/cn/service/josp/agc/index.html)，点击"开发与服务"。
3. 在项目列表中找到您的项目，在项目下的应用列表中点击您的应用。
4. 点击"质量 > 崩溃"，进入崩溃服务的页面。
5. 选择"映射文件 > 原生符号文件"，点击"![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20250704155605.05827644513138691258429033908603:50001231000000:2800:E91C2D50B809ABB6B0C1B092C3C75A013620762C7FB56D9A345E95D9590A42E2.png)上传文件"。 说明
   >
   > 此方式支持上传zip和txt格式的原生符号文件。
   > * zip大小不超过50MB，zip中的原生符号文件必须为txt格式，必须放在zip包的根目录下，且根目录下最多包含50个txt的原生符号文件。解压后的大小不超过400MB和300万行。
   > * txt大小不超过50MB和300万行，超过50MB需压缩后上传，60秒内最多上传5次。

   ![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20250704155605.94303979075851556163460136894698:50001231000000:2800:052ACD866A3C70A8A6198150308E20385B09E73F96DE12EAD61113D860196387.png)
6. 点击弹出框中的![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20250704155605.45975970418450026254671857816682:50001231000000:2800:7A4243E002C9BACCA0264B40BB470ACB103696EC8E587264EFFE1DC3D6A9F0B8.png)，上传原生符号文件。
7. 点击"查看上传记录"，查看文件上传的状态及详情。 ![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20250704155606.37812697862090058971943720782364:50001231000000:2800:FCF81E809B91714D70322AD03D8289DE8F046F46A789639BDA5D613F7FAF08B8.png)

   > 说明
   >
   > 当发生NDK崩溃后，如果AGC中展示的崩溃堆栈仍然为不可阅读的代码，您可通过如下方法检查原生符号文件上传是否准确。
   > 1. 查看崩溃堆栈中的UUID字段。
   > 2. 在"原生符号文件"页面中查看是否存在相同UUID的原生符号文件。
   >    * 如果存在，需[填写工单](https://developer.huawei.com/consumer/cn/support/feedback/#/add/89?level2=9020)联系华为技术支持处理。
   >    * 如果不存在，说明没有上传对应的原生符号文件。您需在获取应用发生NDK崩溃版本的Debug so文件后，重新生成原生符号文件并上传。

## 分析NDK崩溃问题

NDK崩溃问题发生上报后，您即可在AGC上查看和分析崩溃问题，具体操作请参考[分析崩溃问题](https://developer.huawei.com/consumer/cn/doc/AppGallery-connect-Guides/agc-crash-locate-0000001055140557)。
> 说明
>
> 如果[开启了崩溃提醒](https://developer.huawei.com/consumer/cn/doc/AppGallery-connect-Guides/agc-crash-notice-0000001055340559#section1292511192412)，发生NDK崩溃问题时也会自动向您发送崩溃提醒。
