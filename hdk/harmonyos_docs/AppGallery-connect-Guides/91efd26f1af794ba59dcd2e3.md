# 使用限制

#### 渠道包的打包要求

![](https://communityfile-drcn.op.hicloud.com/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20230223213404.33198886702700881537489430885191:50001231000000:2800:310480E423474ABD1D71AB2D94B824C53AD0EC55A443D832162FFED756C9DB74.png?needInitFileName=true?needInitFileName=true)  
如果主包为多包包体场景，则开发者需要上传全量的渠道包，即32位的渠道包和64位的渠道包。否则无法覆盖到所有手机，导致效果统计不准确。

渠道包打包需满足的一致性原则：

* 渠道包除了"渠道号"（在AGC上叫做"包内渠道编码"）与在应用市场上正常上架的主包有差异外，其余内容都要和主包保持一致。

<!-- -->

* 开发者在打包的时候，只允许在配置文件中（"assets"或"AndroidManifest.xml"）预置不同的包内渠道编码，若预置到其他文件中则自动审核不通过。  

#### 渠道包的更新机制

![](https://communityfile-drcn.op.hicloud.com/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20230223213404.20324186339627658256367278813068:50001231000000:2800:512D312BC6838C1432B23EB64634FDC0F4F53AD7BEED14A4B1FA5F8C5F159899.png?needInitFileName=true?needInitFileName=true)  
如果主包为多包包体的更新场景，则开发者需要更新上传全量的渠道包，即32位的渠道包和64位的渠道包。否则无法覆盖到所有手机，导致效果统计不准确。

* 若渠道包被用户下载安装后，应用市场会记录渠道包的信息。后续有新版本渠道包生效时，旧版本的渠道包会被更新为新版本的渠道包。

<!-- -->

* 若没有对应高版本的渠道包时，则旧版本渠道包会被更新为主包。后续有新版本渠道包生效时，主包会被更新为新版本的渠道包。  

#### 渠道包的审核机制

渠道包以自动审核为主，审核约需15-30分钟，请自行查看审核结果。
