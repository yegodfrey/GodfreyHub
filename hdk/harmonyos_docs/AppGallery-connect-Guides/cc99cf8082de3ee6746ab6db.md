# 概述

函数的代码实现基于不同的语言运行环境可分为Node.js、Java、Python，还有一种比较特别的运行环境为Custom Runtime。

具体Custom Runtime详细解释请参见[Custom Runtime详解](#section13875571337)。  

#### Custom Runtime详解

<br />

#### 定义

Custom Runtime是自定义运行环境，本质上是一个具有监听端口的HTTP Server，您需要创建一个启动该目标Server的可执行文件bootstrap，然后将该文件和您的代码文件一起打成ZIP包，最后将该ZIP包部署到AGC云函数平台，作为一个Custom Runtime的函数。

函数计算启动Custom Runtime时，会默认调用bootstrap文件启动您自定义的[HTTP Server](#section04251852144413)，然后这个HTTP Server会接管所有事件。  

#### 执行环境

高版本的语言运行环境通常内置Custom Runtime。内置Custom Runtime功能，即您可以直接创建Custom Runtime，无需安装第三方解释器。  
![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20250425160215.89928472738126613680245729118096:50001231000000:2800:98687909D11EBF924D11B73C353C6DC514E1D3B98894655A2E8FDF07967A2D5C.png)  
低版本的语言运行环境要使用Custom Runtime功能，您需要自行安装第三方解释器。

内置Custom Runtime功能的语言运行环境版本约束如下：

* Python 3.11版本
* Node.js 20.x版本
* Java 1.8版本  

#### HTTP Server要求

创建HTTP Server时您需要满足以下要求：

* 启动的HTTP Server服务需监听0.0.0.0:9000或\*:9000端口。  
  ![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20250425160215.66004213187829151940866741351179:50001231000000:2800:5FB530B33578B4390AB015024A4F7F99ACF8F33592FDBD35D8448277BF7A197F.png)  
  如果您使用127.0.0.1:9000端口，会导致请求超时。
* Custom Runtime的bootstrap文件，如果是Shell脚本需添加"#!/bin/bash"。
* Custom Runtime的bootstrap文件，需具备可执行权限，且文件为UNIX格式。 您可以通过以下方式解决bootstrap文件权限问题：

  * 在打包文件前执行chmod 755 bootstrap或者chmod +x bootstrap。
  * 如果您使用的是Windows操作系统，您需要将bootstrap文件格式修改为UNIX格式，即执行dos2unix bootstrap。

* HTTP Server服务监听：POST /invoke。 函数收到的所有触发事件均会作为请求体被转发到该路径下。
