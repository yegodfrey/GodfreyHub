# 基于用户安全

#### 用户身份验证

当您的APP用户向AGC云存储发出请求时，系统会校验用户身份，校验通过后，会使用用户的uid填充request.auth.uid变量，以此获得访问的权限。而未通过身份验证的用户发出请求时，request.auth变量为null，无法访问数据。因此，您可以通过以下几种常用方法保障数据安全：

* 公开可访问
* 用户身份验证通过的公开可访问
* 用户私有  

#### 公开可访问

对于一些公开数据，可以不通过身份验证进行呈现。因此配置安全规则时，您可以忽略配置request.auth的相关规则，数据权限则会默认为公开可访问。

```
agc.cloud.storage[
    match: /{bucket}/{path=**} {
        allow read, write:  if request.resource.contentType == 'image/jpeg';
    }
]
```

#### 用户身份验证通过的公开可访问

在某些情况下，如果您希望仅某一些用户可查看数据，可通过身份验证进行控制权限。由于未通过身份验证的用户的request.auth变量为null，无法访问数据。因此配置安全规则时，通过检查用户的request.auth变量是否为null即可。

```
agc.cloud.storage[
    match: /{bucket}/{path=**} {
        allow read, write:  if request.auth != null;
    }
]
```

#### 用户私有

对于一些隐私文件，为了保证个人用户对其拥有控制权，在配置安全规则时，可通过在文件路径中包含一个用户唯一的识别信息（例如用户的uid），将文件的访问权限设置为用户私有即可。

```
agc.cloud.storage[
    match: /{bucket}/{userId}/{path=**} {
        allow read, write:  if request.auth.uid == userId;
    }
]
```

#### 属性

其中request和resource对象可以帮助安全规则获取更多的请求上下文，从而进行更合适的控制。

request对象中属性的完整列表如下：  

|属性|类型|说明|
|:---------------|:-------------|:-------------------------------------------|
|request.auth.uid|字符串|用户登录验证通过后的唯一ID。|
|request.path|字符串|请求的资源路径。|
|request.time|字符串|请求的服务器时间。|
|request.resource|映射\<字符串, 字符串\>|新的文件资源的相关信息，与resource对象的信息相同，仅当执行write请求时存在。|

resource对象中属性的完整列表如下：  

|属性|类型|说明|
|:--------------------------|:-------------|:-------------------------------------|
|resource.name|字符串|资源文件的名称。|
|resource.bucket|字符串|资源文件的存储实例名。|
|resource.contentType|字符串|资源文件的文件类型。|
|resource.contentDisposition|字符串|资源文件的处置方式。|
|resource.contentEncoding|字符串|资源文件的编码方式。|
|resource.contentLanguage|字符串|资源文件的语言特征。|
|resource.size|字符串|资源文件的大小。|
|resource.metadata|映射\<字符串, 字符串\>|资源文件的自定义元数据，由\<key, value\>组成的一个map结构。|
