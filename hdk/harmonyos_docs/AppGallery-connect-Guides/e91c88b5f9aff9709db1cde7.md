# 设置采集要求

## 设置采集参数

游戏在采集数据前需要自定义采集要求。

### 数据项设置

* 若为Android游戏、HarmonyOS 3.1/4.0及以下游戏，界面如下： ![](https://alliance-communityfile-drcn.dbankcdn.com/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20260212110223.86549170148637917631915408116846:50001231000000:2800:633ABEABC7D7C35ABC2690F98C7D5D885BF9A1C511718E0C1C7F05DC50C183ED.png)

  CPU trace配置项如下：

  |配置项|说明|配置变量|建议|
  |:------------:|:------------------------------------------------------------:|:-----------------------------:|:-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------:|
  |**采集模式**||||
  |stop_when_full|若缓存存满，将停止采集CPU trace数据，并一次性将数据写入trace文件中。|* 缓存容量 * 最大存储时长|* 缓存过大可能导致游戏可使用的内存降低，请根据实际情况合理分配**缓存容量**。 * 存储时间过长会导致文件过大，建议合理设置**最大存储时长**。 * 存储CPU trace数据会占用较多CPU，建议合理提升**存储（采集）间隔**。 * 文件过大会导致打开慢，甚至可能出现打不开的情况，建议合理设置**最大文件大小**。 * 根据实际的游戏性能需求，**抓取条件**支持设置大卡顿、卡顿及其它帧率事件。 * 根据不同使用场景，选择合适的**抓取模式**。"满足条件后抓取"用于抓取事件触发后10秒内的数据，"循环抓取，覆盖事件前后"用于抓取开始采集时至事件触发后5秒内的数据，并循环抓取直至停止采集。两种模式单次抓取的数据生成不大于256MB缓存容量的trace文件，超过则向前截取。|
  |cycle|在缓存中循环存储CPU trace数据，即新数据将全面覆盖旧数据，最终将缓存中最后一轮采集的数据一次性写入trace文件中。|* 缓存容量 * 最大存储时长|* 缓存过大可能导致游戏可使用的内存降低，请根据实际情况合理分配**缓存容量**。 * 存储时间过长会导致文件过大，建议合理设置**最大存储时长**。 * 存储CPU trace数据会占用较多CPU，建议合理提升**存储（采集）间隔**。 * 文件过大会导致打开慢，甚至可能出现打不开的情况，建议合理设置**最大文件大小**。 * 根据实际的游戏性能需求，**抓取条件**支持设置大卡顿、卡顿及其它帧率事件。 * 根据不同使用场景，选择合适的**抓取模式**。"满足条件后抓取"用于抓取事件触发后10秒内的数据，"循环抓取，覆盖事件前后"用于抓取开始采集时至事件触发后5秒内的数据，并循环抓取直至停止采集。两种模式单次抓取的数据生成不大于256MB缓存容量的trace文件，超过则向前截取。|
  |long_trace|根据存储间隔时间，周期性地将采集到的CPU trace数据直接写入trace文件中。|* 缓存容量 * 最大存储时长 * 存储间隔 * 最大文件大小|* 缓存过大可能导致游戏可使用的内存降低，请根据实际情况合理分配**缓存容量**。 * 存储时间过长会导致文件过大，建议合理设置**最大存储时长**。 * 存储CPU trace数据会占用较多CPU，建议合理提升**存储（采集）间隔**。 * 文件过大会导致打开慢，甚至可能出现打不开的情况，建议合理设置**最大文件大小**。 * 根据实际的游戏性能需求，**抓取条件**支持设置大卡顿、卡顿及其它帧率事件。 * 根据不同使用场景，选择合适的**抓取模式**。"满足条件后抓取"用于抓取事件触发后10秒内的数据，"循环抓取，覆盖事件前后"用于抓取开始采集时至事件触发后5秒内的数据，并循环抓取直至停止采集。两种模式单次抓取的数据生成不大于256MB缓存容量的trace文件，超过则向前截取。|
  |auto_trace|根据抓取模式，自动抓取符合抓取条件的CPU trace数据。|* 抓取条件 * 抓取模式|* 缓存过大可能导致游戏可使用的内存降低，请根据实际情况合理分配**缓存容量**。 * 存储时间过长会导致文件过大，建议合理设置**最大存储时长**。 * 存储CPU trace数据会占用较多CPU，建议合理提升**存储（采集）间隔**。 * 文件过大会导致打开慢，甚至可能出现打不开的情况，建议合理设置**最大文件大小**。 * 根据实际的游戏性能需求，**抓取条件**支持设置大卡顿、卡顿及其它帧率事件。 * 根据不同使用场景，选择合适的**抓取模式**。"满足条件后抓取"用于抓取事件触发后10秒内的数据，"循环抓取，覆盖事件前后"用于抓取开始采集时至事件触发后5秒内的数据，并循环抓取直至停止采集。两种模式单次抓取的数据生成不大于256MB缓存容量的trace文件，超过则向前截取。|
  |**调用栈采样**||||
  |开启/关闭|默认不开启，开启后支持查看函数耗时情况。|-|建议游戏测试版本中保留符号表symbol信息，以便查看调用栈中的函数名称。同时，建议使用Android 13（含）及以上版本的操作系统，否则可能无法采集到调用栈数据。|
  |**自定义数据项**||||
  |Atrace数据|CPU trace的细分数据项，支持自定义。Ftrace数据支持开启/关闭自定义配置功能。|-|-|
  |Ftrace数据|CPU trace的细分数据项，支持自定义。Ftrace数据支持开启/关闭自定义配置功能。|-|建议初次使用该功能时，关闭自定义数据项，使用默认的Ftrace数据项，以便更快上手。|
