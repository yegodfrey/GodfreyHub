# 使用KeySets更换在架应用的软件包签名

## 背景介绍

现网在架的应用版本，由于签名证书过期或泄露等原因，可能需要更换软件包签名。如果直接发布新签名版本，由于新版本的软件包签名和在架版本的软件包签名不一致，存量用户将无法正常更新，需要手动卸载老版本再重装新版本，可能导致用户大量流失。使用KeySets方案进行签名更换，通过发布一个或多个[过渡版本](#ZH-CN_TOPIC_0000001127816317__p626218267328)，可帮助用户从老签名版本平滑升级到新签名版本，避免用户流失的风险。

### 方案原理

现网在架、使用旧签名（old_cert）的应用版本为[老版本](#ZH-CN_TOPIC_0000001127816317__p526252616329)。您可以发布一个[过渡版本](#ZH-CN_TOPIC_0000001127816317__p626218267328)，该过渡版本与老版本的签名相同（old_cert），只是在AndroidManifest.xml文件中添加了key-sets信息，以声明允许新签名（new_cert）版本覆盖更新。为了确保绝大多数用户升级到过渡版本，可以发布多个过渡版本。

* 如果用户安装的是老版本，由于老版本使用了旧签名（old_cert）但未声明支持新签名，则无法直接升级到新签名（new_cert）版本，会提示安装失败（INSTALL_FAILED_UPDATE_INCOMPATIBLE）。
* 如果用户安装的是过渡版本，由于过渡版本使用了和老版本相同的旧签名（old_cert）且声明了支持新签名（new_cert），则将允许继续使用新的过渡版本覆盖更新，同时也支持新签名（new_cert）版本的覆盖更新。
* 如果用户安装的是[新版本](#ZH-CN_TOPIC_0000001127816317__p13759345154414)，由于AndroidManifest.xml中删除了老版本签名信息，因此不会被老版本覆盖更新。

### 相关概念

|名称|说明|
|:---|:--------------------------------------------------------------------------------------------------|
|老版本|现网在架的应用版本，由于签名证书过期或泄露等原因，需要更换软件包签名。|
|过渡版本|过渡版本与老版本使用相同的签名，只是在AndroidManifest.xml文件中添加了key-sets信息，以声明允许新签名版本覆盖更新。为了确保绝大多数用户升级到过渡版本，可以存在多个过渡版本。|
|新版本|使用新签名的版本。过渡版本可以升级到新版本。新版本的AndroidManifest.xml中删除了老版本的签名信息，防止新版本被老版本覆盖安装。|

## 操作步骤

### 获取应用新老版本的公钥信息

可以通过[公钥查询工具](https://github.com/doublexixi-github/keysets/raw/master/GetAppInfo.apk)获取应用的公钥信息，步骤如下：

1. 安装公钥查询工具到手机上，同时安装[老版本](#ZH-CN_TOPIC_0000001127816317__p526252616329)APK。
2. 打开公钥查询工具，输入应用包名，点击"获取应用名字和图标"。
3. 确认应用图标和应用名称正确后，点击"获取证书公钥"，即可获取老版本的证书公钥信息（Old_PublicKey）。
4. 卸载老版本APK，安装[新版本](#ZH-CN_TOPIC_0000001127816317__p13759345154414)APK，重复步骤2-3，获取新版本的证书公钥信息（New_PublicKey）。

### 构建过渡版本

[过渡版本](#ZH-CN_TOPIC_0000001127816317__p626218267328)与老版本唯一的区别是增加声明允许升级的版本签名信息。打开过渡版本的AndroidManifest.xml文件，分别添加新老版本的签名证书公钥信息，声明允许新老版本覆盖更新过渡版本，即完成构建。

```screen
<manifest xmlns:android="https://schemas.android.com/apk/res/android"
        xmlns:tools="https://schemas.android.com/tools"
    <key-sets>
        <!-- 老签名证书公钥信息 -->
        <key-set android:name="oldsign">
            <public-key
                android:name="oldsignkey"
                android:value="Old_PublicKey" />
        </key-set>

        <!-- 新签名证书公钥信息 -->
        <key-set android:name="newsign">
            <public-key
                android:name="newsignkey"
                android:value="New_PublicKey" />
        </key-set>

        <!-- 允许oldsign的老签名进行更新 -->
        <upgrade-key-set
            android:name="oldsign" />

        <!-- 允许newsign的新签名进行更新 -->
        <upgrade-key-set
            android:name="newsign" />
    </key-sets>
    ......

    <application>
        .....
    </application>
</manifest>
```

### 上架过渡版本

上架过渡版本，并持续观察过渡版本与老版本的存量用户情况。当您确认大部分用户已切换至过渡版本后，即可上架新版本，从而保证大部分用户都可以从过渡版本顺利升级到新版本。

### 上架新版本

由于新版本签名和过渡版本签名不同，在上架新版本前，您需删除AndroidManifest.xml中<upgrade-key-set>中的旧签名信息，以拒绝旧签名进行覆盖。之后，您便可以上架新版本。

```screen
<!-- 允许oldsign的老签名进行更新 -->
<!--
<upgrade-key-set
android:name="oldsign" />
-->

 <!-- 允许newsign的新签名进行更新 -->
 <upgrade-key-set
     android:name="newsign" />
```
