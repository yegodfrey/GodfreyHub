# FAQ

## 如何修改AGC上管理的签名密钥或上传密钥？

AGC上管理的签名密钥和上传密钥为保证安全性，一旦上传就不再支持修改，您只能重新创建应用。

## 为什么我对应用签名的上传密钥与上传到AGC的上传密钥不一致，也能成功上传软件包？

上传密钥的一致性校验当前没有强制校验，后续版本会支持。

## 为什么我看不到方式一"由AppGallery Connect创建并管理签名密钥"？

如果您之前上传或发布过APK包，您不能选择这种方式，此选项不展示。

## 应用签名密钥有两个选项，我该如何选择？

* 如果您是首次上传应用，推荐您选择方式一。选择这种方式，AGC会重新生成新的应用签名密钥，SHA256的证书指纹也会发生改变。如您后续集成的服务依赖SHA256证书指纹，您还需为应用添加新的SHA256证书指纹。


* 如果您已有在架应用，您只能选择方式二。选择这种方式，您后续的应用都会使用您上传的应用签名密钥。您务必要保证上传的签名密钥和在架应用保持一致，否则会导致您的应用更新失败。
* 如果您想在多个应用商店使用同一个签名密钥，或者与第三方对接时需要通过签名密钥进行签名验证，请选择方式二，上传您自己的签名文件。

> 注意
>
> 如果软件包配置了其他开放平台的签名，选择方式二可能会造成签名信息的变化并且导致功能异常，请您谨慎选择。

## 我上传密钥证书报错"上传的应用签名密钥系统暂不支持，请重新上传"是怎么回事？

很可能是您的加密算法和密钥长度不支持。

当前AGC支持的加密算法和密钥长度分别如下：

* RSA：1024、2048、4096
* EC：NIST P-256

您可以使用keytool命令查看您的加密算法和密钥长度。如下为RSA的加密算法，密钥长度为2048位：

## 我使用了华为应用签名服务后，页面只显示SHA256的证书指纹，我的应用需要配置SHA1和MD5的证书指纹，我怎么获取？

* 如您选择的是方式一，即AGC为您创建密钥，您可以在应用签名页面下载应用签名证书(certificate.pem)，使用openssl命令生成SHA1和MD5的证书指纹。 若生成过程中提示"unable to load certificate*****bad base64 decode"，可能是您的OpenSSL版本较低，建议您更新OpenSSL版本后重试。

## 使用pepk.jar工具生成output.zip签名文件失败，提示" No value provided for flag: include-cert"。如果我去掉命令后面的"include-cert"，可以生成output.zip签名文件，但是上传失败，系统提示"上传文件类型错误"。什么原因导致？

提示" No value provided for flag: include-cert"，通常是因为您用的pepk.jar文件不对，您需要更换一个正确的pepk.jar文件。另外，您不能擅自修改生成签名文件的命令，必须严格按照文档操作。

## 应用签名的一致性要求是什么？

只有全网版本上架后，应用的签名才生效。其它发布方式（如开放式测试发布、分阶段发布等）的版本上架，不更新应用签名。因此在使用应用签名服务时，上传的应用签名密钥需要与最近一次上架的全网版本应用签名一致。

* 如果当前存在正在审核和已上架的版本，上传的应用签名密钥需要与在架版本的签名一致。
* 如果当前仅存在待审核的全网版本，上传的应用签名密钥需要与待审核的全网版本签名一致。
* 如果当前仅存在已上架的全网版本，上传的应用签名密钥需要与已上架的全网版本签名一致。
* 如果当前存在开放式测试版本和全网版本，上传的应用签名密钥需要与全网版本签名一致。
* 如果当前仅存在开放式测试版本，对上传的应用签名密钥没有限制要求。
* 如果当前存在分阶段发布版本和全网在架版本，上传的应用签名密钥需要与全网在架版本签名一致。
* 版本回退，应用签名不回退，上传的应用签名密钥需要与回退前的版本签名一致。例如，全网版本1.0上架后（未使用应用签名服务），升级到全网版本2.0，又再回退到1.0版本。此时上传应用签名密钥，尽管在架的是全网版本1.0，但上传的应用签名密钥仍需要与全网版本2.0的应用签名一致。
