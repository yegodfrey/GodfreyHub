# 使用入门

#### 编写安全规则

安全规则主要用于确定哪些用户对云存储中存储的文件拥有控制权。其中，安全规则中的match规则，用于识别存储实例下的文件路径。而安全规则中的allow规则，则用于在满足指定的条件下用户拥有对该文件路径的read和write权限。系统会根据您设置的安全规则，对客户端发出的每个请求进行评估后，才决定是否允许其读取或写入数据。  
![](https://alliance-communityfile-drcn.dbankcdn.com/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20251209210004.55362852553606753351411593797377:50001231000000:2800:0CCA4B29633BF0984582683CA237A79CE81A7C678F11437EC487A4BDEF3D4096.png)  
构建安全规则时，需要使用到一些基本的数据类型和运算符，具体请参见[语法介绍](https://developer.huawei.com/consumer/cn/doc/AppGallery-connect-Guides/agc-cloudstorage-securityrules-syntax-0000001054848307)。

```
// 全部允许
agc.cloud.storage[
   match: /{bucket}/{path=**} {
      allow read, write:  if true;
   }
]

// 全部拒绝
agc.cloud.storage[
   match: /{bucket}/{path=**} {
      allow read, write:  if false;
   }
]
```

所有的match语句都应指向文件，match语句可以指向特定的文件，也可以使用通配符指向特定路径下的任意文件。当设置安全规则后，只能访问安全规则明确允许访问的文件，拒绝对所有其他路径下文件的访问。

规则示例：

```
// 安全规则声明
agc.cloud.storage[
   // 匹配images路径下的特定的文件
   match: /{bucket}/images/image.jpg{
      allow read, write:  if true;
   }

   // 匹配images路径下的任意文件
   match: /{bucket}/images/{image} {
      allow read, write:  if true;
   }
]
```

同时，在某些情况下，read规则还可以细分为get和list，而write规则也还可以细分为create、update和delete。例如，您的应用可能希望对文件创建强制执行不同的条件，或者您可能希望允许单个文件读取，但拒绝大量的查询，此时将read和write细分为更细化的操作则非常有用。

规则示例：

```
agc.cloud.storage[
    match: /{bucket}/images/{image}{
        allow get:  if true;
        allow list:  if false;
        allow create:  if true;
        allow update:  if true;
        allow delete:  if false;
    }
]
```

如果需要说明安全规则的作用、使用场景及限制等情况时，注释必须以"//"开头并放在安全规则语句外，且注释内容限定为常用字符。  

#### 配置安全规则

安全规则构建完成后，您可进入云存储管理台进行配置与发布。云存储服务将使用最新发布的安全规则进行数据访问控制。

1. 登录[AppGallery Connect](https://developer.huawei.com/consumer/cn/service/josp/agc/index.html)，点击"开发与服务"。
2. 在项目列表中找到您的项目。
3. 选择"云开发（Serverless）\> 云存储"，进入云存储页面。
4. 选择"安全"页签，进入"配置策略"页面。
5. 配置编写好的安全规则，完成后点击右上角"发布"。

#### 查看安全统计数据

在云存储页面，点击"安全统计"页签，您可查看已配置的安全规则的通过请求数和拒绝请求数详情，还可以通过选择不同时间段（当天、昨天、过去1小时、过去7天、过去30天）查看对应的数据详情。
