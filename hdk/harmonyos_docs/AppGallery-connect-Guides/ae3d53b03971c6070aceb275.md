# 获取可阅读的崩溃报告

当应用在编译时将代码中的类名、字段和方法等替换为不可阅读的代码时，您可以通过iOS符号文件获取经过符号化处理后可阅读的崩溃报告。

## 前提条件

1. 您需要在AGC控制台[开通崩溃服务](https://developer.huawei.com/consumer/cn/doc/AppGallery-connect-Guides/agc-crash-enableservice-0000001326330021)。
2. 您需要在您的应用中[集成崩溃服务](https://developer.huawei.com/consumer/cn/doc/AppGallery-connect-Guides/agc-crash-integratesdk-ios-0000001326720177)。

## 上传iOS符号文件

当前iOS符号文件共支持两种上传方式：

* [配置脚本自动上传](#section8342942044)
* [手动上传](#section11962183611487) 注意
  >
  > 上传的符号表zip文件应仅包含符号表文件，详情请参见[上传iOS符号表文件失败原因及解决方案](https://developer.huawei.com/consumer/cn/forum/topic/0202670135508040196?fid=0101271690375130218)。

### 配置脚本自动上传

当前iOS符号文件支持在Xcode配置自动上传脚本的方式进行上传。

1. 下载AGC崩溃服务提供的符号表自动上传脚本。
   * [下载链接](https://appfile1.hicloud.com:443/FileServer/getFile/app/011/111/111/0000000000011111111.20211026160436.88454870629862504572825469144786:20471231000000:0001:243F522228103813127252777988760AF05B3EE12E021FFC6714D802D8F28E08.zip?needInitFileName=true)
   * 数字签名SHA256：2fc67bda23b06f65b712bbe447107ea8ef8ede103c5888a777ca08352bf7c79a
2. 在Xcode中配置编译执行脚本。
   1. 双击Xcode工程，在Xcode工程对应Target的Build Phases中新增Run Script。 ![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20250704155610.38389213990650708382805685807595:50001231000000:2800:BAD8477532CF2244635186695B2B75F6FA83CC5AC85114F393F748C9776FC9E8.png)

   2. 以文本方式打开下载的脚本中的dsymUploader.sh，复制所有内容，在新增的Run Script Phase中粘贴。
   3. 在新增的Run Script中相应位置填入您AGC项目的信息，其中<your_client_secret> 为您的项目Client Secret，可在下图位置复制获取： ![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20250704155610.57108019236545390754573442733116:50001231000000:2800:B0A3BCA9D5F1B8A5A089561036703FA9D66CB25D837D956CDE36F155A7146BDE.png)

   其他配置项的含义及在配置文件中的值为：
   * <your_app_id>为您的应用ID，对应的值为您下载的配置文件中client/app_id的值。
   * <your_client_id>为您的项目Client ID，对应的值为您下载的配置文件中client/client_id的值。
   * <your_agcgw_url> 为您的AGC服务域名，对应的值为您下载的配置文件中agcgw/url的值。
   * 对应关系如下图：

   ![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20250704155610.16632129728168839766387910856220:50001231000000:2800:83D461E12043495F1151F6BF167CED878F30AEB024328A73626DAA5082375A2E.png) 注意
   >
   > 配置文件中的client_secret值为加密后的项目Client Secret，此处<your_client_secret>应填写上述从AGC控制台获取的Client Secret明文值。

   ![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20250704155610.65866342812110041399892232467647:50001231000000:2800:4542C84B6871C66FF3C613508BBF77B468A8734C6C4C881F68416240608A2E35.png)

   d. 在新增的Run Script中修改上传配置，默认在**Debug** 模式及**模拟器编译** 情况下不会上传符号表，在需要上传的时候，请修改下列选项：
   * Debug模式编译是否上传，1＝上传 0＝不上传，默认为0 UPLOAD_DEBUG_SYMBOLS=0

   * 模拟器编译是否上传，1＝上传 0＝不上传，默认为0 UPLOAD_SIMULATOR_SYMBOLS=0

   * 只有Archive操作时上传，1＝仅Archive上传 0＝Archive和Release都上传，默认为0 UPLOAD_ARCHIVE_ONLY=0

到这里自动上传符号表脚本就配置好了，在每次Xcode工程编译后会自动上传符号表到AGC。

### 手动上传

当前iOS符号文件支持在AGC崩溃服务页面手动上传方式进行上传。

1. 生成iOS符号文件。 a. 找到dSYM文件。

   > 说明
   >
   > Xcode Release编译默认会生成dSYM文件，而Debug编译默认不会生成。对应的Xcode配置：Xcode -> Build Settings -> Build Option -> Debug Information Format -> DWARF with dSYM File。
   * Xcode Release编译项目后，在Xcode左侧项目目录的"Products"中找到生成的"xxx.app",右键选择"Show in Finder"，在文件夹中即可找到生成的"xxx.app.dSYM"文件。
   * 您也可以在 Xcode->Window->Organizer->Archives 里面找到对应的版本，右键选择"Show in Finder"，在打开的文件夹中选中对应的"xxx.xcarchive"，右键选择"显示包内容"，在dSYMs文件夹中可以找到对应的"xxx.app.dSYM"文件。

   b. 生成iOS符号文件的zip压缩包。

   选中对应的"xxx.app.dSYM"文件，右键选择显示包内容，在 Contents/Resources/DWARF/ 目录下可以找到和app同名的 "xxx"文件，压缩"xxx"文件生成"xxx.zip"iOS符号文件。
   > 注意
   > * 如果开启了Bitcode，在上传到App Store时需要注意声明生成新的dSYM文件，然后从App Store中把该版本对应的dSYM文件下载回本地，生成iOS符号文件的zip压缩包并上传至AGC，才能正确符号化Crash日志。
   > * 如果您的应用嵌入了动态库（Dynamic Library），需要用该动态库对应的dSYM文件生成iOS符号文件的zip压缩包并上传至AGC，才能正确符号化Crash日志中该动态库的堆栈信息。


2. 登录[AppGallery Connect](https://developer.huawei.com/consumer/cn/service/josp/agc/index.html)，点击"开发与服务"。
3. 在项目列表中找到您的项目，在项目下的应用列表中点击您的应用。
4. 点击"质量 > 崩溃"，进入崩溃服务的页面。
5. 选择"映射文件 > iOS符号文件"，点击"![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20250704155610.38344597345174607628051056243850:50001231000000:2800:E02A7C44098E2203D8BFFBD926CE580108C7EE82C78D3C73A5B7A53B983B10BE.png)上传文件"。 说明
   >
   > 此方式支持上传zip格式的iOS符号文件。
   >
   > zip大小不超过100MB，且根目录下只能包含1个iOS符号表文件。解压后的大小不超过400MB。

   ![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20250704155610.64166309525395496291955278074470:50001231000000:2800:4AC6F62A19F5FA678951BACABD663AA5BE7FE5ECFC3AF7A1DE375560350FF1A8.png)
6. 点击![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20250704155610.74149127926565345530591852596379:50001231000000:2800:ABD7EB02114E016EC77903EFF47D88A1ADEF213E4D9B69687C9689E047187C79.png)，上传生成的iOS符号文件。

> 说明
>
> 当发生iOS崩溃后，如果AGC中展示的崩溃堆栈仍为不可阅读的代码，您可通过如下方法检查iOS符号表文件上传是否准确：
>
> 1. 查看崩溃日志中的UUID字段。
> 2. 在"iOS符号文件"页面中查看是否存在相同UUID的iOS符号文件。
>    * 如果存在，需[填写工单](https://developer.huawei.com/consumer/cn/support/feedback/#/add/89?level2=9020)联系华为技术支持处理。
>    * 如果不存在，说明没有上传对应的iOS符号文件。您需重新获取应用发生崩溃版本的iOS符号文件并上传。
