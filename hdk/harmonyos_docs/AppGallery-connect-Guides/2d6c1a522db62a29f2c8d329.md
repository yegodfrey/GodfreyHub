# 工作原理

通常，提交到LCD（液晶显示屏）面板的帧如下所示：

![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20240314102210.33541049238269368821927759503832:50001231000000:2800:C22345E23932F83FF6FBAC0444234685414A55514E7FD9C16080BE2EDB9A98CB.png?needInitFileName=true?needInitFileName=true)

为了满足不同类型的游戏对于高质量图像和降低输入延迟的需求，插帧服务提供了两种插帧方案：[内插](#section183995253443)和[外插](#section052313527017)。

## 内插

内插方案主要是通过实际帧N和实际帧N-1来预测插入帧N-0.5。该方案拥有更好的预测质量，但同时也引入了更多的输入延迟，可能会影响用户体验。因此，更适合追求图像高质量和平滑度的游戏类型，例如战略类型游戏。

![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20240314102210.84767608564088279159349720937781:50001231000000:2800:AA9C2628655F18D6CD919B71EC96528224D723FDD56391DA1A92F031F6410476.png?needInitFileName=true?needInitFileName=true)

```screen
// 内插逻辑
for (;;) { // (渲染循环)
    // 1. 绘制实际帧"N"，并将场景输出保存到纹理（s）中
    // 2. 通过FrameFlow_DrawFrame函数发起预测帧"N - 0.5"绘制请求
    // 3. 合成并送显预测帧"N - 0.5"
    // 4. 计算实际帧"N + 1"
    // 5. 合成并送显实际帧"N"
}
```

## 外插

外插方案主要是通过实际帧N和实际帧N-1来预测并插入预测帧N+0.5帧。该方案在输入延迟方面低于内插方案，因此，更适合于竞争、技能或基于反应的游戏。

![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20240314102211.40792512936013915398992598790130:50001231000000:2800:8C9D0E18CB9F02E48C2CA81D3FE402EEEEBA02DE280A3FBD007D94BF2AC5051A.png?needInitFileName=true?needInitFileName=true)

```screen
// 外插逻辑
for (;;) { // (渲染循环)
    // 1. 绘制实际帧"N"，并将场景输出保存到纹理（s）中
    // 2. 合成并送显实际帧"N"
    // 3. 计算实际帧"N + 1"
    // 4. 通过FrameFlow_DrawFrame函数发起预测帧"N + 0.5"绘制请求
    // 5. 合成并送显预测帧"N + 0.5"
}
```

> 说明
>
> * 此方案的关键是通过在连续的送显调用之间插入大量的计算逻辑，以平衡绘制实际帧和预测帧之间的工作负载，当在渲染线程调用第二次送显时，可减轻（或去除）阻塞问题，从而降低渲染线程中的延迟。
> * 外插方案存在一个普遍问题------**overshooting** （过冲），即用户通过触摸屏控制旋转相机时，当在旋转运动的中间停止触摸面板时，可能会导致一个预测帧画面超前。
