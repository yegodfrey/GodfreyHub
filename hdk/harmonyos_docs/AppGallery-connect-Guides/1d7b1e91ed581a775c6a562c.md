# 使用HTTP请求头标签控制缓存策略

合理使用请求资源的缓存，可以有效提升用户体验和降低请求带宽。云存储服务在获取对象时，支持通过HTTP请求头标签If-Modified-Since和If-None-Match来对缓存策略进行控制。  
![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20250424150205.86671039602487363494568222573126:50001231000000:2800:6F68C24B1E16EB23B159B47F830ED606DC575F7E9AACE7061833AC207B0899C1.png)  
当If-Modified-Since和If-None-Match在请求头中同时出现时，If-Modified-Since将被忽略。  

#### If-Modified-Since

当资源在请求头标签If-Modified-Since指定时间后有更新，那么将返回更新的内容，否则将返回304 Not Modified的信息。

以浏览器访问云存储服务器为例。

浏览器发起HTTP请求时，若将If-Modified-Since一起发送给云存储服务器，云存储服务器会将If-Modified-Since所对应的时间，与服务器上文件最后更新时间进行对比。

* 当If-Modified-Since所对应的时间大于、等于最后更新时间，表示资源没有过期，那么云存储服务器将返回304 Not Modified的状态码；请求方获取到304状态码后，可以直接使用本地缓存的内容。
* 当If-Modified-Since所对应的时间小于最后更新时间，表示资源已过期，那么云存储服务器将返回200状态码和新的资源内容；请求方获取到200状态码后，丢弃旧缓存的内容，重新缓存并使用新的资源。

#### If-None-Match

ETag可作为服务端与特定对象关联的字段，当对象更新时，ETag的值也会随之更新。所以通过对比资源的ETag值和请求头标签If-None-Match的值也可以来控制缓存策略。

* 资源的ETag值 ≠ 请求头标签If-None-Match的值时，表示资源已过期，那么云存储服务器将返回200状态码和新的资源内容。
* 资源的ETag值 = 请求头标签If-None-Match的值时，表示资源没有过期，那么云存储服务器将返回304 Not Modified的状态码。

2. 后续请求如果传入If-None-Match的值等于资源的ETag值，则返回304状态码。
