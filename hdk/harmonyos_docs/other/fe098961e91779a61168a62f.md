# Xlayout方案  
  
应用布局优化提供Android整体/页面级别的统一重布局能力，手机的UI系统会在运行时分析用户的界面，将原本大图大字体的页面调整为正常的尺寸，同时识别不同类型的元素并进行智能重排版，尽可能优化用户界面。本方案有以下特点：

     * 支持更简单的接入：开发者仅需要简单的配置就可以使功能生效，大部分情况无需修改代码；
     * 支持更简单的开关：用户可以在设置界面的功能开关轻松的定制自己喜好，选择哪些应用功能生效；

#### 功能使用限制

序号 | 限制  
---|---  
1 | 若应用不支持页面级配置，且需要指定页面生效，需要修改少量代码改造为页面级配置  
2 | 部分三方框架不生效或效果不好（Flutter、React Native等），是否使用请验证过效果后决定

#### 配置指南

**1\. 修改AndroidManifest文件**

在“AndroidManifest.xml”文件的“application”中新增“meta-data”：
    
    <meta-data android:name="EasyGoClient" android:value="true" />

![](https://communityfile-drcn.op.hicloud.com/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20220629161924.55601429768933756528851624134225:50530628094616:2800:72F1616621DEBFEAF8A2534CE28F7C6D63CE1F7E80D732DCC484103916F51028.png?needInitFileName=true?needInitFileName=true)

**2\. 新增easygo.json配置文件**

在工程中assets目录新增easygo.json文件，json文件中配置适配策略、activity名称等信息。目录结构为：

└── app

├── build.gradle

└── src

└── main

├── AndroidManifest.xml

├── assets

│ └── **easygo.json**

└── java

└── com

└── example

若应用已经有该文件，只需要在“logicEntities”字段新增内容。

"easygo.json"文件模板以及字段详细说明：
    
    {
      "easyGoVersion": "1.0",
      "client": "packagename",
      "logicEntities": [
        {
          "head": {
            "function": "xlayout",
            "required": "true"
          },
          "body": {
            "enable": 1,
            "policy": "activity",
            "activities": [
              {
                "activity_name": "com.huawei.example.Main1Activity",
                "activity_policy": 2
              },
              {
                "activity_name": "com.huawei.example.Main2Activity",
                "activity_policy": 2
              }
            ]
          }
        }
      ]
    }

参数 | 是否必选 | 描述  
---|---|---  
easyGoVersion | 是 | 协议版本，固定值为“1.0”  
client | 是 | 应用包名，需要和应用实际包名一致，否则不会生效  
logicEntities | 是 | 配置的组件块，可添加多个组件，互相之间独立  
logicEntities.head.function | 是 | 调用组件名，应用重布局固定值为“xlayout”  
logicEntities.head.required | 是 | 预留字段，固定值“true”，请勿修改  
logicEntities.body.enable | 是 | 启用功能开关： 0 - 关闭 1 - 启用  
logicEntities.body.policy | 是 | 启用的重布局模式： "activity" - 指定activity页面生效  
logicEntities.body.activities.activity_name | 是 | 生效的Activity组件全名，至少写一组  
logicEntities.body.activities.activity_policy | 是 | Activity对应的策略， "1" - 指定模式1生效，所有元素处理 "2" - 指定模式2生效，仅部分元素处理  
  
**Tips：如何获取当前activity名：**

通过以下命令来获取，可以得到当前的{包名/activity名}，配置文件中应该配置对应红框中的activity名
    
    adb shell dumpsys window | findstr mCurrentFocus

#### FAQ

当应用开发者进行折叠屏适配时，可以考虑本优化方案，仅增加配置文件就可以制定页面生效，进行界面重布局，优化显示效果；对于不支持指定页面生效的应用，也仅需要很少量的代码改动就可以完成适配，具体适配方法见如何适配单个页面。

#### 1\. 如何适配单个页面？

由于该方案需要支持页面级配置，如果应用未配置的页面受到影响而显示异常。针对不支持页面级配置的应用，则建议按照如下方法修改。

**如何获取Activity实际显示的窗口大小**

     * **不建议使用** ，可能会导致页面显示异常/功能异常。 
       * 通过DefaultDisplay获取尺寸：
             
             //bad eg1. 
             WindowManager wm = (WindowManager) getSystemService(Context.WINDOW_SERVICE);
             int width = wm.getDefaultDisplay().getWidth();
             int height = wm.getDefaultDisplay().getHeight();
              
             //bad eg2.
             DisplayMetrics dm = new DisplayMetrics();
             getWindowManager().getDefaultDisplay().getMetrics(dm);
             int mScreenWidth = dm.widthPixels;
             int mScreenHeight = dm.heightPixels; 
             
             //bad eg3. DisplayMetrics dm = new DisplayMetrics();
             getWindowManager().getDefaultDisplay().getRealMetrics(dm);
             int mScreenWidth = dm.widthPixels;
             int mScreenHeight = dm.heightPixels;

       * 通过Application的context获取尺寸：
             
             //bad eg4.
             DisplayMetrics windowDisplayMetrics = application.getResources().getDisplayMetrics();
             int windowWidth = windowDisplayMetrics.widthPixels;
             int heightWidth = windowDisplayMetrics.heightPixels;

       * 通过view的接口获取window的尺寸：
             
             //bad eg5.
             Rect rect = new Rect();
             getWindow().getDecorView().getWindowVisibleDisplayFrame(rect);

     * **推荐使用的例子**
           
           //good eg1.
           DisplayMetrics windowDisplayMetrics = activity.getResources().getDisplayMetrics();
           int windowWidth = windowDisplayMetrics.widthPixels;
           int heightWidth = windowDisplayMetrics.heightPixels;

Tips：上述接口中，context为**Activity** 对应的上下文句柄，每个**Activity** 应该严格使用自己的context来进行布局，而不是使用**application** 的context，否则可能会导致其它未配置的页面显示异常。

     2. 分析每个使用到“getDisplayMetrics”、“getDefaultDisplay”以及“getWindowVisibleDisplayFrame”的代码逻辑，如果获取到的屏幕参数用在自适应布局的Activity上，则分以下两种情况来修改： 
        * 如果，代码写在Activity的实现类中，直接把调用对象换为XXActivity.this.getDisplayMetrics。
        * 如果，代码写在工具类中，可以考虑如下的两种方式： 
          * 工具类中新增方法单独给配置的activity使用，通过传入activity的Context来获取屏幕尺寸。
          * 考虑在工具类代码实现的方法中增加一个入参，传入activity的Context，方法内部把getDisplayMetrics或者getDefaultDisplay的调用改成由入参Context调用getDisplayMetrics。

#### 3\. 是否可以保存获取到的屏幕或窗口尺寸数据？

因为本适配方案会对屏幕或窗口信息做修正，因此如果应用只需要适配部分界面时，这部分页面使用到的屏幕或窗口信息需要实时获取，请不要将屏幕宽度等信息保存后使用。
