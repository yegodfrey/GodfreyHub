# 1. 前言

## 1.1 背景和目的

目前安卓系统手机播放器在输出设备为蓝牙耳机时会出现严重音视频不同步现象，严重影响用户体验。本文旨在指导第三方视频播放应用正确获取音频相关信息并使用来保证音视频同步。

精确的音视频同步是媒体播放的关键性能指标之一。一般来说，在录音设备上同时录制的音频和视频需要在播放设备（例如手机，电视，媒体播放器）上同时播放。为了实现设备上的音视频同步可以按如下指南操作。

# 2. 音视频同步原理

音视频数据的最小处理单元称为帧。音频流和视频流都被分割成帧，所有帧都被标记为需要按特定的时间戳显示。音频和视频可以独立下载和解码，但就具有匹配时间戳的音频和视频帧应同时呈现，达到A/V同步的效果。

![](https://communityfile-drcn.op.hicloud.com/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20190910001024.35801053948671295146506384559391:50501008161056:2800:E14539484D759E00C70106060177BABD920709FE54231D7C87F57CE39B8ED052.png)

理论上，因为音频通路存在时延，匹配音频和视频处理，有三种A/V同步解决方案可用：

（1）连续播放音频帧：使用音频播放位置作为主时间参考，并将视频播放位置与其匹配。

（2）使用系统时间作为参考：将音频和视频播放与系统时间匹配。

（3）使用视频播放作为参考：让音频匹配视频。

第一个选项是唯一一个具有连续音频数据流的选项，没有对音频帧的显示时间、播放速度或持续时间进行任何调整。这些参数的任何调整都很容易被人的耳朵注意到，并导致干扰的音频故障，除非音频被重新采样；但是，重新采样也会改变音调。因此，一般的多媒体应用应使用音频播放位置作为主时间参考。以下段落将讨论此解决方案。（其他两个选项不在本文档的范围内）

# 3. 音频视频同步方法

音频和视频的管道必须同时以相同的时间戳呈现每帧数据。音频播放位置用作主时间参考，而视频管道只输出与最新渲染音频帧匹配的视频帧。对于所有可能的实现，精确计算最后一次呈现的音频时间戳是至关重要的。Android提供了几个API来查询音频管道各个阶段的音频时间戳和延迟。

下面按第三方播放器采用的播放器框架区分，分别描述如何获取到音轨的时间戳和时延信息。

## 3.1 第三方定制媒体播放器

在定制的媒体播放器中，应用程序完全控制音频和视频数据流，并知道解码音频和视频数据包需要多长时间。应用程序还可以自由地增加或减少缓冲视频数据量，以保持连续播放。视频管道需要调整为音频管道呈现的时间戳。应该使用以下两个API。

### 3.1.1 AudioTrack.getTimestamp()

音频管道支持查询最新呈现的时间戳，getTimeStamp() 方法提供了一种简单的方法来确定我们要查找的值。如果时间戳可用，则audioTimestamp实例将填充以帧单位表示的位置，以及显示该帧时的估计时间。此信息可用于控制视频管道，使视频帧与音频帧匹配。

注意以下事项：

（1）建议查询时间戳的频率从每10秒一次到每分钟一次。有可能存在轻微误差，但不会突然跳变，因此不需要频繁的查询时间戳。

（2）正确返回时间戳时，应用程序应信任这些值，而不使用任何其他硬编码偏移量。强烈反对增加实验值。它们不是平台独立的，管道可能随时更新（例如，连接蓝牙接收器时），从而使以前正确的值不准确。

```prettyprint linenums prettyprinted
复制


1. int latestAudioFrameTimestamp = audioTrack.getTimeStamp();
```

有关可用参数和返回值的详细信息，请参阅Android文档中的getTimeStamp() 方法。

### 3.1.2 AudioTrack.getPosition()

如果音频管道不支持查询上一节所述的最新呈现音频时间戳，则需要另一种方法。

这个解决方案由两部分组成，使用audioTrack类与AudioSystem类的独立函数。第一个根据audioTrack.getPosition() 方法返回的当前缓存区头部位置计算最新的帧的音频时间戳；第二个根据AudioSystem.getOutputLatency()方法返回硬件延时。

```prettyprint linenums prettyprinted
复制


1. private long framesToDurationUs(long frameCount) {

2.     return (frameCount * C.MICROS_PER_SECOND) / sampleRate;

3. }

4. long timestamp = framesToDurationUs(audioTrack.getPosition());

5. int latestAudioFrameTimestamp = framesToDurationUs(audioTrack.getPosition()-- AudioSystem.getOutputLatency();
```

# 5. 验收方法

## 5.1 接口调用判断

华为手机EMUI，音频Framework通过日志打印的方式，验证音频时间信息是否被第三方应用正确获取和调用。

## 5.2 音视频同步测量

测量手机播放器音频数据下发到耳机发声音的端到端时延。

### 5.2.1 方法1

手机与耳机建立蓝牙连接，手机上加载音视频时延测试APK，产生视频和声音数据时，同步触发拉LED闪光，耳机出声后通过声控LED发光。摄像机同步拍摄。

拍摄后通过数帧来判断声音和视频的同步时延差。
![](https://communityfile-drcn.op.hicloud.com/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20190910001025.86703699591044672582292168249743:50501008161056:2800:F603317848AEEAD25AF0F7DCA83EAA4C3C66958AA18FAB0DBC3C223061823601.png)

耳机出声音到声控LED灯点亮的时延，理想情况下，声音340m/s的传输速度，当两者距离在34cm范围内，时延为1ms。此外，还需要考虑器件的实际因素。

高速相机的时延误差，取决于拍摄帧率，以帧率240fps计算，1帧误差范围为4.2ms。

### 5.2.2 方法2

手机与耳机建立蓝牙连接，手机播放视频同时声音从耳机出声。将音量调整到最大。摄像机靠近耳机同步拍摄。

拍摄后通过数帧来判断声音和视频的同步时延差。
