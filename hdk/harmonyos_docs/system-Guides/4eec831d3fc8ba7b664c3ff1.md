# 信标消息发布与订阅

## 业务流程

![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20240708165623.00306903288091559531556066875468:50001231000000:2800:481555052A53136908573561088E885A4FA68DECEDDEE86406BF4F3389B6C0F2.png?needInitFileName=true?needInitFileName=true "点击放大")

蓝牙信标（Beacon）是一种基于低功耗蓝牙（Bluetooth Low Energy，简称BLE）技术的物理设备，主要有EddyStone和iBeacon。您购买到蓝牙信标设备后可以通过该蓝牙信标设备厂商提供的App进行信标参数配置。在基于蓝牙信标的消息发布和订阅时，Nearby云服务提供信标参数和消息附件的管理能力，具体内容可参见[REST](https://developer.huawei.com/consumer/cn/doc/system-References/overview2-0000001061766323)。您可以通过Nearby云服务进行消息的配置和发布，同时使用[Nearby Message API接口](https://developer.huawei.com/consumer/cn/doc/system-References/message-overview-0000001050130660)扫描信标设备和获取已发布消息。信标消息支持[前台订阅信标消息](#section10629115664212)、[后台订阅信标消息](#section129218919436)和[注册信标扫描任务](#section121131646145815)^**beta**^三种订阅方式，前台订阅可以更快地扫描到周边的蓝牙信标，后台订阅相比前台订阅功耗更低，注册信标扫描任务^**beta**^可以在后台一直扫描，即使应用处于关闭状态，扫到信标后也能及时通知，但是功耗可能相比前两种稍高。

## 配置信标

对信标进行配置，请参见[信标管理](https://developer.huawei.com/consumer/cn/doc/system-Guides/beacon-management-0000001050040616)。

配置信标时，可以将信标ID与消息附件（attachment）进行关联。消息附件是一个特定的字节流（Byte stream）。Nearby Message只对该消息附件进行存储，而不解析其具体内容的含义。消息附件最大长度限制为1024字节，一个信标ID最多关联9个消息附件。

## 前台订阅信标消息

前台订阅比后台订阅的设备发现速度更快，相应的功耗更高。注意只有当应用在前台活动时，前台订阅功能才能启动，当应用退出前台，消息订阅任务将停止。

调用[get](https://developer.huawei.com/consumer/cn/doc/system-References/messageengine-0000001050130686#section5780511181418)([MessageHandler](https://developer.huawei.com/consumer/cn/doc/system-References/messagehandler-0000001050132619), [GetOption](https://developer.huawei.com/consumer/cn/doc/system-References/getoption-0000001050130682))接口，进行前台订阅消息的示例代码：

```screen
MessageHandler mMessageHandler = new MessageHandler() {
    // 获取到周围设备新消息
    @Override
    public void onFound(Message message) {
        super.onFound(message);
        // 当发现新消息时，请处理您的业务
    }
    // 蓝牙设备扫描不到或云端消息消失时回调
    @Override
    public void onLost(Message message) {
        super.onLost(message);
        // 当发现新消息时，请处理您的业务
    }
};
// 默认为订阅所有类型消息，支持添加多种过滤条件
MessagePicker msgPicker = new MessagePicker.Builder()
            .includeNamespaceType("dev91050203040506", "HMS")
            .includeEddystoneUids("5dc33487f02e477d4058", "0117c5986919")
            .includeIBeaconIds(UUID.fromString("01122334-4556-6778-899a-abbccddeeff0"), (short)0x3e8, (short)0x2711)
            .build();
Policy policy = Policy.BLE_ONLY;
GetOption getOption = new GetOption.Builder().setPicker(msgPicker).setPolicy(policy).build();
Task<Void> task = Nearby.getMessageEngine(getApplicationContext()).get(mMessageHandler, getOption);
```

> 说明
>
> * 信标原始消息与信标为一一对应关系，订阅原始消息则代表订阅当前目标信标的状态变化。您可以将信标注册到开发者联盟并创建附件消息，NameSpace、Type为附件消息的属性。当订阅条件为NameSpace和Type时，代表订阅这类消息的状态变化。
> * 您可以通过[MessageHandler](https://developer.huawei.com/consumer/cn/doc/system-References/messagehandler-0000001050132619)设定满足条件的消息发现、丢失、距离变化、信号强度变化时的处理逻辑。
> * [MessagePicker](https://developer.huawei.com/consumer/cn/doc/system-References/messagepicker-0000001050130666)默认条件为[includeAllTypes](https://developer.huawei.com/consumer/cn/doc/system-References/mespicker-builder-0000001050130668#section337237182010)()，设置该条件的应用会订阅到开发者联盟同一项目下的所有应用发布的消息，同时也支持自定义多个消息过滤条件的组合，包括"NamespaceType"、"Eddystone UID"、"iBeacon"三种方式，其中"NamespaceType"方式默认只允许Beacon ID以"6bff00f723fdf7471402"开始的设备被Nearby扫描到，示例见下表。

**信标消息过滤条件示例表**

|方式|示例|过滤**条件**|备注|
|:--------------|:---------------------------------------------------------------------------------------------------------------------|:-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|:-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
|"NamespaceType"|includeNamespaceType("*dev91050203040506*", "HMS")|仅扫描Beacon ID以默认前缀"6bff00f723fdf7471402"开始的信标设备并过滤在该设备上配置的命名空间为"*dev91050203040506*"，类型为HMS的消息。|* 命名空间和类型的获取，请参见[查询消息附件列表](https://developer.huawei.com/consumer/cn/doc/system-References/querybeaconattachment-0000001050154887)。 * 会扫描和发现信标并获取符合命名空间和类型的消息附件，所以您需要提前在开发者联盟上配置信标，请参见[注册信标设备](https://developer.huawei.com/consumer/cn/doc/system-References/login-beacon-0000001050154445)。|

## 后台订阅信标消息

后台订阅的设备发现速度相比前台订阅稍慢，但是后台订阅功耗更低。

以下是调用[get](https://developer.huawei.com/consumer/cn/doc/system-References/messageengine-0000001050130686#section2112412181)(PendingIntent)接口，进行后台订阅的示例代码：

```screen
PendingIntent pendingIntent = PendingIntent.getService(this, 0, new Intent(this, BackgroundGetIntentService.class), PendingIntent.FLAG_UPDATE_CURRENT);
Nearby.getMessageEngine(this).get(pendingIntent);

// 此IntentService会在后台扫描到目标设备时触发
public class BackgroundGetIntentService extends IntentService {
    public BackgroundGetIntentService(String name) {
        super(name);
    }
    protected void onHandleIntent(Intent intent) {
        MessageEngine messageEngine = Nearby.getMessageEngine(context);//context为Context实例
        messageEngine.handleIntent(intent, new MessageHandler() {
            @Override
            public void onFound(Message message) {
                Log.i(TAG, "onFound " + new String(message.getContent()));
            }

            @Override
            public void onLost(Message message) {
                Log.i(TAG, "onLost " + new String(message.getContent()));
            }
        });
    }
}
```

## 注册信标扫描任务（**beta**）

> 注意
>
> 该功能暂不推荐非华为手机使用，可能会导致功能异常。
>
> * 为提高扫描资源利用率、减少手机电量消耗，Nearby Message会自动移除注册超过七天的扫描任务，故针对需要持续扫描的场景，请您在七天内重新注册扫描任务。
> * 调用接口时可能会触发向用户申请授予"位置"等权限的弹窗，为避免影响用户体验，请勿在应用处于后台时调用此接口。

![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20240708165623.42502681436487175576090369596781:50001231000000:2800:45CBDF77B649DB97D619B6F7A1AAF826BFE9DAF1452235A3353656606658B048.png?needInitFileName=true?needInitFileName=true "点击放大")

信标扫描任务会在后台一直运行，当扫描到信标设备后，会通过广播或者Service通知的方式通知到应用。一个应用只能注册一个扫描任务，如果需要修改已注册任务的配置参数，只能先主动取消已注册的任务，然后重新注册。
> 注意
>
> 如果您希望在应用关闭的情况下也能收到信标通知消息，建议您同时开启应用的"允许关联启动"和"允许后台活动"项。操作路径：选择"设置 > 应用与服务 > 应用启动管理"，找到对应的应用，关闭"自动管理"，开启"允许关联启动"和"允许后台启动"。

调用[registerScanTask](https://developer.huawei.com/consumer/cn/doc/system-References/beacon-api-beaconengine-0000001458335162#section37961827165318)(Intent intent, [GetBeaconOption](https://developer.huawei.com/consumer/cn/doc/system-References/beacon-api-getbeaconoption-0000001456834730) option)接口注册扫描任务的代码示例如下：

```screen
TriggerOption triggerOption = new TriggerOption.Builder()
    // 设置通知方式TriggerMode
    .setTriggerMode(2)
    // 设置广播或者服务的类名，请注意要和TriggerMode一致
    .setTriggerClassName(SampleReceiver.class.getName())
    .build();
Intent intent = new Intent();
intent.putExtra(GetBeaconOption.KEY_TRIGGER_OPTION, triggerOption);

BeaconPicker beaconPicker = new BeaconPicker.Builder()
    // 支持按照"NamespaceType"过滤Beacon
    .includeNamespaceType("dev91050203040506", "HMS")
    // 支持按照"Beacon ID前缀+NamespaceType"过滤
    .includeNamespaceType("dev91050203040506", "HMS", "6bff00f723fdf7471402", BeaconPicker.BEACON_TYPE_IBEACON)
    // 支持按照"Beacon ID前缀"过滤
    .includeBeaconId("6bff00f723fdf7471402", BeaconPicker.BEACON_TYPE_IBEACON)
    .build();
GetBeaconOption getOption = new GetBeaconOption.Builder().picker(beaconPicker).build();
Nearby.getBeaconEngine(this).registerScanTask(intent, getOption).addOnSuccessListener(new OnSuccessListener<Void>() {
    @Override
    public void onSuccess(Void unused) {
        Log.i(TAG, "registerScanTask success");
    }
    }).addOnFailureListener(new OnFailureListener() {
    @Override
    public void onFailure(Exception e) {
        Log.i(TAG, "registerScanTask fail:" + e.getMessage());
    }
});
```

* Service方式（"triggerMode = 1"）

  ```screen
  public class SampleService extends Service {
      private static final String TAG = "SampleService";
      // 0：丢失；1：发现
      private static final String KEY_SCAN_ONFOUND_FLAG = "SCAN_ONFOUND_FLAG";
      // 发现或丢失的Beacon信息
      private static final String KEY_SCAN_BEACON_DATA = "SCAN_BEACON";
      
      private static final String BEACON_NOTIFY_CHANNEL_ID = "beacon_notification_channel_id";

      private static final String BEACON_NOTIFY_CHANNEL_NAME = "beacon_notification_channel_name";

      private static final int NOTIFICATION_SERVICE_ID = 101;

      public SampleService() {
      }

      @Override
      public void onCreate() {
          Log.i(TAG, "onCreate");
          new Handler().postDelayed(this::startForeground, 1000);
          super.onCreate();
      }

      @Override
      public int onStartCommand(Intent intent, int flags, int startId) {
          Log.i(TAG, "onStartCommand");
          startForeground();
          int onFound = intent.getIntExtra(KEY_SCAN_ONFOUND_FLAG, 0);
          Log.i(TAG, "onFound:" + onFound);

          // 获取Beacon信息，做业务处理
          List<BeaconInfo> beaconList = intent.getParcelableArrayListExtra(KEY_SCAN_BEACON_DATA);
          return super.onStartCommand(intent, flags, startId);
      }

      public void startForeground() {
          // 通知栏逻辑可自行处理
          if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.O) {
              NotificationChannel channel = new NotificationChannel(BEACON_NOTIFY_CHANNEL_ID,
                      BEACON_NOTIFY_CHANNEL_NAME, NotificationManager.IMPORTANCE_LOW);
              NotificationManager notificationManager = (NotificationManager) getSystemService(Context.NOTIFICATION_SERVICE);
              notificationManager.createNotificationChannel(channel);
          }
          Notification notification = new NotificationCompat.Builder(this, BEACON_NOTIFY_CHANNEL_ID)
                  // 设置通知图标
                  .setSmallIcon(R.mipmap.ic_launcher)
                  // 设置通知标题
                  .setContentTitle("信标提醒")
                  // 设置通知内容
                  .setContentText("发现信标")
                  .setAutoCancel(true)
                  .setOngoing(true)
                  .build();
          // Android 8.0以后系统不希望后台应用启动后台服务，所以在Service中需调用startForeground()，否则可能出现ANR或者Crash
          startForeground(NOTIFICATION_SERVICE_ID, notification);
      }

      @Override
      public IBinder onBind(Intent intent) {
          return null;
      }
  }
  ```

## 信标信号强度与距离估算

订阅者可以查询到与接收到的消息关联的信标信号强度，并获得与信标设备之间距离的粗略估计。示例代码如下：

```screen
MessageHandler mMessageHandler = new MessageHandler() {
    // 当目标设备距离变化（超过1米）时回调
    @Override
    public void onDistanceChanged(Message message, Distance distance) {
       super.onDistanceChanged(message, distance); }
    // 当目标设备蓝牙信号强度等级变化（RSSI变化超过10dbm）时触发此回调
    @Override
    public void onBleSignalChanged(Message message, BleSignal bleSignal) {     
       super.onBleSignalChanged(message, bleSignal); }
};
// 默认为订阅所有类型消息，参见接口文档进行个性化定义
MessagePicker msgPicker = new MessagePicker.Builder().includeAllTypes().build(); 
Policy policy = Policy.BLE_ONLY; 
GetOption getOption = new GetOption.Builder().setPicker(msgPicker).setPolicy(policy).build(); 
Task<Void> task = Nearby.getMessageEngine(getApplicationContext()).get(mMessageHandler, getOption);
```
