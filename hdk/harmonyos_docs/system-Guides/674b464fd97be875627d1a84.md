# 接入说明

#### 概述

Android支持多种进程间通信（IPC, Inter-process communication）机制，既包括Android推荐的Intents、Binder机制，也包括继承于Linux的传统IPC机制，包括共享内存、Netlink Socket、以及Unix Domain Sockets（也称LocalSocket）等方式。

LocalSocket方式下，应用无需集成任何SDK，以彻底解耦的方式与系统的开放能力交互，并且其实现与编程语言无关，适用面最广。LinkTurbo Engine开放的方式，即采用LocalSocket方式，应用无需集成SDK，对应用的开发语言也没有要求，只要按照本文描述的交互方式进行消息交互，即可接入华为LinkTurbo Engine网络加速能力。

在接入前，须确认设备是华为手机（读取原生的prop项ro.product.manufacturer，如果值为"HUAWEI"就是华为手机）才可使用本文档定义的LinkTurbo Engine网络加速能力。只有在支持LinkTurbo Engine的手机上才能通过消息使能网络加速功能。  

#### LocalSocket机制说明

LocalSocket机制为C/S双向实时通信机制。Client与Server的语义仅在建立连接的语境下有意义，一旦连接建立完成，通信双方是对等实体。这意味着，应用既可以向系统发送请求调用API，系统也可以进行事件通知或者请求应用相关信息。  

#### 服务端（EMUI）

服务端创建SOCKET_NAMESPACE类型为ABSTRACT，采用可靠字节流传输STREAM方式的Socket Server，SOCKET_NAME为"resmon"，LinkTurbo Engine系统服务端创建的Socket Server伪代码如下：

```
create_socket_local_server(SOCKET_NAME, SOCKET_NAMESPACE_ABSTRACT, STREAM);
```

此后服务端bind()-\>listen()进入loop循坏等待来自应用作为Socket Client的连接并处理其数据请求。  

#### 客户端（应用侧）

与服务端类似，客户端创建SOCKET_NAMESPACE类型为ABSTRACT，采用可靠字节流传输STREAM方式的Socket Client，SOCKET_NAME为"resmon"，应用创建的Socket Client伪代码如下：

```
create_socket_local_client(SOCKET_NAME, SOCKET_NAMESPACE_ABSTRACT, STREAM);
```

此后客户端connect()进入loop循坏等待发送数据或处理数据请求。  

#### 消息格式

消息基本格式由"消息头+消息体"两部分构成，具体分为两种：

1. Request请求报文
   * 报文格式： ------------------------------------------------------------------

     \| LinkTurboReqHeaderV1 \| body(业务请求结构体序列化数据) \|

     ------------------------------------------------------------------
   * 报文头：LinkTurboReqHeaderV1

     ```
     typedef struct LinkTurboReqHeaderV1 {
         uint32_t begin;        // 包头起始字段，固定填写HEADER_BEGIN
         uint16_t version;     // 协议版本，当前填写HEADER_PROTOCOL_VERSION_1
         uint16_t msgType;    //指明是请求消息，还是响应消息。1：请求，2：响应
         uint16_t funcid;        // 请求对应的function ID，当前固定填写HDR_ FUNCID
         uint32_t bodylen;     // 包体序列化数据长度
         int64_t requestid;     // 当前请求包ID，保持递增、唯一
         int64_t timestamp;     // 当前请求时间戳
         uint32_t bodyformat;     //包体数据序列化格式枚举值，固定填写HDR_BODYFORMAT 
         uint32_t data1;        //预留字段1
         uint32_t data2;        //预留字段2
         uint32_t data3;        //预留字段3
     }__attribute__ ((packed)) LinkTurboReqHeaderV1;
     ```

   * 报文体：JSON序列化字节流，参见[消息体定义](#ZH-CN_TOPIC_0000001050825169__section158581024134511)。
2. Response响应报文
   * 报文格式： ------------------------------------------------------------------

     \| LinkTurboResHeaderV1 \| body(业务请求结构体序列化数据) \|

     ------------------------------------------------------------------
   * 报文头：LinkTurboResHeaderV1

     ```
     typedef struct LinkTurboResHeaderV1 {
         uint32_t begin;      // 包头起始字段，固定填写HEADER_BEGIN
         uint16_t version;    // 协议版本，当前填写HEADER_PROTOCOL_VERSION_1
         uint16_t msgType;    //指明是请求消息，还是响应消息。1：请求，2：响应
         uint32_t bodylen;    // 包体序列化数据长度
         int64_t requestid;   // 响应对应的请求包ID
         int64_t timestamp;   // 当前响应时间戳
         uint32_t bodyformat; //包体数据序列化格式枚举值，固定填写HDR_BODYFORMAT
         uint32_t data1;      //预留字段1
         uint32_t data2;      //预留字段2
         uint32_t data3;      //预留字段3
     }__attribute__ ((packed)) LinkTurboResHeaderV1;
     ```

* 报文体：JSON序列化字节流，参见[消息体定义](#ZH-CN_TOPIC_0000001050825169__section158581024134511)。

#### 系统状态通知

LinkTurbo Engine网络加速系统侧的状态变化，通过事件的方式通知应用，事件类型通过notifyParaJson的"ltEventId"进行区分，不同的事件，通知参数不同。如果应用不需要感知事件，可以不定义处理函数。

说明：

* 系统每次通过消息通告应用时仅包括一个事件；如果存在多个事件需要通知应用，则系统会发送多条通告消息。

* 如果同一事件短时间频繁变化（例如网卡状态1s内发生3次变化），系统会过滤并上报1s内最后一次，以避免过分频繁发送事件。

1. LinkTurbo Engine状态变化事件

   通知参数格式：  

   |值|定义|
   |:---------|:------------------------------------------------------------------------------------------------------------|
   |T_EVENT_ID|1：LinkTurbo Engine状态变化。|
   |LT_ENABLED|* 1：功能可用。 * 0：功能不可用。例如用户关闭了开关，或者当前不存在多网等情况下，系统会向应用通告功能不可用。此时，有Wi-Fi网络，全部链路切换到Wi-Fi网卡，如果没有Wi-Fi网络，全部链路切换到蜂窝网络。|

   在应用启动场景，应该在系统通告了LinkTurbo Engine功能可用后再调用LinkTurbo Engine的其他接口。在系统通告LinkTurbo Engine功能不可用时，应用应理解当前系统的行为并根据自己的诉求决定是否调整网络使用策略。

   举例：LinkTurbo Engine网络加速不可用。

   ```
   {
       "ltEventId":1，
       "ltEnabled":0
   }; 
   ```

2. 网卡状态变化事件

   通知参数格式：  

   |名称|值|类型|描述|
   |:----------|:----------|:--|:-----------|
   |LT_EVENT_ID|"ltEventId"|int|2：可用网络接口有变化。|

   在应用收到系统的该通告时，建议重新调用getAvailableNetInterface（参见[查询可用的网络接口](#ZH-CN_TOPIC_0000001050825169__section2691539563)）获取最新的可用网卡列表。

   举例：网卡状态变化。

   ```
   {"ltEventId":2}; 
   ```

3. 应用级别绑定网卡状态变化事件

   通知参数格式：  

   |名称|值|类型|描述|
   |:----------------|:---------------|:-----|:------------------|
   |LT_EVENT_ID|"ltEventId"|int|3：当前已经绑定的网卡通知。|
   |LT_BOUNDED_NETWOR|"boundedNetwork"|String|当前绑定的网卡，例如"wlan00"。|

   当前系统侧通过该事件通告应用绑定网卡成功，对应接口[将业务绑定到特定网口](#ZH-CN_TOPIC_0000001050825169__section119871412105619)。如果没有收到该回应，说明系统侧未绑定成功，应用应处理在预期时间内（建议3s）未受到系统通告的情况。

   举例：应用级别绑定网卡成功。

   ```
   {
       "ltEventId":3，
       "boundedNetwork":"wlan00"
   };
   ```

4. Socket级别绑定网卡状态变化事件

   通知参数格式：  

   |名称|值|类型|描述|
   |:-----------------------------|:--------------------------|:---------|:-----------------------------------------------------------------------|
   |LT_EVENT_ID|"ltEventId"|int|4：Socket已经绑定的网卡通知。|
   |LT_SOCKET_FD LT_BOUNDED_NETWOR|"socketFd" "boundedNetwork"|int String|描述该Socket的fd。 当前绑定的网卡，例如"wlan00"。当前通过该事件通告应用绑定网卡成功，如果没有收到该回应，说明系统侧未绑定成功。|

   当前系统侧通过该事件通告应用绑定网卡成功，对应接口[将Socket绑定到特定网口](#ZH-CN_TOPIC_0000001050825169__section18355155725510)。如果没有收到该回应，说明系统侧未绑定成功，应用应处理在预期时间内（建议3s）未受到系统通告的情况。

   举例：Socket级别绑定的网卡成功。

   ```
   {
       "ltEventId":4，
       "fd":21，
       "boundedNetwork":"wlan00"
   };
   ```

#### 消息体定义

#### 注册使用LinkTurbo Engine：registerApp()

应用在使用任何LinkTurbo Engine API接口前需要先注册成功，在应用进程的生命周期内无需重复注册。当应用切换至后台、停止运行或被卸载时，再使用LinkTurbo Engine API时需要重新注册。

注册结果会通过Response返回给调用者（参见[notifyId系统向应用通知消息类型枚举](#ZH-CN_TOPIC_0000001050825169__li175671276618)）。但是注册成功不代表此时LinkTurbo Engine网络加速功能可用。需要在收到LinkTurbo Engine状态变化事件（参见[LinkTurbo Engine状态变化事件](#ZH-CN_TOPIC_0000001050825169__li422618711019)）通告LinkTurbo Engine可用，才可以绑定业务到网口。

#### 查询LinkTurbo Engine接口版本号：getLinkTurboVersion()

|Key|Value|
|:---------------|:-------|
|linkturboVersion|23.2.1.0|

举例：


#### 查询可用的网络接口：getAvailableNetInterface()

应用向系统查询可用的网络接口。当应用注册成功的情况下系统通过response报文返回当前处于active状态的所有网络接口信息，每个网络接口信息包括接口名、能力描述等。返回网络接口是使用JSON格式描述的"netInfo"，说明如下：

netInfo：  

|Key|Value|
|:-----------|:----------------------------------------------------------------------------|
|netInterface|wlan AB或rmnet AB。 * A：物理网络接口编号。 * B：逻辑链路编号。 例如"rmnet01"表示第1张sim卡网络中第2个网络切片承载。|
|Label|* normal：0，当前默认返回为0。 * low latency：1，保留值。 * high bandwidth：2，保留值。|

举例：

```
"netInfo": [{"netInterface": "wlan00", "label": 0},  {"netInterface": "rmnet00", "label": 1} ]
```

系统网络接口变化，系统会通告注册的应用，通告事件参见[网卡状态变化事件](#ZH-CN_TOPIC_0000001050825169__li52261075107)。

#### 将业务绑定到特定网口：bindToNetInterface(String netInterface)

将应用后续所有新建的Socket数据流绑定到netInterface指定的网口，netInterface需是[查询可用的网络接口](#ZH-CN_TOPIC_0000001050825169__section2691539563)中返回的系统可用网络接口。Response消息中携带的"retCode"只代表接口调用成功，系统侧处理成功会通过事件告知应用绑定网卡成功，参见[应用级别绑定网卡状态变化事件](#ZH-CN_TOPIC_0000001050825169__li222612712100)。应用应考虑预期时间内未收到系统通告的情况，系统侧建议3s没有收到通知，即可认为失败。

注意：

* 对于TCP连接：仅将系统通告绑定成功后创建的Socket以及已创建但未连接的Socket，绑定到netInterface指定的网口；对于已创建并且connect的Socket不会生效，会维持在原网口。

* 对于UDP连接：则对当前以及后续的Socket连接，立即生效，绑定到netInterface指定的网口。

#### 将Socket绑定到特定网口：bindToNetInterface (int fd, String netInterface)

将应用指定的Socket数据流绑定到netInterface指定的网口，netInterface需是[查询可用的网络接口](#ZH-CN_TOPIC_0000001050825169__section2691539563)中返回的系统可用网络接口。Response消息中携带的"retCode"只代表接口调用成功，系统侧处理成功会通过事件通知应用绑定网卡成功，参见[Socket级别绑定网卡状态变化事件](#ZH-CN_TOPIC_0000001050825169__li82267711106)。应用应考虑预期时间内未收到系统通告的情况，系统侧建议3s没有收到通知，即可认为失败。

系统会使用pid + fd + uid三者唯一确定一个应用内存空间的Socket。系统直接从LocalSocket Client的连接获取pid和uid，fd则由应用传递给系统。

对于TCP连接：应用需在该Socket发起connect之前调用此接口，方可生效；对于UDP连接，无此约束。

#### 去注册LinkTurbo Engine：unregisterApp()

LinkTurbo Engine仅保留Android默认网络接口，关闭其余网口，清空记录的业务规则，所有数据流绑回到Android默认网口。当应用在调整策略中发生丢失网络状态等异常情况，可以使用该接口将业务的网络行为进行重置。
