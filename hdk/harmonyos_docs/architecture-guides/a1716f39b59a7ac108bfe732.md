# 应用内字体大小适配

## 场景介绍

应用内字体大小适配是金融理财类应用的典型场景之一，如中老年及低视力用户将系统字体调至1.75倍及以上大字号后查看账户余额、基金净值与持仓收益，期望转账、理财等核心页面布局不错乱、文字不截断、按钮热区仍可准确点击。

本示例主要基于maxFontScale字体缩放阻断、@ObservedV2+AppStorageV2状态管理、Grid动态列数降级、Flex流式换行、List多列切换、WaterFlow瀑布流单双列切换、Row与Column动态布局等自适应布局技术，实现"跟随系统字号"与"应用内独立调节"双模式字体缩放，并保证钱包首页、基金详情、常用布局示例等典型业务页面在特大字号下内容完整显示、金额数字不溢出的效果。

## 实现思路

1. **全局状态架构设计。**

   通过[AppStorageV2](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/js-apis-statemanagement#appstoragev2)的connect方法创建全局共享的FontScaleState对象，所有V2组件通过同一key绑定，实现跨页面状态同步。FontScaleState使用[@ObservedV2](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/ts-state-management-observedv2)与[@Trace](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/ts-state-management-trace)装饰器，确保属性级深度观测和UI自动刷新。effectiveScale作为布局适配的唯一依据，system模式下等于系统字号，independent模式下等于用户选择的自定义倍率。

   ```ts
   // FontScaleManager.ets
   @ObservedV2
   export class FontScaleState {
     @Trace mode: FontMode = 'system';
     @Trace systemScale: number = 1.0;
     @Trace customScale: number = 1.0;
     @Trace effectiveScale: number = 1.0;
   }

   export class FontScaleManager {
     static getState(): FontScaleState {
       return AppStorageV2.connect(FontScaleState, FONT_SCALE_KEY, () => new FontScaleState())!;
     }

     private static recomputeEffective(): void {
       const state: FontScaleState = FontScaleManager.getState();
       if (state.mode === 'independent') {
         state.effectiveScale = state.customScale;
       } else {
         state.effectiveScale = state.systemScale;
       }
     }
   }
   ```

2. **两种字体缩放模式实现。**
   * **跟随系统模式** ：在configuration.json中配置fontSizeScale: "followSystem"开启系统字体跟随，并通过fontSizeMaxScale: "3.2"设置全局最大缩放倍数。在[UIAbility](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/js-apis-app-ability-ability)的onConfigurationUpdate回调中监听系统字号变化，实时同步到AppStorageV2驱动UI刷新。
   * **应用内独立调节模式** ：通过maxFontScale(1)阻断框架的系统缩放，再以fontSize(base * scale)手动放大，倍率可超出系统限制。用户在字体设置页选择倍率（1.0/1.15/1.3/1.5/1.8），通过FontScaleManager.setCustomScale()写入AppStorageV2，所有ScaledText组件即时响应。

     ```json
     // configuration.json
     {
       "configuration": {
         "fontSizeScale": "followSystem",
         "fontSizeMaxScale": "3.2"
       }
     }
     ```

     ```ts
     // ScaledText.ets --- independent模式下的核心逻辑
     private fontSizeValue(): number {
       if (this.fontState.mode === 'independent') {
         return this.base * this.cappedScale();
       }
       return this.base;
     }

     private maxScaleValue(): number {
       if (this.fontState.mode === 'independent') {
         return 1;
       }
       return this.capScale > 0 ? this.capScale : 3.2;
     }
     ```

3. **六大布局适配策略。**
   * **弹性布局**：禁止固定宽高，全部使用Column、Row等弹性容器配合layoutWeight(1)让内容自适应。
   * **文本控制**：通过ScaledText统一设置maxLines()和textOverflow()防止文本溢出。
   * **动态间距**：padding、margin不写固定值，通过Adapt.space(base, effScale)按字体系数动态计算，封顶1.6倍避免间距过大。
   * **热区适配**：可交互元素通过Adapt.touch(base)保证点击区域不低于44vp×44vp无障碍标准。
   * **布局切换** ：
     * Grid列数通过@Local columnsTemplate属性动态修改；
     * List列数通过.lanes(n)动态修改；
     * Flex流式换行自动折行；
     * 瀑布流在大字体下切换为单列Column自适应高度；
     * Row与Column方向切换使用[DynamicLayout](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/ts-container-dynamiclayout)的算法替换能力。
   * **组件限制** ：对于不希望无限放大的组件（如大数字），通过capScale单独限制最大缩放倍数。

     ```ts
     // DynamicInfoRow.ets---DynamicLayout算法切换
     @Local algorithm: LayoutAlgorithm = new RowLayoutAlgorithm();

     @Monitor('effScale')
     onScaleChange(): void {
       this.updateAlgorithm();
     }

     private updateAlgorithm(): void {
       if (Adapt.isLarge(this.effScale)) {
         this.algorithm = new ColumnLayoutAlgorithm({
           alignItems: HorizontalAlign.Start,
           space: LengthMetrics.vp(Adapt.space(4, this.effScale))
         });
       } else {
         this.algorithm = new RowLayoutAlgorithm({
           alignItems: VerticalAlign.Center
         });
       }
     }

     build() {
       DynamicLayout(this.algorithm) {
         ScaledText({ content: this.label })
         ScaledText({ content: this.value })
       }
     }
     ```

## 常见FAQ

Q：跟随系统模式下，应用内能否单独限制某个组件的字号上限？

A：可以。ScaledText组件提供了capScale参数，在system模式下通过maxFontScale(capScale)限制框架缩放上限，在independent模式下通过min(effScale, capScale)手动限制。两种模式均生效。

Q：DynamicLayout的Row与Column切换会导致子组件重建吗？

A：不会。DynamicLayout通过替换算法对象（RowLayoutAlgorithm↔ColumnLayoutAlgorithm）实现方向切换，子组件状态保持不变。这是DynamicLayout相比if/else条件渲染的核心优势。

Q：不使用API 24能否实现Row与Column方向切换？

A：可以，但只能用if/else条件渲染，切换时子组件会销毁重建。DynamicLayout的算法替换方式子组件不销毁，状态保持。
