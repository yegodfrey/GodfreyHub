# BLE蓝牙扫描连接与自动重连方案

## 场景介绍

* [BLE蓝牙扫描连接与自动重连](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/bluetooth-overview)是智能家居/穿戴健康类应用的高频场景，如手机连接智能门锁、手环等BLE外围设备时，需长期保持GATT连接稳定，断连后能快速自动恢复。
* 本示例基于@kit.ConnectivityKit（[access](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/js-apis-bluetooth-access)、[ble](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/js-apis-bluetooth-ble)）实现完整的BLE设备管理闭环，核心能力如下：

|模块|核心能力|解决的痛点|
|:-------|:-----------------------------------------------------------|:-------------------------------------|
|**扫描发现**|系统层ScanFilter过滤 + 应用层过滤（三级信息提取+ 仅MAC设备过滤 + 设备指纹去重 + 已保存设备排除）|设备名称缺失、回调频繁功耗浪费、扫描列表杂乱、MAC轮转导致重复展示|
|**固化**|addPersistentDeviceId 虚拟MAC固化到蓝牙子系统|蓝牙重启后虚拟MAC变更导致重连失败|
|**连接**|MAC有效性校验+超时机制+旧GattClient清理 + 断连三级分类|连接卡死无响应、GattClient资源泄漏、用户主动断开被自动重连反复接回|
|**重连**|3次重试 + 并发控制 + 冷启动/蓝牙重启/前台恢复多场景自动恢复|意外断连不恢复、历史设备丢失、多设备重连资源竞争|
|**后台保活**|bluetoothInteraction 长时任务 + 连接状态驱动启停|应用切后台被系统冻结导致GATT连接断开|

> 注意
>
> **关于经典蓝牙** ：本方案仅使用BLE扫描和BLE GATT连接。经典蓝牙（BR/EDR）与BLE是两套完全独立的协议栈，扫描地址不互通、连接方式不同。经典蓝牙设备无法通过BLE GATT连接，如需连接经典蓝牙设备（耳机、音箱等），需使用 socket.sppConnect 或 connection.connectAllowedProfiles，详见[如何通过BLE虚拟MAC建立经典蓝牙连接](https://developer.huawei.com/consumer/cn/doc/harmonyos-faqs/faqs-connectivity-15)。

## 实现思路

本方案围绕四个核心模块：**扫描发现→连接→固化→重连** 和两个独立模块：**日志埋点、后台保活（由蓝牙连接状态驱动）**，形成完整的BLE设备管理闭环。

1. **扫描发现方案**

   本模块解决 BLE 设备从发现到展示给用户全链路的问题，分为扫描和结果过滤两个子模块：

   ![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/58/v3/Wv_7i468Sfi3n3ilcLmIGQ/zh-cn_image_0000002757082317.png?HW-CC-KV=V1&HW-CC-Date=20260924T065100Z&HW-CC-Expire=31536000000&HW-CC-Sign=5060ABAC9EDB03E7C14E709D341B133BBAB4DB24E8EEC5D8EFA1E5F893C3F06C "点击放大")

   1. **扫描**

      **解决的痛点**：大量无关设备上报导致回调频繁、功耗浪费。

      **方案**：通过系统层过滤（ble.ScanFilter）在蓝牙芯片/协议栈层面过滤无关设备，减少回调量和功耗。

      **涉及接口**：
      * ble.startBLEScan(filters?, options?) --- BLE扫描启停，filters支持按设备名称、服务UUID等条件在系统层过滤。
      * ble.stopBLEScan() --- 停止BLE扫描。
      * ble.on('BLEDeviceFind') --- BLE扫描结果订阅。
      * ble.ScanOptions --- 扫描参数配置（interval扫描间隔、dutyMode扫描模式、matchMode匹配模式）。

      **流程图**：

      ![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/06/v3/jGydCJEETD-ZNeGlVc0JjA/zh-cn_image_0000002757082519.png?HW-CC-KV=V1&HW-CC-Date=20260924T065100Z&HW-CC-Expire=31536000000&HW-CC-Sign=B5C7A7F902756119E5DC179071D79B279B8B6A0CC387757D63DB865866BAB1C5 "点击放大")

      **生产环境优化建议**：

      |优化项|说明|
      |:-------------------|:--------------------------------------------------------------------------|
      |**系统层过滤优先**|目标设备已知且广播了 serviceUUID 时，务必设置 ScanFilter.serviceUuid，在芯片层过滤可大幅降低功耗和回调频率|
      |**两阶段扫描策略**|阶段一：LOW_LATENCY + interval:0 快速发现；阶段二：发现目标后切换 LOW_POWER + interval:100 省电监控|
      |**后台扫描必须 LOW_POWER**|长时间后台扫描用 LOW_LATENCY 会导致功耗和发热严重|
      |**已知设备重连定向扫描**|已知 MAC 时设置 ScanFilter.deviceId 定向扫描，几乎零冗余回调|
      |**多目标设备多 filter**|多个 ScanFilter 之间是 OR 关系，每个 filter 匹配一类设备|
      |**过滤器数量<=3**|过滤器资源为所有应用共享，单个应用超过3个可能导致开启扫描失败(2900009)|

      |参数|快速发现|省电监控|说明|
      |:----------------------|:------------------------|:-----------------------|:----------------------|
      |```screen interval ```|0|100+|单位ms，0为连续扫描|
      |```screen dutyMode ```|```screen LOW_LATENCY ```|```screen LOW_POWER ```|BALANCED 为折中|
      |```screen matchMode ```|```screen AGGRESSIVE ```|```screen AGGRESSIVE ```|允许误报减少漏扫；STICKY 更严格但易漏扫|

      **使用注意事项**：
      * **ScanFilter的使用** ：ScanFilter中单个filter的多个条件是 **AND 关系**。
      * **扫描前需检查蓝牙状态**：蓝牙未开启时调用startBLEScan会报错，需先通过 access.getState()确认为STATE_ON。
      * **扫描结束必须清理**：页面销毁时调用stopScan()注销BLEDeviceFind监听，否则会持续消耗资源。
      * **每次 startScan 前必须先 stopScan**：否则会叠加多个 BLEDeviceFind 回调，导致重复处理和内存泄漏。
      * **BLEDeviceFind 回调在主线程**：只做数据收集，避免耗时操作，UI更新用状态变量驱动。
      * **BLE与经典蓝牙地址不互通**：BLE扫描返回的虚拟MAC地址不能用于经典蓝牙连接（如socket.sppConnect），两种协议的地址体系完全独立。

      **核心代码**：

      ```ts
      startScan(filterName?: string, filterServiceUuid?: string): void {
        if (this.isScanning) return;
        const btState = this.checkBluetoothState();
        if (btState !== access.BluetoothState.STATE_ON) return;

        this.filterName = filterName ?? '';
        this.filterServiceUuid = filterServiceUuid ?? '';
        this.foundDevices = [];
        this.foundDeviceIds = new Set();
        this.foundDeviceFingerprints = new Set();
        this.deviceServiceUuids = new Map();
        this.deviceManufacturerData = new Map();
        this.isScanning = true;

        try {
          ble.on('BLEDeviceFind', (data: Array<ble.ScanResult>) => {
           // 信息提取 + 过滤逻辑详见"2、扫描结果过滤"
          });
          const scanOptions: ble.ScanOptions = { interval: 0,
            dutyMode: ble.ScanDuty.SCAN_MODE_LOW_LATENCY, matchMode: ble.MatchMode.MATCH_MODE_AGGRESSIVE };
          const filters: Array<ble.ScanFilter> = this.buildScanFilters(this.filterName, this.filterServiceUuid);
          ble.startBLEScan(filters.length > 0 ? filters : null, scanOptions);
        } catch (err) {
          this.isScanning = false;
        }
      }

      private buildScanFilters(filterName: string, filterServiceUuid: string): Array<ble.ScanFilter> {
        const filters: Array<ble.ScanFilter> = [];
        if (filterName.length > 0 && filterServiceUuid.length > 0) {
          const filter: ble.ScanFilter = { name: filterName, serviceUuid: filterServiceUuid };
          filters.push(filter);
        } else if (filterServiceUuid.length > 0) {
          const filter: ble.ScanFilter = { serviceUuid: filterServiceUuid };
          filters.push(filter);
        } else if (filterName.length > 0) {
          const filter: ble.ScanFilter = { name: filterName };
          filters.push(filter);
        }
        return filters;
      }
      ```

   2. **扫描结果过滤** 说明
      >
      > 特别注意事项：在生产环境中，如果业务明确可以通过系统层过滤已能够满足查找到设备，可以不用这个应用层的扫描结果过滤。

      **解决的痛点**：
      1. 系统层无法过滤到准确的扫描设备信息，需要应用层进行二次过滤扫描结果。
      2. BLE扫描经常获取不到完整设备名称。
      3. 仅广播MAC地址的设备混杂在列表中，影响用户体验。
      4. 虚拟MAC地址轮转导致同一物理设备以不同MAC地址重复出现在扫描列表。
      5. 已配对连接的设备因MAC地址变更仍出现在扫描列表中。

      **方案** ：通过**三级信息提取+仅MAC设备过滤+设备指纹去重+已保存设备排除**的应用层二次过滤，从原始扫描结果中提取完整设备信息并过滤，确保扫描结果列表干净无重复。

      **三级信息提取**（BLEDeviceFind回调中，按优先级逐级尝试补全设备信息）：
      * **第1级**：ScanResult.deviceName --- BLE扫描结果自带名称，部分设备会提供。
      * **第2级**：广播数据解析名称（AD Type 0x08/0x09） --- 从BLE广播包原始字节中提取名称。
      * **第3级**：广播数据解析厂商数据（AD Type 0xFF） --- 提取Manufacturer Specific Data，作为设备指纹的兜底特征。

      **过滤链路流程图：**（BLEDeviceFind回调中，信息提取后逐级过滤）：

      ![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/e3/v3/CBEUH6KkQ_qXfRvxyncOeg/zh-cn_image_0000002727686070.png?HW-CC-KV=V1&HW-CC-Date=20260924T065100Z&HW-CC-Expire=31536000000&HW-CC-Sign=B83E2C01C05D36BBA6E1A270F53E2BBFB32D679CB77E47529764481D88D91D6F "点击放大")

      **仅MAC设备过滤**：名称为空、无serviceUuids、无manufacturerData的设备（即仅广播了MAC地址），直接跳过不加入扫描列表。
      > 说明
      >
      > BLE扫描结果中大量设备仅广播了MAC地址（无名称、无服务UUID、无厂商数据），这类设备通常是未配置的蓝牙芯片、其他手机的BLE广播、信标(Beacon)等。统一过滤不展示，除非业务明确需要发现所有BLE设备。

      **设备指纹去重**（解决MAC地址轮转问题）：同一物理设备即使因RPA导致虚拟MAC地址变更，其广播的名称和服务UUID/厂商数据通常不变。通过设备指纹匹配，可在扫描列表中合并同一设备的不同MAC地址：

      |指纹生成条件|指纹组成|可靠性|
      |:--------------------------------|:-----------------------------------------|:--|
      |有 name + serviceUuids|```screen name + sorted(uuids) ```|高|
      |有 name + manufacturerData（无uuids）|```screen name + hex(manufacturerData) ```|中|
      |仅 name|不生成指纹，不做跨MAC合并|---|

      **指纹匹配流程**：
      * 扫描阶段：新MAC在已发现列表中未命中 → 用指纹二次匹配 → 命中则替换为最新MAC。
      * 已保存设备：新MAC未命中已保存列表 → 用指纹二次匹配 → 命中则跳过（不重复展示）。
      * 连接成功时：将设备的 serviceUuids 和 manufacturerData 一并持久化到 DeviceStore，供后续指纹匹配使用。
      * 使用新MAC地址连接更新后，需同步更新固化：deletePersistentDeviceId(旧MAC) + addPersistentDeviceId(新MAC)。

      **生产环境优化建议**：

      |优化项|说明|
      |:-------------|:------------------------------------------------------------------|
      |**指纹数据需持久化**|连接成功后 serviceUuids 和 manufacturerData 存入 DeviceStore，确保应用重启后指纹匹配仍有效|
      |**指纹匹配是尽力而为**|部分设备既不广播名称也不广播UUID/厂商数据，无法生成指纹，MAC轮转后会重复展示，需用户自行识别|
      |**应用层二次过滤兜底**|即使设置了系统层过滤，仍建议保留应用层过滤（仅MAC过滤、指纹去重），防止系统层过滤条件与设备实际广播不匹配导致遗漏|
      |**RSSI 弱信号过滤**|生产环境可在应用层增加 RSSI 过滤（如 rssi < -90 跳过， -20表示信号极强），极弱信号大概率连不上|

      **核心代码**：

      ```ts
      // === 三级信息提取（BLEDeviceFind回调中） ===
      ble.on('BLEDeviceFind', (data: Array<ble.ScanResult>) => {
        for (let i = 0; i < data.length; i++) {
          const result: ble.ScanResult = data[i];
          let deviceName: string = result.deviceName;                             // 第1级
          if (deviceName.length === 0) deviceName = this.parseDeviceNameFromData(result.data);// 第2级
          const manufacturerData: string = this.parseManufacturerData(result.data);  // 第3级
          const normalId: string = this.normalizeDeviceId(result.deviceId);
          if (result.serviceUuids !== undefined) this.deviceServiceUuids.set(normalId, result.serviceUuids);
          if (manufacturerData.length > 0) this.deviceManufacturerData.set(normalId, manufacturerData);
          this.addOrUpdateDevice(result.deviceId, deviceName, result.rssi, result.serviceUuids, manufacturerData);
        }
      });

      // === 仅MAC设备过滤 + 指纹去重 ===
      private addOrUpdateDevice(deviceId: string, deviceName: string, rssi: number,
        serviceUuids: Array<string> | undefined, manufacturerData: string): void {
      // 过滤1：仅广播MAC的设备直接跳过
        if (deviceName.length === 0 && (serviceUuids === undefined || serviceUuids.length === 0)
          && manufacturerData.length === 0) return;
        const fingerprint: string = this.buildDeviceFingerprint(deviceName, serviceUuids, manufacturerData);
      // 过滤2：已保存设备排除（MAC匹配 + 指纹匹配双重判断）
        if (this.isSavedDevice(deviceId, fingerprint)) return;
       // 过滤3：MAC去重 + 指纹去重
        const normalId: string = this.normalizeDeviceId(deviceId);
        let exists: boolean = false;
        for (let j = 0; j < this.foundDevices.length; j++) {
          if (this.normalizeDeviceId(this.foundDevices[j].deviceId) === normalId) {
            this.foundDevices[j].rssi = rssi;
            if (deviceName.length > 0 && this.foundDevices[j].deviceName.length === 0) {
              this.foundDevices[j].deviceName = deviceName;
            }
            exists = true;
            break;
          }
        }
        if (!exists && deviceName.length > 0) {
          if (fingerprint.length > 0 && this.foundDeviceFingerprints.has(fingerprint)) {
         // 指纹命中：同一物理设备MAC轮转，替换为最新MAC
            for (let j = 0; j < this.foundDevices.length; j++) {
              const existingFp: string = this.buildDeviceFingerprint(
                this.foundDevices[j].deviceName, this.foundDevices[j].serviceUuids,
                this.foundDevices[j].manufacturerData);
              if (existingFp === fingerprint) {
                this.foundDeviceIds.delete(this.normalizeDeviceId(this.foundDevices[j].deviceId));
                this.foundDevices[j] = BleDeviceInfo.of(deviceId, deviceName, rssi, serviceUuids, manufacturerData);
                this.foundDeviceIds.add(normalId);
                break;
              }
            }
          } else {
            if (!this.foundDeviceIds.has(normalId)) {
              this.foundDevices.push(BleDeviceInfo.of(deviceId, deviceName, rssi, serviceUuids, manufacturerData));
              this.foundDeviceIds.add(normalId);
              if (fingerprint.length > 0) this.foundDeviceFingerprints.add(fingerprint);
            }
          }
        }
      }

      // === 分层指纹生成 ===
      private buildDeviceFingerprint(deviceName: string, serviceUuids: Array<string> | undefined,
        manufacturerData: string): string {
        if (deviceName.length === 0) return '';
        if (serviceUuids !== undefined && serviceUuids.length > 0) {
          const sortedUuids: Array<string> = serviceUuids.slice();
          sortedUuids.sort();
          return deviceName.toUpperCase() + '|' + sortedUuids.join(',').toUpperCase();
        }
        if (manufacturerData.length > 0) {
          return deviceName.toUpperCase() + '|MFG:' + manufacturerData.toUpperCase();
        }
        return '';
      }
      ```

2. 连接 **解决的痛点**：连接卡死无响应、GattClient资源泄漏、用户主动断开后被自动重连反复接回。

   **方案**：基于GATT客户端实现设备连接，包含MAC地址有效性校验、旧连接清理、超时机制和断连原因三级分类，精准驱动后续行为。

   **涉及接口**：
   * ble.createGattClientDevice() --- 创建GATT客户端实例。
   * GattClientDevice.connect() --- 发起GATT连接。
   * GattClientDevice.disconnect() --- 断开GATT连接。
   * GattClientDevice.close() --- 关闭GATT客户端，释放资源。和连接的基础权限。
   * GattClientDevice.on('BLEConnectionStateChange') --- 订阅GATT连接状态变化。
   * GattClientDevice.getRssiValue() --- 读取远端设备RSSI信号强度。

   **流程图**：

   ![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/e9/v3/zP56F-9uS_aDdV-lwQqKlg/zh-cn_image_0000002757166735.png?HW-CC-KV=V1&HW-CC-Date=20260924T065100Z&HW-CC-Expire=31536000000&HW-CC-Sign=D41CB3926E48B2831BA667CEF396C9C547FB3B6274CFA6C6981DA7FE0AFC075E "点击放大")

   **使用注意事项**：
   * **连接前必须校验MAC有效性**：调用isValidRandomDeviceId，失效地址直接拒绝并标记重连失败，避免浪费15秒超时等待。
   * **连接前必须关闭旧GattClient**：同一设备重复调用createGattClientDevice会导致多个客户端实例，必须先disconnect+close旧实例再创建新的。
   * **disconnect和close的区别**：disconnect断开连接但不释放资源，close才是真正释放；必须先disconnect再close，且必须off('BLEConnectionStateChange')注销回调。
   * **超时定时器必须配对清理**：连接成功时 cancelConnectTimeout，否则定时器回调会误触。
   * **断连回调中的三级分类是关键**：必须根据isUserDisconnected和wasConnecting区分断连原因，否则用户主动断开也会触发自动重连。
   * **用户主动断开必须先标记再断开**：先markUserDisconnect持久化用户意图，再调用disconnect/close，确保断连回调中能识别。
   * **首次连接成功必须固化**：通过deviceStore.getDeviceName判断是否新设备，新设备调用saveDevice固化虚拟MAC地址。
   * **isValidRandomDeviceId在低API版本可能不存在**：需try-catch包裹，异常时降级为继续连接。

   **核心代码**：

   ```ts
   connectDevice(deviceId: string, deviceName: string): void {
     this.cancelReconnect(deviceId);
     this.cancelConnectTimeout(deviceId);
     this.deviceStore.clearUserDisconnect(deviceId);
     const isReconnect: boolean = this.reconnectingDevices.has(deviceId);
     this.reconnectFailedDevices.delete(deviceId);
     this.connectingDevices.add(deviceId);

    // MAC有效性校验：失效地址直接拒绝，避免无效等待
     try {
       const isValid: boolean = access.isValidRandomDeviceId(deviceId);
       if (!isValid) {
         this.connectingDevices.delete(deviceId);
         this.reconnectingDevices.delete(deviceId);
         this.reconnectFailedDevices.add(deviceId);
         this.notifyReconnectStateCallbacks(deviceId, false);
         this.notifyReconnectFailedCallbacks(deviceId, true);
         this.notifyConnectionCallbacks(deviceId, false);
         this.processReconnectQueue();
         return;
       }
     } catch (err) { /* 兼容API 16以下版本，异常时降级为继续连接 */ }

    // 关闭旧GattClient：防止重复创建导致资源泄漏
     const existingClient: ble.GattClientDevice | undefined = this.gattClients.get(deviceId);
     if (existingClient !== undefined) {
       existingClient.off('BLEConnectionStateChange');
       existingClient.disconnect();
       existingClient.close();
       this.gattClients.delete(deviceId);
     }

    // 创建GattClient，监听连接状态变化
     const gattClient: ble.GattClientDevice = ble.createGattClientDevice(deviceId);
     this.gattClients.set(deviceId, gattClient);
     gattClient.on('BLEConnectionStateChange', (state: ble.BLEConnectionChangeState) => {
       if (state.deviceId !== deviceId) return;
       if (state.state === constant.ProfileConnectionState.STATE_CONNECTED) {
         this.cancelConnectTimeout(state.deviceId);
         this.connectingDevices.delete(state.deviceId);
         this.reconnectRetries.delete(state.deviceId);
         const wasReconnecting: boolean = this.reconnectingDevices.has(state.deviceId);
         this.reconnectingDevices.delete(state.deviceId);
         this.reconnectFailedDevices.delete(state.deviceId);
         this.notifyReconnectStateCallbacks(state.deviceId, false);
         this.notifyReconnectFailedCallbacks(state.deviceId, false);
         this.connectedDevices.set(state.deviceId, deviceName);
       // 首次连接成功 → 固化虚拟MAC + 保存指纹数据
         const isNewDevice: boolean = this.deviceStore.getDeviceName(state.deviceId).length === 0;
         if (isNewDevice) {
           const normalId: string = this.normalizeDeviceId(state.deviceId);
           const cachedUuids: Array<string> | undefined = this.deviceServiceUuids.get(normalId);
           const cachedMfg: string | undefined = this.deviceManufacturerData.get(normalId);
           this.deviceStore.saveDevice(state.deviceId, deviceName, cachedUuids, cachedMfg !== undefined ? cachedMfg : '');
         }
         this.notifyConnectionCallbacks(state.deviceId, true);
         this.processReconnectQueue();
       } else if (state.state === constant.ProfileConnectionState.STATE_DISCONNECTED) {
         this.cancelConnectTimeout(state.deviceId);
         this.connectedDevices.delete(state.deviceId);
         this.gattClients.delete(state.deviceId);
         const wasConnecting: boolean = this.connectingDevices.has(state.deviceId);
         if (wasConnecting) this.connectingDevices.delete(state.deviceId);
         const isUserDisconnect: boolean = this.deviceStore.isUserDisconnected(state.deviceId);
         if (isUserDisconnect) {
       // 用户主动断开 → 不重连
           this.reconnectingDevices.delete(state.deviceId);
           this.notifyReconnectStateCallbacks(state.deviceId, false);
           this.notifyConnectionCallbacks(state.deviceId, false);
           this.deviceStore.clearUserDisconnect(state.deviceId);
           this.processReconnectQueue();
         } else if (wasConnecting) {
         // 连接中失败 → 重连
           this.notifyConnectionCallbacks(state.deviceId, false);
           if (this.reconnectingDevices.has(state.deviceId)) this.reconnectingDevices.delete(state.deviceId);
           this.scheduleReconnect(state.deviceId, deviceName, DisconnectReason.CONNECT_FAILED);
         } else {
       // 意外断连 → 重连
           this.notifyConnectionCallbacks(state.deviceId, false);
           if (this.reconnectingDevices.has(state.deviceId)) this.reconnectingDevices.delete(state.deviceId);
           this.scheduleReconnect(state.deviceId, deviceName, DisconnectReason.LINK_LOSS);
         }
       }
     });
     gattClient.connect();
     this.startConnectTimeout(deviceId);
   }
   ```

3. **固化**

   **解决的痛点**：HarmonyOS中BLE蓝牙扫描返回的是虚拟MAC地址。未固化时，地址会周期变更，导致重连直接失败。

   **方案**：通过 addPersistentDeviceId 将虚拟MAC地址持久化到蓝牙子系统映射表，使其长期有效。

   **涉及接口**：
   * access.addPersistentDeviceId() --- 将虚拟MAC地址固化到蓝牙子系统（API 16+）。
   * access.getPersistentDeviceIds() --- 获取已固化的虚拟MAC地址列表。
   * access.deletePersistentDeviceId() --- 删除已固化的虚拟MAC地址。
   * access.isValidRandomDeviceId() --- 校验虚拟MAC地址是否有效。

   **流程图**：

   ![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/5d/v3/op4YaW0VQ02nuylpx9Mj7Q/zh-cn_image_0000002727527562.png?HW-CC-KV=V1&HW-CC-Date=20260924T065100Z&HW-CC-Expire=31536000000&HW-CC-Sign=58B7FCB8837A61E64474E193C57002B4A6842CBC192A94217B2A3493FA5BB4A7 "点击放大")

   **使用注意事项**：
   * **固化的本质** ：HarmonyOS出于信息安全考虑，蓝牙扫描返回的deviceId为**虚拟MAC地址** 而非真实MAC地址，地址机制详见：[蓝牙服务开发概述 --- 设备地址类型](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/bluetooth-overview#蓝牙设备地址类型) ，固化是指蓝牙子系统内部维护虚拟地址与真实地址的映射关系，目的是**改善由于虚拟地址变化，导致应用使用不当而连接失败的场景。
   * **固化成功 ≠ 连接成功**：固化成功仅代表虚拟MAC能够映射到真实地址，不代表一定能连接成功（对端设备关机、拒绝连接等），需具体问题具体分析。
   * **固化后对端虚拟MAC仍会变**：固化后的设备虚拟地址还是会周期变化的，并非一直不变。
   * **固化MAC和真实地址的映射原则** ：同一中心设备（如：手机）里蓝牙子系统遵循**一个真实地址只映射一个虚拟地址**的原则。应用侧难以预知哪些虚拟MAC属于同一设备，建议通过扫描发现新虚拟MAC，结合服务UUID等特征识别是否为同一设备。
   * **必须在首次连接成功后立即固化**：错过时机则蓝牙重启后地址可能失效，后续重连必然失败。
   * **删除设备时必须解除固化**：否则系统层残留固化地址可能导致后续重连到已删除的设备。
   * **初始化时需合并已固化地址**：getPersistentDeviceIds读取系统层已固化的地址列表作为兜底数据，确保应用数据被清理后仍能识别历史设备。
   * **重连前校验地址有效性**：通过 isValidRandomDeviceId 校验，无效地址直接拒绝连接，避免无效等待。
   * **固化失败需记录日志**：addPersistentDeviceId 需记录失败事件，便于排查。

   **核心代码**：

   ```ts
   private persistDeviceId(deviceId: string): void {
     access.addPersistentDeviceId(deviceId).then(() => {
       hilog.info(DOMAIN, TAG, 'addPersistentDeviceId success: %{public}s', deviceId);
     }).catch((err: BusinessError) => {
       hilog.error(DOMAIN, TAG, 'addPersistentDeviceId failed: %{public}s, code: %{public}d',
         deviceId, err.code);
     });
   }

   private unpersistDeviceId(deviceId: string): void {
     access.deletePersistentDeviceId(deviceId).then(() => {
       hilog.info(DOMAIN, TAG, 'deletePersistentDeviceId success: %{public}s', deviceId);
     }).catch((err: BusinessError) => {
       hilog.error(DOMAIN, TAG, 'deletePersistentDeviceId failed: %{public}s, code: %{public}d',
         deviceId, err.code);
     });
   }

   private mergeWithPersistentIds(): void {
     const persistentIds: Array<string> = access.getPersistentDeviceIds();
     for (let i = 0; i < persistentIds.length; i++) {
       if (!this.deviceNames.has(persistentIds[i])) {
         this.deviceNames.set(persistentIds[i], ''); // 应用数据被清理后仍能识别历史设备
       }
     }
     this.saveDeviceNames();
   }
   ```

4. **重连**

   **解决的痛点**：意外断连不恢复、蓝牙重启/应用冷启动后历史设备丢失、多设备同时重连资源竞争。

   **需要自动重连的场景**：

   |场景|触发方式|说明|
   |:-----|:-----------------------|:---------------|
   |连接中失败|断连回调（wasConnecting=true）|GATT连接尚未建立就断开|
   |意外断连|断连回调（非用户主动、非连接中）|已连接设备因走远、设备休眠等断开|
   |连接超时|超时定时器回调|15秒内无连接响应|
   |应用冷启动|EntryAbility.onCreate|应用启动时历史设备未连接|
   |蓝牙重启|stateChange → STATE_ON|蓝牙关闭再开启后设备丢失|
   |应用前台恢复|onForeground|应用从后台回到前台时设备已断连|

   **重连方案包含三个子模块**：
   * **重试策略**：断连后延迟3秒发起重连，最多重试3次，耗尽后标记失败并提供手动重连入口。
   * **并发控制**：同时最多2个设备并发连接，超出上限的设备进入等待队列，连接成功/失败后自动处理队列。
   * **多场景恢复**：覆盖冷启动、蓝牙重启、应用前台恢复三种场景，自动遍历历史设备发起重连。

   **涉及接口**：
   * access.on('stateChange') --- 监听蓝牙开关状态变化，蓝牙开启时触发自动恢复，蓝牙关闭时清理所有重连状态。
   * access.getState() --- 查询蓝牙当前开关状态，重连前必须确认蓝牙已开启。
   * GattClientDevice.on('BLEConnectionStateChange') --- 监听GATT连接状态变化，断连时根据原因判断是否触发重连。
   * GattClientDevice.connect() --- 发起GATT连接，重连复用连接模块。

   **流程图：**

   ![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/99/v3/SLTLpzeESFiAfWgN_nfveA/zh-cn_image_0000002757087553.png?HW-CC-KV=V1&HW-CC-Date=20260924T065100Z&HW-CC-Expire=31536000000&HW-CC-Sign=29F0066A08F7FBE00DCF3F5776DDB7A5844CB1D1BCC01B1135A094C9A5EBE870 "点击放大")

   **使用注意事项**：
   * **断连回调中必须分类判断**：根据isUserDisconnected和wasConnecting区分断连原因，只有连接中失败和意外断连才触发重连，用户主动断开不能重连。
   * **冷启动重连必须在DeviceStore.init后**：tryQuickReconnect依赖getSavedDevices和getUserDisconnectedDevices，需等preferences加载完成。
   * **首次onForeground必须跳过**：冷启动时onCreate已调用tryQuickReconnect，onForeground首次触发时需跳过，否则会重复发起。
   * **蓝牙关闭时必须清理所有状态**：取消所有重连定时器、关闭所有GattClient、清空连接/重连集合，否则蓝牙重新开启后残留状态会干扰重连。
   * **重连定时器必须可取消**：设备连接成功或用户主动断开时需调用cancelReconnect清除定时器，避免误触。
   * **并发上限需根据设备能力调整**：MAX_CONCURRENT_CONNECTS=2是经验值，低端设备可能需要降为1。
   * **重连耗尽后需提供手动入口**：标记reconnectFailedDevices并在UI展示"手动重连"按钮，用户点击后retryReconnectFailed清除标记重新开始。

   **核心代码**：

   ```ts
   // 断连回调中判断是否需要重连
   gattClient.on('BLEConnectionStateChange', (state: ble.BLEConnectionChangeState) => {
     if (state.state === constant.ProfileConnectionState.STATE_DISCONNECTED) {
       this.cancelConnectTimeout(state.deviceId);
       this.connectedDevices.delete(state.deviceId);
       this.gattClients.delete(state.deviceId);
       const wasConnecting: boolean = this.connectingDevices.has(state.deviceId);
       if (wasConnecting) this.connectingDevices.delete(state.deviceId);
       const isUserDisconnect: boolean = this.deviceStore.isUserDisconnected(state.deviceId);
       if (isUserDisconnect) {
         this.reconnectingDevices.delete(state.deviceId);
         this.notifyReconnectStateCallbacks(state.deviceId, false);
         this.deviceStore.clearUserDisconnect(state.deviceId);
         this.processReconnectQueue();
       } else if (wasConnecting) {
         this.scheduleReconnect(state.deviceId, deviceName, DisconnectReason.CONNECT_FAILED);
       } else {
         this.scheduleReconnect(state.deviceId, deviceName, DisconnectReason.LINK_LOSS);
       }
     }
   });

   // 重连调度：重试上限 + 延迟 + 并发控制
   private scheduleReconnect(deviceId: string, deviceName: string, reason: string): void {
     const retries: number | undefined = this.reconnectRetries.get(deviceId);
     const currentRetries: number = retries !== undefined ? retries : 0;
     if (currentRetries >= RECONNECT_MAX_RETRIES) {
       this.reconnectRetries.delete(deviceId);
       this.reconnectingDevices.delete(deviceId);
       this.reconnectFailedDevices.add(deviceId);
       this.notifyReconnectStateCallbacks(deviceId, false);
       this.notifyReconnectFailedCallbacks(deviceId, true);
       this.processReconnectQueue();
       return;
     }
     this.reconnectRetries.set(deviceId, currentRetries + 1);
     this.reconnectingDevices.add(deviceId);
     this.notifyReconnectStateCallbacks(deviceId, true);
     this.cancelReconnect(deviceId);
     const timerId: number = setTimeout(() => {
       this.reconnectTimers.delete(deviceId);
       if (this.connectingDevices.size >= MAX_CONCURRENT_CONNECTS) {
         if (!this.reconnectQueue.includes(deviceId)) this.reconnectQueue.push(deviceId);
         return;
       }
       this.connectDevice(deviceId, deviceName);
     }, RECONNECT_DELAY_MS);
     this.reconnectTimers.set(deviceId, timerId);
   }

   // 多场景自动恢复：判断哪些历史设备需要重连
   tryQuickReconnect(): void {
     if (this.checkBluetoothState() !== access.BluetoothState.STATE_ON) return;
     const savedDevices = this.deviceStore.getSavedDevices();
     const userDisconnected: Set<string> = this.deviceStore.getUserDisconnectedDevices();
     let count = 0;
     for (let i = 0; i < savedDevices.length; i++) {
       if (userDisconnected.has(savedDevices[i].deviceId)) continue;
       if (this.connectedDevices.has(savedDevices[i].deviceId)) continue;
       if (this.connectingDevices.has(savedDevices[i].deviceId)) continue;
       this.reconnectingDevices.add(savedDevices[i].deviceId);
       this.reconnectRetries.set(savedDevices[i].deviceId, 1);
       this.notifyReconnectStateCallbacks(savedDevices[i].deviceId, true);
       count++;
     }
     if (count > 0) this.processReconnectQueue();
   }
   ```

5. **后台保活**

   **解决的痛点**：应用切后台后系统可能冻结进程，导致GATT连接断开且无法自动重连，直到用户手动切回前台才恢复。

   **方案**：当有设备处于连接状态时，申请bluetoothInteraction类型长时任务，防止应用进程被系统挂起；所有设备断开后自动停止长时任务。

   **涉及接口**：
   * bac[model](entry/src/main/ets/model)kgroundTaskManager.startBackgroundRunning() --- 申请长时任务。
   * backgroundTaskManager.stopBackgroundRunning() --- 停止长时任务。
   * wantAgent.getWantAgent() --- 构建通知栏点击拉起应用的 WantAgent。

   **启停策略**（连接状态驱动）：

   ![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/ce/v3/cLIwvyFZROq5pQOBFeDD5A/zh-cn_image_0000002727528282.png?HW-CC-KV=V1&HW-CC-Date=20260924T065100Z&HW-CC-Expire=31536000000&HW-CC-Sign=AC43568C6C7491C6CA312A33126776902CF6718EFD8601A9601A0333C12FE5C2 "点击放大")

   **使用注意事项**：
   * **蓝牙连接断开后需在1分钟内重连成功**，否则长时任务自动结束。本示例的自动重连机制（3次重试，每次间隔3秒）可确保在1分钟内完成重连尝试。
   * **必须在module.json5声明 backgroundModes**，否则startBackgroundRunning调用会失败。
   * **WantAgent配置**：通知栏点击后拉起应用，需正确填写bundleName和abilityName。
   * **长时任务与重连配合**：应用后台保活 + 自动重连双重保障，即使后台连接意外断开也能自动恢复。
   * **无连接时不要启动长时任务**：避免不必要的后台资源占用，只在有设备连接时才申请。

   **核心代码**：

   ```ts
   private startBackgroundRunning(): void {
     if (this.isBackgroundRunning) return;
     const bundleInfo: bundleManager.BundleInfo =
       bundleManager.getBundleInfoForSelfSync(bundleManager.BundleFlag.GET_BUNDLE_INFO_WITH_APPLICATION);
     const wantAgentInfo: wantAgent.WantAgentInfo = {
       wants: [{ bundleName: bundleInfo.name, abilityName: 'EntryAbility' }],
       actionType: wantAgent.OperationType.START_ABILITY,
       requestCode: 0,
       actionFlags: [wantAgent.WantAgentFlags.UPDATE_PRESENT_FLAG]
     };
     wantAgent.getWantAgent(wantAgentInfo).then((wantAgentObj: WantAgent) => {
       backgroundTaskManager.startBackgroundRunning(this.appContext,
         backgroundTaskManager.BackgroundMode.BLUETOOTH_INTERACTION, wantAgentObj).then(() => {
         this.isBackgroundRunning = true;
       }).catch((error: BusinessError) => {
         hilog.error(DOMAIN, TAG, 'startBackgroundRunning failed, code: %{public}d', error.code);
       });
     });
   }

   private stopBackgroundRunning(): void {
     if (!this.isBackgroundRunning) return;
     backgroundTaskManager.stopBackgroundRunning(this.appContext).then(() => {
       this.isBackgroundRunning = false;
     }).catch((err: BusinessError) => {
       hilog.error(DOMAIN, TAG, 'stopBackgroundRunning failed, code: %{public}d', err.code);
     });
   }

   private updateBackgroundRunningState(): void {
     if (this.connectedDevices.size > 0) {
       this.startBackgroundRunning();
     } else {
       this.stopBackgroundRunning();
     }
   }
   ```
