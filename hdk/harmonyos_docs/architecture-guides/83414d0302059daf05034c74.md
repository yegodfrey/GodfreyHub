# 应用内多语言设置不生效

## 场景介绍

应用内多语言设置不生效是金融理财类应用的高频使用场景之一，如用户将系统语言切换为英文后，期望整个应用（包括ArkUI页面和内嵌H5页面）均显示英文，而非"半中半英"。

本示例基于[I18n国际化](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/js-apis-i18n)能力，用一个ArkUI+H5混合的活动页还原这一场景，并通过[资源分类与访问](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/resource-categories-and-access)完成文本资源化，实现ArkUI与H5混合页面的全自动多语言切换效果。整套流程由一个可复用的harmonyos-i18nskill驱动，能推广到任意ArkTS项目。

## 实现思路

1. **ArkUI文本：TEXT_KEYS+rawfile翻译数据文件。**

   skill运行后，源码中不再出现任何硬编码的中文或英文翻译。翻译内容存储在rawfile数据文件中（zh_strings.json和en_strings.json），由skill从资源文件自动生成，与代码完全解耦。

   loadRawFile()方法通过resourceManager.getRawFileContent()运行时加载rawfile，util.TextDecoder解码后存入@State。t(key)按this.lang从对应语言map中取值。切换语言时只改this.lang，@State自动触发UI刷新。新增语言只需添加一个rawfile文件，源码零改动。

   ```ts
   // MixedPage.ets
   import { util } from '@kit.ArkTS';

   // 纯key列表，不含翻译。翻译在rawfile/zh_strings.json和en_strings.json中。
   const TEXT_KEYS: string[] = [
     // 共17个key，全部由skill自动提取生成
     'mixed_title',
     'mixed_btn_to_en',
    // ...
   ];

   @State private textsZh: Record<string, string> = {};
   @State private textsEn: Record<string, string> = {};

   async aboutToAppear(): Promise<void> {
     this.textsZh = await this.loadRawFile('zh_strings.json');
     this.textsEn = await this.loadRawFile('en_strings.json');
   }

   private async loadRawFile(fileName: string): Promise<Record<string, string>> {
     const ctx: Context | undefined = this.getUIContext().getHostContext();
     if (ctx === undefined) {
       hilog.error(DOMAIN, 'MixedPage', 'getHostContext returned undefined');
       return {};
     }
     const rm = ctx.resourceManager;
     try {
       const rawData: Uint8Array = await rm.getRawFileContent(fileName);
       const textDecoder: util.TextDecoder = new util.TextDecoder('utf-8');
       const jsonStr: string = textDecoder.decodeToString(rawData, { stream: false });
       return JSON.parse(jsonStr) as Record<string, string>;
     } catch (e) {
       const err: BusinessError = e as BusinessError;
       hilog.error(DOMAIN, 'MixedPage', 'load %{public}s failed: %{public}s', fileName, err.message);
       return {};
     }
   }

   private t(key: string): string {
     const map: Record<string, string> = this.lang === 'en' ? this.textsEn : this.textsZh;
     return map[key] ?? key;
   }
   ```

2. **H5文本：data-i18n标记+JS对照表。**

   H5页面（mixed_page.html）给每个可翻译节点打上data-i18n="key"属性，内部维护一份I18N对照表。setLang(lang)函数遍历所有[data-i18n]节点，按key和语言查表替换textContent。这套机制独立于ArkUI侧，H5自己也能切换语言。

   ```ts
   // mixed_page.html
   const I18N = {
     h5Tag:     { zh: '活动',                                en: 'EVENT' },
     h5Title:   { zh: '限时优惠活动',                         en: 'Flash Sale' },
    // ...
   };

   let currentLang = 'zh';

   // 切换语言：遍历所有[data-i18n]节点，按key+lang设置文本
   function setLang(lang) {
     currentLang = lang;
     let nodes = document.querySelectorAll('[data-i18n]');
     for (let i = 0; i < nodes.length; i++) {
       let key = nodes[i].getAttribute('data-i18n');
       let entry = I18N[key];
       if (entry) {
         nodes[i].textContent = entry[lang] || entry.zh;
       }
     }
   }
   ```

3. **跨端locale桥接。**

   ArkUI侧通过Web组件的WebviewController.runJavaScript("setLang('en')")调用H5暴露的全局函数，把当前语言推过去。H5收到后执行自身的语言切换。onPageEnd回调里也会同步一次当前语言，确保H5加载完成后立即与ArkUI保持一致。

   ```ts
   // MixedPage.ets
   private notifyH5(): void {
     if (!this.isH5Ready) {
       return;
     }
     try {
       this.webController.runJavaScript(`setLang('${this.lang}')`);
     } catch (e) {
       const err: BusinessError = e as BusinessError;
       hilog.error(DOMAIN, 'MixedPage', 'runJavaScript failed: %{public}s', err.message);
     }
   }
   ```

4. **跟随系统语言能力接入。**

   页面接入了I18n模块（@ohos.i18n），提供"跟随系统语言"能力。点击该按钮后，调用I18n.System.getSystemLanguage()读取系统当前语言（形如zh-Hans-CN），按前缀判断中文或英文，同步到页面状态并通知H5。同时调用I18n.System.getAppPreferredLanguage()读取应用偏好语言，一并展示在转换报告弹窗中。

   ```ts
   // MixedPage.ets
   import I18n from '@ohos.i18n';

   private followSystem(): void {
     let sysLang: string = '';
     let appLang: string = '';
     try {
       sysLang = I18n.System.getSystemLanguage();
       appLang = I18n.System.getAppPreferredLanguage();
     } catch (e) {
       const err: BusinessError = e as BusinessError;
       hilog.error(DOMAIN, 'MixedPage', 'i18n API failed: %{public}s', err.message);
     }
     if (sysLang.startsWith('zh')) {
       this.lang = 'zh';
     } else {
       this.lang = 'en';
     }
     this.notifyH5();
     this.showReport(sysLang, appLang);
   }
   ```

5. **转换结果报告。**

   点"一键转英文"或"跟随系统语言"后，弹窗展示转换报告，包含ArkUI提取条数、H5提取条数、处理方式、locale桥接方式和零遗漏状态。当通过"跟随系统语言"触发时，额外展示系统语言和应用偏好语言。报告让转换结果可验证、可追溯，而不是一个黑盒。
6. **skill的四步流程。**

   harmonyos-i18nskill把上述经验固化成可推广的流程：
   1. **AST扫描提取**------用TypeScript Compiler API解析.ets语法树，定位文本展示位的字符串字面量，禁止用正则做主提取。
   2. **生成key+翻译**------按{页面}_{语义}命名，去重，模板串拆成%d/%s占位符。
   3. **写资源文件+翻译数据文件**------base放中文值，en_US放英文值（资源格式，供$r()使用）；同时自动生成rawfile/zh_strings.json和en_strings.json（键值格式，供运行时加载做应用内手动切换）。
   4. **替换源码**------Text('确定')变Text($r('app.string.confirm'))，变量赋值改Resource类型，ForEach数据源改Resource[]。

   skill还规定了闭环验证：静态复扫确认代码区零中文残留，UiTest运行时遍历所有页面检测渲染出来的中文字符（英文locale下任何中文都是漏译），H5/三方框架按locale桥接规范单独处理。

## 常见FAQ

Q：为什么同时维护官方资源文件（string.json）和rawfile两套数据？

A：架构上采用双层数据源设计：

* 官方资源文件（base/element/string.json、en_US/element/string.json）服务于"跟随系统语言"模式，由resourceManager按系统locale自动解析。
* rawfile数据文件（rawfile/zh_strings.json、en_strings.json）服务于"手动切换"模式，由skill从上述资源文件自动生成，供应用内通过fs.readTextSync读取，实现不依赖系统locale的语言切换。两者共存的原因是：resourceManager.getStringByNameSync()始终按系统locale返回对应资源，无法在应用层指定语言环境。因此，若实现"手动切换"能力，必须引入独立于系统locale的数据源。rawfile正是为此而设------翻译与代码完全解耦，新增语言时只需添加一个rawfile的JSON文件，源码零改动。

Q：H5页面的中文怎么做到不遗漏？

A：H5内部有独立的[data-i18n]标记体系和I18N对照表，用setLang()统一遍历切换。ArkUI侧通过runJavaScript桥接locale。H5自身也需要用i18n lint工具（如i18n-ally）扫描硬编码。跨端的关键是统一语言源------ArkUI是唯一源头，H5只响应。

Q：推广到其他项目要改什么？

A：复制skills/harmonyos-i18n/SKILL.md到目标项目，让AI按skill四步流程处理entry/src/main/ets/下所有.ets文件，产出资源化代码、base/en_US的string.json和提取报告。H5页面按第4.3节locale桥接规范单独处理。
