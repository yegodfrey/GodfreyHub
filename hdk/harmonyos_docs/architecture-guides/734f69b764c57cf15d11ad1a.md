# 适老化动态布局切换

## 场景介绍

适老化动态布局切换是金融理财类应用的高频使用场景之一，如用户在光线较暗或视力不便的环境下，需要一键切换到大字体、大图标的关怀版界面，以便清晰浏览账户资产和操作常用功能。

本示例主要基于[DynamicLayout](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/arkts-layout-development-dynamiclayout)实现常规版与关怀版一键切换功能，核心思路为"同一套子组件+不同布局算法=两种视觉体验"，开发者无需维护两套UX代码，只需替换算法实例即可完成布局切换。

开发者对现有常规版项目进行关怀版适配，可尝试按照下述方法进行操作：

* **第一步**：将现有内容区域包裹在DynamicLayout中，绑定@Local mainLayout算法变量。
* **第二步**：对组件分类。共享组件用instanceof三元表达式自适应尺寸；常规版专属组件用if (!(algorithm instanceof ColumnLayoutAlgorithm))包裹；关怀版专属组件用if (algorithm instanceof ColumnLayoutAlgorithm)包裹。
* **第三步**：添加切换按钮，在animateTo中替换算法实例完成切换。

## 实现思路

1. **用算法实例本身作为状态，消除额外布尔变量。**

   传统方案需要@State isCareMode: boolean来驱动所有if-else判断。本方案用@Local mainLayout: LayoutAlgorithm直接作为状态，算法实例本身即标识当前模式，无需额外状态变量。

   ```ts
   // Index.ets
   @Local mainLayout: LayoutAlgorithm = new GridLayoutAlgorithm({
     columnsTemplate: '1fr',
     rowsGap: LengthMetrics.vp(10)
   });
   ```

   常规版使用GridLayoutAlgorithm（单列，紧凑间距），关怀版使用ColumnLayoutAlgorithm（宽松间距）。通过instanceof判断当前算法类型，即可区分两种模式。
2. **用DynamicLayout包裹现有组件树，切换算法即切换布局。**

   将现有常规版的所有子组件放入DynamicLayout中，算法代表布局方式。切换时通过animateTo替换算法实例，子组件树保持不变，但布局方式发生变化。

   ```ts
   // Index.ets
   DynamicLayout(this.mainLayout) {
   // 共享组件：两种模式都渲染
     this.SharedHeader()
     this.SharedMainFunctions()

    // 常规版专属：营销内容
     if (!(this.mainLayout instanceof ColumnLayoutAlgorithm)) {
       this.RegularPromo()
     }

    // 关怀版专属：常用工具
     if (this.mainLayout instanceof ColumnLayoutAlgorithm) {
       this.CareToolList()
     }
   }
   ```

3. **共享组件内部用instanceof自适应字号和尺寸。**

   两种模式共享的组件（如头部、功能区），内部通过this.mainLayout instanceof ColumnLayoutAlgorithm判断来动态调整字号、间距、图标尺寸，无需为关怀版创建独立的组件副本。

   ```ts
   // Index.ets-SharedHeader内部
   Text($r('app.string.login_register'))
     .fontSize(this.mainLayout instanceof ColumnLayoutAlgorithm ? 26 : 18)
     .margin({ top: this.mainLayout instanceof ColumnLayoutAlgorithm ? 18 : 10 })
   ```

4. **用animateTo包裹算法切换，实现平滑过渡。**

   算法切换通过animateTo触发，结合springMotion弹性曲线，布局变化自然流畅，不会出现突兀的跳变。

   ```ts
   // Index.ets
   private toggleMode(): void {
     const uiContext: UIContext | undefined = this.getUIContext();
     if (uiContext !== undefined) {
       uiContext.animateTo({ duration: 380, curve: curves.springMotion() }, () => {
         if (this.mainLayout instanceof ColumnLayoutAlgorithm) {
          // 切换到常规版：GridLayoutAlgorithm单列，紧凑间距
           this.mainLayout = new GridLayoutAlgorithm({
             columnsTemplate: '1fr',
             rowsGap: LengthMetrics.vp(10)
           });
         } else {
          // 切换到关怀版：ColumnLayoutAlgorithm，宽松间距
           this.mainLayout = new ColumnLayoutAlgorithm({
             space: LengthMetrics.vp(18)
           });
         }
       });
     }
   }
   ```

5. **嵌套DynamicLayout实现子区域网格布局。**

   关怀版的功能区使用嵌套的DynamicLayout+GridLayoutAlgorithm实现2x2大卡片网格，而常规版使用Row横向排列。这种嵌套使用方式让每个子区域可以独立选择最合适的布局算法。

   ```ts
   // Index.ets-SharedMainFunctions关怀版分支
   DynamicLayout(new GridLayoutAlgorithm({
     columnsTemplate: '1fr 1fr',
     columnsGap: LengthMetrics.vp(16),
     rowsGap: LengthMetrics.vp(20)
   })) {
     ForEach(this.mainFuncs.slice(0, 4), (item: FuncItem, idx: number) => {
       Column() { /* 大卡片 */ }
     })
   }
   ```

## 常见FAQ

Q：常规版和关怀版共用的组件，字号如何自适应？

A：直接在组件属性的三元表达式中使用this.mainLayout instanceof ColumnLayoutAlgorithm?大号:小号，无需创建两套组件。

Q：如果关怀版需要完全不同的内容区块怎么办？

A：在DynamicLayout内部使用if (this.mainLayout instanceof ColumnLayoutAlgorithm)条件渲染关怀版专属区块，用if (!(this.mainLayout instanceof ColumnLayoutAlgorithm))条件渲染常规版专属区块。两种模式的区块互斥，但共享数据和组件结构。

Q：切换布局后子组件状态会丢失吗？

A：不会。DynamicLayout的核心特性就是在切换算法时保持子组件状态，这是其与普通条件渲染的本质区别。

Q：能否在嵌套的DynamicLayout中再嵌套一层？

A：可以。本示例中关怀版的功能区就在外层DynamicLayout内部嵌套了另一个DynamicLayout+GridLayoutAlgorithm来实现2x2网格。
