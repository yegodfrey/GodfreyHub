本章节指导开发者完成Push基础能力开发中的客户端开发，通过本开发指导的学习能够帮助开发者快速掌握客户端开发所需的知识技能，快速体验华为Push服务。基础能力客户端开发主要包括如下3个功能点：

1、开发者集成HMS SDK后申请Push Token，请参考申请Push Token章节

2、开发者App客户端接收服务端推送的Push透传消息，请参考接收Push消息章节

3、是否允许NC（Notification Center）显示通知栏消息，请参考是否接收通知栏消息章节

# 1\. 申请Push Token

## 1.1 场景介绍

每个设备上的每个应用的Token都是唯一存在的，客户端调用 [HmsInstanceId.getToken](https://developer.huawei.com/consumer/cn/doc/development/HMS-3-References/push-HmsInstanceId#getToken) 接口向服务端请求应用的唯一标识：Push Token，开发者的服务器根据这个Token发送推送消息。开发者可以将Token上报到自己的应用服务器维护这些已申请的Token列表，然后调用Push服务器的推送消息接口，根据Token批量推送消息，服务器发送消息请参考[Push基础能力服务端开发指导](https://developer.huawei.com/consumer/cn/doc/development/HMS-3-Guides/push-basic-server)章节。某些情况下getToken返回为空，请开发者参考 [HmsMessageService.onNewToken](https://developer.huawei.com/consumer/cn/doc/development/HMS-3-References/HmsMessageService#onNewToken) 接口说明，通过onNewToken接口接收Token值。

Token会在包括但不限于下述场景中发生变化：

1、APP卸载重装；

2、APP调用注销Token接口，；

3、用户恢复出厂设置；

4、清除应用数据；

说明：

HUAWEI Push为了提升安全性，在2018/3/10 升级了Token生成规则和变更机制，增加了Token格式2.0，在新的设备上会使用新格式的Token：Token长度为不定长，当前为130字节，包含字符0-9、a-z、A-Z及特殊字符-和_；

建议的最佳使用实践：

1、应用不要固定判断PUSH Token长度，因为后续长度可变。

2、PUSH Token业务要定期更新（建议应用每次启动的时候都获取Token，如果发现和上次取到的不同，则上报到自己的服务器）。

3、请勿用Token跟踪标记用户。

## 1.2 注意事项  


1、getToken接口只有在AppGallery Connect平台[开通服务](https://developer.huawei.com/consumer/cn/doc/distribution/app/agc-enable_service)后申请token才会返回成功。

2、EMUI10.0及以上版本的华为设备上，getToken接口直接返回token。如果当次调用失败PUSH会自动重试申请，成功后则以onNewToken接口返回。

3、**低于****EMUI10.0****的设备****上，getToken接口如果返回为空，结果后续以onNewToken接口返回** 。

4、缓存重试的申请token以及服务端识别token过期后刷新token，以onNewToken接口返回。

5、集成HMS SDK最新版本需要满足HMS Core（APK）的版本不低于3.0.0。如果低于3.0.0版本，当应用有前台界面时HMS SDK会提示用户升级HMS Core（APK）为最新版本，此时 [HmsInstanceId.getInstance](https://developer.huawei.com/consumer/cn/doc/development/HMS-3-References/push-HmsInstanceId#getInstance) 的入参必须传入Activity类实例；当应用是后台应用时，如果开发者不想弹出引导升级的页面时，可以传入非Activity类型的Context类实例。

## 1.3 开发步骤

建议在APP启动后首个activity的onCreate方法调用getToken方法。

1、调用 getToken 方法获取Token
    
    
    复制
      
        1. private void getToken() {
        2.     new Thread() {
        3.         @Override
        4.         public void run() {
        5.             try {
        6.                 // read from agconnect-services.json
        7.                 String appId = AGConnectServicesConfig.fromContext(this).getString("client/app_id");
        8.                 String token = HmsInstanceId.getInstance(this).getToken(appId, "HCM");
        9.                 Log.i(TAG, "get token:" + token);
        10.                 if(!TextUtils.isEmpty(token)) {
        11.                     sendRegTokenToServer(token);
        12.                 }
        13.             } catch (ApiException e) {
        14.                 Log.e(TAG, "get token failed, " + e);
        15.             }
        16.         }
        17.     }.start();
        18. }
        19. private void sendRegTokenToServer(String token) {
        20.     Log.i(TAG, "sending token to server. token:" + token);
        21. }
    
    

2、Token发生变化时或者**EMUI****版本低于10.0** 以 onNewToken 方法返回
    
    
    复制
      
        1. // This method callback must be completed in 10 seconds. Otherwise, you need to start a new Job for callback processing.
        2. @Override
        3. public void onNewToken(String token) {
        4.     Log.i(TAG, "received refresh token:" + token);
        5.     // send the token to your app server.
        6.     if (!TextUtils.isEmpty(token)) {
        7.         refreshedTokenToServer(token);
        8.     }
        9. }
        10. private void refreshedTokenToServer(String token) {
        11.     Log.i(TAG, "sending token to server. token:" + token);
        12. }
    
    

# 2\. 注销Push Token

## 2.1 场景介绍

开发者如果不希望应用接收Push消息，可以调用 [HmsInstanceId.deleteToken](https://developer.huawei.com/consumer/cn/doc/development/HMS-3-References/push-HmsInstanceId#deleteToken) 接口注销token，注销成功后，客户端就不会再接收到Push消息，包括订阅的主题消息。

但是建议开发者不要依赖 deleteToken 接口，如果开发者要实现不接收Push消息，可以自行将开发者应用服务器端的Token状态设置为失效状态，并且在推送消息时判断Token失效就不进行推送，避免频繁的向服务器申请token。

注意：

HMS Core（APK）的版本不低于3.0.0。

## 2.2 开发步骤

调用注销Token接口。
    
    
    复制
      
        1. new Thread() {
        2.     @Override
        3.     public void run() {
        4.         try {
        5.             // read from agconnect-services.json
        6.             String appId = AGConnectServicesConfig.fromContext(this).getString("client/app_id");
        7.             HmsInstanceId.getInstance(this).deleteToken(appId, "HCM");
        8.             Log.i(TAG, "deleteToken success.");
        9.         } catch (ApiException e) {
        10.             Log.e(TAG, "deleteToken failed." + e);
        11.         }
        12.     }
        13. }.start();

# 4\. 设置是否显示通知栏消息

## 4.1 场景介绍

通知消息是由系统直接在通知中心下拉列表呈现的即时消息。开发者如果想控制应用是否允许显示通知栏消息，可以调用 [HmsMessaging.turnOnPush](https://developer.huawei.com/consumer/cn/doc/development/HMS-3-References/HmsMessaging#turnOnPush) 或者 [HmsMessaging.turnOffPush](https://developer.huawei.com/consumer/cn/doc/development/HMS-3-References/HmsMessaging#turnOffPush)接口。如果开发者不调用此接口，系统默认是允许显示通知栏消息。

注意：

1、该功能仅在EMUI版本不低于EMUI 5.1的设备上支持。

2、集成HMS SDK最新版本需要满足HMS Core（APK）的版本不低于3.0.0。如果低于3.0.0版本，当应用有前台界面时HMS SDK会提示用户升级HMS Core（APK）为最新版本，此时[HmsMessaging.getInstance](https://developer.huawei.com/consumer/cn/doc/development/HMS-3-References/HmsMessaging#getInstance)的入参必须传入Activity类实例；当应用是后台应用时，如果开发者不想弹出引导升级的页面时，可以传入非Activity类型的Context类实例。

## 4.2 开发步骤

设置接收Push通知栏消息调用示例。
    
    
    复制
      
        1. HmsMessaging.getInstance(context).turnOnPush().addOnCompleteListener(new OnCompleteListener<Void>() {
        2.     @Override
        3.     public void onComplete(Task<Void> task) {
        4.         if (task.isSuccessful()) {
        5.             Log.i(TAG, "turnOnPush Complete");
        6.         } else {
        7.             Log.e(TAG, "turnOnPush failed: ret=" + task.getException().getMessage());
        8.         }
        9.     }
        10. });
    
    

# 5\. 点击通知消息

关于通知消息，开发者可以自定义点击消息的行为，包括：打开App首页、打开特定URL、打开自定义富媒体消息、打开自定义App页面。其中打开App首页与自定义App页面需要开发者端云协同开发来完成，下面我们讲下如何实现这两种行为并从服务端接收数据。

注意：

点击动作触发打开应用首页或者自定义App页面，都是通过跨应用启动Activity的方式来实现，需要保证要拉起的目标Activity的exported属性为true，即目标Activity要对外界公开，并且无权限保护，这样才能启动成功。

  


## 5.1 打开自定义App页面

跨应用启动Activity必须使用显式intent方式，通过intent可以携带额外的数据给客户端App。主要通过如下4步来完成。

在AndroidStudio工程中参照如下代码生成intent。

1、intent参数生成
    
    
    复制
      
        1. Intent intent = new Intent(Intent.ACTION_VIEW);
        2. // Scheme协议（pushscheme://com.huawei.codelabpush/deeplink?）需要开发者自定义
        3. intent.setData(Uri.parse("pushscheme://com.huawei.codelabpush/deeplink?"));
        4. // 往intent中添加参数，用户可以根据自己的需求进行添加参数：
        5. intent.putExtra("name", "abc");
        6. intent.putExtra("age", 180);
        7. // 必须带上该Flag
        8. intent.addFlags(Intent.FLAG_ACTIVITY_CLEAR_TOP);
        9. String intentUri = intent.toUri(Intent.URI_INTENT_SCHEME);
        10. // 打印出的intentUri值就是设置到推送消息中intent字段的值
        11. Log.d("intentUri", intentUri);
    
    

其中intent.addFlags(Intent.FLAG_ACTIVITY_CLEAR_TOP);是应用必须添加的选项，如果不添加该选项有可能会显示重复的消息，其他为应用自己的配置项。生成的intentUri字符串即为intent参数需要填写的值。

**开发者传参有两种方法** ：

方法1：参数之间用“&”相连，例如
    
    
    复制
      
        1. intent.setData(Uri.parse("pushscheme://com.huawei.codelabpush/deeplink?name=abc&age=180"));
    
    

其中参数name=abc与age=180两个参数之间用“&”相连。

方法2：intent直接添加参数：
    
    
    复制
      
        1. intent.setData(Uri.parse("pushscheme://com.huawei.codelabpush/deeplink?"));
        2. intent.putExtra("name", "abc");
        3. intent.putExtra("age", 180);
    
    

2、服务端消息体中指定intent值

服务端如何发送消息请参考Push基础能力服务端开发指导。

消息体样例：
    
    
    复制
      
        1. {
        2.     "message": {
        3.         "notification": {
        4.             "title": "message title",
        5.             "body": "message body"
        6.         },
        7.         "android": {
        8.             "notification": {
        9.                 "click_action": {
        10.                     "type": 1,
        11.                     "intent": "intent://com.huawei.codelabpush/deeplink?#Intent;scheme=pushscheme;launchFlags=0x4000000;i.age=180;S.name=abc;end"
        12.                 }
        13.             }
        14.         },
        15.         "token": [
        16.             "pushtoken1"
        17.         ]
        18.     }
        19. }
    
    

3、客户端AndroidManifest.xml文件注册待启动的Activity类

参照如下配置注册自定义的Activity，其中host、path、scheme需与步骤1中协议的配置相对应，否则不能跳转到指定的界面。
    
    
    复制
      
        1. <activity android:name=".DeeplinkActivity">
        2.     <intent-filter>
        3.         <action android:name="android.intent.action.VIEW" />
        4.         <category android:name="android.intent.category.DEFAULT" />
        5.         <category android:name="android.intent.category.BROWSABLE" />
        6.         <data
        7.             android:host="com.huawei.codelabpush"
        8.             android:path="/deeplink"
        9.             android:scheme="pushscheme" />
        10.     </intent-filter>
        11. </activity>
    
    

4、在自定义Activity类中接收数据
    
    
    复制
      
        1. public class DeeplinkActivity extends Activity {
        2.     @Override
        3.     public void onCreate(Bundle savedInstanceState) {
        4.         super.onCreate(savedInstanceState);
        5.         setContentView(R.layout.activity_deeplink);
        6.         Intent intent = getIntent();
        7.         if (null != intent) {
        8.             // 方法1设置的数据通过如下方式获取
        9.             String name1 = intent.getData().getQueryParameter("name");
        10.             int age1 = Integer.parseInt(intent.getData().getQueryParameter("age"));
        11.             // 方法2设置的数据通过如下方式获取
        12.             String name2 = intent.getStringExtra("name");
        13.             int age2 = intent.getIntExtra("age", -1); 
        14.             Toast.makeText(this, "name " + name1 + ",age " + age1, Toast.LENGTH_SHORT).show();
        15.         }
        16.     }
        17. }

# 6\. 客户端测试

至此开发者已经完成了PUSH功能客户端的基础功能开发，开发者可以尝试将自己的android工程打包成apk安装到手机中进行测试，打包的时候请确保使用了正确的[证书指纹](https://developer.huawei.com/consumer/cn/doc/development/HMS-3-Guides/push-Preparations#h2-1575616896242)。

开发者可以参考[控制台发送消息](https://developer.huawei.com/consumer/cn/doc/development/HMS-3-Guides/push-console-send-msg)来测试PUSH消息能否正确送达客户端。如需实现服务端自定义发送Push消息，请参考[服务端开发](https://developer.huawei.com/consumer/cn/doc/development/HMS-3-Guides/push-basic-server)章节。
