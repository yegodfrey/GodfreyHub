# 1.文档说明

尊敬的开发者，您好：

      HMS SDK 3.0版本仅支持maven下载的方式集成，不再提供基于Eclipse的集成方式，我们建议优先使用maven仓方式集成。对于一些无法迁移到Android Studio的应用的开发者，如确实需要使用Eclipse集成，我们提供手工配置方式。本文档基于maven下载的方式，从获取的aar包中抽取出必要资源，结合手工配置的方式满足开发者在Eclipse上的开发需求。

# 2.下载aar包

在集成SDK前，需下载相关的aar包。

## 2.1、下载HMS SDK包。

从以下地址下载HMS SDK的aar包，其中version为当前HMS SDK的版本号，目前最新版本为3.0.2.300。

https://obs.cn-north-2.myhwclouds.com/hms-ds-wf/sdk/hmssdk-aar-{version}.zip

HMS SDK包中包含以下aar包，开发者可根据实际需要集成。

**aar包名**| **说明**  
---|---  
hmssdk-base-{version}.aar| 基础包，必须集成。  
hmssdk-game-{version}.aar| 游戏业务包，游戏业务和应用升级业务必须集成。  
hmssdk-iap-{version}.aar| IAP业务包，使用华为支付时必须集成。  
hmssdk-id-{version}.aar| 帐号业务包，使用华为帐号时必须集成。  
  
hmssdk-location-{version}.aar| 定位业务包，使用Location业务时必须集成。  
hmssdk-opendevice-{version}.aar| AAID业务包，PUSH业务或需要获取AAID时必须集成。  
hmssdk-ppskit-{version}.aar| 广告业务包，使用华为广告业务时必须集成。  
hmssdk-push-{version}.aar| PUSH业务包，使用华为PUSH服务时必须集成。

# 4.Eclipse集成

## 步骤1 移动文件夹

将解压获取资源中包含所有解压后aar文件夹的hms-aar目录移动到Eclipse的工作目录下，例如“D:\eclipse\workspace”。

## 步骤2 生成子工程

Eclipse集成aar工程的整体思路是将从aar包提取出来的工程以子工程的形式集成到Eclipse主工程中，aar工程转变成子工程需执行以下4步：

**1、删除Eclipse工作目录下aar工程目录下的R.txt和proguard.txt文件。以hmssdk-base-{version}目录为例，需删除R.txt文件(目录中没有proguard.txt)。**

![](https://communityfile-drcn.op.hicloud.com/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20200108151630.79399880000234960169178127546432:50510112081447:2800:EF16513C5C1C9997619547507F980478A144BF32643E22FA7B9FA192F0847C81.png)

**2、将class.jar重命名成唯一名称。以hmssdk-base-{version}工程为例，可以将class.jar命名为hmssdk-base-{version}.jar。**

![](https://communityfile-drcn.op.hicloud.com/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20200108151705.15590974733339233728428262502289:50510112081447:2800:645FCBE4863939E610BED370D0DECBDCB649586906D61DBA35380F9815D622F8.png)

说明：

修改名称是因为每个aar工程中都有class.jar文件，在导入不同的子工程时，如果含有同名的class.jar文件会报同名错误。

**3、将改名后的class.jar文件移动到libs文件夹中，没有libs文件夹则手动创建一个。以hmssdk-base-{version}工程为例，如下图所示。**

![](https://communityfile-drcn.op.hicloud.com/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20200108151842.51421557996309627901045799857650:50510112081447:2800:0018F39BB5A766C661D437BE31AA7C1BFDCC11A317D6DE24472AC60D1B81921E.png)

**4、在aar工程目录下手动创建一个project.properties 并在里面写入如下内容。**

     android.library=true

重复执行以上步骤将所有aar工程转变成子工程，以hmssdk-base-{version}工程为例，最终目录结构如下所示。

        4.     android:value="appid=xxx">

# 5.自定义Debug模式的签名信息

如果开发者已经在AppGallery Connect网站上注册过指纹信息，当运行Eclipse工程时向云端请求数据时会验证APP的签名信息。但Debug模式下生成的APP的指纹信息是默认使用Eclipse的debug.keystore的别名和密码，而不是开发者自己创建的签名文件的别名和密码。如果开发这创建签名文件时设置的签名信息与debug.keystore不一致，会导致签名校验不通过，因此在Debug模式下需要将开发者的签名文件信息修改为与debug.keystore一致。

说明：

debug.keystore的位置在“Window > Preferences > Android > Build”窗口可以查看，其具体信息如下。

Keystore name: "debug.keystore"        

Keystore password: "android"        

Key alias: "androiddebugkey"        

Key password: "android"        

CN: "CN=Android Debug,O=Android,C=US"

**5.1、进入开发者自己创建的签名文件所在的文件夹，备份该签名文件。**

**5.2、在开发者自定义签名文件所在的文件夹的路径栏输入“cmd”并回车。**

**5.3、在弹出的命令行窗口执行如下命令修改密码为“android”。**

        keytool -storepasswd -keystore <keystore-file>

        <keystore-file>为开发者自己的签名文件的名称。验证原密码后，输入新的keystore password为“android”。

**5.4、执行如下命令修改别名为“androiddebugkey”，别名密码为“android”。**

![](https://communityfile-drcn.op.hicloud.com/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20200108154128.75088437920584152373893916496435:50510112081447:2800:AD31265D6CC2F36353B6907081FE0B55D9EF4EEF852C463552B9E08AEA690575.png)

**keytool -changealias -keystore** <keystore-file> **-alias** <alias-name>**-destalias androiddebugkey**

<keystore-file>为开发者自己的签名文件的名称，<alias-name> 为开发者自己签名文件中定义的alias名称。

验证步骤3中签名文件新密码后，命令行提示输入原有androiddebugkey的密码，输入后再输入新的androiddebugkey密码为“android”。
