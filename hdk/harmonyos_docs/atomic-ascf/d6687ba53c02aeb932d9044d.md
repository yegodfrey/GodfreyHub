# 拉起ASCF元服务时传递含?的参数导致参数获取不全

背景知识：

* 开发者可以通过不同的方式拉起ASCF元服务并携带自定义参数，具体可以参考[携带参数拉起ASCF元服务](https://developer.huawei.com/consumer/cn/doc/atomic-ascf/develop-open-atomicservice-with-parameters)。

* ascfPara是ASCF框架的内置参数，类型为对象，用于接收外部传递给ASCF的参数。其中，ascfPara.path为自定义的跳转页面路径，拉起ASCF元服务时，会先拉起首页后再跳转到该页面。

* 配置ascfPara.path时，可以通过?携带自定义参数，并使用\&分割多个参数，然后在页面的onLoad回调中获取自定义参数。

问题现象：

开发者创建了一个页面用于加载不同的H5链接，页面路由为pages/h5/index，通过自定义参数传递H5链接，页面路由和自定义参数使用?分割。如果自定义参数的值本身也是一个包含?的url，会导致url中?后面部分的内容缺失。

例如：配置自定义参数ascfPara={"path": "pages/h5/index?url=https://www.example.com?param=value\&param1=value1"}，在pages/h5/index页面的onLoad回调中获取url值只能得到url=https://www.example.com，无法获取param和param1。

问题原因：

自定义参数url本身为H5链接且包含查询参数（带有?），当该url作为值嵌入外层path时，path中会出现两个?。ASCF通过path.split('?')\[1\]提取查询字符串，该逻辑仅能获取第一个?之后的内容，无法区分外层参数与内嵌url参数的边界，导致内嵌URL的查询参数被截断或误解析，最终造成参数缺失。

解决措施：

在配置ascfPara.path参数时，参数值不建议包含?、\&等关键字符，否则会导致参数截取混乱。

如果确实需要携带这些字符，必须先对参数值进行encodeURIComponent编码，再对整个ascfPara值进行encodeURIComponent编码，得到双重编码后的字符串。ASCF在处理参数时只会对整个ascfPara解码一次，从而正确处理参数。

示例：

1. 对url的值https://www.example.com?param=value\&param1=value1进行encodeURIComponent编码，得到https%3A%2F%2Fwww.example.com%3Fparam%3Dvalue%26param1%3Dvalue1。

2. 对ascfPara.path值进行encodeURIComponent编码，得到pages%2Fh5%2Findex%3Furl%3Dhttps%253A%252F%252Fwww.example.com%253Fparam%253Dvalue%2526param1%253Dvalue1。

3. 在onLoad中获取参数。

   ```
   // pages/h5/index.js
   Page({
     onLoad(options = {}) {
       let url = options.url;
       if (url) {
         url = decodeURIComponent(url);
         // https://www.example.com?param=value&param1=value1
         console.info('url', url);
       }
     },
   })
   ```
