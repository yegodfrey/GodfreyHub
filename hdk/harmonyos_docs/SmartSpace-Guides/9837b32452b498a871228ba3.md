# 插件改造

智慧生活Ex（以下统称宿主侧，插件端统称为插件侧）使用 Replugin 框架集成插件。
> 说明
>
> 若第一次接触插件改造，建议可以先使用一个空工程进行插件化改造，以此熟悉改造过程。

1. **本地引入使用** **androidx** **改造好的插件**

2. **修改** **replugin-plugin** **的** **maven** **路径**

在项目根目录的build.gradle文件中的buildscript和allprojects两处位置，⼤家可以根据⾃⼰需求修改本地maven的**绝对路径**，只要和上一步的路径保持⼀致即可(以下格式二选一即可)：

```screen
maven{ 
url 'D:/XXX/XXX/pluginLib/maven' // uri("/XXX/XXX/work/pluginLib/maven")
}
```

**3、** **添加** **RePlugin Plugin Gradle** **依赖**

在项目根目录中添加 replugin-plugin-gradle-androidx依赖，

```screen
buildscript {
     dependencies { 
         classpath ' com.qihoo360.replugin:replugin-plugin-gradle-androidx:2.3.4'
         ...
     }
}
```

**4. 添加** **RePlugin Plugin Library**

在app目录下的build.gradle 文件中，在android{..}模块后添加replugin-plugin-lib-androidx 依赖，appModule的名称建议使用':app'

```screen
apply plugin:'replugin-plugin-gradle'  
 
repluginPluginConfig {
    appModule = ':XXX'
    pluginName = "XXXX"  // 内容为该插件包名
    hostApplicationId = "com.huawei.smarthome.extend" 
hostAppLauncherActivity = "com.huawei.smarthome.login.LauncherActivity"
}
dependencies { 
     implementation 'com.qihoo360.replugin:replugin-plugin-lib-androidx:2.3.4' 
     ...
}
```

**5. 进行插件宿主进程隔离配置**

插件与宿主是子进程和主进程的关系。在app项目的AndroidManifest.xml文件中配置插件的运行进程p9。From填写插件的包名即可，例如：

```screen
<meta-data 
    android:name="process_map" 
    android:value="[{'from':'***.***','to':'$p9'}]"/>
```

至此，完成这五步后，基本已完成插件化改造，可以正常编译出包；

**6. 插件适配** **AiLifeEx** **开发**

完成前五步后，基本已完成插件化改造，可以正常编译出包，如果需要和宿主智慧生活Ex进行通信还需要插件开发两个组件。

a) 插件服务PluginService开发

名称可自定义，此组件主要有两个用途：

* 插件不需要前台运行的场景，宿主可通过定制化场景拉起插件服务，完成插件服务拉起，插件初始化，插件完成后台运行业务。

* 宿主需要从插件获取数据的场景，通过插件service返回的Binder进行对插件数据的访问。

自定义的Service需要在AndroidManifest.xml文件中进行声明，例如：

```screen
<service
            android:name="com.huawei.gxplugin.pluginservice.PluginService"
            android:exported="false" />
```

b) 插件启动页面开发。

* 此界面主要用途是拉起插件内部界面， 拉起界面过程中需要完成初始化，界面分发等。

![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20230525091406.46678598664820140993844489512212:50001231000000:2800:35A4E5ED8C897284EAB0F1E63C15C6814FC25ED473808E1073E9326F9C031A86.png?needInitFileName=true?needInitFileName=true)
> 注意
>
> * 建议插件架构： 开发插件过程中UI界面进程与Service业务进程分离，其中PluginService运行内存建议不超过5M 。
> * 插件整体运行时不超过100M。

**7. 插件和宿主双向通信**

插件侧访问智慧生活Ex侧接口：

1. AiLifeEx已经支持插件宿主服务，不需要特别适配。
2. 插件侧需要先绑定智慧生活Ex插件服务，通过调用HostRemoteControlManager. getInstance. bindRemoteService()完成。绑定成功后即可和宿主进行通信。
3. 调用HostRemoteControlManager. getInstance. call() 完成和宿主的接口访问。

智慧生活Ex侧调用插件侧的AIDL接口：

1. 插件侧需要开发插件自己的Service服务。
2. 插件服务绑定后需要返回实现IPluginRemoteControlInterface接口的binder对象。
3. 插件需要在PluginRemoteControlBinder 的 call() 方法中实现自己的业务细节。 注意
   >
   > **AIDL接口文件以及通信Demo样例请参考[《插件通信集成demo以及说明》](https://developer.huawei.com/consumer/cn/doc/development/SmartSpace-Guides/integration-demo-0000001504936373)**

**8. 业务开发接口参考**

在插件业务开发过程中，宿主也提供部分相关功能接口供插件使用，具体请参考接口文档[《智慧生活Ex插件AIDL API参考》](https://developer.huawei.com/consumer/cn/doc/development/SmartSpace-References/plug-in-interface-reference-0000001505034965)

说明：在接口文档中有如下几个是插件必须实现的接口，否则影响插件UI的呈现以及插件宿主的通信；

* 1.2.3 获取卡片数据
* 1.2.4 更新AccessId
* 1.1.8 请求获取AccessId

其他的接口按需调用即可。

**9. 插件在中控屏的** **UI** **适配**

1. 插件开发完成后，需要在中控屏上呈现出卡片，则需要插件实现一个特定的接口------[《智慧生活Ex插件AIDL API参考》](https://developer.huawei.com/consumer/cn/doc/development/SmartSpace-References/get-card-information-0000001455235302)中的[获取卡片数据接口](https://developer.huawei.com/consumer/cn/doc/development/SmartSpace-References/get-card-information-0000001455235302)；
2. 插件在初次安装后，宿主会主动传accessId给插件以及主动调用插件的getUIcontent接口以此渲染卡片的UI，宿主和插件之间的交互逻辑流程，请参考[《华为全屋智能中控屏卡片规范及开放接口指导》](https://developer.huawei.com/consumer/cn/doc/development/smartspace-Library/introduction-0000001504672469)

**10. 插件开发架构建议及其他注意事项**

1. 在打包过程，versionName字段**不能**包含中划线
2. 插件的常驻进程建议只放跟宿主的通信service，其他非必须常驻的进程建议放在主进程即可；按照这个架构，插件中需要写一个跨进程通信的服务；
