# 1\. 接口原型

承载协议| HTTPS POST  
---|---  
接口方向| 应用服务器->   PUSH服务器  
接口URL| https://push-api.cloud.huawei.com/v1/[appid]/messages:send  
  
# 2\. 接口功能

华为推送提供了两种消息格式：透传消息和通知栏消息。

**透传消息** ：手机收到推送消息后不直接展示，而是将通知消息传递给最终的应用，后续行为由应用决定。

**通知栏消息** ：手机收到推送消息后由EMUI系统直接展示，开发者可以自定义点击消息的行为，包括：拉起App首页、打开特定URL、打开自定义富媒体消息、打开自定义App页面。

# 3\. 调用场景

开发者调用Push服务器完成消息下发功能。

# 4\. 接口约束

消息体最大不能超过4096Bytes。按Token发送时，最大Token数不能超过1000。

Message的结构体定义：

"Message": {"data": string,"notification": {object(Notification)},"android": {object(AndroidConfig)},"token": [string],"topic": string,"condition": string}|   
  
---|---  
  
 

**参数值**| **取值说明**| **必选(M)/****可选(O)**| **功能**  
---|---|---|---

notification| JSON object| O| 通知栏消息内容, 具体字段请参考Notification结构体的定义。  
android| JSON Object| O (如果是通知栏消息，本字段必填)| 参考AndroidConfig中的定义，本结构体定义了Android平台推送的消息体定义。

' : 表示逻辑非'()' : 优先级控制'in' ：关键词**(2)   ****使用限制** 最多可以在条件表达式中包括五个主题**(3)   ****使用案例** "'TopicA' in topics && ('TopicB' in topics || 'TopicC' in topics)"上述表达式将消息发送至已订阅 TopicA 以及 TopicB 或 TopicC 的设备，对于只订阅某个单一主题的用户将不会接收到消息。同样地，未订阅 TopicA 的用户也不会接收到消息。

---|---|---|---  
collapse_key| Integer类型，离线消息的覆盖功能| M| 当下发到离线用户多条消息后，华为推送系统会按照设置的TTL将消息进程缓存，待用户上线后会将缓存下发给用户。默认情况下系统最多给用户发送10条缓存消息，如果开发者想控制缓存消息的行为可以使用本功能。设置collapse_key为-1表示对于本应用的离线消息待用户上线后全部发送给用户；设置collapse_key为0表示对于本应用的离线消息待用户上线后按照华为推送系统默认策略发送给用户(一般是最新的一条);设置collapse_key为1~100是对消息进行分组，例如如果开发者发送了10条消息，其中前5条的collapse_key为1，后5条的collapse_key为2，那么待用户上线后collapse_key为1和2的分别下发最新的一条消息给最终用户。  
ttl| String类型，设置离线消息的存储时间。| M| TTL目前的单位为秒，如果用户设置TTL为0，那么推送系统就不会缓存消息，如果未设置TTL默认会存储消息1天，如果用户设置了其他的数据，那么系统对离线消息存储用户指定的时间，最大15天。

---|---|---
