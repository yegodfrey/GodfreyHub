# 自定义Pipeline

#### 背景信息

本节的接入方式为[从C++层接入](https://developer.huawei.com/consumer/cn/doc/development/Media-Guides/integrating-sdk-0000001156025441#section1143033914488)。

AV Pipeline预置媒体播放所需的[视频播放Pipeline](https://developer.huawei.com/consumer/cn/doc/development/Media-Guides/video-playback-pipeline-0000001110539082)，以及在播放时调用AI插件的[视频超分Pipeline](https://developer.huawei.com/consumer/cn/doc/development/Media-Guides/video-super-resolution-pipeline-0000001110501562)、[声音事件检测Pipeline](https://developer.huawei.com/consumer/cn/doc/development/Media-Guides/sound-event-detection-pipeline-0000001156821439)。若预置Pipeline不符合您的要求，可以自定义Pipeline。

自定义Pipeline主要根据业务场景来定义，如果涉及到业务场景中没有的相关插件，需要[自定义插件](https://developer.huawei.com/consumer/cn/doc/development/Media-Guides/custom-plug-in-0000001164400275)。  

#### 部分自定义

以播放业务为例，若需要在播放业务中编排其它AI算法，则在自定义新的插件后，进行如下操作。

1. 编写[自定义插件](https://developer.huawei.com/consumer/cn/doc/development/Media-Guides/custom-plug-in-0000001164400275)。
2. 编写Pipeline配置文件。以视频超分Pipeline的配置文件PlayerGraphCV.xml为例，请将"xxx"替换为您自定义插件的so名称。

   ```
   <?xml version="1.0"?>
   <Nodes>
       <node id="0" name="AVDemuxer" mime="media/demuxer" type="source">
           <!-- 数据流从这里开始分两路，一路到视频解码节点node 1,一路到音频解码节点node 2 -->
           <next id="1"/>
           <next id="2"/>
       </node>
       <!-- 视频解码节点将解码后的图像送到下一个节点，即next id号对应的3号CVFilter节点 -->
       <node id="1" name="MediaCodecDecoder" mime="video/avc" type="filter">
           <next id="3"/>
       </node>
       <!-- 音频解码节点FFmpegNode将解码后的音频送到下一个节点，即next id号对应的4号AudioSinkOpenSL节点 -->
       <node id="2" name="FFmpegNode" mime="audio/aac" type="filter">
           <next id="4"/>
       </node>
       <!-- node的name、mime、type参考示例中的定义。node id应当唯一，建议为上一个node id加1即可 -->
       <node id="3" name="xxx" mime="video/filter" type="filter">
           <!-- next id为视频流从本节点出去后需要到达的下一个节点，本示例中为送显节点 -->
           <next id="5" />
       </node>
       <node id="4" name="AudioSinkOpenSL" mime="audio/sink" type="sink">
       </node>
       <node id="5" name="VideoSinkBasic" mime="video/sink" type="sink">
       </node>
   </Nodes>
   ```

   配置文件中关键的item必须填写正确。
   * id：每个插件的唯一身份标识。
   * name：标识插件的动态库名称。由于底层采用dlopen的方式来加载具体的插件，这里的命名必须和动态库的名称一致。
   * mime：描述该插件的功能。用"mediatype/capability"来表示，其中"mediatype"可以设置为"media/video/audio"；音视频解码插件的"capability"可以设置为任意一个编解码格式（不代表插件只能解码该格式），其它插件的"capability"可自定义。
   * type：描述该插件的类型。根据插件在Pipeline中的位置，可以分为[SourceNode](https://developer.huawei.com/consumer/cn/doc/development/Media-References/sourcenode-0000001159823217)、[FilterNode](https://developer.huawei.com/consumer/cn/doc/development/Media-References/filternode-0000001113503308)、[SinkNode](https://developer.huawei.com/consumer/cn/doc/development/Media-References/sinknode-0000001113343416)三种类型。
   * next：每个插件的后续插件，如果有需要请填写后续插件对应的id号，没有则不需要填写。
3. 通过[setString](https://developer.huawei.com/consumer/cn/doc/development/Media-References/mediameta-0000001157012727#section14899836152019)设置该配置文件的路径，该路径形式为key-value，key值为MEDIA_GRAPH_PATH，然后通过[setParameter](https://developer.huawei.com/consumer/cn/doc/development/Media-References/mediaplayer-0000001110596458#section94627308113)设置给[MediaPlayer](https://developer.huawei.com/consumer/cn/doc/development/Media-References/mediaplayer-0000001110596458)。

   ```
   MediaMeta meta = new MediaMeta();
   meta.setString(MediaMeta.MEDIA_GRAPH_PATH, "/path/to/xxx.xml");
   mPlayer.setParameter(meta);
   ```

#### 完全自定义

由于AV Pipeline目前只支持播放场景，不具备其他场景（如录制、编辑等）的Pipeline，如果您需要使用可通过如下方式来实现。

1. 实现标准Pipeline接口。

   标准接口如[IPipeline](https://developer.huawei.com/consumer/cn/doc/development/Media-References/ipipeline-0000001159703235)所示，[PipelineListener](https://developer.huawei.com/consumer/cn/doc/development/Media-References/pipelinelistener-0000001113372466)用来通知外部事件和buffer。  
   为了减少基于[IPipeline](https://developer.huawei.com/consumer/cn/doc/development/Media-References/ipipeline-0000001159703235)自定义的Pipeline开发量，将Pipeline非业务逻辑（线程同步、消息传递、状态管理等）封装在[PipelineBase](https://developer.huawei.com/consumer/cn/doc/development/Media-References/pipelinebase-0000001159823219)，可基于[PipelineBase](https://developer.huawei.com/consumer/cn/doc/development/Media-References/pipelinebase-0000001159823219)来完成自定义Pipeline的快速开发。[PipelineBase](https://developer.huawei.com/consumer/cn/doc/development/Media-References/pipelinebase-0000001159823219)采用了模板模式，请关注以下重点接口，这些接口用于子类Pipeline的定制。

   ```
   // 模板模式，按需实现以下接口
   virtual RetCode DoInit() { return OK; }
   virtual void DoDeInit() {}
   virtual RetCode DoPrepare();
   virtual RetCode DoSetParameter(const MediaMetaSP &) { return OK; }
   virtual RetCode DoGetParameter(MediaMeta *) const;
   virtual RetCode DoStart() { return OK; }
   virtual RetCode DoResume() { return OK; }
   virtual RetCode DoStop() { return OK; }
   virtual RetCode DoPause() { return OK; }
   virtual RetCode DoReset() { return OK; }
   virtual RetCode DoFlush() { return OK; }
   // 处理自定义的消息，该消息在专门PipelineBase的消息线程中处理
   virtual RetCode DoRegisterHandlers() { return OK; }
   virtual void DoNodeMessage(const MediaMetaSP &, uint32_t) { }
   ```

2. 编写Pipeline配置文件。以视频超分Pipeline的配置文件PlayerGraphCV.xml为例，请将"xxx"替换为您自定义插件的so名称。

   ```

           <next id="1"/>
           <next id="2"/>
       </node>
       <!-- 视频解码节点将解码后的图像送到下一个节点，即next id号对应的3号CVFilter节点 -->
       <node id="1" name="MediaCodecDecoder" mime="video/avc" type="filter">
           <next id="3"/>
       </node>
       <!-- 音频解码节点FFmpegNode将解码后的音频送到下一个节点，即next id号对应的4号AudioSinkOpenSL节点 -->
       <node id="2" name="FFmpegNode" mime="audio/aac" type="filter">
           <next id="4"/>
       </node>
       <!-- node的name、mime、type参考示例中的定义。node id应当唯一，建议为上一个node id加1即可 -->
       <node id="3" name="xxx" mime="video/filter" type="filter">
           <!-- next id为视频流从本节点出去后需要到达的下一个节点，本示例中为送显节点 -->
           <next id="5" />
       </node>
       <node id="4" name="AudioSinkOpenSL" mime="audio/sink" type="sink">
       </node>
       <node id="5" name="VideoSinkBasic" mime="video/sink" type="sink">
       </node>
   </Nodes>
   ```

   配置文件中关键的item必须填写正确。
   * id：每个插件的唯一身份标识。
   * name：标识插件的动态库名称。由于底层采用dlopen的方式来加载具体的插件，这里的命名必须和动态库的名称一致。
   * mime：描述该插件的功能。用"mediatype/capability"来表示，其中"mediatype"可以设置为"media/video/audio"；音视频解码插件的"capability"可以设置为任意一个编解码格式（不代表插件只能解码该格式），其它插件的"capability"可自定义。
   * type：描述该插件的类型。根据插件在Pipeline中的位置，可以分为[SourceNode](https://developer.huawei.com/consumer/cn/doc/development/Media-References/sourcenode-0000001159823217)、[FilterNode](https://developer.huawei.com/consumer/cn/doc/development/Media-References/filternode-0000001113503308)、[SinkNode](https://developer.huawei.com/consumer/cn/doc/development/Media-References/sinknode-0000001113343416)三种类型。
   * next：每个插件的后续插件，如果有需要请填写后续插件对应的id号，没有则不需要填写。
3. [实现自定义插件](https://developer.huawei.com/consumer/cn/doc/development/Media-Guides/custom-plug-in-0000001164400275#section7368191615404)。
4. 通过[setString](https://developer.huawei.com/consumer/cn/doc/development/Media-References/mediameta-0000001157012727#section14899836152019)设置该配置文件的路径，该路径形式为key-value，key值为MEDIA_GRAPH_PATH，然后通过[setParameter](https://developer.huawei.com/consumer/cn/doc/development/Media-References/mediaplayer-0000001110596458#section94627308113)设置给[MediaPlayer](https://developer.huawei.com/consumer/cn/doc/development/Media-References/mediaplayer-0000001110596458)。
