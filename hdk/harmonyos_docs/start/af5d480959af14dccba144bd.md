# 3. SDK功能

为了给SDK使用者提供优质的用户体验，请确保您的SDK能够为用户提供正常完整、稳定流畅、可实现、有吸引力的功能，不得含有影响用户体验的不合理功能。  

#### SDK全量业务功能说明

SDK应向使用者提供全量业务功能说明，以便使用者能够全面了解SDK的功能范围和使用方法，更好地利用SDK的各项功能，赋能SDK使用者开发出功能丰富、性能卓越的应用。具体要求如下：

3.1 SDK应仅包含与其声明功能相符合的功能，宜进行模块化开发，便于提供功能裁剪方案；不应强制捆绑无关功能；在非服务所必需或无合理场景下，不应进行后台唤醒，或唤醒其他App。

3.2 SDK提供者应提供SDK下载文件以及相应的集成文档和API接口文档，向App提供者告知SDK所具有的全部功能，并对目前可用的历史SDK版本进行管理，提供版本迭代的功能变化说明。

3.3 应针对每项功能有收费模式的说明。  

#### SDK功能划分要求

SDK应按照以下要求明确自身所属类型，并区分基本业务功能和扩展业务功能：

3.4 应根据SDK提供的服务内容，划分SDK所属类型。

3.5 当SDK提供的服务内容涵盖多种类型时，应区分SDK基本业务功能和扩展业务功能，并按照基本业务功能划分自身所属类型。

3.6 当SDK基本业务功能涵盖某类SDK的多项典型子类时，宜对基本业务功能进行拆分。

3.7 SDK为实现自身产品研发、服务改进、客户服务等目的的业务功能应划分为扩展业务功能。

3.8 SDK中使用的外部第三方或关联公司提供的业务功能应划分为扩展业务功能。  
![](https://media:401788750501999178)  
SDK提供的主要服务内容为其基本业务功能，其他服务内容为其扩展业务功能，若某些功能均为基本业务功能所必需，则不需将该业务划分扩展业务功能。  

#### SDK配置能力提供要求

SDK向使用者提供功能服务应同时提供相关业务功能及个人信息配置能力，满足以下要求：

3.9 应向SDK使用者提供扩展业务功能开启与否的配置选项。  
3.10 应向SDK使用者提供可选个人信息收集与否的配置选项。  
![](https://media:401788750502024179)  
通过扩展业务功能配置选项已实现个人信息关闭控制的，可不单独提供个人信息是否收集的配置选项。

3.11 对于可按照不同个人信息收集频次、精度开展的业务功能，应向SDK使用者提供不同频率、精度的配置选项。

3.12 应通过代码选择、参数配置等SDK使用者集成接入过程中可便捷实现的方式提供配置选项，不应仅通过客服沟通等线下方式提供配置能力。

3.13 最终用户可选的相关功能（如可选个人信息同意与否、个性化功能同意与否等），应向SDK使用者提供实时配置能力，便于按照最终用户授权情况及时变更SDK相关功能。

3.14 不应将配置能力的提供与服务费用、服务质量、使用期限等内容捆绑，强迫、诱导SDK使用者接受全部业务功能及个人信息收集要求。  

#### SDK兼容性要求

为了确保SDK的顺利集成和稳定运行，应向SDK使用者明确阐述兼容性要求和设备版本约束，避免因兼容性问题给SDK使用者带来不必要的困扰和影响。具体要求如下：

3.15 应向SDK使用者说明兼容性要求，详细说明所支持的OS版本、系统SDK版本、设备类型，并在SDK发布前完成兼容性测试。

3.16 针对非兼容的接口变更，应提供明确说明。
