# 1. SDK信息

SDK提供者在上传SDK时需提供完善的且满足下列要求的SDK信息，包括但不限于SDK基本信息（如名称、图标、分类、功能描述、开发者信息）、SDK包体信息（如包名、版本号、版本更新说明、获取地址、接口文档、集成使用指南）、隐私信息（如隐私政策、权限说明）、合规使用指南等。同时应确保所提交的SDK信息符合实际功能、用途，能够准确反映SDK的核心体验。并请及时更新，以保持与新版本相应的最新状态。

SDK商品接入操作指南请见：卖家操作指南-[SDK类商品接入说明](https://developer.huawei.com/consumer/cn/doc/start/dev-mall-marketplace-sp-sdkservice-access-explain-0000001866499490)。

## SDK基本信息

1.1 SDK名称长度不得超过40个字符。

1.2 SDK名称应清晰、准确，能够代表SDK的主要功能和用途，不得为广义归纳、普遍且不具辨识性的词汇或热门搜索词，避免干扰搜索结果及误导SDK使用者，包括但不限于使用商标术语、热门SDK名称或别称、流行词、职业名词、类别词、功能性描述的词汇等。结合SDK具体功能特性、经过精心构思的名称，可以帮助SDK使用者快速识别和了解您的SDK，并建立对SDK的记忆和品牌认知。

1.3 SDK名称不得含有占位符文本、乱码、表情符号、特殊符号 (如"*" "&""-""( )") 。

1.4 SDK图标尺寸100*100px，格式为jpg/jpeg/png，大小不超过5MB。

1.5 SDK图标应具有较高品牌辨识度和识别性，不得为视觉传达具体功能的图标，帮助SDK使用者快速识别，建立对您的SDK的记忆和品牌认知。

1.6 SDK分类需与实际功能和用途相符（详细请参见：[SDK分类示例](https://developer.huawei.com/consumer/cn/doc/start/sdk-classification-0000001867143762)）。

1.7 SDK介绍应简单、清晰、准确表达SDK的功能和用途，不得有超出该SDK功能及用途的信息。

1.8 SDK详情应准确、客观地反映其实际功能和提供商介绍，核心优势、约束与限制及成功案例等信息，突出解决开发者痛点、提高开发效率、优化用户体验等方面的实际作用，避免夸大承诺或涉及与功能无关的营销性内容，确保描述简洁明了，以提供有价值的信息并展示SDK的实际价值。

1.9 提供SDK的商户应提供完整的合规使用指南及隐私政策，同时向应用方告知SDK收集使用个人信息的目的、方式、范围、使用频率、存储期限，需申请的相关权限，问题反馈和投诉渠道等，告知的信息应完整、准确、及时，不存在故意隐瞒、欺骗等行为，对于必须收集的个人信息和必须申请的权限，应进一步说明其必要性。如缺少以上SDK收集使用个人信息的介绍和展示，将导致审核不通过。SDK隐私政策及合规使用指南撰写参考请见：[SDK隐私政策规范性参考](https://developer.huawei.com/consumer/cn/doc/start/sdk-privacy-policy-specifications-0000001867303626)、[SDK合规使用指南规范性参考](https://developer.huawei.com/consumer/cn/doc/start/sdk-compliance-specifications-0000001913103017)。

1.10 SDK商品信息成功提交上架申请后，预计1-5个工作日内完成审核。

## SDK包体信息

1.11 SDK包提供：只支持har格式，语言为ArkTs，大小不超过100M。

1.12 SDK获取地址：支持OHPM地址或SDK下载地址，该地址应明确指引开发者获取相应的SDK。

1.13 SDK包名：SDK构建时填写的HarmonyOS模块名称，参考oh-package.json5文件中定义的name字段，如果SDK上架到OHPM仓库，一般等同为仓库坐标名。

1.14 SDK接口文档：支持URL网页链接、docx、pdf格式，大小不超过10M。应清晰明了地描述所有接口的功能、参数、返回值等信息，并提供充足示例，确保开发者能够轻松理解和使用SDK。

1.15 使用指南：支持pdf、docx、zip格式，大小不超过10M。内容需包含完整的集成步骤、配置说明、API调用示例及常见问题解决方案，确保指导清晰可执行。

1.16 权限声明：应完整列出SDK调用的HarmonyOS权限名称，并逐项说明权限用途及使用场景，确保声明准确合规。

1.17 全国SDK管理服务平台登记情况：基于SDK实际登记情况选择登记状态。查询：[全国SDK管理服务平台官网](https://sdk.caict.ac.cn/official/#/home)

1.18 SDK提供者对提供的SDK需自行承担保护源码安全的责任，应采取必要的措施，防范因源码泄露可能带来的技术安全敞口、源码被抄袭等风险，因保护措施不慎而造成损失的，商户应自负其责。

商户构建及提供SDK时，建议：采用字节码HAR方式，并同时开启代码混淆及Release模式。

不建议以下任一方式直接提供SDK：

（1）源码HAR；

（2）不开启代码混淆；

（3）Debug模式。
