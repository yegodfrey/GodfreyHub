# FAQ

#### 已经加载完成动态特性后如何启动？

1. 加载成功后返回。 为FeatureInstallManager实例注册监听器后，可以监听动态加载的过程。开发者可以通过监听器回调方法中的InstallState实例的status()返回的状态，判断动态特性是否已经安装完成。例如：

   ```
   if (state.status() == FeatureInstallSessionStatus.INSTALLED) {
       Log.i(TAG, "installed success ,can use new feature");
   }
   ```

<!-- -->

2. 查看动态特性是否已经安装。 调用getAllInstalledModules()方法，查看对应的特性是否已经安装。

   ```
   private void getInstalledFeature() {
   Set<String> moduleNames = mFeatureInstallManager.
   getAllInstalledModules();
       Log.i(TAG, "get all installed modules : " + moduleNames);
   }
   ```

3. 启动动态特性。 此处以启动动态特性中的FeatureActivity为例：

   ```
   startActivity(new Intent(this, 
   Class.forName("com.huawei.android.demofeature.FeatureActivity")));
   ```

#### 如何查看当前动态加载过程中的有效状态？

为FeatureInstallManager实例注册监听器后，可以监听动态加载的过程。Dynamic Ability SDK预定义的状态码保存在[FeatureInstallSessionStatus](https://developer.huawei.com/consumer/cn/doc/AppGallery-connect-References/featureinstallsessionstatus-0000001058092553)类中。开发者可以通过监听器获取当前动态加载的状态，并做出相应调整。  

#### 动态加载过程中出现错误，该怎么办？

为FeatureInstallManager实例注册监听器后，可以监听动态加载的过程。当监听到失败时，可以通过调用state.errorCode()方法获取具体的错误码。开发者可以根据错误码判断出当前具体的错误和原因，然后再做出相应调整即可。具体错误码可参考[FeatureInstallErrorCode](https://developer.huawei.com/consumer/cn/doc/AppGallery-connect-References/featureinstallerrorcode-0000001057642245)。  

#### App中完成动态加载，但启动特性时提示ClassNotFoundException。

启动feature的某个组件时，可能写错了包名或类名，所以请检查特性对应的Activity完整名称是否书写正确。

此处以启动动态特性模块中的FeatureActivity为例：

```
startActivity(new Intent(this, Class.forName(“com.huawei.android.demofeature.FeatureActivity”)));
```

#### App中完成动态加载，但启动特性时提示java.lang.RuntimeException: Unable to start activity ComponentInfo{xxxx} android.content.res.Resources$NotFoundException: Resource ID xxxx。

假如安装完成后，你需要马上启动新增动态特性的一些Activity，需要重载方法attachBaseContext()。

以FeatureActivity为例。

```
public class FeatureActivity extends Activity {
    @Override
    protected void attachBaseContext(Context newBase) {
        super.attachBaseContext(newBase);
        try {
            FeatureCompat.install(newBase);
        } catch (Exception e) {
            Log.e(TAG, "attachBaseContext error :" + e.getMessage());
        }
}
}
```

#### 加载成功后启动特性，报"UnsatisfiedLinkError: dlopen failed: library name xxxxxx too long"错误。

因为较低版本的Android系统对部分文件的路径长度做了限制，所以建议开发者设置"包名+版本号+feature名称+so文件名称"的总长度不超过50个字符。  

#### 集成Dynamic Ability SDK开发应用并发布到华为应用市场后，只能安装该应用的全量APK包。

由于动态加载SDK使用的是App Bundle技术，仅支持Android 5.0及以上版本。所以，对于低于Android 5.0以下的版本，不支持动态加载，只能安装全量APK。  

#### 针对不同平台（如手机，大屏，带屏音箱）上华为应用市场包名不同的问题，Dynamic Ability SDK是如何适配解决的？

通过应用市场固定的service action，遍历设备上的所有匹配应用，取出其meta-data，如果meta-data中包含指纹和证书链信息并用根证书校验通过，则认为该应用为当前设备上的应用市场，返回其包名即可。如果在设备上同时装多个应用市场版本，则当前策略是返回第一个找到的应用市场包名。  

#### 如何将feature配置为按需下载或随base app同步下载？

在新建feature时，可以通过配置Install-time inclusion来实现。

* 配置为Include module at install-time时，feature会在应用安装时下载。
* 配置为Do not include module at install-time时，feature不会在应用安装时下载，而是会在稍后的请求中下载。

具体的配置信息可以在模块的AndroidManifest文件中查询获取。  

#### 用户授权协议与用户同意下载弹出机制是什么？

用户授权协议与用户同意下载均为应用市场弹窗界面，通过注册监听器[InstallStateListener](https://developer.huawei.com/consumer/cn/doc/AppGallery-connect-References/installstatelistener-0000001059050276)的方式，可以监测用户当前是否已经同意授权以及同意下载。

若用户尚未同意授权，则返回状态码8（FeatureInstallSessionStatus.REQUIRES_USER_CONFIRMATION），此时可以调用[triggerUserConfirm](https://developer.huawei.com/consumer/cn/doc/AppGallery-connect-References/featureinstallmanager-0000001057944555#section379301617139)方法，弹出应用市场的用户授权协议弹窗，征求用户同意。若用户同意，则继续执行。用户未在华为应用市场签署授权协议时，才会触发此提醒。开发者需要监听此业务状态，给用户展示该弹框。如果用户拒绝协议，安装过程将会终止。

在正式开始下载安装前，会判断用户是否使用移动网络：若使用移动网络，会触发流量消耗提醒，此时便需要用户手动确认"同意下载"。因此，开发者可以注册监听器[InstallStateListener](https://developer.huawei.com/consumer/cn/doc/AppGallery-connect-References/installstatelistener-0000001059050276)，当监听到状态码10（FeatureInstallSessionStatus.REQUIRES_PERSON_AGREEMENT）的时候，开发者可以调用[triggerUserConfirm](https://developer.huawei.com/consumer/cn/doc/AppGallery-connect-References/featureinstallmanager-0000001057944555#section379301617139)方法，弹出应用市场的用户同意下载弹窗，征求用户同意。若用户同意下载，则开始执行下载操作。若用户拒绝下载，则下载任务终止。
