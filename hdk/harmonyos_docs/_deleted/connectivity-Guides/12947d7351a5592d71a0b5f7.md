# 开发步骤

#### 开发步骤

#### 链接服务

应用在需要使用DV Engine能力时，首先需要进行初始化连接DV Engine服务，服务初始化结果会通过onConnect回调返回。

当服务断开或异常，会通过onDisconnect回调返回。

在连接成功后调用getKitService来获取VirtualDeviceManager服务实例，用于控制虚拟设备。

当DVEngine服务异常时，onDisconnect回调接口会通知应用，应用此时可以重新进行连接并且清理设备连接状态，或者根据业务需要进行处理。

```
//获取DV Engine对象并连接DV Engine服务 
DvKit.getInstance().connect(getApplicationContext(), new IDvKitConnectCallback() { 
    //服务连接成功后的回调通知 
    @Override 
    public void onConnect(int result) { 
        addLog("msdp service connect"); 
        mVirtualDeviceManager = (VirtualDeviceManager)        DvKit.getInstance().getKitService(VIRTUAL_DEVICE_CLASS); 
        mVirtualDeviceManager.subscribe(EnumSet.of(VIRTUALDEVICE), observer); 
    } 
    //服务断开后的回调通知 
    @Override 
    public void onDisconnect() { 
        addLog("msdp service disconnect"); 
    } 
});
```

#### 设备发现

当DV Engine服务初始化连接成功并且获取到VirtualDeviceManager服务后，应用可以调用VirtualDeviceManager服务的startDiscovery接口用于发现周边可用设备。发现的设备会通过IDiscoveryCallback回调的onFound接口返回。

```
//开始发现设备 
mVirtualDeviceManager.startDiscovery(new IDiscoveryCallback() { 
    //设备发现时的回调接口 
    @Override 
    public void onFound(VirtualDevice device, int state) { 
        if (device == null) { 
            addLog("onDevice callback but device is null"); 
        } else { 
            HwLog.d(TAG, "onDevice Found: " + Util.hideSensitiveInfo(device.getDeviceId()) + " Name: " 
                + device.getDeviceName() + " Type:" + device.getDeviceType()); 
            if (!mVirtualDeviceMap.containsKey(device.getDeviceId())) { 
                addLog("onDevice Found: " + device.getDeviceId() + " Name: " + device.getDeviceName() + " Type:" 
                    + device.getDeviceType()); 
                mVirtualDeviceMap.put(device.getDeviceId(), device); 
                handler.sendMessage(handler.obtainMessage(DEVICE_ADD, device)); 
            } 
        } 
    } 
    //发现状态变更的回调通知 
    @Override 
    public void onState(int state) { 
    } 
});
```

![](https://media:801773457107159403)  
1. 周边设备不能保证一直可用，因此在应用中请不要缓存可用设备列表。每次呈现给用户进行设备选择时，都需要调用startDiscovery接口重新发现周边可用设备。
2. 发现接口调用后，DV Engine会触发持续1分钟的扫描，在此期间，应用无法通过startDiscovery再次触发扫描发现。如果需要再次进行发现，建议在开始前先调用VirtualDeviceManager服务的[cancelDiscovery](https://developer.huawei.com/consumer/cn/doc/connectivity-References/virtual-device-manager-0000001051787342#section20264161611227)停止发现，将发现状态置位后，再触发startDiscovery。  

#### 设备能力使用

当发现到虚拟设备后，应用可以调用虚拟设备的getDeviceCapability()接口获取设备支持的能力，并且根据业务需要有选择的使能设备的能力。

应用可以通过调用enableVirtualDevice来使能所需要使能的设备以及能力，如果需要同时使能设备多个能力，可以同时传入多个能力。

应用使能的结果可以通过subscribe接口传入的回调对象获得。

```
mVirtualDeviceManager.enableVirtualDevice(deviceId, EnumSet.of(CAMERA), null); 
//调用subscribe时传入的observer对象 
private IVirtualDeviceObserver observer = new IVirtualDeviceObserver() { 
    //虚拟设备状态变化时的回调通知 
    @Override 
    public void onDeviceStateChange(VirtualDevice virtualDevice, int returncode) { 
    } 
    //虚拟设备能力状态变化时的回调通知 
    @Override 
    public void onDeviceCapabilityStateChange(VirtualDevice virtualDevice, Capability capability, int returncode) { 
        if (returncode == EventType.EVENT_DEVICE_CAPABILITY_ENABLE) { 
            //当设备能力使能成功时，应用处理使能成功流程 
            onEnable(virtualDevice, capability); 
        } else if (returncode == EventType.EVENT_DEVICE_CAPABILITY_DISABLE) { 
            //当设备能力去使能成功时，应用处理去使能成功流程 
            onDisable(virtualDevice, capability); 
        } else { 
            //当虚拟设备能力状态异常时，应用应处理异常流程 
            onError(virtualDevice, capability, returncode); 
        } 
    } 
};
```

1. 虚拟Display能力。 使用如下代码即可使能设备的虚拟Display能力。

   ```
   mVirtualDeviceManager.enableVirtualDevice(deviceId, EnumSet.of(DISPLAY), null);
   ```

   虚拟Display能力在应用使能Display能力之后就会生效，即手机屏幕显示的画面会在虚拟设备的屏幕上显示。

   应用也可通过操作虚拟设备的Display对象，将指定内容显示在虚拟设备的屏幕上显示，从而使虚拟屏幕和手机屏幕显示不同的内容。

   ```
   //获取DisplayManager 
   DisplayManager displayMgr = getApplicationContext().getSystemService(DisplayManager.class); 
   //使用DisplayManager获取所有display对象 
   displays = displayMgr.getDisplays(); 
   if (displays != null) { 
       for (Display display : displays) { 
           //获取Display对象的ID和name 
           int id = display.getDisplayId(); 
           String name = display.getName(); 
           //虚拟设备的displayId大于默认display对象的id，且名称与虚拟设备名称相同 
           if ((id > Display.DEFAULT_DISPLAY) && (device.getDeviceName().equals(name))) { 
               //获取到虚拟屏幕的display对象，可以使用Android标准接口操作显示 
               ...... 
           } 
       } 
   }
   ```

2. 虚拟Mic能力。 使用如下代码即可使能设备的虚拟Mic能力。

   ```
   mVirtualDeviceManager.enableVirtualDevice(deviceId, EnumSet.of(MIC), null);
   ```

   虚拟Mic能力在应用使能Mic能力之后就会生效。只要使能了虚拟Mic，使用所有的Andriod音频录音接口采集的声音都会使用虚拟设备的Mic采集。
3. 虚拟Speaker能力。 使用如下代码即可使能设备的虚拟Speaker能力。

   ```
   mVirtualDeviceManager.enableVirtualDevice(deviceId, EnumSet.of(SPEAKER), null);
   ```

   虚拟Speaker能力在应用使能Speaker能力之后就会生效。只要使能了虚拟Speaker，使用所有的Andriod音频播放接口播放的声音都会使用虚拟设备的Speaker播放。
4. 虚拟Camera能力。 使用如下代码即可使能设备的虚拟Camera能力。

   ```
   mVirtualDeviceManager.enableVirtualDevice(deviceId, EnumSet.of(CAMERA), null);
   ```

   虚拟Camera能力使能后，应用可以通过getData接口获取虚拟设备上虚拟Camera的id。和本地前后置摄像头一样，应用可以通过Android的getCameraCharacteristics接口获取虚拟Camera的属性信息，以及通过Android的openCamera接口打开虚拟Camera。

   ```
   //通过虚拟设备的getData接口获取设备虚拟Camera的ID 
   String cameraId = device.getData(Constants.ANDROID_CAMERAID_FRONT); 
   //使用CameraManager的getCameraCharacteristics接口获取虚拟Camera的属性信息 
   CameraManager manager = (CameraManager)getSystemService(Context.CAMERA_SERVICE); 
   CameraCharacteristics characteristics = manager.getCameraCharacteristics(cameraId); 
   //使用CameraManager的openCamera接口打开虚拟Camera 
   manager.openCamera(cameraId, mStateCallback, null);
   ```

   当前虚拟Camera仅支持Android Camera2 API预览的基本方法，不支持拍照和录像场景，对于Camera预览中的参数配置，仅支持运行中配置帧率。如果应用有其他场景应用，开发者可发送邮件至[devConnect@huawei.com](mailto:devConnect@huawei.com)联系我们。

   支持的功能点包括以下：

   ```
   CameraManager.getCameraCharacteristics()
   CameraManager.openCamera()
   CameraDevice.createCaptureRequest(CameraDevice.TEMPLATE_PREVIEW)
   CameraDevice.createCaptureSession()
   CameraCaptureSession.setRepeatingRequest()
   CameraDevice.close()
   CameraCaptureSession.close()
   ```

5. 虚拟Sensor能力。 使用如下代码即可使能设备的虚拟Sensor能力。

   ```
   mVirtualDeviceManager.enableVirtualDevice(deviceId, EnumSet.of(SENSOR), null);
   ```

   虚拟Sensor能力在应用使能Sensor能力之后就会生效。只要使能了虚拟Sensor，使用所有的Sensor的能力，当前虚拟Sensor已支持心率计、陀螺仪、加速度计、气压计数据的上报。

   使能虚拟Sensor成功后，可以通过下面的代码获取的Sensor服务。

   ```
   SensorAgent kitService = (SensorAgent) DvKit.getInstance().getKitService(VIRTUAL_SENSOR_SERVICE);
   ```

   获取到虚拟Sensor服务后，可以查看对应设备的Sensor列表。

   ```
   List<VirtualSensor> sensorList = kitService.getSensorList(deviceId, TYPE_HEART_RATE);
   ```

   然后根据业务的需要，选择特定的Sensor进行数据订阅。

   ```
   private IVirtualSensorDataListener sensorDataListener = new IVirtualSensorDataListener() {
       @Override
       public void onSensorChanged(VirtualSensorData data) {
           Log.d(TAG, "onSensorChanged: " + data);
       }
   };
   SensorAgent kitService = (SensorAgent) DvKit.getInstance().getKitService(VIRTUAL_SENSOR_SERVICE);
   kitService.subscribeSensorDataListener(sensorDataListener, virtualSensor, SensorAgent.SENSOR_DELAY_FAST);
   ```

   应用订阅特定的虚拟Sensor数据后， 就可以定期接收到虚拟Sensor的数据。  
   ![](https://media:801773457107191404)  
   1. 当前虚拟Sensor已支持TYPE_HEART_RATE（心率计）、TYPE_ACCELEROMETER（加速度计）、TYPE_GYROSCOPE（陀螺仪）、TYPE_PRESSURE（气压计）类型，上报周期有快速（60ms）、正常（200ms）、缓慢（5s）三档可选。
   2. 使用虚拟Sensor前，调用虚拟Sensor的接口要求该应用必须要具有android.permission.BODY_SENSORS权限和com.huawei.permission.DISTRIBUTED_VIRTUALDEVICE权限。
   3. 使用虚拟Sensor前，调用虚拟Sensor的接口要求该应用必须已经在[华为开发者联盟](https://developer.huawei.com/consumer/cn/)上申请了com.huawei.dv.permission.VIRTUALSENSOR权限。
6. 虚拟Vibrator能力。 使用如下代码即可使能设备的虚拟Vibrator能力。

   ```
   mVirtualDeviceManager.enableVirtualDevice(deviceId, EnumSet.of(VIBRATE), null);
   ```

   虚拟Vibrator能力在应用使能Vibrator能力之后就会生效。只要使能了虚拟Vibrator，然后就可以调用对应的虚拟设备上的Vibrator下发震动指令。

   使能虚拟Vibrator成功后，可以通过下面的代码获取的Vibrator服务。

   ```

   获取到虚拟Vibrator服务后，可以查看对应设备的Vibrator列表。

   vibratorService.getVibrateList(selectedItem.getDeviceId());

   然后根据业务的需要，选择特定的Vibrator下发震动指令。

   ```
   vibrator.vibrate(2000); // 马达振动2s
   ```

   ![](https://media:801773457107216405)  
   1. 使用虚拟Vibrator前，调用虚拟Vibrator的接口要求该应用必须要具有android.permission.VIBRATE权限和com.huawei.permission.DISTRIBUTED_VIRTUALDEVICE权限。
   2. 使用虚拟Vibrator前，调用虚拟Vibrator的接口要求该应用必须已经在[华为开发者联盟](https://developer.huawei.com/consumer/cn/)上申请了com.huawei.dv.permission.VIRTUALVIBRATOR权限。

   mVirtualDeviceManager.enableVirtualDevice(deviceId, EnumSet.of(NOTIFICATION), null);

   虚拟Notification能力在应用使能Notification能力之后就会生效。只要使能了虚拟Notification，则可以使用虚拟Notification的接口给设备发送通知。

8. 设备参数配置。 使能设备能力之后，可以通过VirtualDevice的setData方法对设备下发参数配置，例如：

   使用如下代码即可开启虚拟camera自动旋转。

   ```
   Map<String, Object> params = new HashMap<String, Object>();
   params.put(Constants.CAMERA_POSITION, Constants.ANDROID_CAMERAID_BACK);

#### 马达的使用

1. 马达列表获取。 获取选定设备的马达列表，需要申请分布式马达权限"com.huawei.permission.DISTRIBUTED_VIRTUALDEVICE"以及Android马达权限"android.permission.VIBRATE"。

   ```
   VibratorService vibratorService = (VibratorService) DvKit.getInstance().getKitService(VIRTUAL_VIBRATE_SERVICE);
   List<VirtualVibrator> vibrateList = vibratorService.getVibrateList(deviceId);
   ```

2. 马达振动。 发送马达振动指令，需要申请分布式马达权限"com.huawei.permission.DISTRIBUTED_VIRTUALDEVICE"以及Android马达权限"android.permission.VIBRATE"，约束条件《[API接口文档](https://developer.huawei.com/consumer/cn/doc/connectivity-References/overview-0000001051392757)》。

   ```
   vibrator.vibrate(2000); // 振动2000ms
   vibrator.vibrate(new long[]{2000, 500, 1000, 200}, 0); // 振动2000ms，暂停500ms，振动1000ms,暂停200ms，一直重复
   vibrator.vibrate(new long[]{2000, 500, 1000, 200}, 1); // 振动2000ms，暂停500ms，振动1000ms,暂停200ms，遍历一次
   ```

3. 取消马达振动。 发送取消马达振动指令，需要申请分布式马达权限"com.huawei.permission.DISTRIBUTED_VIRTUALDEVICE"以及Android马达权限"android.permission.VIBRATE"。

   ```
   vibrator.cancel();
   ```

#### Sensor的使用

1. Sensor列表获取。 获取选定设备的Sensor列表，需要申请分布式Sensor权限"com.huawei.permission.DISTRIBUTED_VIRTUALDEVICE"以及申请Android的Sensor权限"android.permission.BODY_SENSORS"。当前可请求的Sensor类型包括心率计、加速度计、陀螺仪、气压计。

   ```
   SensorAgent kitService = (SensorAgent) DvKit.getInstance().getKitService(VIRTUAL_SENSOR_SERVICE);
   List<VirtualSensor> sensorList = kitService.getSensorList(selectedItem.getDeviceId(),VirtualSensor. TYPE_HEART_RATE);
   ```

2. 订阅Sensor数据监听。 订阅Sensor数据监听，需要申请分布式Sensor权限"com.huawei.permission.DISTRIBUTED_VIRTUALDEVICE"以及申请Android的Sensor权限"android.permission.BODY_SENSORS"。订阅数据监听时，上报周期共有快速（60ms）、正常（200ms）、缓慢（5s）三档可选。

   ![](https://media:801773457107247406)  
   * 订阅Sensor数据时若设置的上报周期小于设备所支持的最小上报周期，会返回设备能力不支持的错误码（ReturnCode.ERROR_CODE_DEVICE_NOT_SUPPORT），请根据情况重新设置。

   ```
   private IVirtualSensorDataListener sensorDataListener = new IVirtualSensorDataListener() {
       @Override
       public void onSensorChanged(VirtualSensorData data) { 
       }
   };
   SensorAgent kitService = (SensorAgent) DvKit.getInstance().getKitService(VIRTUAL_SENSOR_SERVICE);
   // 使用数据监听接口，上报周期设为快速（60ms）
   kitService.subscribeSensorDataListener(sensorDataListener, virtualSensor, SensorAgent.SENSOR_DELAY_FAST);
   ```

3. 取消订阅Sensor数据监听。 取消订阅Sensor数据监听，需要申请分布式sensor权限"com.huawei.permission.DISTRIBUTED_VIRTUALDEVICE"以及申请Android的Sensor权限"android.permission.BODY_SENSORS"。

   ```
   SensorAgent kitService = (SensorAgent) DvKit.getInstance().getKitService(VIRTUAL_SENSOR_SERVICE);
   kitService.unSubscribeSensorDataListener(sensorDataListener);
   ```

#### 消息通知的使用

先设置消息内容，然后调用发送消息的接口发送消息到设备。

目前有两种消息模板：

1. 通用消息模板COMMON_LAYOUT_TEMPLATE、
2. 导航消息模板GUIDE_LAYOUT_TEMPLATE。

通用消息模板COMMON_LAYOUT_TEMPLATE是预留模板。

当前只支持导航消息模板GUIDE_LAYOUT_TEMPLATE的显示。

对应的需要设置的属性有：KEY_PACKAGE_NAME、KEY_GUIDE_DISTANCE、KEY_DISTANCE_UNIT、KEY_DIRECTION_INDEX、KEY_GUIDE_TEXT以及KEY_VIBRATE，其中KEY_VIBRATE不设置时默认为普通震动提醒NORMAL_VIBRATION。具体请参见《[API接口文档](https://developer.huawei.com/consumer/cn/doc/connectivity-References/dv-notification-0000001052227330#section166908324161)》。

1. 设置消息体的属性。 消息体通过setNotificationProperty方法进行统一设置，以导航消息为例：先申请一个Map对象，然后设置模板对应的属性值KEY_PACKAGE_NAME、KEY_GUIDE_DISTANCE、KEY_DISTANCE_UNIT、KEY_DIRECTION_INDEX、KEY_GUIDE_TEXT以及KEY_VIBRATE，之后调用setNotificationProperty方法传入模板以及已经设置好的Map对象。最后调用doNotification方法进行消息通知的发送。

   ```
   DvNotificationService notificationService =(DvNotificationService)HiWearActivity.mDvKit.getKitService(VIRTUAL_NOTIFICATION_SERVICE);
   DvNotification notification = new DvNotification();
   Map<String, Object> notificaitonProperty = new HashMap<>();
   notificaitonProperty.put(DvNotification.KEY_PACKAGE_NAME, “packageName”); // 设置三方应用的包名，用于区分消息的来源
   notificaitonProperty.put(DvNotification.KEY_GUIDE_DISTANCE, 500); // 设置导航的距离
   notificaitonProperty.put(DvNotification.KEY_DISTANCE_UNIT, “m”); // 设置导航的单位
   notificaitonProperty.put(DvNotification.KEY_DIRECTION_INDEX, 1); // 设置导航图标的索引
   notificaitonProperty.put(DvNotification.KEY_GUIDE_TEXT, “turn left”); // 设置消息导航的文本
   notificaitonProperty.put(DvNotification.KEY_VIBRATE, DvNotificationService.NORMAL_VIBRATION); // 设置消息提醒的震动方式
   notification.setNotificationProperty(DvNotificationService.GUIDE_LAYOUT_TEMPLATE,notificaitonProperty); // 通过该接口设置导航消息的属性
   int res = notificationService.doNotification(deviceId, notificationId, notification, DvNotificationService.ADD_NOTIFY); // 发送消息通知到设备的接口
   ```

2. 获取消息体的属性。 设置好消息属性，如果需要查看已设置的消息属性，可通过接口getNotificationProperty，传入正确模板类型进行查询。

   ```
   String notificationProperty = notification.getNotificationProperty(DvNotificationService.GUIDE_LAYOUT_TEMPLATE); //用于获取已设置的导航类消息属性值，notification定义参考上个步骤
   ```

#### 设备能力去使能

当应用不想使用虚拟设备能力时，可以通过调用[disableVirtualDevice](https://developer.huawei.com/consumer/cn/doc/connectivity-References/virtual-device-manager-0000001051787342#section9766131822311)接口来去使能虚拟设备能力，释放底层虚拟设备资源。

```
mVirtualDeviceManager.disableVirtualDevice(deviceId, EnumSet.of(CAMERA));
```

#### 服务断连

当应用不再需要使用DVEngine所提供的服务时，可以通过调用disConnect接口来断开和服务的连接，从而释放底层资源。

```
DvKit.getInstance().disConnect();
```

#### 异常场景

* 由于开发者集成的DVEngine包，在非华为设备、华为EMUI 10.1以下设备上无具体实现，其接口会抛出NoClassDefFoundError，所有开发者需要对此异常进行捕获处理，只有在华为正确版本的设备上运行后才能调用具体实现。

* 在调用接口时如果接口返回ERROR_CODE_NO_PERMISSION错误码，说明应用没有合法权限调用接口，请参见[接入准备](https://developer.huawei.com/consumer/cn/doc/connectivity-Guides/add-permissions-0000001052548539)中"申请权限"章节处理。

* 在调用接口时如果接口返回ERROR_CODE_UPGRADE错误码，说明当前连接设备版本过低，无法匹配手机侧设备虚拟化能力，需要升级设备侧版本，应用App在接收到此错误码时，需要提醒用户对连接设备进行升级。

* 如果应用APP1使能了外部设备1的能力1，在应用APP2也使能设备1的能力1时，会返回ERROR_CODE_BUSY，此时应用APP2需要提醒用户相应的错误信息。

* 如果应用APP1使能了外部设备1的能力1，如果应用APP2此时去使能设备1的能力1，则会返回ERROR_CODE_CAN_NOT_DISABLE，确保不同应用对设备能力使用的准确性。

* [startDiscovery](https://developer.huawei.com/consumer/cn/doc/connectivity-References/virtual-device-manager-0000001051787342#section962519012018)接口和[getVirtualDevicesList](https://developer.huawei.com/consumer/cn/doc/connectivity-References/virtual-device-manager-0000001051787342#section1559914385227)接口均为获取虚拟设备的接口，其中startDiscovery接口为异步接口，调用此接口会触发底层服务的发现流程去发现周边的虚拟设备，发现的虚拟设备会通过回调接口返回。getVirtualDevicesList接口为同步接口，此接口直接返回之前通过startDiscovery接口发现的设备，并不会真正触发一次发现。

* DV Engine对外的接口都要求有华为联盟授予的能力权限以及对应手机侧的权限，例如：如果应用需要使用DV Engine提供的摄像头能力，也就是需要使用CAMERA能力，需要在[开发者联盟](https://developer.huawei.com/consumer/cn/)向华为申请BASE和VIRTUALCAMERA的权限，同时需要用户授予android.permission.CAMERA权限，如果应用没有对应权限，则调用DV Engine的接口的时候会抛出异常SecurityException("NO appName ACCESS DMSDP")，应用需要在对应接口中处理该异常。

* 应用没有主动停止服务，但是接收到EVENT_DEVICE_CAPABILITY_DISABLE事件，通知底层出现使能服务。此时应用如果没有主动下发停止服务并且应用的进程没有出现异常，应用可以根据当前用户的使用情况决策是否停止服务，如果应用认为可以停止服务，则直接断开当前提供的服务；如果应用需要继续服务，则需要重新调用使能接口[enableVirtualDevice](https://developer.huawei.com/consumer/cn/doc/connectivity-References/virtual-device-manager-0000001051787342#section146237599223)重新使能对应的能力。

* 应用没有主动停止服务，但是接收到Camera服务的EVENT_DEVICE_CAPABILITY_DISABLE事件，这种情况可能是设备出现异常，比如设备断电。此时可根据当前业务需要进行异常处理，比如切回本地相机等。
