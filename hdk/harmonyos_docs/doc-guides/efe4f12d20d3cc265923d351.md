# 基础体验要求

折叠屏相较于普通手机来说存在两个较为明显的特点：一是可以随时折叠展开，二是展开后屏幕将会变大。

为了能充分利用折叠屏的上述特点，为用户提供良好的使用体验，我们在折叠屏开发过程之中需要考虑以下体验诉求：

     1. **体验连****续**

屏幕可随时折叠展开，在体验上要保证用户体验的连续性，应用需要遵从屏幕显示的兼容和应用状态的连续。

**屏幕兼容：** 由于屏幕尺寸发生变化，应用需要适当对屏幕的内容布局进行优化调整。

**应用连续：** 应用在折叠与展开状态切换的过程中能够保持正常运行。

     2. **体验增值**

屏幕变大后，用户体验在某些方面有增值。具体体现在以下方面：

**更多内容** ：大尺寸屏幕可显示更多内容，提高显示和操作的效率。

**更加沉浸** ：大尺寸屏幕可显示更清晰的细节，适合图片浏览、视频欣赏、游戏等应用和场景。

**多任务并行** ：多个窗口可同时在大尺寸屏幕内展示，为用户多任务并行提供了直观高效的方式。

为实现以上体验诉求，我们需要在config.json进行如下配置：
            
            "module": {
              "resizeable": true,
                "metaData": {
                  "customizeData" : [{
                    "name" : "com.huawei.******.multiwindow.multiinstance.enable",
                    "value" : "true"
                  }]
                },
              ……
             
              "abilities": [{
                  "configChanges": ["orientation","layout","density","size","smallestSize"],
                  "metaData": {
                    "customizeData": [
                      {
                        "name": "hwc-theme",
                        "value": "****8hwext:style/Theme.Emui.Light.NoTitleBar.Fullscreen"
                      }
                    ]
                  },
                  ……
                }
              ]
            }

配置项说明：

com.huawei.******.multiwindow.multiinstance.enable：支持多任务能力，开启智慧分屏。

******hwext:style/Theme.Emui.Light.NoTitleBar.Fullscreen：全屏无状态栏。

configChanges相关配置或者想要了解更多配置，可以查看：[configChanges配置说明](https://developer.harmonyos.com/cn/docs/documentation/doc-guides/package-structure-0000001333321033)。

根据前文提到的体验诉求，为了保证折叠屏的体验连续，需要我们在折叠屏开发过程中满足以下基础体验要求。

#### 信息展示完整

     * 折叠屏的文字、图片、视频等视觉元素不应发生变形、裁剪、显示不全等信息缺失。
     * 一般情况下，展开态不应出现页面内的内容元素数量减少，或图形化元素模糊、分辨率下降或视觉体量减小等损失，同时要确保展开态的内容元素不少于折叠态内容元素信息量的四分之三。

#### 交互不中断

展开态不应出现操作步骤增加，操作时间延长，操作更复杂等体验下降的情况。不应破坏应用内原有的沉浸式体验，避免仅仅为了扩充内容或强制应用分屏而过度改变用户体验和用户习惯的情况发生。

在折叠态和展开态之间切换时，需要保证当前任务的连续性。切换之前的任务和相关状态能保存、延续，或能够快速恢复，给用户提供连续的体验。不发生闪退、重启等异常。

折叠屏交互不中断体验的相关示例代码请参见：[交互不中断示例代码](https://developer.harmonyos.com/cn/docs/documentation/doc-guides/foldable-screen-samples-interaction-0000001392180910)

#### 横竖屏旋转适配

由于折叠屏在展开态下的屏幕显示比例接近正方形，基于此特征，我们在开发时需要做如下考虑：

支持展开态横屏显示。展开态横竖屏布局一致。除部分特殊界面外，建议应用在横屏和竖屏下保持一样的布局。

#### 字体/图标适配

展开态图标和字体大小不应发生明显变化，在保证可读性的基础上，建议保持跟折叠态一样的大小。若一定要发生大小变化，则最大不要超过1.2倍。为确保有较好的可读性，展开态单屏文本长度不超过40字，推荐保持在36字左右。

#### 图片/视频适配

展开态的图片/视频应适应页面的宽度、间距、列数等因素来进行适配显示，不能造成信息量的明显减少。

常见的图片/视频可以分为三种类型：
     1. **运营类图片/视频，通常是Banner的运营广告或分类入口。**
        * 在展开态下，运营类内容的显示列数会增加。
        * 若展开态放大显示图片/视频，务必确保该图片/视频不超过屏幕的1/2高度。

以下为运营类图片/视频的效果示例，相关示例代码请参见：[运营类图片/视频](https://developer.harmonyos.com/cn/docs/documentation/doc-guides/foldable-screen-samples-media-0000001391701846#section9272196105014)

        * 宫格或瀑布流布局的图片/视频/卡片：建议在展开态增加显示列数，横向图列数+1；竖向图列数+2。具体列数由三方确定，但避免信息过密（一般最多不超过6列）和信息过大（宫格中单张卡片超过1/2屏幕高度）。
        * 上下图文布局：建议在展开态平铺显示更多图片/视频内容或让图片/视频内容居左/居右/居中对齐。单张图片/视频最高不超过屏幕的1/3高度，但是采用宫格样式聚合显示的图片/视频整体，最高不超过屏幕的1/2高度。

弹出框在开发过程中较为常见，例如红包、广告等场景均使用到了弹出框，建议展开态和折叠态弹出框保持相同的大小，或大小变化最大不超过1.2倍。

#### 其他控件适配

对于页面中的其他界面元素，例如按钮、输入框等，建议展开折叠时高度按照字体大小的缩放比例进行缩放，或大小变化最大不超过1.2倍，而宽度则根据元素本身的响应式规则进行设计，部分元素（例如按钮）保持等比缩放，部分元素（例如列表、输入框）对宽度进行适当延伸，最宽不超过整个窗口的宽度。

以下为效果示例，示例代码请参见：[其他控件适配示例代码](https://developer.harmonyos.com/cn/docs/documentation/doc-guides/foldable-screen-samples-component-0000001391861370)
