# 故障分析

资源泄漏目前支持ArkTS内存泄漏，Native内存泄漏、FD泄漏及GPU泄漏，系统检测出内存超过一定阈值进而导致的异常退出，并上报事件及对应的日志。

主页面提供问题列表及趋势分析等功能；问题列表页面提供全方位的故障筛选能力，支持应用版本、系统版本、机型、时间等维度过滤能力；同时提供OOM率、OOM次数、OOM设备数的趋势分析能力；Top问题列表基于故障特征进行聚合，提供多个维度的聚合列表，默认基于故障发生次数排序，方便开发者聚焦头部问题快速提升应用质量。

## 问题筛选

在资源泄漏问题列表中支持多个维度问题筛选能力，主要如下：

![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/ab/v3/Gml1XT72QLiyBy2ST1EH1w/zh-cn_image_0000002581570858.png?HW-CC-KV=V1&HW-CC-Date=20260916T033630Z&HW-CC-Expire=31536000000&HW-CC-Sign=8087EC044DDC4FDE0583BD5DF86A7825D1197B43C3A0C211C87CBD187582B330)

以下为资源泄漏故障图表对应的筛选条件说明：

|筛选条件|说明|
|:-----|:----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
|应用版本|应用的版本标识|
|系统版本|应用适配的系统版本|
|设备型号|唯一标识设备硬件规格和版本的代码，例如：ALN-AL00|
|时间范围|筛选数据的时间段，支持以下数据聚合粒度： * 天：最长跨度30天，时间支持按天调整 * 小时：最长跨度7天，时间支持按小时调整 * 分钟：最长跨度2天，时间支持按分钟调整|
|系统发布类型|鸿蒙OS系统的发布类型，候选值如下： * Canary：早期预览版本 * Beta：公开发布的测试版本 * Release：正式发布版本|
|ROM版本|设备终端当前运行的操作系统固件版本|
|泄漏类型|泄漏的分类类型，候选值如下： * MEMORY_LEAK：内存泄漏 * PSS_MEMORY：Native内存泄漏 * S_LEAK： JS内存泄漏 * RSS_LEAK：进程实际占用物理内存泄漏 * GPU_LEAK：GPU内存泄漏 * GPU_RSS_LEAK：RSS中GPU部分内存泄漏 * KERNEL_MEMORY：内核内存泄漏 * FD_LEAK：句柄泄漏 * THREAD_LEAK：线程泄漏|

> 说明
>
> * 当前只支持ArkTS泄漏、Native泄漏、GPU泄漏及FD泄漏的问题分析。
> * 由于泄漏问题依赖对应日志分析，但端侧日志上报存在限制，可能可分析的故障数少于故障事件数。

## 资源泄漏信息详情

### TOP问题列表

在时间范围与筛选维度的条件下，所有崩溃日志按照崩溃摘要进行聚合，展示了故障特征ID、问题定界、泄漏类型、故障模块、发生次数(占比)、影响设备(占比)，最大泄漏数，同时支持查看问题详情，问题备注及状态处理，默认每页10条翻页，聚合结果展示内容具体说明如下：

* 问题特征ID：基于故障类型、错误类型、故障模块维度信息进行哈希生成特征ID，用于问题聚合。
* 问题定界：基于故障模块及专家规则分析给出问题定界结论，初步定界为应用问题或系统问题。
* 泄漏类型：泄漏问题的分类类型，包括JS_LEAK、PSS_MEMORY、GPU_LEAK和FD_LEAK。
* 故障模块：给出问题的关键堆栈或问题原因，一般为应用的业务堆栈。
* 发生次数：指定筛选条件下同一聚合根因的问题出现的次数。
* 影响设备：指定筛选条件下同一聚合根因的问题出现的设备数。
* 最大泄漏数：该类问题最大的泄漏数量，JS_LEAK、GPU_LEAK、MEMORY_LEAK为内存申请次数，FD_LEAK为文件句柄数。
* 问题状态：用户可以给聚合的问题设置处理状态，包括"未处理"，"已忽略"，"处理中"，"已修复"。
* 优先级：设置问题的优先级，包括"高"，"中"，"低"。
* 问题备注：针对问题进行备注描述。

### ArkTS内存泄漏

**泄漏对象**：分析平台分析出最有可能泄漏的对象，这些对象往往RetainedSize异常的大，或者数量异常的多。点击不同的泄漏对象卡片可切换查看不同的内容。

## 现场数据

内存占比会通过饼图及柱状图的形式显示Native堆的占比情况。PSS（Proportional Set Size）指的是进程实际占用的物理内存总量，计算方式为：将共享内存按使用该内存的进程数量进行分摊后，再将其与进程私有内存相加。SWAP PSS是鸿蒙（HarmonyOS）内存分析中的一个关键指标，用于衡量进程在交换分区（SWAP）中占用的实际物理内存大小。
