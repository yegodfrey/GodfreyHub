# 页面路由

## 接口声明

无需声明

## 导入模块

在调用接口页面的<script>部分增加如下配置。

```screen
import router from '@system.router'
```

或

```screen
var router = require("@system.router")
```

## 使用限制

|限制条件|说明|
|:---|:-----------|
|适用终端|手机、平板、智慧屏、车机|
|适用区域|全球|

## 接口定义

|接口|描述|
|:----------------------------------------------|:--------------------------|
|[router.push(OBJECT)](#section19418113011289)|跳转到设置的页面。|
|[router.replace(OBJECT)](#section0654153283717)|跳转到应用内的某个页面，当前页面无法返回。|
|[router.back(OBJECT)](#section11901104014429)|返回上一页面。|
|[router.clear()](#section1540623114411)|清空所有历史页面记录，仅保留当前页面，即保留栈顶页面。|
|[router.getLength()](#section209802047104412)|获取当前页面栈的页面数量。|
|[router.getPages()](#section1232234864519)|返回当前页面栈列表。|
|[router.getState()](#section17761173615484)|获取当前页面状态。|

### router.push(OBJECT)

**描述**

跳转到设置的页面。
> 说明
>
> 页面跳转传递的数据可能被其他应用获取，建议不要传递安全敏感度较高的数据，禁止在后台调用。

**OBJECT参数**
> 说明
>
> OBJECT参数总大小不能超过128KB。

|参数|类型|是否必填|说明|
|:-----|:-----|:---|:---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
|uri|string|是|要跳转到的uri，可以是下面的格式： * 包含scheme的完整uri；目前支持的scheme有tel，sms，mailto和hap（1035+），例如tel:10086，mailto:abc@gmail.com，hap://app/com.company.app/index?param1=value1 * 以"/"开头的应用内页面的路径；例：/about * 以非"/"开头的应用内页面的名称；例：About * 特殊的，如果uri的值是"/",则跳转到path为"/"的页，没有则跳转到首页 * hap://settings/permission_manager，跳转到快应用的权限管理界面（1035+） * hap://settings/permissions，跳转到快应用的权限管理页面（1107+） * hap://settings/location_source_manager，跳转到手机系统的位置管理界面（1035+） * hap://settings/5g，跳转到5G开关设置页面（1080+） * hap://settings/feedback，跳转到统一菜单下的"问题与建议"页面（1103+） 注意 > 在加载器上调试无效，上架后生效。 支持包含scheme的完整uri。对于带有scheme的uri，处理流程如下： 1. 查找app下所有page的filter设置来选择合适的page处理请求（参见"[manifest文件](https://developer.huawei.com/consumer/cn/doc/quickApp-References/quickapp-manifest-0000001073698621)"） 2. 如果没有合适的page能够处理请求，会使用默认策略来处理请求。目前默认策略支持对http、https、internal这几种scheme的处理 3. 如果默认策略也不能处理请求，会尝试使用系统中的应用来处理请求 4. 如果没有系统应用可以处理请求，会抛弃请求 默认策略的处理逻辑： 1. 如果scheme是http/https，会用内置的web页面打开网页，不支持在卡片中打开网页 2. 如果scheme是internal（参见"[文件组织](https://developer.huawei.com/consumer/cn/doc/quickApp-References/quickapp-filestructure-0000001074564510)"），会根据uri的文件扩展名来确定文件类型，再调用系统中的应用打开文件|
|params|object|否|跳转时需要传递的数据。参数可以在页面中通过this.param1的方式使用，param1为json中的参数名，param1对应的值会统一转换为String类型。|

**params说明：**

|参数|类型|是否必填|说明|
|:------------------------------------|:-----|:---|:-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
|___PARAM_LAUNCH_FLAG___(1050+)|string|否|快应用启动参数，目前仅支持"clearTask"，在启动目标页面时会清除除此页面外的其他页面。详细请参见"[页面启动模式](https://developer.huawei.com/consumer/cn/doc/quickApp-References/quickapp-startupmode-0000001073124559)"。|
|___PARAM_LAUNCH_NATIVE_FLAG___(1070+)|string|否|在打开原生应用页面时设置flag。默认值为newTask。可以根据需要设置多个flag，多个flag之间用 | 分割，例如newTask|clearTask、newTask|clearTop。 * newTask：引擎默认行为，与打开activity时携带 Intent.FLAG_ACTIVITY_NEW_TASK 参数行为保持一致。 * standard：使用activity打开的默认行为，将新打开的页面入栈到快应用的栈里，点击返回后仍然在快应用中。与打开activity时不携带flag保持一致。 * broughtToFront：与打开activity时携带 Intent. FLAG_ACTIVITY_BROUGHT_TO_FRONT 参数行为保持一致。 * clearTask：与打开activity时携带 Intent. FLAG_ACTIVITY_CLEAR_TASK 参数行为保持一致。 * singleTop：与打开activity时携带 Intent. FLAG_ACTIVITY_SINGLE_TOP 参数行为保持一致。 * clearTop：与打开activity时携带 Intent.FLAG_ACTIVITY_CLEAR_TOP 参数行为保持一致。|
|___PARAM_PAGE_ANIMATION___(1070+)|object|否|页面跳转时的动画类型。 > 说明 > 华为暂不支持，设置后无效果。|

**示例代码**

```screen
// launch phone app
router.push({
  uri: 'tel:10086'
});
// open page by path
router.push({
  uri: '/about',
  params: {testId:'1'}
});
// open page by name
router.push({
  uri: 'About',
  params: {testId:'1'}
});
// send sms
router.push({
  uri: 'sms:',
  params: {body:'test send message'}
});
```

### router.replace(OBJECT)

**描述**

跳转到应用内的某个页面，当前页面无法返回。
> 说明
>
> 页面跳转传递的数据可能被其他应用获取，建议不要传递安全敏感度较高的数据。

**OBJECT参数**

|参数|类型|是否必填|说明|
|:-----|:-----|:---|:--------------------------------------------------------------------------------------------------------------------|
|uri|string|是|要跳转到的uri，可以是下面的格式： 1. 以"/"开头的应用内页面的路径；例：/about 2. 以非"/"开头的应用内页面的名称；例：About 3. 特殊的，如果uri的值是"/"，则跳转到path为"/"的页，没有则跳转到首页|
|params|object|否|跳转时需要传递的数据，参数可以在页面中通过this.param1的方式使用，param1为json中的参数名，param1对应的值会统一转换为String类型。|

**示例代码**

```screen
router.replace({
  uri: '/test',
  params: {testId:'1'}
})
```

### router.back(OBJECT)

**描述**

返回上一页面。

**OBJECT参数（1020+）**

如果不传入参数，返回上一个页面，效果类似按手机返回键；传入参数请参见下表中的说明。

|参数|类型|是否必填|说明|
|:----|:-----|:---|:------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
|path|string|否|返回指定path的界面，可以是以下几种取值： 1. 不传该参数，如果 delta 设置了，则按 delta 设置的页面数层层返回；delta 未设置，和默认router.back()效果一样，返回上一页面。 2. 以"/"开头的应用内的页面，则返回到指定应用界面，例如：/about。如果设置了多个path，则返回到栈顶的path对应页面。 3. 特殊的，如果 path 设置的页面在应用内不存在，则返回上一个页面。 > 注意 > path不能设置返回到其他应用的页面。|
|delta|number|否|返回的页面数（华为扩展接口，非厂商联盟规范，非华为应用请勿使用），缺省为1，如果 delta 大于现有页面数，则返回到首页，假如同时填写了path和delta字段，则以path字段为准。|

**示例代码**

```screen
// A页面, open page by name
router.push({
    uri: 'B'
})
// B页面, open page by name
router.push({
    uri: 'C'
})
// C页面, open page by name
router.push({
    uri: 'D'
})
// D页面, open page by name
router.push({
    uri: 'E'
})
// E页面不传入页面路径，返回至D页面
router.back()
// D页面不传入页面名称，返回至C页面
router.back()
// C页面传入页面路径，返回至A页面
router.back({
    path: '/A'
})
```

### router.clear()

**描述**

清空所有历史页面记录，仅保留当前页面，即保留栈顶页面。

**示例代码**

```screen
router.clear()
```

### router.getLength()

**描述**

获取当前页面栈的页面数量。

**返回值**

|参数|说明|
|:-----|:---|
|string|页面数量|

**示例代码**

```screen
var length= router.getLength()
console.log("pages' length = "length);
```

### router.getPages()(1070+)

**描述**

返回当前页面栈列表。

**返回值**

|参数|说明|
|:----|:---------------------|
|array|页面栈列表是一个数组，数组每一项是一个对象。|

**Object参数列表**

|参数|类型|说明|
|:---|:-----|:----|
|name|string|页面名称。|
|path|string|页面路径。|

**示例代码**

```screen
// 调用getPages方法
let pages = router.getPages()
// 由于获得的值是一个JSON数组，所以直接打印是打印不出来的，可以使用下面的方法来打印
console.log("tag", printJSONArray(router.getPages()));
function printJSONArray(array) {
    let result = ""
    const suffix = ", "
    Array.isArray(array) && array.forEach((element, index) => {
        result = result + JSON.stringify(element) + (index === array.length-1 ? "" : ", ")
    })
    return result
}
```

### router.getState()

**描述**

获取当前页面状态。

**返回值**

|参数|类型|说明|
|:----|:-----|:-------------------------------------|
|index|string|当前页面在页面栈中的位置。 > 注意 > 请勿对index的类型进行强校验。|
|name|string|当前页面的名称|
|path|string|当前页面的路径|

**示例代码**

```screen
var page = router.getState()
console.log("page index = "+page.index);
console.log("page name = "+page.name);
console.log("page path = "+page.path);
```
