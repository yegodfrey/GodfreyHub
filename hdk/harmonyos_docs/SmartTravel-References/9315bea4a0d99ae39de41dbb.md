# Call State  
  
#### Scenario Overview

By default, the HiCar app provides the phone call service, which may conflict with the native phone call service of the head unit. To resolve the conflict, the head unit needs to notify the HiCar app of the local phone call state.

Solution to phone call conflicts:

     * The HiCar app sends the current call state to the head unit when the state on the phone changes.
     * When the head unit starts a local call, it notifies the HiCar app that the phone call service is unavailable. When the call ends, it notifies the HiCar app that the phone call service is available.

#### Data Type

504

#### API Version

1.0

#### API Definition

**Table 1** Call state APIsParameter | **Mandatory** | Type | **Description**  
---|---|---|---  
callState | Yes | int | HiCar call state sent by the HiCar app to the head unit:
     * **0** : Idle state.
     * **1** : Ringing (upon incoming calls).
     * **2** : Off-hook, dialing, or calling.  
isCallAvailable | Yes | boolean | The head unit notifies the HiCar app of the call service availability:
     * **true** : The HiCar phone call service is available.
     * **false** : The HiCar phone call service is unavailable.  
  
#### API Examples

Example: The HiCar app sends the current call state to the head unit when the state on the phone changes.
    
    {
        "callState":1
    }

Example: After the local call ends, the head unit notifies the HiCar app that the phone call service is available.
    
    {
        "isCallAvailable":true
    }
