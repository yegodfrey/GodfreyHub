# Detection of Foreground Apps  
  
#### Scenario Overview

The HiCar SDK notifies the head unit of apps running in the foreground, and the head unit then processes related service logic. For example, when the head unit is notified that a video app is running in the foreground, it adjusts the audio cache to ensure that the image and audio are always in sync.

#### Data Type

533

#### API Version

1.0

#### API Definition

**Table 1** Detection of foreground appsParameter | Mandatory | Type | Description  
---|---|---|---  
status | Yes | int | App status:
     * **1** : An app of the **appType** type is running in the foreground.
     * **0** : An app of the **appType** type is not running in the foreground.  
appType | Yes | string | App type to be detected. Currently, the value is always **video**.  
appName | Yes | string | Name of the app that is running in the foreground. Generally, the value is the app package name. If no app of the **appType** type is running in the foreground (that is, the value of **status** is **0**), this parameter is an empty string.  
RespCode | Yes | int | After receiving the notification about the **appType** type app from the HiCar SDK, the head unit processes related service logic and returns the result to HiCar on the mobile phone.
     * **100000** : Successful
     * **-100000** : Failed  
  
#### API Examples

The HiCar SDK notifies the head unit that an app of the **appType** type is running in the foreground. The sample code is as follows:
    
    {
        "status":1,
        "appType":"video",
        "appName":"com.huawei.himovie"
    }

The HiCar SDK notifies the head unit that no app of the **appType** type is running in the foreground. The sample code is as follows:
    
    {
        "status":0,
        "appType":"video",
        "appName":""
    }

The head unit processes related logic and sends a message to the HiCar SDK. The sample code is as follows:
    
    {
       " RespCode":100000
    }
