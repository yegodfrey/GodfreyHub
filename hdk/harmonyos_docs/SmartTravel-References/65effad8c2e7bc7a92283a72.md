# HiCar in the Foreground/Background on the Converged Desktop

#### Scenario Overview

In the integrated desktop form, HiCar notifies the head unit of switching the HiCar app to the foreground or background based on the real-time scenarios. The typical scenarios are as follows:

     * When the phone is connected to the head unit via HiCar, HiCar may display pre-projection screens for user authorization before initializing services. Such screens include the Safe Driving Statement, Privacy Statement update confirmation, Super Privacy mode, and the Out of Box Experience (OOBE) screen. Pre-projection screens will display during the initial connection or when any update is available on any pre-projection screens. In this case, the head unit needs to display HiCar for users to confirm upon successful connection, and switch HiCar back to the background to process relevant service logic of the converged desktop.
     * When an app fails to be started (for example, when the network is poor, the music template screen fails to be loaded, or the user touches the confirm button on a failure prompt), the head unit needs to go back to its native screen and switch HiCar to the background.
     * Some apps provide a button for users to directly go back to the head unit screen. When a user touches an app icon on the converged desktop, and then touches such a button in the app, the head unit needs to switch HiCar to the background.

#### Data Type

532

#### API Version

1.0

#### API Definition

**Table 1** APIs for displaying HiCar in the foreground/background on the converged desktopParameter | Mandatory | Type | Description  
---|---|---|---  
ProjectAction | Yes | object | Whether to switch HiCar to the background. For details, please refer to Table 2.  
ProjectActionResp | Yes | object | Response data. For details, please refer to Table 3.  
  
**Table 2** ProjectActionParameter | Mandatory | Type | Description  
---|---|---|---  
Background | Yes | boolean | Whether to display HiCar in the background:
     * **true** : display HiCar in the background
     * **false** : display HiCar in the foreground
Specifically:
     * During the initial connection, the value of **Background** is **false**. After the user grants authorization on all pre-projection screens, HiCar sends a message to the head unit indicating that **Background** is set to **true**.
     * During non-initial connections, if the user does not grant authorizations on all pre-projection screens, the value of **Background** is **false**. After the user grants authorization on all pre-projection screens, HiCar sends a message to the head unit indicating that **Background** is set to **true**.
     * During non-initial connections, if the user grants authorizations on all pre-projection screens, the value of **Background** is **true**.  
  
**Table 3** ProjectActionRespParameter | Mandatory | Type | Description  
---|---|---|---  
RespCode | Yes | int | Response result:
     * **100000** : HiCar successfully switched to the foreground/background
     * **100001** : HiCar fails to switch to the foreground/background  
  
#### API Examples

When the head unit is connected to the phone, the HiCar app will automatically send a message to the head unit indicating whether to switch HiCar to the background, without requiring a request from the head unit. The sample code is as follows:
    
    {
        "ProjectAction" : {
            "Background" : false
        }
    }

After the head unit receives the message, it switches HiCar to the foreground if the parameter value is **false** , and switches HiCar to the background if the value is changed to **true** upon user authorization. The head unit sends a response message to the HiCar app. The sample code is as follows:
    
    {
        "ProjectActionResp" : {
            "RespCode" : 100000
        }
    }
