# Rust远程调试

由于使用Rust语言开发OpenHarmony系统服务需要在远端（Linux端）进行，调测时基本上采用的是植入Log的方式来定位问题，效率较为低下。

从4.0 Release版本起，DevEco Device Tool提供远程调测Rust代码能力，帮助开发者提高问题定位效率。

#### 前提条件

     * 在Visual Studio Code的插件管理窗口，搜索“CodeLLDB”插件并安装。
     * 已完成Rust工程的编译。
     * Windows环境中已下载SDK包并解压。
       * 发布版本的SDK下载路径可参考OpenHarmony官网的版本说明，例如[OpenHarmony 3.2 Release](https://docs.openharmony.cn/pages/v3.2/zh-cn/release-notes/OpenHarmony-v3.2-release.md/)。
       * 若您需要使用OpenHarmony Master分支的最新特性，可使用OpenHarmony CI提供的[每日构建](http://ci.openharmony.cn/dailys/dailybuilds)版本。

#### 操作步骤

     1. 编写Rust待调测文件。

该章节中的后续操作均以“build/rust/tests/test_dylib_crate”节点下的调测文件为例进行说明。

     2. 在TERMINAL中执行如下命令对待调测文件进行编译。

![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20240930102426.62916708116795230480224647811532:50001231000000:2800:C3DA339BDA9BB421E237839C678F9A3CC30FDCD525926419C3036E2EAD4DE6E9.png?needInitFileName=true?needInitFileName=true)

“build/rust/tests/test_dylib_crate:test_dylib_crate”为所编译组件的名称和路径，请根据实际情况替换。
            
            ./build.sh --product-name rk3568 --target-cpu arm64 --build-target build/rust/tests/test_dylib_crate:test_dylib_crate  --no-prebuilt-sdk

编译完成后，生成对应的二进制文件以及依赖文件：

        * /out/rk3568/exe.unstripped/common/common/test_dylib_crate
        * /out/rk3568/lib.unstripped/common/common/libsimple_printer_dylib.dylib.so（若调测文件不涉及依赖，则不会生成此依赖文件）

     3. 使用hdc工具将编译后的二进制文件推送至设备。

        1. 参考[使用远程hdc能力](https://device.harmonyos.com/cn/docs/documentation/guide/remote_hdc-0000001491837812)配置hdc工具，保证hdc服务连通性。
        2. 在“TERMINAL”中执行如下命令将系统分区挂载为可读写模式。

其中，“xxx.xxx.xxx.xxx:xxx”为Windows本地IP地址及hdc服务端口号（在[使用远程hdc能力](https://device.harmonyos.com/cn/docs/documentation/guide/remote_hdc-0000001491837812)中配置）。
               
               hdc -s xxx.xxx.xxx.xxx:xxx shell mount -o rw,remount /

        3. 推送编译文件至设备。
           * 开发者可使用“hdc file send”命令将步骤2生成的二进制文件推送至设备指定位置，命令格式为：
                 
                 hdc -s _hdc_client_ip:portid_ file send _binaryfile_ _savedpath_
                 hdc -s _hdc_client_ip:portid_ file send _libfile_ /system/lib/ (依赖文件必须推送至此路径)

例如：
                 
                 hdc -s 10.10.10.1:8710 file send /openharmony/out/rk3568/exe.unstripped/common/common/test_dylib_crate /data/local/tmp
                 hdc -s 10.10.10.1:8710 file send /openharmony/out/rk3568/lib.unstripped/common/common/libsimple_printer_dylib.dylib.so  /system/lib/

           * 开发者亦可使用hdc工具提供的文件传输窗口进行文件推送。

单击“PROJECT TASKS”下的“HDC”，打开设备文件系统界面，按照界面信息进行二进制文件和依赖文件的传输。

依赖文件必须推送至“/system/lib/”。

     4. 配置lldb-server工具。

        1. 打开“Project Settings”页面。
        2. 单击“Project Config”后的“manager”按钮。

![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20240930102426.41400533308110938292305882428403:50001231000000:2800:95F6A74C1389742152D97DE919B6EC7B99823A2B2E91064423FEA71B9AF61344.png?needInitFileName=true?needInitFileName=true)

        3. 在搜索框中输入“lldb”，勾选搜索结果中的“lldb_server_path”和“lldb_server_port”，单击“Confirm”。

![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20240930102426.75338518744757772084967129575931:50001231000000:2800:4016BA5F4189BCEE7325A28A3A9B5E2E63E0E29C24BA94CA8ED0BFBEDF89D4A1.png?needInitFileName=true?needInitFileName=true)

        4. 按照实际情况配置lldb_server的路径和端口号。

lldb_server可从下载的SDK包中获取，以OpenHarmony 4.0-Beta1版本为例，其自带的lldb_server的路径为“\ohos-sdk\linux\native-linux-x64-4.0.7.5-Beta1\native\llvm\lib\clang\15.0.4\bin”，请根据实际情况选择对应版本。

![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20240930102426.48257532486278284240991476415084:50001231000000:2800:6D96A6DB1156A6CFF5044C9592715DDF87EB7FFED84BEFDA2F135315C53422E5.png?needInitFileName=true?needInitFileName=true)

     5. 在“PROJECT TASKS”下单击“LLDB-Server”启动lldb服务。

![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20240930102426.42522944989336981492816861753514:50001231000000:2800:1ACF86C180057053EEFA8B4DD71612A4679744FED21794704440B1F92FA988B0.png?needInitFileName=true?needInitFileName=true)

在启动lldb服务之前，请确认远程计算机（Ubuntu开发环境）与本地计算机（Windows开发环境）为断开状态（**REMOTE DEVELOPMENT > Local PC**右边连接按钮为![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20240930102426.53127340174962140472135069972946:50001231000000:2800:D6A07832FE74D4FB055D4F85BDA838D0DB5F8EBEEEB93F4AFDE3227845C4924F.png?needInitFileName=true?needInitFileName=true)）。

     6. 配置Windows环境端口转发参数。

        1. 使用管理员权限打开Windows命令行工具。
        2. 执行“netsh interface portproxy show all”查看当前端口转发配置情况。

如存在配置，请执行delete命令清除当前配置：
               
               netsh interface portproxy delete v4tov4 listenaddress=x.x.x.x listenport=xxxx

        3. 执行add命令添加端口转发参数，并通过show命令确认配置成功。
               
               netsh interface portproxy add v4tov4 listenport=7789 listenaddress=0.0.0.0 connectport=7789 connectaddress=127.0.0.1

![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20240930102426.82182208991560022535802681936075:50001231000000:2800:339CAC5D4F50E282E770E8DAF794C2818F42940D499B48A694CDBF9E6F104A05.png?needInitFileName=true?needInitFileName=true)

     7. 获取进程ID并修改配置文件。

        1. 获取进程ID。
           1. 在“PROJECT TASKS”中单击对应开发板下的“HDC”，在“TERMINAL”中执行如下命令进入设备文件系统。
                  
                  ./hdc -s _Windows本地IP地址_ :_hdc服务端口号_ shell

           2. 执行“ps -ef|grep lldb”确认lldb服务已启动。

![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20240930102426.43208780193482998877919604289847:50001231000000:2800:73DBEB7BD79C25CCFEC51CBE62546C08A32BF0907989EEE6895898F1D37B2A8C.png?needInitFileName=true?needInitFileName=true)

           3. 进入步骤3中推送的二进制文件所在路径。
                  
                  cd data/local/tmp/

           4. 确认二进制文件在当前目录下。
                  
                  ls

           5. 为二进制文件添加可执行权限。
                  
                  chmod u+x test_dyliub_creat

           6. 运行二进制文件，获取到进程ID。

在此示例中，进程ID为5255。
                  
                  ./test_dylib_crate &

![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20240930102426.48253337278435057833639873215871:50001231000000:2800:B2E20D4D65304ADB8FA7BF6E43126918E0FBDCAEB6C79EC260BBC8A2AD39D091.png?needInitFileName=true?needInitFileName=true)

        2. 配置“.vscode/launch.json”文件。

此处需要配置如下参数：

           * initCommands：步骤2中编译生成的二进制文件路径
           * targetCreateCommands：生成的可执行的待调测文件路径
           * preRunCommands：步骤4中配置的lldb-server的IP地址和端口号。
           * processCreateCommands：步骤6中获取到的进程ID。

示例如下：
    
    {
        "version": "0.2.0",
        "configurations": [
            {
                "type": "lldb",
                "request": "attach",
                "name": "Debug",
                "initCommands": [
                    "settings append target.exec-search-paths /openharmony/out/rk3568/lib.unstripped/common/common/"
                ],
                "targetCreateCommands": [
                    "target create /openharmony/out/rk3568/exe.unstripped/common/common/test_dylib_crate"
                ],
                "preRunCommands": [
                    "gdb-remote 10.10.10.1:7789"
                ],
                "processCreateCommands": [
                    "attach 5255"
                ],
            }
        ]
    }

     8. 启动调测。

单击Visual Studio Code的调测按钮。调测结果的分析方法请参考CodeLLDB插件的相关介绍。
