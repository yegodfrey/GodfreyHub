# 建立扫码连接（Beta）

## 交互流程

扫码连接是无线连接的补充方案，当车机无法通过BLE广播进行连接时，可以通过扫码连接的方式实现无线连接。

扫码连接与前文通过BLE广播实现的无线连接之间，区别仅在于扫码连接通过扫描二维码的方式替换了车机发送BLE广播输入PIN码的步骤。

在进行扫码连接之前，需要针对蓝牙和Wi-Fi进行相应的适配，具体内容请参考[无线连接流程](https://developer.huawei.com/consumer/cn/doc/HiCar-Guides/wireless-connection-process-0000001052464951)。扫码连接方案，仅需要完成其中非BLE相关的内容。

1. 厂商应用启动后，厂商应用初始化HiCar SDK，详见[初始化说明](https://developer.huawei.com/consumer/cn/doc/HiCar-Guides/interaction-process-0000001052542489)。
2. 用户进入到扫码界面，厂商应用要将车机蓝牙状态更改成可扫码可连接状态，且扫码界面和PIN码界面互斥，不能同时显示。
3. 厂商应用通过HiCar SDK接口获取二维码码值，为了防止二维码信息泄露，厂商应用需要每两分钟重新获取码值重新生成二维码图片。
4. 手机扫码，识别后手机会有发现弹框提示用户发现汽车。
5. 用户点击连接后，开始建立蓝牙BR连接，进行认证鉴权。
6. 认证鉴权成功后，开始建立WiFI连接，进行HiCar投屏，显示HiCar界面后连接成功。

## 启用SDK无线连接和扫码连接功能

扫码连接的连接通道与无线连接一致，只是触发方式不一样，因此在初始化时需要通过配置项启用无线连接的功能，如果SDK的无线连接功能未启用，则调用获取二维码码值接口时会返回错误。同时connectAllowType第3bit位表示是否支持扫码方式，所以第3bit位也要置为1。

启用无线功能的接口调用代码示例如下：

```screen
// 在初始化时设置是否支持无线连接，具体设置请参考API接口说明
CarConfig config;
Config.connectInfo.connectAllowType = 0x5; // 仅支持扫码时的设置
```

## 获取二维码码值

厂商HMI应用可以通过HiCar SDK提供的"HiCarGetConnectQRCode"接口获取二维码码值。

获取二维码码值的示例代码如下所示：

```screen
uint8_t qrCode[512] = {0};    
HiCarGetConnectQRCode(qrCode, 512);
```

在获取该二维码码值后，厂商HMI应用需要将码值转成二维码图片，并展示在车机界面上供手机扫描。

## 处理认证回调

在扫码连接过程中，PIN码信息已包含在二维码中，车机HMI应用不需要单独展示PIN码信息。虽然不再需要获取并展示PIN码信息，但厂商HMI应用仍然需要处理认证回调，完成认证流程。

厂商HMI应用在扫码连接过程中的认证回调处理，与无线连接过程中的认证回调处理采用相同的逻辑与处理函数，详情请参考无线连接章节的[处理认证回调](https://developer.huawei.com/consumer/cn/doc/HiCar-Guides/process-callback-0000001195856541#section16702192691018)。

## 处理连接事件回调

厂商HMI应用在手机和车机连接后，可以通过回调方法获取到具体的连接事件，根据事件进行投屏、退出应用等操作，具体处理连接事件回调的方式可以参考无线连接章节的[处理连接事件回调](https://developer.huawei.com/consumer/cn/doc/HiCar-Guides/process-callback-0000001195856541#section12985733201014)。
