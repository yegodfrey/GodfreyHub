# 配置BLE

## 场景说明

HiCar无线连接通过BLE进行设备发现。由车机侧发送BLE广播，手机扫描到BLE广播后弹窗提示用户，用户点击连接后触发连接流程（手机侧扫描到BLE广播后，触发BR连接，车机需要完成BR相应配置，详细内容参考后续章节）。

## 接口说明

厂商需实现HiCar SDK包中设备接口（driver_adapt.h）的FcDriverAdaptOps类型变量以及其中的部分接口。

配置BLE时，FcDriverAdaptOps变量中必须实现的接口如[表1](#ZH-CN_TOPIC_0000001055654311__table7112357182912)所示。

|结构体|结构体成员名称|说明|
|:---------------|:-------|:---------------------------------------------------------------------------------------------------------------------------------------------|
|FcDriverAdaptOps|name|BLE driver名称，必须填写为BLE_DRIVER_NAME。|
|FcDriverAdaptOps|desc|BLE设备接口描述，厂商可根据需要自行填写，例如"ble driver"。|
|FcDriverAdaptOps|Init|BLE driver初始化接口，HiCar SDK在使用其他BLE接口前，首先会调用该接口进行初始化。该接口需保证蓝牙控制器、协议栈正常启动，且为以下接口的调用做好准备。|
|FcDriverAdaptOps|Deinit|BLE driver去初始化接口，厂商可按需进行相关操作（如释放资源，关闭BLE控制器等）。|
|FcDriverAdaptOps|SetParam|HiCar SDK调用该接口设置BLE相关参数给厂商。设置的参数包括service uuid、读写character uuid、character权限、BLE连接间隔参数、BLE广播超时参数。|
|FcDriverAdaptOps|GetParam|HiCar SDK会调用该接口获取厂商Model ID、advpower值。 其中，advpower值表示蓝牙发射功率。|
|FcDriverAdaptOps|StartAdv|启动BLE广播接口，HiCar SDK会通过入参将广播内容传递给厂商，厂商需要在该接口中广播HiCar SDK传递的字段（type为0x16），并广播设备BR MAC地址。 一般情况下BLE广播的地址都是随机MAC地址，为了适配HiCar需求，请厂商在BLE广播中携带固定BR的地址。|
|FcDriverAdaptOps|StopAdv|停止BLE广播接口。|
[**表1**FcDriverAdaptOps结构体]

FcDriverAdaptOps类型的变量实现方式请参考HiCar SDK包中BLE demo代码（driver_ble.c），其中须注意，变量名称必须为"g_fcAdaptBleOps"。

HiCar SDK会按照以下顺序调用厂商实现的接口：

1. 调用Init初始化BLE。
2. 调用SetParam将BLE相关参数设置给厂商。
3. 调用GetParam获取DeviceModelId。
4. 调用GetParam获取advPower。
5. 调用StartAdv开启BLE广播。
6. 调用StopAdv关闭BLE广播。
7. HiCarRelease接口被调用时，Deinit接口会被同步调用，完成资源清理工作。

## 开发步骤

1. 实现BLE初始化接口Init，在接口中保证蓝牙BLE控制器、协议栈正常启动。
2. 实现BLE去初始化接口Deinit，在接口中释放BLE相关资源。
3. 实现设置BLE参数接口SetParam。

   BLE适配使用到枚举值SET_BLE_PARAMS，以SetParamsType类型传递参数。当入参枚举值为SET_BLE_PARAMS时，HiCar SDK通过该接口传递的内容如下：
   * serviceUuid：服务uuid，需要注册到BLE协议栈
   * readUuid：服务下所属的读属性uuid，需要注册到蓝牙协议栈
   * writeUuid：服务下所属的写属性uuid，需要注册到蓝牙协议栈
   * attrPerm：character permission
   * charProp：character property
   * maxInterval：Connection Interval最大值
   * minInterval：Connection Interval最小值
   * timeout：BLE广播超时时间

   其中，接口中并未包含BLE广播数据nearbyAdvData和advDataLen，广播数据会在StartAdv接口中传递。

   示例代码如下所示：

   ```screen
   /*
    * @function   : BleSetParam
    * @brief      : 为driver 设置参数
    * @param[IN]  : paramType, 参考枚举值SetParamsType，设置到BLE参数，当前HiCar BLE 只需要发广播，不需要建立长连接，只需要关注(minInterval,maxInterval,timeout)，其他参数可以不用关注。minInterval 和 maxInterval 当前下发的值均是20 (ms)。timeout 当前设置的是120(s), 表示经过120s 如果无连接就关闭广播, 当RFCOMM连接成功后，Nearby会调用StopAdv接口。
    * @param[IN]  : context SetParamsType对应的value值，内存由调用方分配，BLE driver需要适配SET_BLE_PARAMS属性。
    * @return     : 0 成功，非0 失败
    */
   static int BleSetParam(SetParamsType paramType, const void *context)
   {
       printf("BleSetParam[in] paramType:%d.\r\n", paramType);
       if (context == NULL) {
           printf("BleSetParam[in] input is invalid, paramType:%d.\r\n", paramType);
           return RESULT_RET_ERROR;
       }

       if (paramType == SET_BLE_PARAMS) {
           BleParams *bleParams = (BleParams *)context;
           (void)bleParams;
           printf("BleSetParam[in] paramType:SET_BLE_PARAMS, paramType:%d.\r\n", paramType);
       } else {
           printf("BleSetParam[in] unknown paramType:%d.\r\n", paramType);
       }

       return RESULT_RET_OK;
   }
   ```

4. 实现获取设备参数接口GetParam。

   HiCar SDK会根据GetParamsType类型中的GET_MODEL_ID和GET_BLE_ADV_POWER来获取厂商对应的相关信息：
   * 当GetParamsType为GET_MODEL_ID时，厂商需要将车型ID以DeviceModelId的结构体在出参result中返回。
   * 当GetParamsType为GET_BLE_ADV_POWER时， 厂商需要将蓝牙发射功率（即advPower值，1个字节）在出参result中返回。

   > 说明
   >
   > 厂商可以通过调整蓝牙发射功率获取到手机靠近发现的最佳距离。
   >
   > 最佳距离约定：在实车环境下，手机距离中控0.7米以内100%弹出设备发现弹框，距离中控1.5米以外100%不弹出设备发现弹框。

   示例代码如下所示：

   ```screen
   /*
    * @function   : BleGetParam
    * @brief      : 获取driver 参数值，BLE需要适配GET_MODEL_ID
    * @param[IN]  : paramType， 参考GetParamsType
    * @param[OUT] : result SetParamsType对应的value值
    * @return     : 0 成功，非0 失败
    */
   static int BleGetParam(GetParamsType paramType, void *result)
   {
       printf("BleGetParam[in] paramType:%d", paramType);
       if (paramType == GET_MODEL_ID) {
           DeviceModelId *devModeld = (DeviceModelId *)result;
           // 调试可用以下数据
           devModeld->subModelFlag = 0x01;
           devModeld->subModelId = 0x01;
           unsigned char modelId[] = {0x00, 0x04, 0x14};
           memcpy(devModeld->modelId,
               modelId,
               DEV_MODEL_ID_LEN);  // memcpy_s(devModeld->modelId, DEV_MODEL_ID_LEN, modelId, DEV_MODEL_ID_LEN);
           printf("BleGetParam[in] paramType:GET_MODEL_ID, paramType:%d", paramType);
       } 
       else {
           printf("BleGetParam[in] unknown paramType:%d.\r\n", paramType);
           return RESULT_RET_ERROR;
       }

       return RESULT_RET_OK;
   }
   ```

   关于advPower参数适配说明如下：设备发送的靠近发现广播会携带AdvPower TRP字段，代表广播的实际发射功率AdvPower TRP=TxPower（设备芯片广播发射功率）--OTA（设备天线损耗）， AdvPower TRP参数可先写入测算值，然后通过如下方法进行校准调整：
   1. 设备AdvPower TRP参数测量。
      * TxPower：芯片广播发射功率请参考芯片规格说明书或芯片固件参数配置取值；
      * OTA天线损耗：参考天线效率规格说明书或使用TxPower减去测量的天线口输出功率得出；
      * 在OTA天线损耗固定的前提下，芯片发射功率TxPower调整后，AdvPower TRP跟随调整； 实例：芯片广播发射功率TxPower配置为6dBm，测试得到天线输出功率为-4dBm，整个通路的OTA天线损耗为10=6-- (-4)dBm，则AdvPower TRP基线可配置为-4dBm；如果芯片广播发射功率配置调整为-8dBm，则AdvPower TRP基线配置为-18 =-8--10dBm；

   2. 设备AdvPower TRP参数校准。 由于设备实际发射功率受到设备天线方向性和信道平坦度差异影响，会存在一定误差，所以需基于基线AdvPower TRP参数进行靠近发现弹框KPI测试来校准参数，校准方法如下：

      基于基线AdvPower TRP参数进行调测，以设备为中心，保持手机顶部朝向设备，遍历8个角度，如果>50cm弹框了，则上调AdvPower TRP，如果<30cm不弹框，则下调AdvPower TRP，建议每次调整幅度为1~2dBm，最后满足手机绕设备一圈，都能做到>50cm不弹框，<30cm必定弹框。若设备某个角度体验偏差过大，建议联系芯片厂商或者天线团队进行硬件性能一致性调优。
   3. 在适配driver_ble.c的BleGetParam中，在GET_BLE_ADV_POWER中返回值。广播强度变量类型为char，占1字节，取值范围为[-128,127]。

5. 实现开启BLE广播接口StartAdv。

   入参context中包含nearby广播数据与nearby广播数据长度，需以BleAdvData格式解析，请厂商以Type：0x16广播该字段。另外，必须将BLE广播自带的MAC地址设置为BR的固定MAC地址（不能是随机地址），具体操作方法需联系芯片厂商确认。

6. 实现关闭BLE广播接口StopAdv。

### 特别说明

1. 发送BLE广播时，对应的广播事件必须是非定向可连接事件（ADV_IND)。其他事件类型如非定向不可连接事件（ADV_NONCONN_IND）, 会导致手机连接车机蓝牙后HiCar不弹框，请注意避免。

2. 车机蓝牙应该按照蓝牙标准协议配置成车载蓝牙类型上报[COD值](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/js-apis-bluetooth-connection#deviceclass)，否则在[蓝牙通话](https://developer.huawei.com/consumer/cn/doc/HiCar-Guides/tele-call-bluetooth-0000001239515063)设备选择策略中会出现未知问题。常见的车载蓝牙类型COD值为0x240408或者0x200408。
