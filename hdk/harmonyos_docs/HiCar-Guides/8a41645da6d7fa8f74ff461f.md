# 建立有线连接

## 启用SDK有线连接功能

只有当HiCar SDK的有线连接功能被启用时，HiCar SDK才会处理USB插入事件，从而进行有线连接。

厂商HMI应用可以在SDK初始化或者运行时动态启用有线连接功能。

SDK初始化启用有线连接功能的示例代码如下所示：

```screen
CarConfig.Builder builder = new CarConfig.Builder();
......
//在SDK初始化时启用有线连接功能，值为true表示启用有线连接功能，值为false表示禁用有线连接功能
builder.withSupportUsb(true);
CarConfig carconfig = builder.build();
```

运行时动态启用有线连接功能的示例代码如下所示：

```screen
//在运行时动态更新是否启用有线连接功能
carconfig.updateSupportUsb(true);
```

## 处理认证回调

有线连接过程中，PIN码信息将由HiCar SDK内部通过USB有线连接通道直接发送给手机侧，厂商HMI应用无需获取并展示PIN码信息。虽然不再需要获取并展示PIN码信息，但厂商HMI应用仍然需要处理认证回调，完成认证流程。

厂商HMI应用在有线连接过程中的认证回调处理，与无线连接过程中的认证回调处理采用相同的逻辑与处理函数，详情请参考无线连接章节的[处理认证回调](https://developer.huawei.com/consumer/cn/doc/HiCar-Guides/process-callbacks-0000001193322373#section317145010317)。

## 处理连接事件回调

厂商HMI应用在手机和车机连接后，可以通过回调方法获取到具体的连接事件，根据事件进行投屏、退出应用等操作，具体处理连接事件回调的方式可以参考无线连接章节的[处理连接事件回调](https://developer.huawei.com/consumer/cn/doc/HiCar-Guides/process-callbacks-0000001193322373#section134661359336)。
> 说明
>
> 有线连接虽然不依赖车机蓝牙，但为了保证后续可以通过蓝牙进行无线连接，厂商HMI应用在有线连接完成，接收到连接成功事件时，需要主动打开蓝牙。
>
> 当然，如果车机仅支持有线连接时，则无需进行该操作。

## 处理多互联产品冲突

如果车机同时支持多个通过有线方式进行连接的互联产品，那么厂商在集成HiCar时需要处理多互联产品冲突。如果车机仅支持HiCar互联产品，请忽略本章节内容。

假设车机同时支持A与HiCar两款互联产品，处理流程应为：

1. 用户通过USB将手机连接到车机。
2. 车机弹出提示界面，等待用户选择连接HiCar或者连接A。多互联产品选择弹窗的设计，请参考《HUAWEI HiCar 设备接入UX设计规范》相关章节。
3. 车机根据用户的选择，启动对应互联产品的连接流程。

|类|方法|说明|
|:--------|:---------------|:------------|
|Carconfig|updateSupportUsb|动态更新是否支持有线连接。|
[**表1**处理多互联产品冲突涉及到的接口]

1. 在SDK初始化时，厂商HMI应用禁用SDK的有线连接功能，即**CarConfig.Builder::** **withSupportUsb(false)**，避免手机通过有线方式连接车机时直接启动HiCar连接流程。
2. 当用户选择连接HiCar时，厂商HMI应用动态启用SDK的有线连接功能，即**Carconfig::updateSupportUsb(true)**。
3. 当用户断开HiCar连接时，厂商HMI应用动态禁用SDK的有线连接功能，即**Carconfig::updateSupportUsb(false)**。避免手机再次通过有线方式连接车机时直接启动HiCar连接流程。
