# Audio

## 场景说明

HiCar手机与车机连接后，可以把车机的MIC和Speaker设备进行虚拟化，供手机使用。例如将手机的音乐通过车机的Speaker播放出来；在语音交互时，通过车机的MIC进行收音后，传递给手机进行识别。

厂商根据HiCar SDK提供的Audio设备接口头文件，实现Audio相关接口，并生成"libdmsdpaudiohandler.so"文件。HiCar SDK会在运行时，试图加载该so库文件，如果加载失败或未找到文件，则认为车机未实现Audio相关接口。如果找到该文件，则动态加载该so链接库。

虚拟音频能力是接入HiCar的必要条件，厂商必须实现上述内容。实现过程中可参考HiCar SDK包中的"dmsdp_audio_sdk_samples.c"。

1. HiCar SDK初始化时，会试图加载libdmsdpaudiohandler.so，如果存在，则认为厂商适配了Audio功能，HiCar SDK会获取相应音频能力，并注册状态回调函数，接收来自厂商的状态事件。
2. 当用户点击HiCar界面播放音乐按钮时，经过手机和车机HiCar SDK之间的协商后，HiCar SDK设置音频参数，然后开始向Speaker写入数据，如果收到第一帧数据时，车机Speaker还没有打开，此时需要先打开Speaker再写数据。
3. 当用户暂停音乐播放时，会停止调用WriteStreamBuffer。
4. 当SDK调用OpenAudioRecord时，车机需要打开车载MIC用于收音，并将收集的声音数据按照上报的能力，传送给HiCar SDK。当SDK调用CloseAudioRecord接口时，需要关闭车载MIC。同时，为了不影响HiCar后端语音识别，MIC数据振幅不能小于2K。

## 接口说明

HiCar SDK定义的Audio接口包括：获取音频能力，打开/关闭MIC，读写音频数据等。

```screen
dmsdp_business.h             -- 定义了错误码，状态码等信息
dmsdp_audio_data_type.h      -- 定义audio数据类型
dmsdp_audio_handler.h        -- 定义了audio设备操作接口
```

## 开发步骤

1. 梳理车机Audio硬件信息，判断哪些车机Audio设备需要进行分布式虚拟化，供手机使用。只有需要参与分布式虚拟化业务的Audio信息需要进行能力上报。能力上报可以参考dmsdp_audio_sdk_samples.c中的GetAudioCapability接口。通常情况下，车机需要提供一个MIC和一个Speaker供HiCar SDK使用。
2. 当前HiCar SDK提供了虚拟电话能力，虚拟电话使用的MIC和Speaker，可以和普通音频场景使用同一个硬件设备。但是设备id和type不能相同（DMSDPAudioCapabilities结构中的id和type），同样请参见dmsdp_audio_sdk_samples.c中的示例代码。其中WriteStreamBuffer和ReadStreamBuffer接口在实现的时候不能阻塞太久。特别是在连接断开时，如果一直阻塞可能会造成有些消息无法传递给HMI应用。
3. 由于HiCar SDK需要通过设备接口操作车机MIC或者Speaker设备，同时车机上原生业务也可能操作MIC或者Speaker，所以需要在厂商妥善处理不同业务对于音频设备使用的冲突，处理好音频策略的问题。
4. 车机上报音频能力给手机后，可能存在音频设备状态变化的情况，例如音频设备被车机其他业务使用，如果发生状态变化，可以通过DMSDPListener中的两个接口UpdateServiceStatus和UpdateServiceAction反向通知HiCar SDK。

> 说明
>
> 车机需要上报的audio数据类型包括AudioChannelMasks通道、AudioFormats采样位数以及AudioSampleRates采样率。
