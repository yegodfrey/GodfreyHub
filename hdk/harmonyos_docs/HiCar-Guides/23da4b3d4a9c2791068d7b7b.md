# 管理车机麦克风

## 处理车机麦克风冲突

HiCar SDK与车机应用本身都会使用车机麦克风（以下简称MIC）进行收音，为了避免冲突，HiCar SDK通过事件的方式与车机协商使用MIC。

|类|方法|说明|
|:----------|:-------------|:---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
|CarListener|onDeviceChange|HiCar SDK通过回调的方式向厂商HMI应用通知MIC相应的事件： * EVENT_DEVICE_MIC_REQUEST （值为109）：HiCar请求使用车机MIC时发送该事件，厂商HMI应用收到该事件后释放MIC供HiCar使用。 * EVENT_DEVICE_MIC_RELEASE（值为110）：HiCar释放车机MIC时发送该事件，厂商HMI应用收到该事件后可以使用车机MIC。|
[**表1**处理车机MIC冲突相关接口]

1. 厂商HMI应用在HiCar SDK初始化时注册事件回调，详见[注册事件侦听回调](https://developer.huawei.com/consumer/cn/doc/HiCar-Guides/register-event-listener-0000000000030698)。
2. 当厂商HMI应用从onDeviceChange回调方法中收到EVENT_DEVICE_MIC_REQUEST事件后，释放车机MIC，供HiCar使用。

   1. HiCar在使用车机MIC之前，发送EVENT_DEVICE_MIC_REQUEST事件请求使用车机MIC。
   2. 厂商HMI应用通过onDeviceChange回调方法接收到EVENT_DEVICE_MIC_REQUEST事件后，立即释放车机MIC，且厂商HMI应用释放MIC的时延应小于15ms。
   3. HiCar发送EVENT_DEVICE_MIC_REQUEST事件后，每隔3ms检测一次车机MIC使用状态，连续检测5次。
      1. 如果车机MIC被释放，HiCar则创建和启动AudioRecord，使用AudioRecord录音。
      2. 如果车机MIC未被释放，则在下一个录音周期(20ms)重复步骤[2](#ZH-CN_TOPIC_0000001147994296__li1286054673715)和[3](#ZH-CN_TOPIC_0000001147994296__li11878117173814)。

3. 当厂商HMI应用从onDeviceChange回调方法中收到EVENT_DEVICE_MIC_RELEASE事件后，可以继续使用车机MIC。

   在HiCar使用完车机MIC之后，会立即释放MIC资源，并发送EVENT_DEVICE_MIC_RELEASE事件。

## 处理麦克风可用状态（Beta）

> 注意
>
> 厂商如果在Android Q版本以前的系统中通过定制实现了对并发录音的支持，则需要参考本小节内容进行实现；如果不支持，请忽略本小节内容。

Android Q之前版本系统不支持并发录音，HiCar SDK在开始录音之前使用Android原生接口getActiveRecordingConfiguration查询是否有活动录音任务来确认MIC是否空闲。但车机系统如果对音频框架进行了定制，支持多应用同时录音后，此时HiCar SDK无法再根据原生接口查询活动录音列表判断车机是否可以录音。因此，HiCar SDK提供接口供车机系统反馈当前车机MIC是否可用。

|类|方法|说明|
|:---------------|:-------------------------|:-------------------------------------------------------------------|
|CarAudioListener|getCarAudioRecordingStatus|厂商HMI应用在接收到HiCar SDK的接口调用后，根据当前MIC是否可用进行处理，若MIC可用，则返回2；若MIC不可用，则返回1。|
|HiCarAdapter|registerCarAudioListener|厂商HMI应用应该在初始化SDK时注册音频事件侦听。|
|HiCarAdapter|unRegisterCarAudioListener|厂商HMI应用应该在反初始化SDK时取消音频事件侦听。|
[**表2**处理车机麦克风可用状态相关接口]

车机MIC可用状态接口的适配，需要厂商HMI应用在SDK初始化过程中先注册监听音频事件回调，同时在回调接口中返回MIC当前的状态。

1. 厂商HMI应用实现自定义的CarAudioListener音频事件监听回调。

   示例代码如下所示：

   ```screen
   public class HiCarAudioListener extends CarAudioListener {
       @Override
       public int getCarAudioRecordingStatus() {
           Log.d(TAG, "getCarAudioRecordingStatus");
           // if 车机mic可用  return 2;
           // if 车机mic不可用  return 1;
           // if 暂不涉及 return 0;
       }
   }
   ```

   > 说明
   >
   > 接口适用场景为厂商车机版本是Q版本以前，同时支持并发录音，非此类场景不需要实现该接口。
   >
   > 如果暂不处理MIC状态，可返回0。

2. 在HiCar SDK初始化过程中，注册音频事件侦听回调。

   示例代码如下所示：

   ```screen
   int carAudioRerCode = mHiCarAdapter.registerCarAudioListener(mHiCarAudioListener);
   if (carAudioRerCode != HiCarConst.SUCCESS) {
   	Log.d(TAG, "HiCar reg audio listener failed");
   }
   ```

3. 在HiCar SDK反初始化时，取消注册音频事件侦听。

   示例代码如下所示：

   ```screen
   int carListenerRetCode = mHiCarAdapter.unRegisterCarListener(mHiCarListener);
   if (carListenerRetCode != HiCarConst.SUCCESS) {
   	Log.d(TAG, "HiCar unreg listener failed");
   }
   ```

## 设置MIC音频采样率

音频采样率是指音频输入源（例如麦克风）在一秒钟内对声音信号的采样次数，采样频率越高，声音的质量也就越好，还原的声音就越真实，但同时它占用的资源越多。

HiCar支持设置车机麦克风的采样率，相关接口和示例代码如下所示。

|类|方法|说明|
|:----------------|:--------------|:------------------------|
|CarConfig.Builder|withMicProfiles|厂商HMI应用通过此接口设置车机麦克风音频采样率。|
[**表3**设置MIC音频采样率相关接口]

例如，设置采样率为16k，示例代码如下所示：

```screen
CarConfig.Builder builder = new CarConfig.Builder();
List<AudioProfile> profileList = new ArrayList<>();
profileList.add(new AudioProfile(16000, 1,HiCarConst.AUDIO_FORMAT_PCM));
builder.withMicProfiles(profileList);
....
CarConfig mCarConfig = builder.build();
HiCarAdapter.init(getApplicationContext(), mCarConfig, new HiCarInitCallback(){
});
```

## 适配PCM传输通道

此功能针对需要加入软降噪算法的厂商，若无此需求，可忽视此功能。适配PCM传输通道后，HiCar SDK会在录音时通知HMI开启录音。HMI自行录音，可以对采集的PCM做降噪处理，之后按规定的长度将PCM传给HiCar SDK。

相关接口和示例代码如下所示。

|类|方法|说明|
|:---------------|:---------------------|:------------------------------------------------------------------------------------------------------------------------------|
|CarAudioListener|openAudioRecordCustom|HiCar通过此接口通知车机HMI开始录音，同时传递需要的录音音频规格，如采样率等。 车机返回0表示打开录音成功，返回-1表示打开失败。 > 说明 > 若车机打开录音失败，返回-1后，HiCar会自行录音，不会影响用户使用。具体参数说明见API参考文档。|
|CarAudioListener|readStreamBufferCustom|HiCar主动调用此接口，获取车机HMI采集并准备好的PCM数据，参数附带需要的长度。|
|CarAudioListener|closeAudioRecordCustom|HiCar通过此接口通知车机HMI停止录音，释放相关资源。|
[**表4**设置PCM传输通道相关接口]

1. 实现接口中的三个方法，示例代码如下：

   ```screen
   private class HiCarAudioCustomListener implements CarAudioCustomListener
       @Override
       public int openAudioRecordCustom(int sessionId, int audioSource, int audioSampleRate, int channelMask,
           int format) {
           Log.d(TAG, "openAudioRecordCustom");
           Log.d(TAG, "audioSampleRate" + audioSampleRate + "channelMask" + channelMask + "format" + format);
           return -1;
       }
       @Override
       public byte[] readStreamBufferCustom(int sessionId, int length) {
           Log.d(TAG, "readStreamBufferCustom");
           Log.d(TAG, "length" + length);
           byte[] result = new byte[length];
           return byte[];
       }
       @Override
       public int closeAudioRecordCustom(int sessionId) {
           Log.d(TAG, "closeAudioRecordCustom");
           return 1;
       }
   }
   ```

2. 在onInitSuccess和unloadHiCarSdk中注册和反注册。

   ```screen
   public void onInitSuccess(HiCarAdapter hiCarAdapter) {
       carAudioRerCode = mHiCarAdapter.registerCarAudioCustomListener(mHiCarAudioCustomListener);
       if (carAudioRerCode != HiCarConst.SUCCESS) {
            Log.d(TAG, "HiCar reg audio record listener failed, retCode:" + retCode);
       }
   }

   private void unloadHiCarSdk() {
       carAudioListenerRetCode = mHiCarAdapter.unRegisterCarAudioCustomListener(mHiCarAudioCustomListener);
       if (carAudioListenerRetCode != HiCarConst.SUCCESS) {
            Log.d(TAG, "HiCar unreg audio custom listener failed");
       }
   }
   ```
