# 建立扫码连接

## 交互流程

扫码连接是无线连接的补充方案，当车机无法通过BLE广播进行连接时，可以通过扫码连接的方式实现无线连接。

扫码连接与前文通过BLE广播实现的无线连接之间，区别仅在于扫码连接通过扫描二维码的方式替换了车机发送BLE广播输入PIN码的步骤。

在进行扫码连接之前，需要针对Wi-Fi进行相应的适配，具体内容请参考[说明](https://developer.huawei.com/consumer/cn/doc/HiCar-Guides/note-0000001194049481)。扫码连接方案，仅需要完成其中非BLE相关的内容。

## 启用SDK无线连接功能

扫码连接的连接通道与无线连接一致，因此在初始化时需要通过配置项启用无线连接的功能，示例代码请参考[启用SDK无线连接功能](https://developer.huawei.com/consumer/cn/doc/HiCar-Guides/setting-wireless-connection-parameters-0000001147240376#section1592814466522)。

## 获取二维码码值

在扫码连接过程中，厂商HMI应用可以通过HiCar SDK提供的接口获取二维码码值，将其转换为二维码图片后展示在连接界面中供用户扫描。

|类|方法|说明|
|:-----------|:-------------|:--------------|
|HiCarAdapter|generateQrCode|生成二维码码值，用于扫码连接。|
[**表1**获取二维码码值涉及到的接口]

1. 厂商HMI应用绘制扫码连接界面。
2. 厂商HMI应用通过generateQrCode接口获取二维码码值。

   二维码值有效期为2分钟，超过2分钟需要重新调用接口获取。

   获取二维码码值的示例代码如下所示：

   ```screen
   String qrCode = mHiCarAdapter.generateQrCode();
   ```

3. 厂商HMI应用将码值转成二维码图片，并展示在扫码连接界面上供手机扫描。

## 处理认证回调

在扫码连接过程中，PIN码信息已包含在二维码中，车机HMI应用不需要单独展示PIN码信息。虽然不再需要获取并展示PIN码信息，但厂商HMI应用仍然需要处理认证回调，完成认证流程。

厂商HMI应用在扫码连接过程中的认证回调处理，与无线连接过程中的认证回调处理采用相同的逻辑与处理函数，详情请参考无线连接章节的[处理认证回调](https://developer.huawei.com/consumer/cn/doc/HiCar-Guides/process-callbacks-0000001193322373#section317145010317)。

## 处理连接事件回调

厂商HMI应用在手机和车机连接后，可以通过回调方法获取到具体的连接事件，根据事件进行投屏、退出应用等操作，具体处理连接事件回调的方式可以参考无线连接章节的[处理连接事件回调](https://developer.huawei.com/consumer/cn/doc/HiCar-Guides/process-callbacks-0000001193322373#section134661359336)。
