## 音频流类型

HiCar SDK定义的音频流类型有：媒体、铃声、语音电话、闹钟、通知音、语音助手、导航、其它。

## 音频焦点类型

手机和车机建立HiCar连接后，HiCar将在播放音频之前请求音频焦点。车机也需要通过音频焦点通知向HiCar通知当前的音频焦点状态。

HiCar在车机播放音频申请的焦点类型，如[表2](#ZH-CN_TOPIC_0000001051064494__table13577433183714)所示。

HiCar在不同场景下申请的焦点类型，如[表 不同场景下申请的焦点类型](#ZH-CN_TOPIC_0000001051064494__table1987815356188)所示

车机在本地应用播放时通知音频焦点变化，对应的焦点变化通知如[表4](#ZH-CN_TOPIC_0000001051064494__table1617132216386)所示。

|主体|手机应用申请|焦点类型|说明|
|:-|:-----------|:----------------------------------|:----------------------------------------|
|手机|长焦点|AUDIOFOCUS_GAIN|HiCar请求长期占有音频焦点，失去焦点者停止播放和释放焦点。|
|手机|短焦点|AUDIOFOCUS_GAIN_TRANSIENT|HiCar请求短时占有音频焦点，失去焦点者暂停播放。|
|手机|Duck焦点|AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK|HiCar请求短时占有音频焦点，失去焦点者可以继续播放但音量需要降低或者暂停播放。|
|手机|独占焦点|AUDIOFOCUS_GAIN_TRANSIENT_EXCLUSIVE|HiCar请求短时占有音频焦点，但希望失去焦点者不要有声音播放。|
|手机|释放短焦点/Duck焦点|AUDIOFOCUS_RELEASE|HiCar请求释放音频焦点。|

HiCar在申请音频焦点时，厂商需要进行的工作主要包括：

* HiCar申请Duck短焦点时，厂商对本地所有多媒体应用的音频内容做降音混音处理，需要注意手机侧会降音混音后向车机发送音频流，HiCar上播放的多媒体应用无需降音混音处理。
* HiCar申请短焦点时，厂商对本地所有多媒体应用的音频做暂停处理，在HiCar释放焦点后，做续播处理。
* HiCar申请长焦点时，厂商对本地所有多媒体应用的音频做暂停播放处理。

|主体|车机本地应用申请|焦点变化通知|说明|
|:-|:-----------|:---------------------------------|:------------------------|
|车机|长焦点|AUDIOFOCUS_LOSS|HiCar失去了音频焦点或无法获得音频焦点。|
|车机|短焦点|AUDIOFOCUS_LOSS_TRANSIENT|HiCar暂时失去了音频焦点。|
|车机|Duck焦点|AUDIOFOCUS_LOSS_TRANSIENT_CAN_DUCK|如果音量降低，HiCar可以继续通过媒体通道播放。|
|车机|释放短焦点/Duck焦点|AUDIOFOCUS_GAIN|HiCar获得了音频焦点。|
[**表4**车机向HiCar发送的焦点变化通知]

HiCar通过代理获取车机侧的焦点变化事件，并传递到手机侧同步控制手机侧应用，所以车机本地应用申请音频焦点时需注意：

* 需要HiCar音频停止的业务，如车机本地音乐、FM等，在车机侧申请长焦点。
* 需要HiCar音频停续播的业务，如本地短视频、语音交互、通话等，在车机侧申请短焦点。
* 需要HiCar音频音量降低进行混音的业务，如本地导航播报、通知音等，在车机侧申请Duck焦点。

## 使能音频分流

分布式业务场景下，通过WIFI通道将音频数据从手机传输至车机进行播放，其中的音频数据会在手机侧进行混音处理。使能音频分流功能后，导航流、媒体流、通话流不进行混音处理，直接传输到车机，写入不同的AudioTrack；其他类型的音频流仍经手机混音处理后传输到车机。

车机可以在初始化SDK成功之后，调用接口使能音频分流策略，收到[连接成功回调](https://developer.huawei.com/consumer/cn/doc/HiCar-Guides/register-event-listener-0000000000030698#ZH-CN_TOPIC_0000001050744537__table42321929463)后需要调用[updateCarConfig](https://developer.huawei.com/consumer/cn/doc/HiCar-References/update-car-config-0000000000030585)更新音频分流参数。需要注意的是：操作系统Harmony OS 3.0及以上版本的手机支持音频分流能力。

|类|方法|说明|
|:-----------|:------------------------|:--------|
|HiCarAdapter|enableMultiAudioBusPolicy|使能音频分流功能。|

## 处理自定义音频策略（Beta）

> 注意
>
> 需要定制音频策略的厂商可以参考本小节内容进行实现，无需自定义音频策略的厂商请忽略本小节内容。

音频数据从手机传递到车机后，HiCar SDK负责使用AudioTrack进行音频数据播放，手机音频数据在车机播放时，由HiCar SDK按照华为定义的音频转换策略进行映射。考虑到不同厂商对音频策略的映射机制不同，因此HiCar SDK开放自定义音频策略的能力给车机厂商。HiCar SDK负责将手机侧获取的音频数据的原始Usage、ContentType和focusGain等音频参数上报给厂商HMI应用，厂商HMI应用根据原始信息映射构造AudioAttributes/StreamType并返回给HiCar SDK，HiCar SDK根据映射后的AudioAttributes或者StreamType申请焦点进行焦点管理或创建AudioTrack进行音频流播放。

厂商HMI应用处理分为两个场景：

* 焦点申请：Usage为单Usage，厂商HMI应用直接映射构造AudioAttribute或StreamType。
* 音频流播放：单音源场景Usage为单Usage和contentType，可直接映射构造AudioAttributes/StreamType；多音源混音场景存在多个有效Usage和contentType，需要根据Usage确定混音场景，转换构造合适的AudioAttributes/StreamType。

|类|方法|说明|
|:---------------|:---------------------------|:-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
|CarAudioListener|getCustomizedAudioAttributes|厂商HMI应用应该根据原始信息映射构造AudioAttributes/StreamType并通过该方法返回给HiCar SDK。 厂商HMI应用在收到该方法回调时，需注意focusGain参数： * 0：表示当前为音频播放回调，在获取音频播放需要使用的streamtype或者AudioAttributes。播放需要使用的streamtype或者AudioAttributes。厂商HMI应用需要根据传递参数中的usage，转换为指定的streamtype或者AudioAttributes，并根据此参数实例化CustomizedAudioAttributes并返回。 * -1：表示当前为释放音频焦点回调，这个操作只是通知到厂商HMI释放了焦点，厂商HMI不需要关注其他参数，只需要拿到释放焦点的回调后，做相应的操作即可，返回任何值都可以。 * 其他（1，2，3，4）：表示当前为音频焦点申请回调，在获取申请焦点使用的streamtype或者AudioAttributes。厂商HMI应用可根据usage，转换为指定的streamtype或者AudioAttributes，或者结合usage以及focusGain的值转换成适当的streamtype或者AudioAttributes，并根据此参数实例化CustomizedAudioAttributes并返回。|
|HiCarAdapter|registerCarAudioListener|厂商HMI应用应该在初始化SDK时注册音频事件侦听。|
|HiCarAdapter|unRegisterCarAudioListener|厂商HMI应用应该在反初始化SDK时取消音频事件侦听。|
[**表6**处理自定义音频策略相关接口]

自定义音频策略需要厂商HMI应用在SDK初始化过程中先注册监听音频事件回调，同时在回调接口中实现自定义的音频策略。

1. 厂商HMI应用实现自定义的CarAudioListener音频事件监听回调。

   示例代码如下所示：

   ```screen
   public class HiCarAudioListener extends CarAudioListener {
   	@Override
   	public CustomizedAudioAttributes getCustomizedAudioAttributes(int[] usage, int[] contentType,
   		int focusGain, Map<String, String> info) {
   		Log.i(TAG, "getCustomizedAudioAttributes.");
   		CustomizedAudioAttributes customizedAudioAttributes;
   		// 如果usages有多个值，则根据多个usage判断，根据判断之后的usage转换streamType
   		int usage = usages[0];
   		int streamType = usageToStreamType(usage);
                   // 语音上报时，usage类型可能为17，这个是华为特有的语音类型，需要转换为Android中其他usage类型，这里转换为USAGE_ASSISTANT
                   if (usage == 17) {
                          usage = AudioAttributes.USAGE_ASSISTANT;
                   }
   		int contentType = streamType2ContentType(streamType);
   		if (Build.VERSION.SDK_INT > Build.VERSION_CODES.O) {
   			AudioAttributes audioAttributes = new AudioAttributes.Builder().setUsage(usage)
   					.setContentType(contentType).build();
   			customizedAudioAttributes = new CustomizedAudioAttributes(audioAttributes,
   					focusGain, map);
   		} else {
   			customizedAudioAttributes = new CustomizedAudioAttributes(streamType, focusGain, map);
   		}
   		Log.i(TAG, "getCustomizedAudioAttributes, mCustomizedAudioAttributes:"
   				+ customizedAudioAttributes.toString());
   		return customizedAudioAttributes;
   	}
   }
   ```

   > 说明
   >
   > 如果厂商不需要自定义音频策略可以不用调用registerCarAudioListener接口注册监听音频事件回调，也可以在getCustomizedAudioAttributes回调中直接返回null值，HiCar SDK采用HiCar自定义的音频策略进行映射。

2. 在HiCar SDK初始化过程中，注册音频事件侦听回调。

   示例代码如下所示：

   ```screen
   int carAudioRerCode = mHiCarAdapter.registerCarAudioListener(mHiCarAudioListener);
   if (carAudioRerCode != HiCarConst.SUCCESS) {
   	Log.d(TAG, "HiCar reg audio listener failed");
   }
   ```

3. 在HiCar SDK反初始化时，取消注册音频事件侦听。

   示例代码如下所示：

   ```screen
   int carListenerRetCode = mHiCarAdapter.unRegisterCarListener(mHiCarListener);
   if (carListenerRetCode != HiCarConst.SUCCESS) {
   	Log.d(TAG, "HiCar unreg listener failed");
   }
   ```

   > 说明
   >
   > 如果车机集成的HiCar SDK为6.1.0.100及以上版本，可以通过adb命令设置prop属性，打开SDK音频数据的功能开关，用于抓取车机端HiCar SDK输入和输出的音频数据（仅用于调试，不可带入商用）。
   >
   > 命令如下：
   >
   > 打开功能开关：adb shell setprop persist.vendor.hicarsdk.catch.pcm 1
   >
   > 关闭功能开关：adb shell setprop persist.vendor.hicarsdk.catch.pcm 0
   >
   > 音频数据存储路径：/data/log/pcm
