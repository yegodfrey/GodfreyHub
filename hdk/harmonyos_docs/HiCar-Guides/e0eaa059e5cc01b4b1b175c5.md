# 蓝牙

## 配置BLE广播

HiCar通过BLE广播进行服务发现，而HiCar手机侧使用经典蓝牙BR地址进行蓝牙配对并在连接过程中建立BR链路，一般情况下BLE广播的地址都是随机MAC地址，为了适配HiCar的需求，车机设备需要在BLE广播中携带BR地址。

车机厂商可以通过[修改配置文件](#section1412418485380)或者[修改协议栈](#section2125154863818)的方式进行适配，选择其中任一方案实现或者使用BLE随机MAC功能，从而避免在BLE广播协议中携带车机真实MAC地址，更改为由GATT将数据传给手机。
> 说明
>
> 如果车机无法提供BLE广播进行发现连接，可以通过[扫码连接](https://developer.huawei.com/consumer/cn/doc/HiCar-Guides/scan-qrcode-connect-0000001051010285)的方案实现无线连接。
> 注意
>
> 以下是基于Android 8系统的修改方案及代码示例，具体修改内容还需厂商根据自身系统情况独立完成适配。其他系统版本的适配修改方案参见[Android 10.0适配须知](https://developer.huawei.com/consumer/cn/doc/HiCar-Guides/android-10-adaptation-0000001050028055)或[Android 9.0适配须知](https://developer.huawei.com/consumer/cn/doc/HiCar-Guides/android-9-adaptation-0000000000044614)。
>
> BLE随机MAC功能需要车机蓝牙版本为4.0及以上。

### 方式一：修改配置文件

1. 在Android源码中查找"system\bt\include\bt_target.h"，将其中的"BLE_LOCAL_PRIVACY_ENABLED"标志位修改为"FALSE"。示例如下所示。

   ```screen
   /*
    * Enables or disables support for local privacy (ex. address rotation)
    */
   #ifndef BLE_LOCAL_PRIVACY_ENABLED
   #define BLE_LOCAL_PRIVACY_ENABLED FALSE    //该标志位修改成FALSE
   #endif
   ```

2. 在Android源码中查找"frameworks\base\core\res\res\values\config.xml"，将其中的"config_bluetooth_le_peripheral_mode_supported"配置项修改为"true"。示例如下所示。

   ```screen
   <!-- Boolean indicating if current platform supports BLE peripheral mode -->
   <bool name="config_bluetooth_le_peripheral_mode_supported">true</bool>    //修改该值为true
   ```

### 方式二：修改协议栈

1. 在Android源码中查找"system\bt\stack\btm\btm_ble_addr.cc"。
2. 在函数"btm_gen_resolve_paddr_cmpl"中，修改与随机地址相关的内容，代码段如下所示。

   ```screen
   static void btm_gen_resolve_paddr_cmpl(tSMP_ENC* p) {
     tBTM_LE_RANDOM_CB* p_cb = &btm_cb.ble_ctr_cb.addr_mgnt_cb;
     BTM_TRACE_EVENT("btm_gen_resolve_paddr_cmpl");
     if (p) {
       /* set hash to be LSB of rpAddress */
       p_cb->private_addr[5] = p->param_buf[0];
       p_cb->private_addr[4] = p->param_buf[1];
       p_cb->private_addr[3] = p->param_buf[2];
       /* set it to controller */

       //第一处修改
       if(btm_ble_set_random_address(*controller_get_interface()->get_address())){
    p_cb->last_private_addr=*controller_get_interface()->get_address();
   }else{
    p_cb->private_addr=*controller_get_interface()->get_address();
   }

       //第二处修改
       p_cb->own_addr_type=BLE_ADDR_PUBLIC; //原值为BLE_ADDR_RANDOM

       /* start a periodical timer to refresh random addr */
       period_ms_t interval_ms = BTM_BLE_PRIVATE_ADDR_INT_MS;
   #if (BTM_BLE_CONFORMANCE_TESTING == TRUE)
       interval_ms = btm_cb.ble_ctr_cb.rpa_tout * 1000;
   #endif
       alarm_set_on_queue(p_cb->refresh_raddr_timer, interval_ms,
                          btm_ble_refresh_raddr_timer_timeout, NULL,
                          btu_general_alarm_queue);
     } else {
       /* random address set failure */
       BTM_TRACE_DEBUG("set random address failed");
     }
   }
   ```

   本方案有两处修改点：
   1. "btm_ble_set_random_address(*controller_get_interface()->get_address()) "，Android源码里此处使用的是随机地址，需要修改成上面代码片段中的内容。
   2. "p_cb->own_addr_type=BLE_ADDR_PUBLIC" ，Android源码里使用的BLE_ADDR_RANDOM，需要修改成为BLE_ADDR_PUBLIC。

3. （可选）处理可能的告警。

   第一处的修改在部分编译器上有可能产生告警错误，可以使用如下方式修复：

   ```screen
   p_cb->own_addr_type=BLE_ADDR_PUBLIC; //BLE_ADDR_RANDOM
   p_cb->private_addr=*controller_get_interface()->get_address();
   btm_ble_set_random_address(p_cb->private_addr);
   ```

### 方式三：BLE随机MAC

1. 设置系统属性persist.sys.hicar.random.mac恒为true。
2. 在CarConfig中传入BrMac和ModelId，其中BrMac为车机固定蓝牙MAC。

> 说明
>
> * 开启BLE随机MAC功能后，start Adv将会额外发起一个BLE广播（GATT Server），新增的BLE广播协议中仍然携带随机MAC，手机在接收到该广播后会连接GATT Server，数据中携带固定MAC。
> * 车机设备依然需要提供固定蓝牙MAC地址，只是不会再将固定MAC地址暴露在BLE广播中。

### 特别说明

1. 发送BLE广播时，对应的广播事件必须是非定向可连接事件（ADV_IND)。其他事件类型如非定向不可连接事件（ADV_NONCONN_IND）, 会导致手机连接车机蓝牙后HiCar不弹框，请注意避免。

2. 车机蓝牙应该按照蓝牙标准协议配置成车载蓝牙类型上报COD值，否则在[蓝牙通话](https://developer.huawei.com/consumer/cn/doc/HiCar-Guides/tele-call-bluetooth-0000001257144161)设备选择策略中会出现未知问题。常见的车载蓝牙类型COD值为0x240408或者0x200408。

## 处理蓝牙冲突

### 处理蓝牙互顶

当车机仅支持蓝牙和手机一对一配对时，如果手机A已经和车机蓝牙配对，此时手机B再响应HiCar无线连接，手机B向车机发起的RFCOMM连接会被拒绝或因其他原因无法正常连接。

建议车机在HiCar SDK广播时，如果检测到另外一台手机发起RFCOMM连接，则在另外一台手机与车机建立蓝牙ACL连接后，主动断开前一台手机的蓝牙连接，方案有二：

* （建议）在蓝牙协议栈中完成上述逻辑处理。
* 在厂商HMI应用中完成上述逻辑处理。

### 处理HFP与HiCar通话冲突

HiCar通话时触发蓝牙SCO链路连接，导致车机侧的蓝牙通话申请通话焦点并执行来电相关业务，可能会出现HiCar通话无声音的问题。解决HFP（Hands-free Profile）与HiCar通话间冲突的方案如下：

* （推荐）HiCar连接状态时关闭HFP。

### 处理A2DP与HiCar音乐冲突

HiCar音乐播放时，可能会与A2DP产生冲突，导致本地蓝牙音乐播放/暂停功能失效。解决A2DP与HiCar音乐间冲突的可能方案如下：

* （推荐）HiCar连接状态下关闭A2DP。

### 处理蓝牙通话

若车机选择使用本机[蓝牙通话](https://developer.huawei.com/consumer/cn/doc/HiCar-Guides/tele-call-bluetooth-0000001257144161)（即不支持[HiCar虚拟通话](https://developer.huawei.com/consumer/cn/doc/HiCar-Guides/tele-call-hicar-0000001257064215)），则不需要处理HFP与HiCar通话的冲突，车机连接HiCar状态下仅需关闭A2DP。

* （推荐）HiCar连接状态下关闭A2DP。

> 说明
>
> * 如果采用断开HFP和A2DP的方案，可能会存在HiCar断开连接后，因为蓝牙的HFP和A2DP重连导致又触发了HiCar自动连接的问题，此处建议在HiCar断开的固定时间内（具体可参考HFP回连的超时时间，建议设置为30秒左右）不响应自动连接。
