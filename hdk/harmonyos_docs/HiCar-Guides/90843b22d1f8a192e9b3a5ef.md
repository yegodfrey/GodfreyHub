# 建立自动连接

## 交互流程

如果用户已经成功通过无线方式连接了HiCar，并在手机HiCar App中允许了"自动连接"，那么当用户再次进入驾驶环境时，手机将自动与车机建立HiCar无线连接。此功能即为HiCar的自动连接功能。

厂商HMI应用与HiCar SDK间自动连接交互流程如[图1](#ZH-CN_TOPIC_0000001051064486__fig14455341152419)所示。

HiCar自动连接功能依赖车机的基础蓝牙回连能力（基础蓝牙回连能力指车机会自动与已配对的手机建立蓝牙连接），厂商HMI应用在收到蓝牙回连成功事件后，调用"startReconnect"接口触发HiCar连接流程。

## 启用SDK自动连接功能

只有当HiCar SDK的自动连接功能被启用时，厂商HMI应用调用"startReconnect"接口时才能触发HiCar连接流程。

厂商HMI应用可以在SDK初始化或者运行时动态启用自动连接功能。

SDK初始化启用自动连接功能的示例代码如下所示：

```screen
CarConfig.Builder builder = new CarConfig.Builder();
......
//在SDK初始化时启用自动连接功能，值为true表示启用自动连接功能，值为false表示禁用自动连接功能
builder.withSupportReconnect(true);
CarConfig carconfig = builder.build();
```

运行时动态启用自动连接功能的示例代码如下所示：

```screen
//在运行时动态更新是否启用自动连接功能
carconfig.updateSupportReconnect(true);
```

## 发起自动连接

### 自动连接场景

厂商HMI应用需要在用户再次用车时发起自动连接。由于自动连接依赖车机的基础蓝牙连接，一般情况下，厂商HMI应用可以通过侦听系统的基础蓝牙连接事件，在收到蓝牙连接完成的系统广播后，调用HiCar SDK的"startReconnect"接口发起自动连接流程。

厂商HMI应用需要侦听的系统蓝牙事件如下所示：

```screen
android.bluetooth.headsetclient.profile.action.CONNECTION_STATE_CHANGED
```

由于部分车辆在熄火后并不会立即断开蓝牙连接，所以在部分车辆熄火后重新启动的场景下，无法通过侦听蓝牙连接事件发起回连流程，此时需要厂商HMI应用判断蓝牙已连接后，即可发起回连流程。
> 说明
>
> 在回连过程中，厂商HMI应用避免再调用"startAdv()"接口发送连接广播，避免出现自动连接成功后手机仍在弹出发现连接窗口的情况。
>
> 厂商HMI在整个车机上电周期内都需监听系统蓝牙事件发起回连流程，用户手动断开连接除外。

### 自动连接失败处理

自动连接失败常见场景及原因如下：

* 手机侧HiCar App设置界面中"自动连接"未打开，导致自动连接失败。
* 手机侧HiCar App设置界面"我的设备"中将该车机连接信息删除，导致自动连接失败。

当上述连接失败场景发生时，HiCar SDK会将具体原因透传到厂商HMI，具体错误码如[表1](#ZH-CN_TOPIC_0000001051064486__table643372151820)所示。

|枚举类|枚举值|说明|
|:-----------------|:-----------------------------|:--------------------------|
|ConstantDevicePair|REASON_AUTO_CONNECT_SWITCH_OFF|手机侧HiCar App设置界面中"自动连接"未打开。|
[**表1**自动连接失败错误码]

厂商可根据具体原因进行界面提示或其他处理，异常处理代码示例如下所示：

```screen
CarListener carListener = new CarListener() {
    @Override
    public void onDeviceChange(String deviceId, int state, int errorCode) {
        switch(state) {
            ...
            case HiCarConst.EVENT_DEVICE_RECONNECT_FAILED:
                //TODO:厂商逻辑，根据错误码提示用户连接失败原因
               if(errorCode = ConstantDevicePair.REASON_AUTO_CONNECT_SWITCH_OFF)  {
                ...
               } 
                break;
            default:
                break;
        }
    }
};
```

### 无需自动连接场景

当用户手动断开HiCar连接时，厂商HMI应用需要确保在车机当前上电周期内，即使蓝牙重新连接也不会触发自动连接，但需要确保车机熄火后，再冷、热启动可以自动回连。

该场景下，厂商HMI应用需要在通过"onDeviceChange"回调获取到HiCar断开连接事件时，可以采用如下方式判断当前是否为用户主动断开：

* 根据"onDataReceive"回调中获取DataType为518的事件进行判断。详情请参考[主动断开车机连接通知](https://developer.huawei.com/consumer/cn/doc/HiCar-Guides/disconnect-notification-0000001100064722)。

如果是用户主动断开连接，则设置相应标志位，在用户下次用车之前都不触发回连流程。详情请参考[处理连接事件回调](#section567215212120)。

## 处理连接事件回调

厂商HMI应用在自动连接后，可以通过回调方法获取到具体的连接事件，根据事件进行投屏、退出应用等操作，具体处理连接事件回调的方式可以参考无线连接章节的[处理连接事件回调](https://developer.huawei.com/consumer/cn/doc/HiCar-Guides/process-callbacks-0000001193322373#section134661359336)。

无需自动连接场景中判断断连事件以及用户主动断开状态的示例代码如下所示：

```screen
CarListener carListener = new CarListener() {
    @Override
    public void onDeviceChange(String deviceId, int state, int errorCode) {
        switch(state) {
            ...
            case HiCarConst.EVENT_DEVICE_CONNECT:
                //TODO:厂商逻辑，如加载连接动画等
                break;
            case HiCarConst.EVENT_DEVICE_DISCONNECT:
                //TODO:厂商逻辑，如退出厂商HMI应用
                ...
                if(errorCode == HiCarConst.DISCONNECT_TYPE_MANUAL){
		//TODO：厂商逻辑，如通过标志位记录状态，在用户下次用车前不触发回连流程		...
                }
                break;
            default:
                break;
        }
    }
};
```
