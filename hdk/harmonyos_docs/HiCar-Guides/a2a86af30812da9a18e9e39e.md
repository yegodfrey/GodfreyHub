# 处理音频数据缓存

## 场景介绍

在无线连接场景下，手机背景扫描或空间干扰可能会导致数据延迟发送或重复发送，从而可能导致音频数据播放出现卡顿现象。

为了避免出现音频卡顿的现象，需要厂商在无线连接场景下对非实时的音频数据流（例如音乐）进行延迟播放。对于实时性要求高的数据，例如通话、语音播报、语音提示"滴"声，不进行处理。

建议延迟缓存500ms（25帧），最大缓存建议600ms（最大缓存的意义在于，抑制更大抖动，但不增加延时播放），超过最大缓存，则丢包。

## 开发步骤

1. 初始化延时播放时间（对应一个缓冲区），根据经验值判断，建议延迟播放500ms（25帧数据）。
2. 当接收到数据流时，判断是否需要做延时播放处理。

   不需要延时的数据，可参考的判断依据如下：
   * 通话：StreamType=0，包含运营商通话、畅连通话、VoIP通话。
   * 语音播报：usage=65536。
   * 语音提示"滴"声：voiceState=1时且接下来接收到音频数据usage=0。

3. 对于需要做延时处理的数据，等满足缓存到延时播放时间后，再从缓冲区拿数据开始播放。后续播放可保证抖动如果小于确定的延时时间，则不会出现卡顿情况（注意：整个过程数据一直缓存到缓冲区）；如果缓存大小为0时，则重新只缓存，不播放。厂商可参考如下状态处理变化。
