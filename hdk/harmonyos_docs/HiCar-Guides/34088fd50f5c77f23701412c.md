# 无线连接参数

## AP热点与Wi-Fi共存

在无线连接过程中，HiCar在开启AP热点时，默认会关闭Wi-Fi，可能会与车机已支持的AP热点和Wi-Fi共存的功能产生冲突。

HiCar SDK支持通过系统参数"persist.sys.hicar.apsta.coexist"指定车机是否支持AP热点和Wi-Fi共存的功能。

|参数名|类型|说明|
|:------------------------------|:--|:----------------------------------------|
|persist.sys.hicar.apsta.coexist|int|车机是否支持AP热点和Wi-Fi共存： * 0：不支持（缺省默认值） * 1：支持|
[**表1**参数说明]

如果车机要设置该参数，需要保证HiCar SDK可以通过getprop方式正常读取。 调试命令可参考如下所示：

```screen
adb shell
> setprop persist.sys.hicar.apsta.coexist 1 //车机支持AP热点和Wi-Fi共存
```

## 复用已有的AP热点

在无线连接过程中，HiCar默认会关闭当前的AP热点，并创建新的AP热点。在车机已有AP热点的情况下，影响用户体验。

HiCar SDK支持通过系统参数"persist.sys.hicar.reuse.ap"指定是否支持复用车机已有的AP热点。如果设置为支持，在无线连接过程中，HiCar会尝试使用车机已有的AP热点，从而提升用户体验。

|参数名|类型|说明|
|:-------------------------|:------|:-------------------------------------------------|
|persist.sys.hicar.reuse.ap|boolean|车机是否支持HiCar复用已有的AP热点： * false：不支持（缺省默认值） * true：支持|
[**表2**参数说明]

如果车机要设置该参数，需要保证HiCar SDK可以通过getprop方式正常读取。 调试命令可参考如下所示：

```screen
adb shell
> setprop persist.sys.hicar.reuse.ap true //支持复用已有的AP热点
```

> 说明
>
> 因手机规格限制，当手机已连接车机热点时，HiCar无法连接。如车机涉及此场景，需提醒用户在连接HiCar之前断掉车机热点。

## 指定无线连接使用的网卡

当车机存在多块网卡时，在HiCar的无线连接过程中，存在小概率获取到不同的网卡导致连接失败的问题。

HiCar SDK支持通过系统参数"persist.sys.hicar.ap.interface"指定无线连接过程中使用的网卡名称，避免在连接过程因获取到不同网卡导致连接失败。

|参数名|类型|说明|
|:-----------------------------|:-----|:--------------------------------|
|persist.sys.hicar.ap.interface|string|厂商可根据实际需要设置无线连接过程中，HiCar可使用的网卡名称。|
[**表3**参数说明]

如果车机要设置该参数，需要保证HiCar SDK可以通过getprop方式正常读取。 调试命令可参考如下所示：

```screen
adb shell
> setprop persist.sys.hicar.ap.interface wwan0 //设置在无线连接中使用指定的wwan0网卡
```

## HMI自行配置热点信息（Beta）

随着车机android版本的更新，越来越多的原生接口不再适用。在android13多用户的系统中，获取MAC的接口失效，只能获取到默认的物理地址(02:00:00:00:00:00)。若无法获取到正确的GO信息，将无法建立P2P连接。通过新的接口获取MAC显然是该问题最直接的解决方式，但无法保证在后续的android版本中，其它接口仍然适用。且原方式仅支持厂商通过prop配置nearby获取信息的网口名称，这种方式限制太大。因此决定将配置GO信息的能力提供给HMI。

1. SDK初始化时，需要在CarConfig配置成员SoftAPConfig。

   ```screen
   // 获取不到热点信息时，MAC可传默认值"02:00:00:00:00:00"，frequency可以传-1，其它值可以传空字符串
   builder.withSoftApConfig(new SoftApConfig("HiCarAP-0", "02:00:00:00:00:00", "12345678", 5745));
   ```

   ```screen
   // 获取不到热点信息时，也可以使用无参构造器构造出一个SoftApConfig，不可传null
   builder.withSoftApConfig(new SoftApConfig())
   ```

2. 当热点打开时，或每次连接开始时（发起广播、发起回连以及扫码连接）若热点已打开，需要通过updateSoftApConfig和updateCarConfig更新配置信息。

   ```screen
   carConfig.updateSoftApConfig(new SoftApConfig("HiCarAP-0", "**...**:**", "12345678", 5745));
   hiCarAdapter.updateCarConfig(carConfig);
   ```

若想强制使用某一IP,需要在SDK初始化时将softApConfig的成员变量IpAddressEnables设置为true，IPAddress和其它成员一同在热点打开后传入。配置参考：

```screen
softApConfig.setIpAddressEnabled(true);
softApConfig.setIpAddress("192.168.43.1");
```

> 说明
>
> 1.在多数场景中HMI初始化SDK时，由于热点还没有打开，无法获取到热点信息。这时仍然要初始化一个所有成员为默认值的SoftApConfig，以告知nearby下次连接时需要等待HMI传SoftApConfig上来，否则开机后首次连接时就不会使用HMI传来的SoftApConfig导致连接失败。
>
> 2.此接口只是为了应对Android版本更新原生接口失效的问题，虽然SoftApConfig由HMI提供，但是如果没有开启热点复用，热点是还是由nearby来打开。因此若不复用热点，HMI不能自行设置热点名称、密码、信道，必须在nearby打开热点后通过系统接口获取这些信息。
