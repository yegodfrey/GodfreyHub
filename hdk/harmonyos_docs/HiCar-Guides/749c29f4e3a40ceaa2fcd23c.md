# 处理音频焦点

## 音频流类型

HiCar SDK定义的音频流类型有：媒体、铃声、语音电话、闹钟、通知音、语音助手、导航、其它。

## 音频焦点类型

手机和车机建立HiCar连接后，HiCar将在播放音频之前请求音频焦点。车机也需要通过音频焦点通知向HiCar通知当前的音频焦点状态。

HiCar在车机播放音频申请的焦点类型，如[表1](#ZH-CN_TOPIC_0000001050121800__table13577433183714)所示。

HiCar在不同场景下申请的焦点类型，如[表 不同场景下申请的焦点类型](#ZH-CN_TOPIC_0000001050121800__table1987815356188)所示

车机在本地应用播放时通知hicar音频焦点变化，对应的焦点变化通知如[表2](#ZH-CN_TOPIC_0000001050121800__table1617132216386)所示。

|主体|手机应用申请|焦点类型|说明|
|:-|:-----------|:----------------------------------|:----------------------------------------|
|手机|长焦点|AUDIOFOCUS_GAIN|HiCar请求长期占有音频焦点，失去焦点者停止播放和释放焦点。|
|手机|短焦点|AUDIOFOCUS_GAIN_TRANSIENT|HiCar请求短时占有音频焦点，失去焦点者暂停播放。|
|手机|Duck焦点|AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK|HiCar请求短时占有音频焦点，失去焦点者可以继续播放但音量需要降低或者暂停播放。|
|手机|独占焦点|AUDIOFOCUS_GAIN_TRANSIENT_EXCLUSIVE|HiCar请求短时占有音频焦点，但希望失去焦点者不要有声音播放。|
|手机|释放短焦点/Duck焦点|AUDIOFOCUS_RELEASE|HiCar请求释放音频焦点。|
[**表1**HiCar在车机播放音频申请的焦点类型]

|主体|车机本地应用申请|焦点变化通知|说明|
|:-|:-----------|:---------------------------------|:------------------------|
|车机|长焦点|AUDIOFOCUS_LOSS|HiCar失去了音频焦点或无法获得音频焦点。|
|车机|短焦点|AUDIOFOCUS_LOSS_TRANSIENT|HiCar暂时失去了音频焦点。|
|车机|Duck焦点|AUDIOFOCUS_LOSS_TRANSIENT_CAN_DUCK|如果音量降低，HiCar可以继续通过媒体通道播放。|
|车机|释放短焦点/Duck焦点|AUDIOFOCUS_GAIN|HiCar获得了音频焦点。|
[**表2**车机向HiCar发送的焦点变化通知]

|场景|申请的焦点类型|释放的焦点类型|
|:-----|:---------------------------------|:---------------------------------|
|媒体|AUDIOFOCUS_GAIN|AUDIOFOCUS_LOSS|
|视频|AUDIOFOCUS_GAIN|AUDIOFOCUS_LOSS|
|游戏|AUDIOFOCUS_GAIN|AUDIOFOCUS_LOSS|
|电子书|AUDIOFOCUS_GAIN|AUDIOFOCUS_LOSS|
|VOIP电话|AUDIOFOCUS_GAIN_TRANSIENT|AUDIOFOCUS_LOSS_TRANSIENT|
|视频通话|AUDIOFOCUS_GAIN_TRANSIENT|AUDIOFOCUS_LOSS_TRANSIENT|
|语音播报|AUDIOFOCUS_GAIN_TRANSIENT|AUDIOFOCUS_LOSS_TRANSIENT|
|语音消息|AUDIOFOCUS_GAIN_TRANSIENT|AUDIOFOCUS_LOSS_TRANSIENT|
|响铃|AUDIOFOCUS_GAIN_TRANSIENT|AUDIOFOCUS_LOSS_TRANSIENT|
|蜂窝通话|AUDIOFOCUS_GAIN_TRANSIENT|AUDIOFOCUS_LOSS_TRANSIENT|
|闹钟|AUDIOFOCUS_GAIN_TRANSIENT|AUDIOFOCUS_LOSS_TRANSIENT|
|录音|AUDIOFOCUS_GAIN_TRANSIENT|AUDIOFOCUS_LOSS_TRANSIENT|
|导航|AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK|AUDIOFOCUS_LOSS_TRANSIENT_CAN_DUCK|
|拨号音|AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK|AUDIOFOCUS_LOSS_TRANSIENT_CAN_DUCK|
[**表3**不同场景下申请的焦点类型]

手机申请AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK焦点时，手机侧已经做了压低操作，车机侧在同步收到此焦点后无需重复做压低行为，否则会出现二次压低导致被压低的音频流音量异常。

## 接口说明

|接口|方法|说明|
|:----------------|:------------------|:--------------------|
|DMSDPAudioHandler|RegisterListener|注册音频事件侦听回调。|
|DMSDPAudioHandler|RequestAudioFocus|HiCar SDK向车机申请焦点。|
|DMSDPAudioHandler|AbandonAudioFocus|HiCar SDK向车机释放焦点。|
|DMSDPListener|UpdateServiceAction|车机向HiCar SDK通知音频焦点变化。|

## 开发步骤

HiCar侧焦点有变化的情况下，通过"RequestAudioFocus"和"AbandonAudioFocus"接口申请和释放焦点。

车机侧焦点有变化的情况下，通过事先注册的DMSDPListener调用到HiCar侧。

1. 注册事件侦听回调。

   厂商HMI应用在HiCar SDK初始化时注册Listener。结构定义如下所示：

   ```screen
   // 车机在收到南向DMSDPAudioHandler.RegisterListener 时，车机记录存储listener
   int32_t DMSDPExtendRegisterListener(const DMSDPListener *listener)
   {
       pthread_mutex_lock(&g_listener.lock);
       if (listener != NULL) {
           g_listener.listener.UpdateServiceAction = listener->UpdateServiceAction;
           g_listener.listener.UpdateServiceStatus = listener->UpdateServiceStatus;
       } else {
           g_listener.listener.UpdateServiceAction = NULL;
           g_listener.listener.UpdateServiceStatus = NULL;
       }
       pthread_mutex_unlock(&g_listener.lock);
       return 0;
   }
   ```

2. 车机向HiCar申请音频焦点。

   当车机需要向HiCarSDK申请焦点的时候，可以通过如下接口UpdateServiceAction进行申请焦点和释放焦点：

   ```screen
   typedef struct {
       int32_t (*UpdateServiceStatus)(const char *id, uint32_t idLen, const DMSDPServiceStatus status);
       int32_t (*UpdateServiceAction)(const char *id, uint32_t idLen, DMSDPServiceAction *action);
   } DMSDPListener;
   ```

   举例：当车机需要短暂抢占焦点的时候，发送短焦点给HiCar SDK，HiCar音乐会暂停播放。车机自己播放完后，通过释放焦点，HiCar音乐可以重新播放。

   焦点类型的枚举值定义在dmsdp_audio_data_type.h中，申请短焦点使用AUDIOFOCUS_LOSS_TRANSIENT，释放短焦点使用AUDIOFOCUS_GAIN。

   ```screen
   // 申请短焦点的枚举值是-2，注意传递是字符串"-2"
   DMSDPServiceAction requestAction = { AUDIO_FOCUS_CHANGE, "-2", 2 };
   g_listener.listener.UpdateServiceAction("testID", 6, &requestAction);
   // 短焦点的释放枚举值是1，注意传递是字符串"1"
   DMSDPServiceAction abandonAction = { AUDIO_FOCUS_CHANGE, "1", 1 };
   g_listener.listener.UpdateServiceAction("testID", 6, &abandonAction);
   ```

3. HiCar向车机申请音频焦点。

   当HiCar SDK需要使用车机的焦点时，会通过如下接口进行申请焦点及释放焦点：

   请求焦点接口，焦点类型[表1](#ZH-CN_TOPIC_0000001050121800__table13577433183714)中定义

   ```screen
   /*
   * request audio focus
     * streamType the main audio stream type affected by the focus request
   * focusType: focus type
     */
   int32_t (*RequestAudioFocus)(int32_t streamType, int32_t focusType);
   ```

   释放焦点接口，释放时不需要区分具体的焦点类型。
   > 说明
   >
   > 部分场景下存在焦点无法释放的问题。此时可以通过数据流的传输来判断播放是否结束，对数据流传输做一个超时检测。以TTS播报为例：如果超过一到两秒没有收到音频类型为TTS的数据流，就可以默认TTS播报结束，车机侧自行释放TTS焦点。

   ```screen
   /*
   * abandon audio focus
   */
   int32_t (*AbandonAudioFocus)();
   ```
