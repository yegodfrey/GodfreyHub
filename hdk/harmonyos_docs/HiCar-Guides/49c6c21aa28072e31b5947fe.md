# 设备接入FAQ

## 1.集成HUAWEI HiCar SDK硬件约束

**[问题一]** **厂商的车机硬件能否满足HUAWEI HiCar（以下简称HiCar）运行的要求?**

请下载最新版本《HUAWEI HiCar 软硬件资源约束》并进行检查，请注意反馈完整软硬件资源约束信息，以便HUAWEI HiCar团队评估准入，如反馈内容不完整，将无法进行评估。如对内容存在疑问，可邮件联系HUAWEI HiCar团队："huaweihicar@huawei.com"。

## 2.有线连接

**[问题一]** **使用演示APK，插入USB线后，手机侧没有出现发现弹框，该如何分析？**

按照如下步骤依次检查：

1. 查看车机侧Nearby 、DMSDP模块是否正常拉起，获取日志检查是否有nearby 、DMSDP关键字。
2. 检查车机侧是否正确注册广播接收器，由于车机侧在下发publishDevice 才会注册USB系统广播接收器，在unpublishDevice的时候会取消注册，也就无法感知USB的插入事件。搜索日志关键字publishDevice，确认是否有该日志打印。

**[问题二]使用演示APK，插入USB线，提示连接失败，该如何分析？**

按照以下步骤进行检查：

1. 车机侧是否支持NCM，确认方法是对比手机侧和车机侧流程，手机侧使能了NCM模式，但是车机侧没有wwan0的网卡出现。
2. 检查路由表是否配置，使用命令ip route show查看当前的路由信息，检查NCM生成的IP地址是否添加到路由表中。此处如果发现路由没有添加，可以在USB连接过程中手动输入ip route add命令添加路由表，可临时规避该问题，路由的正式添加需厂商实现。

**[问题三]使用演示APK连接后，投屏失败，该如何分析？**

按照以下步骤依次检查：

1. 检查当前连接是否正常，有线连接成功日志（车机侧）：SocketListenerTransport:accept after..
2. 检查startProjection投屏接口使用方式。常见问题车机在拉起相关Activity前就已经开始投屏了，上层应用向下设置了无效的surfaceView，导致无法正确的配置解码器，最终导致画面始终黑屏。

推荐启动投屏的动作放在surfaceChanged事件处理中，确保此时获取到的surface是有效的，并且在启动投屏前更新新的surface，实现方式如下（可参考《HUAWEI HiCar SDK开发指南》）。

## 3.无线连接

**[问题一]点击开始连接按钮，车机侧没有生成PIN码，该如何分析？**

按照以下步骤进行检查：

1. 获取车机侧日志，在日志中搜索 "DMSDP|HiCarSDK" 关键字，检查HiCar服务是否正常运行。
2. 搜索车机日志关键字 "CarAuthentication：generate pin code"，有该日志打印表明PIN码已生成并上报，没有该日志打印需联系认证模块进一步分析。

**[问题二]集成HiCar SDK及安装演示APK后，打开APK，点击开始广播，手机侧没有发现弹框，该如何分析？**

按照以下步骤依次检查：

1. 演示APK打开后，检查是否出现PIN码。如果没有出现PIN码，则说明HiCar SDK没有初始化成功，此时可获取车机日志进行分析。
2. 检查演示APK配置文件hicar.properties中ModelID项是否设置，该项是必选项，不设置无法发送广播。
3. 检查演示APK配置文件hicar.properties是否正确推送到车机目录下：/system/etc/。
4. 检查手机蓝牙是否打开，发现弹框要求蓝牙必须打开。
5. 以上步骤后仍然存在问题，需要抓取双端日志，进一步分析。

**[问题三]使用演示APK发现弹框后，手机侧出现弹框，点击连接后连接失败，该如何分析？**

按照以下步骤依次检查：

1. 观察连接失败现象，如果在PIN框展示阶段，已经提示连接失败，此时是蓝牙连接失败，需要厂商蓝牙或Wi-Fi的开发人员进行分析。
2. 全局搜索"CreateSocketListenerTransport:onCreateFail failCode = XXX," 该日志表明Nearby连接失败。
3. 以上步骤后仍然存在问题，需要抓取手机端和车机端日志，进一步分析。

## 4.无感连接

**[问题一]无感连接对蓝牙回连策略有哪些要求？**

HiCar在连接过程中，手机会尝试和车机建立蓝牙连接，如果此时车机也同时尝试配对连接手机，会导致HiCar连接失败（必现）。目前车机厂商在蓝牙回连时，通常不会判断手机与车机是否已解除配对，而是直接尝试与手机配对连接，这导致了HiCar连接成功率低。因此对厂商回连策略提出如下要求：

1. 只有手机与车机同时保存配对信息时，车机侧才发起无感连接。
2. 如果手机侧单方面解除了配对，则车机侧不应该一直尝试配对手机。
3. 如果车机侧解除了与手机配对，则车机侧不应该主动再与手机发起配对。
4. 车机的配对信息在用户主动解除前不应该丢失（例如车机重启时，不能丢失配对信息）。

## 5.HUAWEI HiCar 运行

**[问题一]使用演示APK连接后，Mic或Speaker没有正常工作，该如何分析？**

按照以下步骤进行检查：

1. 先检查Mic或Speaker硬件是否有问题。

   检查方法：使用手机与车机蓝牙手动建立配对连接，在手机上播放音乐，检查车机Speaker是否能正常放音；使用手机拨打电话，使用车机Mic通话，检查对端手机是否能正常收音。

2. 获取手机侧日志，搜索关键字"ServiceController:startDeviceServiceByType: start audio service"检查手机侧是否正常使能虚拟audio。
3. 获取车机侧日志，搜索关键字"AudioTracker|AudioRecord"检查播放函数是否有异常信息。

**[问题二]HiCar 需要使用Mic时，如何抢占车机的Mic？**

HiCar 抢占车机 Mic 的流程如下：

1. HiCar在使用Mic 前，检测Mic是否被占用，若被占用发送请求Mic事件EVENT_REQUEST_MIC。
2. 车机通过onDeviceChange 收到EVENT_REQUESET_MIC后，需要主动释放Mic且释放要耗时小于15ms。
3. HiCar发送请求Mic事件EVENT_REQUESET_MIC后，每隔3ms检测一次Mic使用状态，连续检测5次。

   若Mic被释放，则创建和启动AudioRecord，使用AudioRecord录音。

   若Mic未被释放，下一个录音周期(20ms)重复步骤上面的步骤。

4. HiCar在释放完Mic资源后，发送释放Mic事件EVENT_ RELEASE _MIC。
5. 车机通过onDeviceChange收到EVENT_REQUESET_MIC后，根据业务情况做后置处理。
