# Carrier Call (HiCar Virtual Modem Mode)

#### Scenario

After HiCar is connected, it is recommended that the HiCar channel be used for carrier calls. To avoid conflicts with the HFP phone of the head unit, the Bluetooth of the head unit needs to be disabled or the Bluetooth FP connection needs to be disconnected, and the connection is restored after HiCar is disconnected.

When a carrier call is connected or ended, the HiCar SDK notifies your HMI app using event notifications. Upon receiving such an event, your HMI app is supposed to set parameters such as echo cancellation and noise reduction for the microphone on the head unit, in order to avoid echo and noises during the call.

#### APIs

**Table 1** API and events related to carrier calls and VoIP callsAPI | Method | Description  
---|---|---  
CarListener | DeviceServiceChange | The HiCar SDK notifies the HMI app of the carrier call events through callback.
     * **HICAR_DEVICE_VIRMODEM_CALLING** (value being **307**): This event is sent after a carrier call is connected. Upon receiving this event, the HMI app needs to notify the microphone of the head unit to set echo cancellation and other related parameters to prevent echoes during calls.
     * **HICAR_DEVICE_VIRMODEM_HANGUP** (value being **308**): This event is sent after a carrier call is ended. Upon receiving this event, the HMI app needs to restore the microphone settings of the head unit to the normal state.  
  
#### Development Procedure

The sample code for handing the carrier call and VoIP call events is as follows:
    
    void DeviceServiceChange(const char *serviceId, uint32_t idLen, int state) {
        LOGD("DeviceServiceChange, state:%d", state);
        switch (state) {
            case HICAR_DEVICE_VIRMODEM_CALLING: {  
                // When a carrier call is connected, the HMI app needs to perform corresponding processing, for example, enabling echo cancellation.
                break;
            }
            case HICAR_DEVICE_VIRMODEM_HANGUP: {  
                // When a carrier call is ended, the HMI app needs to perform corresponding processing.
                break;
            }
            default: break;
        }
    }

#### Handling Conflicts During Calls

By default, the HiCar app provides the call service. If the head unit also provides the call service, conflicts may occur when they run at the same time. Therefore, the head unit should notify the HiCar app of the native call service state. When the HiCar app provides the call service, the head unit needs to report the call/hang-up event based on the call state of the HiCar app when the user presses the control button. Therefore, the head unit needs to obtain the call state from the HiCar app.

For details about conflicts during calls, please refer to [Call State and Focus](https://developer.huawei.com/consumer/cn/doc/development/SmartTravel-Guides/call-status-and-focus-0000001052659461).
