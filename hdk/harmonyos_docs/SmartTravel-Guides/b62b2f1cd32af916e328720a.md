# Setting Up an Automatic Connection  
  
#### Interaction Process

If the user has successfully connected to HiCar in wireless mode, and automatic connection is enabled in the HiCar app on the phone, when the user enters the driving environment again, the phone automatically establishes a wireless HiCar connection with the head unit. This is the automatic connection function of HiCar.

Figure 1 shows the automatic connection interaction process between the HMI app and the HiCar SDK.

The HiCar automatic connection function depends on the basic Bluetooth reconnection capability of the head unit (the ability to automatically establish a Bluetooth connection with paired phones). After receiving the successful Bluetooth connection event, the HMI app calls **startReconnect** to trigger the HiCar connection process.

#### Enabling Automatic Connection on the SDK

Only when automatic connection of the HiCar SDK is enabled, the HiCar connection process can be triggered when the HMI app calls **startReconnect**.

The HMI app can enable automatic connection during SDK initialization, or dynamically enable the function when the SDK is running.

The following is the sample code for enabling automatic connection during SDK initialization:
    
    CarConfig.Builder builder = new CarConfig.Builder();
    ......
    // Enable automatic connection during SDK initialization. The value **true** indicates that the feature is enabled, and the value **false** indicates that the feature is disabled.
    **builder.withSupportReconnect(true);**
    CarConfig carconfig = builder.build();

The following is the sample code for dynamically enabling automatic connection when the SDK is running:
    
    // Dynamically update whether to enable automatic connection when the SDK is running.
    **carconfig.updateSupportReconnect(true);**

#### Initiating Automatic Connection

#### [h2]Automatic Connection Scenarios

The HMI app needs to initiate automatic connection when the user uses the vehicle again after they have already connected their phone and the head unit. Automatic connection depends on the basic Bluetooth connection of the head unit. Generally, the HMI app can listen to the basic Bluetooth connection event of the system. After receiving the system advertisement indicating that the Bluetooth connection is complete, the app calls the **startReconnect** method of the HiCar SDK to initiate the connection process.

The HMI app needs to listen to the following Bluetooth event:
    
    **android.bluetooth.headsetclient.profile.action.CONNECTION_STATE_CHANGED**

Some vehicles do not drop the Bluetooth connection immediately after the engine is turned off. Therefore, in the scenario where some vehicles restart after the engine is turned off, the connection process cannot be initiated by listening to the Bluetooth connection event. In this case, the HMI app needs to ensure that the Bluetooth connection is successful before initiating the connection process.

![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20230817210255.94992263851401121367490049215398:50001231000000:2800:B551F07F6D30B2C6E7F916FB2DB8405E82183B21D8178B03814E5C24322133B2.png?needInitFileName=true?needInitFileName=true)

During reconnection, the HMI app should avoid calling **startAdv()** to send the connection advertisement. This prevents the connection dialog box from being displayed on the phone after the automatic connection is successful.

#### [h2]Handling Automatic Connection Failures

The common scenarios and causes of automatic connection failures are as follows:

     * Automatic connection is not enabled on the settings screen of the HiCar app on the phone.
     * The head unit connection information is deleted from **My Devices** on the settings screen of the HiCar app on the phone.

If any of the preceding scenarios occurs, the HiCar SDK will send the cause to the HMI app. For details about the error codes, please refer to Table 1.

**Table 1** Error code for automatic connection failuresEnumeration Class | Enumerated Value | Description  
---|---|---  
ConstantDevicePair | REASON_AUTO_CONNECT_SWITCH_OFF | Automatic connection is not enabled on the settings screen of the HiCar app on the phone.  
REASON_CAR_DEVICE_NOT_EXIST | The head unit connection information is deleted from **My Devices** on the settings screen of the HiCar app on the phone.  
  
You can display prompts or process as required according to the specific cause. The sample code for processing exceptions is as follows:
    
    CarListener carListener = new CarListener() {
        @Override
        public void **onDeviceChange**(String deviceId, int state, int errorCode) {
            switch(state) {
                ...
                case HiCarConst.EVENT_DEVICE_RECONNECT_FAILED:
                    // TODO: Display a prompt indicating the failure cause based on the error code. The logic is defined by yourself.
                   if(errorCode = ConstantDevicePair.REASON_AUTO_CONNECT_SWITCH_OFF)  {
                    ...
                   } else if(errorCode = ConstantDevicePair.REASON_CAR_DEVICE_NOT_EXIST) {
                    ...  
                   }     
                    break;
                default:
                    break;
            }
        }
    };

#### [h2]Scenarios Where Automatic Connection Is Not Required

When the user manually disconnects HiCar, the HMI app must ensure that the automatic connection is not triggered even if the Bluetooth is reconnected, before the user starts the vehicle next time.

In this scenario, the HMI app should obtain the HiCar disconnection event through the **onDeviceChange** callback, and determine if the user proactively drops the connection using either of the following methods:

     * Obtain the event whose DataType in the **onDataReceive** callback is **518**. For details, please refer to [Notification for User-initiated Disconnection from the Head Unit](https://developer.huawei.com/consumer/cn/doc/development/SmartTravel-Guides/disconnect-notification-0000001100064722).
     * Check the **errorCode** field in the disconnection event.

If the user proactively drops the connection, the HMI app needs to set a corresponding flag bit. In this way, the reconnection process will not be triggered before the user uses the vehicle next time. For details, please refer to Handling Connection Event Callback.

#### Handling Connection Event Callback

After the phone is automatically connected to the head unit, the HMI app can obtain the connection event through callback, and perform operations such as projection and exiting the app based on the event. For details about the connection event callback method, refer to [Handling Connection Event Callback](https://developer.huawei.com/consumer/cn/doc/development/SmartTravel-Guides/process-callbacks-0000001193322373#section134661359336) in the wireless connection section.

The following is the sample code for determining the disconnection event and whether the user initiated the disconnection, in a scenario where automatic connection is not required:
    
    CarListener carListener = new CarListener() {
        @Override
        public void **onDeviceChange**(String deviceId, int state, int errorCode) {
            switch(state) {
                ...
                case HiCarConst.EVENT_DEVICE_CONNECT:
                    // TODO: Your own logics, for example, loading the connection animation.
                    break;
                case **HiCarConst.EVENT_DEVICE_DISCONNECT** :
                    // TODO: Your own logics, for example, exiting the HMI app.
                    ...
                    if(**errorCode == HiCarConst.DISCONNECT_TYPE_MANUAL**){
    		// TODO: Your own logics, for example, recording status using flag bits to ensure that the connection process is not triggered before the user uses the vehicle next time.
    		...
                    }
                    break;
                default:
                    break;
            }
        }
    };
