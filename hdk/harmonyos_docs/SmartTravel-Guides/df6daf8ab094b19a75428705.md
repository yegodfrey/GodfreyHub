# Carrier Call (HiCar Virtual Modem Mode)

#### Scenario

HiCar supports calls over the Wi-Fi link, and it notifies the HMI app of the current carrier call state through the carrier call event.

The native media apps of the head unit severely interfere with carrier calls, voice calls, and voice recognition functions. Therefore, after receiving **EVENT_DEVICE_SERVICE_VIRMODEM_CALLING** in the **onDeviceServiceChange** callback, the manufacturer's HMI app needs to disable the native media apps, and perform echo cancellation and noise reduction.

#### API Description

**Table 1** API for handling carrier call conflictsClass | Method | Description  
---|---|---  
CarListener | onDeviceServiceChange | The HiCar SDK notifies the HMI app of the carrier call events through callback.
     * **EVENT_DEVICE_SERVICE_VIRMODEM_CALLING** (value being **209**): This event is sent before the physical link for the carrier call is set up. After receiving this event, the HMI app disables the local media app and enables echo cancellation and noise reduction to prevent interference to the carrier call.
     * **EVENT_DEVICE_SERVICE_VIRMODEM_HANG_UP** (value being **210**): This event is sent when a carrier call ends.  
  
#### Development Procedure

     1. The HMI app should register the event callback when the HiCar SDK is initialized. For details, please refer to [Registering Event Listeners](https://developer.huawei.com/consumer/cn/doc/development/SmartTravel-Guides/register-event-listener-0000000000030698).
     2. After receiving **EVENT_DEVICE_SERVICE_VIRMODEM_CALLING** in the **onDeviceChange** callback, the HMI app should disable the local media app.
     3. After receiving **EVENT_DEVICE_SERVICE_VIRMODEM_HANG_UP** in the **onDeviceChange** callback, the HMI app should enable the local media app.

#### Handling Conflicts During Calls

By default, HiCar provides the call service. If the head unit also provides the call service, conflicts may occur when they run at the same time. Therefore, the head unit should notify HiCar of the native call service state. When HiCar provides the call service, the head unit needs to report the call/hang-up event based on the call state of HiCar when the user presses the control button. Therefore, the head unit needs to obtain the call status from HiCar.

For details about call conflicts, please refer to [Call Status and Focus](https://developer.huawei.com/consumer/cn/doc/development/SmartTravel-Guides/call-status-and-focus-0000001051530010).
