# Description

#### Process

The HiCar wireless connection requires the head unit to support Bluetooth (classic Bluetooth and Bluetooth Low Energy (BLE)) and Wi-Fi. Corresponding adaptations should also be made.

**Figure 1** Wireless HiCar connection process  
![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20230817210250.71580650720295686262371616509853:50001231000000:2800:5E28B8BE85954371C15C96D11981D002BF775C10F8D6B50AFBD6643601726948.png?needInitFileName=true?needInitFileName=true)

     1. An RFCOMM connection is set up between the phone and the head unit.
     2. A GC_AP connection is set up between the phone and the head unit.
     3. A TCP socket connection is set up between the phone and the head unit.
     4. The HiCar projection between the phone and the head unit starts.

The wireless HiCar connection process involves Bluetooth service discovery, Bluetooth pairing, Bluetooth RFCOMM connection, and Wi-Fi connection. Figure 2 shows the message exchange process during the wireless connection.

**Figure 2** Message exchange during the wireless connection  
![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20230817210250.30746976913183608159703804595387:50001231000000:2800:2C7720D38F023BBFB73CCC130F954EE3CE8693C4AD380EED63C48F157A4E03B0.png?needInitFileName=true?needInitFileName=true)

During wireless connection, the phone interacts with the head unit to fulfill the following purposes:

     1. Carrying the Classic Bluetooth (BR) address of the head unit in a BLE advertising packet to the phone, so that the phone can establish a BR link according to the address.
     2. Establishing a low-speed Bluetooth control channel (RFCOMM control channel in the figure), based on which a Bluetooth data channel and high-speed Wi-Fi control channel can be established.
     3. Establishing a low-speed Bluetooth data channel (RFCOMM data channel in the figure) used for HiCar authentication.
     4. Negotiating a high-speed Wi-Fi channel based on the low-speed Bluetooth control channel.
     5. Establishing a high-speed Wi-Fi control channel (Wi-Fi control channel in the figure) to incubate high-speed Wi-Fi data channels.
     6. Establishing a high-speed Wi-Fi data channel (Wi-Fi data channel in the figure) to implement HiCar projection.

#### Involved APIs

To help fulfill the preceding purposes, the native Android system of the head unit needs to keep the native APIs listed in Table 1.

**Table 1** Native APIs that the wireless connection process depends onService | Service Process | API  
---|---|---  
BLE advertising | Carrying the BR address of the head unit when the head unit sends BLE advertisement data packets | android.bluetooth.le.BluetoothLeAdvertiser.startAdvertisingSet android.bluetooth.le.AdvertisingSet.setAdvertisingData  
Enabling/Disabling Wi-Fi hotspot | Establishing a GC_AP connection between the phone and the head unit | android.net.wifi.WifiManager.setWifiApConfiguration android.net.wifi.WifiManager.saveConfiguration android.net.ConnectivityManager.startTethering android.net.ConnectivityManager.stopTethering  
BR connection | Establishing an RFCOMM connection between the phone and the head unit | android.bluetooth.BluetoothAdapter.listenUsingInsecureRfcommWithServiceRecord android.bluetooth.BluetoothDevice.createInsecureRfcommSocketToServiceRecord  
Disabling Wi-Fi | Establishing a GC_AP connection between the phone and the head unit | android.net.wifi.WifiManager.setWifiEnabled
