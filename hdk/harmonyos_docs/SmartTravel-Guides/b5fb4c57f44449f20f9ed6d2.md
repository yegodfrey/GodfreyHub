# Initialization Description

#### Interaction Process

Interaction Process shows the initialization interaction process between the HMI app and the HiCar SDK.

The manufacturer's HMI app can communicate with the components in the HiCar SDK after **hicarsdk.aar** in the SDK package is integrated to the app.

     * SDK initialization: Set necessary head unit parameters in the HMI app for the SDK to use. During SDK initialization, the service processes of each component are started one by one. The manufacturer's HMI app can obtain the events of each SDK component through registered event listeners.
     * SDK de-initialization: After the HMI app is closed, clear the cached configuration data through the de-initialization API and end the service process of each component.

#### SDK Lifecycle

The HiCar SDK provides the **init** and **deInit** APIs to control the SDK lifecycle.

     * When **init** is called, the SDK completes initialization, and starts the service processes of the components such as DMSDP, Nearby, and HiSight.
     * When **deInit** is called, the SDK performs deinitialization. In this case, the SDK clears the cached configuration information and stops the service processes of the components such as DMSDP, Nearby, and HiSight. After the deinitialization is complete, all HiCar SDK related processes will be ended.

To ensure that users can use HiCar when they get on the vehicle and disconnect from HiCar when they get off, it is recommended that the HMI app control the lifecycle of the HiCar SDK in the following scenarios:

     * Initialization: The HMI app should call the **init** API to initialize the HiCar SDK when the user starts to use the vehicle (for example, the vehicle is started and the in-vehicle screen turns on).
     * Deinitialization: The HMI app should call the **deInit** API to deinitialize the HiCar SDK after the user stops using the vehicle (for example, after the user turns off the engine and the screen).
