# Configuring BLE

#### Scenario

When setting up a wireless HiCar connection, device discovery is implemented via BLE. After detecting the BLE advertising sent from the head unit, the phone displays a prompt to notify the user. After the user confirms the connection, the connection procedure is triggered. (After the phone scans the BLE advertising, the BR connection will be triggered, and related BR configurations need to be completed on the head unit side. For details, see the following sections.)

#### API Description

You need to implement the **FcDriverAdaptOps** variable (including certain APIs) of the device API (**driver_adapt.h**) in the HiCar SDK package.

Please refer to Table 1 for APIs that must be implemented in the **FcDriverAdaptOps** variable, to configure BLE.

**Table 1****FcDriverAdaptOps** structureStructure | Structure Member | Description  
---|---|---  
FcDriverAdaptOps | name | BLE driver name, which must be **BLE_DRIVER_NAME**.  
desc | Description of the BLE device API, which can be customized, for example, **ble driver**.  
Init | BLE driver Initialization API. The HiCar SDK calls this API to initialize the driver before using other BLE APIs. This API ensures the proper startup of the Bluetooth controller and protocol stack and prepares for the calling of the subsequent APIs.  
Deinit | BLE driver deinitialization API. You can deinitialize the BLE driver as required, for example, to release resources or disable the BLE controller.  
SetParam | API that is called by the HiCar SDK to set BLE parameters. The parameters that need to be set include the service uuid, read and write character uuid, character permission, BLE connection interval, and BLE advertising timeout.  
GetParam | The HiCar SDK calls this API to obtain your **Model ID** and **advpower**. The value of **advpower** indicates the Bluetooth transmit power.  
StartAdv | API for starting BLE advertising. The HiCar SDK passes the advertising content to you using the input parameter. You need to advertise the field (type: 0x16) passed by the HiCar SDK in the API and the BR MAC address of the device in the API. Generally, the BLE broadcast address is a random MAC address. To adapt to HiCar requirements, make sure to carry a fixed BR address in the BLE broadcast.  
StopAdv | API for stopping BLE advertising.  
  
For details about the implementation of the **FcDriverAdaptOps** variable, see the BLE demo code (**driver_ble.c**) in the HiCar SDK. Note that the variable name must be **g_fcAdaptBleOps**.

The HiCar SDK calls the APIs you have implemented in the following sequence:

     1. Call **Init** to initialize BLE.
     2. Call **SetParam** to set BLE-related parameters.
     3. Call **GetParam** to obtain **DeviceModelId**.
     4. Call **GetParam** to obtain **advPower**.
     5. Call **StartAdv** to start BLE advertising.
     6. Call **StopAdv** to stop BLE advertising.
     7. When **HiCarRelease** is called, **Deinit** is also called to clear resources.

#### Development Procedure

     1. Implement the BLE initialization API **Init** and ensure that the Bluetooth BLE controller and protocol stack are started properly in the API.
     2. Implement the BLE deinitialization API **Deinit** and release BLE-related resources in the API.
     3. Implement **SetParam** for setting BLE parameters.

The enum value **SET_BLE_PARAMS** is used for BLE adaptation, and the parameter is transferred in the **SetParamsType** type. When the enum value of the input parameter is **SET_BLE_PARAMS** , the content passed by the HiCar SDK through this API is as follows:

        * **serviceUuid** : service UUID, which needs to be registered with the BLE protocol stack.
        * **readUuid** : UUID of the read attribute of the service, which needs to be registered with the Bluetooth protocol stack.
        * **writeUuid** : UUID of the write attribute of the service, which needs to be registered with the Bluetooth protocol stack.
        * **attrPerm** : character permission.
        * **charProp** : character property.
        * **maxInterval** : maximum value of the connection interval.
        * **minInterval** : minimum value of the connection interval.
        * **timeout** : BLE advertising timeout.

The API does not contain the BLE advertising data **nearbyAdvData** and **advDataLen** , and the advertising data is transferred in the **StartAdv** API.

The following is the sample code:
    
    /*
     * @function   : BleSetParam
     * @brief      : Sets parameter for the driver.
     * @param[IN]  : **paramType** , as enumerated in **SetParamsType**. Set the BLE parameters. Currently, the HiCar BLE only needs to send an advertising message and does not need to establish a persistent connection. You only need to pay attention to **minInterval** , **maxInterval** , and **timeout**. You do not need to pay attention to other parameters. The values of **minInterval** and **maxInterval** are both **20** , in unit of ms. The current value of **timeout** is **120** , in unit of seconds. This means that the advertising stops if no connection can be set up after 120s. After the RFCOMM connection is set up, the Nearby calls the **StopAdv** API.
     * @param[IN]  : value of context **SetParamsType**. The memory is allocated by the invoker. The BLE driver needs to adapt to the **SET_BLE_PARAMS** attribute.
     * @return     : Returns **0** if successful; returns a non-zero value if otherwise.
     */
    static int BleSetParam(SetParamsType paramType, const void *context)
    {
        printf("BleSetParam[in] paramType:%d.\r\n", paramType);
        if (context == NULL) {
            printf("BleSetParam[in] input is invalid, paramType:%d.\r\n", paramType);
            return RESULT_RET_ERROR;
        }
    
        if (paramType == SET_BLE_PARAMS) {
            BleParams *bleParams = (BleParams *)context;
            (void)bleParams;
            printf("BleSetParam[in] paramType:SET_BLE_PARAMS, paramType:%d.\r\n", paramType);
        } else {
            printf("BleSetParam[in] unknown paramType:%d.\r\n", paramType);
        }
    
        return RESULT_RET_OK;
    }

     4. Implement **GetParam** , which is an API to obtain device parameters.

The HiCar SDK obtains your information based on **GET_MODEL_ID** and **GET_BLE_ADV_POWER** in **GetParamsType**.

        * When **GetParamsType** is set to **GET_MODEL_ID** , you need to return the vehicle model ID in the **DeviceModelId** structure in the result.
        * When **GetParamsType** is set to **GET_BLE_ADV_POWER** , you need to return the Bluetooth transmit power (that is, the **advPower** value occupying 1 byte) in the result.

You can adjust the Bluetooth transmit power to obtain the optimal discovery distance range of the phone away from the head unit.

In a real vehicle environment, a device discovery prompt should be displayed every time the phone is within 0.7 m away from the head unit. The device discovery prompt should not be displayed anyway when the phone is over 1.5 m away from the head unit.

The following is the sample code:
    
    /*
     * @function   : BleGetParam
     * @brief      : Obtains the value of the **driver** parameter. The BLE needs to adapt to **GET_MODEL_ID**.
     * @param[IN]  : paramType. For details, see **GetParamsType**.
     * @param[OUT] : result, which is the value of **SetParamsType**.
     * @return     : Returns **0** if successful; returns a non-zero value if otherwise.
     */
    static int BleGetParam(GetParamsType paramType, void *result)
    {
        printf("BleGetParam[in] paramType:%d", paramType);
        if (paramType == GET_MODEL_ID) {
            DeviceModelId *devModeld = (DeviceModelId *)result;
            // The following data can be used for debugging:
            devModeld->subModelFlag = 0x01;
            devModeld->subModelId = 0x01;
            unsigned char modelId[] = {0x00, 0x04, 0x14};
            memcpy(devModeld->modelId,
                modelId,
                DEV_MODEL_ID_LEN);  // memcpy_s(devModeld->modelId, DEV_MODEL_ID_LEN, modelId, DEV_MODEL_ID_LEN);
            printf("BleGetParam[in] paramType:GET_MODEL_ID, paramType:%d", paramType);
        } 
        else {
            printf("BleGetParam[in] unknown paramType:%d.\r\n", paramType);
            return RESULT_RET_ERROR;
        }
    
        return RESULT_RET_OK;
    }

Refer to the following for the adaptation of the **advPower** parameter. The proximity discovery advertisement sent by the device carries the **AdvPower TRP** field, indicating the actual transmit power of the advertising AdvPower TRP = TxPower (advertisement transmit power of the device chip) – OTA (antenna loss of the device). You can write the calculated value to the **AdvPower TRP** parameter, and then calibrate and adjust the parameter as follows:

        1. Measure the **AdvPower TRP** parameter of the device.
           * **TxPower** : indicates the advertisement transmit power of the chip. For details, see the chip specifications or the chip's firmware parameters.
           * OTA antenna loss: Refer to the antenna efficiency specifications, or calculate by subtracting the measured output power of the antenna connector from **TxPower**.
           * When the OTA antenna loss is fixed, the **AdvPower TRP** is changed accordingly with the adjustment of the chip transmit power **TxPower**.

Example: If the advertisement transmit power (**TxPower**) of the chip is set to 6 dBm, the antenna output power is –4 dBm, and the OTA antenna loss of the entire channel is 6 – (–4) = 10 dBm, the **AdvPower TRP** baseline can be set to –4 dBm. If the **TxPower** is changed to –8 dBm, the baseline value of **AdvPower TRP** is –8–10 = 18 dBm.

        2. Calibrate the **AdvPower TRP** parameter of the device.

The actual transmit power of the device is affected by the antenna directivity and channel flatness difference, so there may be deviations. Therefore, you need to calibrate the parameters based on the baseline **AdvPower TRP** parameters by performing the KPI test of the proximity connection prompt. The calibration method is as follows:

Perform calibration based on the baseline **AdvPower TRP** parameters. With the head unit as the center, keep the top of the phone facing the device and traverse all eight directions. If a prompt box is displayed when the distance is greater than 50 cm, increase the **AdvPower TRP**. If no prompt box is displayed when the distance is less than 30 cm, decrease the **AdvPower TRP**. It is recommended that the adjustment range be 1 to 2 dBm each time. Ensure that a prompt box is displayed when the phone is less than 30 cm from the head unit, and is not displayed when the phone is more than 50 cm away. If the deviation of a single angle is large, contact the head unit vendor or antenna team jointly calibrate the hardware performance consistency.

        3. When adapting **BleGetParam** in **driver_ble.c** , the value is returned in **GET_BLE_ADV_POWER**. The type of the advertisement power variable is char, occupying one byte. The value range is [–128, +127].
     5. Implement the **StartAdv** API for starting BLE advertising.

The input parameter **context** contains the Nearby advertising data and the length of the Nearby advertising data, which must be parsed in **BleAdvData** format. You need to advertise this field in type: 0x16 format. In addition, the built-in MAC address of BLE advertising must be set to the fixed MAC address (not a random address) of the BR. For details, contact the chip vendor.

     6. Implement the **StopAdv** API for stopping BLE advertising.
