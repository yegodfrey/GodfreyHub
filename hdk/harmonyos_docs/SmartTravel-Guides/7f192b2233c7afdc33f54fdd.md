# Establishing Scan to Connect (Beta)

#### Interaction Process

Scan to connect is a supplement to wireless connection. When the head unit cannot be connected through BLE advertising, use QR code scanning instead.

The only difference between scan to connect and the wireless connection implemented through BLE advertising is whether a QR code or PIN is used for identification.

This connection method requires you to adapt the Bluetooth and Wi-Fi functions. For details, see [Wireless Connection Process](https://developer.huawei.com/consumer/cn/doc/development/SmartTravel-Guides/wireless-connection-process-0000001052464951). Note that only non-BLE-related items need to be completed.

     1. After startup, the HMI app initializes the HiCar SDK. For details, please refer to [Initialization Description](https://developer.huawei.com/consumer/cn/doc/development/SmartTravel-Guides/interaction-process-0000001052542489).
     2. When the user enters the QR code scanning screen, the HMI app changes the head unit's Bluetooth status to scannable and discoverable. The QR code scanning screen and the PIN code screen are mutually exclusive and cannot be displayed at the same time.
     3. The HMI app obtains the QR code value through the corresponding API in the HiCar SDK. To prevent information leakage, the QR code value must be refreshed every 2 minutes.
     4. After the phone scans and identifies the QR code, it prompts the user to connect to the head unit.
     5. After the user touches the connect button, a Bluetooth BR connection is initiated and authentication starts.
     6. If the authentication is successful, a Wi-Fi connection is set up. When the HiCar screen is displayed, the connection is successful.

#### Enabling Wireless Connection and Scan to Connect Functions of the SDK

The scan to connect method uses the same channel as the wireless connection method, with a different triggering mode. For the API to obtain the QR code value to be called successfully, make sure to enable the wireless connection function in configuration during initialization. In addition, the third bit of **connectAllowType** must be set to **1** to allow scan to connect.

The following is the sample code for calling the API to enable wireless connection:
    
    // Set whether to support wireless connection during initialization. For details, please refer to the API Reference.
    CarConfig config;
     Config.connectInfo.connectAllowType = 0x5; // Indicates that only scan to connecxt is supported.

#### Obtaining the QR Code Value

The HMI app can obtain the QR code value by calling the **HiCarGetConnectQRCode** API provided by the HiCar SDK.

The sample code is as follows:
    
    uint8_t qrCode[512] = {0};    
    HiCarGetConnectQRCode(qrCode, 512);

After obtaining the QR code value, the HMI app needs to convert it into a QR code image and display it on the in-vehicle screen for the phone to scan.

#### Handling Authentication Event Callback

In scan to connect mode, the head unit does not need to display the PIN separately, as the PIN is included in the QR code. However, the HMI app still needs to process the authentication callback to complete the authentication process.

The HMI app uses the same logic and processing functions for authentication event callback as in wireless connection mode. For details, see [Handling Authentication Event Callback](https://developer.huawei.com/consumer/cn/doc/development/SmartTravel-Guides/process-callback-0000001195856541#section16702192691018).

#### Handling Connection Event Callback

After the phone is connected to the head unit, the HMI app can obtain the connection event through callback, and perform operations such as projection and exiting the app based on the event. For details about the connection event callback method, see [Handling Connection Event Callback](https://developer.huawei.com/consumer/cn/doc/development/SmartTravel-Guides/process-callback-0000001195856541#section12985733201014) in the wireless connection section.
