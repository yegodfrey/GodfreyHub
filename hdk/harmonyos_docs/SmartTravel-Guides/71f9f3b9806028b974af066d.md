# Starting the HMI App After Connecting to the Phone via Bluetooth

#### Scenario

To simplify the procedure of connecting to HiCar for the first time, the head unit can directly start the HMI app after being connected to the phone via Bluetooth.

![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20230817210309.55862723729695912764978412563969:50001231000000:2800:1ECA97A54EF5C128277A6E24E56E401FF0890040F5E97DC0B95E1EE65D1293ED.png?needInitFileName=true?needInitFileName=true)

To implement this feature, the head unit Bluetooth must support Secure RFCOMM communications with the UUID (FA87C0D0-AFAC-11DE-8A39-0800200C9A66).

When a Bluetooth connection is established between a phone and a head unit that both support HiCar, the HiCar SDK on the head unit and the HiCar app on the phone will interact via the Bluetooth RFCOMM channel, to determine that HiCar is supported on both sides. The phone will then recommend HiCar to the user. After the user agrees to the use of HiCar, the head unit directly displays the connection screen (where users can enter a PIN or scan the QR code to connect). In this way, the initial connection procedure is made easy and simple for the user.

User path:

     1. After the head unit supporting HiCar is connected to the phone via Bluetooth, the following prompts will display, asking whether the user would like to try HiCar out.

![](https://communityfile-drcn.op.dbankcloud.cn/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20230817210309.74486873458432464735640955869038:50001231000000:2800:F8D1BD4D80C2767B3300E1D78973DFE0C406A6067715489F50D28A51425BA80B.png?needInitFileName=true?needInitFileName=true)

     2. If the user touches **Try Now** , the head unit displays the HiCar HMI app (where users can enter a PIN or scan the QR code to connect); if the user touches **No Thanks** , the head unit will not receive any callback and no action will be triggered.

#### API Description

**Table 1** Related APIsFile | API | Description  
---|---|---  
hicar.c | HiCarStartBluetoothRecommend(const char* modelId, int32_t allowConnectionType) | Passes the head unit's **modelID** and connection types supported by the head unit after the SDK is initialized.  
hicar.c | ShowStartPage() | Redirects to the HiCar connection screen after receiving the callback (implemented by the HMI app) for displaying the connection screen.  
  
**Table 2** Structures (**bt_socket_wrapper.h**)Structure | Function in the Structure | Description  
---|---|---  
BtRecommendAdpterOps | registerBtSocketCallback(BtSocketDataCallback *callback) | Obtains the data processing function from the SDK to process the data obtained from Bluetooth sockets.  
initBtSocket(RfcommServerInfo serverInfo) | Creates Bluetooth sockets based on **RfcommServerInfo** provided by the SDK, and processes data received from the Bluetooth sockets.  
sendData(char *data) | Called by the SDK to send data to the phone.  
unregisterBtSocketCallback() | A deregister function that releases the data processing function obtained from the SDK.  
deInitBtSocket() | A de-initialization function that destroys Bluetooth sockets.  
  
#### Development Procedure

     1. Implement the API to listen for Bluetooth connections. Once a Bluetooth connection is detected, in the callback for successful initialization of the HiCar SDK, call **HiCarStartBluetoothRecommend** , and pass the head unit's **modelID** (with complete eight characters) and connection types supported by the head unit.
     2. Implement **ShowStartPage**. In this callback, redirect to the HiCar connection screen (where you can enter a PIN or scan the QR code to connect).
     3. Implement the APIs in the header file **bt_socket_wrapper.h** to realize Bluetooth connections and data sending/receiving. That is, implement **bt_socket_wrapper.c** according to the header file.
