# Managing Buttons, Knobs, and Touchpads  
  
#### Scenario

HiCar allows users to control apps and services by using physical keys and knobs. For example, the user can press the corresponding key to play the next music track or end a call. When integrating the HiCar SDK, report physical key and knob events to the HiCar SDK to control the corresponding apps and services.

When processing the physical keys, knobs, and touchpads of the head unit, the manufacturer should properly process the distribution logic of physical events between the head unit and HiCar.

#### API Description

**Table 1** APIs related to keys and knobsClass | Method | Description  
---|---|---  
HiCarAdapter | sendKeyEvent | Sends a key event. The input parameters include key values and key operations.
     * Key values: For information about key and knob events supported by the HiCar SDK, see Table 2.
     * Key operations:
       * **0** : ACTION_DOWN
       * **1** : ACTION_UP
       * **2** : Unspecified (ACTION_DOWN and ACTION_UP are not distinguished), such as for operations on the knob.  
  
You do not need to report the key events that do not require the handling of HiCar, such as those of the volume control keys and mute key. For the physical key events that need to be reported, see Table 2.

#### Development Procedure

     1. When a physical key or knob is triggered, you need to parse the corresponding event.
     2. Send the corresponding event to the HiCar SDK via the **sendKeyEvent** API.

The following is the sample code:
            
            // Send the advertisement for a key event.
            **mHiCarAdapter.sendKeyEvent(2000, 0);**
