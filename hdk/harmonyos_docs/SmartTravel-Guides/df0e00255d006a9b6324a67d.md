# Processing Related Callbacks

#### Handling PIN Event Callback

The HMI app can obtain the PIN through the **HiCarGetPinCode** API and display the PIN on the connection screen so that the user can enter it when prompted on the HiCar phone.

**Table 1** API for obtaining the PINHeader Files | Methods | **Description**  
---|---|---  
hicar.h | HiCarGetPinCode | The HMI app obtains the PIN via this API.  
  
     1. The HMI app calls the **HiCarGetPinCode** method to obtain the PIN and then display it on the connection setup screen.

Refer to HUAWEI HiCar App UX Design Specification to design the connection setup screen.

The sample code for obtaining the PIN is as follows:
            
            uint8_t pinCode[8] = {0};  
            HiCarGetPinCode(pinCode, 8);   

     2. Refer to HUAWEI HiCar App UX Design Specification to design the connection failure prompt screen, which is displayed when the PIN fails to be obtained.

#### Handling Authentication Event Callback

The HiCar SDK authenticates the phone that has been successfully connected to the head unit, so that they can be connected again without requiring a PIN.

The HMI app needs to store the authentication information in the head unit system, and read, save, and delete the authentication file by using the callback methods provided by the HiCar SDK.

The authentication data returned by the HiCar SDK to the HMI app through callback has been encrypted in white box mode. The HMI app only needs to ensure storage security.

It is recommended that you plan a dedicated security storage area to store authentication files.

**Table 2** APIs related to handling authentication event callbackInterface | Methods | **Description**  
---|---|---  
CarListener | GetSecureFileSize | Obtains the authentication file size.  
ReadSecureFile | Reads the authentication file information.  
WriteSecureFile | Saves the authentication information as a local file or to the secure storage area of the head unit.  
RemoveSecureFile | Deletes the security authentication file.  
  
Complete the authentication file processing logic in the authentication-related callbacks registered in [Registering Event Callbacks](https://developer.huawei.com/consumer/cn/doc/development/SmartTravel-Guides/register-event-listener-0000000000105633).

The following is the sample code for authentication callback:
    
    int32_t GetSecureFileSize(const char *filename)
    {    
        FILE* fp;
        int32_t size = 0;
    
        if (filename == NULL) {
            printf("GetSecureFileSize param null.\n");
            return -1;
        }
    
        char filenameInBox[256] = {0};
        sprintf(filenameInBox, "%s/%s", HICHAIN_FILE_PATH, filename);
        fp = fopen(filenameInBox, "rb");
        if (fp == NULL) {
            printf("fopen null.\n");
            return 0;
        }
    
        if (fseek(fp, 0L, SEEK_END) != 0) {
            printf("fseek error.\n");
            fclose(fp);
            return -1;
        }
    
        size = ftell(fp);
        fclose(fp);
    
        return size;
    }
    
    int32_t ReadSecureFile(const char *filename, uint32_t offset, uint8_t *buf, uint32_t len)
    {
        FILE* fp;
        int32_t size = 0;
    
        (void)offset;
    
        if (filename == NULL || buf == NULL) {
            printf("ReadSecureFile param null.\n");
            return -1;
        }
    
        char filenameInBox[256] = {0};
        sprintf(filenameInBox, "%s/%s", HICHAIN_FILE_PATH, filename);
        fp = fopen(filenameInBox, "rb");
        if (fp == NULL) {
            printf("fopen null.\n");
            return 0;
        }
    
        size = fread(buf, sizeof(uint8_t), (size_t)len, fp);
        fclose(fp);
    
        return size;
    }
    
    int32_t WriteSecureFile(const char *filename, uint32_t offset, uint8_t *buf, uint32_t len)
    {
        (void)offset;
        FILE* fp;
        size_t size;
    
        if (filename == NULL || buf == NULL) {
            printf("WriteSecureFile param null.\n");
            return -1;
        }
    
        char filenameInBox[256] = {0};
        sprintf(filenameInBox, "%s/%s", HICHAIN_FILE_PATH, filename);
        fp = fopen(filenameInBox, "wb");
        if (fp == NULL) {
            printf("fopen null.\n");
            return 0;
        }
    
        size = fwrite(buf, sizeof(uint8_t), (uint32_t)len, fp);
        fflush(fp);
        fclose(fp);
    
        if (size != len) {
            printf("WriteSecureFile error.\n");
            return -1;
        }
    
        return 0;
    }

#### Handling Connection Event Callback

After a phone is connected to the head unit, the HMI app can obtain the specific connection event through the callback method and complete the corresponding logic processing based on the connection event. For example, after a disconnection event is received, the HMI app will exit.

**Table 3** API for processing connection event callbacksClass | Methods | **Description**  
---|---|---  
CarListener | DeviceChange | The HiCar SDK notifies the HMI app of the connection events through callback.
     * **HICAR_DEVICE_CONNECTED** (value being **101**): The device is connected. After receiving a connection success event, the HMI app needs to display the connection animation. The animation will last until the projection is successful or times out. While the animation is on display, the name of the device involved in the connection can be displayed by calling **HiCarGetTrustDeviceList** , which is used to obtain the list of trusted devices. For details, please refer to [Managing Head Unit Connections](https://developer.huawei.com/consumer/cn/doc/development/SmartTravel-Guides/connection-management-0000000000105737).
     * **HICAR_DEVICE_DETECT_DISCONNECT** (value being **106**): The device is disconnected. After a disconnection event is received, the HMI app should exit.  
  
The following is the sample code for connection event callback:
    
    void DeviceChange(const char *deviceId, uint32_t idLen, int state, int errorCode)
    {
        printf("DeviceChange, deviceId:%s, state:%d\n", deviceId, state);
        switch (state) {
            case HICAR_DEVICE_CONNECTED:
            // Display the connection animation.
            break;
            case HICAR_DEVICE_DETECT_DISCONNECT:
            // Exit the head unit screen.
            break;
            default:
            break;
        }
    }
