# Setting Up an Automatic Connection

#### Interaction Process

If the user has successfully connected to HiCar in wireless mode, and automatic connection is enabled in the HiCar app on the phone, when the user enters the driving environment again, the phone automatically establishes a wireless HiCar connection with the head unit. This is the automatic connection function of HiCar.

The HiCar automatic connection function depends on the basic Bluetooth reconnection capability of the head unit (the ability to automatically establish a Bluetooth connection with paired phones). After receiving the successful Bluetooth connection event, the HMI app calls **HiCarReconnect** to trigger the automatic HiCar connection process.

The HMI app calls the automatic connection API (**HiCarReconnect**) in the HiCar SDK only when the following conditions are all met:

     * The head unit is able to automatically reconnect to previously paired phones.
     * The head unit automatically initiates a Bluetooth connection with a phone when they are close enough to each other.
     * Before the head unit is powered off or restarted, the phone user does not disconnect the phone from HiCar.

When initiating the connection process, the HMI app calls the **HiCarReconnect** API to transfer the phone's Bluetooth MAC address. The API checks whether the phone has passed the HiCar authentication. A HiCar connection will be completed only after the phone has passed the authentication.

#### Initiating Automatic Connection

#### [h2]Automatic Connection Scenarios

The HMI app needs to initiate an automatic connection with a previously connected phone, when the phone user uses the vehicle again. The automatic connection depends on the basic Bluetooth connection of the head unit. Generally, the HMI app can listen to the basic Bluetooth connection event of the system. After receiving the system advertisement indicating that the Bluetooth connection is complete, the app calls the **HiCarReconnect** API of the HiCar SDK to initiate the automatic connection process.

Some vehicles do not drop the Bluetooth connection immediately after the engine is turned off. Therefore, in some scenarios where the vehicles restart after the engine is turned off, the automatic connection process cannot be initiated by listening to the Bluetooth connection event. In this case, the HMI app needs to ensure that the Bluetooth connection is successful before initiating the automatic connection process.

During automatic connection, the HMI app does not need to call **HiCarStartAdv** , so that the connection dialog box does not display on the phone even after the automatic connection is successful.

#### [h2]Scenarios Where Automatic Connection Is Not Required

When the user manually disconnects HiCar, the HMI app must ensure that the automatic connection is not triggered even if the Bluetooth is reconnected, before the user starts the vehicle next time. **If the user actively triggers the connection again in the current power-on period, the record of the user's active disconnection needs to be cleared.**

In this scenario, the HMI app should obtain the HiCar disconnection event through the **DataReceive** callback, and determine if the user proactively drops the connection. If yes, the HMI app needs to set a corresponding flag bit. In this way, the automatic connection process will not be triggered before the user uses the vehicle next time. For details, please refer to [Notification for User-initiated Disconnection from the Head Unit](https://developer.huawei.com/consumer/cn/doc/development/SmartTravel-Guides/disconnect-notification-0000001081869175).
