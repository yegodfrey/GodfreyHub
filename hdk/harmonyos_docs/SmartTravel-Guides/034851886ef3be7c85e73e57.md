# Processing Related Callbacks

#### Handling PIN Event Callback

After you start advertising by calling **startAdv** , the PIN code callback is triggered. The HMI app can then use the callback method **onPinCode()** to obtain the PIN, and display it on the screen for the user to enter. If a user enters incorrect PINs for three consecutive times, the PIN is automatically refreshed.

**Table 1** API for handling PIN event callbackClass | Method | Description  
---|---|---  
CarListener | onPinCode | The HMI app obtains the PIN via this API.  
  
     1. Obtain the PIN from the callback of the **onPinCode()** listener that is registered, and display the PIN on the connection screen.

Refer to HUAWEI HiCar App UX Design Specification to design the connection setup screen.

The following is the sample code for PIN event callback:
            
            CarListener carListener = new CarListener() {
                ...
                @Override
                public void **onPinCode**(final String pinCode) {
                    runOnUiThread(new Runnable() {
                        @Override
                        public void run() {
                            mPinText.setText(pinCode);
                            mPinText.setVisibility(View.VISIBLE);
                        }
                    });
                }
            };

     2. Refer to HUAWEI HiCar App UX Design Specification to design the connection failure prompt screen, which is displayed when the PIN fails to be obtained.

#### Handling Authentication Event Callback

The HiCar SDK authenticates the phone that has been successfully connected to the head unit, so that they can be connected again without requiring a PIN.

The HMI app needs to store the authentication information in the head unit system, and read, save, and delete the authentication file by using the callback methods provided by the HiCar SDK.

The authentication data returned by the HiCar SDK to the HMI app through callback has been encrypted in white box mode. The HMI app only needs to ensure storage security.

It is recommended that you plan a dedicated security storage area to store authentication files.

**Table 2** APIs related to handling authentication event callbackClass | Method | Description  
---|---|---  
CarListener | getSecureFileSize | Obtains the authentication file size.  
readSecureFile | Reads the authentication file information.  
writeSecureFile | Saves the authentication information as a local file or to the secure storage area of the head unit.  
removeSecureFile | Deletes the security authentication file.  
  
Complete the authentication file processing logic in the authentication-related callback methods registered in [Registering Event Listeners](https://developer.huawei.com/consumer/cn/doc/development/SmartTravel-Guides/register-event-listener-0000000000030698).

The following is the sample code for authentication callback:
    
    CarListener carListener = new CarListener() {
        ...
        @Override
        public long getSecureFileSize(String fileName) {
            try(FileInputStream fis = getApplicationContext().openFileInput(fileName)) {
                return fis.available();
            } catch (IOException e) {
                Log.d(TAG, "read file IOException", e);
            }
            return FAILED;
        }
     
        @Override
        public byte[] readSecureFile(String fileName) {
            Log.i(TAG,"readSecureFile: fileName = " + fileName);
            byte[] readFileData = null;
            try(FileInputStream fis = getApplicationContext().openFileInput(fileName)) {
                byte[] temp = new byte[1024];
                int len = 0;
                // read file
                Log.d(TAG,"readSecureFile: openFileInput success");
                while ((len = fis.read(temp)) != FAILED) {
                    if ((readFileData != null) && (readFileData.length != 0)) {
                        readFileData = byteMerger(readFileData, temp, len);
                    } else {
                        readFileData = new byte[0];
                        readFileData = byteMerger(readFileData, temp, len);
                    }
                }
                Log.d(TAG,"read secure file");
                return readFileData;
            } catch (IOException e) {
                Log.d(TAG,"read file IOException", e);
            }
            return null;
        }
     
        @Override
        public boolean writeSecureFile(String fileName, byte[] data) {
            Log.i(TAG,"write secure file:" + fileName);
     
            try(FileOutputStream fos = getApplicationContext().openFileOutput(fileName, Context.MODE_PRIVATE)) {
                fos.write(data);
                fos.flush();
                fos.close();
                return true;
            } catch (FileNotFoundException e) {
                Log.d(TAG,"write file FileNotFoundException", e);
            } catch (IOException e) {
                Log.d(TAG,"write file IOException", e);
            }
            return false;
        }
     
        @Override
        public boolean removeSecureFile(String s) {
            return false;
        }
    };

#### Handling Connection Event Callback

After a phone is connected to the head unit, the HMI app can obtain the specific connection event through the callback method and complete the corresponding logic processing based on the connection event. For example, after a disconnection event is received, the HMI app will exit.

**Table 3** API for processing connection event callbacksClass | Method | Description  
---|---|---  
CarListener | onDeviceChange | The HiCar SDK notifies the HMI app of the connection events through callback.
     * **EVENT_DEVICE_CONNECT** (value being **101**): The device is connected. After receiving a connection success event, the HMI app needs to stop the advertising and display the connection animation. The animation will last until the projection is successful or times out.
     * **EVENT_DEVICE_DISCONNECT** (value being **102**): The device is disconnected. After a disconnection event is received, the HMI app should exit.
     * **EVENT_DEVICE_CONNECT_FAILD** (value being **103**): The device fails to be connected. After a connection failure event is received, the HMI app should exit.  
  
The following is the sample code for connection event callback:
    
    CarListener carListener = new CarListener() {
        @Override
        public void **onDeviceChange**(String deviceId, int state, int errorCode) {
            switch(**state**) {
                ...
                case **HiCarConst.EVENT_DEVICE_CONNECT** :
                    //TODO: Your own logics, for example, loading the connection animation.
                    break;
                case **HiCarConst.EVENT_DEVICE_DISCONNECT** :
                    // TODO: Your own logics, for example, exiting the HMI app.
                    break;
                case HiCarDemoServiceListener**.EVENT_DEVICE_CONNECT_FAILD** :
                    // TODO: Your own logics, for example, exiting the HMI app.
                    break;
                default:
                    break;
            }
        }
    };
