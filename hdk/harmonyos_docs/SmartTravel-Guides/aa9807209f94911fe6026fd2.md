# Starting/Stopping Head Unit Advertisement

#### Scenario

When the HMI app is started, or the user presses a physical key on the head unit (such as long pressing the voice wakeup key), the HMI app can call **startAdv()** to send the BLE advertising packets. After the connection is successful, the HMI app can call **stopAdv()** to stop the BLE advertisement. When calling these APIs, the HMI app should determine whether the advertisement is really started or stopped based on the return value.

#### API Description

**Table 1** APIs related to advertisingClass | Method | Description  
---|---|---  
HiCarAdapter | startAdv | The HMI app starts BLE advertising via this API.  
stopAdv | The HMI app stops BLE advertising via this API.  
CarListener | onDeviceChange | The HiCar SDK notifies the HMI app of the events through callback.
     * **EVENT_DEVICE_ADV_START** (value being **106**): The advertising starts.
     * **EVENT_DEVICE_START_ADV_TIMEOUT** (value being **124**): The advertising sending times out. After an advertising timeout event is received, the HMI app needs to initiate a reconnection.
     * **EVENT_DEVICE_ADV_STOP** (value being **107**): The advertising stops. If the connection still fails, the HMI app needs to trigger the advertising process again.  
  
#### Development Procedure

     1. When the HMI app is started or the user presses the physical button on the head unit, the Bluetooth status of the head unit needs to be checked.

If Bluetooth is not enabled on the head unit, the HMI app needs to enable Bluetooth on the head unit.

     2. Send the BLE advertising via **startAdv()**.

After the HMI app calls the advertisement sending API, each advertisement lasts for 2 minutes. After 2 minutes, the advertisement automatically stops. If the advertisement is triggered again during the transmission, the duration is reset.

The following is the sample code for calling the API to send advertising packets:
            
            // Start advertising.
            int retCode = **mHiCarAdapter.startAdv()** ;
            if (retCode == HiCarConst.SUCCESS) {
                Log.i(TAG, "handleStartAdv: start adv success");
                return;
            }

     3. Respond to an advertising event.

The HiCar SDK notifies the HMI app of the corresponding advertising event via a callback. The HMI app can handle accordingly after obtaining the advertisement event.

The following is the sample code for advertisement event callback:
            
            CarListener carListener = new CarListener() {
                @Override
                public void onDeviceChange(String deviceId, int state, int errorCode) {
                    switch(state) {
                        ...
                        case **HiCarConst.EVENT_DEVICE_ADV_START** :
                            // Advertising starts.
                            // TODO: Your own logics
                            break;
                        case HiCarDemoServiceListener**.EVENT_DEVICE_START_ADV_TIMEOUT** :
                            // Advertising times out.
                            //TODO: Your own logics, such as resending the advertising
                            break;
                        case **HiCarConst.EVENT_DEVICE_ADV_STOP** :
                            // Advertising stops. After this event is received, the PIN becomes invalid and the head unit screen stops displaying the PIN.
                            // TODO: Your own logics
                            break;
                        default:
                            break;
                    }
                }
            };

     4. Handle the PIN event callback. For details, please refer to [Handling PIN Event Callback](https://developer.huawei.com/consumer/cn/doc/development/SmartTravel-Guides/process-callbacks-0000001193322373#section71806403312).

Each time the HMI app triggers an advertisement, the HiCar SDK returns a PIN to the app via a callback. The HMI app needs to display the PIN on the screen of the head unit. The PIN is used as the connection verification code in the current advertising period. The user needs to enter the correct PIN to connect to the head unit.

     5. Process the authentication callback. For details, please refer to [Handling Authentication Event Callback](https://developer.huawei.com/consumer/cn/doc/development/SmartTravel-Guides/process-callbacks-0000001193322373#section317145010317).

The HMI app needs to store the HiCar SDK and head unit authentication information in the head unit system, and read, save, and delete the authentication file by using the callback methods provided by the HiCar SDK.

     6. Process the connection event callback. For details, please refer to [Handling Connection Event Callback](https://developer.huawei.com/consumer/cn/doc/development/SmartTravel-Guides/process-callbacks-0000001193322373#section134661359336).

The HMI app needs to listen for connection events and complete corresponding logic operations processing based on the connection events.

     7. Upon receiving the connection success event, the HMI app stops sending BLE advertising by calling **stopAdv()**.

The following is the sample code for calling the API to stop sending advertising packets:
            
            // Stop advertising.
            int retCode = **mHiCarAdapter.stopAdv()** ;
            if (retCode != HiCarConst.SUCCESS) {
                Log.d(TAG, "handleStopAdv failed");
            }
