# Managing the Head Unit Microphone

#### Handling Microphone Conflicts

The HiCar SDK and head unit apps use the microphone for sound pickup. To avoid conflicts, the HiCar SDK negotiates with the head unit to use the microphone through events.

**Table 1** API for handling microphone conflicts of the head unitClass | Method | Description  
---|---|---  
CarListener | onDeviceChange | The HiCar SDK notifies the HMI app of the microphone events through callback.
     * **EVENT_DEVICE_MIC_REQUEST** (value being **109**): This event is sent when HiCar requests to use the microphone of the head unit. After receiving this event, the HMI app releases the microphone for HiCar.
     * **EVENT_DEVICE_MIC_RELEASE** (value being **110**): This event is sent when HiCar releases the microphone of the head unit. After receiving this event, the HMI app can use the microphone of the head unit.  
  
     1. The HMI app should register the event callback when the HiCar SDK is initialized. For details, please refer to [Registering Event Listeners](https://developer.huawei.com/consumer/cn/doc/development/SmartTravel-Guides/register-event-listener-0000000000030698).
     2. After receiving **EVENT_DEVICE_MIC_REQUEST** in the **onDeviceChange** callback, the HMI app should release the vehicle microphone for HiCar to use.
        1. Before using the head unit microphone, HiCar sends **EVENT_DEVICE_MIC_REQUEST** to request the use of the head unit microphone.
        2. After receiving **EVENT_DEVICE_MIC_REQUEST** in the **onDeviceChange** callback method, the HMI app immediately releases the microphone of the head unit. The delay for the HMI app to release the microphone should be less than 15 ms.
        3. After sending **EVENT_DEVICE_MIC_REQUEST** , HiCar detects the microphone status of the head unit every 3 ms for five consecutive times.
           1. If the head unit microphone is released, HiCar creates and starts **AudioRecord** and uses **AudioRecord** for recording.
           2. If the head unit microphone is not released, repeat step 2 and step 3 in the next recording period (20 ms).
     3. After receiving **EVENT_DEVICE_MIC_RELEASE** in the **onDeviceChange** callback, the HMI app can continue to use the microphone of the head unit.

After using the microphone, HiCar immediately releases the microphone resources and sends the **EVENT_DEVICE_MIC_RELEASE** event.

#### Processing the Microphone Availability Status (Beta)

If you have customized support for concurrent recording in a system earlier than Android Q, refer to the content in this section. Otherwise, skip this section.

Versions earlier than Android Q do not support concurrent recording. Before starting recording, the HiCar SDK uses the Android native API **getActiveRecordingConfiguration** to check whether there are active recording tasks to determine whether the microphone is idle. However, if the audio framework of the head unit system is customized to support simultaneous recording of multiple apps, the HiCar SDK cannot query the active recording list based on the native API to determine whether the head unit system can record audio. Therefore, the HiCar SDK provides an API for the head unit system to provide feedback about whether the microphone of the head unit is available.

**Table 2** APIs for processing the availability status of the head unit microphoneClass | Method | Description  
---|---|---  
CarAudioListener | getCarAudioRecordingStatus | After receiving an API call request from the HiCar SDK, the HMI app returns a value based on whether the current microphone is available. If the microphone is available, **2** is returned. If the microphone is unavailable, **1** is returned.  
HiCarAdapter | registerCarAudioListener | The HMI app should register the listener for audio events when initializing the SDK.  
unRegisterCarAudioListener | The HMI app should deregister the listener for audio events when deinitializing the SDK.  
  
To adapt to the head unit microphone availability status API, the HMI app must register the audio event listener during SDK initialization and return the current microphone status in the callback API.

     1. The HMI app should implement the customized **CarAudioListener**.

The following is the sample code:
            
            public class HiCarAudioListener extends CarAudioListener {
                @Override
                public int getCarAudioRecordingStatus() {
                    Log.d(TAG, "getCarAudioRecordingStatus");
                    // Value **2** is returned if the head unit microphone is available.
                    // Value **1** is returned if the head unit microphone is unavailable.
                    // Value **0** is returned if the microphone status is not involved.
                }
            }

This API applies to the scenario where the head unit version is earlier than Android Q and concurrent recording is supported. In other scenarios, this API does not need to be implemented.

If the microphone status is not processed currently, **0** is returned.

     2. Register the audio event listener during the initialization of the HiCar SDK.

The following is the sample code:
            
            int carAudioRerCode = mHiCarAdapter.registerCarAudioListener(mHiCarAudioListener);
            if (carAudioRerCode != HiCarConst.SUCCESS) {
            	Log.d(TAG, "HiCar reg audio listener failed");
            }

     3. Cancel the audio event listener during the deinitialization of the HiCar SDK.

The following is the sample code:
            
            int carListenerRetCode = mHiCarAdapter.unRegisterCarListener(mHiCarListener);
            if (carListenerRetCode != HiCarConst.SUCCESS) {
            	Log.d(TAG, "HiCar unreg listener failed");
            }

#### Setting Microphone's Audio Sampling Rate

Audio sampling rate refers to the number of samples taken by an audio input source (such as the microphone) per second. A higher audio sampling rate indicates better sound quality, but also more resources occupied.

HiCar allows you to set the sampling rate of the head unit's microphone. The relevant APIs and sample code are as follows:

**Table 3** APIs for setting the microphone's audio sampling rateClass | Method | Description  
---|---|---  
CarConfig.Builder | withMicProfiles | This API is provided for the HMI app to set the audio sampling rate of the head unit's microphone.  
  
In the following sample code, the sampling rate is set to 16 kHz.
    
    CarConfig.Builder builder = new CarConfig.Builder();
    List<AudioProfile> profileList = new ArrayList<>();
    profileList.add(new AudioProfile(16000, 1,HiCarConst.AUDIO_FORMAT_PCM));
    builder.withMicProfiles(profileList);
    ....
    CarConfig mCarConfig = builder.build();
    HiCarAdapter.init(getApplicationContext(), mCarConfig, new HiCarInitCallback(){
    });

#### Adapting to the PCM Transmission Channel

This feature is intended for those who need noise cancellation algorithms. Skip this section if you do not need such algorithms. After adapting the PCM transmission channel, the HiCar SDK will inform the HMI app to start audio recording when needed. The HMI app records audio independently, performs noise cancellation on the collected PCM data, and sends the PCM data of a specified length to the HiCar SDK.

The related APIs and sample code are as follows:

**Table 4** APIs for setting PCM transmission channelsClass | Method | Description  
---|---|---  
CarAudioListener | openAudioRecordCustom | HiCar informs the HMI app on the head unit to start audio recording through this API, and passes the required recording specifications, such as the sampling rate. The head unit returns **0** if audio recording is started successfully, and returns **-1** otherwise. NOTE: If the head unit fails to start recording and returns **-1** , HiCar will start recording automatically, which does not affect user experience. For details about the parameters, see the API Reference.  
readStreamBufferCustom | HiCar calls this API to obtain the PCM data collected and prepared by the HMI app. The required PCM data length is attached in the parameter.  
closeAudioRecordCustom | HiCar informs the HMI app to stop recording and release related resources through this API.  
  
     1. Implement the three methods in the API. The sample code is as follows:
            
            private class HiCarAudioCustomListener implements CarAudioCustomListener
                @Override
                public int openAudioRecordCustom(int sessionId, int audioSource, int audioSampleRate, int channelMask,
                    int format) {
                    Log.d(TAG, "openAudioRecordCustom");
                    Log.d(TAG, "audioSampleRate" + audioSampleRate + "channelMask" + channelMask + "format" + format);
                    return -1;
                }
                @Override
                public byte[] readStreamBufferCustom(int sessionId, int length) {
                    Log.d(TAG, "readStreamBufferCustom");
                    Log.d(TAG, "length" + length);
                    byte[] result = new byte[length];
                    return byte[];
                }
                @Override
                public int closeAudioRecordCustom(int sessionId) {
                    Log.d(TAG, "closeAudioRecordCustom");
                    return 1;
                }
            }

     2. Register and deregister the listener in **onInitSuccess** and **unloadHiCarSdk**.
            
            public void onInitSuccess(HiCarAdapter hiCarAdapter) {
                carAudioRerCode = mHiCarAdapter.registerCarAudioCustomListener(mHiCarAudioCustomListener);
                if (carAudioRerCode != HiCarConst.SUCCESS) {
                     Log.d(TAG, "HiCar reg audio record listener failed, retCode:" + retCode);
                }
            }
            
            private void unloadHiCarSdk() {
                carAudioListenerRetCode = mHiCarAdapter.unRegisterCarAudioCustomListener(mHiCarAudioCustomListener);
                if (carAudioListenerRetCode != HiCarConst.SUCCESS) {
                     Log.d(TAG, "HiCar unreg audio custom listener failed");
                }
            }
