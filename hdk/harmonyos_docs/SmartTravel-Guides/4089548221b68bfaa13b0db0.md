# Development and Testing on the Head Unit

Complete the development and testing of the HiCar project on the head unit based on the implementation solution and plan.

#### UI/UE Design

Huawei has formulated clear UX specifications for products integrated with HiCar and provides design resources such as icons and connection screens required in the design phase. Related UX specifications and design resources are provided in the "Interaction Design" section on the left side of the website.

Vehicle manufacturers must strictly follow the HiCar UX specifications in the UI/UE design phase, and communicate with the Huawei team in a timely manner in case of any failure to comply with the specifications.

#### Integration and Development

#### [h2]HiCar System Architecture

The HiCar system aims to establish connections between mobile phones and vehicles. By building a shared resource pool between mobile phones and cars through distributed technologies, it manages to integrate mobile phone capabilities and ecosystem to the vehicle environment, ensuring seamless service connections and updated digital experience in travel scenarios.

#### [h2]Division of Responsibilities

In integration and development phases, Huawei will provide vehicle manufacturers with:

     * HiCar SDK and demo (versions for Android and Linux are provided respectively; for Linux, Huawei needs the head unit compilation toolchain for Linux before providing the compiled SDK).
     * Online development guide, API reference, and other documents.
     * CEPM system for Huawei to provide technical support and for vehicle manufacturers to track problems (<https://workplace.cbgcpm.huawei.com/#/group/partner/portal>). If the CEPM system is unavailable, contact Huawei technical support engineers in the project team.

**Table 1** Division of responsibilities in the integration of HiCarParticipant | Integration Step | Remarks  
---|---|---  
Vehicle manufacturer | Adaption of HiCar UI and UE to the head unit | Customizes and develops HiCar-related interfaces and interactions, including the wireless connection prompt (connection via PIN/QR code), connection exception prompt, connection loading screen, connection management screen, and converged desktop screen.  
HiCar HMI apps | Implements relevant service logic through standard APIs provided by the SDK for HiCar apps on the head unit.  
Preset of the HiCar SDK on the head unit | The SDK for Android comprises the following:
     * Binary files (.aar) of the Android library, which are compiled together with HMI apps.
     * System capability base (app packages and SO files), such as the app packages and SO files of Nearby Service and DMSDP modules, which must be preset in the ROM of the head unit.
The SDK for Linux comprises the SO files and API header files to be implemented by vehicle manufacturers.  
Bluetooth protocol stack adaptation for the head unit | This step is mandatory if the head unit supports proximity detection, and is optional if the head unit is connected via QR code scanning.  
Wi-Fi protocol stack adaptation for the head unit | This step is mandatory if the head unit supports wireless connection, and is optional if the head unit supports only wired connection.  
Adaptation to other peripherals | Adapts to the head unit's microphone, speaker, camera, and other peripherals. If the built-in camera of the head unit is invoked for video calls, the camera needs to adapt to and connect to HiCar.  
  
#### [h2]Problem Tracking and Resolving

Any technical problems or questions about the process during HiCar integration can be resolved as follows:

     1. Refer to the HiCar development guide, API reference, and other documents.
     2. If you cannot find an answer by referring to the documents, send an email with the questions attached, or contact the Huawei BD for a Q&A. Before the Q&A, send an email with the list of questions attached.
     3. Perform preliminary analysis and troubleshooting for bugs or other problems that should be resolved through log analysis. If the problem is found to lie with Huawei, submit a ticket in the CEPM system for Huawei to analyze and troubleshoot.

CEPM ticket submission rules:

        * Test environment: Fill in the mobile phone model and ROM version, head unit hardware platform and system version, HUAWEI HiCar app version on the mobile phone, and HMI app version on the head unit.
        * Test procedure: Fill in the detailed procedure for reproducing the problem.
        * Problem description: Fill in the time when the problem occurred and the preliminary analysis conclusion.

#### [h2]Self-test

Huawei provides complete self-test cases for the HiCar integration project. After the development of HiCar functions is complete, vehicle manufacturers need to complete the test according to the self-test cases before submitting the project for certification.

Passing the self-test cases 100% is the prerequisite for vehicle manufacturers to be certified by Huawei. During the certification, Huawei will review and spot-check the self-test reports provided by vehicle manufacturers.
