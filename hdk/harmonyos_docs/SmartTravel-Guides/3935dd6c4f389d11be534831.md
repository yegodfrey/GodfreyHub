# Handling Audio Focus

#### Audio Stream Types

The HiCar SDK defines the following audio stream types: media, ringtone, voice call, alarm, notification tone, and others.

#### Audio Focus Types

After a HiCar connection is set up between the phone and the head unit, HiCar will request the audio focus before playing the audio. The head unit also needs to notify HiCar of the current audio focus status by using the audio focus notification.

For the audio focus types that can be applied by HiCar while playing audio on the head unit, see Table 1.

The head unit notifies HiCar of the audio focus change when a native app is playing videos. For the corresponding focus change notifications, see Table 2.

**Table 1** Audio focus types for HiCar audio playbackDevice | Focus Type | Method | Description  
---|---|---|---  
Phone | Permanent focus | AUDIOFOCUS_GAIN | HiCar requests to occupy audio focus for an extended period of time. If focus is lost, the playback stops and the focus is released.  
Transient focus | AUDIOFOCUS_GAIN_TRANSIENT | HiCar requests to occupy audio focus for a short period of time. If focus is lost, the playback is paused.  
Duck focus | AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK | HiCar requests to occupy audio focus for a short period of time. If focus is lost, the playback can go on but the volume should be turned down or the playback should be paused.  
Exclusive and transient audio focus | AUDIOFOCUS_GAIN_TRANSIENT_EXCLUSIVE | HiCar requests to occupy audio focus for a short period of time. Other audio sources that don't have focus are expected to be muted.  
Releasing transient focus or transient focus with ducking | AUDIOFOCUS_RELEASE | HiCar requests for the release of audio focus.  
  
**Table 2** Focus change notifications sent by the head unit to HiCarDevice | Focus Type | Focus Change | Description  
---|---|---|---  
Head unit | Permanent focus | AUDIOFOCUS_LOSS | HiCar loses audio focus or cannot obtain audio focus.  
Transient focus | AUDIOFOCUS_LOSS_TRANSIENT | HiCar temporarily loses audio focus.  
Duck focus | AUDIOFOCUS_LOSS_TRANSIENT_CAN_DUCK | If the volume is decreased, HiCar can continue to play through the media channel.  
Releasing transient focus or transient focus with ducking | AUDIOFOCUS_GAIN | HiCar obtains audio focus.  
  
#### APIs

**Table 3** APIs for handling audio focusAPI | Method | Description  
---|---|---  
DMSDPAudioHandler | RegisterListener | Register an audio event listener.  
RequestAudioFocus | Requests focus from the head unit.  
AbandonAudioFocus | Releases focus to the head unit.  
DMSDPListener | UpdateServiceAction | The head unit notifies the HiCar SDK of the audio focus change.  
  
#### Development Procedure

HiCar manages audio focus by calling **RequestAudioFocus** and **AbandonAudioFocus**.

If audio focus changes on the head unit side, it notifies HiCar of the change by calling registered DMSDPListener.

     1. Register an event listener.

The HMI app registers the listener when the HiCar SDK is initialized. The structure is defined as follows:
            
            // Upon receiving the southbound **DMSDPAudioHandler.RegisterListener** , the head unit records and stores the listener.
            int32_t DMSDPExtendRegisterListener(const DMSDPListener *listener)
            {
                pthread_mutex_lock(&g_listener.lock);
                if (listener != NULL) {
                    g_listener.listener.UpdateServiceAction = listener->UpdateServiceAction;
                    g_listener.listener.UpdateServiceStatus = listener->UpdateServiceStatus;
                } else {
                    g_listener.listener.UpdateServiceAction = NULL;
                    g_listener.listener.UpdateServiceStatus = NULL;
                }
                pthread_mutex_unlock(&g_listener.lock);
                return 0;
            }

     2. The head unit applies for the audio focus from the HiCar.

When the head unit needs to apply for the focus from the HiCar SDK, it can apply for and release the focus by calling **UpdateServiceAction**.
            
            typedef struct {
                int32_t (*UpdateServiceStatus)(const char *id, uint32_t idLen, const DMSDPServiceStatus status);
                int32_t (*UpdateServiceAction)(const char *id, uint32_t idLen, DMSDPServiceAction *action);
            } DMSDPListener;

For example, when the head unit needs to temporarily preempt the focus, it sends the transient focus to the HiCar SDK, and HiCar will pause the music playback. After the head unit completes the playback and releases the focus, HiCar can resume the music playback.

The enum values of the focus type are defined in **dmsdp_audio_data_type.h**. **AUDIOFOCUS_LOSS_TRANSIENT** is used to apply for the transient focus, and **AUDIOFOCUS_GAIN** is used to release the transient focus.
            
            // The enum value for applying for the transient focus is **-2** (in the string presentation).
            DMSDPServiceAction requestAction = { AUDIO_FOCUS_CHANGE, "-2", 2 };
            g_listener.listener.UpdateServiceAction("testID", 6, &requestAction);
            // The enum value for releasing the transient focus is **1** (in the string presentation).
            DMSDPServiceAction abandonAction = { AUDIO_FOCUS_CHANGE, "1", 1 };
            g_listener.listener.UpdateServiceAction("testID", 6, &abandonAction);

     3. HiCar applies for the audio focus from the head unit.

When the HiCar SDK needs to use the focus of the head unit, it applies for and releases the focus by calling the following APIs:

The following code snippet requests audio focus. For details about the focus types, please refer to Table 1.
            
            /*
            * request audio focus
              * streamType the main audio stream type affected by the focus request
            * focusType: focus type
              */
            int32_t (*RequestAudioFocus)(int32_t streamType, int32_t focusType);

The following code snippet releases audio focus. There is no need to distinguish the focus that is being held during releasing.
            
            /*
            * abandon audio focus
            */
            int32_t (*AbandonAudioFocus)();
