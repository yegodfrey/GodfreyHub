# Configuring BR

#### Scenario Overview

The BR channel is required for wireless HiCar connection. After detecting the BLE advertising, the phone displays a prompt to notify the user. After the user confirms the connection, the connection procedure is triggered. (After the phone scans the BLE advertising, the BR connection will be triggered. In such a case, the phone proactively initiates a BR connection to start the device discovery and connection procedure.)

#### API Description

You need to implement the **FcDriverAdaptOps** variable (including certain APIs) of the device API (**driver_adapt.h**) in the HiCar SDK package.

Please refer to Table 1 for APIs that must be implemented in the **FcDriverAdaptOps** variable.

**Table 1****FcDriverAdaptOps** structureStructure | Structure Member | Description  
---|---|---  
FcDriverAdaptOps | name | BR driver name, which must be **BR_DRIVER_NAME**.  
desc | Description of the BR device API, which can be customized, for example, **br driver**.  
Init | BR driver Initialization API. The HiCar SDK calls this API to initialize the USB driver before using other BR APIs. This API ensures the proper startup of the protocol stack and prepares for the calling of the subsequent APIs.  
Deinit | BR driver deinitialization API, used to release related resources.  
SetParam | API that is called by the HiCar SDK to set BR parameters for vendors. The parameters to be set include the mapping between **service uuid** and **sessionId**.  
GetParam | API used by the HiCar SDK to obtain the MAC address of the BR and the channel ID of the data channel.  
Connect | API called when the head unit automatically connects to the phone based on the **sessionId**.  
Disconnect | API used to disable a specified BR channel and release the resources occupied by the channel.  
SendData | API called by the HiCar SDK to send data to the phone through the BR channel.  
RegisterChannelCallback | API called by the BR driver to save the application APIs registered by the HiCar SDK.  
  
For details about the implementation of the **FcDriverAdaptOps** variable, see the BR demo code (**driver_br.c**) in the HiCar SDK. Note that the variable name must be **g_fcDriverBrOps**.

The HiCar SDK calls the APIs implemented by vendors in the following sequence:

     1. When wireless HiCar connection is initiated for the first time:
        1. Call **Init** to initialize the BR driver.
        2. Call **SetParam** to set the mapping between sessions and **serviceUuid**.
        3. Call **GetParam** to obtain the MAC address of the head unit BR.
        4. During data interaction, call **SendData** to send data to the BR service of the peer phone.
        5. When exiting the Nearby service, call **Deinit** to release BR driver resources.
     2. When the connection is performed automatically:
        1. Call **Init** to initialize the BR driver.
        2. Call **SetParam** to set the mapping between sessions and **serviceUuid**.
        3. Call **Connect** to connect to the BR service on the phone.
        4. During data interaction, call **SendData** to send data to the BR service of the peer phone.
        5. When exiting the Nearby service, call **Deinit** to release BR driver resources.

#### Development Procedure

     1. Implement the BR initialization API **Init** , to ensure the proper startup of the protocol stack.
     2. Implement the BR driver deinitialization API **Deinit** , to release related resources.
     3. Implement **SetParam** for setting BR parameters.

When **paramType** is set to **SET_BR_UUID** , the pointer of the **ServiceUuidRelatedSessionId** type is used to receive **paramValue**. Save the mapping between **serviceUuid** and **sessionId** in the **ServiceUuidRelatedSessionId** structure and monitor **serviceUuid**. When the channel status corresponding to **serviceUuid** changes, **ChannelStateChange** provided by the HiCar SDK is called. When data from the phone is received, **ReceiveData** provided by the HiCar SDK can be called to report the data to the HiCar SDK for further processing.

The following is the sample code:
            
            /*
             * @function   : BrSetParam
             * @brief      : Set the BR parameters. The BR needs to adapt to **SET_BR_UUID**.
             * @param[IN]  : paramType. For details, see **SetParamsType**.
             * @param[IN]  : context, used to set the value of **paramType**.
             * @return     : Returns **0** if successful; returns a non-zero value if otherwise.
             */
            static int BrSetParam(SetParamsType paramType, const void *context)
            {
                printf("BrSetParam[in] paramType:%d.\r\n", paramType);
                if (context == NULL) {
                    printf("BrSetParam[in] input param is invalid. paramType:%d\r\n.", paramType);
                    return RESULT_RET_ERROR;
                }
            
                if (paramType == SET_BR_UUID) {
                    // Register the service UUID and record the mapping relationship. The channel will be subsequently managed based on the session ID.
                    ServiceUuidRelatedSessionId *serviceUuid2SessionId = (ServiceUuidRelatedSessionId *)context;
                    char serviceUuid[BT_SERVICE_UUID_LEN + 1] = {0};
                    (void)strncpy(serviceUuid,
                        serviceUuid2SessionId->serviceUuid,
                        BT_SERVICE_UUID_LEN);  // (void)strcpy_s(serviceUuid, BT_SERVICE_UUID_LEN + 1,
                                               // serviceUuid2SessionId->serviceUuid);
            
                    int sessionId = serviceUuid2SessionId->sessionId;
                    printf("BrSetParam[in] paramType:SET_BR_UUID, sessionId:%d, serviceuuid:%s.\r\n", sessionId, serviceUuid);
            
                    // Monitors the BR service UUID.
            
                } else {
                    printf("BrSetParam[in] unknown paramType:%d.\r\n", paramType);
                    return RESULT_RET_ERROR;
                }
            
                return RESULT_RET_OK;
            }

     4. Implement **GetParam** , which is an API to obtain device parameters.

The adaptation is required only when **paramType** is set to **GET_DEV_MAC** or **GET_MAP_PORT** :

        * In the case of **GET_DEV_MAC** , the MAC address of the head unit's BR channel is obtained. In such a case, the type of **paramValue** is **MacParam**. The vendor returns the MAC value.
        * In the case of **GET_MAP_PORT** , the input parameter **result** needs to be parsed based on the **ServiceUuidMapPort** type. The **ServiceUuidMapPort** type data contains the UUID of the char* type of the Bluetooth service. The vendor needs to query the port (also called **channelId**) corresponding to the service in the Bluetooth protocol stack based on the UUID. **channelId** is of the int type and its value must be greater than 0. You can directly assign a value to **ServiceUuidMapPort- >port**.

The following is the sample code:
    
    /*
     * @function   : BrGetParam
     * @brief      : Obtains the BR parameter information. The BR needs to adapt to the case where **paramType** is set to **GET_DEV_MAC** or **GET_MAP_PORT**.
     * @param[IN]  : paramType. For details, see **GetParamsType**.
     * @param[out] : result, which indicates the obtained parameter value.
     * @return     : Returns **0** if successful; returns a non-zero value if otherwise.
     */
    static int BrGetParam(GetParamsType paramType, void *result)
    {
        printf("BrGetParam[in], paramType:%d.\r\n", paramType);
        if (result == NULL) {
            printf("BrGetParam[in] paramType is invalid. paramType:%d.\r\n", paramType);
            return RESULT_RET_ERROR;
        }
    
        if (paramType == GET_DEV_MAC) {
            // get device mac
            MacParam *macParam = (MacParam *)result;
            //Note: The MAC address must be in uppercase.
            char macSrc[STR_MAC_ADDR_LEN + 1] = "12:34:56:78:9A:1F";
            (void)strncpy(macParam->mac, macSrc, macParam->len);  // strcpy_s(macParam->mac, macParam->len, macSrc);
            printf("BrGetParam[in], paramType:GET_DEV_MAC, get br mac:%s.\r\n", macParam->mac);
        } else if (paramType == GET_MAP_PORT) {
            // get service uuid map port
            ServiceUuidMapPort *uuid2Port = (ServiceUuidMapPort *)result;
            char serviceUuid[BT_SERVICE_UUID_LEN + 1] = {0};
            (void)strncpy(serviceUuid,
                uuid2Port->serviceUuid,
                BT_SERVICE_UUID_LEN);  // (void)strcpy_s(serviceUuid, BT_SERVICE_UUID_LEN + 1, uuid2Port->serviceUuid);
    
            uuid2Port->port = 4;  // Obtain the port (also called **channelId**) mapped to the **BR_SERVICE_UUID** from the protocol stack.
            printf("BrGetParam[in], paramType:GET_MAP_PORT, get map port:%d.\r\n", uuid2Port->port);
        } else {
            printf("BrGetParam[in], unknown paramType:%d.\r\n", paramType);
            return RESULT_RET_ERROR;
        }
    
        return RESULT_RET_OK;
    }

     5. Implement **RegisterChannelCallback**.

The type of the **channelCallback** parameter is **ChannelCallback** , which is an input parameter of the HiCar SDK and contains APIs to be called during BR connection. BR status changes and received data are uploaded to the HiCar SDK via the related APIs. The BR driver calls only the two function pointers in the **channelCallback** parameter:

        1. **ChannelStateChange** (called when the BR channel status changes). When calling this function, a parameter with the type being **BrChannelData** and a one with the type being **EventType** need to be passed. For **BrChannelData** , **sessionId** needs to be provided (see step 3 for the information about how to obtain **sessionId**. **EventType** indicates the channel status, which can be either **EVENT_CONNECT** (channel established) or **EVENT_DISCONNECT** (channel disconnected).
        2. **ReceiveData** (called when the BR driver uploads Bluetooth data to the HiCar SDK). When the Bluetooth protocol stack receives data from the peer end, this function will be called, with four parameters passed. The first parameter must be **CHANNEL_BREDR**. The second parameter is of the **BrChannelData** type, and **sessionId** needs to be provided. The third parameter is the data to be uploaded, and the fourth parameter is the length of the data to be uploaded.
     6. Implement **Connect**.

Use the **BrChannelData** type to receive the **channelInfo** parameter. This API is called only when the head unit initiates a connection with the phone, using the **sessionId** and **MAC address** in the parameters.

     7. Implement **Disconnect**.

The **channelInfo** parameter is received by using the **BrChannelData** type. The BR channel specified by **sessionId** in the parameter is disabled, and the related resources are released.

     8. Implement **SendData**.

The **data** parameter indicates the data that needs to be sent to the phone. **dataLen** indicates the length of the data to be sent in bytes. **sessionId** is specified in the **channelInfo** parameter of the **BrChannelData** type. The vendor needs to find the corresponding Bluetooth UUID based on the **sessionId** to send data to the peer end. (For details about the mapping between the Bluetooth UUID and **sessionId** , see step 3.)

The following is the sample code:
            
            /*
             * @function   : BrSendData
             * @brief      : Sends data over the BR APIs.
             * @param[IN]  : data, which indicates the data to be sent.
             * @param[IN]  : dataLen, which indicates the length of the data to be sent.
             * @param[IN]  : context. For the data structure of the channel, see **BrChannelData**.
             * @return     : Returns **0** if successful; returns a non-zero value if otherwise.
             */
            static int BrSendData(const unsigned char *data, int dataLen, const void *context)
            {
                if ((data == NULL) || (dataLen <= 0) || (context == NULL)) {
                    printf("BrSendData[in] input is invalid.\r\n");
                    return RESULT_RET_ERROR;
                }
            
                BrChannelData *channelInfo = (BrChannelData *)context;
                // Send data through different channels based on the **sessionId**.
                printf("BrSendData[in] sessionId:%d, remoteMac:%s.\r\n", channelInfo->sessionId, channelInfo->remoteMac);
            
                return RESULT_RET_OK;
            }
