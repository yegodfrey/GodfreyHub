# Managing Voice Interactions

#### Scenario Overview

HiCar allows users to use its functions through voice interactions, such as voice navigation, voice control of air conditioners, and voice control of music playback. You will need to wake up HiCar voice interaction so that your users can be able to interact with HiCar through voice commands.

HiCar voice interaction wakeup can be triggered by touching an icon, using the physical key, or via voice commands.

#### [h2]1. Touching an Icon for Wakeup

The user wakes up HiCar voice interaction by touching the voice ball icon. In this case, the entire process is implemented by HiCar and you do not need to perform any operations.

#### [h2]2. Using the Physical Key for Wakeup

The user can press the voice wakeup key on the steering wheel to wake up HiCar voice interaction. In this case, you need to parse the physical key event and send the wakeup data to HiCar on the phone side using the **sendHotWord** API provided by the HiCar SDK. HiCar then completes the subsequent voice recognition processing.

Physical key wakeup for HiCar works as follows:

     * If the head unit features native voice functions, the user can press and hold the physical key to wake up HiCar voice interaction. During a voice interaction session, each time the user presses and holds the physical key, voice interaction will be woken up again. Pressing the physical key without holding it will cause voice interaction to exit. 
     * If the head unit does not have native voice function, the user can press the physical key once to wake up HiCar voice interaction. During a voice interaction session, each time the user presses and holds the physical key, voice interaction will be woken up again. Pressing the physical key without holding it will cause voice interaction to exit. 

When the voice wakeup button is triggered, determine whether to distribute the button event of voice recognition start or end based on the current voice wakeup status of HiCar. For details about the HiCar voice status, please refer to [Voice State](https://developer.huawei.com/consumer/cn/doc/development/SmartTravel-Guides/voice-status-0000001051370067).

#### [h2]3. Voice Wakeup

The user can wake up HiCar voice interaction with voice commands. This includes two scenarios: 
     * The user wakes up HiCar voice interaction through the phone's voice assistant. In this case, the entire process is implemented by HiCar and you do not need to perform any operations. 
     * The user wakes up the HiCar voice interaction through the native voice recognition app of the head unit. In this case, you need to identify "Xiaoyi Xiaoyi" and "Nihao YoYo" in the native voice recognition app of the head unit, and send the wakeup data to HiCar on the phone side using the **sendHotWord** API provided by the HiCar SDK. HiCar then completes the subsequent voice recognition processing. 

#### API Description

**Table 1** APIs for voice wakeup  Class | Method | Description  
---|---|---  
HiCarAdapter | sendHotWord | Sends a popular keyword to wake up HiCar voice interaction. For details about the wakeup data format, see Table 2.  
  
**Table 2** Head Unit Side Voice Interaction APIs  **Parameter** | **Mandatory** | **Type** | **Description**  
---|---|---|---  
frontEndInfo | - | - | Yes | map | Head unit information.  
wakeType | - | Yes | string | Wakeup mode:
     * **voice** : Voice wakeup, for which **wakeWord** must be specified. 
     * **buttonPress** : Wakeup by operations on the physical button.   
intent | - | Yes | string | User intent:
     * **startVoiceRecognize** : Start voice recognition after saying the voice wakeup phrase or pressing the physical key. 
     * **stopVoiceRecognize** : Stop voice recognition by pressing the physical key.   
voice | - | Yes | map | Voice information.  
wakeWord | No | string | Voice wakeup phrases: "Xiaoyi Xiaoyi" or "Nihao YOYO".  
vendorName | Yes | string | Provider of front-end voice processing, such as "xunfei" and "baidu".  
version | Yes | string | Version of the app that implements front-end voice processing, such as "10.0.0.1".  
infoToVendorCloud | No | string | Information sent to the cloud: The front-end voice processing must follow the same specifications as that used by the voice service provider.  
centralControl | - | Yes | map | Head unit central control information.  
vendorName | Yes | string | Provider of the head unit central control system, such as "PATEO".  
version | Yes | string | Version of the head unit central control system, such as "10.0.0.1".  
car | - | Yes | map | Vehicle info.  
micNumber | Yes | int | Number of microphones.  
speakerNumber | Yes | int | Number of speakers.  
  
When the HiCar voice is in the wakeup advertising state, if the native voice assistant of the head unit is woken up, you can send the **stopVoiceRecognize** intent to HiCar to cancel the HiCar voice wakeup, avoiding simultaneous voice advertisement.

For details about the wakeup data, refer to [Voice Vehicle Wakeup](https://developer.huawei.com/consumer/cn/doc/development/SmartTravel-References/voice-wakeup-0000001199330033) in the **APIs Between the HiCar App and Head Unit** section in the _HUAWEI HiCar SDK API Reference_.

#### Development Procedure

#### [h2]Using the Physical Button for Wakeup

     1. You need to parse physical key events based on your own head unit system.
     2. After a physical key event for wakeup is triggered, the **sendHotWord** API provided by the HiCar SDK needs to be called to send wakeup data.

The following is the sample code for assembling and sending wakeup data:
            
            String hotWordStr =
            "{\n" +
            "	\"frontEndInfo\": {\n" +
            "		\"car\": {\n" +
            "			\"micNumber\": 2,\n" +
            "			\"speakerNumber\": 4\n" +
            "		},\n" +
            "		\"centralControl\": {\n" +
            "			\"vendorName\": \"XX\",\n" +
            "			\"version\": \"10.0.0.12\"\n" +
            "		},\n" +
            "		\"intent\": \"startVoiceRecognize\",\n" +
            "		\"voice\": {\n" +
            "			\"infoToVendorCloud\": \"HicarManager\",\n" +
            "			\"vendorName\": \"10.0.0.12\",\n" +
            "			\"version\": \"12\"\n" +
            "		},\n" +
            "		\"wakeType\": \"buttonPress\"\n" +
            "	}\n" +
            "}\n";
            **mHiCarAdapter.sendHotWord(hotWordStr);**

     3. After the wakeup data is sent, the HiCar voice assistant enters the wakeup state. In this case, set parameters such as echo cancellation and noise reduction for the microphone of the head unit to achieve better sound pickup effect.

You can call the voice status API to determine the current voice state, and perform operations like echo cancellation and noise reduction when in the wakeup state. For details about the voice states, see [Voice State](https://developer.huawei.com/consumer/cn/doc/development/SmartTravel-Guides/voice-status-0000001051370067).

     4. After a physical key event for exiting voice interaction (or the local voice assistant) is triggered, the **sendHotWord** API provided by the HiCar SDK needs to be called to stop sending wakeup data.

The following is the sample code for stopping voice interaction when a physical key event is triggered.
            
            **** String hotWordStr =
            "{\n" +
            "	\"frontEndInfo\": {\n" +
            "		\"car\": {\n" +
            "			\"micNumber\": 2,\n" +
            "			\"speakerNumber\": 4\n" +
            "		},\n" +
            "		\"centralControl\": {\n" +
            "			\"vendorName\": \"XX\",\n" +
            "			\"version\": \"10.0.0.12\"\n" +
            "		},\n" +
            "	        \"intent\": \"s**topVoiceRecognize\** ",\n" +
            "		\"voice\": {\n" +
            "			\"infoToVendorCloud\": \"HicarManager\",\n" +
            "			\"vendorName\": \"10.0.0.12\",\n" +
            "			\"version\": \"12\"\n" +
            "		},\n" +
            "		\"wakeType\": \"buttonPress\"\n" +
            "	}\n" +
            "}\n";
            **mHiCarAdapter.sendHotWord(hotWordStr);**

#### [h2]Using Voice for Wakeup

     1. Make sure that your native voice system recognizes "Xiaoyi Xiaoyi" and "Nihao YoYo".
     2. Assemble wakeup data and send it to the HiCar app via the **sendHotWord** API provided by the HiCar SDK.

The following is the sample code for assembling and sending wakeup data:
            
            String hotWordStr ="{" +
            "    \"frontEndInfo\":" +
            "    {\"wakeType\":\"voice\"," +
            "    \"intent\":\"startVoiceRecognize\"" +
            "   ,\"voice\":{\"wakeWord\":\" Xiaoyi Xiaoyi \"}" +
            "    }" +
            "}"
            **mHiCarAdapter.sendHotWord(hotWordStr);**
