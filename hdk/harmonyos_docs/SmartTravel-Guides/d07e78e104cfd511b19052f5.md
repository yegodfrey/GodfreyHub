# Initializing the SDK

#### Scenario

The HMI app should provide the head unit parameters during the initialization of the HiCar SDK, such as the screen size, Bluetooth address, driver position, and head unit type. Then, initialize the SDK at a proper time (generally when the user needs to use the vehicle, for example, after the head unit system is powered on and the screen of the head unit system is turned on).

#### API Description

**Table 1** Initialization APIsClass | Method | Description  
---|---|---  
HiCarAdapter | init | The HMI app should call the **init** API to initialize the HiCar SDK when the user uses the vehicle (for example, the head unit screen turns on after the vehicle is started).  
  
The initialization process is an asynchronous process. The initialization result is returned to the HMI app through event callback. For details about the callbacks related to initialization, see Table 2.

**Table 2** Initialization Callback MethodsAPI | Callback Method | Description  
---|---|---  
HiCarInitCallback | onInitSuccess() | Callback for successful initialization. After the initialization is successful, the SDK returns a **HiCarAdapter** instance. The HMI app should save this instance because calling other APIs in the SDK require this instance too.  
onInitFail() | Callback for failed initialization. If the operation fails, the SDK returns an error code. For details about the cause of error, see the _HUAWEI HiCar SDK API Reference_.  
onBinderDied() | Callback for unexpected exits of submodules of HiCar, such as the DMSDP, Nearby, and HiSight modules. When receiving this callback, the HMI app should call the **unRegisterCarListener** and **deInit** methods to clear resources related to the HiCar SDK. In addition, **to improve the connection stability, and avoid consecutive connection failures and unexpected process killing, it is recommended that you add operations of restarting the SDK and HMI app in the onBinderDied() callback method of the HMI app.**  
  
#### Development Procedure

     1. The HMI app should set the basic information of the head unit before calling the **init** API to initialize the HiCar SDK.

For details about supported parameters, see Table 3.

**Table 3** Required configurations during SDK initializationCategory | Attribute | Mandatory | Data Type | Unit | Description  
---|---|---|---|---|---  
Core parameters of the head unit | **modelID** | Yes | String | - | The value is usually an 8-digit number, for example, **00010001**. The first six digits identify the vehicle manufacturer, and the last two digits identify the vehicle model. The value is allocated by Huawei to the vehicle manufacturer. Each vehicle model has a unique **ModelID**. The SDK uses this value to obtain the information about the vehicle manufacturer and model.  
**brMac** | Yes | String | - | Bluetooth MAC address of the vehicle head unit. The SDK uses this value to generate the unique identifier of the head unit.  
**HardwareInfo** | Yes | HardwareInfo | - | Head unit hardware information. NOTE: **HardwareInfo** contains the vehicle manufacturer name, Bluetooth chip model, and Wi-Fi chip model. The head unit hardware information must be set and the value cannot be empty. If this information is not set or is empty, the SDK initialization fails.  
Projection parameters | Surface | No | Surface | - | Projection surface object.  
ScreenWidth | No | int | Pixel | Width of the screen resolution, for example, 1920. It is recommended that you set this parameter. Otherwise, the SDK attempts to obtain the value through the operating system function.  
ScreenHeight | No | int | Pixel | Height of the screen resolution, for example, 720. It is recommended that you set this parameter. Otherwise, the SDK attempts to obtain the value through the operating system function.  
ScreenSize | No | float | Inch | Length of the screen diagonal, for example, 10.4. It is recommended that you set this parameter. Otherwise, the SDK attempts to obtain the value through the operating system function.  
PhysicsWidth | No | int | mm | Physical width of the screen, which can be calculated based on the resolution and screen size.  
PhysicsHeight | No | int | mm | Physical height of the screen, which can be calculated based on the resolution and screen size.  
VideoWidth | No | int | Pixel | Width of the projection area. The default value is the same as the screen width (in full-screen display).  
VideoHeight | No | int | Pixel | Height of the projection area. The default value is the same as the screen height (in full-screen display).  
DefaultBitrate | No | int | - | Default projection bit rate. The default value is 2 x 1000 x 1000. This parameter can be used to improve the image quality. Under the same network quality, a larger value indicates better image quality. The value is between 500 x 1000 and 20 x 1000 x 1000. The default bit rate can be dynamically updated when the SDK is running. NOTE: The values of **DefaultBitrate** , **MaxBitrate** , and **MinBitrate** must be set at the same time.  
MaxBitrate | No | int | - | Maximum projection bit rate, which is dynamically adjusted during HiCar projection. The maximum bit rate is the upper limit of the adjustment, and the maximum value is 20 x 1000 x 1000. The maximum bit rate can be set only once during the initialization of the HiCar SDK.  
MinBitrate | No | int | - | Minimum projection bit rate, which is dynamically adjusted during HiCar projection. The minimum bit rate is the lower limit of the adjustment, and the minimum value is 500 x 1000. The minimum bit rate can be set only once during the initialization of the HiCar SDK. For details about the bit rate corresponding to each resolution in the H.264 video encoding format, please refer to Table 4.  
Dpi | No | int | - | Dots per inch. The value range is 120–640. The policy for the **dpi** parameter is described as follows:
        * If you have set the **dpi** parameter, this value will take effect.
        * If you have not set the **dpi** parameter, the DPI can still be calculated based on the width, height, and screen size.
        * If you have not set the **dpi** parameter, and the DPI can't be calculated based on other specified parameters, the default value **320** will take effect.  
Fps | No | int | - | Frame per second. The default value is 30. The value range is 20–60.  
Gop | No | int | - | Interval between two I-frames. The default value is 30. The value range is 30–600.  
CodecType | No | int | - | Video encoding mode. The options are as follows:
        * **1** : H.264 (default value)
        * **2** : H265  
CodecConfigureFlag | No | int | - | Customized configuration parameter of the projector decoder. Use the default value **0** , which indicates that no customization is required.  
Function parameters | isSupportWireless | No | boolean | - | Indicates whether wireless connection is supported. The default value is **true**.  
isSupportUsb | No | boolean | - | Indicates whether wired connection is supported. The default value is **true**.  
isSupportReconnect | No | boolean | - | Indicates whether automatic connection is supported. The default value is **false**.  
InitialConfig | No | Map<String,String> | - | HiCar requires the initialization configurations such as the Dark/Light mode and driving position. For details, please refer to Table 5.  
CameraCustomDefine | No | CameraCustomDefine | - | Hardware information of the camera supported by the head unit. For details, please refer to [Configuring Camera Information](https://developer.huawei.com/consumer/cn/doc/development/SmartTravel-Guides/configure-camera-0000001064941294).  
AdvPower | No | int | - | BLE advertising signal strength. The value range is –128 to +127. A larger value indicates stronger signals.  
Support5gChannels | No | int[] | - | List of 5 GHz channels supported by the head unit. The default value is **[36,40,44,48,149]**.  
DefaultAudioFormat | No | int | - | **(Beta)** Default audio data output format:
        * **0** : AAC
        * **1** : PCM (default value), which is recommended when the Wi-Fi transmission rate of the head unit reaches 320 Mbps or higher.
NOTE: When AAC audio data is played on the head unit, the HiCar SDK decodes the data and then calls **AudioTrack** to play the data. For head units with lower performance, the CPU usage is high during audio decoding, which may cause intermittence during audio playback.  
AudioSourceConfig | No | Map<String, String> | - | AudioSource configuration information. Configure this parameter when the head unit needs to modify **MIC** and **VOICE_COMMUNICATION** in **AudioSource**. For details about the parameter key, please refer to Table 6.  
AudioDelayBuffer | No | int | - | Number of buffered audio frames, which ranges from 5 to 40.  
IsAllowMediaButton | No | boolean | - | Indicates whether button messages can be listened for with **MediaSession**. The default value is **false** (listening is not supported).

**Table 5****InitialConfig** information during initializationValue | Type | Description  
---|---|---  
isOnlyParkAllow | String | Whether entertainment apps (such as video and game apps whose icons are marked with the character "P") are available during driving:
        * **1** : Entertainment apps are available only when the vehicle is parked.
        * **0** : Entertainment apps are always available (default value).  
isSupportRoundCorner | String | Style of the HiCar screen's four corners:
        * **0** : rounded corner (default value)
        * **1** : square corner  
CAR_BRAND | String | Vehicle brand information, which is displayed below the vehicle logo icon on the native vehicle system UI after successful projection.
        * When the vehicle brand information can be obtained, set this parameter based on the actual vehicle brand.
        * If the head unit cannot obtain the vehicle brand information, set this parameter to **notsupport** , which is the default value.  
DAY_NIGHT_MODE | String | Indicates whether the vehicle can detect Dark/Light mode and its current mode:
        * **day** : Light mode
        * **night** : Dark mode
        * **notsupport** : The Dark/Light mode is not supported. This is the default value.
        * **pending** : The current mode cannot be determined, but the information can be dynamically sent to HiCar later.  
DRIVING_POSITION | Int | Position of the driver's seat in the vehicle.
        * **left** : The driver is on the left (default value).
        * **right** : The driver is on the right.  
INPUT_FEATURES | Int | Operation mode supported by the screen of the head unit, which is determined based on the bit.
        * Touchscreen: Bit 0. **1** : supported; **0** : not supported.
        * Knob: Bit 1. **10** : supported; **00** : not supported.
        * Touch panel: Bit 2. **100** : supported; **000** : not supported.
You will need to convert the result into int-type data based on the actual situation and report the data. For example, if the touchscreen (1) is supported, report **1**. If the knob (10) is supported, report **2**. If the touchscreen and knob (11) are supported, report **3**. If all control modes (111) are supported, report **7**.  
PRIMARY_INPUT | Int | Main operation mode of the head unit. One or more main operation modes can be reported.
        * **1** : Touchscreen (default value).
        * **2** : Knob.
        * **3** : Touchpad.  
DEVICE_TYPE | Int | Head unit type.
        * **0** : Unknown head unit (default value).
        * **1** : Reserved device A
        * **2** : Reserved device B
        * **3** : Smart display powered by HUAWEI HiCar
        * **4** : Pre-installed head unit

     2. The HMI app initializes the SDK by calling the **init** API.

The following is the sample code:
            
            // Initialize the SDK.
            HiCarAdapter.init(getApplicationContext(), carconfig, new HiCarInitCallback() { 
                @Override 
                public void onInitSuccess(HiCarAdapter hiCarAdapter) { 
                    Log.i(TAG, "HiCar onInitSuccess");

                        return; 
                    } 
                    
                    Log.i(TAG, "HiCar reg listener success"); 
                } 
            
                @Override 
                public void onInitFail(int errorCode) { 
                    Log.i(TAG, "HiCar init failed");
