# Beep Tone of the Voice Prompt

#### Scenario Overview

In the voice interaction between the HiCar and the head unit, if a virtual audio channel needs to be recreated, the beep tone of the voice prompt may be lost or become a crack sound due to overlong delay. To avoid this situation, you can save the beep tone file on the head unit. After receiving the notification message from the HiCar app, the head unit broadcasts the beep tone locally.

For details about the related data format, please refer to [Voice Prompt Broadcast](https://developer.huawei.com/consumer/cn/doc/development/SmartTravel-References/voice-prompt-announcement-0000001199339969) in the **APIs Between the HiCar App and Head Unit** section in the API Reference.

#### Development Procedure

     1. The HiCar app queries whether the head unit can play the beep tone locally.
        1. After the connection is successful, the HiCar app sends a query message (**dataType = 519**) to the head unit to query whether the head unit can play the beep tone locally. The following is an example:
               
               {
                   "isVoicePromptSupport":1
               }

        2. The head unit uses the **DataReceive** method to determine the data type and then receives the preceding data. Then, the head unit returns a response message through the **HiCarSendData** API.

Example: The head unit can play the beep tone locally.
               
               {
                   "isVoicePromptSupport":2
               }

Example: The head unit cannot play the beep tone locally.
               
               {
                   "isVoicePromptSupport":-1
               }

     2. The HiCar app instructs the head unit to start or stop playing the beep tone. Example:
            
            //Start to play the beep tone.
            {
                "voicePrompt":1
            }
            
            //Stop playing the beep tone.
            {
                "voicePrompt":0
            }
