# Handling Video Frame Loss

#### Scenario

During projection, upon receiving video frame data from the phone, the HiCar SDK sends the video frame data to the HMI app via the **GetVideoData** function registered by the HMI app during initialization. The registered **GetVideoData** function cannot contain time-consuming operations, in order not to block subsequent callbacks.

The HMI app can locally maintain a list of video frames for decoding and display. If video frames are stacked, some video frames can be discarded to ensure real-time projection. In case of video frame loss, the HMI app can request I-frames through the HiCar SDK API to restore the decoding of subsequent video frames.

#### APIs

**Table 1** APIs for handling video frame lossHeader File | Method | Description  
---|---|---  
hicar.h | HiCarPostEvent | When an I-frame is requested, **CarEventType** in the input parameter is set to **HICAR_EVENT_REQUEST_IDRFRAME** and**content** can be NULL.  
  
#### Development Procedure

     1. Register the **GetVideoData** function for video data callback during the HiCar SDK initialization. For details, please refer to [Registering Event Callbacks](https://developer.huawei.com/consumer/cn/doc/development/SmartTravel-Guides/register-event-listener-0000000000105633).
     2. Decode the video in the callback function and send it to the display. In addition, add an exception handling process. When video data is stacked, discard frames and request I-frames by calling the **HiCarPostEvent** API.
