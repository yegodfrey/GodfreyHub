# Implementation Suggestion

#### Code Structure

The following describes the components and peripheral services of the HMI app:

     * UI resources: UI and animation resources involved in guidance and exception prompt during connection.
     * HiCarActivity: Main UI of the HMI app, which is used to interact with users and process UI-related logic and features.
     * HiCarService: Main service of the HMI app, which is used for HiCar SDK interaction and processing logic such as connection and projection.
     * Handler: Abstraction of different service logics that need to be implemented in the HMI app. The implementations may differ depending on vehicle models.
     * HandlerFactory: Instantiation service of the Handler object. It enables the same set of HMI app code to load the required Handler on different head units through attributes such as compilation options.
     * Other apps: Other apps on the head unit that interact with HiCar, such as voice assistant, navigation, call, and settings.
     * Vendor-customized services: System-level services developed by vendors that interact with HiCar and do not use Android standard APIs, such as the steering wheel button service, power management service, and audio service.

#### Initiation Suggestion

HiCarService needs to be automatically started with the system. The startup mode depends on the head unit. The following lists the typical modes:

     1. (Recommended) Modify the system framework layer and allow HiCarService to start after the head unit is started. It is recommended that the FWK start HiCarService after UserUnlock is started.
     2. (Not recommended) Start HiCarService based on the BOOT_COMPLETED startup broadcast. Generally, the boot broadcast has a delay, which affects the performance of HiCar automatic connection. Therefore, this mode is not recommended unless necessary.
     3. (Others) Other mechanisms on the head unit indirectly start HiCarService.

To reduce the chance of the HiCarService-related processes getting killed, increase the priority of these processes. It is recommended that you set them to foreground or visible processes. Alternatively, increase the priority by configuring a trustlist based on the actual situation of the head unit.
