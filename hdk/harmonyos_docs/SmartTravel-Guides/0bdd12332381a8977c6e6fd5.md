# Sending a USB Control Command

#### Scenario

After detecting a new device via USB, the head unit needs to check whether **vendorID** is **0x12D1** or **0x339B** (indicating a Huawei or Honor phone). If it is, the head unit encapsulates the vehicle information (including model ID, Bluetooth MAC address, IP address, and port number) according to the Nearby interconnection protocol specifications, and sends it to the phone through the USB command word transmission API.

Table 1 shows the data format of the interconnection protocol header.

**Table 1** Data format of the Nearby interconnection protocol headerField | Size (byte) | Description  
---|---|---  
magic_string | 8 | Indicates compliance with the Nearby interconnection protocol. This field has a fixed value of **hwnearby**.  
total_len | 2 | Indicates the total length, including the length of the protocol header and data (not more than 256 bytes).  
type | 2 | Indicates the type of the connected device. This field has a fixed value of **0x01**.  
version | 2 | Indicates the protocol version. For version 1.0, the value is **0x0100**.  
subtype | 2 | Indicates the interconnection subservice. This field has a fixed value of **0x01**.  
  
The extended data is in TLV format. For details, please refer to Table 2.

**Table 2** Extended data formatTag | Length (byte) | Description  
---|---|---  
0 | 1 | **0x01** : NCM **0x02** : AOA **0x03** : NCM+AOA More IDs can be included. Currently, only NCM (**0x01**) is supported.  
1 | 3 | **ModelID**.  
2 | 1 | Sub-model ID. **SubModelID** is the fourth byte of the **ModelID**.  
3 | 32 | **DeviceID** : sha256(**ModelID** +**SubModelID** +Bluetooth MAC address) The letters in the MAC address must be uppercase.  
4 | 6 | Bluetooth MAC address. The letters in the MAC address must be uppercase.  
5 | Variable length | Device name.  
6 | 14 | IP address: The format is 192.168.66._xxx_ , with _xxx_ within the range from 100 to 255.  
7 | 4 | Port number of the socket server.  
  
Table 3 describes the format of a USB control command sent by the head unit.

**Table 3** USB control command formatField | Size (byte) | Description  
---|---|---  
bmRequestType | 1 | 0x40: USB_DIR_OUT | USB_TYPE_VENDOR  
bRequest | 1 | 0x34  
wValue | 2 | 0x00  
wIndex | 2 | 0xA0  
wLength | 2 | Actual length of the transmitted data. The maximum length is 256 bytes.  
  
#### Development Procedure

The sample code for the head unit to send a USB control command is as follows:
    
    // For example:
    if (libusb_device_descriptor.idVendor == VENDOR_ID_HUAWEI || libusb_device_descriptor.idVendor == VENDOR_ID_HONOR) {
        unsigned char data[256] = {0};
        FillUsbControlBuffer(data); //Fill in the data according to the Nearby interconnection protocol.
        /**
    * In the preceding information, the **data** field indicates the vehicle information to encode, which contains a maximum of 256 characters.
          */
        libusb_control_transfer(0x40, 0x34, 0, 0xA0, data, data.length, 2000);
    }
    
    int FillUsbControlBuffer(uint8_t *buf) {
        int totalLen = 0;
        // fill nearby head
        HiCarNearbyHead *pHead = (HiCarNearbyHead*)(buf + totalLen);
        totalLen += sizeof(HiCarNearbyHead);
        memcpy(pHead->magic_string, HICAR_NEARBY_STRING, 8);
        pHead->type = Nearby_Type_Car;
        pHead->version = Nearby_Version;
        pHead->subtype = Nearby_Subtype_Car;
    
        // fill Extend Data, format of TLV
        // Trans Channel
        HiCarUSBExtendData *pTLV = (HiCarUSBExtendData*)(buf + totalLen);
        pTLV->tag = TAG_TransferType;
        pTLV->len = 1;
        pTLV->value[0] = VALUE_TransferType_NCM;
        totalLen += TLV_TOATL_LEN(pTLV);
        // Encapsulate ModelID, SubModelID, DeviceID, and BluetoothMac.
        ....
        pHead->total_len = totalLen;
    }
