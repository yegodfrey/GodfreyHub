# 概述

所有dispatch_xxx_create()类型的接口创建的对象都是在堆上申请一定大小的空间的。由于没有垃圾回收机制，这类由使用者创建的对象需要在使用者确定不再使用的时候主动释放。

[dispatch_retain](https://developer.huawei.com/consumer/cn/doc/development/graphics-References/dispatch-retain-0000001050170891)(object)会将对象的引用计数加1，[dispatch_release](https://developer.huawei.com/consumer/cn/doc/development/graphics-References/dispatch-release-0000001050284094)(object)会将对象的引用计数减1。当对象的引用计数为0的时候，会释放这个对象。

当对象调用dispatch_xxx_create()接口创建的时候，在内部会调用[dispatch_retain](https://developer.huawei.com/consumer/cn/doc/development/graphics-References/dispatch-retain-0000001050170891)。因此[dispatch_release](https://developer.huawei.com/consumer/cn/doc/development/graphics-References/dispatch-release-0000001050284094)接口需要与对应对象的create接口配对使用。
> 注意
>
> 不同于iOS平台的GCD，由于objective-c/swift中拥有垃圾回收机制，所以GCD中对象创建后使用者无需关心它的释放动作。
>
> 任何dispatch对象创建的接口都建议配对一个[dispatch_release](https://developer.huawei.com/consumer/cn/doc/development/graphics-References/dispatch-release-0000001050284094)，除非是希望这个对象全局永久存在。
>
> 尤其是在Android应用环境下一个可能多次调用到的C过程中创建并使用的一个dispatch对象，必须正确地配对调用[dispatch_release](https://developer.huawei.com/consumer/cn/doc/development/graphics-References/dispatch-release-0000001050284094)，否则将面临内存泄露的问题。请注意C/C++中是没有自动垃圾回收的，除非进程生命周期结束。

一些情况下，除了与create过程配对的[dispatch_release](https://developer.huawei.com/consumer/cn/doc/development/graphics-References/dispatch-release-0000001050284094)外，还需要额外地手动配对调用[dispatch_retain](https://developer.huawei.com/consumer/cn/doc/development/graphics-References/dispatch-retain-0000001050170891)和[dispatch_release](https://developer.huawei.com/consumer/cn/doc/development/graphics-References/dispatch-release-0000001050284094)，去维护某个对象的异步使用。

这种情形会比较难理解一点，因此需要非常小心。

简单而言，在[dispatch_release](https://developer.huawei.com/consumer/cn/doc/development/graphics-References/dispatch-release-0000001050284094)前发生的所有这个对象的**显式** **使用** 都是安全的，即使动作会在未来才彻底完成。而在[dispatch_release](https://developer.huawei.com/consumer/cn/doc/development/graphics-References/dispatch-release-0000001050284094)时间点后面则不允许对这个对象的**显式** **使用**。
> 说明
>
> **显式使用**定义为以某个对象为参数调用multithread-lib提供的任何接口。

例如：

```screen
#创建组任务
dispatch_group_t grp = dispatch_group_create();
dispatch_queue_t q = dispatch_get_global_queue(QOS_CLASS_DEFAULT, 0);

#异步执行组任务
dispatch_group_async(grp, q, ^{ /* Do something */ } );
dispatch_group_async(grp, q, ^{ /* Do something else */ } );
dispatch_group_async(grp, q, ^{ /* Do more things */ } );

dispatch_group_notify(grp, dispatch_get_main_queue(), ^{ /* Everything is done */ });

#释放创建的组
dispatch_release(grp);
```

这个示例代码就是正确的，因为所有grp的调用接口都发生在[dispatch_release](https://developer.huawei.com/consumer/cn/doc/development/graphics-References/dispatch-release-0000001050284094)之前。

尽管有任务会异步地在未来执行完成，当未来任务执行完成的时候仍然会用到grp变量。但是multithread-lib在所有异步接口的内部都对使用到的对象在开始时候自动retain，使用完毕后自动release。

因此使用者无须操心multithread-lib接口内部对某个对象的使用。当配对于create的[dispatch_release](https://developer.huawei.com/consumer/cn/doc/development/graphics-References/dispatch-release-0000001050284094)调用后会把对象引用计数减1，如果此时对象的计数不是0则意味着仍然有某个接口还要使用它。只有当它计数到0的时候才发生真正的释放动作。

下面的例子也是正确的：

```screen
dispatch_queue_t q = dispatch_queue_create("deferred_jobs", DISPATCH_QUEUE_CONCURRENT);
dispatch_time_t time = dispatch_time(0, (int64_t)(6*NSEC_PER_SEC));

dispatch_after(time, q, ^{
	/* Do something 6 secs later */
});

dispatch_release(q);
```

在[dispatch_after](https://developer.huawei.com/consumer/cn/doc/development/graphics-References/after-0000001050168876)调用的时候q会被自动retain，6s后当任务执行完毕，q上的处理过程结束，此时自动调用release。

另外注意，栈上的内容是不需要也不能[dispatch_release](https://developer.huawei.com/consumer/cn/doc/development/graphics-References/dispatch-release-0000001050284094)的。只有函数名中带create的接口才是在堆上分配，需要配对[dispatch_release](https://developer.huawei.com/consumer/cn/doc/development/graphics-References/dispatch-release-0000001050284094)。

例如上面的dispatch_time_t，就是栈上的内容。或：

```screen
int a = 100;
void (^block2)(void) = ^{
	printf("%d\n", a);
};
block2();
```

^{ }创建的block是栈上的临时block对象。尽管这种block对象可能会被[dispatch_async](https://developer.huawei.com/consumer/cn/doc/development/graphics-References/async-0000001050168872)之类的异步接口使用，但是会由[dispatch_async](https://developer.huawei.com/consumer/cn/doc/development/graphics-References/async-0000001050168872)这样的接口的内部实现中去把栈上临时block对象拷贝到堆上并维护release动作。

下面看一个会在[dispatch_release](https://developer.huawei.com/consumer/cn/doc/development/graphics-References/dispatch-release-0000001050284094)动作的未来再发生对象显式使用的例子：

```screen
dispatch_queue_t callback_queue = dispatch_queue_create("example", NULL);
...
dispatch_async(some_queue, ^{
    /* some work */
    ...
    dispatch_async(callback_queue, ^{
        /* code to execute after 'some work' */
        ...
    });
});
...
dispatch_release(callback_queue); /* wrong!! */
```

以上代码就是一个**错误** 的例子。[dispatch_async](https://developer.huawei.com/consumer/cn/doc/development/graphics-References/async-0000001050168872)(callback_queue)的动作发生在[dispatch_release](https://developer.huawei.com/consumer/cn/doc/development/graphics-References/dispatch-release-0000001050284094)(callback_queue)之后，而在最后一行[dispatch_release](https://developer.huawei.com/consumer/cn/doc/development/graphics-References/dispatch-release-0000001050284094)(callback_queue)的时候由于看不到callback_queue的计数了因此callback_queue会被释放掉，此时在some_queue的上下文中再使用callback_queue则是非法的。

正确用法需要提前retain，并在完成使用后release：

```screen
dispatch_queue_t callback_queue = dispatch_queue_create("example", NULL);
...
dispatch_retain(callback_queue);
dispatch_async(some_queue, ^{
    /* some work */
    ...
    dispatch_async(callback_queue, ^{
        /* code to execute after 'some work' */
        ...
    });
    dispatch_release(callback_queue);
});
...
dispatch_release(callback_queue);
```

最后再看一个稍微复杂一些的正确示例：

```screen
static void
work(dispatch_queue_t this_queue)
{
    dispatch_queue_t a_concurrent_queue = dispatch_queue_create("another_queue", DISPATCH_QUEUE_CONCURRENT);

    dispatch_retain(this_queue);
    dispatch_async(a_concurrent_queue, ^{
        /* some job */
        dispatch_async(this_queue, ^{
            ...
        });
        dispatch_release(this_queue);
    });

    dispatch_retain(this_queue);
    dispatch_async(a_concurrent_queue, ^{
        /* another job */
        dispatch_async(this_queue, ^{
            ...
        });
        dispatch_release(this_queue);
    });

    dispatch_release(a_concurrent_queue);
}

static void
dispatch_after_test(dispatch_time_t when)
{
    dispatch_queue_t queue = dispatch_queue_create("example", DISPATCH_QUEUE_CONCURRENT);

    dispatch_after(when, queue, ^{
        work(queue);
    });

    dispatch_release(queue);
}
```

> 注意
>
> 当对象会在不止一个上下文中使用的时候，请非常小心地调用[dispatch_release](https://developer.huawei.com/consumer/cn/doc/development/graphics-References/dispatch-release-0000001050284094)，避免由于不正确地[dispatch_retain](https://developer.huawei.com/consumer/cn/doc/development/graphics-References/dispatch-retain-0000001050170891)/[dispatch_release](https://developer.huawei.com/consumer/cn/doc/development/graphics-References/dispatch-release-0000001050284094)导致难以察觉的或偶发的提前释放，造成应用或程序crash。
>
> 最重要的原则是，任何对某个dispatch对象obj进行显式使用的接口（包括调用[dispatch_retain](https://developer.huawei.com/consumer/cn/doc/development/graphics-References/dispatch-retain-0000001050170891)(obj)），都必须发生在一个受到[dispatch_retain](https://developer.huawei.com/consumer/cn/doc/development/graphics-References/dispatch-retain-0000001050170891)(obj)和[dispatch_release](https://developer.huawei.com/consumer/cn/doc/development/graphics-References/dispatch-release-0000001050284094)(obj)配对保护的上下文中（其中dispatch_xxx_create视作一个[dispatch_retain](https://developer.huawei.com/consumer/cn/doc/development/graphics-References/dispatch-retain-0000001050170891)）。
