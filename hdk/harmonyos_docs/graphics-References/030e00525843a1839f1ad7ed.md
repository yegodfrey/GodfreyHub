# dispatch_apply

## 功能描述

（同步地）在指定队列重复执行多次某个任务。
> 注意
>
> * dispatch_apply是同步的接口。因此需要注意目标队列的使用。通常建议传入DISPATCH_APPLY_AUTO，multithread-lib则会使用跟当前队列优先级最接近的一个全局并发队列。
> * 当使用DISPATCH_APPLY_AUTO或一个并发队列作为目标队列的时候，任务的多次执行是并发执行的，各自接收不同的iteration参数。因此在这种情况下任务的设计需要保证可重入。

## 函数原型

```screen
void dispatch_apply(size_t iterations, dispatch_queue_t queue, void (^block)(size_t));
```

## 参数

|名称|类型|描述|
|:---------|:---------------|:-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
|iterations|size_t|执行次数。|
|queue|dispatch_queue_t|目标队列。 由于是同步执行一个循环，目标队列通常意义不大，因此建议传递DISPATCH_APPLY_AUTO，系统会自动使用一个合适的queue，实际是优先级最接近的一个全局并发队列。 > 注意 > * 如果queue是个并发队列，那么任务的多次执行是并行执行的，使用者自然也需要保证任务可重入。 > * 如果queue是个串行队列，任务会串行执行。此时行为等效于循环调用[dispatch_sync](https://developer.huawei.com/consumer/cn/doc/development/graphics-References/sync-0000001050168874)，因此一般[dispatch_apply](https://developer.huawei.com/consumer/cn/doc/development/graphics-References/apply-0000001050170837)不使用串行队列，而是希望发挥并发队列并行执行的能力从而达到最好的性能。|
|block|void|任务。 这个block要求有一个入参。这个入参表示当前block执行的是第几个iteration，从0开始记，即多个任务接收到的入参会是0..(iterations-1)。|

## 返回

|类型|描述|
|:---|:-|
|void|-|
