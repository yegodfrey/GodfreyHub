# dispatch_apply_f

## 功能描述

[dispatch_apply](https://developer.huawei.com/consumer/cn/doc/development/graphics-References/apply-0000001050170837)的_f版本。

## 函数原型

```screen
void dispatch_apply_f(size_t iterations, dispatch_queue_t queue, void *context, void (*work)(void *, size_t));
```

## 参数

|名称|类型|描述|
|:---------|:------------------------|:------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
|iterations|size_t|执行次数。|
|queue|dispatch_queue_t|目标队列。 由于是同步执行一个循环，目标队列通常意义不大，因此建议传递DISPATCH_APPLY_AUTO，系统会自动使用一个合适的queue，实际也就是优先级最接近的一个全局并发队列。 > 注意 > * 如果queue是个并发队列，那么任务的多次执行是并行执行的，使用者自然也需要保证任务可重入。 > * 如果queue是个串行队列，任务会串行执行。此时行为等效于for循环调用[dispatch_sync](https://developer.huawei.com/consumer/cn/doc/development/graphics-References/sync-0000001050168874)。因此一般[dispatch_apply](https://developer.huawei.com/consumer/cn/doc/development/graphics-References/apply-0000001050170837)不使用串行队列，而是希望发挥并发队列并行执行的能力从而达到最好的性能。|
|context|void *|任务入参。|
|work|void (*f)(void *, size_t)|函数。 这个函数接收两个入参，一个是使用者定义的函数参数，另一个是multithread-lib框架传过去的表示这个执行的是第几次循环，从0开始记。|

## 返回

|类型|描述|
|:---|:-|
|void|-|
