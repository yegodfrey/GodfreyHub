# 1\. 场景介绍

**概念介绍**

您可以将玩家的游戏进度存储至华为云空间中，或从华为云空间取得之前的游戏进度继续游戏。因此，只要用户使用相同的华为帐号登录，则游戏存档可以在任意设备取回进行游戏，即使用户之前的设备丢失、损毁或换了新设备也能继续之前的游戏进度。

一个存档主要由2部分组成：

  * 存档文件：开发者可以将游戏数据自行写入需要存档的文件，在获取存档文件后也由开发者自行解析，存档文件大小限制为3MB。

  * 存档元数据：存档元数据是指存档本身的属性，开发者可以向用户展示存档属性，用户可以根据属性信息选择哪个存档继续游戏，比如存档名称、上次修改时间等。存档的主要属性如下表所示。


属性| 说明  
---|---  
存档ID| 存档在该游戏中的唯一标识，在提交存档后由华为游戏服务器生成。  
存档名称| 存档保存的文件名，在提交存档后由华为服务器生成。  
存档描述| 存档用于展示给玩家的描述信息，在提交存档时由开发者自行定义，最多1000个字符。  
上次修改时间| 服务器生成的时间戳（以毫秒为单位），表示上次更新保存的游戏的时间。  
游戏时长| 开发者在提交存档时提供的玩家在该存档上游戏总时间（以毫秒为单位）。  
游戏进度| 开发者在提交存档时提供的玩家在该存档上的游戏进度，由开发者自行定义。比如第几关等，用整数进行识别。  
封面图片| 开发者在提交存档时提供的存档封面图像，一般来说为游戏存档时的截图，若未提供，则为系统默认图片，最大200KB，支持JPG或PNG格式，长宽比为16:9。  
  
**离线同步**  


  * 没有网络连接时，支持本地缓存的方式读取和保存游戏存档。

  * 读取和写入的均为本地缓存数据，网络重新连接后，自动与华为服务器进行同步。

  * 离线同步仅对有登录华为帐号的用户生效，否则无法离线存储。

  * 若在再次联网前用户进行华为帐号登出，则本地缓存的存档被丢弃。




**冲突处理**

在游戏存档时可能存在同一个帐号在多个设备中同时存档的情况，如果设备因网络问题存档延时，则可能会发生数据冲突。当更新存档或打开存档时发现两份存档的存档属性对比存在不一致时，华为游戏服务器会返回对应的冲突结果给开发者，并允许开发者选择使用其中某份存档作为最终使用的存档，或者也允许开发者自主混合存档数据作为最终使用的存档。

  * 冲突判断有两个场景，更新存档和打开存档，判断条件有多个，之间为【或】的关系，即只要有一个条件满足，即判断为冲突，同时告知开发者冲突原因。冲突判断条件参见下表。

  * 若有存档对应字段不存在无法进行判断，则认为存在冲突，且认为另一个存档对应字段更大。


操作场景| 冲突判断条件  
---|---  
更新存档| 存入存档为A，服务器已存在存档为B。

  * B的游戏时长更大
  * B的游戏进度更大
  * B的上次修改时间距现在更近
  * A的描述信息或封面与B不同

  
打开存档| 缓存中已有存档为A，服务器取回存档为B。

  * A的游戏时长更大
  * A的游戏进度更大
  * A的上次修改时间距现在更近
  * A的描述信息或封面与B不同

  
  
解决冲突的方式有2种：  


  * 开发者在打开存档时指定冲突解决策略，在发生冲突时由华为游戏服务器按冲突解决策略自动解决冲突。

  * 开发者在发生冲突时自行选择冲突解决方案，可以选择其中任何一个作为最终使用的存档，也允许开发者混合编辑数据后，使用编辑后的新存档。




# 2\. 受限说明

  * 游戏存档实际是存储游戏相关文件至当前用户的华为帐号所属的华为云空间中，因此用户需要同意开通华为云空间服务，才能使用游戏存档功能。游戏存档当前仅支持华为云空间服务支持的国家和地区，具体请参见[华为云空间服务支持的地区](https://developer.huawei.com/consumer/cn/doc/development/HMS-Guides/drivekit-support-regions)。

  * 调用存档相关接口时，用户的华为帐号必须为已登录状态。

  * 单个用户在华为云空间剩余存储容量充足情况下，最多可以保存100个存档。  


  * 用户必须打开华为应用市场（10.3及以上版本）中的游戏服务开关才能使用存档功能。如果用户没有开启游戏服务开关，当游戏调用存档相关接口时HMS SDK会自动拉起华为应用市场的游戏服务开关页面引导用户打开开关，如果用户未打开游戏服务开关，将返回7018错误码，游戏需要主动提示用户到华为应用市场“我的-设置-游戏服务”页面中开启游戏服务开关后才能使用存档功能。




说明：

用户打开游戏服务授权后，建议您在游戏中提供取消游戏服务授权的功能，可调用[GamesClient.cancelGameService](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/gamesclient-v4#cancelGameService)方法实现。

# 5\. 展示存档列表

玩家可以在存档入口选择浏览存档记录，此时游戏需要展示所有的存档记录供用户选择。存档记录选择界面的展示方法分为2种：

  * 直接展示应用助手的存档页面：游戏需要获取应用助手存档界面的Intent对象，然后通过startActivityForResult方法拉起存档选择页面，开发者不需要自己开发存档展示页面。此方式仅支持EMUI为9.0及以上版本的终端，且必须安装10.3及以上版本的华为应用助手。




注意：

只有游戏正式上架后应用助手才会正常展示存档列表，测试阶段无法正常展示。

  * 自行展示存档列表：获取存档数据，自行开发存档记录页面。

# 6\. 更新存档

更新存档是指玩家保存游戏时，如果玩家之前保存过该游戏，游戏服务器选择修改已有的存档文件和存档元数据，以节省云空间的存储空间。

说明：

玩家保存游戏时新增存档还是更新存档，由开发者自行设计确定，华为仅提供能力。

  


![](https://communityfile-drcn.op.hicloud.com/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20191216224824.44501254775088745545033020921196:50510410113207:2800:336377948E5B952DED9D1D20E8D1660930289D1ACEED9FA0C3237EB698137662.png)

1、玩家保存存档时，游戏调用[ArchivesClient.getArchiveSummaryList](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/archivesclient#getArchiveSummaryList)方法获取当前玩家的存档列表。

2、游戏获取到玩家保存过该游戏，从查询结果中取出存档的[ArchiveSummary](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/archivesummary)元数据，解析存档ID。

# 7\. 打开存档

打开存档是指玩家进入游戏后加载之前提交的存档继续进行游戏。

  * 如果打开应用助手展示的存档，由应用助手加载。

  * 如果打开开发者自行展示的存档，建议[ArchivesClient.getArchiveSummaryList](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/archivesclient#getArchiveSummaryList)方法获取的存档，不要打开本地缓存的存档。




![](https://communityfile-drcn.op.hicloud.com/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20191216224905.32506450182384743499966671275428:50510410113207:2800:9CD44924A2272FD8C87F967C557F46E9E28E6B0FDD9FACD87C4F0E32A9268F58.png)

1、玩家选择一个存档加载时，应用调用[ArchivesClient](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/archivesclient)的loadArchiveDetails方法加载存档文件，有以下几种方式选择。

  * 不处理数据冲突：即在发生数据冲突时华为服务器不处理数据冲突，需要开发者自行处理。此方式使用[loadArchiveDetails(ArchiveSummary summary)](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/archivesclient#loadArchiveDetails)方法或[loadArchiveDetails(String archiveId)](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/archivesclient#loadArchiveDetails4)方法。

  * 指定冲突处理的策略：可以指定游戏时长、进度、修改时间作为冲突处理策略，如果发生冲突，华为服务器使用指定的策略处理数据冲突。此方式使用[loadArchiveDetails(ArchiveSummary summary, int diffStrategy)](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/archivesclient#loadArchiveDetails2)方法或[loadArchiveDetails(String archiveId, int diffStrategy)](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/archivesclient#loadArchiveDetails3)方法。




2、如果结果中的[OperationResult.isDifference](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/operationresult#isDifference)返回true，表示加载存档时发生数据冲突，开发者需要进行数据冲突处理，详细步骤参见冲突处理。

# 8\. 冲突处理

当更新或打开存档时缓存中的存档和服务器取回的存档发生数据冲突，在返回结果中会返回具体的冲突细节，开发者可以根据游戏的策略自行选择冲突解决方案。

  * 开发者在冲突的两个存档中选择其中任何一个作为最终使用的存档。

  * 开发者自行混合编辑数据后，使用编辑后的新存档作为最终使用的存档。




![](https://communityfile-drcn.op.hicloud.com/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20191216225137.32679216267493010138759712294373:50510410113207:2800:D5D1F8D8DFC876D4B65B57032915DD318ECFB320D7D47B90D43FB06B6C995479.png)

1、当打开存档时返回的[OperationResult.isDifference](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/operationresult#isDifference)为true，表示发生数据冲突。应用需要使用[OperationResult.getDifference](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/operationresult#getDifference)获取冲突细节数据。

2、开发者可以根据冲突数据提示玩家来选择使用哪个存档，或者由开发者自行确定使用哪个存档来解决冲突。

3、开发者确定解决冲突的原则后，生成解决冲突的存档数据。

  * 如果直接本地缓存的存档作为最终存档，可以[OperationResult.Difference.getRecentArchive](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/difference#getRecentArchive)使用方法获取存档数据。

  * 如果选择使用服务器存在的存档作为最终存档，可以使用[](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/difference#getRecentArchive)[OperationResult.Difference.getServerArchive](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/difference#getServerArchive)方法获取存档数据。

  * 如果选择使用混合编辑后的数据作为最终存档，应用需要自行编辑本地缓存的存档数据和服务器取回的存档数据，并生成最终存档的[ArchiveSummaryUpdate](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/archivesummaryupdate)和[ArchiveDetails](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/archivedetails)对象。




4、生成解决冲突的存档数据后，应用可以调用[ArchivesClient](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/archivesclient)的updateArchive方法解决冲突。

  * 如果使用编辑后的[ArchiveSummaryUpdate](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/archivesummaryupdate)和[ArchiveDetails](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/archivedetails)对象解决冲突，可以调用[ArchivesClient.updateArchive(String archiveId, ArchiveSummaryUpdate update, ArchiveDetails details)](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/archivesclient#updateArchive)。

  * 如果选择本地缓存存档或服务器取回的存档作为最终存档，可以调用[ArchivesClient.updateArchive(Archive archive)](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/archivesclient#updateArchive2)方法。




5、冲突解决后根据返回结果中的[OperationResult.isDifference](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/operationresult#isDifference)方法再次判断是否仍然存在冲突。如果仍然存在冲突，则重复以上步骤再次解决冲突，直到[OperationResult.isDifference](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/operationresult#isDifference)返回false。

示例代码：
    
    
    复制

        9.         }
        10.         Task<OperationResult> task = Games.getArchiveClient(this, signInHuaweiId).updateArchive(serverArchive);
        11.         task.addOnSuccessListener(new OnSuccessListener<OperationResult>() {
        12.             @Override
        13.             public void onSuccess(OperationResult operationResult) {
        14.                 Log.i("archive","isDifference:"
        15.                         + ((operationResult == null) ? "" : operationResult.isDifference()));
        16.                 if (operationResult != null && !operationResult.isDifference()) {
        17.                     Archive archive = operationResult.getRecentArchive();
        18.                     if (archive != null && archive.getSummary() != null) {
        19.                         Log.i("archive","ArchiveId:" + archive.getSummary().getId());
        20.                     }
        21.                 } else {

        23.                 }
        24.             }
        25.         }).addOnFailureListener(new OnFailureListener() {
        26.             @Override

        28.                 ApiException apiException = (ApiException) e;
        29.                 Log.e("archive" , "resolve result:" + apiException.getStatusCode());
