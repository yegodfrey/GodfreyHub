Nearby Message允许一个用户从附近的其他用户APP处订阅消息，同时也允许用户从附近信标（Beacon）设备处订阅消息。Nearby Message提供以下两种业务：第一种是基于应用的消息发布和订阅，第二种是基于信标的消息发布和订阅。

# 1 注意事项

  * 请注意尊重用户隐私，提醒用户使用Nearby Message服务时，不要发布敏感信息；

  * 请明确告知用户，使用Nearby Message服务的时候其电量消耗会比没有使用服务的情况下消耗快；

  * 在进行应用开发时，当应用退出的时候，请必须调用[**unput******](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/api-message-messageengine#9)() 回收发布的消息和[**unget******](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/api-message-messageengine#11)() 接口停止订阅消息；

  * 请遵守适用的数据保护法律法规，包括但不限于对个人数据的收集和处理、识别用户身份以及履行数据主体权利；

  * 请负责存储用户的设备和网络标识符，华为近距离通信服务不会存储用户的任何设备/网络标识符。

  * 您保证不要在用户不知情的情况下发布或订阅消息。

  * 使用户易于停止消息的发布和订阅。




# 2 开发步骤

先添加权限，再根据业务类型选择相应的接口进行开发。

## 2.1 添加权限

在使用Nearby Message之前，您需要添加网络权限、蓝牙权限、位置权限。在工程的AndroidManifest.xml文件中添加如下权限：
      
      1. <uses-permission android:name="android.permission.INTERNET " />
        2. <uses-permission android:name="android.permission.BLUETOOTH" />
        3. <uses-permission android:name="android.permission.BLUETOOTH_ADMIN" />
        4. <uses-permission android:name="android.permission.ACCESS_NETWORK_STATE" />
        5. <!-- Android6.0之后蓝牙还需要地理位置权限 -->
        6. <uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" />
        7. <uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />

### 2.2.1 发布消息

发布消息的时候，传递消息字节数组，每个消息的大小不能超过100KB。

注意：Nearby Message服务允许一个应用5s内最多发布50条有效消息。

以下是调用[**put**](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/api-message-messageengine#2)()接口，发布消息的示例代码：
      
      1. Nearby.getMessageEngine(this).put(new Message("Hello World!".getBytes()));
    
    

### 

如果需要更新TTL，请先调用unput接口，然后再次调用put接口，并在该次put接口的选项中配置新的TTL。

### 2.2.2 取消发布消息

若取消发布消息，请调用[**unput**](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/api-message-messageengine#9)()接口，传入之前发布消息的message对象。

注意：开发者在进行应用开发时，请在应用程序退出时使用该接口取消之前的消息发布。

以下是调用[**unput**](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/api-message-messageengine#9)()接口，取消发布消息的示例代码：
      
      1.  Nearby.getMessageEngine(this).unput(new Message("Hello World!".getBytes()));
    
    

### 2.2.3 订阅消息

为了从其他设备订阅消息，需要实例化一个[**MessageHandler**](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/api-message-messagehandler)类的对象来处理收到的订阅消息。

以下是调用[**get**](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/api-message-messageengine#6)()接口，订阅消息的示例代码：
      
      1. MessageHandler messageHandler = new MessageHandler() {    
        2.     @Override    
        3.     public void onFound(Message message) {        
        4.         Log.i(TAG, "onFound " + new String(message.getContent()));   
        5.     }     
        6.     @Override   
        7.     public void onLost(Message message) {        
        8.         Log.i(TAG, "onLost " + new String(message.getContent()));   
        9.     }
        10. };
        11. Nearby.getMessageEngine(this).get(messageHandler);
    
    

### 

说明：

Nearby Message按照一定的时间间隔从云端获取消息，这个时间间隔由云端设定，可能会修改。如果您认为该参数的修改，影响到您的使用，请发邮件到nearbyservice@huawei.com。

  


### 2.2.4 取消订阅消息

若取消订阅消息，请调用[**unget**](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/api-message-messageengine#11)()接口，传入之前为了订阅消息、构造的[**MessageHandler**](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/api-message-messagehandler)。

以下是调用[**unget**](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/api-message-messageengine#11)()接口，取消订阅消息的示例代码：
      
      1. MessageHandler messageHandler = new MessageHandler() {    
        2.     @Override    
        3.     public void onFound(Message message) {        
        4.         Log.i(TAG, "onFound " + new String(message.getContent()));    
        5.     }     
        6.     @Override    
        7.     public void onLost(Message message) {        
        8.         Log.i(TAG, "onLost " + new String(message.getContent()));    
        9.     }
        10. };
        11. Nearby.getMessageEngine(this).unget(messageHandler);
    
    

## 2.3 基于信标（Beacon）消息发布和订阅

业务流程图：

![](https://communityfile-drcn.op.hicloud.com/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20200110203756.55277363342678102938741723544749:50510427083512:2800:E2264647CF78CC669F651D6D9606D07DEFF5C20C01FE96E97B8D10B93A2BF338.png?needInitFileName=true)

在基于低功耗蓝牙信标的消息发布场景中，需要将一个特定ID绑定到物理设备，即Beacon设备。Nearby Message允许开发者在云服务上将该ID和消息关联起来。信标通过蓝牙广播该ID，应用通过扫描到的ID去云服务获取相应的消息。基于信标（Beacon）的消息订阅不仅支持前台监听，同时也支持后台监听，而基于应用的消息发布和订阅只支持前台监听。

### 2.3.1 在云服务上配置信标

请参考[Beacon管理](https://developer.huawei.com/consumer/cn/doc/development/HMS-Guides/Nearby-Service-Beacon-Management)，对信标进行配置。

配置信标时，允许将信标ID与消息附件（attachment）进行关联。attachment是一个特定的字节流（Byte stream）。Nearby Message只对该attachment进行存储，而不解析其具体内容的含义。该attachment最大长度限制为1024 字节。一个信标ID可以关联多个attachment。

### 2.3.2 前台监听信标消息

前台监听可以实现快速的设备发现，但是可能会引入较大的功耗。只有当应用在前台活动时，前台监听功能才能启动。

以下是调用[**get**](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/api-message-messageengine#6)()接口，进行前台监听的示例代码：
      
      1. MessageHandler messageHandler = new MessageHandler() {    
        2.     @Override    
        3.     public void onFound(Message message) {        
        4.         Log.i(TAG, " onFound " + new String(message.getContent()));   
        5.     }     
        6.     @Override    
        7.     public void onLost(Message message) {        
        8.         Log.i(TAG, " onLost " + new String(message.getContent()));    
        9.     }
        10. };
        11. Nearby.getMessageEngine(this).get(messageHandler);
    
    

### 2.3.3 后台监听信标消息

后台监听可以减少能耗，但是会不可避免地带来更高的设备发现延迟。

以下是调用[**get**](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/api-message-messageengine#8)()接口，进行后台监听的示例代码：
      
      1. PendingIntent pendingIntent = PendingIntent.getService(this, 0, new Intent(this, BackgroundGetIntentService.class), PendingIntent.FLAG_UPDATE_CURRENT);
        2. Nearby.getMessageEngine(this).get(pendingIntent);
        3. public class BackgroundGetIntentService extends IntentService {    
        4.     protected void onHandleIntent(Intent intent) {        
        5.         messageEngine.handleIntent(intent, new MessageHandler() {           
        6.             @Override            
        7.             public void onFound(Message message) {               
        8.                 Log.i(TAG, " onFound " + new String(message.getContent()));            
        9.             }   
        10.             @Override           
        11.             public void onLost(Message message) {               
        12.                 Log.i(TAG, " onLost " + new String(message.getContent()));           
        13.             }        
        14.         });   
        15.     }
        16. }
    
    

### 2.3.4 扩展接口

距离估计和信号强度：订阅者可以查询到与接收到的消息关联的Beacon信号强度，并获得与Beacon设备之间距离的粗略估计。示例代码如下：
      
      1. MessageHandler messageHandler = new MessageHandler() {     
        2.     @Override     
        3.     public void onBleSignalChanged(Message message, BleSignal bleSignal) {         
        4.         Log.i(TAG, " onBleSignalChanged " + new String(message.getContent()) + " " + String.valueOf(bleSignal.getRssi()));     
        5.     }     
        6.     @Override    
        7.     public void onDistanceChanged(Message message, Distance distance) {         
        8.         Log.i(TAG, " onDistanceChanged " + new String(message.getContent()) + " " + String.valueOf(distance.getMeters()));    
        9.     }     
        10. };
        11. Nearby.getMessageEngine(this).get(messageHandler);
