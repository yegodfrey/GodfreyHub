# 修改agconnect-services配置文件中的collector_url后，导致数据上报失败？

【根因分析】

Analytics Kit 会对collector_url做允许清单校验，在SDK中预置的允许清单域名为：

{“dbankcloud.com”,“dbankcloud.cn”, “dbankcloud.eu”,“dbankcloud.asia”,  
“digitalincloud.com”,“digitalincloud.cn”,“digitalincloud.eu”,“digitalincloud.asia”,  
“dbankcdn.com”,“dbankcdn.cn”,“dbankcdn.eu”,“dbankcdn.asia”,“hicloud.com”}  
该地址由系统维护，不允许修改。

【解决方法】

collector_url由系统维护，不允许修改。

# 实时分析为何没有数据上报？

【根因分析】  


未关闭debug模式，上报的事件数据不会出现在实时分析里，而是在“[应用调试](https://developer.huawei.com/consumer/cn/doc/development/HMS-Guides/meta_manage#app_debugging)”里。

【解决方法】

打开本地日志，查看日志中是否有debugMode enabled的字样，如有，则表示debug模式未关闭，请执行如下命令行，停用调试模式后再次尝试：
      
      1. adb shell setprop debug.huawei.hms.analytics.app .none.  
    
    

# 应用已经集成了Huawei Analytics Kit，为什么当天在事件分析报告里查不到数据？  


【根因分析】

Huawei Analytics Kit的数据报告（如事件分析报告、留存分析报告等），除实时趋势是分钟级更新外，其他各项指标均为次日更新。

【解决方法】

应用集成Huawei Analytics Kit后，次日可查看事件分析、留存分析等报告。

# 为什么相同时间段内，同一事件在“事件分析”中的事件计数与“漏斗分析”中的事件计数结果不一致？

【根因分析】：

该现象是正常现象，详细原因如下：

在漏斗分析过程中，如果一个用户在一个转化周期内有多个事件都符合某个转化步骤的定义，那么会优先选择更靠近最终转化目标的事件作为转化事件，并在第一次达到最终转化目标时停止转化的计算。

假设定义一个漏斗的转化步骤有A、B、C三步，那么不同用户的行为序列及实际转化步骤（加粗部分）见如下例子：

例1：A ->A ->**A - >B**        

例2：A ->A ->**A - >B ->C**        

例3：A ->A ->**A - >B ->C ->A ->B**        

例4：**A**  ->B **- >B ->C**    

为什么在“实时分析”或者“事件分析”中看不到上报事件的自定义参数？

【根因分析】

因为在事件管理中未添加自定义参数，导致实时分析和事件分析中都看不到自定义参数。

【解决方法】

请确认在“事件管理”中已给事件添加自定义参数。添加自定义参数的具体操作步骤如下：在“分析 > 管理 > 事件管理 > 编辑”“按钮，然后在输入框中添加自定义参数后单击“添加”即可。

# agconnect-services.json中为什么存在.cn的域名？

此域名为备用域名，与.com域名解析得到的站点IP是相同的。假如您选择的数据存储位置是德国站点，那么.com域名与.cn域名解析后都是德国站点的IP。.cn域名是为了确保.com域名解析失败时，能将您的数据及时、可靠地上传到云侧，避免因域名解析失败丢失数据，进而影响您的运营决策。  


# 在应用调试模式下，为什么应用内购买事件不是实时上报，而在打开应用时上报？

【根因分析】

开发者在MainActivity中的onCreate()方法中调用绑定服务接口regHmsSvcEvent()，在onDestroy()方法中调用解绑服务接口unRegHmsSvcEvent()。MainActivity如果即时销毁会触发调用解绑服务接口，导致应用内购买事件不能实时上报。

【解决方法】

建议在Application中调用regHmsSvcEvent()和unRegHmsSvcEvent()接口，即可实时上报应用内购买事件。
