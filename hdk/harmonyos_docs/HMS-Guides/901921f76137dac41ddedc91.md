# 1 服务端支付签名处理

在客户端开发章节我们提到，对于有服务器的非单机应用，需要在应用的服务端完成支付参数的签名，以保障支付私钥的安全性，本章节介绍如何在服务端完成支付签名方法的开发，至于应用客户端和应用服务端之间的交互接口，由开发者自行实现。

## 1.1 开发步骤

**步骤1**  构造待签名支付参数字串

1、将支付参数中需要参与签名的参数（参与签名的参数是指payreq中标识需要签名的参数，值为空<包括null和"">的不参与签名），按参数名的ASCII码的增序排序，若遇到相同首字母，则看第二个字母，以此类推。

2、排序完成之后，再把所有数组值以“&”字符连接起来。

例如：BankId=JUNNETNET&amount=2.00¬ifyTime=1353317037173&orderId=918370122485714G&payType=2&productName=珍珠项链&requestId=1352286825177&result=0&userName=lilan

Java代码实现示例，以作参考
      
      1. /**
        2.  * 除了sign、signType以及回调中不存在的参数不参与签名，将其他的所有请求参数按照key的ASCII码进行升序排列，然后拼接成 
        3.  * key1=value1&key2=value2&key3=value3..... 
        4.  * 如果参数为null或空，写成key1=&key2=value2&key3=value3 
        5.  * @param params 上面获取的所有请求参数 
        6.  * @return 用于签名校验的字符串
        7.  */
        8. public static String getSignData(Map<String, Object> params)
        9. {
        10.     StringBuffer content = new StringBuffer();
        11.     // 按照key做排序  
        12.     List<String> keys = new ArrayList<String>(params.keySet());
        13.     Collections.sort(keys);
        14.     for (int i = 0; i < keys.size(); i++)
        15.     {
        16.         String key = (String) keys.get(i);
        17.         if ("sign".equals(key)) // 如果是sign字段，不作为签名校验参数  
        18.         {
        19.             continue;
        20.         }                
        21.         if ("signType".equals(key)) // 如果是signType字段，不作为签名校验参数  
        22.         {
        23.             continue;
        24.         }                
        25.         String value = (String) params.get(key);
        26.         if (value != null)
        27.         {
        28.             content.append((i == 0 ? "" : "&") + key + "=" + value);
        29.         }
        30.         else
        31.         // 如果value为null，则写成：key=&key1=value1  
        32.         {
        33.             content.append((i == 0 ? "" : "&") + key + "=");
        34.         }
        35.     }
        36.     return content.toString();
        37. }
    
    

**步骤2**  生成签名值  


（a）将源串使用RSA算法（SHA256WithRSA）进行签名。

（b）将签名后的字符数组经过Base64.encode编码，生成签名值

详细代码参考[服务端示例代码](https://developer.huawei.com/consumer/cn/doc/development/HMS-Examples/iap-tv-sampleServerCode-v4)章节。

  


# 2 支付回调接口处理

说明：

对于无服务器的单机应用，开发者无需关注本章节，有服务器的非单机应用开发者需要实现本章节，以实现支付结果回调的处理。支付回调是用户使用华为支付进行付款成功后，华为支付服务器将回调开发者的服务器通知支付结果。开发者需在华为开发者联盟上申请支付服务时，填入回调URL才可使用本功能，回调URL为开发者的应用服务器对外提供的服务地址。

本章节将介绍支付回调的接口以及CP如何实现该接口。

## 2.1 回调机制的说明

回调重发：若开发者服务器对于支付回调返回结果为非成功响应（返回的result值为非0），将对同一笔订单的回调进行周期性重发。

重发机制：共2天，前3次每20s尝试一次，4-20次每200s尝试一次，之后每3小时尝试一次；

## 2.2 回调接口协议描述

方向：华为支付平台->商户服务器

协议：HTTP

方法：POST

POST请求接口数据格式： application/x-www-form-urlencoded

POST请求接口数据字符编码：UTF-8

响应接口数据格式：JSON

响应接口数据字符编码：UTF-8

**注意：**

1、请严格按接口定义返回相应的结果码，包括已经明确定义的错误情况。具体结果码请参考2.4 响应。

2、不允许商户设置IP允许清单用于限制华为侧的出口IP地址。IP允许清单本身并不能提高安全性且会给业务发展带来约束，在消息层面已有更安全的RSA签名机制条件下，没有存在价值。商户不遵守该约定而导致的后果由商户承担。

## 2.3 回调接口请求参数

URL参数：无

Body参数：见下表

注意：Java中对本接口参数的处理建议：

本接口采用的是application/x-www-form-urlencoded格式，会在http层进行编码，同时接收端会自动解码。建议通过如下方法获得的get参数串，也就是华为支付服务器发送的原始信息。而原始信息是没有urlencode的，验签也是需要使用原始内容参与的。而使用request. getParameter()会隐含进行urldecode，在部分情况下可能无法正确获取原始参数信息，比如参数取值中如果包含”%”等特殊符号。

      参考代码如下：
      
      1. InputStream stream=request.getInputStream();
        2. InputStreamReader isr=new InputStreamReader(stream);
        3. BufferedReader br=new BufferedReader(isr);
        4. String str=br.readLine();  //original parameters string
    
    

采用如上方法获取参数时，对于sign、sysReserved和extReserved参数需要进行urldecode处理，其余参数不需要处理。

## 2.4 回调响应约定

http返回码：200

Body参数：

  


名称| 类型| 描述| 可选  
---|---|---|---  
result| int| 操作结果，0表示成功，1: 验签失败2: 超时3: 业务信息错误，比如订单不存在94: 系统错误95: IO 错误96: 错误的url97: 错误的响应98: 参数错误99: 其他错误| M  
  
注意：对于重复的订单，要求返回0；另外，请严格按定义的结果码返回，包括各种已经明确定义的错误码。另外，商户收到通知消息时，在完成最小必要处理后，要立即返回响应，避免超时。

## 2.5 开发步骤

应用服务端的开发者需要完成对支付回调中支付结果的验签，验签方法参见上一章节《服务端支付签名处理》，并更新自己服务端的支付结果，此处逻辑应用自行实现，部分代码请参考《服务端示例代码》
