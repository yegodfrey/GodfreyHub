# 1\. 自定义通知渠道

通知渠道（channel）是Android O版本引入的新功能，意在解决如下问题：

1、应用的通知越来越多，给用户造成明显打扰。

2、华为手机系统EMUI 10.0之前仅有一个**默认通知** 渠道，无法做通知消息呈现方式的定制。

华为手机系统从EMUI 10.0开始新增了三个通知渠道（服务提醒，普通通知与营销通知）来实现不同级别（非常重要，重要与一般）的通知消息展示。我们也支持自定义通知渠道的消息展示功能，如何创建自定义渠道安卓官方文档已有非常详细的描述，这里不再赘述。应用想在自定义渠道上展示消息，只需要通过服务端消息请求报文中**message.android.notification.channel_id** 字段设置要使用的渠道标识即可。消息最终能否展示在应用渠道上，受用户终端上该渠道是否创建以及渠道的开关策略控制。

注意：

自定义通知渠道仅对发给用户设备的通知消息级别为重要与非常重要时有效，一般级别消息仍然通过华为营销通知渠道展示。

示例报文：  

      
      1. {
        2.     "message": {
        3.         "notification": {
        4.             "title": "message title",
        5.             "body": "message body"
        6.         },
        7.         "android": {
        8.             "notification": {
        9.                 "channel_id": "RingRing",
        10.                 "click_action": {
        11.                     "type": 2,
        12.                     "url": "https://example.com"
        13.                 }
        14.             }
        15.         },
        16.         "token": [
        17.             "pushtoken1"
        18.         ]
        19.     }
        20. }
    
    

# 2\. 通知消息本地化

通知消息本地化又可以理解为国际化多语言展示，指通知消息可以根据手机本地语言变化展示对应语言的标题和内容，从而覆盖本消息中普通的标题和内容。

通知消息多语言展示效果图如下：

![](https://communityfile-drcn.op.hicloud.com/FileServer/getFile/cmtyPub/011/111/111/0000000000011111111.20191218153254.00952125191622478687561534046137:50510530085518:2800:97B5A73971BB63D680DACB851C9870DEB87E37D973EAAD0661CFDB9110647869.png?needInitFileName=true?needInitFileName=true)

通知消息本地化展示可以由华为统一消息中心（NC）展示，也可以由开发者通过服务端提供的REST API接口设置为应用在前台时由应用自己处理。下面我们分别介绍下这两种处理方式下开发者要做的事情。

## 2.1 华为NC展示

华为NC展示有两种方式实现，方式1是全部通过服务端提供的REST API接口实现，不需要应用本地的字符串资源文件**strings.xml** 的配合；方式2需要服务端REST API配置（不需要配置**multi_lang_key** 字段）与应用本地的字符串资源文件配合实现。

说明：如果同时指定了**multi_lang_key** 字段与本地字符串资源文件，则优先使用**multi_lang_key** 字段，本字段读取失败，则从APK本地资源文件中读取。

#### 方式1

  * 服务端参数的配置参考见下JSON文本，开发者如果想指定**title** 字段也是变化的请同步配置**title_loc_args** 字段。



      
      1. {
        2.     "title_loc_key": "title_key",
        3.     "body_loc_key": "body_key",
        4.     "body_loc_args": [
        5.         "Jack",
        6.         "Shanghai"
        7.     ],
        8.     "multi_lang_key": {
        9.         "title_key": {
        10.             "en": "New Friend Request",
        11.             "zh": "添加好友请求",
        12.             "ru": "Запрос нового друга"
        13.         },
        14.         "body_key": {
        15.             "en": "My name is %s, I am from %s.",
        16.             "zh": "我叫%s，来自%s。",
        17.             "ru": "Меня зовут %s, я из %s."
        18.         }
        19.     }
        20. }
    
    

注意：

名称为**multi_lang_key** 的字段的值是一个对象，对象的名称必须与**title_loc_key** 、**body_loc_key** 字段的值一致。上文JSON文本举例来说，body_key字段的值也是一个对象，对象中适配国际化多语言，目前最多支持三种适配语言。**en** 字段的值是一个格式化字符串，%s代表这是字符串类型。**body_loc_args** 字段的值是一个可变的字符串数组，用于填充**en** 字段的值中对应的占位符%s，您可以根据自己的业务进行设置。

#### 方式2

  * 服务端参数的配置参考见下JSON文本，开发者如果想指定**title** 字段也是变化的请同步配置**title_loc_args** 字段。



      
      1. "title_loc_key": "title_key",
        2. "body_loc_key": "body_key",
        3. "body_loc_args": ["Jack", "Shanghai"]
    
    

  * 安卓资源文件**/res/values/strings.xml** 中字符串资源定义见下，其中**body_key** 节点是支持占位符的，其中%后面是占位符的位置，从1开始，$后面是填充数据的类型。



      
      1. <string name="title_key">New Friend Request</string>
        2. <string name="body_key">My name is %1$s, I am from %2$s.</string>
    
    

****

说明：

开发者可以在res目录下进行多语言适配，比如**/res/values-en-rGB/strings.xml** 进行英语（英国）本地化适配。

  * 参考下面的代码动态获取可变字符串，并对资源节点进行字符串格式化，填充内容到占位符中。



      
      1. public class DemoHmsMessageService extends HmsMessageService {
        2.     @Override
        3.     public void onMessageReceived(RemoteMessage message) {
        4.         String[] bodyArrays = message.getNotification().getBodyLocalizationArgs();
        5.         String key = getResources().getString(R.string.body_key);
        6.         String body = String.format(key, bodyArrays[0], bodyArrays[1]);
        7.         Log.i(TAG, body);
        8.     }
        9. }
    
    

注意：

**title_loc_key** 字段的值要与本地**strings.xml** 里面定义的节点名要一致，**title_loc_args** 中可变字符串值用于替换**strings.xml** 中格式说明符，因此可变数组的长度要保证不小于**strings.xml** 中对应的节点中占位符的个数。

## 2.2 应用处理

由于Push SDK中没有提供获取服务端REST API设置的multi_lang_key字段值方法，因此要完成应用自展示功能，开发者必须配置应用的本地字符串资源文件strings.xml，请参考**华为NC展示** 中方式2部分。

# 3\. 通知消息前台展示

当您在服务端推送通知消息时，通过服务端提供的开放接口设置了如果应用进程在前台则不通过华为的统一消息中心（Notification Center, 简称NC）展示消息，那么应用在前台时这个通知消息是直接透传给应用，由应用自己处理展示。您可以通过设置 **message.android.notification.foreground_show** 字段来表示消息由谁来展示。

注意：

该功能仅在EMUI 9.1.0以上，HMS SDK 4.0以上支持。

示例报文：
      
      1. {
        2.     "message": {
        3.         "notification": {
        4.             "title": "message title",
        5.             "body": "message body"
        6.         },
        7.         "android": {
        8.             "notification": {
        9.                 "foreground_show": false,
        10.                 "click_action": {
        11.                     "type": 1,
        12.                     "action": "com.huawei.codelabpush.intent.action.test"
        13.                 }
        14.             }
        15.         },
        16.         "token": [
        17.             "pushtoken1"
        18.         ]
        19.     }
        20. }
    
    

字段值说明：值为true或者不填写值，表示应用在前台时仍旧由NC展示通知消息。如果填写false，表示应用在前台时不再由NC展示通知消息，通知消息的全部内容将会通过[HmsMessageService](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/push-HmsMessageService-cls)的[onMessageReceived](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/push-HmsMessageService-cls#onMessageReceived)([RemoteMessage](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/push-RemoteMessage-cls) message)方法传递给应用，应用需要通过RemoteMessage提供的方法获取相应字段，自行处理，这种情况下，华为推送服务不会校验消息字段的合法性。

# 4\. 通知消息展示覆盖

通知消息到达终端设备展示后，如果用户没有点击或者清理，支持新来的消息覆盖掉之前展示的消息。本功能可以通过服务端提供的API来设置实现。有三种方式，1、通过**tag** 字段（值为字符串）设置，2、通过**notify_id** 字段（值为整数）设置，3、通过**group** 字段（值为字符串）设置。

**tag** 字段示例报文：
      
      1. {
        2.     "message": {
        3.         "notification": {
        4.             "title": "message title",
        5.             "body": "message body"
        6.         },
        7.         "android": {
        8.             "notification": {
        9.                 "tag": "tagBoom",
        10.                 "click_action": {
        11.                     "type": 2,
        12.                     "url": "https://example.com"
        13.                 }
        14.             }
        15.         },
        16.         "token": [
        17.             "pushtoken1"
        18.         ]
        19.     }
        20. }
    
    

具有相同**tag** 标签值的新消息覆盖老的消息。

**notify_id** 字段示例报文：
      
      1. {
        2.     "message": {
        3.         "notification": {
        4.             "title": "message title",
        5.             "body": "message body"
        6.         },
        7.         "android": {
        8.             "notification": {
        9.                 "notify_id": 123,
        10.                 "click_action": {
        11.                     "type": 2,
        12.                     "url": "https://example.com"
        13.                 }
        14.             }
        15.         },
        16.         "token": [
        17.             "pushtoken1"
        18.         ]
        19.     }
        20. }
    
    

**notify_id** 标识每条消息在通知显示时的唯一标识。不同的通知栏消息可以相同的**notify_id** ，实现新的通知栏消息覆盖老的。

**group** 字段示例报文：
      
      1. {
        2.     "message": {
        3.         "notification": {
        4.             "title": "message title",
        5.             "body": "message body"
        6.         },
        7.         "android": {
        8.             "notification": {
        9.                 "group": "espace",
        10.                 "click_action": {
        11.                     "type": 2,
        12.                     "url": "https://example.com"
        13.                 }
        14.             }
        15.         },
        16.         "token": [
        17.             "pushtoken1"
        18.         ]
        19.     }
        20. }
    
    

相同**group** 的多条消息，只展示最新的一条消息。

注意：

指定**tag** ，指定**notify_id** ，指定**group** 三个功能是互斥的，只能三选一。如果都设置，优先级是：**group** >**tag** >**notify_id** 。

# 5\. 基于条件的消息推送

支持基于主题组合条件发送，即指定目标主题的布尔表达式来进行消息推送。比如向订阅了weather和sports主题的用户推送消息。目前只有安卓应用可以使用条件推送，**condition** 字段详细说明请参考[服务端发送Push消息](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/push-sendapi)。

示例报文：
      
      1. {
        2.     "validate_only": false,
        3.     "message": {
        4.         "notification": {
        5.             "title": "message title",
        6.             "body": " message body"
        7.         },
        8.         "android": {
        9.             "notification": {
        10.                 "click_action": {
        11.                     "type": 1,
        12.                     "action": "com.huawei.codelabpush.intent.action.test"
        13.                 }
        14.             }
        15.         },
        16.         "condition": "'weather' in topics && 'sports' in topics"
        17.     }
        18. }

# 9\. 锁屏不展示通知内容

锁屏下不展示通知消息内容是指当手机处于锁屏状态下收到通知消息后不在锁屏界面上展示通知内容，可以通过[服务端发送Push消息](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/push-sendapi)API提供的**visibility** 字段实现。**visibility** 字段值说明：

  * VISIBILITY_UNSPECIFIED：未指定visibility，效果等同于设置了PRIVATE。

  * PUBLIC：锁屏时收到通知栏消息，显示消息内容。  


  * SECRET：锁屏时收到通知栏消息，不提示收到通知消息。

  * PRIVATE：设置了锁屏密码，“锁屏通知”（导航：“设置”--“通知中心”）选择“隐藏通知内容”时收到通知消息，不显示消息内容。




注意：

全局“隐藏通知内容”仅对visibility字段值为PRIVATE起作用。

样例报文：
      
      1. {
        2.     "message": {
        3.         "notification": {
        4.             "title": "message title",
        5.             "body": "message body"
        6.         },
        7.         "android": {
        8.             "notification": {
        9.                 "visibility": "PRIVATE",
        10.                 "click_action": {
        11.                     "type": 2,
        12.                     "url": "https://example.com"
        13.                 }
        14.             }
        15.         },
        16.         "token": [
        17.             "pushtoken1"
        18.         ]
        19.     }
        20. }
    
    

# 10\. 桌面角标

华为推送服务提供了在服务端设置桌面角标的API接口，开发者可以在消息中封装角标参数。如果消息为通知栏消息，华为推送服务负责应用桌面角标数量的展示。如果消息为透传消息，开发者可以调用 [getBadgeNumber()](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/push-Notification-cls#getBadgeNumber) 方法获取消息中的角标数字并展示角标数字值。

# 11\. 自定义通知小图标

华为推送服务给开发者提供了两种设置通知栏消息小图标的方法，一种是通过[服务端发送Push消息](https://developer.huawei.com/consumer/cn/doc/development/HMS-References/push-sendapi)API中的**icon** 字段设置，一种是通过应用的**AndroidManifest.xml** 文件添加**meta-data** 元数据来实现。添加meta-data方式如下：

在**application** 标签添加<meta-data>元数据，**meta-data** 元数据**name** 不可改变，**resource** 指定的资源图标由开发者指定，需要在应用的**res/drawable** 目录下。
      
      1. <application
        2.     <meta-data
        3.         android:name="com.huawei.messaging.default_notification_icon"
        4.         android:resource="@drawable/ic_push_notification" />
        5. </application>
    
    

注意：

1\. 应用存储的图标文件需要有扩展名（目前支持的文件格式为png、jpg。），但是不要把扩展名写在uri中。  


2\. 如果应用两种方式同时设置，优先取消息中的**icon** 资源图标展示。如果两个都不设置，默认读取应用的桌面图标展示。

# 14\. 基于第三方审核结果的消息推送

HUAWEI Push Kit禁止推送包含敏感词的消息，建议App的运营人员在推送消息的时候基于三方机构的审核结果来进行消息推送。即在推送消息给Push服务器时，需附带三方审核机构对消息体内容审核后的结果，当Push服务器检测到审核结果不通过时，会对消息进行拦截，并返回结果给App运营人员。

如何将待审核的消息体内容发送至三方机构进行审核，请参考[推必安公有云接口文档](https://public.tuibianchina.com/)。
