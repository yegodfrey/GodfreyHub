# 开发指导

#### 接口说明

API接口参见[音频接口](https://developer.huawei.com/consumer/cn/doc/lite-wearable-references/litewearable-audio-js)。

准备工作：

音频文件：当前只支持MP3类型

歌单文件：手机传输给手表，在手机存储的

音频信息文件：手机传给手表。

#### 配置和切换播放列表

音乐应用需要提供播放列表，并在列表中指定音乐文件类型和是否加密和音乐文件时长信息，音乐服务在播放前解析播放列表，完成音乐播放。音乐服务的后台播放能力也是借助播放列表实现。

#### [h2]配置播放列表

为方便音乐应用写入，播放列表格式设计为文本格式，每个播放条目之间用分号分割，播放项内部用逗号分割，以便音乐服务解析，格式如下：
    
    音乐文件名1,音乐类型,是否加密,音乐总时长,歌曲名,歌手名称;音乐文件名2,音乐类型,是否加密,音乐总时长,歌曲名,歌手名称;……音乐文件名N,音乐类型,是否加密,音乐总时长,歌曲名,歌手名称;

示例：
    
    song1.mp3,1,0,150,歌曲名,歌手名;song2.mp3,1,0,150,歌曲名,歌手名;song3.mp3,1,0,250,歌曲名,歌手名;song4.mp3,1,0,200,歌曲名,歌手名;

各字段取值说明如下：

     * 音乐文件名称：必选；120字节限制，例如：song1.mp3。
     * 音乐类型：必选；音乐服务不能自动判断文件类型，需要音乐应用在播放列表中指定，当前只支持MP3类型，类型为1。
     * 是否加密：必选；音乐服务不能自动识别音乐文件是否加密，需要音乐应用在播放列表中指定；0代表未加密，1代表加密。
     * 音乐总时长：必选；目前运动手表没有解析音乐文件时长的能力，播放时长需要音乐应用在播放列表中指定，时长计量单位秒。如果不指定总时长，会认为该项无效而丢弃。
     * 歌曲名：可选；不超过120字节。如果没有歌曲名，请填“未知”。
     * 歌手名：可选；不超过60字节。如果没有歌手名，请填“未知”。

歌曲名和歌手名在未填写时，播放歌曲时不会入在驻播控中心显示。

#### [h2]切换播放列表

音乐应用执行播放操作或一曲播放结束准备播放下一首时，音乐服务会读取音乐播放列表文件。为避免该文件读写冲突导致播放异常，建议音乐应用采用多个播放列表，将待播放列表的文件名写入cur_playlist。写入后，该播放列表就交给音乐服务使用，音乐应用就不应再操作该播放列表。

应用需要创建internal://app/cur_playlist文件，并写入播放列表文件名，比如当前播放的播放列表是playlist1, 则将“playlist1”写入文件，也可以指定相对目录，比如folder/playlist2。

#### 解密接口

对于加密音乐文件，开发者需要提供配套的解密库，由音乐服务加载和调用。

因轻量级智能穿戴的内存资源有限，同时只能加载一个解密库，音乐服务根据当前要播放的音乐应用动态地加载对应的解密库。

开发者提供的解密库名称为audio_decode.bin，放在App工程的entry\src\main\resources\rawfile\lib\目录下，随应用一起打包，并安装到手表上。

     * 解密库魔术字：解密库中需要指定魔术字为0x484d2e62，否则加载时会匹配失败。
     * 解密接口：解密库需要提供如下两个接口，按照顺序暴露出来，供音乐服务调用： 
       1. 解密函数，作为解密库对外暴露的第一个函数。 
              
              typedef int32 (*AUDIO_DecryptFuncion)(uint8 *inBuf, int32 inSize, uint8 *outBuf, int32 outSize);

       2. 解密单元大小函数，作为解密库对外暴露的第二个函数。 
              
              typedef uint32 (*AUDIO_GetDecryptUnitLength)(void);

顺序在编译工程的.s启动文件中指定，代码示例如下：
              
              EXTERN  __deinit 
                      EXTERN  __init 
                      EXTERN  GetDecryptFunc                       ; First external interface 
                      EXTERN  GetDecryptUnitLength                 ; Second external interface 
              	DATA 
              __los_fu_header 
                      DCD     (0x484d2e62)                          ; magic words 
                      ... 
                      DCD     __init - __los_fu_header 
                      DCD     __deinit - __los_fu_header 
                      DCD     2                                      ; Number of external functions 
                      DCD     GetDecryptFunc - __los_fu_header       ; First external interface 
                      DCD     GetDecryptUnitLength - __los_fu_header ; Second external interface

#### 管理音乐文件

音乐服务提供基本的音乐文件管理功能，包括从手表上下载和删除音乐相关文件、查询音乐相关文件是否存在、查询音乐文件列表以及查询歌单列表功能。

音乐文件管理功能依赖Wear Engine Kit的文件发送和消息收发功能，需要配置包名和证书指纹信息。开发者需要提供手机侧音乐应用的包名和证书指纹，音乐服务配置进白名单，才能正常使用文件管理功能。

Wear Engine Kit使用方法参考[Wear Engine开发指南](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/wear-engine-kit-guide)。

#### [h2]下载音乐文件

音乐服务通过Wear Engine Kit完成文件下载功能，可实现音乐应用不在情况下后台下载。

**文件传输**

手表侧音乐应用安装后，音乐服务向Wear Engine Kit注册了文件传输服务，包含音乐应用包名及文件接收路径。因每个应用只能配置一个文件接收目录，音乐服务自动将internal://app/music配置为文件接收路径。

手机侧音乐应用可调用Wear Engine Kit的发送文件接口完成文件传输，包括音乐文件、歌单文件和音乐信息文件。Wear Engine Kit的发送文件接口使用参考[Wear Engine Kit开发指导](https://developer.huawei.com/consumer/cn/doc/connectivity-Guides/phone-dev-0000001086797354)的“Android手机侧应用开发”章节说明。

设备连接示例代码：
    
    p2pClient = HiWear.getP2pClient(getApplicationContext()); 
    p2pClient.setPeerPkgName("com.*.*"); 
    p2pClient.setPeerFingerPrint("SystemApp");

**文件传输完成通知**

手表侧接收到的音乐文件、歌单文件和音乐信息文件都放置在music目录下，需要手机侧音乐应用在收到Wear Engine Kit的文件传输完成通知时，发消息给音乐服务，以便音乐服务对文件进行管理。目前仅支持歌单文件和音乐信息文件的搬移，即从music目录移到到对应的目录。

手机侧音乐应用和音乐服务之间使用Wear Engine Kit的消息通道。

#### [h2]查询音乐文件列表

手机音乐应用给手表音乐服务发送查询音乐列表的消息，音乐服务收到消息后返回查询结果。该功能分两个步骤完成：

     1. 查询文件列表概要信息：音乐服务收到消息后查找本应用下的音乐文件，生成音乐列表，并回响应消息，携带总的数据帧个数和文件个数。

        * 消息协议 

**表10** 查询音乐文件列表概要信息的请求消息  命令字 |  数据区长度  
---|---  
cmd(0) |  len  
uint32 |  uint32  
  
**表11** 查询音乐文件列表概要信息的响应消息  命令字 |  数据区长度 |  操作结果 |  总数据帧个数 |  总文件个数  
---|---|---|---|---  
cmd(1) |  len |  result |  frameNum |  fileNum  
uint32 |  uint32 |  uint32 |  uint16 |  uint16  
  
        * 命令字 

**表12** 查询音乐文件列表概要信息的命令字  文件类型 |  查询文件列表概要信息的命令字 |  响应消息的命令字  
---|---|---  
音乐文件列表 |  0 |  1  
  
     2. 查询文件列表数据：手机音乐应用收到音乐列表概要信息后，根据总的数据帧个数，从第0帧开始，一帧一帧地向音乐服务请求列表数据，每一个请求帧对应一个响应帧，直到完成所有数据传输。

        * 消息协议 

**表13** 查询音乐文件列表数据的请求消息  命令字 |  数据区长度 |  下一个数据帧序号  
---|---|---  
cmd(2) |  len |  nextFrameNo  
uint32 |  uint32 |  uint32  
  
每个响应帧的大小最大为1024字节， 每个音乐文件名称最大为256字节，删除消息头占用的大小，每个响应帧最多携带3个音乐文件名称，每个响应帧返回的实际文件个数根据fileNum字段确定。

**表14** 音乐文件列表概要信息的响应消息  命令字 |  数据区长度 |  操作结果 |  帧序号 |  本帧的文件个数 |  文件名1 |  文件名2 |  文件名3  
---|---|---|---|---|---|---|---  
cmd(3) |  len |  result |  frameNo |  fileNum |  fileName1 |  fileName2 |  fileName3  
uint32 |  uint32 |  uint32 |  uint16 |  uint16 |  uint8[256] |  uint8[256] |  uint8[256]  
  
     * 命令字 

**表15** 查询音乐文件列表数据的命令字  文件类型 |  查询音乐文件列表的请求消息命令字 |  响应消息的命令字  
---|---|---

#### [h2]查询歌单列表

手机音乐应用给手表音乐服务发送查询歌单列表的消息，音乐服务收到消息后查询所有的歌单，并返回歌单名称列表。

歌单最多支持20个，歌单文件名称最大32字节（含结束符），一帧即可返回所有歌单列表。

     * 命令字
