# 分布式HCE支付场景解决方案

#### 方案简介

手表支付作为一种新兴的支付方式，正逐渐受到消费者的欢迎。腕上支付无需携带钱包或手机，只需轻轻一抬手腕，即可完成支付过程，大幅提升了支付的便捷性和效率。

因为轻量级智能穿戴设备无法实时联网，不支持TEE（Trusted execution environment）生态开放，传统的HCE（Host Card Emulation）移动支付解决方案无法直接部署在轻量级穿戴设备。手机和手表分布式HCE支付解决方案如下图所示，将中间件和支付App分离（中间件由统一的服务商提供全球化，支付App由本地的服务商提供），帮助支付开发者提供了一套快捷接入方案，缩短手表开发周期，降低手表部署成本。

该方案支持iOS手机，Android手机和HarmonyOS手机，同时该方案适用于轻量级智能穿戴设备和智能穿戴设备。

#### 实现架构

     * 发卡银行服务器：发行借记卡或信用卡的金融机构的服务器，负责管理账户、设定信用额度、承担交易审批与金融风险。
     * 卡组织服务器：提供银行卡交易处理、制定支付规范的清算机构的服务器。
     * 支付应用：用户使用的银行或者钱包支付应用，完成用户的开卡，开通线上支付功能。
     * 集成商(Token Requestor Aggregator，简称TRA) 手机侧SDK：支持手表和手机的账户绑定激活，代理手表侧token的申请，刷新，通过Wear Engine Kit将token传输给手表侧SDK。
     * 集成商(Token Requestor Aggregator，简称TRA) 手表侧SDK：存储申请的token，支持通过NFC将token传输给POS机。

#### 支付安全

#### [h2]支付安全总览

在享受腕上支付便利的同时，需要保证支付安全，确保交易信息的保密性、完整性和可用性，防止信息被窃取、篡改或滥用。为了实现支付安全，通常会采取多种技术和管理措施，如应用安全管理、应用安全启动和安全隔离等。

安全保护方案 | 消减的具体风险  
---|---  
安装管理：应用上架AppGallery Connect（以下简称AGC）、下载和安装。 | 通过应用上架获取AG签名，安装的时候通过根证书验证签名。  
安全启动：硬件芯片支持安全启动，校验软件版本镜像合法性。 | 避免非法用户，通过烧录非法镜像，绕过系统校验，激活银行卡刷卡。  
安全隔离：三方应用与系统应用隔离，其他三方应用无法访问支付类应用的数据或者内存。 | 三方应用采用JS语言，通过JS 运行时runtime实现安全隔离；系统API调用系统堆栈等内存资源，相对安全；应用资源仅能访问自己的资源文件，跨应用禁止访问；应用内存与系统内存隔离。  
软件安全：提供安全启动、安全升级、安全通信、安全执行等能力。 | 新版本的完整性和合法性、穿戴设备、云端/其他设备数据传输的安全性，以及安全环境执行。  
安全存储：开发安全存储API，封装HUKS加解密能力。 | 支付类三方应用：三方应用调用系统提供的安全存储接口，可以对密钥、临时支付凭证等进行存储，数据保存在Flash中。  
其他安全校验方式：NFC支付时，需要用户手动输入校验手表锁屏密码。 适用于小额支付，超额则需要再POS输入密码。 | 刷卡时，需要在手表输入验证锁屏密码，系统校验密码通过后，才能刷卡；密码校验不通过，无法刷卡。 支付限额：海外部分银行要求超过50美金，则需在POS机输入密码。  
换手机配对（无账号/不同账号），须恢复出厂，恢复出厂过程系统会删除银行卡数据。 | 非法用户使用手机配对手表，无法正常使用；须对手表恢复出厂才能配对使用，恢复出厂过程系统会删除银行卡数据。  
  
#### [h2]支付应用上架下载安装安全

![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/8d/v3/71GMJdaZQOGO8WXe4admew/zh-cn_image_0000002675432353.png?HW-CC-KV=V1&HW-CC-Date=20261005T092457Z&HW-CC-Expire=86400&HW-CC-Sign=75B04E646762F24DF3F1EE6EEAD0496ADE648CBAFBA9697148400BC553F16D6D)

**流程描述****：**

Step1：用户打开华为运动健康应用，通过华为账户，访问华为运动健康服务器，服务器验证访问令牌。

Step2：华为运动健康应用通过预配置证书验证服务器。

Step3：华为运动健康应用和华为轻量级穿戴设备对密钥进行配对并建立安全通道。

Step4：手机生态应用调用Wear Engine Kit通过预配置验证生态应用包名和签名。

Step5：华为运动健康应用验证应用包名和签名，手机生态应用获取用户授权。

Step6：开发者将穿戴生态应用申请上架App，AGC完成应用审核，测试与发布到AGC服务器，并且给穿戴生态应用设置AGC签名。

Step7：AG 客户端登录AG服务器，通过预配置证书验证服务器，并且下载穿戴生态应用，传输到轻量级穿戴设备进行安装。

Step8：轻量级穿戴设备在安装应用包之前，通过预配置的证书验证AGC签名，签名通过则完成应用的安装。

#### [h2]安全启动

![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/3a/v3/PtkZesWnTaiOX0gGV8mjyQ/zh-cn_image_0000002645273208.png?HW-CC-KV=V1&HW-CC-Date=20261005T092457Z&HW-CC-Expire=86400&HW-CC-Sign=E60291750B55726908A930C4176689029A0AD13871C0803F4C29DFE3EC39507D)

**信任根（Root of********Trust）** ：

     * Secure Boot Code唯一启动入口。
     * Secure Boot Code不能被bypass：安全启动开启后，其它的启动入口全部关闭。
     * Secure Boot Code不能被修改：安全启动开启后，安全启动代码设置为写保护。

**Secure Boot Code：**

     * 认证下一阶段要运行的代码：检查应用代码镜像的签名，采用SHA256+RSA验签完整性和合法性。
     * 认证通过才跳转执行：认证通过才执行应用代码，认证失败复位系统。

**安全启动的开启：**

     * 安全启动的开关不可逆（Efuse开关），开启后无法关闭。
     * 安全启动开启后，所有的调试端口关闭、安全启动代码是唯一入口。

#### [h2]安全隔离

三方应用采用JS语言，通过JS运行时runtime实现安全隔离。

![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/aa/v3/1qWalwcZTC2aICeB7vyUsA/zh-cn_image_0000002669469053.png?HW-CC-KV=V1&HW-CC-Date=20261005T092457Z&HW-CC-Expire=86400&HW-CC-Sign=684C160C1A59FB17709B27395A7E48D6872A6E747634FB6D8A15C506852BE9BE)

① **JS应用执行环境：**

JS调用栈、数据对象都在应用内存池，所以JS应用无法操作系统内存。

应用内存池JS引擎做了越界保护。

②**系统API调用：**

系统API由OS提供，API无存在风险。

系统API的调用栈和对象，在系统内存池。

③ **应用资源访问隔离：**

资源访问接口做了范围限定，应用只能访问自己的资源文件，无法越界访问系统应用资源（访问时根据包名判定）。

④ **内存管理：**

JS应用内存与系统内存分片管理，无法越界。

JS引擎对内存采用先申请后使用的方式，申请不到直接crash应用，JS应用不会内存越界。

#### [h2]支付密码

支付应用启动，银行卡开卡的业务流程中，建议先设置锁屏密码并开启离腕锁屏开关。离腕之后，首次打开支付应用需要输入锁屏密码。

建议手表侧设置小额度的支付限制。
