# 上报异常订单信息

## 功能介绍

异常订单是指商品支付订单的**下单用户与支付用户不一致** ，或**无支付用户标识**。

开发者调用该接口，向华为游戏服务器上报异常订单的相关信息。

## 接口原型

|承载协议|HTTPS POST|
|------|------------------------------------------------------------------------------------------|
|接口方向|开发者服务器 -> 华为游戏服务器|
|性能指标|TPS>1000|
|最大响应时间|<1000ms|
|接口URL|https://jos-open-api.cloud.huawei.com/gameservice/api/gbClientApi|
|数据格式|请求：Content-Type: application/x-www-form-urlencoded（表单方式） 响应：Content-Type: application/json|

## 请求参数

### Body

|参数|是否必选|类型|描述|
|:----------|:---|:-----------|:-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
|method|是|String(64)|固定传入external.hms.gs.reportAbnormalOrder。|
|appId|是|String(32)|游戏在AppGallery Connect中的APP ID。 * 获取HarmonyOS 4及以下游戏APP ID请参见[查看应用基本信息](https://developer.huawei.com/consumer/cn/doc/app/agc-help-appinfo-0000001100014694)。 * 获取HarmonyOS 5.0及以上游戏的APP ID请参见[查看应用信息](https://developer.huawei.com/consumer/cn/doc/app/agc-help-view-app-info-0000002282674569)。|
|orderId|是|String(256)|支付订单ID。 * HarmonyOS 4及以下游戏的支付订单ID请参见[InAppPurchaseData.getOrderID](https://developer.huawei.com/consumer/cn/doc/HMSCore-References/inapppurchasedata-0000001050137635#section183172365611)。 * HarmonyOS 5.0及以上游戏的支付订单ID请参见[PurchaseOrderPayload.purchaseOrderId](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/iap-data-model#purchaseorderpayload)。|
|userIdType|是|Int|订单关联的**下单**用户标识类型： * 1：playerId * 2：openId * 3：unionId|
|userId|是|String(256)|订单关联的**下单**用户标识，在使用华为账号登录游戏后生成。 > 说明 > userIdType表示用户标识的类型，userId是对应的具体标识值，两者一一对应。|
|purchaseExt|是|String(8192)|订单扩展信息。 调用IAP的[Order服务验证购买Token](https://developer.huawei.com/consumer/cn/doc/HMSCore-References/api-order-verify-purchase-token-0000001050746113)接口返回。|
|reasonCode|是|Int|异常码： * 5001：无支付用户标识。 * 5002：下单用户标识与支付用户标识不一致。|
|ts|是|Long|当前时间的时间戳，即当前时间距离GMT（格林威治时间）时间1970年1月1号0时0分0秒所差的毫秒数，由System.currentTimeMillis()获取。|
|sign|是|String(8192)|用于华为游戏服务器对请求参数验签的签名字符串。 为防止请求被篡改，游戏需要根据[签名机制](#section98054116219)中的方法生成签名字符串，华为游戏服务器在收到请求后会对签名字符串进行验签，验签成功后才会进行后续处理，否则将返回失败错误码。|

## 请求示例

```screen
POST /gameservice/api/gbClientApi
Host: jos-open-api.cloud.huawei.com
Content Type : application/x-www-form-urlencoded; charset=UTF-8 
// 所有请求参数值均需要urlencode编码后再进行拼接
method=external.hms.gs.reportAbnormalOrder&appId=***&orderId=***&userIdType=1&userId=***&purchaseExt=***&reasonCode=***&sign=***&ts=***
```

## 响应参数

|参数|是否必选|类型|描述|
|:------|:---|:--|:-------------------------------------------------------------------------------------------------------|
|rtnCode|是|Int|华为服务器返回码： * -1：失败。可能因为调用超时或网络波动等异常情况，导致订单信息上传失败。建议开发者尝试重新调用接口**两次**。 * 0：成功。 * 1：验签失败。 * 3001：参数格式校验未通过。|

## 响应示例

```screen
HTTP/1.1 200 OK 
Content Type : application/json ; charset=UTF-8 
{ 
    "rtnCode":0 
}
```

## 签名机制

为了确保HTTPS传输的安全性，防止请求参数被篡改，应用需要在调用接口时携带请求参数的签名字符串，用于华为服务器对请求参数进行校验。

签名字符串的生成规则如下所示：

1. 将请求参数Body中除sign以外的参数，按参数名首字母的ASCII码将参数升序排序。若遇到相同首字母，则比较第二个字母，以此类推。
2. 排序完成之后，将所有参与签名的参数值进行urlencode之后以"&"字符连接成字符串，例如"a=xxxxxx&b=xxxxxxx&c=xxxxxx"，此字符串便是待签名字符串。 Java示例代码如下：

   ```screen
   // 组装body内除sign以外的参数，此处参数值仅为示例
   Map<String, String> paramsMap = new HashMap<>();
   paramsMap.put("appId", "123025123");
   paramsMap.put("orderId", "2026033015054469438bb6a6d1.123025123");
   paramsMap.put("userIdType", "2");
   paramsMap.put("userId", "MDFAMTA2NTE3MzFAY2FhOWU1ODJhMmQ3MTYyYjA2OWFkYWMyOTQ0NjI2YzdAMmZkMzRlY2");
   paramsMap.put("purchaseExt", "{"playerId": "xxx", "openId": "xxx", "unionId": "xxx"}");
   paramsMap.put("reasonCode", "5002");
   paramsMap.put("ts", "1775014892799");


   // 对参数进行字典序排序
   Map<String, String> tempMap = new TreeMap<>(params);


   // 拼接参数
   for (Map.Entry<String, String> entry : tempMap.entrySet()) {
       String key = entry.getKey();
       String value = entry.getValue();
       base.append(key).append('=').append(null == value ? '' : URLEncoder.encode(value, "UTF-8")).append('&');
   }


   if (base.length() > 0) {
       base.deleteCharAt(base.length() - 1);
   }
   ```

3. 将待签名字符串使用游戏私钥按照RSA算法（SHA256WithRSA/PSS）进行签名，将签名后的字符串经过Base64编码，得到的字符串即为签名字符串。 说明
   > * 游戏私钥在开通游戏服务后生成，获取方式请参见[获取游戏服务信息](https://developer.huawei.com/consumer/cn/doc/development/HMSCore-Guides/query-game-info-0000001050164346)。
   > * golang默认使用PSSSaltLengthAuto，需换成PSSSaltLengthEqualsHash。

   Java示例代码如下：

   ```screen
   // 获取签名私钥，具体实现方法由开发者自行决定，此处仅为接口示例
   String privateKey = "xxxxxx";


   // 加签，BouncyCastleProvider的创建较耗费性能，建议写成单例
   byte[] keyBytes = Base64.decodeBase64(privateKey);
   PKCS8EncodedKeySpec pkcs8KeySpec = new PKCS8EncodedKeySpec(keyBytes);
   KeyFactory keyFactory = KeyFactory.getInstance("RSA");
   PrivateKey privateK =  keyFactory.generatePrivate(pkcs8KeySpec);
   Signature signature = Signature.getInstance("SHA256withRSA/PSS", new BouncyCastleProvider());
   signature.initSign(privateK);
   signature.update(sortedParams.getBytes(StandardCharsets.UTF_8));
   String sign =  Base64.encodeBase64String(signature.sign());
   ```
