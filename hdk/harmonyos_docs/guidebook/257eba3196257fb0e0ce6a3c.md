# 界面开发

依据多设备应用的UX设计理念和方法，HarmonyOS 提供了一系列面向多设备屏幕的布局、组件和交互能力，帮助开发者完成面向多设备应用界面的开发。

## 4.2.1 布局

布局能力涵盖基础的自适应布局和进阶的响应式布局。使用自适应布局可以应对各种屏幕变化，但在大尺寸屏幕上，结合响应式布局能力，可以更有效地利用大尺寸屏幕优势，为用户提供更加场景化的优质应用体验。

### 4.2.1.1 自适应布局

针对响应式设计方法，一多提炼了七种最常用的自适应布局场景能力，这些布局能力既可以独立使用，也可以组合使用。

表4-1 自适应布局能力

|布局能力|能力描述|能力对照|
|:---|:--------------------------------------|:----------------------------------------------------|
|拉伸能力|容器组件尺寸发生变化时，增加或减小的空间全部分配给容器组件内指定区域|Blank组件；弹性布局的FlexAlign.SpaceBetween空间分配策略|
|均分能力|容器组件尺寸发生变化时，增加或减小的空间均匀分配给容器组件内所有空白区域|Row、Column或Flex使用弹性布局的FlexAlign.SpaceEvenly实现剩余空间平均分配|
|占比能力|子组件的宽或高按照预设的比例，随容器组件发生变化|组件指定layoutWeight，系统基于权重进行比例分配计算|
|缩放能力|子组件的宽高按照预设的比例，随容器组件发生变化，且变化过程中子组件的宽高比不变|组件指定aspect-ratio宽高比|
|延伸能力|容器组件内的子组件，按照其在列表中的先后顺序，随容器组件尺寸变化显示或隐藏|List自带滚动能力，或嵌套Scroll滚动容器|
|隐藏能力|容器组件内的子组件，按照其预设的显示优先级，随容器组件尺寸变化显示或隐藏|组件设置displayPriority后系统依据优先级动态处理内容显示隐藏|
|折行能力|容器组件尺寸发生变化时，如果布局方向尺寸不足以显示完整内容，自动换行|弹性布局设置FlexWrap属性即可实现内容自动换行|

### 4.2.1.2 响应式布局

合理使用自适应布局进行页面开发后，无论窗口尺寸如何变化，界面布局都会自动适应窗口展示区域。然而，随着窗口尺寸大幅增加后，原有的手机页面内容在大尺寸窗口上会出现图片异常放大、页面内容稀疏以及留白过多等问题，影响用户体验。因此，开发者需要针对不同的窗口尺寸以及设备的使用场景，进行适当的增量设计和开发，以提供更贴近用户场景的应用使用体验。这需要运用到响应式布局能力。

响应式布局是指页面内的元素可以根据特定的特征（如窗口宽度、窗口宽高比等）自动调整页面布局，以适应外部容器变化的布局能力。响应式布局能力包括三个部分：断点、媒体查询、栅格布局和容器断点。

断点是响应式布局的核心工具。HarmonyOS 提供了断点查询API， [getWindowWidthBreakpoint()](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/arkts-apis-uicontext-uicontext#getwindowwidthbreakpoint13) 用于查询横向断点区间，可获取XSmall、Small、Medium、Large和XLarge 5个屏幕宽度区间；[getWindowHeightBreakpoint()](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/arkts-apis-uicontext-uicontext#getwindowheightbreakpoint13) 用于查询纵向断点区间，可获取Small、Medium、Large 3个区间代表屏幕宽高比例。基于横向和纵向的断点划分，开发者可以完成最多15种界面布局设计，为全场景设备的屏幕尺寸变化、横竖屏切换、应用分屏、自由多窗等场景提供独特的应用使用体验。关于断点的最佳实践，可以查阅官方网站的[指南](https://developer.huawei.com/consumer/cn/doc/best-practices/bpta-multi-device-responsive-layout#section1532120147301)。

媒体查询是多设备开发的另一个关键工具，支持查询屏幕分辨率、横竖屏、深浅色模式等与用户界面相关的要素，允许开发者在这些场景变化时进行布局差异化开发，以满足不同场景下的界面精致体验诉求。值得注意的是，当前媒体查询还提供了设备类型的查询能力，建议开发者尽量避免使用此功能进行页面布局管理，以确保页面布局在各种设备间最大化复用。关于媒体查询的更多信息，可以查阅[媒体查询使用指南](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/arkts-layout-development-media-query)。

栅格布局是用于处理多屏幕尺寸下动态布局的能力，适用于规律性的页面布局场景，其核心思想是将页面划分为等宽的列数，便于对页面元素进行定位和排版。栅格布局集成了断点自定义能力，支持以窗口为参照物定义断点区间，同时也支持以自身为参考进行组件级别的断点自定义，使用场景更加灵活。关于栅格布局的更多信息，可以查阅[栅格布局使用指南](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/arkts-layout-development-grid-layout)。

容器断点组件是基于组件自身实际尺寸和断点阈值数组确定断点值，通过双向绑定实时返回容器尺寸和断点信息，用于响应式布局。与窗口断点不同，容器断点关注的是组件所在容器的实际尺寸，而非整个窗口的尺寸。关于容器断点组件的更多信息，可以查阅[容器断点使用指南](https://gitcode.com/openharmony/docs/blob/81a6f31aee537116dbf3752dfa53966e33d1e2d8/zh-cn/application-dev/ui/arkts-layout-development-container-reader.md#容器断点组件)。

在使用web组件时，需要考虑W3C标准的响应式布局规格，用媒体查询@media对页面整体结构进行布局，用容器@container查询来对组件布局进行调整。Web的响应式布局规格允许使用具体的尺寸，为了取得混合页面的最佳显示效果，可以考虑将web的尺寸断点对齐ArkUI原生断点。在web中，页面需要考虑横屏及竖屏的UX设计，单纯地使用vw、vh等单位进行布局可能会导致设备旋转时页面部分内容被截断。

### 4.2.2.2 多态组件

为提升应用在多设备开发过程的开发效率，HarmonyOS 从 API20 开始为开发者提供了 UI Design Kit 的多态组件能力。通过扩展 ArkUI 基础组件，这一能力提供了符合多设备设计规范的高阶精致多态组件，帮助开发者在多设备开发中实现一致性和个性化的平衡，同时降低维护成本，提升用户体验。

UI Design Kit 提供丰富的扩展能力，允许开发者根据实际需要进行二次开发和定制，构建独特的应用体验。可通过以下 import 方式按需加载相应的组件。

```screen
import { hdsSideBar, HdsNavigation, HdsTabs} from '@kit.UIDesignKit';
```

以导航类组件为例，HdsSidebar 和 HdsNavigation 组件作为核心模块，不仅延续了 ArkUI 基础导航组件的核心功能，还通过创新设计提升了用户体验，如分栏的断点设计、PC端的避让逻辑，以及与 HdsNavigation 组件的协同工作。通过示例代码和实际效果展示，开发者将了解如何在不同断点下实现单栏、双栏或三分栏的布局效果，以及如何在不同设备上实现差异化样式设计。此外，我们还将探讨 HdsNavigation 组件在不同设备上的独特交互体验，如标题栏的自动显隐功能、动态模糊等精致效果，以及 HdsNavigation 与 HdsSidebar 组件在不同设备的差异化交互设计。

   ```screen
   HdsSideBar({
   ```

   HdsNavigation组件扩展支持标题栏动态模糊样式，通过实时模糊效果，提升应用交互精致度、沉浸感、空间感等高阶体验。当应用开发者需要使用标题栏样式随内容区滚动而动态改变样式的导航组件时，可以通过设置titleBar属性中的标题栏样式配置，自定义滚动前后的标题栏样式。当前支持通用模糊、过渡模糊、渐变模糊样式设置。默认为通用模糊样式。

   ```screen
   HdsNavigation() {

   .titleBar({ 
     style: {  
       scrollEffectOpts: {
   ```

   ```screen
   HdsNavigation() {  
   }

     hideStatusBar: false,
   ```

   ```screen
   HdsNavigation() {

         builder: this.BottomBuilder.bind(this),  
         height: 56,  
         showType: BottomBuilderShowType.DIRECTLY_SHOW,  
       } // 标题栏底部自定义区域  
     }  
   })
   ```

   * 支持设备类型

   手机、PC、Pad、智慧屏、座舱
   * 断点及UX设计

   |屏幕宽度|≤600vp||(600vp, 840vp]|

### 4.2.4.1 启动页

启动页是应用冷启动时最先显示的页面，在应用进程尚未运行或应用内容未完全加载前，都始终显示启动页，有助于提升用户在应用启动阶段的等待体验。启动页的配置方式有简易启动页和增强启动页两种。开发者通过在module.json5配置文件中的[abilities标签](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/module-configuration-file#abilities标签) 配置启动页资源。简易启动页方案仅支持配置startWindowIcon和startWindowBackground字段，需要开发者针对不同屏幕大小综合考虑并设计和配置相应的资源，往往无法应对屏幕尺寸多变场景，我们建议开发者使用增强启动页方案进行应用启动页配置。增强方案可用于元素更复杂的启动页配置。同时，相应资源也能够具备根据窗口尺寸进行自动调整，更加适用于屏幕多样化场景。

1. 在创建的UIAbility模板中，上述startWindow字段未配置，开发者可以新增startWindow字段指向二级配置json文件，以启用启动页增强配置。其中，json文件需要由开发者自行创建并放置到工程目录下。推荐的文件名及路径为resources/base/profile/start_window.json。
2. 配置二级json文件的具体字段，包括背景颜色、插画资源、品牌标识、背景图片和图片填充方式，系统基于窗口尺寸进行相应资源的自适应调整。

以下面的配置为例：

```screen
{ 
  "startWindowIllustration": "$media:illustration",  // 启动页插画资源 
  "startWindowBrandingImage": "$media:branding",     // 启动页品牌标识 
  "startWindowBackgroundColor": "$color:start_window_background",   // 启动页背景色 
  "startWindowBackgroundImage": "$media:startingWindowBackground",  // 启动页背景图片 
  "startWindowBackgroundImageFit": "Cover"  // 背景图片在窗口内的填充方式 
} 
```

最终在各种屏幕尺寸的效果如下（自左向右分别对应：手机、手机应用分屏、大折叠展开态、平板横屏）：

### 4.2.4.2 横竖屏旋转

HarmonyOS 手机因其多样化的形态和用户使用场景，例如大折叠（X5、X6）拥有接近方型的屏幕，需要确保横竖屏体验一致；而三折叠（XT）在展开后接近平板，用户也有横屏的使用诉求。因此，强烈建议在应用启动时或进入特定页面时，避免强制设定屏幕方向为竖屏，这可能会给用户带来不好的应用使用体验。

HarmonyOS 通过对全场景设备进行了横屏使用的人因分析，得出的结论是当屏幕较短一边的逻辑像素大于348vp时可以获得较好的横屏阅读体验。因此，建议开发者在满足此条件后支持应用横屏使用，并做好横屏下的页面布局和交互体验设计。

横竖屏控制行为在应用内是统一的，因此只需要对横竖屏响应进行一次性实现和控制，业务页面内就不需要再重复处理横竖屏响应。第一步，先依据窗口的虚拟像素尺寸并结合横竖屏旋转 API 实现横竖屏响应控制的处理：

```screen
// 设置默认的横竖屏策略 
setDefaultOrientation(): void { 
  let windowRect: window.Rect = this.windowObj!.getWindowProperties().windowRect; 
  let windowWidthVp: number = this.uiContext!.px2vp(windowRect.width); 
  let windowHeightVp: number = this.uiContext!.px2vp(windowRect.height); 
  // 满足屏幕短边大于348vp时允许横屏 
  if (Math.min(windowWidthVp, windowHeightVp) > 348) { 
    this.windowObj?.setPreferredOrientation(window.Orientation.AUTO_ROTATION_RESTRICTED); 
  } 
  else { 
    this.windowObj?.setPreferredOrientation(window.Orientation.PORTRAIT); 
  } 
} 
```

下一步，在窗口创建阶段调用横竖屏控制处理。由于三折叠设备由折叠收起状态进入展开状态时存在一次横竖屏的状态变化，因此还需要监听窗口尺寸变化，并实时对横竖屏响应策略进行调整：

```screen
onWindowStageCreate(windowStage: window.WindowStage): void { 
  // Main window is created, set main page for this ability 
  windowStage.getMainWindow().then((windowObj) => { 
    this.windowObj = windowObj; 
  }); 
  windowStage.loadContent('pages/Index', (err) => { 
    this.uiContext = this.windowObj!.getUIContext(); 
    // 启动阶段设置横竖屏控制 
    this.setDefaultOrientation(); 
    // 窗口尺寸变化时动态调整横竖屏控制 
    this.windowObj!.on('windowSizeChange', this.onWindowSizeChange); 
  }); 
}
```

**首页菜单差异化实现**

菜单的搜索功能框在窄屏时与菜单存在换行关系，可以使用Flex弹性布局的换行能力来进行实现。

```screen
// Flex设置wrap属性为换行后，当容器横向宽度不足以一行显示时，会自动换行显示 
Flex({ wrap: FlexWrap.Wrap }) { 
  // 二级菜单导航 
  MenuBar() 
  // 搜索功能区 
  SearchBar() 
}
```

需要注意，在进行搜索框部分的代码实现时，部分开发者会基于设计稿进行断点和固定vp尺寸的动态布局实现，但这样会导致窗口在Small断点区间内小幅度变化时输入框无法撑满整个应用窗口。

```screen
// XSmall和Small断点时宽度为280vp，Medium、Large、XLarge时宽度为240vp 
TextInput({ placeholder: '搜索...' }) 
.width(new WidthBreakpointType(280, 280, 240, 240, 240).getValue(this.currentWidthBreakpoint))
```

虽然也是基于断点思路进行差异化实现，但以PuraX为例，其屏幕宽度是440vp，280vp这个固定的像素布局会导致搜索框不能铺满整行空间。可以使用Flex布局的布局权重自适应布局能力来让搜索框宽度基于屏幕宽度自动计算剩余宽度：

```screen
Flex() { 
  // 将Text的布局权重标记为1后，文本框的宽度会自动占满弹性盒子剩余空间，在容器宽度发生变化时会自动重新适应 
  Text('搜索...') 
    .layoutWeight(1) 
  Button() { 
    Image($r('app.media.search_history')).width('100%').height('100%').fillColor(Color.White)) 
  }
```

**Tab导航组件实现屏幕断点是 Large 时显示在页面左侧**

ArkUI的Tabs组件支持开箱即用的数据驱动式布局变化，开发者需要在满足断点是Large时做以下两个配置：首先将barPosition设置为BarPosition.Start，其次将vertical设置为true。

```screen
Tabs({ 
  barPosition: this.currentWidthBreakpoint === WidthBreakpoint.WIDTH_LG ? BarPosition.Start : BarPosition.End 
}).vertical(this.currentWidthBreakpoint=== WidthBreakpoint.WIDTH_LG) 
```

当三折叠进入三屏展开状态的横屏时，Tab导航会自动由屏幕下方切换至屏幕左侧。

需要注意，当前对Tabbar的布局定义是，当宽度断点是Large时居左显示，否则显示到屏幕下方。断点规格在Large之上还有更大的XLarge，为了保持Tab在XLarge屏幕上仍然在左侧显示，上面的代码可以做以下优化以避免在更大屏幕上出现问题：

```screen
Tabs({ 
  barPosition: [WidthBreakpoint.WIDTH_LG, WidthBreakpoint.WIDTH_XL].includes(this.currentWidthBreakpoint) ? 
    BarPosition.Start : 
    BarPosition.End 
}) 
.vertical([WidthBreakpoint.WIDTH_LG, WidthBreakpoint.WIDTH_XL].includes(this.currentWidthBreakpoint))  
```

**Banner图的图片展示**

Banner图区域是应用非常重要的区域，其使用场景是通过多张图片来展示当前的热门信息。推荐使用Swiper轮播图组件进行实现。考虑到屏幕尺寸变化场景，开发者需要注意不要因为头图占用区域过大导致整体页面布局不协调。针对这种场景，有两种常用的设计和实现方式：

* **轮播图在不同屏幕尺寸下永远展示一张图片，用户可左右滑动来切换。** 这种场景要为不同屏幕提前准备特定的图片资源，以保障最佳的信息展示效果。

  实现上需要在各个断点区间加载提前准备的不同尺寸的图片资源。

  ```screen
  // 定义轮播图在不同屏幕断点下的资源地址 
  private bannerImgList: Array<BannerImg> = [ 
    // 示例代码演示的是随APP包发布的资源定义方式，从网络服务器加载资源图片的场景则把资源地址更换为网络地址 
    new BannerImg($r('app.media.ic_banner_1'), $r('app.media.ic_banner_1_sm')), 
    ... 
  ]; 
   
  build() { 
    Swiper() { 
      LazyForEach(this.bannerDataSource, (item: BannerImg) => { 
        Row() { 
          Image( 
  [WidthBreakpoint.WIDTH_XS,WidthBreakpoint.WIDTH_SM].includes(this.currentWidthBreakpoint) ?  item.getImgSrcSm() : item.getImgSrc() 
          ).width('100%').height('100%').objectFit(ImageFit.Cover) 
        }.width('100%').height('100%') 
      }, (item: BannerImg, index: number) => index + JSON.stringify(item)) 
    } 
  }
  ```

  上图效果中使用了同一张图片，可以看到，为了保证整体页面结构合理性，三种不同设备下使用相同图片时会存在内容被裁切的现象。反之，若为了追求图片完整显示，则在大尺寸窗口时，图片会占据大量显示区域，降低信息阅读体验。


* **轮播图通过在不同屏幕上展示不同的图片数量来更有效地利用宽屏的信息展示优势。** 这种场景可以结合断点来为不同屏幕定制轮播图默认展示的图片数量。

  ```screen
  Swiper() { 
    LazyForEach(this.bannerDataSource, (item: BannerImg) => { 
      ... 
    }, (item: BannerImg, index: number) => index + JSON.stringify(item)) 
  }.displayCount( 
    [WidthBreakpoint.WIDTH_XS, WidthBreakpoint.WIDTH_SM].includes(this.currentWidthBreakpoint)) ? 1 : 2 
  )
  ```

**宫格式内容展示实现**

宫格展示可以使用Grid基础布局组件来实现，按照UI设计稿，可以结合断点来将宫格划分为指定数量的等宽格子，列数仅与屏幕横向宽度有关，因此，基于横向断点设置为Small时2列，Medium时3列，Large时4列，这里同样建议为其他未设计的断点规格预设列数配置，XSmall时1列，XLarge时5列。

```screen
Grid() { 
  LazyForEach(this.videoListItems, (item: VideoListItem, index: number) => { 
    GridItem() { 
      ... 
    } 
  }, ((item: VideoListItem, index: number) => `${item.title}_${index}`)) 
} 
.columnsTemplate( 
  `repeate(${new BreakpointType(1, 2, 3, 4, 5).getValue(this.currentWidthBreakpoint)}, 1fr` 
) 
```

上述代码中使用的Grid组件，适合宫格卡片高度相同的场景。对于高度不同的宫格场景可以使用WaterFlow组件，实现方式与Grid相似：

```screen
WaterFlow({ 
  layoutMode: WaterFlowLayoutMode.SLIDING_WINDOW

  LazyForEach(this.videoListItems, (item: VideoListItem, index: number) => { 
    FlowItem() {

    }, ((item: VideoListItem, index: number) => `${item.title}_${index}`) 
  )

  new WidthBreakpointType( 
    ColumnTemplateUnit.repeat(1), ColumnTemplateUnit.repeat(2), 
    ColumnTemplateUnit.repeat(3), ColumnTemplateUnit.repeat(4), 
    ColumnTemplateUnit.repeat(5) 
).getValue(this.currentWidthBreakpoint)) 
```

**视频长按后以弹窗形式播放**

长按的交互动作可以使用touch原始事件来完成长按的识别，但touch事件是触摸屏专有事件，鼠标操作场景时不会被触发，会出现鼠标无法长按播放的用户体验问题。

为了避免在鼠标场景中针对mouse事件进行额外的功能开发，ArkUI提供了归一化的长按手势事件[LongPressGesture](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/ts-basic-gestures-longpressgesture)。该事件对touch事件和mouse事件进行了归一化处理，无论是触摸屏点击还是鼠标点击都会正常触发长按手势事件，用这个事件可以一举两得。

```screen
Image(item.preview) 
.gesture( 
  LongPressGesture({ repeat: false }).onAction(() => { 
    // 控制视频弹窗出现 
    ... 
  }) 
)
```

在IM页面的分栏场景中，初次进入时尚未选择聊天对象，因此需要实现一个占位页面并在最右侧的聊天区域显示。这里涉及到的断点区间包括Medium、Large和XLarge。

这里需要考虑一个体验优化场景。当用户在折叠屏展开态下正在与联系人聊天时，如果因为一些原因必须将手机折叠使用时，页面将保留聊天详情页面。但若此时用户还没有选择聊天对象，则折叠后需要退回到联系人列表页面，避免展示一个无意义的占位页面。这个优化在折叠收起状态到展开态也同样需要。在该场景下，由于页面路由状态是聊天占位页面，不能通过布局来改变什么。因此需要使用代码逻辑来实现这个体验优化，通过@Watch监听断点变化，并按需将页面路由从占位页面回退到联系人列表页面，或从联系人列表页面前进到聊天详情占位页面。

```screen
// 监听断点变化 
@StorageLink('currentWidthBreakpoint') 
@Watch('currentWidthBreakpointChange') currentWidthBreakpoint: WidthBreakpoint = WidthBreakpoint.WIDTH_SM; 
// 断点变化的监听回调处理 
currentWidthBreakpointChange() { 
  if (this.currentSelectTabIndex !== 1) { 
    return; 
  } 
  if (![WidthBreakpoint.WIDTH_XS, WidthBreakpoint.WIDTH_SM].includes(this.currentWidthBreakpoint) && this.pageInfos.size() === 0) { 
    // 当断点进入Medium、Large、XLarge时代表由折叠收起到展开态，我们路由到聊天详情占位页面 
    this.pageInfos.pushPath({ name: 'ConversationDetailNone' }); 
  } else if ([WidthBreakpoint.WIDTH_XS, WidthBreakpoint.WIDTH_SM].includes(this.currentWidthBreakpoint) && this.pageInfos.size() > 0) { 
    // 当断点进入XSmall、Small时代表由展开态收起到折叠态，若路由栈顶部为占位页ConversationDetailNone，则回退到联系人列表页面 
    let pathNames: Array<string> = this.pageInfos.getAllPathName(); 
    if (pathNames.length > 0 && pathNames[pathNames.length - 1] === 'ConversationDetailNone') { 
      this.pageInfos.clear(); 
      return; 
    } 
  } 
} 
```

**横版视频全屏播放**

市面上的视频观看场景主要是影视剧类的横版视频和短视频类的竖版视频，横版视频由于其比例的原因，通常可以通过横屏全屏播放来将视频画面放大，提升观看体验。先来看下横版视频的全屏播放实现。

```screen
this.screenHeight = display.getDefaultDisplaySync().height;  // 窗口高度 
this.screenWidth = display.getDefaultDisplaySync().width;  // 窗口宽度 
this.screenRatio = this.screenHeight / this.screenWidth; // 窗口高宽比
```

```screen
if (this.screenRatio > 2) {
```

市面上的短视频比例较为多样化，开发者需要结合短视频宽高比例和运行设备的屏幕尺寸再动态决定视频的摆放位置。下面是我们以 9:16 宽高比的视频源来进行实现，开发者可以类推其他比例的布局实现。

下图是 16:9 视频源在各种尺寸屏幕下的摆放建议：

![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/f6/v3/lDHnAuuVSFiL3wvjVWyCWA/zh-cn_image_0000002594673044.png?HW-CC-KV=V1&HW-CC-Date=20260909T171329Z&HW-CC-Expire=31536000000&HW-CC-Sign=8D41695925ABA1D38641C1C81354881167AB677BBD5217BB2CA6C4F804A924FD "点击放大")

从图中可整理出以下布局规则：

* 规则1：至少在上下或左右中选择其一铺满显示，另一边可接受留白
* 规则2：当窗口比例小于 14.4:9 时，优先保障视频内容完整性，左右留白
* 规则3：当窗口比例接近 16:9（位于 14.4:9，18:9 区间）时，可对视频铺满一边后对超出部分进行裁剪，实现全屏沉浸
* 规则4：当窗口比例位于18:9，20:9 区间时，由于屏幕竖边过长，视频左右铺满后仍不能铺满整个窗口，此时视频从状态栏区域开始显示，满足顶部和左右三边沉浸
* 规则5：当窗口比例大于 20:9 时，基于规则4的实现会导致下方留白过多，此时视频在纵向居中显示

需要注意的是，与横版视频全屏完全不同的是，短视频的页面布局只与窗口尺寸有关。我们通过监听窗口尺寸变化，并动态计算和更新小视频布局来实现沉浸式体验。

我们通过组件的getMainWindow().getWindowProperties可以获取到窗口的宽高尺寸数据，通过计算得到宽高比，从而确定视频在各种尺寸屏幕下的摆放位置。

使用videoSizeChange来获取视频宽高，从而根据屏幕大小来调整视频流比例大小。

```screen
avPlayer?.on('videoSizeChange', (width: number, height: number) => { 
  this.videoHeight = height; 
  this.videoWeight = width 
})
```

通过XComponent.setXComponentSurfaceRect来设置视频流比例。以 16:9 的视频比例为例。

* 窗口宽高比例小于等于 14.4:9 时，将视频流高度设置为窗口高度，可以根据窗口高度*视频宽高比得到视频流的高度，且此时视频透过Tabs组件显示，所以设置barOverlap为fasle。

```screen
this.barOverlap = false; 
// 根据高度算宽度 
this.xComponentController.setXComponentSurfaceRect({ 
  surfaceWidth: this.windowHeight * this.videoWeight / this.videoHeight, 
  surfaceHeight: this.windowHeight 
});
```

* 14.4:9 < 屏幕比例 <= 18:9，此时需要计算视频宽高比是否>=1，宽高比>=1则说明视频的宽度大于高度，此时视频流的高度为窗口高度，视频流宽度为视频宽高比*窗口高度，且此时Tabs组件需要调整透明度，以达成沉浸式观影体验，所以设置barOverlap为fasle。

```screen
this.barOverlap = false; 
if (videoSizeHeight >= 1) { 
  this.xComponentController.setXComponentSurfaceRect({ 
    surfaceWidth: videoSizeHeight * this.windowHeight, 
    surfaceHeight: this.windowHeight 
  }) 
} else { 
  // 根据宽度算高度 
  this.xComponentController.setXComponentSurfaceRect({  
    surfaceWidth: this.windowWidth, 
    surfaceHeight: this.windowWidth * this.videoHeight / this.videoWeight 
  }) 
}
```

* 18:9 < 窗口比例 <= 20:9，此时需要视频在Tabs上半部分显示，所以设置barOverlap为true，视频流的高度为窗口高度，视频流宽度为视频宽高比*窗口高度。

```screen
this.xComponentController.setXComponentSurfaceRect({ 
  surfaceWidth: videoSizeHeight * this.windowHeight, 
  surfaceHeight: this.windowHeight 
}); 
this.barOverlap = true
```

* 窗口比例大于20:9，此时视频在Tabs上半部分显示，所以设置barOverlap为true，且需要显示上导航栏，视频流的高度为窗口高度减去两倍的上导航栏高度，视频流宽度为视频流高度*视频宽高比。

```screen
this.xComponentController.setXComponentSurfaceRect({ 
  surfaceWidth: videoSizeHeight * (this.windowHeight - 2 * this.statusHeight), 
  surfaceHeight: (this.windowHeight - 2 * this.statusHeight) 
}); 
this.barOverlap = true; 
```

[https://gitcode.com/openharmony-sig/hadss_adaptive/blob/master/README.md](https://gitcode.com/openharmony-sig/hadss_adaptive/blob/master/README.md)获取。

**相机预览实现**

1. 使用XComponent显示相机流，通过在ArkTS侧获取SurfaceId，并使用createPreviewOutput()创建预览输出对象并绑定同一个SurfaceId，显示预览数据流。

```screen
XComponent({ 
  type: XComponentType.SURFACE, 
  controller: this.mXComponentController 
}) 
.onLoad(async () => { 
  // ... 
  surfaceId = this.mXComponentController.getXComponentSurfaceId(); 
}) 
// 可以实时显示相机画面，相机系统优先输出帧率确保流畅体验 
previewOutput = cameraManager.createPreviewOutput(previewProfile, surfaceId);
```

2. createPreviewOutput()接口中的previewProfile通过getSupportedOutputCapability获取，并通过设备屏幕比例选取最佳预览分辨率。
   1. 监听窗口尺寸变化，同时监听display屏幕旋转变化，更新最佳比例。需要注意的是，同一个应用不要多处调用display.on("change")且不关闭，容易造成逻辑处理错误，同时异步方法必须加上await，保证执行顺序。

      ```screen
      this.windowClass.on('windowSizeChange', async (size) => { 
        this.mWindowWidth = size.width; 
        this.mWindowHeight = size.height; 
        // 更新xcomponet宽高 
      }); 
      display.on("change", async () => { 
        this.initDisplayRotation = display.getDefaultDisplaySync().rotation 
        // 更新xcomponet宽高 
      });
      ```

   2. 根据屏幕比例选择合适的预览分辨率，适用于全屏显示的场景，如果业务需要特殊比例，修改mConfigRatio即可。

      ```screen
      @State mConfigRatio: number = 1; // 设置分辨率比例初始值 
      // 根据屏幕初步计算比例，长边/短边 
      this.mConfigRatio = (this.mWindowWidth > this.mWindowHeight) ? (this.mWindowWidth / this.mWindowHeight) : 
          (this.mWindowHeight / this.mWindowWidth); 
      ```

   3. 根据上步确定的比例选择预览分辨率。
      1. 获取全量能力值，获取预览分辨率。

         ```screen
         this.cameraOutputCapability = this.cameraManager.getSupportedOutputCapability(cameraDevice, this.curSceneMode);   
         let previewProfiles = cameraOutputCapability.previewProfiles;
         ```

      2. 遍历所有的预览分辨率，选择最接近mConfigRatio比例的预览分辨率，可能存在支持的分辨率与想要的比例无法完全匹配的情况，所以要允许一定的误差存在，比如示例代码中以0.2作为误差比例，可根据业务自行调整。

         ```screen
         for (let i = 0; i < previewProfiles.length; i++) { 
             if (previewProfiles[i].format !== this.previewProfileObj.format) { 
               continue; 
             } 
             let ratio = previewProfiles[i].size.width / previewProfiles[i].size.height; //1088*1080 
             // 检查宽高比是否匹配 
             if (Math.abs(ratio - configRatio) > 0.2) continue; // 0.2的误差可自行调整 
             // 选择最接近的分辨率 
             if (Math.abs(previewProfiles[i].size.height - this.reConfigType) < minDiff) { 
               optimalSize = previewProfiles[i]; 
               minDiff = Math.abs(previewProfiles[i].size.height - this.reConfigType); 
             } 
           } 
         //...可以补充其他的选分辨率逻辑 
         return optimalSize;
         ```

   4. 根据上一步获得的optimalSize比例重新设置XComponent宽高。

      ```screen
      this.mConfigRatio = optimalSize.size.width / optimalSize.size.height;
      ```


3. 创建相机输入：通过cameraManager类中的getSupportedCameras()方法，获取当前设备支持的相机列表，并通过createCameraInput()方式创建相机输入。

   ```screen
   // 获取摄像头列表 
   let cameraArray: camera.CameraDevice[] = cameraManager.getSupportedCameras(); 
   if (cameraArray.length <= 0) { 
     return []; 
   } 
   //选中需要的镜头，以后置为例 
   cameraInput = cameraManager.createCameraInput(CameraPosition.CAMERA_POSITION_BACK, CameraType.CAMERA_TYPE_DEFAULT);
   ```


4. 针对折叠屏设备，Camera Kit会动态上报镜头，折叠状态改变后，可使用Camera Kit提供的on('foldStatusChange')回调方法获取当前设备的折叠状态和当前折叠状态所支持的相机列表信息，再通过getSupportedCameras()动态获取当前折叠/展开状态下的镜头，并根据诉求打开对应的摄像头。参考[适配不同折叠状态的摄像头变更指导](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/camera-foldable-display)，示例代码如下：

   ```screen
   function callback(err: BusinessError, foldStatusInfo: camera.FoldStatusInfo): void { 
     if (err !== undefined && err.code !== 0) { 
       return; 
     } 
     // 折展态变化重新获取镜头列表 
     // 更新屏幕比例 
   } 
   function registerFoldStatusChange(cameraManager: camera.CameraManager): void { 
     cameraManager.on('foldStatusChange', callback); // 注册折叠状态变化监听 
   } 
   // .... 
   async updateCameraInfo () { //最佳比例发生变化后，需要重新选择镜头与分辨率，重新打开相机. 
     if (surfaceId == '' || this.mConfigRatio === 0 || //非首次进入 
       (cameras.length === this.mLastCameraLength && cameraPosition !== this.mLastCameraPosition)) { //非切换镜头场景 
       return; 
     } 
     // 重新打开相机 
     this.mLastCameraLength = cameras.length; 
     this.mLastCameraPosition = cameraPosition; 
   }
   ```


5. 相机预览分为两种情况：

* 直接送显场景：预览流直接送到Xcomponent进行显示；
* 二次处理（自绘制）场景：应用获取每帧buffer，且旋转逻辑完全由应用自己处理；

由于物理镜头和物理屏幕的关系是固定的，因此相机预览正向与屏幕显示角度相关，故预览角度的计算需考虑镜头安装角度和屏幕旋转角度。

对于直接送显场景，应用需首先查询屏幕旋转角度displayRotation，

然后调用接口getPreviewRotation(displayRotation)获得预览旋转角度，

最终通过setPreviewRotation(previewRotation)设置给相机系统。

获取屏幕旋转角度：

```screen
initDisplayRotation = display.getDefaultDisplaySync().rotation 
```

获取图像预览旋转角度：

```screen
let initPreviewRotation = previewOutput.getPreviewRotation();
```

设置图像预览旋转角度：

```screen
previewOutput.setPreviewRotation(initPreviewRotation);
```

对于二次处理场景，应用通过getPreviewRotation(displayRotation)获取预览旋转角度后，可自行旋转图像buffer并进行显示。

6. 调整完预览相机流的角度后，需要调整XComponent组件大小，以防止相机预览时出现变形等问题。可通过设置setXComponentSurfaceRect来调整相机流的大小。

* 使用display.getDefaultDisplaySync().rotation获取屏幕旋转角度

```screen
this.mRotate = display.getDefaultDisplaySync().rotation * camera.ImageRotation.ROTATION_90；
```

* 重新设置Xcomponent组件的宽高

```screen
@State mXComponentWidth: number = CameraConstants.X_COMPONENT_SURFACE_WIDTH;// 定义为状态监听 
@State mXComponentHeight: number = CameraConstants.X_COMPONENT_SURFACE_HEIGHT; 

updateXcomponentSize(): void { 
  let angleDiff = (this.mRotate + cameraDevice.cameraOrientation) % 360; // 用于判断握持方向 
  if (angleDiff === 90 || angleDiff=== 270) { // 竖向布局 
    this.mXComponentWidth = this.mWindowWidth; 
    this.mXComponentHeight = this.mConfigRatio * this.mWindowWidth; //1920 * 1080 
  } else { // 横向布局 
    this.mXComponentWidth = this.mConfigRatio * this.mWindowHeight; 
    this.mXComponentHeight = this.mWindowHeight; //1080 * 1920 
  } 
}
```

**相机拍照实现**

1. 获取设备旋转角度，当前可通过调用once(type: SensorId.GRAVITY, callback: Callback<GravityResponse>)获取一次重力传感器在x、y、z三个方向上的数据，并通过下面示例计算得出设备旋转角度deviceDegree。

   ```screen
   getRealData(data: sensor.GravityResponse): number { 
     let getDeviceDegree: number = 0; 
     let x = data.x; 
     let y = data.y; 
     let z = data.z; 
     if ((x * x + y * y) * 3 < z * z) { 
       return getDeviceDegree; 
     } else { 
       let sd: Decimal = Decimal.atan2(y, -x); 
       let sc: Decimal = Decimal.round(Number(sd) / 3.141592653589 * 180) 
       getDeviceDegree = 90 - Number(sc); 
       getDeviceDegree = getDeviceDegree >= 0 ? getDeviceDegree % 360 : getDeviceDegree % 360 + 360; 
     } 
     return getDeviceDegree; 
   }
   ```


2. 获取并设置拍照旋转角度。调用PhotoOutput类中的getPhotoRotation可以获取到拍照旋转角度，将拍照角度写入PhotoCaptureSetting.rotation。

   ```screen
   function getPhotoRotation(photoOutput: camera.PhotoOutput, deviceDegree: number): camera.ImageRotation { 
   let photoRotation: camera.ImageRotation = camera.ImageRotation.ROTATION_0; 
   try { 
       photoRotation = photoOutput.getPhotoRotation(deviceDegree);   
     } catch (error) {   
      //...打印异常   
     } 
   return photoRotation;  
   }
   ```

### 4.2.4.7 窗口变化场景应对

为了满足用户不同使用场景的需要，HarmonyOS提供了多种窗口形态，给用户带来更佳体验，在折叠设备上，用户还可以通过折叠开合改变窗口尺寸。在给用户带来便利的同时，也给开发者带来更多挑战，开发者需要在单个设备上动态响应窗口的变化：

* 窗口尺寸非固定：用户可通过折叠设备开合、[分屏](https://developer.huawei.com/consumer/cn/doc/design-guides/system-features-multi-window-interaction-0000001795392917#section45872633319)、[悬浮窗](https://developer.huawei.com/consumer/cn/doc/design-guides/system-features-multi-window-interaction-0000001795392917#section865385641914)等交互模式主动改变应用可显示区域
* 复合布局干扰项：


* 系统级避让区（状态栏/导航条等）压缩应用可显示区域高度
* 横竖屏切换导致宽高比变化
* 系统设置中的显示缩放功能引发逻辑像素尺寸变化

**窗口核心状态监听**

为了应对上述变化场景，推荐开发者使用响应式布局进行页面布局开发，可在窗口尺寸变化场景下自动调整布局，为用户提供更加舒适的界面和更好的应用使用体验。为了实现响应式布局开发，开发者需要关注的窗口核心状态，通过响应核心状态变化，可实现不同窗口形态、窗口尺寸下都具备良好的用户体验。

**核心状态**

通过监听并响应核心状态变化，刷新布局，即可实现基于断点系统的响应式布局，满足绝大部分场景使用。

|状态|监听事件|影响|触发场景|
|:-----|:-----------------------------------------------------------------------------------------------------------------------------------------------------|:----------------------------------------------------------------------------|:----------------------------------------------|
|窗口尺寸|[window.on('windowSizeChange')](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/arkts-apis-window-window#onwindowsizechange7)|窗口尺寸变化可能会导致断点发生跃迁，需要触发布局刷新|用户触发分屏、悬浮窗、折叠屏开合、自由窗口尺寸调节、横竖屏旋转等会导致窗口尺寸px值变化的操作|
|窗口显示大小|[window.on('systemDensityChange')](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/arkts-apis-window-window#onsystemdensitychange15)|窗口显示大小表示窗口所在屏幕的显示缩放系数，缩放系数变化时，窗口物理像素（px）或逻辑单位（vp）的映射关系变化，可能会导致断点区间变化，需要页面重新布局|用户在设置中修改窗口显示大小|
|系统避让区|[window.on('avoidAreaChange')](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/arkts-apis-window-window#onavoidareachange9)|避让区坐标、宽高变化，应用需要调整布局，避开不可操作区域|除窗口尺寸触发场景外，还有自由窗口拖动位置、左右、上下分屏位置切换等操作|

屏幕圆角

**监听窗口尺寸、窗口显示大小和避让区变化**

当窗口宽度/高宽比跨越预设断点阈值时，触发布局重构事件。为了准确计算断点，开发者需要监听所有影响断点计算的状态，当前影响断点计算的状态包括窗口尺寸和窗口显示大小变化。

1. 通过监听窗口尺寸windowSizeChange和窗口显示大小systemDensity来更新断点区间的变化

```screen
import { window } from '@kit.ArkUI'; 
export default class EntryAbility extends UIAbility { 
  onWindowStageCreate(windowStage: window.WindowStage): void { 
    windowStage.loadContent('pages/Index', (err) => { 
      // 保存windowStage实例，用于获取UIContext等操作 
      AppStorage.setOrCreate("windowInstance", windowStage.getMainWindowSync()) 
      // 监听窗口尺寸变化 
      windowStage.getMainWindowSync().on('windowSizeChange', this.windowSizeChangeListener) 
      // 监听窗口显示大小变化 
      windowStage.getMainWindowSync().on("systemDensityChange", this.systemDensityChangeListener) 
    }); 
  } 
  windowSizeChangeListener(size: window.Size) { 
    // ... 
  } 
  systemDensityChangeListener(density: number) { 
    // ... 
  } 
}
```

当窗口尺寸变化或窗口显示大小变化时，开发者可以在windowStage.loadContent()页面加载后，通过UIContext中提供的[getWindowWidthBreakpoint()](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/arkts-apis-uicontext-uicontext#getwindowwidthbreakpoint13)和[getWindowHeightBreakpoint()](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/arkts-apis-uicontext-uicontext#getwindowheightbreakpoint13)接口获取窗口的断点信息。

```screen
windowSizeChangeListener(size: window.Size) { 
  EntryAbility.updateBreakpoint() 
} 
systemDensityChangeListener(density: number) { 
  EntryAbility.updateBreakpoint() 
} 
static updateBreakpoint() { 
  let windowInstance: window.Window = AppStorage.get("windowInstance") as window.Window 
  AppStorage.setOrCreate('windowWidthBreakpoint',  windowInstance.getUIContext().getWindowWidthBreakpoint()) 
  AppStorage.setOrCreate('windowHeightBreakpoint', windowInstance.getUIContext().getWindowHeightBreakpoint()) 
} 
```

2. 通过监听avoidAreaChange和keyboardHeightChange来正确获取避让区尺寸信息

```screen
import { window } from '@kit.ArkUI'; 
export default class EntryAbility extends UIAbility { 
  onWindowStageCreate(windowStage: window.WindowStage): void { 
    // 监听避让区变化 
    windowStage.getMainWindowSync().on("avoidAreaChange", this.avoidAreaChange) 
    // 监听固定态软键盘高度变化 
    windowStage.getMainWindowSync().on("keyboardHeightChange", this.keyboardHeightChange) 
    windowStage.loadContent('pages/Index', (err) => { 
      ... 
    }); 
  } 
 
  avoidAreaChange(options: window.AvoidAreaOptions) { 
    // 处理避让区变化 
  } 
  keyboardHeightChange(height: number) { 
     AppStorage.setOrCreate('keyboardHeight', height) 
  } 
} 
```

**常见误区**：仅在windowSizeChange回调中获取避让区，没有监听avoidAreaChange回调，窗口尺寸变化和避让区变化之间没有必然联系，在部分场景下（例如弹出软键盘），避让区发生变化时，不会导致窗口尺寸变化，因此不会触发windowSizeChange回调。所以对于安全区变化场景，开发者仍应当监听avoidAreaChange事件以处理避让区变化后的页面布局。

在窗口状态变化时，web组件内部的页面可能受到影响。推荐更多地使用CSS的方法来替代Javascript强行干预布局的写法，以达成最佳性能和状态变化时的及时更新。如果由于业务需要缓存window.innerWidth或window.innerHeight时，推荐使用ResizeObserver在窗口变化时及时更新缓存值和对应的样式。
