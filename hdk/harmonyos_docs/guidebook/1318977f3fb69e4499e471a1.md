# Skills工程化实践：从迁移经验到可复用能力资产

一、概览

在安卓鸿蒙化实践中，我们发现仅依赖通用大模型直接完成端到端迁移，难以稳定应对真实应用中的复杂工程约束。原因在于，鸿蒙ArkTS语法、ArkUI组件体系、生命周期差异、资源迁移规则、三方库替换策略、编译错误修复经验等知识，往往分散在人工经验、历史问题和项目代码中。如果这些经验不能被结构化沉淀，每次迁移都会重新依赖人工判断，难以形成规模化复用。

为此，我们在实践过程中引入 Skills 机制，将迁移过程中反复出现的专家经验、操作步骤、规则约束和错误修复模式，封装为可被智能体调用的能力单元。Skills 不只是Prompt模板，而是面向具体迁移任务的工程化知识载体，既包含"怎么做"的流程步骤，也包含"不能怎么做"的约束规则，以及常见问题的处理策略。

通过 Skills 机制，UI迁移、资源转换、Spec 生成、代码开发、编译修复、代码检视、集成测试等环节中的关键经验得以沉淀，并在后续项目中复用，从而降低模型自由发挥带来的不确定性，提升迁移过程的稳定性和可复制性。

二、技术方案

![](https://media:801788430183398329 "点击放大")

Skills工程化实践主要包含两个重要的能力：

1）Skills沉淀：从人工经验到结构化能力

在迁移过程中，我们将高频出现的任务模式抽象为独立 Skills。例如，在UI迁移阶段，沉淀安卓控件到 ArkUI组件的映射规则、MVVM 页面结构约束、资源引用方式和布局还原策略；在代码开发阶段，沉淀基于 Spec 进行最小改动、保持项目架构一致、避免重新理解需求等开发约束；在编译修复阶段，沉淀常见ArkTS编译错误、API 替换规则、类型修复方式和构建问题处理经验。

这些 Skills 的核心价值，是把原本依赖专家临场判断的经验，转化为智能体可执行、可复用、可迭代的工程资产。

2）Skills演进：从失败案例中持续优化能力

在多轮迁移实践中，我们将编译错误、代码检视缺陷、UI对齐问题和测试失败案例进行归因分析，识别高频问题模式，并将有效修复经验反向沉淀到 Skills中。例如，当某类ArkTS类型错误在多个页面中反复出现时，可以将其抽象为编译修复Skill的规则；当某类安卓控件在ArkUI中经常还原不准确时，可以补充到UI映射Skill 中；当某类业务边界场景经常在Spec中遗漏时，可以增强需求分析Skill 的场景检查规则。

通过这种方式，Skills 从一次性经验文档，逐步演进为支持迁移系统持续提升的能力资产。

三、实践效果

在真实 App 迁移过程中，Skills机制主要带来了三方面收益：

第一，提升了迁移过程的稳定性。通过将关键规则前置为Skills，智能体在执行任务时不再完全依赖模型自身知识，而是在明确的工程约束下完成迁移。

第二，降低了人工介入成本。过去需要人工反复提醒的编码规范、资源处理方式、组件映射规则和错误修复经验，可以通过Skills自动注入到智能体执行过程中。

第三，形成了可复用的迁移资产。随着项目数量增加，迁移过程中积累的问题和修复经验可以持续沉淀到Skills中，使后续迁移任务能够继承前序实践成果，而不是从零开始。

因此，Skills 实践是将安卓鸿蒙化迁移中的专家经验、工程规则和失败教训转化为可调用、可验证、可演进的系统能力。
