# 需求分析

**一、概览**

![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/41/v3/hsUUgxgtSPygCccXai227g/zh-cn_image_0000002686648683.png?HW-CC-KV=V1&HW-CC-Date=20260909T144356Z&HW-CC-Expire=31536000000&HW-CC-Sign=57880D4B4F0AB4D193D5D3B9D47D6D78668F43F0D9A0178AF40EF090C4487927)

需求分析阶段的目的是根据原始的安卓项目源码实现，为用户要开发的鸿蒙应用需求生成需求规格Spec，从而指导下游的代码开发智能体进行功能点的正确开发。其输入包括原始的安卓UI界面及代码，以及用户要开发的UI界面需求文档，输出是鸿蒙UI界面需求Spec。

在实际应用中，用户提供的原始需求通常是十分简明扼要的（比如"进入扫描音乐页面后实现扫描音乐功能"），这样的需求描述不够清晰，而且缺失了原始安卓应用中蕴含的各种边界和异常场景的处理逻辑，难以有效指导后续编码智能体进行开发。为此，需求SPEC生成智能体有两大主要任务：

**1）安卓源码分析：**根据用户提供的页面和需求功能点信息，扫描原始的安卓项目源码，识别出该功能点在安卓源码中的具体功能实现情况，包括页面信息、组件信息、代码调用链等等，以及该功能实现中对于边界、异常场景的处理情况。

**2）需求SPEC生成：**根据安卓项目分析的结果，为该需求功能点生成一份详细的需求规格Spec。该Spec不仅包含了原始功能点的清晰的场景逻辑描述，而且补充了各种边界和异常场景的逻辑步骤，从而能够更好地指导下游代码开发智能体进行代码开发。

**二、技术方案**

![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/24/v3/yJHDCfI0T2WwkUW4mSi5KA/zh-cn_image_0000002656609204.png?HW-CC-KV=V1&HW-CC-Date=20260909T144356Z&HW-CC-Expire=31536000000&HW-CC-Sign=8E85DD5B51DF9B060C64F4B6E8ED766D2DBA8AA4EF08966CDF497D818307BA79 "点击放大")上图是需求分析阶段的技术方案，包含安卓源码分析和需求SPEC生成等两个部分：

**1）Stage0 预处理**

安卓源码分析做了两方面关键预处理：一方面，利用GitNexus工具为原始安卓项目源码建立知识图谱。GitNexus能将源码索引为一张有向图，并提供图查询能力来理解代码间的调用、依赖和影响关系，这为后续追踪需求对应的代码间依赖和调用关系奠定了基础。另一方面，建立全局页面索引，保证后续阶段使用词汇一致性，同时减少后续阶段的重复处理。

**2）Stage1 源码分析**

源码分析包括功能追踪阶段和审核阶段。功能追踪阶段以页面为单位进行调用链追踪，理解每个控件背后完整的调用逻辑、状态写入和数据流情况。审核阶段对追踪产物进行审核，检查追踪的调用关系和函数体是否存在，确保结果正确性，并通过检查处理步骤的数据流闭合性、关键参数完整性和需求覆盖性等，保障结果完整性。

**3）Stage2 Spec生成**

Spec生成阶段根据需求将分散的页面功能实现整合生成场景并编写需求Spec。先结合跨页面的代码功能描述做功能聚类，再生成场景并按要求格式编写Spec，不引入新的语义内容。通过将场景整合和Spec生成解耦，提升了Spec生成的准确性和完整性。

**4）Gate Spec确认**

交付前需人工验证需求规格Spec文档的场景完整性及与原始需求的一致性，如存在问题，返回对应前序阶段进行修复。
