# 评测结果

我们汇总了SWEbench-Ark 和 FEABench的实验结果，展示于下图。从 Token 消耗与任务成功率的散点分布结果可以看出，在本次鸿蒙ArkTS专项评测数据集上，DevEco Code任务成功率显著优于OpenCode。其中，DevEco Code‑GLM‑5.1的组合表现最优，任务成功率达到 61.17%，在所有测试样本中处于最高水平，体现出该Agent在鸿蒙原生开发场景下更强的代码生成、需求适配与工程交付能力。

对比同基座模型下的OpenCode，GLM‑5.1 基座对应的OpenCode任务成功率仅为 49.51%，二者性能差距明显，说明DevEco Code针对鸿蒙生态的深度优化有效提升了端到端开发任务的完成质量。从资源消耗角度分析，DevEco Code‑GLM‑5.1 虽 Token 消耗高于OpenCode同模型版本，但换取了更高的任务成功率；而其余DevEco Code组合虽 Token 消耗更大，任务成功率却未实现同步提升，反映出基座模型适配性对 Agent性能存在关键影响。综合来看，基座模型与 Agent的生态适配性是决定鸿蒙场景下Coding Agent实际落地能力的核心因素（评测结果展示见下图，观点：人工review可以改善任务完成率）。

一、DevEco Code和OpenCode对比

增量需求场景

在增量需求开发任务的对比实验中（FEABench-Ark），DevEco Code（基于GLM5.1）与OpenCode两类智能体模型表现各有侧重：DevEco Code编译通过率达到 100%，显著优于OpenCode的 81.25%，体现出更强的代码语法合规性与编译稳定性；但二者任务成功率相近，DevEco Code为 43.75%，OpenCode 略高至 46.88%；在资源消耗层面，两类模型总 Token 消耗规模接近，DevEco Code略高于OpenCode，整体 Token 开销差异较小。综合来看，DevEco Code在代码可编译性上具备明显优势，而OpenCode在任务端到端完成效果上略有提升，二者在资源消耗层面处于同一量级。  

|------|-----------|---------------|--------------|----------|
|模型|Agent|编译通过率|任务成功率|总Token消耗|
|GLM5.1|DevEco Code|100.00% (32/32)|43.75% (14/32)|33,288,145|
|GLM5.1|OpenCode|81.25% (26/32)|46.88% (15/32)|32,621,895|

FEABench-Ark（SDD）属于增量 Spec Driven 评测任务，任务以规范为核心驱动，一个任务包含多个功能点和结构约束，不仅要求代码能够编译，还需要严格满足规范行为。本次结果以 50 个 Spec 任务为统计粒度：GLM-5.1 在DevEco Code下编译通过率为 82%（41/50）、任务成功率为 34%（17/50）；在OpenCode下编译通过率为 80.0%（40/50）、任务成功率为 30%（15/50）。整体来看，两款Agent的编译通过率较高，但任务成功率明显更低，说明模型已具备初步SDD工程生成能力，但在完整满足复杂 Spec 约束方面仍有挑战。  

|-------|-----------|--------------|--------------|----------|
|模型|Agent|编译通过率|任务成功率|总Token消耗|
|　GLM5.1|DevEco Code|82.00% (41/50)|34.00% (17/50)|61,943,500|
|　GLM5.1|OpenCode|80.00% (40/50)|30.00% (15/50)|69,957,150|

缺陷修复场景

在缺陷修复任务场景下，DevEco Code（基于 GLM5.1）相较OpenCode展现出全面性能优势：DevEco Code编译通过率达 98.59%，远高于OpenCode的 77.46%，代码语法正确性与可执行性表现突出；任务成功率为 69.01%，较OpenCode的 50.70% 提升显著，缺陷修复的端到端有效性更强；资源消耗方面，DevEco Code总 Token 消耗高于OpenCode，反映其在缺陷修复过程中投入了更多的推理开销以保障代码质量与修复效果。整体而言，在缺陷修复任务中，DevEco Code在编译可靠性与实际问题解决能力上均具备明显优势，代价为更高的 Token 资源消耗。  

|-------|-----------|--------------|--------------|----------|
|模型|Agent|编译通过率|任务成功率|总Token消耗|
|　GLM5.1|DevEco Code|98.59% (70/71)|69.01% (49/71)|53,194,609|
|　GLM5.1|OpenCode|77.46% (55/71)|50.70% (36/71)|43,748,024|

小结

综合增量需求、缺陷修复、文件级多场景评测结果可见，DevEco Code智能体依托深度适配鸿蒙生态的设计优势，可提供开箱即用的开发能力，原生兼容鸿蒙 Skill工具链，在编译稳定性、缺陷修复效果与推理效率上综合表现突出；相较于通用大模型驱动的Agent，其更贴合鸿蒙开发的业务特征与工程规范，是鸿蒙应用开发场景下的最优选择。

受当前数据集规模、任务来源、自动化验证能力和执行成本限制，评测结果尚不能完全覆盖多设备协同、一次开发多端部署、自由流转、分布式能力调用、复杂业务合规与生产级性能优化等鸿蒙全场景开发能力。同时，LLM-as-Judge、功能点评分和动态测试等评估方式仍需通过更多真实项目样本和人工抽检持续校准。后续将进一步扩展评测数据规模，增强动态运行与UI验证能力，引入稳定性、成本效率和多轮修复等过程指标，以提升评测体系的全面性和可信度。
