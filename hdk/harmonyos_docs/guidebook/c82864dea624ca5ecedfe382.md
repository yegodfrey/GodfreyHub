# 开发环境和工具

## 4.4.1 API 工程管理

* 创建多设备工程模板

在创建应用/元服务工程时，Device types 字段可以选择应用需要的设备类型，DevEco Studio 会根据选中的设备类型去匹配对应的功能模块。

![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/23/v3/b2jAmpxgTxSzHIOFf4wDkw/zh-cn_image_0000002625112561.png?HW-CC-KV=V1&HW-CC-Date=20260909T151617Z&HW-CC-Expire=31536000000&HW-CC-Sign=C0BA1B52B017E77D5E4372A17002F07281DE38DF581A66E17B0B405644CEFB26 "点击放大")

* 添加一个支持多设备的模块

在添加模块时也可以在 Device types 字段选择模块需要的新增设备类型。

如果添加的是 entry 模块，DevEco Studio 会检测已有 entry 模块的设备类型，避免不同的 entry 模块之间，出现支持的设备类型重叠的情况。

后续如需修改模块的设备类型，可手动编辑模块下的 module.json5 文件，修改 deviceTypes 字段。如：entry/src/main/module.json5 文件。

```screen
{ 
  "module": { 
    "name": "entry", 
    "type": "entry", 
    "description": "$string:module_desc", 
    "mainElement": "EntryAbility", 
    "deviceTypes": [         // 定义模块支持的设备类型 
      "phone", 
      "tablet", 
      ...... 
    ], 
    ...... 
}
```

* 工程目录结构推荐

通过架构设计章节，我们推荐典型的多设备工程目录结构如下所示：

```screen
/application 
 ├── common                  # 公共能力目录 
 │   ├── utils               # 工具类目录：如网络、图片、文件管理工具等  
 │   ├── components          # 公共组件目录：如共用的弹窗、列表、详情页组件等 
 │   └── ...                  
 │ 
 ├── features                # 基础特性目录 
 │   ├── login               # 登录模块 
 │   ├── setting             # 设置模块 
 │   └── ...                  
 │ 
 └── products                # 产品定制目录 
     ├── phone               # 手机版本目录 
     ├── tablet              # 平板版本目录 
     ├── pc                  # PC版本目录 
     ├── default             # 默认设备泛类目录 
     └── ...
```

* 多设备下的资源文件管理

当需要针对不同设备定制对应的资源文件时，可以通过资源目录来管理。资源目录名中可包含描述设备类型、屏幕密度、语言、文字、国家或地区、横竖屏、颜色模式等限定词，应用在运行时，系统会根据限定词去匹配最合适的资源目录。

为了简化操作，DevEco Studio提供了新建资源目录，可视化选择限定词的功能。

![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/bd/v3/DniQ_MhaQ1G5BRhpZuqkNw/zh-cn_image_0000002594832972.png?HW-CC-KV=V1&HW-CC-Date=20260909T151617Z&HW-CC-Expire=31536000000&HW-CC-Sign=48C82A1791B16BB6CFC4A76B57C7BD04D16F761DDD94C7A0D05A0E6C83974559 "点击放大")

添加完成后的资源目录结构如下所示：

```screen
resources 
 |---base        // 默认的资源文件目录
 |   |---element 
 |   |   |---string.json 
 |   |---media 
 |   |   |---icon.png 
 |---zh_CN-vertical-tablet-ldpi      // 自定义限定词目录。示例：中文-竖屏-平板-高分辨率
 |   |---element 
 |   |   |---string.json 
 |   |---media 
 |   |   |---icon.png 
 |   |---profile 
 |   |   |---test_profile.json 
 |---rawfile                         // 弱文件类型
 |---resfile                         // 其他资源类型
```

**资源文件匹配规则**

应用使用某资源时，系统会根据当前设备状态优先从相匹配的限定词目录中寻找该资源。只有当resources目录中没有与设备状态匹配的限定词目录，或者在限定词目录中找不到该资源时，才会去base目录中查找。rawfile和resfile是原始文件目录，不会根据设备状态去匹配资源。

* 在为设备匹配对应的资源文件时，限定词目录匹配的优先级从高到低依次为：移动国家码和移动网络码 > 区域（可选组合：语言、语言_文字、语言_国家或地区、语言_文字_国家或地区）> 横竖屏 > 设备类型 > 颜色模式 > 屏幕密度。
* 如果限定词目录中包含移动国家码和移动网络码、语言、文字、横竖屏、设备类型、颜色模式限定词，则对应限定词的取值必须与当前的设备状态完全一致，该目录才能够参与设备的资源匹配。例如，限定词目录 zh_CN-car-ldpi 不能参与 en_US 设备的资源匹配。
* 如果存在多个屏幕密度限定词目录，则优先向上匹配最接近的屏幕密度限定词目录，否则向下匹配最为接近的屏幕密度限定词目录。例如，假设存在限定词目录 xldpi 和 xxldpi ，设备屏幕密度为xxldpi，则会匹配 xxldpi 限定词目录。

* API检测

检测设备特有API是否可用，以避免API被误用。

例如：在一个平板应用上调用NFC接口，编辑区会标红。此外，查看提示信息可以知道，平板设备不具备NFC的能力。

## 4.4.3 编译打包

* 多个设备类型共用一个HAP包

DevEco Studio中的每个entry模块都会被编译为一个HAP包。如果多个设备共用一个HAP包，只需要一个entry模块，修改entry模块的src/main/module.json5文件，在deviceTypes字段中添加应用支持的设备类型即可。

在编译产物build/default/outputs下可以查看编译出的HAP包所支持的设备类型。

![](https://contentcenter-vali-drcn.dbankcdn.cn/pvt_2/DeveloperAlliance_scene_100_1/02/v3/EiahdrOvRfiu2F7LQDB-lg/zh-cn_image_0000002625192419.png?HW-CC-KV=V1&HW-CC-Date=20260909T151617Z&HW-CC-Expire=31536000000&HW-CC-Sign=08DD3A1C4DB00BEF4DF99560E96DED85A97B00B1E7153B1DB0B1456651A5BAB3)

* 每个设备类型单独打HAP包

为达到多设备应用场景化最佳效果，可以考虑针对不同的设备类型定义独立的entry模块，并定制编译打包配置。

```screen
/application 
 ├── common                  # 公共特性目录 
 │ 
 ├── features                # 功能模块目录 
 │   ├── feature1            # 子功能 
 │   ├── feature2            # 子功能2 
 │   └── ...                 # 子功能n 
 │ 
 └── products                # 产品层目录 
     ├── phone               # 手机版本目录 
     ├── tablet              # 平板版本目录 
     ├── pc                  # PC版本目录 
     ├── default             # 默认设备泛类目录 
     └── ...
```

以推荐的工程目录为例，可以为每个设备类型定制编译文件。如打开products/phone/build-profile.json5文件，并修改如下参数：

```screen
{  
  "apiType": 'stageMode',  
  "buildOption": {  
  },  
  "targets": [  
    {  
      "name": "default",  
      "config": {  
        "deviceType": [  
          "phone"       // 定义HAP支持的设备类型 
        ]  
      },  
      "source": { 
        "abilities": [ 
          { 
            "name": "EntryAbility", 
            "icon":"$media:layered_image",          // 定义手机版本的icon图标 
            "label":"$string:EntryAbility_label",   // 定义手机版本的应用显示名称 
            "launchType": "singleton"               // 定义手机版本的启动模式为单实例模式 
          } 
        ] 
      } 
      "resource": {       //定义手机版本使用的资源文件目录  
        "directories": [  
          "./src/main/resources_default",  
          "./src/main/resources_phone"          // 使用手机专有的资源文件目录 
        ]  
      }  
    } 
  ]  
}
```

* APP打包配置

APP包为应用上架分发的产物，通常需要将不同设备类型的HAP打包到一起，以推荐的工程目录结构为例，打开根目录下的build-profile.json5文件，编译配置如下：

```screen
{ 
  "app": { 
    "signingConfigs": [], 
    "products": [ 
      { 
        "name": "default",      // 默认的APP包配置 
      } 
    ] 
  }, 
  "modules": [ 
    { 
      "name": "phone",          // 手机模块 
      "srcPath": "./products/phone", 
      "targets": [ 
        { 
          "name": "default", 
          "applyToProducts": [ 
            "default"           // 将手机HAP打包到默认APP中 
          ] 
        } 
      ] 
    }, 
    { 
      "name": "tablet",          // 平板模块 
      "srcPath": "./products/tablet", 
      "targets": [ 
        { 
          "name": "default", 
          "applyToProducts": [ 
            "default"           // 将平板HAP打包到默认APP中 
          ] 
        } 
      ] 
    }, 
    ... 
  ] 
}
```

支持添加多个APP配置，甚至可以为每个设备类型打包一个APP文件。

DevEco Studio 提供了一系列的调试工具，帮助开发者提升多设备开发效率，保障应用质量。

## 4.4.5 自测

DevEco Studio针对多设备静态编码检测、运行效果检测提供了两种检测工具：

* Code Linter编码检测

支持对应用/元服务的代码文件进行扫描、检测，对于违反多设备开发规范的代码进行告警。典型规范如颜色使用固定值、字体单位未使用fp等。

**检查方法：**在已打开的代码编辑器窗口单击右键点击Code Linter，对当前代码文件执行检查。或在工程管理窗口中鼠标选中单个或多个工程文件/目录，右键选择Code Linter > Full Linter执行代码全量检查。
