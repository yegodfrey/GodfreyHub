# 响应式设计方法

基于设备差异展现最佳体验设计一直是 HamronyOS 设计的核心初衷。不同设备场景下的响应式设计需要协调界面本身的自适应规则，并结合设备硬件屏幕展示空间的约束共同定义。横向与纵向断点的判断只是一种处理方式，应用自身需要避免硬编码的处理方式，减少硬编码带来的各种截断、操作不便、比例不协调问题。

当窗口容器大小发生变化时，界面元素需要自动变化以适应容器大小的变化。

根据使用场景，提供了以下 8 种不同的布局方法，在面向多端应用设计过程中不同的方法可以叠加使用。具体布局方法可参阅：[响应式布局方法](https://developer.huawei.com/consumer/cn/doc/design-guides/design-responsive-layout-method-0000001795698449)

自适应拉伸：某单个内容或某组内容的显示宽度不是固定值，而是通过相对参照物的方式来确定其显示宽度。当参照物的宽度发生变化时，内容或内容间距的宽度随之发生自适应拉伸。

![](https://media:801788430175867226)

均分拉伸: 容器组件尺寸发生变化时，增加或减小的空间均匀分配给容器组件内所有空白区域。

自适应拉伸适用于文字、普通按钮、间距等展示宽度灵活，对宽高比不敏感的内容和内容组合。

![](https://media:801788430175895227)

自适应缩放：子组件的宽或高按照预设的比例，随容器组件发生变化。

1. 等比缩放： 容器组件尺寸发生变化时，增加或减小的空间均匀分配给容器组件内所有空白区域。 ![](https://media:801788430175933228)

2. 占比缩放： 子组件的宽高按照预设的比例，随容器组件发生变化，且变化过程中子组件的宽高比不变。 自适应缩放适用于图片、圆形按钮、banner、反应真实物体形状的图像等必须保证宽高比的内容。

   ![](https://media:801788430175967229)

自适应延伸：组件的显示数量不是固定的，而是通过相对参照物的方式来确定其显示数量。当参照物的宽度发生变化时，组件随之发生自适应延伸显示更多数量。

1. 自适应延伸：容器组件内的子组件，按照其在容器中的先后顺序，随容器组件尺寸变化显示或隐藏。 ![](https://media:801788430176051230)

2. 自适应隐藏：容器组件内的子组件，按照其预设的显示优先级，随容器组件尺寸变化显示或隐藏。相同显示优先级的子组件同时显示或隐藏。

自适应延伸/隐藏适用于页签、操作块、推荐栏目等具有相同交互层级且有更多数据可以填充的内容。

需要判断因隐藏而不展示的内容对功能完整性是否有影响，并考虑通过滑动或"更多"按钮提供查看使用该内容的方式。

![](https://media:801788430176098231)

自适应折行：容器组件尺寸发生变化，当布局方向尺寸不足以显示完整内容时自动换行。

自适应折行适用于操作块、内容流等具有相同交互层级，且希望保证类型和数量完整性的内容。

![](https://media:801788430176220232)

缩进布局：为了在宽屏上内容显示有更好的效果，在不同宽度的设备上进行不同缩进效果。

缩进布局适用于纯段落文本/上图下段落文本/卡片的布局结构的场景，在其对应的栅格规格下，缩进的规则占用栅格数量进行布局。

![](https://media:801788430176525233 "点击放大")

挪移布局：利用屏幕的宽度优势，将原先的上下布局切换成左右布局。

挪移布局适用于横竖屏切换，以及类似的宽高比明显变化 (大于 200%) 同时希望保证内容完整的场景。例如上下布局的插画和文字，横屏后左右布局。

![](https://media:801788430177125234 "点击放大")

重复布局：利用屏幕的宽度优势，将相同属性的组件横向并列排布。

重复布局适用于对宽高比敏感的图片和及组合内容，当内容放大以后导致原图放大超过 150% 的场景。

![](https://media:801788430177373235 "点击放大")

分栏布局：利用屏幕的宽度优势，将有上下级层级的界面同时左右显示。

当同时满足水平 vp 大于等于 600，可以响应分栏布局。

![](https://media:801788430177756236 "点击放大")

以启动页为例，布局会在多个窗口尺寸、组合之间切换，首要条件是界面自身布局要定义一套展示规则，例如按照窗口尺寸拆分占比，并定义好对齐和展示规则。

![](https://media:801788430177817237 "点击放大")

接下来根据设备布局差异，在断点网格中匹配对应的响应式规则。上下结构的启动页使用一套布局进行适配，在极端的窗口比例下，可以选择隐藏部分元素或缩小所占比例来达到布局的平衡。

![](https://media:801788430177913238 "点击放大")

除此以外，ArkUI 组件也是基于全场景设备进行设计，通过对使用环境和设备差异性的考量，既保证了组件能力的统一性，又在不同设备的表现层面呈现了更加贴合设备本身的设计。在电脑产品上，ArkUI 重点优化了键鼠及触控板带来的体验交互差异，穿戴产品由于圆形手表形态的限制，为了更好的贴合硬件形态，提供了弧型差异组件，如 ArcButton、ArcList、ArcScrollBar 等。

多端适配的首要问题是界面布局发生变化时的响应规则，常规的界面操作类设备基本都是矩形屏幕，通过改变硬件设备的宽度和高度数据，结合内外开合的物理特性，实现了丰富多样的产品可玩性。在 HarmonyOS 产品阵营中，除了传统的竖屏手机、折叠屏、平板等类型外，我们迎来新成员------阔折叠。阔折叠的出现丰富了产品本身的功能性和趣味性，同时也带来了界面布局上的新挑战，例如：针对方形小外屏的界面适配，如何将 16:10 的手机布局调整到 1:1 的比例，又如何在更矮及更宽的内屏进行界面适配。

从内屏切换到外屏时，除展示功能区域变小外，还需要做很多增量的组件层、功能层的调整。保证外屏的文本、图标、布局信息结构均与内屏保持一致。由于小屏空间极其有限，可以考虑隐藏信号栏、导航条等区域，来确保可用空间最大化。

在组件能力上，ArkUI 也提供了针对较小场景的组件样式以供选择，例如标题栏选择使用单行的样式，搜索框组件隐藏到标题栏按钮中，索引条组件使用缩略模式，弹出框组件需要按照比例生效最大高度和高度等等。同时，也可以考虑在滑动界面的过程中对部分组件进行滑动隐藏操作，Tabs 及 Navigation 组件均支持滑动隐藏属性接口，可通过配置 bindTabsToScrollable 触发滑动事件对组件的反馈。

一多布局的适配随着业务界面复杂度不同，在处理方式上也有差异化，但无论如何，随着万物互联时代的加速到来，多设备协同已成为用户体验升级的核心方向，也是设计系统长期发展的体验目标。HarmonyOS 设计系统也将持续在系统设计、跨设备规范文档、组件能力等多维度持续演进并提供支撑多设备应用开发。
