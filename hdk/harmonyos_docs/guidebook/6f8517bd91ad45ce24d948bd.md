# 安卓UI组件迁移

一、概览

![](https://media:801788430175682224)

UI界面迁移智能体的目的是将安卓应用的UI界面迁移至鸿蒙并保持高一致性。当前开发者在安卓鸿蒙化迁移场景上主要有两种UI诉求：一、应用还未有鸿蒙版本，需要进行从0到1进行全量开发，用户诉求是一次性批量转换尽可能多的UI界面；二、应用已有鸿蒙版本，但未对齐安卓版本，需要进行从N到N+1的增量开发，用户诉求是在现有代码基础上一次性转好用户指定的页面。针对上述两个场景，我们设计并实现了UI全量迁移智能体和UI增量开发智能体。

UI全量迁移智能体：输入安卓可运行apk以及源码，输出可编译运行的鸿蒙应用，预期包含全量UI界面。

UI增量开发智能体：输入安卓可运行apk以及源码、鸿蒙现有代码、以及用户增量UI需求（例如指定xx页面），输出可编译运行的鸿蒙应用，预期包含用户指定的增量页面。

二、技术方案

![](https://media:801788430175717225 "点击放大")

UI全量迁移智能体主要包含全量页面抓取、资源迁移、UI界面迁移这3个步骤，其具体技术实现如下：

1）全量页面抓取：全量页面抓取的目的是自动分析App中有多少个用户可视页面，并尽可能将所有页面的截图和组件树信息抓取下来作为后续步骤输入。全量页面抓取脚本通过 ADB 连接设备，自动逐层点击目标 App中的所有可交互元素，发现并记录每一个可达页面。核心思路是：每次点击后先快速获取页面结构判断是否为新页面，已访问过的直接跳过；通过对页面中可点击元素集合做哈希来识别同一个页面，实现精准去重。最终输出每个页面的截图、组件树、元数据 ，以及汇总的 HTML 可视化报告。

2）资源迁移：资源迁移的目的是提前将安卓应用内所有资源批量转换到鸿蒙可用的格式，以加速后续的UI转换过程。资源迁移Skill支持字符串、颜色、尺寸、图片、矢量图、形状drawable、自适应图标等资源的迁移，并自动处理不同屏幕密度、语言区域、夜间模式等配置变体。它采用优先构建反编译的策略获取最完整的资源集（包含第三方库资源），无apk时也可以基于源码目录转换。资源转换过程中通过格式转换（XML转JSON、矢量图转SVG）、限定符映射、依赖引用解析，将安卓系统资源和跨资源引用解析为具体值，对缺失的库资源自动填充默认值。最终输出转换后资源、转换报告和资源映射文档。

3）UI界面迁移：UI界面迁移步骤基于前两个阶段的产出及安卓源码生成ArkUI代码。首先，从用户请求中解析安卓项目路径、鸿蒙项目路径和页面快照根目录，每个快照目录包含UI界面的元数据、组件树和界面截图。Agent针对目录下所有待转换页面，为每个页面创建Task并调用独立子Agent执行转换。子Agent读取Skill自带的mappings映射规则（安卓控件到ArkUI组件映射）和MVVM架构文档，将安卓UI代码转换为遵循MVVM的ArkTS页面代码。转换完成后统一调用编译修复工具修复整个项目的编译错误，最后输出包含成功/失败统计、各页面输出文件路径和待人工处理TODO项的汇总报告。

UI增量开发智能体主要包含指定界面抓取、UI界面对齐两个主要步骤。其具体技术实现如下：

1）指定UI界面抓取：与全量界面迁移智能体不同，增量智能体只需要抓取用户需要对齐的UI界面。技术方案采用三阶段流水线：首先解析用户输入的自然语言需求来确认页面抓取计划，确定基础页面的导航路径；然后通过大模型执行自动化导航，成功后抓取组件树和截图；最后扫描已捕获页面的视图树，识别所有会改变UI状态的交互元素，为每个交互状态创建独立捕获任务，确保完整覆盖页面的所有UI子组件。整个过程自动处理导航失败重试、应用重启等异常情况，为后续对齐提供完整的双端UI数据基础。

2）UI界面对齐：该阶段能够深度对比安卓与鸿蒙页面的UI差异，自动生成修复清单并逐项修正ArkTS代码，实现像素级对齐或补全缺失页面。技术方案包含四个核心环节：首先基于前一阶段抓取的截图和组件树生成结构化的UI界面分析文档，详细记录每个组件的位置、尺寸、颜色、文字、对齐方式等视觉属性。其次以安卓界面为基准进行逐组件对比，生成包含差异详情的UI对比表格。接着，分析鸿蒙项目架构与MVVM模式，按照典型的UI差异处理模式，逐一修正所有差异项。最后会通过项目构建工具通过并确保清单所有项已完成，实现从分析到修复的闭环自动化流程。
