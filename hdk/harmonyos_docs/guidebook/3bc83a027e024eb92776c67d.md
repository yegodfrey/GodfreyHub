# 业务逻辑开发

优秀的应用用户体验包含合理且美观的界面布局，和针对不同设备进行精心设计的场景化功能。为了方便开发者对多设备的差异性进行感知和功能实现，HarmonyOS 开放能力定义了系统能力的最小单位：SystemCapability。不同的设备支持的 SystemCapability 集不同，开发者可以根据 SystemCapability 判断当前系统是否支持该开放能力，从而做好代码逻辑控制，避免功能异常导致用户侧不可用。  

#### 4.3.1 API跨设备兼容性介绍

HarmonyOS 支持在手机、平板、PC、穿戴、座舱等不同品类设备上运行，这些设备在硬件、器件、系统能力上存在差异，因此，在不同品类上支持的开放能力API也会存在差异。

由于HarmonyOS SDK 是统一版本，包含了所有的 API 声明，如果应用调用的 API 在某个品类上不支持，而应用又未做好代码保护，则应用运行在这个设备上时会出现崩溃或功能不可用等异常问题，影响用户体验。

如下表格所示，若没有统一的策略处理不同设备品类间 API 的差异，应用使用了拨打电话的 API，在 PC 和座舱等不支持电话服务的设备品类上，会出现运行异常。  

|设备品类|电话服务|蓝牙|打印|心率传感器|陀螺仪|
|:---|:---|:-|:-|:----|:--|
|手机|是|是|否|否|是|
|PC|否|是|是|否|是|
|手表|是|是|否|是|是|
|座舱|否|是|否|否|是|
|智慧屏|否|是|否|否|否|

除此之外，由于设备能力的差异，同一个 API 在不同的设备品类上会出现行为不一致的情况。例如，在PC场景下，PC应用最小化的时候，UIAbility不会进入后台生命周期。再列举一个子窗口的例子，在PC或者平板自由多窗模式下，子窗可以独立拖拽到父窗口外，但在手机的智慧多窗模式下不支持此行为；在自由多窗下，允许应用最大化自身（例如浏览器点击视频全屏按钮），但是在手机的智慧多窗下不支持此功能。

为了解决以上两类多设备兼容的问题，HarmonyOS 在开发、编译、上架等多个阶段提供了以下能力：

1. 在开发态，IDE 可对应用使用的 API 以及应用需要分发安装的设备进行检查，若应用使用了设备不支持的 API，应提示开发者进行防护处理。
2. 在应用分发时，检查该应用使用的 API 是否在目标设备上都支持。
3. API 在不支持的设备品类上运行场景，应在文档中明确告知会存在多设备行为差异，便于开发者对此类问题进行防护。
4. 系统应提供主动查询的方式，帮助开发者查看 API 在当前设备上是否支持。  

#### 4.3.2 API SysCap机制

定义

SysCap 是 SystemCapability 的缩写，中文定义为"系统能力"，指操作系统中一个相对独立的特性。从应用的角度，SysCap 决定了应用开发者可以使用的 API 范围；从硬件设备看，SysCap 描述了一款HarmonyOS 设备具备的能力。SysCap 定义格式采用如下格式：

SystemCapability.特性\[.子特性\]

其中，特性、子特性与系统类型使用大驼峰的命名方式，如 SystemCapability.Media.Camera。

API 与 SysCap 的关系

SysCap的用途：

1.首要职责：隔离不同设备类型之间的开放能力差异。

以蓝牙为例，不同设备类型对蓝牙的支持情况有所不同，为便于开发者判断相关API是否可用，引入了SysCap机制。

开发者可通过[canIUse](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/js-apis-syscap#caniuse)接口，判断指定SysCap所代表的开放能力API集合是否支持在目标设备类型上调用。

2.次要职责：进行特性归类。

每个SysCap所代表的开放能力API集合，对应操作系统中一个独立的功能特性。例如上述蓝牙SysCap标识的API集合，逻辑上均属于"蓝牙核心通信能力"。

SysCap与SDK、Kit形成结构化、层级化结构，如下图所示：

![](https://media:801788430180879289 "点击放大")

1.SDK由多个功能独立的Kit组成；

2.每个Kit包含一个或多个SysCap，且每个SysCap仅属于一个 Kit；

3.每个SysCap标识/代表了一个或多个API接口。

这一结构化设计，使得开发者在编写代码时，可通过开发工具（如 DevEco Studio）的智能提示与自动联想，精准、高效地定位和调用所需接口，显著降低误用风险，提升开发效率。  

#### 4.3.3 API CanIUse介绍

CanIUse 是 HarmonyOS SDK 提供的用于在运行时对 API 跨设备兼容性的查询手段，开发者在编码阶段调用API前使用 CanIUse 进行防护，避免用户使用应用过程中出现崩溃或不可用问题。

declare canIUse(sysCap: string): boolean;

CanIUse 是全局可用的工具函数，不需要 import 即可使用。对于存在跨设备兼容性的API， 在调用时，开发者需要先通过 CanIUse 来查询当前设备是否支持此 API，并对不支持的场景进行补充处理。

参考下面案例，地理位置功能并非在所有设备上均支持，开发者可基于CanIUse进行是否支持该能力的两种功能实现，为用户提供合理的应用功能。

```
import geolocation from '@ohos.geolocation'; 
 
const isLocationAvailable: boolean = canIUse('SystemCapability.Location.Location'); 
if (isLocationAvailable) { 
  geolocation.getCurrentLocation((location: Location) => { 
    // 处理地理位置业务 
  }); 
} else { 
  // 对不支持地理位置获取设备的补充处理 
}
```

应用开发可分为：

1.单设备应用开发：指应用工程的Device type只配置1个设备类型。

2.多设备应用开发：指应用工程的Device type配置多个设备类型。

多设备应用开发时，DevEco Studio需同时识别多种设备类型，适配开发过程如下图所示：

![](https://media:801788430180910290 "点击放大")

1. 使用canIUse判断并集内交集外的SysCap集合是否可用。 canIUse仅适用于多设备应用开发，单设备应用开发可直接进行接口能力查询。

   多设备应用开发场景下，当SysCap所属设备类型处于deviceTypes选择范围与API支持范围的并集但不在其交集内时（如设备类型选Phone/Tablet，而API仅支持Phone/2in1），必须通过canIUse进行可用性校验。
2. 如果API在同一设备类型下的不同设备型号存在能力不一致的情况，需使用能力查询接口判断接口能力可用性（注意：此处的能力查询机制并非canIUse）；使用系统侧的isXXXSupported()等接口判断API是否可用，如下所示：

   ```
   import { geoLocationManager } from '@kit.LocationKit';
   if (!canIUse("SystemCapability.Location.Location.Core")) { // 首先对能力集进行可用性判断，该步骤仅适用于多设备应用开发，单设备应用开发可忽略该步骤。
     return;
   }
   try {
     if (geoLocationManager.isPoiServiceSupported()) { // 然后进行POI服务能力的查询
       geoLocationManager.getPoiInfo().then((poiInfo) => { // 判断能力支持后，进行位置信息的获取接口调用
         if (poiInfo !== undefined) {
           console.info("get PoiInfo:" + JSON.stringify(poiInfo));
         }
       })
     }
   } catch (error) {
     console.error("getPoiInfo errCode:" + error.code + ", errMessage:" + error.message);
   }
   ```

   在硬件动态扩展场景中，部分硬件插拔会导致能力变化，开发者可以主动监听扩展能力变化。

   例如：对于USB类型的Camera，存在动态插拔的场景，系统侧提供了on的监听接口，支持开发者处理摄像头设备的动态变化。

   ```
   import { BusinessError } from '@kit.BasicServicesKit';
   import { camera } from '@kit.CameraKit';
   callback(err: BusinessError, cameraStatusInfo: camera.CameraStatusInfo): void {
     if (err !== undefined && err.code !== 0) {
       console.error('cameraStatus with errorCode = ' + err.code);
       return;
     }
     console.info(`camera : ${cameraStatusInfo.camera.cameraId}, status: ${cameraStatusInfo.status}`);
   }
   registerCameraStatus(cameraManager: camera.CameraManager): void {
     cameraManager.on('cameraStatus', this.callback); // 开发者通过监听Camera的状态，处理动态硬件设备
   }
   ```

   3. 为了避免调用接口出现的异常情况，进行错误码异常处理。

   ```
   import { omapi } from '@kit.ConnectivityKit';
   import { hilog } from '@kit.PerformanceAnalysisKit';
   let seService : omapi.SEService;
   let seReaders : omapi.Reader[];
   // 在使用seService之前，需要对seService进行初始化
   function secureElementDemo() {
     // 获取readers
     try {
       seReaders = seService.getReaders();
     } catch (error) {
       if(error.code=== 801) {
         console.error('This device does not support this capability');
       }
     }
   }
   ```
