# 鸿蒙基准数据集

在开发验证场景下，进一步抽象出若干典型开发任务类型，并针对不同任务形态构建专项评测数据集。具体包括：新需求代码生成、增量需求代码生成和缺陷修复三类核心开发任务。其中，新需求代码生成主要评估模型从零实现鸿蒙应用功能的能力；增量需求代码生成主要评估模型在已有工程基础上进行跨层功能扩展、UI功能补充、Kit 或三方 SDK 集成等能力；缺陷修复则重点评估模型基于现象描述、崩溃日志或失败测试定位并修复问题的能力。

下表展示了鸿蒙开发验证场景下的关键任务分类、子场景划分及对应评测数据集：

|--------|-------------------------------------------------------------------------------|-----------------------------------|
|**一级场景**|**二级场景**|**评测数据集**|
|全新特性代码生成|A-1 短任务App（单功能/单页） A-2 长任务App（多功能/全栈） A-3 鸿蒙特有能力 App|文件级：FileBench-Ark|
|增量特性代码生成|B-1 全栈跨层功能实现 B-2 UI独立功能实现 B-3 HarmonyOS Kit集成 B-4 三方SDK集成 B-5 功能参数扩展 B-6 场景覆盖扩展|仓库级： FEABench-Ark、FEABench-Ark（SDD）|
|缺陷修复|C-1 仅现象描述 C-2 现象 + 崩溃日志 C-3 现象 + 失败测试|仓库级：Swebench-Ark|

**全新特性代码生成**

**FileBench-Ark**是鸿蒙文件级评测集，包含 100 道文件级鸿蒙ArkTS代码生成任务，覆盖算法与数据结构、字符串处理、数学计算、日期时间、游戏开发、图像处理、UI组件、实用工具及 3D 图形九大类任务场景。其中算法与数据结构类题目占比最高，达 37%，数据集兼顾通用编程基础问题与鸿蒙生态特有的界面交互、图形渲染、设备工具类开发需求，能够从基础代码逻辑、生态适配能力、工程实用性等多维度综合评估Coding Agent在鸿蒙平台下完成完整文件级代码开发的生成质量与任务交付能力。

**增量特性代码生成**

**FEABench-Ark** 是一个面向鸿蒙ArkTS工程级增量代码生成的专用评测集。该评测集基于真实开源项目的工程开发实践与持续集成提交记录PR构建，聚焦近一年内鸿蒙生态应用新增的业务特性与功能迭代需求，通过严格的人工筛选与标准化流程形成高质量评测基准。

在构建流程上，FEABench-Ark 从海量真实项目提交中筛选具备代表性的增量开发需求，筛选规则严格限定为：需求描述清晰明确、功能边界完整、单次修改文件数量不超过 10 个，确保任务既符合真实开发习惯，又能精准衡量大模型代码智能体（Coding Agent）在工程化上下文理解、多文件协同修改、代码规范对齐与增量开发能力。为保证评测的客观性与可复现性，所有任务均采用 Hypium 自动化 UX 测试框架构建测试用例，生成能够模拟人类用户交互行为（如点击、输入、滑动、组件校验等）的自动化测试脚本，实现对功能完整性、UI渲染效果与交互逻辑的统一量化评估。

**FEABench-Ark（SDD）**，是FEABench-Ark的规格驱动开发（Specification-Driven Development）评测子集，当前共包含 50 个 Spec、190 个功能点测试用例。不同于以自然语言需求到代码片段、单文件实现或简单页面生成为主的传统代码生成评测，FEABench-Ark（SDD）以结构化、可执行导向的功能 Spec 作为输入，要求模型在已有 HarmonyOS 工程基础上完成增量开发，并最终交付可构建、可运行、可验证的 HAP 包。

***示例任务***

*在首页文本类组件下方第一个位置，添加文本(Text)组件。首页组件列表为数据驱动渲染，需在数据源和代码配置中同时添加文本组件条目。新增的文本组件应参照项目中已有组件（如TextInput）的目录结构和代码模式来实现，包含预览区域和调整区域，预览区域默认显示"开发者你好"，调整区域包括字重、字号、文字阴影、字间距。*

*该任务全面覆盖工程结构理解、多文件修改、组件化开发、UI配置与鸿蒙生态编码规范，可有效评估Coding Agent在真实工程增量开发场景下的综合代码生成与交付能力。*

**缺陷修复场景**

**SWEBench-Ark** 是一款面向鸿蒙ArkTS工程化代码修复任务的专用评测集，整体构建思路参考经典评测基准 SweBench，聚焦真实开发场景下的缺陷修复与问题排查能力。该评测集当前共包含 71 道高质量代码修复任务，所有任务均源自鸿蒙生态真实开源项目的修复类 Pull Request（PR），具备高度的工程真实性与实用价值。

在构建与筛选机制上，Swebench-Ark 严格遵循真实工程修复流程：从海量项目提交记录中筛选缺陷修复、功能恢复、稳定性优化类 PR，核心筛选规则限定为任务需求明确、缺陷现象可复现、单次修改文件数量小于 10 个，确保任务既能有效评估Coding Agent的故障定位、代码理解与问题修复能力，又符合轻量化、可量化的评测标准。为保障评测结果的客观性、公正性与可复现性，所有任务均采用 Hypium 自动化 UX 测试框架构建标准化测试用例，通过脚本模拟人类用户的点击、输入、界面跳转、组件校验等真实交互行为，对功能完整性、UI渲染效果及交互逻辑进行自动化验证；所有测试用例均满足缺陷修复前执行失败、修复完成后执行成功的严格标准，实现对代码修复效果的统一量化评估。

***示例任务***

*Penkit 功能闪退修复，任务描述为当前应用工程在启动时点击体验Penkit 功能按钮时，应用直接发生闪退，无法正常进入对应功能模块。*

*该任务需要在理解工程结构与代码逻辑的基础上完成精准修复，使应用启动 Penkit 功能时不再闪退并正常运行。该任务可有效评估Coding Agent在真实工程中的故障定位、代码调试与缺陷修复能力。*
