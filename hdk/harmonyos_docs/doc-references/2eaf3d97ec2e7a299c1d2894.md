An asynchronous channel for stream-oriented connecting sockets.  Asynchronous socket channels are created in one of two ways. A newly-created AsynchronousSocketChannel is created by invoking one of the [open](https://developer.harmonyos.com/cn/docs/documentation/doc-references/asynchronoussocketchannel-0000001054119819#ZH-CN_TOPIC_0000001054119819__open-java_nio_channels_AsynchronousChannelGroup-) methods defined by this class. A newly-created channel is open but not yet connected. A connected AsynchronousSocketChannel is created when a connection is made to the socket of an [AsynchronousServerSocketChannel](https://developer.harmonyos.com/cn/docs/documentation/doc-references/asynchronousserversocketchannel-0000001054358478). It is not possible to create an asynchronous socket channel for an arbitrary, pre-existing [socket](https://developer.harmonyos.com/cn/docs/documentation/doc-references/socket-0000001054678480).  A newly-created channel is connected by invoking its [connect](https://developer.harmonyos.com/cn/docs/documentation/doc-references/asynchronoussocketchannel-0000001054119819#ZH-CN_TOPIC_0000001054119819__connect-java_net_SocketAddress-A-java_nio_channels_CompletionHandler-) method; once connected, a channel remains connected until it is closed. Whether or not a socket channel is connected may be determined by invoking its [getRemoteAddress](https://developer.harmonyos.com/cn/docs/documentation/doc-references/asynchronoussocketchannel-0000001054119819#ZH-CN_TOPIC_0000001054119819__getRemoteAddress--) method. An attempt to invoke an I/O operation upon an unconnected channel will cause a [NotYetConnectedException](https://developer.harmonyos.com/cn/docs/documentation/doc-references/notyetconnectedexception-0000001054838450) to be thrown.  Channels of this type are safe for use by multiple concurrent threads. They support concurrent reading and writing, though at most one read operation and one write operation can be outstanding at any time. If a thread initiates a read operation before a previous read operation has completed then a [ReadPendingException](https://developer.harmonyos.com/cn/docs/documentation/doc-references/readpendingexception-0000001054119825) will be thrown. Similarly, an attempt to initiate a write operation before a previous write has completed will throw a [WritePendingException](https://developer.harmonyos.com/cn/docs/documentation/doc-references/writependingexception-0000001054518510).  Socket options are configured using the [setOption](https://developer.harmonyos.com/cn/docs/documentation/doc-references/asynchronoussocketchannel-0000001054119819#ZH-CN_TOPIC_0000001054119819__setOption-java_net_SocketOption-T-) method. Asynchronous socket channels support the following options:  Additional (implementation specific) options may also be supported. **Timeouts** The [read](https://developer.harmonyos.com/cn/docs/documentation/doc-references/asynchronoussocketchannel-0000001054119819#ZH-CN_TOPIC_0000001054119819__read-java_nio_ByteBuffer-long-java_util_concurrent_TimeUnit-A-java_nio_channels_CompletionHandler-) and [write](https://developer.harmonyos.com/cn/docs/documentation/doc-references/asynchronoussocketchannel-0000001054119819#ZH-CN_TOPIC_0000001054119819__write-java_nio_ByteBuffer-long-java_util_concurrent_TimeUnit-A-java_nio_channels_CompletionHandler-) methods defined by this class allow a timeout to be specified when initiating a read or write operation. If the timeout elapses before an operation completes then the operation completes with the exception [InterruptedByTimeoutException](https://developer.harmonyos.com/cn/docs/documentation/doc-references/interruptedbytimeoutexception-0000001054678496). A timeout may leave the channel, or the underlying connection, in an inconsistent state. Where the implementation cannot guarantee that bytes have not been read from the channel then it puts the channel into an implementation specific error state. A subsequent attempt to initiate a read operation causes an unspecified runtime exception to be thrown. Similarly if a write operation times out and the implementation cannot guarantee bytes have not been written to the channel then further attempts to write to the channel cause an unspecified runtime exception to be thrown. When a timeout elapses then the state of the [ByteBuffer](https://developer.harmonyos.com/cn/docs/documentation/doc-references/bytebuffer-0000001054439771), or the sequence of buffers, for the I/O operation is not defined. Buffers should be discarded or at least care must be taken to ensure that the buffers are not accessed while the channel remains open. All methods that accept timeout parameters treat values less than or equal to zero to mean that the I/O operation does not timeout. **Since:** 1.7Constructor Summary Modifier | Constructor | Description

This method initiates an asynchronous read operation to read a sequence of bytes from this channel into the given buffer. The handler parameter is a completion handler that is invoked when the read operation completes (or fails). If a timeout is specified and the timeout elapses before the operation completes then the operation completes with the exception [InterruptedByTimeoutException](https://developer.harmonyos.com/cn/docs/documentation/doc-references/interruptedbytimeoutexception-0000001054678496).
