# CountDownLatch

[java.lang.Object](https://developer.harmonyos.com/cn/docs/documentation/doc-references/object-0000001054678446) |---java.util.concurrent.CountDownLatch
    
    public class CountDownLatch
    extends [Object](https://developer.harmonyos.com/cn/docs/documentation/doc-references/object-0000001054678446)

A synchronization aid that allows one or more threads to wait until a set of operations being performed in other threads completes. 

A CountDownLatch is initialized with a given count. The [await](https://developer.harmonyos.com/cn/docs/documentation/doc-references/countdownlatch-0000001054358591#ZH-CN_TOPIC_0000001054358591__await--) methods block until the current count reaches zero due to invocations of the [countDown()](https://developer.harmonyos.com/cn/docs/documentation/doc-references/countdownlatch-0000001054358591#ZH-CN_TOPIC_0000001054358591__countDown--) method, after which all waiting threads are released and any subsequent invocations of [await](https://developer.harmonyos.com/cn/docs/documentation/doc-references/countdownlatch-0000001054358591#ZH-CN_TOPIC_0000001054358591__await--) return immediately. This is a one-shot phenomenon -- the count cannot be reset. If you need a version that resets the count, consider using a [CyclicBarrier](https://developer.harmonyos.com/cn/docs/documentation/doc-references/cyclicbarrier-0000001054238611). 

A CountDownLatch is a versatile synchronization tool and can be used for a number of purposes. A CountDownLatch initialized with a count of one serves as a simple on/off latch, or gate: all threads invoking [await](https://developer.harmonyos.com/cn/docs/documentation/doc-references/countdownlatch-0000001054358591#ZH-CN_TOPIC_0000001054358591__await--) wait at the gate until it is opened by a thread invoking [countDown()](https://developer.harmonyos.com/cn/docs/documentation/doc-references/countdownlatch-0000001054358591#ZH-CN_TOPIC_0000001054358591__countDown--). A CountDownLatch initialized to N can be used to make one thread wait until N threads have completed some action, or some action has been completed N times. 

A useful property of a CountDownLatch is that it doesn't require that threads calling countDown wait for the count to reach zero before proceeding, it simply prevents any thread from proceeding past an [await](https://developer.harmonyos.com/cn/docs/documentation/doc-references/countdownlatch-0000001054358591#ZH-CN_TOPIC_0000001054358591__await--) until all threads could pass. 

**Sample usage:** Here is a pair of classes in which a group of worker threads use two countdown latches: 

    * The first is a start signal that prevents any worker from proceeding until the driver is ready for them to proceed; 
    * The second is a completion signal that allows the driver to wait until all workers have completed. 
    
    class Driver { // ...
       void main() throws InterruptedException {
         CountDownLatch startSignal = new CountDownLatch(1);
         CountDownLatch doneSignal = new CountDownLatch(N);
    
         for (int i = 0; i < N; ++i) // create and start threads
           new Thread(new Worker(startSignal, doneSignal)).start();
    
         doSomethingElse();            // don't let run yet
         startSignal.countDown();      // let all threads proceed
         doSomethingElse();
         doneSignal.await();           // wait for all to finish
       }
     }
    
     class Worker implements Runnable {
       private final CountDownLatch startSignal;
       private final CountDownLatch doneSignal;
       Worker(CountDownLatch startSignal, CountDownLatch doneSignal) {
         this.startSignal = startSignal;
         this.doneSignal = doneSignal;
       }
       public void run() {
         try {
           startSignal.await();
           doWork();
           doneSignal.countDown();
         } catch (InterruptedException ex) {} // return;
       }
    
       void doWork() { ... }
     }

Another typical usage would be to divide a problem into N parts, describe each part with a Runnable that executes that portion and counts down on the latch, and queue all the Runnables to an Executor. When all sub-parts are complete, the coordinating thread will be able to pass through await. (When threads must repeatedly count down in this way, instead use a [CyclicBarrier](https://developer.harmonyos.com/cn/docs/documentation/doc-references/cyclicbarrier-0000001054238611).) 
    
    class Driver2 { // ...
       void main() throws InterruptedException {
         CountDownLatch doneSignal = new CountDownLatch(N);
         Executor e = ...
    
         for (int i = 0; i < N; ++i) // create and start threads
           e.execute(new WorkerRunnable(doneSignal, i));
    
         doneSignal.await();           // wait for all to finish
       }
     }
    
     class WorkerRunnable implements Runnable {
       private final CountDownLatch doneSignal;
       private final int i;
       WorkerRunnable(CountDownLatch doneSignal, int i) {
         this.doneSignal = doneSignal;
         this.i = i;
       }
       public void run() {
         try {
           doWork(i);
           doneSignal.countDown();
         } catch (InterruptedException ex) {} // return;
       }
    
       void doWork() { ... }
     }

Memory consistency effects: Until the count reaches zero, actions in a thread prior to calling countDown() [_happen-before_](https://developer.harmonyos.com/cn/docs/documentation/doc-references/overview-0000001054558607#ZH-CN_TOPIC_0000001054558607__MemoryVisibility) actions following a successful return from a corresponding await() in another thread.

#### [h2]await

public void await​() throws [InterruptedException](https://developer.harmonyos.com/cn/docs/documentation/doc-references/interruptedexception-0000001054678421)

Causes the current thread to wait until the latch has counted down to zero, unless the thread is [Thread#interrupt](https://developer.harmonyos.com/cn/docs/documentation/doc-references/thread-0000001054238447#ZH-CN_TOPIC_0000001054238447__interrupt--). 

If the current count is zero then this method returns immediately. 

If the current count is greater than zero then the current thread becomes disabled for thread scheduling purposes and lies dormant until one of two things happen: 

    * The count reaches zero due to invocations of the [countDown()](https://developer.harmonyos.com/cn/docs/documentation/doc-references/countdownlatch-0000001054358591#ZH-CN_TOPIC_0000001054358591__countDown--) method; or 
    * Some other thread [Thread#interrupt](https://developer.harmonyos.com/cn/docs/documentation/doc-references/thread-0000001054238447#ZH-CN_TOPIC_0000001054238447__interrupt--) the current thread. 

If the current thread: 

    * has its interrupted status set on entry to this method; or 
    * is [Thread#interrupt](https://developer.harmonyos.com/cn/docs/documentation/doc-references/thread-0000001054238447#ZH-CN_TOPIC_0000001054238447__interrupt--) while waiting, 
then [InterruptedException](https://developer.harmonyos.com/cn/docs/documentation/doc-references/interruptedexception-0000001054678421) is thrown and the current thread's interrupted status is cleared.

#### [h2]await

public boolean await​(long timeout, [TimeUnit](https://developer.harmonyos.com/cn/docs/documentation/doc-references/timeunit-0000001054838570) unit) throws [InterruptedException](https://developer.harmonyos.com/cn/docs/documentation/doc-references/interruptedexception-0000001054678421)

Causes the current thread to wait until the latch has counted down to zero, unless the thread is [Thread#interrupt](https://developer.harmonyos.com/cn/docs/documentation/doc-references/thread-0000001054238447#ZH-CN_TOPIC_0000001054238447__interrupt--), or the specified waiting time elapses. 

If the current count is zero then this method returns immediately with the value true. 

If the current count is greater than zero then the current thread becomes disabled for thread scheduling purposes and lies dormant until one of three things happen: 

    * The count reaches zero due to invocations of the [countDown()](https://developer.harmonyos.com/cn/docs/documentation/doc-references/countdownlatch-0000001054358591#ZH-CN_TOPIC_0000001054358591__countDown--) method; or 
    * Some other thread [Thread#interrupt](https://developer.harmonyos.com/cn/docs/documentation/doc-references/thread-0000001054238447#ZH-CN_TOPIC_0000001054238447__interrupt--) the current thread; or 
    * The specified waiting time elapses. 

If the count reaches zero then the method returns with the value true. 

If the current thread: 

    * has its interrupted status set on entry to this method; or 
    * is [Thread#interrupt](https://developer.harmonyos.com/cn/docs/documentation/doc-references/thread-0000001054238447#ZH-CN_TOPIC_0000001054238447__interrupt--) while waiting, 
then [InterruptedException](https://developer.harmonyos.com/cn/docs/documentation/doc-references/interruptedexception-0000001054678421) is thrown and the current thread's interrupted status is cleared. 

If the specified waiting time elapses then the value false is returned. If the time is less than or equal to zero, the method will not wait at all.

#### [h2]countDown

public void countDown​()

Decrements the count of the latch, releasing all waiting threads if the count reaches zero. 

If the current count is greater than zero then it is decremented. If the new count is zero then all waiting threads are re-enabled for thread scheduling purposes. 

If the current count equals zero then nothing happens.
