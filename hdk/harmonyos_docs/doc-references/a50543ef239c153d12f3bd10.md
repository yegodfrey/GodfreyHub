# CopyOnWriteArraySet

[java.lang.Object](https://developer.harmonyos.com/cn/docs/documentation/doc-references/object-0000001054678446) |---[java.util.AbstractCollection](https://developer.harmonyos.com/cn/docs/documentation/doc-references/abstractcollection-0000001054358576)<E> |---|---[java.util.AbstractSet](https://developer.harmonyos.com/cn/docs/documentation/doc-references/abstractset-0000001054358569)<E> |---|---|---java.util.concurrent.CopyOnWriteArraySet<E>

    extends [AbstractSet](https://developer.harmonyos.com/cn/docs/documentation/doc-references/abstractset-0000001054358569)<E>
    implements [Serializable](https://developer.harmonyos.com/cn/docs/documentation/doc-references/serializable-0000001054358416)

A [Set](https://developer.harmonyos.com/cn/docs/documentation/doc-references/set-0000001054439873) that uses an internal [CopyOnWriteArrayList](https://developer.harmonyos.com/cn/docs/documentation/doc-references/copyonwritearraylist-0000001054518624) for all of its operations. Thus, it shares the same basic properties: 
    * It is best suited for applications in which set sizes generally stay small, read-only operations vastly outnumber mutative operations, and you need to prevent interference among threads during traversal. 
    * It is thread-safe. 
    * Mutative operations (add, set, remove, etc.) are expensive since they usually entail copying the entire underlying array. 
    * Iterators do not support the mutative remove operation. 
    * Traversal via iterators is fast and cannot encounter interference from other threads. Iterators rely on unchanging snapshots of the array at the time the iterators were constructed. 

**Sample Usage.** The following code sketch uses a copy-on-write set to maintain a set of Handler objects that perform some action upon state updates. 
    
    class Handler { void handle(); ... }
    
     class X {
       private final CopyOnWriteArraySet<Handler> handlers
         = new CopyOnWriteArraySet<Handler>();
       public void addHandler(Handler h) { handlers.add(h); }
    
       private long internalState;
       private synchronized void changeState() { internalState = ...; }
    
       public void update() {
         changeState();
         for (Handler handler : handlers)
           handler.handle();
       }
     }

#### [h2]toArray

public <T> T[] toArray​(T[] a)

Returns an array containing all of the elements in this set; the runtime type of the returned array is that of the specified array. If the set fits in the specified array, it is returned therein. Otherwise, a new array is allocated with the runtime type of the specified array and the size of this set. 

If this set fits in the specified array with room to spare (i.e., the array has more elements than this set), the element in the array immediately following the end of the set is set to null. (This is useful in determining the length of this set _only_ if the caller knows that this set does not contain any null elements.) 

If this set makes any guarantees as to what order its elements are returned by its iterator, this method must return the elements in the same order. 

Like the [toArray()](https://developer.harmonyos.com/cn/docs/documentation/doc-references/copyonwritearrayset-0000001054678612#ZH-CN_TOPIC_0000001054678612__toArray--) method, this method acts as bridge between array-based and collection-based APIs. Further, this method allows precise control over the runtime type of the output array, and may, under certain circumstances, be used to save allocation costs. 

Suppose x is a set known to contain only strings. The following code can be used to dump the set into a newly allocated array of String: 
    
    String[] y = x.toArray(new String[0]);

Note that toArray(new Object[0]) is identical in function to toArray().
