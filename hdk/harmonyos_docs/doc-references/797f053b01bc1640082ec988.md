# Path
    
    public interface Path
    extends [Comparable](https://developer.harmonyos.com/cn/docs/documentation/doc-references/comparable-0000001054558443)<[Path](https://developer.harmonyos.com/cn/docs/documentation/doc-references/path-0000001054558505)>, [Iterable](https://developer.harmonyos.com/cn/docs/documentation/doc-references/iterable-0000001054238441)<[Path](https://developer.harmonyos.com/cn/docs/documentation/doc-references/path-0000001054558505)>, [Watchable](https://developer.harmonyos.com/cn/docs/documentation/doc-references/watchable-0000001054838458)  
  
---  
An object that may be used to locate a file in a file system. It will typically represent a system dependent file path. 

A Path represents a path that is hierarchical and composed of a sequence of directory and file name elements separated by a special separator or delimiter. A root component, that identifies a file system hierarchy, may also be present. The name element that is farthest from the root of the directory hierarchy is the name of a file or directory. The other name elements are directory names. A Path can represent a root, a root and a sequence of names, or simply one or more name elements. A Path is considered to be an _empty path_ if it consists solely of one name element that is empty. Accessing a file using an _empty path_ is equivalent to accessing the default directory of the file system. Path defines the [getFileName](https://developer.harmonyos.com/cn/docs/documentation/doc-references/path-0000001054558505#ZH-CN_TOPIC_0000001054558505__getFileName--), [getParent](https://developer.harmonyos.com/cn/docs/documentation/doc-references/path-0000001054558505#ZH-CN_TOPIC_0000001054558505__getParent--), [getRoot](https://developer.harmonyos.com/cn/docs/documentation/doc-references/path-0000001054558505#ZH-CN_TOPIC_0000001054558505__getRoot--), and [subpath](https://developer.harmonyos.com/cn/docs/documentation/doc-references/path-0000001054558505#ZH-CN_TOPIC_0000001054558505__subpath-int-int-) methods to access the path components or a subsequence of its name elements. 

In addition to accessing the components of a path, a Path also defines the [resolve](https://developer.harmonyos.com/cn/docs/documentation/doc-references/path-0000001054558505#ZH-CN_TOPIC_0000001054558505__resolve-java_nio_file_Path-) and [resolveSibling](https://developer.harmonyos.com/cn/docs/documentation/doc-references/path-0000001054558505#ZH-CN_TOPIC_0000001054558505__resolveSibling-java_nio_file_Path-) methods to combine paths. The [relativize](https://developer.harmonyos.com/cn/docs/documentation/doc-references/path-0000001054558505#ZH-CN_TOPIC_0000001054558505__relativize-java_nio_file_Path-) method that can be used to construct a relative path between two paths. Paths can be [compared](https://developer.harmonyos.com/cn/docs/documentation/doc-references/path-0000001054558505#ZH-CN_TOPIC_0000001054558505__compareTo-java_nio_file_Path-), and tested against each other using the [startsWith](https://developer.harmonyos.com/cn/docs/documentation/doc-references/path-0000001054558505#ZH-CN_TOPIC_0000001054558505__startsWith-java_nio_file_Path-) and [endsWith](https://developer.harmonyos.com/cn/docs/documentation/doc-references/path-0000001054558505#ZH-CN_TOPIC_0000001054558505__endsWith-java_nio_file_Path-) methods. 

This interface extends [Watchable](https://developer.harmonyos.com/cn/docs/documentation/doc-references/watchable-0000001054838458) interface so that a directory located by a path can be [registered](https://developer.harmonyos.com/cn/docs/documentation/doc-references/path-0000001054558505#ZH-CN_TOPIC_0000001054558505__register-java_nio_file_WatchService-java_nio_file_WatchEvent_Kind:A-java_nio_file_WatchEvent_Modifier___-) with a [WatchService](https://developer.harmonyos.com/cn/docs/documentation/doc-references/watchservice-0000001054199778) and entries in the directory watched. 

**WARNING:** This interface is only intended to be implemented by those developing custom file system implementations. Methods may be added to this interface in future releases. 

**Accessing Files**

Paths may be used with the [Files](https://developer.harmonyos.com/cn/docs/documentation/doc-references/files-0000001054678506) class to operate on files, directories, and other types of files. For example, suppose we want a [BufferedReader](https://developer.harmonyos.com/cn/docs/documentation/doc-references/bufferedreader-0000001054199702) to read text from a file "access.log". The file is located in a directory "logs" relative to the current working directory and is UTF-8 encoded. 
    
    Path path = FileSystems.getDefault().getPath("logs", "access.log");
         BufferedReader reader = Files.newBufferedReader(path, StandardCharsets.UTF_8);
     

__**Interoperability**

Paths associated with the default [provider](https://developer.harmonyos.com/cn/docs/documentation/doc-references/filesystemprovider-0000001054439803) are generally interoperable with the [java.io.File](https://developer.harmonyos.com/cn/docs/documentation/doc-references/file-0000001054119759) class. Paths created by other providers are unlikely to be interoperable with the abstract path names represented by java.io.File. The [toPath](https://developer.harmonyos.com/cn/docs/documentation/doc-references/file-0000001054119759#ZH-CN_TOPIC_0000001054119759__toPath--) method may be used to obtain a Path from the abstract path name represented by a java.io.File object. The resulting Path can be used to operate on the same file as the java.io.File object. In addition, the [toFile](https://developer.harmonyos.com/cn/docs/documentation/doc-references/path-0000001054558505#ZH-CN_TOPIC_0000001054558505__toFile--) method is useful to construct a File from the String representation of a Path. 

**Concurrency**

Implementations of this interface are immutable and safe for use by multiple concurrent threads.

#### [h2]getParent

[Path](https://developer.harmonyos.com/cn/docs/documentation/doc-references/path-0000001054558505) getParent​()

Returns the parent path, or null if this path does not have a parent. 

The parent of this path object consists of this path's root component, if any, and each element in the path except for the farthest from the root in the directory hierarchy. This method does not access the file system; the path or its parent may not exist. Furthermore, this method does not eliminate special names such as "." and ".." that may be used in some implementations. On UNIX for example, the parent of "/a/b/c" is "/a/b", and the parent of "x/y/." is "x/y". This method may be used with the [normalize](https://developer.harmonyos.com/cn/docs/documentation/doc-references/path-0000001054558505#ZH-CN_TOPIC_0000001054558505__normalize--) method, to eliminate redundant names, for cases where shell-like navigation is required. 

If this path has one or more elements, and no root component, then this method is equivalent to evaluating the expression: 
    
    subpath(0, getNameCount()-1);
     

**Returns:**

a path representing the path's parent

#### [h2]startsWith

Tests if this path starts with the given path. 

This path starts with the given path if this path's root component starts with the root component of the given path, and this path starts with the same name elements as the given path. If the given path has more name elements than this path then false is returned.

#### [h2]endsWith

#### [h2]normalize

[Path](https://developer.harmonyos.com/cn/docs/documentation/doc-references/path-0000001054558505) normalize​()

Returns a path that is this path with redundant name elements eliminated. 

The precise definition of this method is implementation dependent but in general it derives from this path, a path that does not contain redundant name elements. In many file systems, the "." and ".." are special names used to indicate the current directory and parent directory. In such file systems all occurrences of "." are considered redundant. If a ".." is preceded by a non-".." name then both names are considered redundant (the process to identify such names is repeated until it is no longer applicable). 

This method does not access the file system; the path may not locate a file that exists. Eliminating ".." and a preceding name from a path may result in the path that locates a different file than the original path. This can arise when the preceding name is a symbolic link.

**Returns:**

#### [h2]relativize

[Path](https://developer.harmonyos.com/cn/docs/documentation/doc-references/path-0000001054558505) relativize​([Path](https://developer.harmonyos.com/cn/docs/documentation/doc-references/path-0000001054558505) other)

Constructs a relative path between this path and a given path. 

Relativization is the inverse of [resolution](https://developer.harmonyos.com/cn/docs/documentation/doc-references/path-0000001054558505#ZH-CN_TOPIC_0000001054558505__resolve-java_nio_file_Path-). This method attempts to construct a [relative](https://developer.harmonyos.com/cn/docs/documentation/doc-references/path-0000001054558505#ZH-CN_TOPIC_0000001054558505__isAbsolute--) path that when [resolved](https://developer.harmonyos.com/cn/docs/documentation/doc-references/path-0000001054558505#ZH-CN_TOPIC_0000001054558505__resolve-java_nio_file_Path-) against this path, yields a path that locates the same file as the given path. For example, on UNIX, if this path is "/a/b" and the given path is "/a/b/c/d" then the resulting relative path would be "c/d". Where this path and the given path do not have a [root](https://developer.harmonyos.com/cn/docs/documentation/doc-references/path-0000001054558505#ZH-CN_TOPIC_0000001054558505__getRoot--) component, then a relative path can be constructed. A relative path cannot be constructed if only one of the paths have a root component. Where both paths have a root component then it is implementation dependent if a relative path can be constructed. If this path and the given path are [equal](https://developer.harmonyos.com/cn/docs/documentation/doc-references/path-0000001054558505#ZH-CN_TOPIC_0000001054558505__equals-java_lang_Object-) then an _empty path_ is returned. 

For any two [normalized](https://developer.harmonyos.com/cn/docs/documentation/doc-references/path-0000001054558505#ZH-CN_TOPIC_0000001054558505__normalize--) paths _p_ and _q_ , where _q_ does not have a root component, 

_p_.relativize(_p_.resolve(_q_)).equals(_q_)

For example, if this path is "/a/b" and the given path is "/a/x" then the resulting relative path may be "../x". If "b" is a symbolic link then is implementation dependent if "a/b/../x" would locate the same file as "/a/x".

#### [h2]toUri

[URI](https://developer.harmonyos.com/cn/docs/documentation/doc-references/uri-0000001054838434) toUri​()

The exact form of the scheme specific part is highly provider dependent. 

In the case of the default provider, the URI is hierarchical with a [URI#getPath()](https://developer.harmonyos.com/cn/docs/documentation/doc-references/uri-0000001054838434#ZH-CN_TOPIC_0000001054838434__getPath--) component that is absolute. There is no guarantee that the URI may be used to construct a [java.io.File](https://developer.harmonyos.com/cn/docs/documentation/doc-references/file-0000001054119759). In particular, if this path represents a Universal Naming Convention (UNC) path, then the UNC server name may be encoded in the authority component of the resulting URI. In the case of the default provider, and the file exists, and it can be determined that the file is a directory, then the resulting URI will end with a slash. 

The default provider provides a similar round-trip guarantee to the [File](https://developer.harmonyos.com/cn/docs/documentation/doc-references/file-0000001054119759) class. For a given Path _p_ it is guaranteed that

so long as the original Path, the URI, and the new Path are all created in (possibly different invocations of) the same Java virtual machine. Whether other providers make any guarantees is provider specific and therefore unspecified. 

When a file system is constructed to access the contents of a file as a file system then it is highly implementation specific if the returned URI represents the given path in the file system or it represents a compound URI that encodes the URI of the enclosing file system. A format for compound URIs is not defined in this release; such a scheme may be added in a future release.

#### [h2]equals

boolean equals​([Object](https://developer.harmonyos.com/cn/docs/documentation/doc-references/object-0000001054678446) other)

Tests this path for equality with the given object. 

If the given object is not a Path, or is a Path associated with a different FileSystem, then this method returns false. 

Whether or not two path are equal depends on the file system implementation. In some cases the paths are compared without regard to case, and others are case sensitive. This method does not access the file system and the file is not required to exist. Where required, the [Files#isSameFile](https://developer.harmonyos.com/cn/docs/documentation/doc-references/files-0000001054678506#ZH-CN_TOPIC_0000001054678506__isSameFile-java_nio_file_Path-java_nio_file_Path-) method may be used to check if two paths locate the same file.
