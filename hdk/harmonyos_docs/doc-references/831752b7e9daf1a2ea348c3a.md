A standard set of fields.  This set of fields provide field-based access to manipulate a date, time or date-time. The standard set of fields can be extended by implementing [TemporalField](https://developer.harmonyos.com/cn/docs/documentation/doc-references/temporalfield-0000001054439865).  These fields are intended to be applicable in multiple calendar systems. For example, most non-ISO calendar systems define dates as a year, month and day, just with slightly different rules. This counts the nanosecond within the second, from 0 to 999,999,999. This field has the same meaning for all calendar systems.  This field is used to represent the nano-of-second handling any fraction of the second. Implementations of TemporalAccessor should provide a value for this field if they can return a value for [SECOND_OF_MINUTE](https://developer.harmonyos.com/cn/docs/documentation/doc-references/chronofield-0000001054119838#ZH-CN_TOPIC_0000001054119838__SECOND_OF_MINUTE), [SECOND_OF_DAY](https://developer.harmonyos.com/cn/docs/documentation/doc-references/chronofield-0000001054119838#ZH-CN_TOPIC_0000001054119838__SECOND_OF_DAY) or [INSTANT_SECONDS](https://developer.harmonyos.com/cn/docs/documentation/doc-references/chronofield-0000001054119838#ZH-CN_TOPIC_0000001054119838__INSTANT_SECONDS) filling unknown precision with zero.  When this field is used for setting a value, it should set as much precision as the object stores, using integer division to remove excess precision. For example, if the TemporalAccessor stores time to millisecond precision, then the nano-of-second must be divided by 1,000,000 before replacing the milli-of-second.  When parsing this field it behaves equivalent to the following: The value is validated in strict and smart mode but not in lenient mode. The field is resolved in combination with MILLI_OF_SECOND and MICRO_OF_SECOND.
