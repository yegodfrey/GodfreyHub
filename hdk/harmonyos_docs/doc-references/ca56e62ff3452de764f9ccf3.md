# LifecycleObserver  
  
[java.lang.Object](https://developer.harmonyos.com/cn/docs/documentation/doc-references/object-0000001054678446) |---ohos.aafwk.ability.LifecycleObserver
    
    public class LifecycleObserver
    extends [Object](https://developer.harmonyos.com/cn/docs/documentation/doc-references/object-0000001054678446)
    implements [ILifecycleObserver](https://developer.harmonyos.com/cn/docs/documentation/doc-references/ilifecycleobserver-0000001054678647)  
  
---  
Observes and responds to lifecycle changes. 

[Lifecycle](https://developer.harmonyos.com/cn/docs/documentation/doc-references/lifecycle-0000001054439967) dispatches a lifecycle event to a registered LifecycleObserver. LifecycleObserver then implements lifecycle callbacks for [Ability](https://developer.harmonyos.com/cn/docs/documentation/doc-references/ability-0000001054120007) or [AbilitySlice](https://developer.harmonyos.com/cn/docs/documentation/doc-references/abilityslice-0000001054678680). This allows your application to have a decoupled architecture where [Ability](https://developer.harmonyos.com/cn/docs/documentation/doc-references/ability-0000001054120007) or [AbilitySlice](https://developer.harmonyos.com/cn/docs/documentation/doc-references/abilityslice-0000001054678680) takes only a single responsibility.

You should inherit the LifecycleObserver class, override lifecycle callback methods as required, and call [Lifecycle#addObserver(ILifecycleObserver)](https://developer.harmonyos.com/cn/docs/documentation/doc-references/lifecycle-0000001054439967#ZH-CN_TOPIC_0000001054439967__addObserver-ohos_aafwk_ability_ILifecycleObserver-) to register a LifecycleObserver with [Lifecycle](https://developer.harmonyos.com/cn/docs/documentation/doc-references/lifecycle-0000001054439967). The callback methods in LifecycleObserver provide the same functions as those provided in [Ability](https://developer.harmonyos.com/cn/docs/documentation/doc-references/ability-0000001054120007) and [AbilitySlice](https://developer.harmonyos.com/cn/docs/documentation/doc-references/abilityslice-0000001054678680), but they are called in different sequence. The system calls those in [Ability](https://developer.harmonyos.com/cn/docs/documentation/doc-references/ability-0000001054120007) and [AbilitySlice](https://developer.harmonyos.com/cn/docs/documentation/doc-references/abilityslice-0000001054678680) first and then those in LifecycleObserver. You are advised to use LifecycleObserver for lifecycle callbacks of [Ability](https://developer.harmonyos.com/cn/docs/documentation/doc-references/ability-0000001054120007) and [AbilitySlice](https://developer.harmonyos.com/cn/docs/documentation/doc-references/abilityslice-0000001054678680) when your application is complicated.

public void onStart​([Intent](https://developer.harmonyos.com/cn/docs/documentation/doc-references/intent-0000001054120019) intent)

You are advised to implement some initialization logic using this method, for example, you can initialize a timer or define some global objects.

#### [h2]onInactive

public void onInactive​()

Called back in response to an ON_INACTIVE event. 

When an ON_INACTIVE event is received, the ability or ability slice is in the INACTIVE state. INACTIVE is an intermediate state before the state changes to ACTIVE or BACKGROUND. In this state, the UI may be visible but is not interactive. You are advised not to use this method to invoke complex service logic.

#### [h2]onBackground

public void onBackground​()

Called back in response to an ON_BACKGROUND event. 

When an ON_BACKGROUND event is received, the ability or ability slice is invisible. You are advised to suspend the threads related to this ability or ability slice and clear resources for more system memory.
