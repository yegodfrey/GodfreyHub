# Overview  
  
Defines channels, which represent connections to entities that are capable of performing I/O operations, such as files and sockets; defines selectors, for multiplexed, non-blocking I/O operations. 

A _channel_ represents an open connection to an entity such as a hardware device, a file, a network socket, or a program component that is capable of performing one or more distinct I/O operations, for example reading or writing. As specified in the [Channel](https://developer.harmonyos.com/cn/docs/documentation/doc-references/channel-0000001054838442) interface, channels are either open or closed, and they are both _asynchronously closeable_ and _interruptible_. 

The [Channel](https://developer.harmonyos.com/cn/docs/documentation/doc-references/channel-0000001054838442) interface is extended by several other interfaces. 

The [ReadableByteChannel](https://developer.harmonyos.com/cn/docs/documentation/doc-references/readablebytechannel-0000001054518502) interface specifies a [read](https://developer.harmonyos.com/cn/docs/documentation/doc-references/readablebytechannel-0000001054518502#ZH-CN_TOPIC_0000001054518502__read-java_nio_ByteBuffer-) method that reads bytes from the channel into a buffer; similarly, the [WritableByteChannel](https://developer.harmonyos.com/cn/docs/documentation/doc-references/writablebytechannel-0000001054558491) interface specifies a [write](https://developer.harmonyos.com/cn/docs/documentation/doc-references/writablebytechannel-0000001054558491#ZH-CN_TOPIC_0000001054558491__write-java_nio_ByteBuffer-) method that writes bytes from a buffer to the channel. The [ByteChannel](https://developer.harmonyos.com/cn/docs/documentation/doc-references/bytechannel-0000001054678457) interface unifies these two interfaces for the common case of channels that can both read and write bytes. The [SeekableByteChannel](https://developer.harmonyos.com/cn/docs/documentation/doc-references/seekablebytechannel-0000001054358469) interface extends the ByteChannel interface with methods to [query](https://developer.harmonyos.com/cn/docs/documentation/doc-references/seekablebytechannel-0000001054358469#ZH-CN_TOPIC_0000001054358469__position--) and [modify](https://developer.harmonyos.com/cn/docs/documentation/doc-references/seekablebytechannel-0000001054358469#ZH-CN_TOPIC_0000001054358469__position-long-) the channel's current position, and its [size](https://developer.harmonyos.com/cn/docs/documentation/doc-references/seekablebytechannel-0000001054358469#ZH-CN_TOPIC_0000001054358469__size--). 

The [ScatteringByteChannel](https://developer.harmonyos.com/cn/docs/documentation/doc-references/scatteringbytechannel-0000001054678490) and [GatheringByteChannel](https://developer.harmonyos.com/cn/docs/documentation/doc-references/gatheringbytechannel-0000001054119817) interfaces extend the [ReadableByteChannel](https://developer.harmonyos.com/cn/docs/documentation/doc-references/readablebytechannel-0000001054518502) and [WritableByteChannel](https://developer.harmonyos.com/cn/docs/documentation/doc-references/writablebytechannel-0000001054558491) interfaces, respectively, adding [read](https://developer.harmonyos.com/cn/docs/documentation/doc-references/scatteringbytechannel-0000001054678490#ZH-CN_TOPIC_0000001054678490__read-java_nio_ByteBuffer:A-int-int-) and [write](https://developer.harmonyos.com/cn/docs/documentation/doc-references/gatheringbytechannel-0000001054119817#ZH-CN_TOPIC_0000001054119817__write-java_nio_ByteBuffer:A-int-int-) methods that take a sequence of buffers rather than a single buffer. 

The [NetworkChannel](https://developer.harmonyos.com/cn/docs/documentation/doc-references/networkchannel-0000001054199762) interface specifies methods to [bind](https://developer.harmonyos.com/cn/docs/documentation/doc-references/networkchannel-0000001054199762#ZH-CN_TOPIC_0000001054199762__bind-java_net_SocketAddress-) the channel's socket, obtain the address to which the socket is bound, and methods to [get](https://developer.harmonyos.com/cn/docs/documentation/doc-references/networkchannel-0000001054199762#ZH-CN_TOPIC_0000001054199762__getOption-java_net_SocketOption-) and [set](https://developer.harmonyos.com/cn/docs/documentation/doc-references/networkchannel-0000001054199762#ZH-CN_TOPIC_0000001054199762__setOption-java_net_SocketOption-T-) socket options. The [MulticastChannel](https://developer.harmonyos.com/cn/docs/documentation/doc-references/multicastchannel-0000001054439775) interface specifies methods to join Internet Protocol (IP) multicast groups. 

The [Channels](https://developer.harmonyos.com/cn/docs/documentation/doc-references/channels-0000001054119748) utility class defines static methods that support the interoperation of the stream classes of the [java.io](https://developer.harmonyos.com/cn/docs/documentation/doc-references/overview-0000001054838380) package with the channel classes of this package. An appropriate channel can be constructed from an [InputStream](https://developer.harmonyos.com/cn/docs/documentation/doc-references/inputstream-0000001054358420) or an [OutputStream](https://developer.harmonyos.com/cn/docs/documentation/doc-references/outputstream-0000001054678403), and conversely an [InputStream](https://developer.harmonyos.com/cn/docs/documentation/doc-references/inputstream-0000001054358420) or an [OutputStream](https://developer.harmonyos.com/cn/docs/documentation/doc-references/outputstream-0000001054678403) can be constructed from a channel. A [Reader](https://developer.harmonyos.com/cn/docs/documentation/doc-references/reader-0000001054238435) can be constructed that uses a given charset to decode bytes from a given readable byte channel, and conversely a [Writer](https://developer.harmonyos.com/cn/docs/documentation/doc-references/writer-0000001054199710) can be constructed that uses a given charset to encode characters into bytes and write them to a given writable byte channel. 

The [FileChannel](https://developer.harmonyos.com/cn/docs/documentation/doc-references/filechannel-0000001054199764) class supports the usual operations of reading bytes from, and writing bytes to, a channel connected to a file, as well as those of querying and modifying the current file position and truncating the file to a specific size. It defines methods for acquiring locks on the whole file or on a specific region of a file; these methods return instances of the [FileLock](https://developer.harmonyos.com/cn/docs/documentation/doc-references/filelock-0000001054678492) class. Finally, it defines methods for forcing updates to the file to be written to the storage device that contains it, for efficiently transferring bytes between the file and other channels, and for mapping a region of the file directly into memory. 

A FileChannel is created by invoking one of its static [open](https://developer.harmonyos.com/cn/docs/documentation/doc-references/filechannel-0000001054199764#ZH-CN_TOPIC_0000001054199764__open-java_nio_file_Path-java_util_Set-java_nio_file_attribute_FileAttribute___-) methods, or by invoking the getChannel method of a [FileInputStream](https://developer.harmonyos.com/cn/docs/documentation/doc-references/fileinputstream-0000001054439717), [FileOutputStream](https://developer.harmonyos.com/cn/docs/documentation/doc-references/fileoutputstream-0000001054199704), or [RandomAccessFile](https://developer.harmonyos.com/cn/docs/documentation/doc-references/randomaccessfile-0000001054558437) to return a file channel connected to the same underlying file as the [java.io](https://developer.harmonyos.com/cn/docs/documentation/doc-references/overview-0000001054838380) class. __

Multiplexed, non-blocking I/O, which is much more scalable than thread-oriented, blocking I/O, is provided by _selectors_ , _selectable channels_ , and _selection keys_. 

A [_selector_](https://developer.harmonyos.com/cn/docs/documentation/doc-references/selector-0000001054119821) is a multiplexor of [_selectable channels_](https://developer.harmonyos.com/cn/docs/documentation/doc-references/selectablechannel-0000001054838446), which in turn are a special type of channel that can be put into [_non-blocking mode_](https://developer.harmonyos.com/cn/docs/documentation/doc-references/selectablechannel-0000001054838446#ZH-CN_TOPIC_0000001054838446__bm). To perform multiplexed I/O operations, one or more selectable channels are first created, put into non-blocking mode, and [_registered_](https://developer.harmonyos.com/cn/docs/documentation/doc-references/selectablechannel-0000001054838446#ZH-CN_TOPIC_0000001054838446__register-java_nio_channels_Selector-int-java_lang_Object-) with a selector. Registering a channel specifies the set of I/O operations that will be tested for readiness by the selector, and returns a [_selection key_](https://developer.harmonyos.com/cn/docs/documentation/doc-references/selectionkey-0000001054358480) that represents the registration. 

Once some channels have been registered with a selector, a [_selection operation_](https://developer.harmonyos.com/cn/docs/documentation/doc-references/selector-0000001054119821#ZH-CN_TOPIC_0000001054119821__selop) can be performed in order to discover which channels, if any, have become ready to perform one or more of the operations in which interest was previously declared. If a channel is ready then the key returned when it was registered will be added to the selector's _selected-key set_. The key set, and the keys within it, can be examined in order to determine the operations for which each channel is ready. From each key one can retrieve the corresponding channel in order to perform whatever I/O operations are required. 

That a selection key indicates that its channel is ready for some operation is a hint, but not a guarantee, that such an operation can be performed by a thread without causing the thread to block. It is imperative that code that performs multiplexed I/O be written so as to ignore these hints when they prove to be incorrect. 

This package defines selectable-channel classes corresponding to the [DatagramSocket](https://developer.harmonyos.com/cn/docs/documentation/doc-references/datagramsocket-0000001054678445), [ServerSocket](https://developer.harmonyos.com/cn/docs/documentation/doc-references/serversocket-0000001054518492), and [Socket](https://developer.harmonyos.com/cn/docs/documentation/doc-references/socket-0000001054678480) classes defined in the [java.net](https://developer.harmonyos.com/cn/docs/documentation/doc-references/overview-0000001054119730) package. Minor changes to these classes have been made in order to support sockets that are associated with channels. This package also defines a simple class that implements unidirectional pipes. In all cases, a new selectable channel is created by invoking the static open method of the corresponding class. If a channel needs an associated socket then a socket will be created as a side effect of this operation. 

The implementation of selectors, selectable channels, and selection keys can be replaced by "plugging in" an alternative definition or instance of the [SelectorProvider](https://developer.harmonyos.com/cn/docs/documentation/doc-references/selectorprovider-0000001054119756) class defined in the [java.nio.channels.spi](https://developer.harmonyos.com/cn/docs/documentation/doc-references/overview-0000001054358477) package. It is not expected that many developers will actually make use of this facility; it is provided primarily so that sophisticated users can take advantage of operating-system-specific I/O-multiplexing mechanisms when very high performance is required. 

Much of the bookkeeping and synchronization required to implement the multiplexed-I/O abstractions is performed by the [AbstractInterruptibleChannel](https://developer.harmonyos.com/cn/docs/documentation/doc-references/abstractinterruptiblechannel-0000001054238497), [AbstractSelectableChannel](https://developer.harmonyos.com/cn/docs/documentation/doc-references/abstractselectablechannel-0000001054678467), [AbstractSelectionKey](https://developer.harmonyos.com/cn/docs/documentation/doc-references/abstractselectionkey-0000001054838452), and [AbstractSelector](https://developer.harmonyos.com/cn/docs/documentation/doc-references/abstractselector-0000001054358486) classes in the [java.nio.channels.spi](https://developer.harmonyos.com/cn/docs/documentation/doc-references/overview-0000001054358477) package. When defining a custom selector provider, only the [AbstractSelector](https://developer.harmonyos.com/cn/docs/documentation/doc-references/abstractselector-0000001054358486) and [AbstractSelectionKey](https://developer.harmonyos.com/cn/docs/documentation/doc-references/abstractselectionkey-0000001054838452) classes should be subclassed directly; custom channel classes should extend the appropriate [SelectableChannel](https://developer.harmonyos.com/cn/docs/documentation/doc-references/selectablechannel-0000001054838446) subclasses defined in this package. 

[Asynchronous channels](https://developer.harmonyos.com/cn/docs/documentation/doc-references/asynchronouschannel-0000001054238487) are a special type of channel capable of asynchronous I/O operations. Asynchronous channels are non-blocking and define methods to initiate asynchronous operations, returning a [Future](https://developer.harmonyos.com/cn/docs/documentation/doc-references/future-0000001054838562) representing the pending result of each operation. The Future can be used to poll or wait for the result of the operation. Asynchronous I/O operations can also specify a [CompletionHandler](https://developer.harmonyos.com/cn/docs/documentation/doc-references/completionhandler-0000001054358476) to invoke when the operation completes. A completion handler is user provided code that is executed to consume the result of I/O operation. 

This package defines asynchronous-channel classes that are connected to a stream-oriented connecting or listening socket, or a datagram-oriented socket. It also defines the [AsynchronousFileChannel](https://developer.harmonyos.com/cn/docs/documentation/doc-references/asynchronousfilechannel-0000001054838444) class for asynchronous reading, writing, and manipulating a file. As with the [FileChannel](https://developer.harmonyos.com/cn/docs/documentation/doc-references/filechannel-0000001054199764) it supports operations to truncate the file to a specific size, force updates to the file to be written to the storage device, or acquire locks on the whole file or on a specific region of the file. Unlike the FileChannel it does not define methods for mapping a region of the file directly into memory. Where memory mapped I/O is required, then a FileChannel can be used. 

Asynchronous channels are bound to an asynchronous channel group for the purpose of resource sharing. A group has an associated [ExecutorService](https://developer.harmonyos.com/cn/docs/documentation/doc-references/executorservice-0000001054558609) to which tasks are submitted to handle I/O events and dispatch to completion handlers that consume the result of asynchronous operations performed on channels in the group. The group can optionally be specified when creating the channel or the channel can be bound to a default group. Sophisticated users may wish to create their own asynchronous channel groups or configure the ExecutorService that will be used for the default group. 

As with selectors, the implementation of asynchronous channels can be replaced by "plugging in" an alternative definition or instance of the [AsynchronousChannelProvider](https://developer.harmonyos.com/cn/docs/documentation/doc-references/asynchronouschannelprovider-0000001054119827) class defined in the [java.nio.channels.spi](https://developer.harmonyos.com/cn/docs/documentation/doc-references/overview-0000001054358477) package. It is not expected that many developers will actually make use of this facility; it is provided primarily so that sophisticated users can take advantage of operating-system-specific asynchronous I/O mechanisms when very high performance is required. 

Unless otherwise noted, passing a null argument to a constructor or method in any class or interface in this package will cause a [NullPointerException](https://developer.harmonyos.com/cn/docs/documentation/doc-references/nullpointerexception-0000001054119710) to be thrown.
