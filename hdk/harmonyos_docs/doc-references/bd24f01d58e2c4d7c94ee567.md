# ChronoLocalDateTime
    
    public interface ChronoLocalDateTime<D extends [ChronoLocalDate](https://developer.harmonyos.com/cn/docs/documentation/doc-references/chronolocaldate-0000001054558573)>
    extends [Temporal](https://developer.harmonyos.com/cn/docs/documentation/doc-references/temporal-0000001054838532), [TemporalAdjuster](https://developer.harmonyos.com/cn/docs/documentation/doc-references/temporaladjuster-0000001054119907), [Comparable](https://developer.harmonyos.com/cn/docs/documentation/doc-references/comparable-0000001054558443)<[ChronoLocalDateTime](https://developer.harmonyos.com/cn/docs/documentation/doc-references/chronolocaldatetime-0000001054238571)<?>>

A date-time without a time-zone in an arbitrary chronology, intended for advanced globalization use cases. 

**Most applications should declare method signatures, fields and variables as[LocalDateTime](https://developer.harmonyos.com/cn/docs/documentation/doc-references/localdatetime-0000001054119897), not this interface.**

A ChronoLocalDateTime is the abstract representation of a local date-time where the Chronology chronology, or calendar system, is pluggable. The date-time is defined in terms of fields expressed by [TemporalField](https://developer.harmonyos.com/cn/docs/documentation/doc-references/temporalfield-0000001054439865), where most common implementations are defined in [ChronoField](https://developer.harmonyos.com/cn/docs/documentation/doc-references/chronofield-0000001054119838). The chronology defines how the calendar system operates and the meaning of the standard fields. 

**When to use this interface** The design of the API encourages the use of LocalDateTime rather than this interface, even in the case where the application needs to deal with multiple calendar systems. The rationale for this is explored in detail in [ChronoLocalDate](https://developer.harmonyos.com/cn/docs/documentation/doc-references/chronolocaldate-0000001054558573). 

Ensure that the discussion in ChronoLocalDate has been read and understood before using this interface.

**Since:**

1.8

Gets a comparator that compares ChronoLocalDateTime in time-line order ignoring the chronology. 

This comparator differs from the comparison in [compareTo(java.time.chrono.ChronoLocalDateTime<?>)](https://developer.harmonyos.com/cn/docs/documentation/doc-references/chronolocaldatetime-0000001054238571#ZH-CN_TOPIC_0000001054238571__compareTo-java_time_chrono_ChronoLocalDateTime-) in that it only compares the underlying date-time and not the chronology. This allows dates in different calendar systems to be compared based on the position of the date-time on the local time-line. The underlying comparison is equivalent to comparing the epoch-day and nano-of-day.

Obtains an instance of ChronoLocalDateTime from a temporal object. 

This obtains a local date-time based on the specified temporal. A TemporalAccessor represents an arbitrary set of date and time information, which this factory converts to an instance of ChronoLocalDateTime. 

The conversion extracts and combines the chronology and the date-time from the temporal object. The behavior is equivalent to using [Chronology#localDateTime(TemporalAccessor)](https://developer.harmonyos.com/cn/docs/documentation/doc-references/chronology-0000001054678541#ZH-CN_TOPIC_0000001054678541__localDateTime-java_time_temporal_TemporalAccessor-) with the extracted chronology. Implementations are permitted to perform optimizations such as accessing those fields that are equivalent to the relevant objects. 

This method matches the signature of the functional interface [TemporalQuery](https://developer.harmonyos.com/cn/docs/documentation/doc-references/temporalquery-0000001054199852) allowing it to be used as a query via method reference, ChronoLocalDateTime::from.

#### [h2]with

default [ChronoLocalDateTime](https://developer.harmonyos.com/cn/docs/documentation/doc-references/chronolocaldatetime-0000001054238571)<[D](https://developer.harmonyos.com/cn/docs/documentation/doc-references/chronolocaldatetime-0000001054238571)> with​([TemporalAdjuster](https://developer.harmonyos.com/cn/docs/documentation/doc-references/temporaladjuster-0000001054119907) adjuster)

Returns an adjusted object of the same type as this object with the adjustment made. 

This adjusts this date-time according to the rules of the specified adjuster. A simple adjuster might simply set the one of the fields, such as the year field. A more complex adjuster might set the date to the last day of the month. A selection of common adjustments is provided in [TemporalAdjusters](https://developer.harmonyos.com/cn/docs/documentation/doc-references/temporaladjusters-0000001054238579). These include finding the "last day of the month" and "next Wednesday". The adjuster is responsible for handling special cases, such as the varying lengths of month and leap years. 

Some example code indicating how and why this method is used: 
    
    date = date.with(Month.JULY);        // most key classes implement TemporalAdjuster
      date = date.with(lastDayOfMonth());  // static import from Adjusters
      date = date.with(next(WEDNESDAY));   // static import from Adjusters and DayOfWeek

#### [h2]atZone

[ChronoZonedDateTime](https://developer.harmonyos.com/cn/docs/documentation/doc-references/chronozoneddatetime-0000001054358560)<[D](https://developer.harmonyos.com/cn/docs/documentation/doc-references/chronolocaldatetime-0000001054238571)> atZone​([ZoneId](https://developer.harmonyos.com/cn/docs/documentation/doc-references/zoneid-0000001054678539) zone)

Combines this time with a time-zone to create a ChronoZonedDateTime. 

This returns a ChronoZonedDateTime formed from this date-time at the specified time-zone. The result will match this date-time as closely as possible. Time-zone rules, such as daylight savings, mean that not every local date-time is valid for the specified zone, thus the local date-time may be adjusted. 

The local date-time is resolved to a single instant on the time-line. This is achieved by finding a valid offset from UTC/Greenwich for the local date-time as defined by the [ZoneRules](https://developer.harmonyos.com/cn/docs/documentation/doc-references/zonerules-0000001054838536) of the zone ID. 

In most cases, there is only one valid offset for a local date-time. In the case of an overlap, where clocks are set back, there are two valid offsets. This method uses the earlier offset typically corresponding to "summer". 

In the case of a gap, where clocks jump forward, there is no valid offset. Instead, the local date-time is adjusted to be later by the length of the gap. For a typical one hour daylight savings change, the local date-time will be moved one hour later into the offset typically corresponding to "summer". 

To obtain the later offset during an overlap, call [ChronoZonedDateTime#withLaterOffsetAtOverlap()](https://developer.harmonyos.com/cn/docs/documentation/doc-references/chronozoneddatetime-0000001054358560#ZH-CN_TOPIC_0000001054358560__withLaterOffsetAtOverlap--) on the result of this method.

**Parameters:**

Parameter Name | Parameter Description  
---|---  
zone  |  the time-zone to use, not null  
  
**Returns:**

the zoned date-time formed from this date-time, not null

#### [h2]compareTo

default int compareTo​([ChronoLocalDateTime](https://developer.harmonyos.com/cn/docs/documentation/doc-references/chronolocaldatetime-0000001054238571)<?> other)

Compares this date-time to another date-time, including the chronology. 

The comparison is based first on the underlying time-line date-time, then on the chronology. It is "consistent with equals", as defined by [Comparable](https://developer.harmonyos.com/cn/docs/documentation/doc-references/comparable-0000001054558443). 

For example, the following is the comparator order: 

    1. 2012-12-03T12:00 (ISO)
    2. 2012-12-04T12:00 (ISO)
    3. 2555-12-04T12:00 (ThaiBuddhist)
    4. 2012-12-05T12:00 (ISO)
Values #2 and #3 represent the same date-time on the time-line. When two values represent the same date-time, the chronology ID is compared to distinguish them. This step is needed to make the ordering "consistent with equals". 

If all the date-time objects being compared are in the same chronology, then the additional chronology stage is not required and only the local date-time is used. 

This default implementation performs the comparison defined above.
