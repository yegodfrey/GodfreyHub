# DoubleAccumulator  
  
[java.lang.Object](https://developer.harmonyos.com/cn/docs/documentation/doc-references/object-0000001054678446) |---[java.lang.Number](https://developer.harmonyos.com/cn/docs/documentation/doc-references/number-0000001054518458) |---|---java.util.concurrent.atomic.DoubleAccumulator

    extends [Number](https://developer.harmonyos.com/cn/docs/documentation/doc-references/number-0000001054518458)
    implements [Serializable](https://developer.harmonyos.com/cn/docs/documentation/doc-references/serializable-0000001054358416)

One or more variables that together maintain a running double value updated using a supplied function. When updates (method [accumulate(double)](https://developer.harmonyos.com/cn/docs/documentation/doc-references/doubleaccumulator-0000001054678589#ZH-CN_TOPIC_0000001054678589__accumulate-double-)) are contended across threads, the set of variables may grow dynamically to reduce contention. Method [get()](https://developer.harmonyos.com/cn/docs/documentation/doc-references/doubleaccumulator-0000001054678589#ZH-CN_TOPIC_0000001054678589__get--) (or, equivalently, [doubleValue()](https://developer.harmonyos.com/cn/docs/documentation/doc-references/doubleaccumulator-0000001054678589#ZH-CN_TOPIC_0000001054678589__doubleValue--)) returns the current value across the variables maintaining updates. 

This class is usually preferable to alternatives when multiple threads update a common value that is used for purposes such as summary statistics that are frequently updated but less frequently read. 

The supplied accumulator function should be side-effect-free, since it may be re-applied when attempted updates fail due to contention among threads. The function is applied with the current value as its first argument, and the given update as the second argument. For example, to maintain a running maximum value, you could supply Double::max along with Double.NEGATIVE_INFINITY as the identity. The order of accumulation within or across threads is not guaranteed. Thus, this class may not be applicable if numerical stability is required, especially when combining values of substantially different orders of magnitude. 

Class [DoubleAdder](https://developer.harmonyos.com/cn/docs/documentation/doc-references/doubleadder-0000001054838574) provides analogs of the functionality of this class for the common special case of maintaining sums. The call new DoubleAdder() is equivalent to new DoubleAccumulator((x, y) -> x + y, 0.0). 

This class extends [Number](https://developer.harmonyos.com/cn/docs/documentation/doc-references/number-0000001054518458), but does not define methods such as equals, hashCode and compareTo because instances are expected to be mutated, and so are not useful as collection keys.

#### [h2]get

public double get​()

Returns the current value. The returned value is NOT an atomic snapshot; invocation in the absence of concurrent updates returns an accurate result, but concurrent updates that occur while the value is being calculated might not be incorporated. 

**Returns:**

the current value

#### [h2]reset

public void reset​()

Resets variables maintaining updates to the identity value. This method may be a useful alternative to creating a new updater, but is only effective if there are no concurrent updates. Because this method is intrinsically racy, it should only be used when it is known that no threads are concurrently updating. 

#### [h2]getThenReset

public double getThenReset​()

Equivalent in effect to [get()](https://developer.harmonyos.com/cn/docs/documentation/doc-references/doubleaccumulator-0000001054678589#ZH-CN_TOPIC_0000001054678589__get--) followed by [reset()](https://developer.harmonyos.com/cn/docs/documentation/doc-references/doubleaccumulator-0000001054678589#ZH-CN_TOPIC_0000001054678589__reset--). This method may apply for example during quiescent points between multithreaded computations. If there are updates concurrent with this method, the returned value is not guaranteed to be the final value occurring before the reset.
