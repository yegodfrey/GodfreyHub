# Matcher

[java.lang.Object](https://developer.harmonyos.com/cn/docs/documentation/doc-references/object-0000001054678446) |---java.util.regex.Matcher
    
    public final class Matcher
    extends [Object](https://developer.harmonyos.com/cn/docs/documentation/doc-references/object-0000001054678446)
    implements [MatchResult](https://developer.harmonyos.com/cn/docs/documentation/doc-references/matchresult-0000001054358628)  
  
---  
An engine that performs match operations on a [character sequence](https://developer.harmonyos.com/cn/docs/documentation/doc-references/charsequence-0000001054678442) by interpreting a [Pattern](https://developer.harmonyos.com/cn/docs/documentation/doc-references/pattern-0000001054439927). 

A matcher is created from a pattern by invoking the pattern's [Pattern#matcher](https://developer.harmonyos.com/cn/docs/documentation/doc-references/pattern-0000001054439927#ZH-CN_TOPIC_0000001054439927__matcher-java_lang_CharSequence-) method. Once created, a matcher can be used to perform three different kinds of match operations: 

    * The [matches](https://developer.harmonyos.com/cn/docs/documentation/doc-references/matcher-0000001054119898#ZH-CN_TOPIC_0000001054119898__matches--) method attempts to match the entire input sequence against the pattern. 

    * The [lookingAt](https://developer.harmonyos.com/cn/docs/documentation/doc-references/matcher-0000001054119898#ZH-CN_TOPIC_0000001054119898__lookingAt--) method attempts to match the input sequence, starting at the beginning, against the pattern. 

    * The [find](https://developer.harmonyos.com/cn/docs/documentation/doc-references/matcher-0000001054119898#ZH-CN_TOPIC_0000001054119898__find--) method scans the input sequence looking for the next subsequence that matches the pattern. 

Each of these methods returns a boolean indicating success or failure. More information about a successful match can be obtained by querying the state of the matcher. 

A matcher finds matches in a subset of its input called the _region_. By default, the region contains all of the matcher's input. The region can be modified via the[region](https://developer.harmonyos.com/cn/docs/documentation/doc-references/matcher-0000001054119898#ZH-CN_TOPIC_0000001054119898__region-int-int-) method and queried via the [regionStart](https://developer.harmonyos.com/cn/docs/documentation/doc-references/matcher-0000001054119898#ZH-CN_TOPIC_0000001054119898__regionStart--) and [regionEnd](https://developer.harmonyos.com/cn/docs/documentation/doc-references/matcher-0000001054119898#ZH-CN_TOPIC_0000001054119898__regionEnd--) methods. The way that the region boundaries interact with some pattern constructs can be changed. See [useAnchoringBounds](https://developer.harmonyos.com/cn/docs/documentation/doc-references/matcher-0000001054119898#ZH-CN_TOPIC_0000001054119898__useAnchoringBounds-boolean-) and [useTransparentBounds](https://developer.harmonyos.com/cn/docs/documentation/doc-references/matcher-0000001054119898#ZH-CN_TOPIC_0000001054119898__useTransparentBounds-boolean-) for more details. 

This class also defines methods for replacing matched subsequences with new strings whose contents can, if desired, be computed from the match result. The [appendReplacement](https://developer.harmonyos.com/cn/docs/documentation/doc-references/matcher-0000001054119898#ZH-CN_TOPIC_0000001054119898__appendReplacement-java_lang_StringBuffer-java_lang_String-) and [appendTail](https://developer.harmonyos.com/cn/docs/documentation/doc-references/matcher-0000001054119898#ZH-CN_TOPIC_0000001054119898__appendTail-java_lang_StringBuffer-) methods can be used in tandem in order to collect the result into an existing string buffer, or the more convenient [replaceAll](https://developer.harmonyos.com/cn/docs/documentation/doc-references/matcher-0000001054119898#ZH-CN_TOPIC_0000001054119898__replaceAll-java_lang_String-) method can be used to create a string in which every matching subsequence in the input sequence is replaced. 

The explicit state of a matcher includes the start and end indices of the most recent successful match. It also includes the start and end indices of the input subsequence captured by each [capturing group](https://developer.harmonyos.com/cn/docs/documentation/doc-references/pattern-0000001054439927#ZH-CN_TOPIC_0000001054439927__cg) in the pattern as well as a total count of such subsequences. As a convenience, methods are also provided for returning these captured subsequences in string form. 

The explicit state of a matcher is initially undefined; attempting to query any part of it before a successful match will cause an [IllegalStateException](https://developer.harmonyos.com/cn/docs/documentation/doc-references/illegalstateexception-0000001054678452) to be thrown. The explicit state of a matcher is recomputed by every match operation. 

The implicit state of a matcher includes the input character sequence as well as the _append position_ , which is initially zero and is updated by the [appendReplacement](https://developer.harmonyos.com/cn/docs/documentation/doc-references/matcher-0000001054119898#ZH-CN_TOPIC_0000001054119898__appendReplacement-java_lang_StringBuffer-java_lang_String-) method. 

A matcher may be reset explicitly by invoking its [reset()](https://developer.harmonyos.com/cn/docs/documentation/doc-references/matcher-0000001054119898#ZH-CN_TOPIC_0000001054119898__reset--) method or, if a new input sequence is desired, its [reset(CharSequence)](https://developer.harmonyos.com/cn/docs/documentation/doc-references/matcher-0000001054119898#ZH-CN_TOPIC_0000001054119898__reset-java_lang_CharSequence-) method. Resetting a matcher discards its explicit state information and sets the append position to zero. 

Instances of this class are not safe for use by multiple concurrent threads.

#### [h2]appendReplacement

public [Matcher](https://developer.harmonyos.com/cn/docs/documentation/doc-references/matcher-0000001054119898) appendReplacement​([StringBuffer](https://developer.harmonyos.com/cn/docs/documentation/doc-references/stringbuffer-0000001054678448) sb, [String](https://developer.harmonyos.com/cn/docs/documentation/doc-references/string-0000001054518460) replacement)

Implements a non-terminal append-and-replace step. 

This method performs the following actions: 

    1. It reads characters from the input sequence, starting at the append position, and appends them to the given string buffer. It stops after reading the last character preceding the previous match, that is, the character at index [start()](https://developer.harmonyos.com/cn/docs/documentation/doc-references/matcher-0000001054119898#ZH-CN_TOPIC_0000001054119898__start--) \- 1. 

    2. It appends the given replacement string to the string buffer. 

    3. It sets the append position of this matcher to the index of the last character matched, plus one, that is, to [end()](https://developer.harmonyos.com/cn/docs/documentation/doc-references/matcher-0000001054119898#ZH-CN_TOPIC_0000001054119898__end--). 

The replacement string may contain references to subsequences captured during the previous match: Each occurrence of ${_name_} or $_g_ will be replaced by the result of evaluating the corresponding [group(name)](https://developer.harmonyos.com/cn/docs/documentation/doc-references/matcher-0000001054119898#ZH-CN_TOPIC_0000001054119898__group-java_lang_String-) or [group(g)](https://developer.harmonyos.com/cn/docs/documentation/doc-references/matcher-0000001054119898#ZH-CN_TOPIC_0000001054119898__group-int-) respectively. For $_g_ , the first number after the $ is always treated as part of the group reference. Subsequent numbers are incorporated into g if they would form a legal group reference. Only the numerals '0' through '9' are considered as potential components of the group reference. If the second group matched the string "foo", for example, then passing the replacement string "$2bar" would cause "foobar" to be appended to the string buffer. A dollar sign ($) may be included as a literal in the replacement string by preceding it with a backslash (\$). 

Note that backslashes (\\) and dollar signs ($) in the replacement string may cause the results to be different than if it were being treated as a literal replacement string. Dollar signs may be treated as references to captured subsequences as described above, and backslashes are used to escape literal characters in the replacement string. 

This method is intended to be used in a loop together with the [appendTail](https://developer.harmonyos.com/cn/docs/documentation/doc-references/matcher-0000001054119898#ZH-CN_TOPIC_0000001054119898__appendTail-java_lang_StringBuffer-) and [find](https://developer.harmonyos.com/cn/docs/documentation/doc-references/matcher-0000001054119898#ZH-CN_TOPIC_0000001054119898__find--) methods. The following code, for example, writes one dog two dogs in the yard to the standard-output stream: 
    
    Pattern p = Pattern.compile("cat");
     Matcher m = p.matcher("one cat two cats in the yard");
     StringBuffer sb = new StringBuffer();
     while (m.find()) {
         m.appendReplacement(sb, "dog");
     }
     m.appendTail(sb);
     System.out.println(sb.toString());
