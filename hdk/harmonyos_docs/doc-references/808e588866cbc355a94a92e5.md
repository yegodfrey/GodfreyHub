# Overview  
  
Interfaces and classes providing a framework for locking and waiting for conditions that is distinct from built-in synchronization and monitors. The framework permits much greater flexibility in the use of locks and conditions, at the expense of more awkward syntax. 

The [Lock](https://developer.harmonyos.com/cn/docs/documentation/doc-references/lock-0000001054678622) interface supports locking disciplines that differ in semantics (reentrant, fair, etc), and that can be used in non-block-structured contexts including hand-over-hand and lock reordering algorithms. The main implementation is [ReentrantLock](https://developer.harmonyos.com/cn/docs/documentation/doc-references/reentrantlock-0000001054439909). 

The [ReadWriteLock](https://developer.harmonyos.com/cn/docs/documentation/doc-references/readwritelock-0000001054358601) interface similarly defines locks that may be shared among readers but are exclusive to writers. Only a single implementation, [ReentrantReadWriteLock](https://developer.harmonyos.com/cn/docs/documentation/doc-references/reentrantreadwritelock-0000001054199896), is provided, since it covers most standard usage contexts. But programmers may create their own implementations to cover nonstandard requirements. 

The [Condition](https://developer.harmonyos.com/cn/docs/documentation/doc-references/condition-0000001054518634) interface describes condition variables that may be associated with Locks. These are similar in usage to the implicit monitors accessed using Object.wait, but offer extended capabilities. In particular, multiple Condition objects may be associated with a single Lock. To avoid compatibility issues, the names of Condition methods are different from the corresponding Object versions. 

The [AbstractQueuedSynchronizer](https://developer.harmonyos.com/cn/docs/documentation/doc-references/abstractqueuedsynchronizer-0000001054358610) class serves as a useful superclass for defining locks and other synchronizers that rely on queuing blocked threads. The [AbstractQueuedLongSynchronizer](https://developer.harmonyos.com/cn/docs/documentation/doc-references/abstractqueuedlongsynchronizer-0000001054678591) class provides the same functionality but extends support to 64 bits of synchronization state. Both extend class [AbstractOwnableSynchronizer](https://developer.harmonyos.com/cn/docs/documentation/doc-references/abstractownablesynchronizer-0000001054238621), a simple class that helps record the thread currently holding exclusive synchronization. The [LockSupport](https://developer.harmonyos.com/cn/docs/documentation/doc-references/locksupport-0000001054119880) class provides lower-level blocking and unblocking support that is useful for those developers implementing their own customized lock classes.

#### Interface Summary

Interface | Description  
---|---  
[Condition](https://developer.harmonyos.com/cn/docs/documentation/doc-references/condition-0000001054518634) | Condition factors out the Object monitor methods ([Object#wait()](https://developer.harmonyos.com/cn/docs/documentation/doc-references/object-0000001054678446#ZH-CN_TOPIC_0000001054678446__wait--), [Object#notify](https://developer.harmonyos.com/cn/docs/documentation/doc-references/object-0000001054678446#ZH-CN_TOPIC_0000001054678446__notify--) and [Object#notifyAll](https://developer.harmonyos.com/cn/docs/documentation/doc-references/object-0000001054678446#ZH-CN_TOPIC_0000001054678446__notifyAll--)) into distinct objects to give the effect of having multiple wait-sets per object, by combining them with the use of arbitrary [Lock](https://developer.harmonyos.com/cn/docs/documentation/doc-references/lock-0000001054678622) implementations.  
[Lock](https://developer.harmonyos.com/cn/docs/documentation/doc-references/lock-0000001054678622) | Lock implementations provide more extensive locking operations than can be obtained using synchronized methods and statements.  
[ReadWriteLock](https://developer.harmonyos.com/cn/docs/documentation/doc-references/readwritelock-0000001054358601) | A ReadWriteLock maintains a pair of associated [Lock](https://developer.harmonyos.com/cn/docs/documentation/doc-references/lock-0000001054678622), one for read-only operations and one for writing.

[ReentrantReadWriteLock.WriteLock](https://developer.harmonyos.com/cn/docs/documentation/doc-references/reentrantreadwritelock_writelock-0000001054678624) | The lock returned by method [ReentrantReadWriteLock#writeLock](https://developer.harmonyos.com/cn/docs/documentation/doc-references/reentrantreadwritelock-0000001054199896#ZH-CN_TOPIC_0000001054199896__writeLock--).  
[StampedLock](https://developer.harmonyos.com/cn/docs/documentation/doc-references/stampedlock-0000001054358603) | A capability-based lock with three modes for controlling read/write access.
